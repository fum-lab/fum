# Границы Git-чтения и удержания index

Наблюдатель продолжает текущую сессию и опрос доступного дерева примерно каждые 50 секунд. Управляющий принимает решения и результаты; завершение агента не доказывает устойчивое восстановление. Неизменные состояния не пересылаются.

## Фактические передачи и результаты

По сообщениям Управляющего полный synthetic reader и kwdefaults-проверка прошли после исправления реальной потери keyword-only defaults в types.FunctionType. Следующая регрессия отслеживаемых байтов требует конкретную причину отказа при неизменных commit/index/JSON, а не любой exit2.

При source review выявлены local Git exec-пути: core.fsmonitor и clean/process filters через attributes. Управляющий сообщил actual positive controls и RED/GREEN для fsmonitor; одного fsmonitor=false оказалось недостаточно для clean filter в diff и status. Подготовлен частный controlled clean-filter test: собственный shell marker и identity cat, без новых .py, сети и Creator. Наблюдатель его не запускал.

В текущем wrapper status/diff временно закрыты до verified filter admission. Остальные запросы имеют конечную аргументную грамматику, stdin DEVNULL и timeout30 с переводом TimeoutExpired в ОшибкаОтчёта. Известные write/editor/filter flags и глобальные overrides отвергаются. Это не attestation установленного Git, config/include closure или cleanup потомков. Связанные исторические Git-readers являются другими функциями и не получают защиту автоматически. Нормальный выход лидера с живыми потомками признан отдельным lifetime-policy вопросом; private candidate автоматической остановки не принят из-за custody/PGID reuse и background semantics.

Объявленный контекст Git и доменное связывание hash приняты как подготовительный pure блок. Старые hashes могут совпадать при разных контекстах на одном входе и расходиться после изменения ignore; совпадение примера не означает совместимости policies. Отдельный bounded subprocess draft был отозван, поскольку обошёл бы новый HOLD status/diff.

## Index и FD-примитив

Существующий компонент historical.Снимки удерживает обычные файловые FD и повторные байты, но не является полным snapshot engine. Нужны отдельные directory/absence/alias/config/attributes layers и связывание physical Gitdir/index. Split/sparse, игнорируемые файлы и gitlink нельзя молча терять из нового отпечатка.

В pure parser index v2 обнаружен и исправлен несоседний D/F-контрпример a, a-, a/b. Введены caps index16МиБ,100000 записей, path8192 и depth64; checksum SHA1/SHA256, stage0 regular modes, nonzero OID и один opaque TREE framing. По сообщению Управляющего восемь адресных тестов прошли, включая actual own SHA1/SHA256 после write-tree и volume boundaries. Это не семантическая проверка TREE, object existence/type или casefold/Unicode namespace. Будущий snapshot обязан хэшировать все raw index bytes, а не только извлечённые triples.

В review pinned-index исправлены: отсутствие per-open deadline/owner checks и cap; ложное срабатывание на timestamps/nlink общих каталогов; отсутствие полного post-read pathname recheck; подавление own close failure из-за ambient sys.exc_info. Новая версия использует explicit local primary, notes capability до opens, pop-before-close без повторов сомнительного FD, dir identity без namespace counters, file bytes/hash и pre/post chain, terminal cooperative deadline. Mock owner PID не является real fork lifetime. Exception notes не заменяют отдельный receipt UNKNOWN cleanup; close error до фактического close может оставить FD открытым.

Последний reviewed private pinned patch: 4903649906ef01d72c801b4bbaf03957b6f2b323c4413e327969c2dd1cd46f6c. В ограниченной подготовительной роли новых blockers не найдено; runtime мною не запускался. Namespace custody, ACL, same-UID races, rename→restore, binding к actual Git query и hard cancellation blocked syscall не доказаны. Публичный guard этим не открыт.

## Последующие зависимости

Управляющий принимает exact source/tests и исполняет разрешённые проверки. Главстрой отвечает за согласованный следующий компонент. Наблюдатель передаёт конкретные дефекты и зависшие передачи, не создаёт работников ради ACK, не читает host ENV, ROOT JSONL или чужую личную память. Своя память сохраняется direct commit/push по исключению человека без её тестов, ревью, hooks и remote readback.
