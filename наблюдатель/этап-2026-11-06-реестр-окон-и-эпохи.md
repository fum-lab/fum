# Реальный внутрипроцессный этап реестра окон

Корневая задача 01a07d3d-d376-7ad2-aafc-67e4c25a67eb. Наблюдатель gpt-6.1-sol; effort неизвестен. Результаты исполнения ниже сообщены ROOT; наблюдатель занимался статическим приёмом проектов.

ROOT сообщил: реестр WorkspaceRegistry с epoch/generation, weak references и восстановлением длинного prompt прошёл три адресных Swift-теста; сборка Xcode завершилась кодом 0. Это реальный внутрипроцессный этап. Регистрация жизненного цикла окна, transport, MCP и фактическая authority ещё не подключены. W2 не закоммичен. Сборка не означает доставку, активацию или проверенный UI runtime.

В ходе приёма обнаружены: strong retention создавал адресуемые ghost windows; длинный prompt, введённый напрямую в модель, отравлял list и даже исправляющее изменение; terminal set мог превысить4096 и навсегда исчерпать реестр; отказ пустого чужого реестра не доказывал epoch binding. Переданы конкретные исправления и тестовые границы.

Принятый проект использует слабые ссылки и не продлевает жизнь модели. List возвращает только адрес и revision; snapshot слишком длинного prompt отказывает отдельно, short prompt способен восстановить окно. Адрес регистрации содержит epoch UUID, монотонный UInt64 generation и model.instance; после unregister и повторного register старый адрес не оживает. Все операции требуют полный адрес и затем revision. Переполнение счётчика отказывает; runtime-проверка этого предела отдельно не заявлена. Active map ограничен64, вечного tombstone set нет.

Адресные тесты различают foreign epoch при совпадающих instance/generation, поддельный generation, duplicate, stale/no mutation, слабый lifecycle,64/65 и16384/16385 байтов prompt. Weak reference не заменяет фактическое закрытие окна, если модель удерживается иным владельцем; UI registration owner обязан управлять настоящим жизненным циклом. Адрес — средство выбора экземпляра, не полномочие изменять его. При будущем транспорте нужен версионированный envelope без instance-only fallback, реальный authority/custody и явная область пользователя/процесса.

Наблюдение и анализ потребности автоматизации продолжаются в текущей сессии. Автоматическое восстановление после приложения/хоста не доказано. Память сохраняется по исключению без тестов, ревью, хуков и независимого readback.
