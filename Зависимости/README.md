# Зависимости FUM

Внешние Git-зависимости FUM хранятся как Git submodule из постоянного форка рядом с актуальным GitHub-репозиторием FUM. `.gitmodules` фиксирует публикационно допустимый URL форка и воспроизводимый URL оригинального `upstream`, а основной Git-репозиторий фиксирует точный gitlink.

## LinguisticKit

LinguisticKit подключён для канонической транслитерации русских смысловых названий [автоматизаций FUM](../Глоссарий/автоматизация-FUM.md):

- форк и `origin`: `https://github.com/fum-lab/LinguisticKit.git`;
- оригинал и `upstream`: `https://github.com/Roman-Kerimov/LinguisticKit.git`;
- выбранная ревизия: `837e2ce107b97ee7b9d3344c9fe99142281fe393`;
- лицензия выбранной ревизии: CC0 1.0 Universal;
- локальный путь: `Зависимости/LinguisticKit`.

Форк синхронизирован с актуальной веткой `master`, но gitlink намеренно сохраняет ранее проверенную совместимую ревизию. Обновление форка не меняет контракт транслитерации автоматически: переход на другую ревизию оформляется отдельной миграцией имён и эталонов.

Автономный контракт submodule проверяет [автоматизация Git-зависимостей](../Инструменты/fum-proverka-git-zavisimostej/SKILL.md). Живое поведение пакета проверяет [реестр названий автоматизаций](../Инструменты/реестр-названий-автоматизаций.json) через Swift-обёртку.

## После свежего клонирования FUM

Обычная инициализация submodule восстанавливает `origin` из `.gitmodules`, но не создаёт локальный remote `upstream`. После `git clone` с `--recurse-submodules` или без него до полного smoke-check нужно выполнить:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py init \
  --repo-root . \
  --path Зависимости/LinguisticKit
```

Команда выводит URL форка и оригинала из единственных отслеживаемых `url` и `fumUpstream` в `.gitmodules`, а ревизию — из gitlink текущего Git-индекса. Она до материализации проверяет обычный UTF-8-файл метаданных, компоненты рабочего пути и канонический Git-каталог submodule, при необходимости материализует выбранный путь, проверяет или восстанавливает точный `upstream`, получает оба remote с prune, безопасно выбирает gitlink в detached HEAD и завершает автономной проверкой всей локальной топологии. Повторный точный запуск допустим.

Режим применим только к одному явно указанному уже зарегистрированному верхнеуровневому submodule. Он может обращаться к сети, но не создаёт новую зависимость, не меняет `.gitmodules` или gitlink, не выбирает новую ревизию по вершинам remote и не синхронизирует форк. Расходящаяся с индексом или неоднозначная `.gitmodules`, отсутствующие `fumUpstream` или gitlink, локальная подмена URL, небезопасный путь или Git-каталог, грязная зависимость, shallow-клон, лишние remote, нестандартный fetch refspec и неверный существующий `upstream` останавливают инициализацию без переписывания расходящегося состояния. Родство, синхронизация и публикация форка, лицензия и публикационная допустимость проверяются отдельно.
