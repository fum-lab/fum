# Назначение архитектора

Первичный человеческий запрос, переданный ROOT:

> Davaj yesjhyo kakogo-nibudj arkhitektora sozdadim, kotoryij budet progonjatj arkhitekturu.

Последующее прямое уточнение человека:

> Voobsjhe eto kasayetsya kazhdogo agenta na lyubom urovne vlozhennosti.

Позднее уточнение человека о наблюдении:

> Nablyudeniye stejta fajlovoj sistemyi, nablyudeniye stejta gita.

Рабочий контракт держит filesystem observation и Git observation раздельно, у каждого собственные source и freshness cursor. Их согласованность проверяется явно и не подразумевается.

Следующее уточнение человека:

> Upravleniye stejtom budet ekvivalentno obnovleniyu stejta fajlovoj sistemyi i gita.

Для FUM это означает программу изменения файловой системы и Git с отдельным наблюдаемым результатом. Первый оператор является только preflight; он не выполняет эту транзакцию и не служит полным исполнительным адаптером.

Поздние архитектурные аксиомы человека, сохранённые в исходном порядке:

1. «Vsem agentam v celom sleduyet datj maksimum avtonomii v organizacii svoyej pamyati.»
2. «Stejt pamyati v Git — eto i yestj struktura stejta agenta.»
3. «Kommit — eto vsyo, chto nuzhno dlya vosstanovleniya agenta.»
4. «Vetka — eto i yestj uzel.»

Рабочее следствие: branch — узел агента, commit — его версионированный снимок, tree — память и непосредственные дети, процесс — инкарнация. Общий JSON предлагается как минимальный совместимый управляющий дескриптор и точки входа, а не второе полное зеркало Git-дерева. Это целевая модель; готовая массовая реализация не заявляется.

## Объём

Архитектор FUM/FUMA проверяет шесть связей: логический адрес агента с веткой, рабочим деревом и инкарнацией; собственную память с общей памятью и иерархией; желаемое и наблюдаемое состояние с append-only историей; восстановление и приёмку без хэша будущего собственного коммита и полного диалога; минимальный работающий runtime FUMA против усложнения допуска; владельца, заказчиков и реальное использование общего инструмента.

Уточнение действует рекурсивно на каждый уровень вложенности: агент поддерживает собственную память и актуальное состояние, находит повторяемую работу, поручает действия непосредственным детям, заказывает общий инструмент у его владельца и эскалирует только нехватку полномочий, ресурса или данных на своём уровне. Сообщения и результаты ходят вверх к ближайшему общему предку и затем вниз непосредственным маршрутом.

Выход этапа: краткий аудит с фактами и гипотезами, малый перечень машинных инвариантов и контрпримеров и один наиболее полезный исполняемый контроль. Входные примеры трений ROOT подтверждаются только тем уровнем свидетельства, который указан рядом с ними; неизвестное происхождение не дополняется догадкой.

## Полномочия и границы

- Собственная память: каталог arkhitektura/**. Общие каталоги и код читаются, но не изменяются.
- Не создавать третий центральный реестр или dispatcher. Состояние агента предлагается как минимальное совместимое уточнение уже существующих expected/observed и FUMA snapshot/observation моделей.
- Не добавлять Python-реализации или глобальные legacy readers. Код FUMA/Swift при необходимости относится к общему корневому пакету; новый Package.swift не создаётся.
- Не изменять общий Package.swift, AGENTS.md, инвентарь правил и чужой код. Нужные общие изменения оформлять запросом ROOT.
- Не публиковать приватные локальные пути или секреты. Точные привязки W передаются ROOT отдельно.
- Точная база этой ветки: 6999fcb256d298302358d1329c2e57fead00a808. Ref: refs/heads/fum-lab/fum/arkhitektura/master. Это контрольная точка направления, не ROOT acceptance и не интеграция.

## Начальные наблюдения

- W создан на точной базе, symbolic ref совпадает с назначением, рабочее дерево чистое. Физический путь хранится приватно и передан ROOT отдельно.
- На этой базе действует ручная последовательная запись с изоляцией задач; перед записью сверяются HEAD, полный ref, физическое дерево и отсутствие второго писателя.
- API выбора этой дочерней сессии принял model=gpt-6-luna и reasoning_effort=max по подтверждению ROOT. Runtime model/effort не наблюдены; это различие сохранено в состоянии.json.
- Issues #151, #365 и #328 прочитаны адресно вместе с последними относящимися комментариями. Корневые JSONL и общий Git log не перечитывались.

## Следующий шаг

Один чистый `restore-preflight` принимает descriptor из C и отдельное свежее наблюдение среды. Он сохраняет identity, append-only history и desired; проверяет W/ref/base, владельца, область и единственность писателя; чтение истории не требует хэша самого C или полного диалога. Неизвестный эффект не повторяется автоматически. API, модель и секреты объявляются зависимостями конкретного последующего действия, а не гарантией commit. Исполнитель не делает внешних эффектов; результат — продолжение, пауза или точное препятствие.
