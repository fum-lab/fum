# Git и рабочая сессия

Эти правила полностью читаются до изменения Git-состояния, подготовки коммита и любой пишущей работы после выбора маршрута.

<!-- FUM-ПРАВИЛО: FUM-ПРАВИЛО-НОВОЕ-000018 -->
- Постоянная ветка `refs/heads/planirovaniye` предназначена для согласованных пользователем планов FUM/FUMA и необходимых сопроводительных материалов. Её точное имя выбрано пользователем как исключение из обычного префикса `codex/`. Работа ведётся в отдельном изолированном Git worktree с одним писателем дерева и ref. Согласованные этапы фиксируются последовательными проверяемыми коммитами по `FUM-ПРАВИЛО-000062`, каждый коммит публикуется по `FUM-ПРАВИЛО-000064`. Приёмка для последующего слияния и интеграция в `master` выполняются позднее по отдельному явному запросу пользователя и правилам принимающего `master`. До принятой интеграции настоящая норма действует только в `refs/heads/planirovaniye` и не считается действующей в `master`.

<!-- FUM-ПРАВИЛО: FUM-ПРАВИЛО-НОВОЕ-000019 -->
- Каждая новая интеграция принятого результата Git-ветки, включая первичную интеграцию и обратную доставку, оформляется отдельным коммитом слияния, в том числе при возможности fast-forward (`--no-ff`). До слияния фиксируются точные OID принимающей вершины и принятого источника; итоговый коммит имеет родителей `[принимающая вершина, принятый источник]`. Сохраняются действующие проверки допуска, состава, происхождения, разрешения конфликтов, отчёта и публикации. Cherry-pick, squash и копирование дельты не заменяют итоговую интеграцию.

Для частичного результата сначала готовится отдельный проверенный срез с ровно принятой дельтой и без непринятой истории исходной ветки. Полная непринятая ветка не становится вторым родителем: такое родство ошибочно объявило бы её историю интегрированной. Cherry-pick, squash или копирование могут применяться при подготовке среза с сохранением происхождения; затем срез интегрируется коммитом слияния.

Для кандидата по `FUM-ПРАВИЛО-НОВОЕ-000011` сохраняются родители `[L, M]` и продвижение `master` к уже принятому C; второй коммит слияния поверх C не создаётся. Подтверждение ранее выполненной интеграции также использует существующий коммит. Правило относится к новым интеграциям и не даёт полномочий переписывать опубликованную историю, менять чужие refs или выполнять не согласованное слияние.

<!-- FUM-ПРАВИЛО: FUM-ПРАВИЛО-000063 -->
- Для агентского коммита `Author Name` имеет точный формат `FUM <Название роли с большой буквы>` и отражает фактическую роль текущей сессии, например `FUM Писатель`, `FUM Запросы`, `FUM Ревью` или `FUM Интегратор`. Это правило не меняет email и данные committer; роль нельзя придумывать вместо фактически назначенной или явно принятой в ручной схеме.

Для выбора роли меняй только `GIT_AUTHOR_NAME`; перед коммитом сравнивай `git var GIT_AUTHOR_IDENT` и `git var GIT_COMMITTER_IDENT` с исходными данными, после него проверяй фактические поля commit. Переопределение общего `user.name` ради роли затрагивает также committer и не соответствует этой норме. [Наблюдаемая ошибка и проверенное восстановление](../../Сбои/FUM-СБОЙ-0047-подмена-committer-при-выборе-роли-автора.md).

<!-- FUM-ПРАВИЛО: FUM-ПРАВИЛО-000201 -->
- Сообщение коммита пишется на русском языке и включает точный текст исходного пользовательского запроса, описание сделанного и последний Git trailer `Codex-Thread-ID: <UUID>` в теле сообщения. Значение trailer должно совпадать с разделом `## Идентификатор сеанса Codex` файла запроса и относиться к корневой пользовательской задаче Codex, а не к дочернему субагенту.

<!-- FUM-ПРАВИЛО: FUM-ПРАВИЛО-000202 -->
- Ссылкой на файл исходного запроса нельзя заменять сам текст запроса в сообщении коммита; ссылка может быть добавлена только как дополнительная справка.

<!-- FUM-ПРАВИЛО: FUM-ПРАВИЛО-НОВОЕ-000008 -->
- Внешний агент без допущенного локального checkout передаёт только недоверенное предложение изменения с точными базой, манифестом и хэшем и не становится писателем `master`. Проверка такого пакета не применяет его и не означает принятие: только действующая локальная корневая сессия в собственном рабочем дереве действующей схемы вправе выбрать содержательные строки, сформировать локальные `Журнал/`, recency, индексы и `Proyekcii/**`, выполнить проверки и создать локальный коммит по действующему допуску. Публикацию принятого коммита регулирует правило `FUM-ПРАВИЛО-000064` корневого ядра.
