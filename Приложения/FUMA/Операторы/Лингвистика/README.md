# Лингвистика: контекстная ячейка на FUMA

Первый срез выбирает одну русскую ячейку транслитерации графом JSON v2 настоящего `AutomationExecutor`. Вход содержит ровно три поля: `буква`, `слева`, `справа`. Цель — одна современная строчная NFC-буква; сосед — такая же буква либо `null`, означающий границу. Область включает 33 буквы и 40 исходных ячеек. Потоковая строка, регистр, NFD, старые буквы и другие языки требуют отдельных срезов.

Граф определения [контекстная-ячейка.json](Определения/контекстная-ячейка.json) выполняет классификацию соседей и выбор ячейки. Swift-код в `проверки/` служит harness и независимым oracle. Выход содержит результат, классы соседей, нулевой индекс в полном исходном массиве из 53 ячеек и выбранные условия. Например, `{"буква":"ъ","слева":"б","справа":"а"}` даёт `yh`, индекс 48.

Классы взяты из первой исходной ячейки буквы: `й`, `ь`, `э` относятся к `vowel`; `е`, `ё`, `ъ`, `ы`, `ю`, `я` — к `other`. Это значения закреплённого исходного контракта. Генератор использует таблицу CC0 и проверяет её SHA; независимые фикстуры он не читает.

## Подтверждённый результат

Настоящий интерпретатор прошёл 58 положительных и 16 отрицательных фикстур, включая точные ошибки, канонический JSON и связи трассы; повтор harness сохранил всё наблюдение. Все 38 148 допустимых сочетаний цели и соседей побайтно совпали с прямым Swift oracle на закреплённом gitlink. Реальный macOS-продукт `fum` собран; replay после удаления приватных файлов определения и входа воспроизвёл полное наблюдение и сохранил префикс контейнера.

Компактная сериализация уменьшила определение с 29 892 до 15 009 байт при одинаковом JSON-содержимом. В последовательных волнах профиля медиана разбора снизилась с 12,50 до 5,57 мс. Тёплый набор из 40 ячеек занимает около 252 мс у FUMA и около 1 мс у прямого oracle. FUMA включает более широкий протокол проверки и наблюдения; это сравнение разных API. Ускорение исполнения не заявлено. [Все замеры и границы](профиль/сравнение.json) сохраняют шесть пар на каждую форму, память, происхождение и реальный replay.

Срез сохраняется контрольной точкой. Общая финальная приёмка, интеграция и воспроизведение поставки в независимом чистом клоне остаются координатору.

## Воспроизведение

Из чистого клона FUM подготовьте объявленные зависимости штатным порядком репозитория. Oracle требует чистый полный checkout зарегистрированного `Зависимости/LinguisticKit` на gitlink `837e2ce107b97ee7b9d3344c9fe99142281fe393`; при отсутствии закрыто отказывает. Подготовка и сборка не входят во время исполнения.

Из корня FUM, с физическим приватным `рабочий_каталог` вне любого Git-предка:

```sh
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/собрать-определение.py --проверить
swift build --package-path Приложения/FUMA/Операторы/Лингвистика/проверки --scratch-path "$рабочий_каталог/build" --jobs 2 -Xswiftc -enable-testing
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-и-измерить.py фикстуры --исполняемый "$рабочий_каталог/build/debug/ПроверкаТранслитерации" --каталог-работы "$рабочий_каталог"
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-и-измерить.py oracle --исполняемый "$рабочий_каталог/build/debug/ПроверкаТранслитерации" --каталог-работы "$рабочий_каталог"
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-и-измерить.py полный-домен --исполняемый "$рабочий_каталог/build/debug/ПроверкаТранслитерации" --каталог-работы "$рабочий_каталог"
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-и-измерить.py профиль --исполняемый "$рабочий_каталог/build/debug/ПроверкаТранслитерации" --каталог-работы "$рабочий_каталог"
swift build --package-path Приложения/FUMA/macOS --scratch-path "$рабочий_каталог/build-fum" --product fum --jobs 2
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-и-измерить.py CLI-replay --исполняемый "$рабочий_каталог/build/debug/ПроверкаТранслитерации" --fum "$рабочий_каталог/build-fum/debug/fum" --каталог-работы "$рабочий_каталог"
```

Это вложенные команды: проектные проверки проводятся под штатной отчётной обёрткой текущего Журнала. Для `CLI-replay` нужен свежий рабочий каталог без `runtime-журнал`; приватный контейнер создаётся с правами 0700. macOS-продукт использует объявленную libmpv; текущая сборка выдала предупреждения устаревшего OpenGL и версии macOS библиотеки, завершилась успешно.

[План профиля](профиль/план.json) определяет границы. Для двух волн используйте разные приватные рабочие каталоги и отдельные `--выход <до.json>` и `--выход <после.json>` внутри соответствующего каталога: driver записывает каналы по фиксированным именам. Сохраните каналы первой волны до второй. До/после воспроизводится тем же harness с `--определение <приватная копия в рабочем каталоге>`: исходная pretty-форма получается `json.dumps(json.loads(компактные_байты), ensure_ascii=False, indent=2) + LF` и имеет SHA из сравнения.

## Проверка корня пакета

[Помощник проверки](проверки/проверить-корень-пакета.py) запускает настоящий `swift package dump-package` с явным путём пакета. Он проверяет работу из другого каталога, наличие обязательной памяти и маркеров корня, выбор необязательного эталона и закрытые отказы неверной структуры. Собственные отказы сохраняются при обычном Python, `-O` и `-OO`.

Каталог работы должен быть новым физическим каталогом вне Git. Пример из корня FUM:

```sh
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-корень-пакета.py проверить --корень-репозитория . --каталог-работы "$рабочий_каталог/проверка-корня" --компилятор swift --выход "$рабочий_каталог/проверка-корня.json"
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/test_контрактов_проверок.py
python3 -B -O Приложения/FUMA/Операторы/Лингвистика/проверки/test_контрактов_проверок.py
python3 -B -OO Приложения/FUMA/Операторы/Лингвистика/проверки/test_контрактов_проверок.py
```

`--выход` хранит структурированное наблюдение. Исходные каналы каждого вызова SwiftPM сохраняются только в приватном каталоге работы как `N.stdout` и `N.stderr`; наблюдение содержит их SHA-256. Для публикации наблюдения выбирается явный путь, сырые каналы автоматически в Git не переносятся. Проектные запуски по-прежнему проходят штатную отчётную обёртку текущего Журнала.

### Миграция формата

Начиная со следующего этапа после `0b3edaa1f125e7276b53811bd35a6ecae988a504` помощник выдаёт `fum.проверка-корня-лингвистики.2` и `fum.профиль-корня-лингвистики.2`. Прежние результаты `.1`, отчёты, профили и сырые материалы сохраняются побайтно. Новое основное имя флага — `--компилятор`; опубликованный в указанном коммите `--компилятор-swift` сохраняется как совместимый алиас с тем же значением.

| Поле `.1` | Поле `.2` |
|---|---|
| `stdout_sha256` | `хэш_стандартного_вывода` |
| `stderr_sha256` | `хэш_стандартных_ошибок` |
| `JSON_sha256` | `хэш_канонических_данных` |
| `манифест_sha256` | `хэш_манифеста` |
| `swift` | `версия_компилятора` |
| `argv_одинаков` | `аргументы_одинаковы` |
| `cwd_одинаков` | `рабочий_каталог_одинаков` |
| `разобранный_JSON_равен` | `разобранные_данные_равны` |
| `манифесты_sha256` | `хэши_манифестов` |
| `выход_sha256` | `хэш_результата` |

Алгоритмы значений сохранены: хэши потоков и файлов вычисляются по исходным байтам; хэш данных — по UTF-8-представлению JSON с упорядоченными ключами, без ASCII-экранирования и с разделителями `,` и `:`. Поле `хэш_результата` относится к точным байтам файла `--выход`.

Собственные имена случаев и каталогов также мигрируют: `посторонний-cwd` → `посторонний-каталог`, `настоящий-пакет-из-другого-cwd` → `настоящий-пакет-из-другого-каталога`, `другой-cwd` → `другой-каталог`, `без-gitmodules` → `без-объявления-подмодулей`, `нет-gitmodules` → `нет-объявления-подмодулей`. Точное имя внешнего файла `.gitmodules`, интерфейс SwiftPM и его выходные поля сохраняются.

[Новый этап проверки](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/отчёт.md) хранит адресные записи запусков. Структурированные результаты настоящего SwiftPM сохранены отдельно для [обычного Python после уточнения каталога](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/материалы/проверка-корня-обычная-уточнённая.json), [оптимизации `-O`](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/материалы/проверка-корня-оптимизация.json) и [оптимизации `-OO`](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/материалы/проверка-корня-полная-оптимизация.json). [Первая попытка обычного запуска](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/материалы/проверка-корня-обычная.json) также сохранена. Приватные `stdout`/`stderr` не являются содержимым канонических сырых материалов прежнего среза.

### Ограниченный профиль проверки

Для сравнения изменённой функции `проверить_пакет` сохраните исходный помощник из указанного коммита вне Git и запустите:

```sh
git show 0b3edaa1f125e7276b53811bd35a6ecae988a504:Приложения/FUMA/Операторы/Лингвистика/проверки/проверить-корень-пакета.py > "$рабочий_каталог/помощник-до.py"
python3 -B Приложения/FUMA/Операторы/Лингвистика/проверки/test_контрактов_проверок.py профиль --исходный-помощник "$рабочий_каталог/помощник-до.py" --выход "$рабочий_каталог/профиль-проверки.json"
```

Два прогрева и шесть чередующихся пар используют одну неизменную структуру данных, один процесс и одинаковый уровень оптимизации 0; импорт находится вне замера. [Результат профиля](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/материалы/профиль-проверки-уточнённый.json) сохраняет исходные длительности, хэши кода, сценария и входа. Он измеряет функцию проверки; скорость целого помощника и SwiftPM требует отдельного измерения. Цель этой миграции — корректность отказов при оптимизации Python. Прежний [профиль до устранения машинного пути в тесте](../../../../Журнал/2026-10-08_09-34-19_MSK_исправить-имена-и-проверки-лингвистики/материалы/профиль-проверки.json) сохранён отдельно.
