# GitHub в FUMA

GitHub FUM ведётся через воспроизводимую автоматизацию: сведения о репозиториях, коммитах, задачах, PR, проверках Actions и релизах связываются с памятью проекта. [Поручения](../../Журнал/2026-09-15_22-18-05_MSK_принять-допуск-постоянных-веток/запрос.md) задают направление; адаптер ещё не реализован.

Первый срез читает состояние явно выбранного репозитория и формирует наблюдения общего API структурирующих операторов. Источник, время, версия ответа, пагинация и признаки устаревания сохраняются. Следующий срез добавляет отдельные команды разрешённых изменений с проверяемым исходом. Неизвестный результат сетевой операции не приводит к слепому повтору создания объекта.

Учётные данные передаются адаптеру через приватное окружение исполнения; Журнал содержит допустимые идентификаторы и результаты. Конкретный способ авторизации, разрешения, REST/GraphQL и события выбираются при подготовке первого технического контракта по официальной документации. Эта постановка не выдаёт отсутствие ответа за успех и не заявляет настройки внешней учётной записи.

Код размещается в общем пакете FUMA по назначению компонентов. Для повторяющейся работы готовятся команды, фикстуры, инструкции, TDD и профиль; ручные исключения обозначаются. Управление Git через локальные проверенные команды и наблюдение через GitHub API связываются общими commit OID, но не подменяют друг друга.

Текущие приоритеты — интеграция принятого результата в master и запуск Torrent-направления. Подготовка этого плана не активирует все прежние приостановленные работы.
