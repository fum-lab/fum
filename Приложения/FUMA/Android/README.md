# Android runtime FUMA

Общий Swift-сценарий реально проверен на Android ARM64/API 36: интерпретатор исполняет сохранённое определение UTF-8 → скаляры → UTF-32LE, контейнер сохраняет вход и выход, после закрытия и повторного открытия вход исполняется заново. Три корректных входа совпали с независимым Python-эталоном; четыре некорректных UTF-8 отклонены без контейнера. Целевой минимум бинарника — API 23; запуск на самом API 23 ещё не проверен.

Это консольный runtime. APK, JNI, жизненный цикл приложения и Vulkan не входят в этот срез. Windows-файловый адаптер и проверка iOS sandbox остаются отдельными работами.

## Подготовка

Нужны macOS ARM64, Python 3.10+, Git, curl, pkgutil, unzip и Android SDK с adb. Все команды выполняются из корня FUM. Инициализируйте два закреплённых подмодуля штатной автоматизацией:

```sh
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py init --repo-root . --path Зависимости/swift-crypto
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py init --repo-root . --path Зависимости/swift-asn1
python3 -B Приложения/FUMA/сценарии/подготовить-Android-среду.py --каталог "$FUMA_ANDROID_CACHE"
```

`FUMA_ANDROID_CACHE` задаёт отдельный каталог вне checkout. Установщик загружает три официальных архива по [закреплённым версиям и SHA-256](../сценарии/версии-Android.json), проверяет полные байты до распаковки и подпись pkg, размещает toolchain/NDK в кэше, устанавливает Swift SDK штатной командой. Существующие архивы повторно проверяются; повреждённый файл или незавершённая `.part` останавливают операцию. Уже распакованная среда проверяется по версии, но не проходит полный побайтовый аудит файлов. Профиль подготовки остаётся рядом с кэшем. stdout сообщает пути `swift` и `ndk`; используйте их ниже. Глобальный toolchain Xcode не переключается.

Проверенная пара: открытый Swift 6.4.0 + Swift SDK 6.4.0, NDK r30 `30.0.16248370`. Первоначальная загрузка и распаковка выполнены штатными командами; автоматизированный повтор по готовому кэшу проверен отдельно. Полностью холодный запуск установщика из чистой машины ещё не принят. SDK/NDK остаются под собственными лицензиями; полное зеркало Swift/LLVM не объявляется готовым.

Для эмулятора использован отдельный AVD с образом `system-images;android-36;default;arm64-v8a`. Установите образ через Android SDK Manager, создайте AVD через `avdmanager` из установленного `cmdline-tools` внутри SDK и запустите его. `adb devices` должен показывать конкретное устройство в состоянии `device`. Установка Android SDK, принятие его лицензии и создание AVD не выполняются сценарием проверки автоматически.

## Одна команда сборки и проверки

Задайте `FUMA_SWIFT`, `FUMA_NDK`, `FUMA_ADB` абсолютными путями подготовленной среды, `FUMA_DEVICE` — точным serial собственного эмулятора, `FUMA_ANDROID_CACHE` — кэшем, `FUMA_ANDROID_RESULT` — новым каталогом результатов вне checkout:

```sh
python3 -B Приложения/FUMA/сценарии/проверить-Android-runtime.py \
  --swift "$FUMA_SWIFT" --ndk "$FUMA_NDK" --adb "$FUMA_ADB" \
  --устройство "$FUMA_DEVICE" --кэш "$FUMA_ANDROID_CACHE/build" \
  --выход "$FUMA_ANDROID_RESULT"
```

Сценарий проверяет ABI/API, собирает `сценарий-runtime` в Release для `aarch64-unknown-linux-android23` со статической Swift stdlib, переносит бинарник и `libc++_shared.so` в новый приватный каталог Android, исполняет семь случаев и сравнивает реальные файлы. Для зависимостей задаётся `SWIFTCI_USE_LOCAL_DEPS=1`; внешние Git-загрузки во время сборки не нужны. Сырые логи, профили процессов и runtime-данные сохраняются вне Git. Сборка использует SwiftBuild: native SwiftPM этой версии не передал C-компилятору sysroot в наблюдённом Android-прогоне.

Код 0 и `манифест.json` означают успех всех семи случаев. При отказе сохраняются уже полученные логи и профиль; повтор требует нового каталога результата. `--бинарник` позволяет отдельно проверить уже собранный ELF: манифест явно отмечает этот режим, он не доказывает сборку. Тайм-аут каждого процесса — 600 секунд, меняется через `--тайм-аут`. Удалённые данные и AVD не удаляются автоматически.

В каждой успешной папке результата есть `вход.bin`, `ожидание.bin`, `выход.bin`, `повтор.bin`, `сегмент.fumobs`, `профиль.json`. Полный вызов через adb включает транспорт, запуск и завершение процесса; он не называется временем JNI или чистым временем старта. Внутренние вложенные интервалы не суммируются как независимые затраты.

## Проверки и границы безопасности

```sh
python3 -B -m unittest discover -s Приложения/FUMA/сценарии/проверки
SWIFTCI_USE_LOCAL_DEPS=1 swift test --build-system native --package-path Приложения/FUMA --scratch-path "$FUMA_ANDROID_CACHE/host-tests" --jobs 4
```

Контейнер сохраняет проверки владельца, прав, числа ссылок, `O_NOFOLLOW`, блокировку и `fsync`. Только на Android предки открываются через `O_PATH`: это позволяет проходить закрытый для чтения `/data`; конечный каталог открывается через `O_RDONLY`. ACL и sandbox iOS этим срезом не переопределяются. Процесс запускается от shell-пользователя тестового AVD, не от UID Android-приложения; проверка app sandbox остаётся следующей границей.
