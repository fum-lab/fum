# Повторное объединение Swift-пакетов

[Сценарий объединения](сценарии/объединить-пакеты.py) принимает явно перечисленные собственные пакеты в одном checkout, строит общий manifest и карту перемещений. Это ограниченный профиль SwiftPM: неподдержанная конструкция останавливает планирование. Текущий сложный manifest FUMA с C/system targets требует следующего расширения профиля; автоматизация не объявляется универсальным объединителем любых пакетов.

## Поддержанный профиль

- `// swift-tools-version: 6.0`, `import PackageDescription`, единственное статическое `let package = Package(...)`; произвольный Swift-код не исполняется. Комментарии допускаются, вычисления и условные директивы и соседние `Package@swift-*.swift` — нет.
- Swift 6, совпадающие платформенные минимумы всех входов; обычные Swift `.target`, `.executableTarget`, `.testTarget` с единственным каталогом исходников.
- Имена targets и products сохраняются. `.library` и `.executable` сохраняют состав; внутренняя product-зависимость преобразуется в target только для automatic library с ровно одной целью.
- Ресурсы `.copy` и `.process` поддержаны только для обычных файлов. Имена ресурсов не должны сталкиваться внутри target. Markdown-ресурсы, каталоги ресурсов и локализация отклоняются. Разные targets могут иметь одноимённые ресурсы.
- Зависимости только `.package(path:)`; все такие зависимости должны входить в явный список объединяемых пакетов. Внешний локальный пакет отклоняется, чтобы не оставить неучтённую обратную ссылку на архивируемый manifest. `.product` требует явный `package`; условие `.when(platforms:)` сохраняется. Условия в самих исходниках `#if` остаются байтово неизменными.
- Plugins, macros, binary/system/C targets, удалённые зависимости, настройки компилятора/линкера, `sources`, `exclude` и остальные неизвестные поля требуют отдельного расширения и тестов. Автоматического смыслового разрешения конфликтов нет.

Входные файлы должны быть обычными чистыми отслеживаемыми файлами Git. Символические ссылки, вложенные Git-области, коллизии регистра/NFC, циклы зависимостей, неоднозначные продукты, повторное владение файлами и занятые назначения отклоняются. Индекс и исходные SHA связываются с просмотренным планом. Наследованные `GIT_*` не перенаправляют выполнение в чужое дерево или индекс.

## Вход

Сохраните JSON вне checkout; замените OID и SHA на фактические значения. `назначение` — новый каталог либо один из перечисленных входных пакетов. Общий manifest, если уже существует, должен входить в список. Входных пакетов от 2 до 32; суммарный batch ограничен 1000 перемещениями.

```json
{
  "схема": "fum.объединение-пакетов.1",
  "HEAD": "полный-OID-текущего-коммита",
  "назначение": "Приложения/Общее",
  "имя": "Общее",
  "пакеты": [
    {"корень": "Компоненты/Геометрия", "sha256": "SHA256-его-Package.swift"},
    {"корень": "Компоненты/Палитра", "sha256": "SHA256-его-Package.swift"}
  ]
}
```

План содержит полный будущий `Package.swift`, его SHA, граф, снимки исходников, каталоги назначения и вход готового [batchtool](../../Инструменты/fum-pereimenovaniye-fajla-s-obnovleniyem-ssyilok/SKILL.md). Старые manifests перемещаются без изменения байтов в `Происхождение/пакет-N.swift`; карта сохраняет их прежние пути. Остальные файлы вне target-каталогов, например README, остаются на месте. Порядок пакетов задаёт номера архивов.

## Последовательность

Команды выполняются из корня FUM; `КОРЕНЬ` задаёт физический корень обрабатываемого Git checkout. `ВХОД`, `ПЛАН`, `ПЕРЕНОС` — абсолютные пути внешних JSON-файлов. Для применения прочитайте весь план и его SHA, затем весь план ссылок. Хэши не заменяют смысловой просмотр.

```sh
python3 -B Приложения/FUMA/сценарии/объединить-пакеты.py план \
  --корень "$КОРЕНЬ" --вход "$ВХОД" > "$ПЛАН"

python3 -B Приложения/FUMA/сценарии/объединить-пакеты.py каталоги \
  --корень "$КОРЕНЬ" --вход "$ПЛАН" --sha256 "$ХЭШ_ПЛАНА"

python3 -B Приложения/FUMA/сценарии/объединить-пакеты.py план-переноса \
  --корень "$КОРЕНЬ" --вход "$ПЛАН" --sha256 "$ХЭШ_ПЛАНА" > "$ПЕРЕНОС"

python3 -B Приложения/FUMA/сценарии/объединить-пакеты.py перенести \
  --корень "$КОРЕНЬ" --вход "$ПЛАН" --sha256 "$ХЭШ_ПЛАНА" \
  --перенос-sha256 "$ХЭШ_ПЕРЕНОСА"

python3 -B Приложения/FUMA/сценарии/объединить-пакеты.py завершить \
  --корень "$КОРЕНЬ" --вход "$ПЛАН" --sha256 "$ХЭШ_ПЛАНА"
```

`каталоги` создаёт только пустые каталоги после повторной проверки плана. `перенести` вызывает прежний batchtool с отдельным просмотренным SHA: Git mv и обновление Markdown-ссылок имеют его прежние проверки и откат. `завершить` проверяет байты, режимы и индекс всех перемещённых файлов, отсутствие прежних путей и полный инвентарь итоговых target-каталогов, затем устанавливает новый manifest без перезаписи существующих иных байтов.

Это несколько стадий, а не единая атомарная транзакция. Если процесс прервался после успешного переноса, повторите `завершить` с прежним планом. Повтор успешного `завершить` допускается до изменения HEAD, если итоговые байты и инвентарь совпадают. Повтор `перенести` после успешного переноса не нужен и закрыто отклоняется. Частично изменённое либо неподтверждённое состояние требует разбора сохранённых свидетельств; автоматического восстановления догадками нет. Пустые созданные каталоги могут остаться после отказа.

Новый manifest не добавляется в индекс автоматически. После просмотра exact diff выполните применимые сборки и тесты, оформите Журнал и коммит по правилам своей задачи. Изменение HEAD, исходников, инструмента или индекса до переноса требует нового плана. Публикация, разрешение конфликтов между ветками и интеграция не входят в этот сценарий.

## Проверка на другом наборе

[Открытые тесты](сценарии/проверки/test_объединение_пакетов.py) создают независимые пакеты Геометрия, Палитра и Рисунок. [Профиль](сценарии/проверки/профиль_объединения.py) собирает XCTest и CLI до/после, проверяет ресурсы, вывод, перенос ссылок и повтор установки.

```sh
python3 -B -m unittest discover -s Приложения/FUMA/сценарии/проверки -p test_объединение_пакетов.py
python3 -B Приложения/FUMA/сценарии/проверки/профиль_объединения.py --выход "$ПРОФИЛЬ"
```

Сборки измеряются отдельно от планирования/переноса. Временные репозитории и сборки находятся вне FUM; профиль не является доказательством поддержки всех конструкций SwiftPM или ускорения любого переноса.
