# Подготовить ARM64-инструменты Windows

План предназначен для существующей Windows 11 ARM64 в Parallels. Он подготовлен к согласованию окна установки; установщики не запускались. Текущая независимая работа ограничена диагностикой и сборочной оболочкой. Полностью закреплённый установочный комплект ещё не получен.

## Ресурсы и область изменения

Гостевое чтение 15 сентября 2026 года показало 4 логических процессора, 17173250048 байтов RAM, системный том 273260998656 байтов и 235195060224 свободных байта. Значения относятся к моменту чтения; доступность диска хоста и рост динамического диска VM требуют повторной проверки перед загрузкой.

Для первого среза предлагается зарезервировать **100 ГиБ свободного гостевого и физического хостового диска** под offline-комплект, установленный toolchain, чистый клон FUM и отдельный SwiftPM-кэш. Это бюджет проекта, а не измеренный размер выбранных пакетов. Microsoft указывает 20–50 ГБ для типичной Visual Studio, фактический размер зависит от компонентов. Минимум RAM — 4 ГБ, рекомендация Microsoft — 16 ГБ; наблюдавшаяся VM примерно соответствует рекомендуемой памяти. Полный layout всех компонентов не нужен.

Выделить новый каталог `FUMA-Windows-01a0a633` на локальном гостевом диске, вне существующих рабочих каталогов: `installers`, `layout-vs2022`, `source`, `cache`, `container`, `result`. Абсолютный путь выбирается после согласования и остаётся приватным параметром. Компоненты Visual Studio и SDK также меняют системные каталоги и реестр: отдельная папка не изолирует эти системные эффекты. Сборочная оболочка получает каждый путь явно и требует новые непересекающиеся каталоги данных вне checkout.

## Предлагаемый комплект

| Компонент     | Закрепляемый выбор                                                                                     | Что ещё требуется                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Swift         | Официальный Windows ARM64 6.3.3 RELEASE                                                                | SHA-256 и Authenticode конкретного полученного EXE; точная `compilerVersion` после установки                            |
| Visual Studio | VS 2022 Community, компоненты C++ ARM64 и x64/x86                                                      | Согласованная применимость лицензии; точный выпуск bootstrapper и сохранённый channel/catalog layout                    |
| MSVC          | `Microsoft.VisualStudio.Component.VC.Tools.ARM64`, `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` | Фактические package versions/hashes из закреплённого layout                                                             |
| Windows SDK   | `Microsoft.VisualStudio.Component.Windows11SDK.22621`                                                  | Полный servicing-выпуск и package hashes                                                                                |
| Git           | Git for Windows                                                                                        | Закреплённые версия, архитектура, подпись/хэш установщика                                                               |
| Python        | 3.10.x по инструкции Swift; Python 3.10+ для собственной оболочки                                      | Проверка доступного выпуска и архитектуры, совместимости зависимостей Swift/LLDB; не подменять её версией Python на Mac |

Официальная [ссылка выбранного Swift ARM64 6.3.3](https://download.swift.org/swift-6.3.3-release/windows10-arm64/swift-6.3.3-RELEASE/swift-6.3.3-RELEASE-windows10-arm64.exe) взята из страницы установки. EXE пока не скачан, размер, подпись и SHA неизвестны. Страница также предлагает более новый Swift; обновление выбранного профиля должно быть явным. Совместимость общего ядра проверяется сборкой, а не номером выпуска.

## Последовательность воспроизведения после согласования

1. Повторить диагностику, подтвердить владельца окна VM, ресурсы обоих дисков и выбранную учётную запись. Сохранить публикационно чистые результаты. Отдельно прояснить `LicenseStatus=5`; активация и права использования не следуют из наличия работающей ОС.
2. Получить из официальных источников конкретный bootstrapper VS 2022 и Swift EXE. До запуска проверить Authenticode и SHA-256; записать версии, итоговые URL и хэши. Непроверенные байты не считать готовым комплектом.
3. Создать ограниченный offline-layout VS внешней командой ниже. Сохранить channel/catalog и хэши всего layout вне Git. Повтор должен использовать этот комплект с запретом догрузки, а не изменяемую сетевую ссылку bootstrapper. `--verify` проверяет сохранённый layout. Точные размеры измеряются после получения; недостаточный диск останавливает подготовку.
4. Установить согласованные компоненты из layout, затем проверенные Python/Git и Swift. Developer Mode требуется официальной инструкцией Swift; это отдельное системное изменение в согласованном окне. Не включать лишние workloads, не менять ресурсы VM и не перезагружать чужую работу автоматически.
5. После установки записать `swift --version`, `swift -print-target-info`, `git --version`, версию Python, установленный MSVC/SDK и исходные хэши. Целевой triple — `aarch64-unknown-windows-msvc`. Windows x64 требует отдельного профиля и отдельного испытания.
6. Получить чистый FUM на принятом полном OID общего ядра и Windows-адаптера, с объявленными зеркалами и лицензиями. Выполнить [сборочную оболочку](README.md) сначала как план, затем нативно; сохранить тесты, оба точных выхода и профиль. На этом шаге проверяется полезный сценарий, а не только установка компилятора.

Пример внешнего интерфейса VS Installer; `<каталог-layout>` заменяется согласованным абсолютным путём. Эти команды здесь не исполнялись:

```text
vs_community.exe --layout <каталог-layout> --lang en-US --add Microsoft.VisualStudio.Component.VC.Tools.ARM64 --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.Windows11SDK.22621
vs_community.exe --layout <каталог-layout> --verify
```

Окончательные installPath и команда установки без сети формируются из полученного layout и закреплённого bootstrapper. Пока их нет, нельзя утверждать побайтовую воспроизводимость установки или выбранный размер загрузки. Лицензии и общие контракты этим планом не изменяются.

## Конкретные препятствия первому build

- Не согласовано окно системной установки в используемой VM; координатор явно оставил тяжёлый toolchain вне текущего исполнения.
- Swift/MSVC/SDK/Git/Python не подтверждены в используемом гостевом окружении. Публикационно допустимого манифеста установщиков ещё нет.
- Не доставлен принятый Windows-совместимый общий пакет. Контейнер Android использует `openat`, `pread`, `flock`, POSIX-права и `fsync` каталогов; заглушка или удаление этих гарантий не заменяют Windows-адаптер.
- Состояние активации — Notification, права лицензий не подтверждены. Покупка и активация не выполняются.
- Для GUI отдельно нужны действующий Vulkan ICD/устройство и проба Win32 surface; loader DLL уже обнаружен, графический сценарий ещё не испытан.
