# Проверка четырёх пакетов FUMA

Проверка выполняется из корня чистого клона FUM на Mac с установленным Swift. Пакеты используют Swift tools 6.0 и язык Swift 6; в манифестах объявлена macOS 14. Наблюдённая приёмка выполнена на macOS 27 arm64 с Apple Swift 6.4. Она подтверждает эту среду, а поддержка других платформ требует отдельной проверки.

Собственные зависимости заданы относительными путями соседних пакетов. У контейнера нет пакетных зависимостей; снимок и статистика зависят от контейнера, архив — от снимка и контейнера. Сетевые SwiftPM-зависимости, libmpv и LinguisticKit для этих четырёх сборок не нужны. Связи с macOS-приложением в исходной реализации не было, перенос её не добавляет.

## Сборки и тесты

Из корня клона выполните последовательно:

```sh
FUM_PACKAGES="$PWD/Приложения/FUMA/Packages"
for FUM_PACKAGE in КонтейнерНаблюдений СнимокАгентскойЗадачи СтатистикаВызовов АрхивныйСнимокЗадачи; do
    swift test --package-path "$FUM_PACKAGES/$FUM_PACKAGE" --build-system native --jobs 2 || exit
    swift build --package-path "$FUM_PACKAGES/$FUM_PACKAGE" --build-system native --jobs 2 -c release || exit
done
```

В проверенной среде применён backend `native`; Swift 6.4 предупреждает о его устаревании. Отдельный scratch-каталог здесь не задаётся: имеющиеся процессные тесты находят собственные вспомогательные продукты в `.build/debug` пакета. Этот каталог игнорируется Git. Код возврата любой команды должен быть нулевым; результаты Swift Testing и XCTest учитываются отдельно, поэтому служебная строка о нуле тестов одного фреймворка не отменяет тесты другого.

При миграционной приёмке все процессы дополнительно запускались внутри системной песочницы с запретом чтения прежнего каталога исходников. Работоспособность запрета проверена реальным отказом чтения существующего файла. SwiftPM получал `--disable-sandbox` только внутри этой внешней песочницы. Машинный профиль ограничений и абсолютные местоположения не являются входами обычной сборки; публичные [свидетельства клона](../../Журнал/2026-09-11_01-56-50_MSK_проверить-пакеты-FUMA-из-клона/материалы/чистый-клон.json) фиксируют результат и границу проверки.

## Синтетические профили

После Release-сборки создайте отдельный временный корень. Профили получают только созданные ими открытые синтетические данные. Каталог архива должен отсутствовать перед его запуском, остальные три каталога создаются заранее.

```sh
FUM_PROFILE_ROOT="$(mktemp -d)"
FUM_PROFILE_ROOT="$(cd "$FUM_PROFILE_ROOT" && pwd -P)"
mkdir "$FUM_PROFILE_ROOT/container" "$FUM_PROFILE_ROOT/snapshot" "$FUM_PROFILE_ROOT/statistics"

"$FUM_PACKAGES/КонтейнерНаблюдений/.build/release/профиль-контейнера" записать "$FUM_PROFILE_ROOT/container" 8 65536
"$FUM_PACKAGES/КонтейнерНаблюдений/.build/release/профиль-контейнера" восстановить "$FUM_PROFILE_ROOT/container"
"$FUM_PACKAGES/СнимокАгентскойЗадачи/.build/release/снимок-задачи" профиль "$FUM_PROFILE_ROOT/snapshot" 32
"$FUM_PACKAGES/СтатистикаВызовов/.build/release/статистика-вызовов" профиль --выход "$FUM_PROFILE_ROOT/statistics" --размер малый
"$FUM_PACKAGES/АрхивныйСнимокЗадачи/.build/release/профиль-архивного-снимка" "$FUM_PROFILE_ROOT/archive" 1000000 --служебные-оболочки
```

Запускайте каждый следующий профиль только после нулевого кода предыдущего. Профиль архива намеренно удаляет собственный синтетический вход перед восстановлением без источника. Он не предназначен для переданного реального пользовательского журнала. Профиль снимка называет стадию построения снимка в памяти «чистая-сборка»; это не компиляция Swift.

Вывод содержит длительности и контрольные показатели. Для контейнера сравниваются хэши до и после восстановления; снимок подтверждает нулевой прирост хранения при повторах; архив сравнивает результат первого импорта, двух повторов и восстановления без источника. Временные результаты остаются вне Git. Повтор профиля выполняется с новым корнем.

## Наблюдённый результат

На публичном коммите `aeae18cb146a34563ff39c84d9bc5ef59fffab91` прошли 133 теста: контейнер — 28, снимок — 35, статистика — 35, архив — 35. Все четыре Release-сборки успешны. Восемь запусков заняли 113,59 с по системному `time`; наибольший максимальный RSS составил 599 212 032 байта. В эти значения входит работа сборщика, поэтому они не описывают память работающей библиотеки.

Пять небольших профилей показали максимальный RSS процессов от 7 372 800 до 12 451 840 байт. Вход контейнера — 512 КиБ, снимка — 32 наблюдения, статистики — 32 вызова, архива — 1 МБ служебных оболочек. Это отдельные наблюдения с тёплым файловым кэшем, без заявления о предельной нагрузке или статистической устойчивости времени. Перенос не менял исполняемые байты пакетов; новая оптимизация им не требовалась.

Полные значения и ограничения сохранены в [отчёте проверки](../../Журнал/2026-09-11_01-56-50_MSK_проверить-пакеты-FUMA-из-клона/отчёт.md), [результатах сборок и тестов](../../Журнал/2026-09-11_01-56-50_MSK_проверить-пакеты-FUMA-из-клона/материалы/проверки-пакетов.json) и [метриках профилей](../../Журнал/2026-09-11_01-56-50_MSK_проверить-пакеты-FUMA-из-клона/материалы/метрики-работы-пакетов.json). Бинарники остаются вне Git; их хэши обозначают проверенные продукты, а не обещание детерминированной побайтной сборки на другой машине.
