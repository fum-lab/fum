# Синтетический снимок агентской задачи

Библиотека и CLI первого ограниченного сегмента FUM-STEP-0159. Они воспроизводят записанный конечный сценарий, сохраняют каждое наблюдение и переход в принятом контейнере и восстанавливают снимок новым экземпляром или процессом. Сборщиков живых данных здесь нет.

[Записанный пример](Примеры/пять-сценариев.json) содержит 18 синтетических наблюдений пяти предметных сценариев. Его байты сверяются тестом с генератором `примерСценария()`. JSON и Markdown строятся из одного `Снимок`; Markdown не интерпретирует HTML, ссылки и разметку исходных свидетельств.

## Запуск

Из корня этого внешнего Swift-репозитория:

```sh
swift build --package-path Packages/СнимокАгентскойЗадачи --build-system native --jobs 2 -c release
FUM_SNAPSHOT_DIR="$(mktemp -d /private/tmp/fum-snapshot.XXXXXX)"
Packages/СнимокАгентскойЗадачи/.build/release/снимок-задачи собрать "$PWD/Packages/СнимокАгентскойЗадачи/Примеры/пять-сценариев.json" "$FUM_SNAPSHOT_DIR" json
Packages/СнимокАгентскойЗадачи/.build/release/снимок-задачи восстановить "$FUM_SNAPSHOT_DIR" синтетический-codex стенд задача-1 markdown
```

Команды CLI:

- `пример` — канонический JSON записанного сценария в stdout.
- `собрать <абсолютный-вход.json> <абсолютный-корень> <json|markdown>` — полный preflight, сохранение и снимок. Повтор того же сценария не добавляет записи, но повторяет успешный fsync.
- `восстановить <абсолютный-корень> <поставщик> <хост> <ID-задачи> <json|markdown>` — только чтение. Исходный сценарий не нужен; ожидаемая идентичность проверяется по сохранённым наблюдениям.
- `профиль <новый-абсолютный-корень> <1..256>` — конечная синтетическая нагрузка, чистая сборка, запись, replay и 32 повтора. Корень уже должен существовать и не содержать наблюдений.

Корень данных — существующий физический каталог владельца без символических ссылок и групповой/общей записи. Ошибка даёт код 2 и stderr; успешный снимок не печатается до сохранения. CLI не читает окна, JSONL Codex или системные источники и не запрашивает полномочия.

## Значение снимка

Каждое наблюдение содержит версию, устойчивый ID, составную задачу, канал и экземпляр источника, логический такт и срок, охват, область, исходный синтетический факт и типизированное содержание. Это единые логические часы сценария, не синхронизированные часы реальных API и не атомарный снимок ОС.

Знание поля — неизвестность, согласованное значение или противоречие. Свежесть вычисляется отдельно для каждого кандидата: конфликт может одновременно устареть. Повтор ID не меняет такт или срок. Все исходники остаются доступны по ID, включая замещённые и проигнорированные наблюдения.

| Поле / факт | Допустимые каналы и смысл |
| --- | --- |
| Желаемая модель | Настройка или интерфейс; не доказывает фактическую модель |
| Наблюдённая модель | Журнал или интерфейс; обязательный контекст конкретного хода |
| Runtime cwd | Журнал; отдельное поле задачи |
| Cwd команды | Команда; обязательный ID команды в контексте |
| Назначенный worktree | Настройка; запуск команды в другом cwd не меняет владение |
| Ветка | Журнал или команда; контекст дерева обязателен |
| Существование, текущая работа, ожидание | Журнал, API или интерфейс |
| Ожидание | Значения: нет, пользователь, полномочия, процесс, другая-задача |

Модель прошлого хода не переносится на новый ход и не объявляется активной без свидетельства. Значение текущей работы не закрывает пользовательское обязательство. Поля без свидетельств перечисляются явно; запрос неизвестного контекста возвращает неизвестность.

Отсутствие задачи в **любом** списке, даже объявленном полным, означает только «не перечислена в этой области ответа». Для отрицания существования нужно отдельное явное свидетельство. Положительное свидетельство списка в v1 нельзя заменить через `заменяет`; позднее отрицание остаётся видимым конфликтом, при необходимости устаревшим.

Явное замещение разрешено только для активного значения того же поля, контекста, источника и области. Разные источники не разрешают конфликт порядком поступления.

## Команда, эффект, отказ

Намерение, отправка и транспортное принятие — отдельные фазы, но ни одна не подтверждает UI-эффект. Фазы сохраняют первоначальные источник, область, ожидаемый эффект и основание.

Подтверждение требует более позднего свидетельства канала интерфейса с совпадающими задачей, областью, операцией и эффектом. Корректировка дополнительно ссылается на прежнее типизированное `расхождение` той же области с тем же ожидаемым результатом. Только после UI-подтверждения она становится последней подтверждённой корректировкой. Это историческое подтверждение, не обещание неизменности интерфейса после него.

Отказ действует на **весь канал**, включая новые экземпляры. Последующие наблюдения этого канала сохраняются как проигнорированные и не дают новых значений или подтверждений. Прежние свидетельства остаются историей и могут устаревать. Автоматического повторного получения полномочий или обхода отказа нет.

Источники синтетические и заявлены входом; проверка SHA-256 обеспечивает целостность воспроизведения, но не аутентичность внешнего факта.

## Байты, идентичность и формат v1

Сериализация — точный JSON `JSONEncoder` с `sortedKeys` и `withoutEscapingSlashes`, допустим один завершающий LF. Это ограниченный протокол, не общий RFC 8785: иной порядок/пробелы, неизвестные и повторные ключи, усечение и неизвестная версия отклоняются.

**Payload не нормализуется.** Исходные UTF-8-последовательности строк, включая NFC/NFD и `Наблюдение.задача`, сохраняются. Побайтовое равенство сериализованного наблюдения обязательно для retry; обычный Swift `String ==` / `Equatable` недостаточен. Другой payload с тем же ID — конфликт.

Только `Снимок.задача` использует явно названное `нормализованнаяИдентичность` (NFC). Три компонента машинного ключа ограничены до и после преобразования: по 128 байтов; после него допустимы Unicode-буквы, десятичные цифры и `._:-`. Остаточные combining marks, emoji и подписи интерфейса не являются идентификаторами v1. Это предотвращает неоднозначную обработку патологических combining-последовательностей; не меняет исходный payload. Кириллический NFC/NFD-ключ проверяется отдельным тестом; сохранение NFD-payload — процессным replay.

Пределы: 256 наблюдений, 4 МиБ входа, глубина JSON 12, 16 КиБ наблюдения, 32 КиБ контейнерного объекта, 8 экземпляров источников, 64 пары поле/контекст, 16 UI-операций, до 16 ссылок замещения; обычная строка до 1024 байтов, исходный факт до 8192. Структурные и скалярные проверки идут до промежуточного кодирования наблюдения.

При открытии существующего файла контейнер сначала сканирует его по собственным принятым пределам (256 МиБ сегмента, 4096 записей). Лишь затем оболочка применяет меньшие пределы снимка. Это не обещание сканирования произвольного чужого контейнера в пределах 4 МиБ входа. Диагностическое чтение профиля имеет отдельный cap 16 МиБ.

## Хранение и строгая Concurrency

Актор единолично владеет синхронным non-Sendable контейнером. Между редукцией, записью и публикацией снимка нет `await`; контейнер наружу не передаётся, `unchecked Sendable` отсутствует.

На событие приходится один атомарный объект: исходное наблюдение, версия редуктора, номер перехода и SHA-256 снимков до/после. Replay вычисляет переход заново и побайтово сверяет метаданные и конверт. Хэш до следующего перехода повторно используется только из уже вычисленного и проверенного предыдущего хэша после.

Повтор ID распознаётся до редукции и повторяет успешную синхронизацию исходных байтов. После неопределённой ошибки записи актор требует закрытия/replay; видимость записи на диске сама по себе не даёт успешного ack. Отказ режима только чтения не повреждает возможность чтения.

Сценарий предварительно проверяется целиком, но атомарность сохраняется **по событию**, не по всему сценарию: I/O-сбой может оставить подтверждённый префикс. Неполный хвост, повреждение, чужая идентичность, неизвестная версия или неверный переход дают отказ; автоматического ремонта и миграции нет.

## Проверки и профиль

`swift test --package-path Packages/СнимокАгентскойЗадачи --build-system native --jobs 2`

На стенде Apple Swift 6.4, языковой режим Swift 6, macOS arm64. Native backend — временная граница стенда из-за кодовой подписи кириллического XCTest bundle в другом backend; SwiftPM сообщает его deprecated-статус.

Профиль на 256 наблюдениях до ограниченного повторного использования проверенного хэша: чистая сборка около 20 мс, запись 1,11–1,14 с, replay 1,06–1,09 с. После — запись около 0,65 с, replay 0,58–0,59 с. Вход 297121 байт, контейнер 597922 байта, 32 повтора дают нулевой прирост; SHA-256 снимка и файла совпадают до/после. Профиль локальный, без SLA и без доказательства холодного дискового кэша. Финальные записи и хэши исходников передаются в отдельном FUM Журнале.

Принятый пакет `КонтейнерНаблюдений` не изменён. Новый экземпляр и процесс не доказывают устойчивость к перезапуску ОС или потере питания. Полные FUM-STEP-0159, FUM-STEP-0156 и FUM-REQ-0044 этим синтетическим сегментом не закрываются.
