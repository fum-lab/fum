# Каналы МАКС

Локальный Swift-пакет подготавливает текстовый пост и подписку Bot API, разбирает события каналов и проверяет исход публикации через подменяемый транспорт. Он предназначен для первого автономного среза FUMA. Реальный HTTP-исполнитель, токен, Webhook-сервер и подключение интерфейса FUMA пока отсутствуют.

## Проверить сценарии

Из корня FUM с установленным Swift 6 выполните:

```sh
swift test --package-path Приложения/FUMA/Packages/КаналыМАКС --scratch-path /tmp/каналы-макс-сборка --jobs 2
```

Для воспроизведения профиля на тех же сценариях:

```sh
FUM_MAX_PROFILE=/tmp/каналы-макс-профиль.json swift test --package-path Приложения/FUMA/Packages/КаналыМАКС --scratch-path /tmp/каналы-макс-сборка --jobs 2
```

Переменная `FUM_MAX_PROFILE` — интерфейс запуска из POSIX-оболочки; ASCII нужен синтаксису присваивания. В PowerShell задайте её через `$env:FUM_MAX_PROFILE` и передайте собственные внешние пути к профилю и сборке. Это инструкция воспроизведения, запуск Windows пока не подтверждён. Обычный набор не создаёт файл профиля. В контролируемой сессии FUM обе команды выполняются через отчётную обёртку.

Успех означает прохождение локальных синтетических сценариев. XCTest может напечатать ноль тестов; фактический набор выполняет Swift Testing, итог — 12 тестов. Профиль измеряет отдельно 100 000 решений ограничителя и 10 000 повторно доставленных событий, исключая сборку. Проверки одновременно контролируют число принятых запросов и повторов.

## Подготовка и отправка

`ПодготовленныйЗапрос.публикация` принимает Int64 идентификатор канала и непустой текст до 4000 Unicode scalar. Такой подсчёт консервативен для составных символов. Получается `POST /messages?chat_id=…`, JSON с `text` и `notify=true`, Content-Type и отдельный признак необходимости авторизации. Секрета в запросе нет. Host закреплён как `platform-api2.max.ru`.

`подписка` готовит `POST /subscriptions` для `bot_added`, `bot_removed`, `chat_title_changed`. Принимается HTTPS-URL без явного порта, credentials и fragment. Проверка формы URL не удостоверяет доступность, TLS-сертификат или владение доменом. Необязательный секрет Webhook в этом срезе не создаётся; перед live-подключением его поддержку и проверку входящего заголовка нужно реализовать отдельно.

`АдаптерКаналов` получает реализацию `ТранспортКаналов`. Сначала вызовите `подготовить` со стабильным идентификатором операции, затем `отправить` с монотонным временем в секундах. Один actor обслуживает одного бота. Встроенный ограничитель удерживает скользящее окно: 30 обращений за секунду всего и два поста в один канал. Отказ лимита сохраняет `подготовлено`; последующий явный вызов после освобождения окна может исполнить эту ещё не отправлявшуюся операцию. Сам ограничитель также доступен для будущего общего учёта других методов. Отдельные экземпляры или внешние отправители одного бота должны разделять общий лимит; сейчас они не координируются.

История различает:

- `подготовлено` — запрос собран;
- `отправлено` — начался вызов транспорта, принятие сервером неизвестно;
- `подтверждено(mid)` — получены HTTP 200, непустой `message.body.mid` и совпадающий `message.recipient.chat_id`;
- `неизвестно` — тайм-аут, потеря ответа, ответ 5xx, повреждённое или чужое подтверждение;
- `отказАвторизации` — HTTP 401/403;
- `отклонено(код)` — другой HTTP 4xx, включая 429.

Повтор того же идентификатора после начала вызова транспорта ничего не отправляет, включая повторный вход во время ожидания. Автоматического retry нет. Подтверждение API не доказывает прочтение поста человеком. После 429 или отказа авторизации требуется решение вызывающего слоя; создание нового идентификатора может породить другую публикацию и не служит безопасным retry неизвестной операции.

## События и границы хранения

`СобытиеКанала` типизирует внешний JSON; `РеестрКаналов` принимает синтетические байты. `bot_added` с `is_channel=true` создаёт канал; группа не становится каналом. Изменение названия и удаление применяются только к уже известному каналу. Более старый timestamp не отменяет новое состояние; при одинаковом timestamp сохраняется порядок поступления. Событие добавления не подтверждает права публикации.

Дедупликация учитывает канонический JSON целиком, поэтому перестановка полей не создаёт новый экземпляр. Окно ограничено 1024 событиями по умолчанию; после вытеснения повтор может снова обрабатываться. Неизвестный тип возвращается явно, не интерпретируется как команда и не публикует ответ. Повреждённое известное событие отклоняется ошибкой до регистрации повтора. Вызывающий слой отвечает за сохранение исходных байтов и доказательство подлинности входа.

История операций, каналы и дедупликация существуют только в памяти. Перезапуск теряет их. До реального запуска нужны долговечное хранилище операций и входов, восстановление, проверка секретного заголовка Webhook, общий лимит всего бота, ограничение размера входа, проверка прав и каналов. Эти обязанности не объявляются выполненными локальными тестами.

Ядро импортирует только Foundation; внешних пакетных зависимостей, AppKit и Metal нет. Платформенный транспорт должен добавлять `Authorization: <token>` только перед реальным HTTPS-вызовом и сохранять неизвестный исход при неопределённости. Проверку доверия TLS отключать нельзя. В этом этапе реально проверена только macOS arm64 с Apple Swift 6.4; Android и Windows требуют отдельных целевых сборок и запусков.

## Основания и статус

[Обзор Bot API](../../../../Источники/URL/https/dev.max.ru/docs-api/source-index.md) и [подготовка бота](../../../../Источники/URL/https/dev.max.ru/docs/chatbots/bots-coding/prepare/source-index.md) архивированы 15 сентября 2026 года. Bot API действует от имени бота; Open Client API — отдельный режим, здесь не выбран. Создание и модерация бота, верификация профиля организации и реальный канал не подтверждены. `GET /chats` больше не используется; канал поступает из событий. Production требует Webhook, HTTPS на 443 без явного порта, доверенного сертификата и ответа HTTP 200 в течение 30 секунд. События могут доставляться повторно.
