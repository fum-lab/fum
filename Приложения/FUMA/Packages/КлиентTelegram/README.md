# Автономный клиент Telegram

Swift 6 пакет первого клиента FUMA для macOS arm64. Сейчас подтверждён синтетический контур через продукционные очередь, ядро и сериализатор. Настоящая загрузка TDLib и её профиль ещё не выполнены; полный сборочный комплект не готов. Это продолжающаяся реализация [FUM-STEP-0222](../../../../Планирование/карточки-шагов/🟡-FUM-STEP-0222-реализовать-Swift-клиент-TDLib-и-синтетический-контур-каналов-FUM.md).

## Собрать собственный код

Из корня FUM на macOS с Swift 6:

```sh
python3 -B Приложения/FUMA/Packages/КлиентTelegram/Проверки/проверить-пакет.py --кэш /tmp/fum-telegram-swift
swift build --build-system swiftbuild --package-path Приложения/FUMA/Packages/КлиентTelegram --scratch-path /tmp/fum-telegram-swift --jobs 1 -c release
swift build --build-system swiftbuild --package-path Приложения/FUMA/Packages/КлиентTelegram --scratch-path /tmp/fum-telegram-swift -c release --show-bin-path
```

Последняя команда показывает каталог исполняемого файла `проверить-telegram`. Пакет зависит только от соседнего собственного `КонтейнерНаблюдений`; SwiftPM не загружает TDLib. Последний проверенный профиль использует macOS 27.0 (26A428), Command Line Tools for Xcode 27.0 beta 6, SDK 27.0 (26A5419a) и Swift 6.4 (swiftlang-6.4.0.33.1). Прежний Xcode после обновления отсутствует. Исполнитель проверки получает developer directory через xcode-select, проверяет установленный Swift Testing и передаёт его пути только дочерней команде; неполный комплект или ссылки за пределы developer directory отклоняются. Процедура подтверждена для Swift Testing и не доказывает XCTest. После дочернего процесса исполнитель выводит в stderr JSON `fum.исход-проверки-пакета.1`: обычный код сохраняется, сигнал возвращает код `128 + номер` и отдельные поля с исходным отрицательным кодом и номером сигнала. Поэтому SIGTERM различим с обычным выходом 143 по JSON. Внешняя отчётная обёртка видит 143 как обычный неуспех; прозрачная передача POSIX-сигнала ей не заявлена. Произвольный `--пакет` не получает гарантии автономности: SwiftPM может получать его внешние зависимости; проверенный местный граф этого клиента не распространяется на другие манифесты. Минимум macOS 15 в Package.swift не означает, что эта ОС отдельно проверена.

## Автономная команда

В каталоге собранных исполняемых файлов:

```sh
./проверить-telegram --help
./проверить-telegram --библиотека /абсолютный/путь/libtdjson.dylib --простой-секунд 15
```

Для второго запуска нужна отдельно собранная TDLib с закреплённого коммита `d1085f9cebc5a62379991ae1652673954f229c1f`, доступного через gitlink [Зависимости/TDLib](../../../../Зависимости/TDLib). Инструкция полного воспроизводимого комплекта ещё готовится: OpenSSL не принят после отказов полного клонирования, установленный CLT относится к beta 6, отдельные условия его SDK и право передачи полного комплекта ещё не подтверждены. Прежняя seed-лицензия macOS не переносится на обновлённую ОС. Установленная библиотека Homebrew сама по себе этот пробел не закрывает.

Команда загружает современные `td_create_client_id`, `td_send`, `td_receive`, создаёт клиента, ожидает коррелированный ответ `getAuthorizationState` со значением `authorizationStateWaitTdlibParameters`, измеряет простой и выполняет `close` с ожиданием фактического `Closed`. Параметры приложения, телефон и вход в аккаунт этому сценарию не нужны. До настоящего запуска утверждение об отсутствии обращений библиотеки к сети остаётся непроверенной границей.

Успех возвращает код 0 и JSON `fum.автономный-запуск-телеграма.1`; ошибка — код 2 и ограниченный код причины. Отсутствующие измерения не заменяются нулями. Измерение простоя включает процессорное время всех потоков и выборки RSS раз в секунду; две начальные секунды прогрева, запуск и закрытие исключены из CPU/wall интервала. Пиковый RSS относится ко всему процессу с момента его старта. Сетевая задержка этим измерением не определяется.

При ошибке приватный каталог незавершённого запуска остаётся на диске, его путь выводится в stderr. В нём находятся журнал и отдельный случайный ключ; вместе они позволяют прочитать сохранённое состояние. Эти данные нельзя публиковать. После проверенного чистого закрытия временный каталог удаляется. Проверка флагов и отсутствующей библиотеки доступна в [Проверки/проверить-команду.py](Проверки/проверить-команду.py), ей передаётся абсолютный путь исполняемого файла.

## Синтетические измерения

Собранная Release-команда запускает конечные профили без библиотеки TDLib:

```sh
./проверить-telegram --профиль поток --кадров 1000
./проверить-telegram --профиль отмена --повторов 30
```

[Проверка команды](Проверки/проверить-команду.py) принимает абсолютный путь этого исполняемого файла; добавление `--измерить` запускает оба профиля в отдельных процессах с внешним тайм-аутом 45 секунд и выводит объединённый JSON. Сборка и запуск измеряются отдельно. [Сохранённый профиль](Профили/README.md) содержит результаты, хэши, границы измерения и решение об оптимизации.

Поток проходит копирование C-байтов, очередь и настоящее ядро с AES-GCM и журналом; генератор создаёт два вымышленных аккаунта. Задержка передачи включает ожидание обратного давления. Отмена проверяет кооперативный обработчик и весь четырёхкадровый хвост, без обещания принудительно прервать файловую синхронизацию. Сквозное сохранение аварийного хвоста фасадом и восстановление ядра проверены отдельными процессами; реальный idle TDLib остаётся в приёмке.

## Сквозной хвост и восстановление

Из корня FUM передайте абсолютный путь собранной Release-команды:

```sh
python3 -B Приложения/FUMA/Packages/КлиентTelegram/Проверки/проверить-восстановление.py /путь/проверить-telegram
python3 -B Приложения/FUMA/Packages/КлиентTelegram/Проверки/измерить-восстановление.py /путь/проверить-telegram
```

Первый исполнитель проводит повреждённый кадр через копирование C-байтов, приёмник, фасад и зашифрованный журнал. Новый процесс сверяет точный хвост, отказ чужого ключа, признак разрыва, отсутствие обращений к транспорту и неизменность сегмента. Отдельно проверяются отказ повторной подготовки и отсутствие автосоздания сегмента при восстановлении. Здесь повторно открывается ядро; перезапуск фасада поверх клиента в карантине не выполняется.

Второй исполнитель создаёт 16, затем 256 синтетических черновиков и незавершённых попыток. Для каждого объёма подготовка и восстановление идут в разных процессах; открытие ядра измеряется отдельно от проверки результата. Приватная квитанция версии 2 связывает исходные тела запросов, попытки и полные pending-события. Восстановление обязано вернуть точные данные с необходимостью разбора и без слепой повторной отправки. [Результаты и ограничения](Профили/README.md) включают объём входа, CPU, RSS и хэши.

Исполнители сами создают каталоги 0700 и случайный ключ 0600. Успешные временные каталоги удаляются только после проверок. При отказе путь сохранённого журнала и ключа выводится в приватный stderr; результаты завершённых фаз профиля остаются в JSON с кодом 2. Проверки не отключаются флагом Python -O. Каждый дочерний процесс ограничен 45 секундами. Новый процесс не означает холодный файловый кэш.

## Библиотечный жизненный цикл

`СредаКлиента.открыть` создаёт ядро и единственного владельца receive в процессе. `добавитьКлиента` разрешён только до начала закрытия. Возвращённые C-байты копируются до следующего вызова API, затем ограниченная очередь передаёт их последовательно в actor. Клиенты разделяются по `@client_id`, ответы — по `@extra`.

`закрыть` выполняется один раз даже при конкурентных вызовах. Отмена ожидающего вызывающего не отменяет очистку. После остановки потоков неприменённый хвост сохраняется зашифрованным. Если `Closed` не подтверждён либо произошёл разрыв, результат требует разбора, а владелец библиотеки остаётся в карантине до конца процесса. Это исключает повторный receive поверх живого клиента. Успешно загруженный образ также сохраняется до завершения процесса: глобальный менеджер современной TDLib не допускает безопасного произвольного dlclose.

Тайм-аут закрытия ограничивает ожидание событий и кооперативного обработчика. Он не способен прервать зависший системный fsync либо чужой C-вызов. Нельзя считать `@extra`, `sending_id` или тайм-аут подтверждением идемпотентной доставки.

## Состояние, разрешения и хранение

Типизированная авторизация различает параметры, телефон, почту и коды, пароль, QR, Ready, отзыв доступа и закрытие. Полный текущий объект авторизации доступен в `СнимокКлиента.сведенияАвторизации`: интерфейс получает обновляемую ссылку QR, сведения о коде и подсказки 2FA. Регистрация, покупка Premium и неизвестное состояние не проходят автоматически; QR первого среза запрашивается только в ожидании телефона. Прикладные операции требуют Ready и подтверждения аккаунта через getMe. Обновления до этого подтверждения сохраняются до успешного применения каждого элемента.

`загрузитьЧаты` запрашивает основной список; конец загрузки отмечается по коррелированному 404. Позиции обновляются через `updateChatPosition`, `updateChatLastMessage` и `updateChatDraftMessage`. Нулевой `order` удаляет позицию списка, сохраняя объект чата. Серверный draft не изменяет собственный местный черновик. `прочитатьИсторию` возвращает отдельную страницу до 100 сообщений; параметры `от`, `смещение` и `толькоМестная` задаются явно, результат доступен через `взятьОтвет`. Короткая страница не объявляется доказанным концом истории.

Местные черновики не вызывают `setChatDraftMessage`. Отправка текста, документа, альбома и правки текста, подписи или медиа проверяют адресата, разрешение, права канала и применимые свойства сообщения. Перед отправкой сохраняются точное намерение, данные вложений и идентичность попытки. Неопределённая доставка после перезапуска требует явного вызова `сверить`: он читает историю TDLib и не повторяет send. Совпадающий текст под другим ID или отсутствие сообщения на странице не доказывают исход. Частичный отказ альбома сохраняет неизвестные исходы остальных элементов; после перезапуска они требуют разбора. Подтверждённая замена временного ID сохраняется и при поздних обновлениях этого ID.

Корень журнала, база TDLib и её файлы требуют собственных физических каталогов 0700 без расширенного ACL. Ключи — 32 байта; `прочитатьПриватныйКлюч` читает обычный файл 0600 с одной жёсткой ссылкой через удерживаемый дескриптор, проверяет ACL и неизменность метаданных. Каталог базы и каталог файлов должны физически различаться. Секреты авторизации не включаются в журнал действий.

Журнал шифрует содержимое AES-GCM поверх [контейнера наблюдений](../КонтейнерНаблюдений/README.md). Вложения сохраняются через openat с проверкой фактических дескрипторов и идентичности открытого корня журнала, затем синхронизируются до записи намерения. Само содержимое файлов вложений на диске не зашифровано: доступ ограничивают права и ACL. TDLib позже открывает эти файлы по имени; вызывающая сторона должна сохранять их неизменными. Защита от злонамеренного процесса того же пользователя, игнорирующего владение, не гарантируется.

## Граница приёмки

Синтетические проверки используют вымышленные аккаунты и сообщения. Авторизация реального аккаунта, подключение канала и публикация в Telegram не выполнены. Дальнейшая реальная проверка требует отдельно разрешённых аккаунта, адресата, содержимого и конкретных действий, а также защищённых api_id/api_hash. Переписка и секреты не должны попадать в Git, открытые фикстуры или профили.

Read-state, sponsored messages и полная обработка пользовательского контента остаются условиями будущего полного клиента. Передача чужой переписки модели не выполняется автоматически. CC0 собственного кода FUM не изменяет лицензии TDLib и сборочных зависимостей.

Происхождение и результаты текущих проверок: [этап жизненного цикла](../../../../Журнал/2026-09-11_23-10-14_MSK_завершить-жизненный-цикл-клиента-Telegram/отчёт.md).
