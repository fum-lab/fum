# Первый сегмент контейнера наблюдений

Автономный SwiftPM-пакет для macOS 14+, не подключённый к приложению или датчикам FUM. Один явно переданный каталог содержит один файл сегмент.fumobs. Корень должен существовать, принадлежать текущему пользователю, не разрешать запись группе/остальным и иметь физический абсолютный путь без символических ссылок. Данные по умолчанию ниоткуда не читаются.

## Подтверждение и восстановление

Наблюдение состоит из стабильного идентификатора, типа, версии типа, источника, времени, непрозрачной спецификации и сырых байтов. Неизвестный тип сохраняется без интерпретации. SHA-256 обнаруживает случайное повреждение, но не является аутентификацией.

Группа begin → data* → commit подтверждается только после полного write и успешных fsync файла и каталога. EINTR повторяется, короткий write дописывается, нулевой write считается ошибкой. Отказ ввода-вывода блокирует дальнейшее использование экземпляра; требуется закрытие и новое открытие.

Повтор идентификатора сравнивает все метаданные, длину и SHA-256 содержимого. Совпадение возвращает ту же квитанцию без дописывания файла, но только после новой успешной синхронизации. Видимый commit после ошибочного fsync сам по себе не даёт права подтвердить повтор. Конфликт идентификатора отклоняется.

Читатель не меняет файл и показывает только группы с проверенным commit. Частичный кадр или полные begin/data без commit считаются незавершённым хвостом. Писатель не дописывает поверх хвоста. Явный восстановитель заново проверяет весь файл, обрезает только незавершённый хвост до последней полной группы и синхронизирует. Повреждённый полный кадр/зафиксированный префикс отклоняется без обрезки. Существующий пустой либо повреждённый файл не переинициализируется; отсутствующий файл восстановитель не создаёт.

## Формат версии 1

Сигнатура файла — восемь байтов FUMOBS01. Каждый кадр:

| Поле | Размер |
| --- | --- |
| OBS1, вид (1 begin / 2 data / 3 commit), три нулевых байта | 8 байт |
| Длина JSON, длина payload, порядковый номер; unsigned big-endian | 4 + 4 + 8 байт |
| SHA-256 предыдущих 24 байтов | 32 байта |
| Канонический JSON-заголовок, затем сырые бинарные байты | По длинам |
| SHA-256 предыдущего chain hash + префикса 24 байта + JSON + payload | 32 байта |

Первый chain hash — SHA-256 восьми байтов сигнатуры FUMOBS01. JSON имеет отсортированные ключи, без escaping slash; декодирование требует точного равенства повторно закодированным байтам, поэтому лишние/повторные поля отклоняются. Спецификация Data кодируется стандартным Codable внутри JSON, сам payload не кодируется в JSON/base64. Commit хранит размер, число фрагментов и SHA-256 целого объекта. Номер кадра непрерывен от 0; номер и смещение data-фрагмента начинаются с 0 в каждой группе. Пустое наблюдение имеет begin и commit без data.

## Ограничения и владение

Пределы проверяются до соответствующих выделений памяти и чтения: JSON 128 КиБ, спецификация 64 КиБ, data-фрагмент 1 МиБ, объект 64 МиБ, сегмент 256 МиБ, 4096 наблюдений и 16384 фрагмента. API принимает и возвращает Data целого ограниченного объекта; это не потоковый API с памятью только в один фрагмент. Сканер хранит ограниченный индекс метаданных и расположений фрагментов.

Неблокирующий advisory flock захватывается сначала на открытом корне, затем на сегменте. Writer/recovery используют exclusive lock, reader — shared. Корневой замок предшествует созданию файла, закрывая гонку двух создателей. Не поддерживающая directory flock файловая система отклоняется без обхода блокировки. Замки явно освобождаются в обратном порядке при закрытии. Один экземпляр синхронный, не Sendable, не используется конкурентно или через fork.

Защита корня и сегмента использует последовательный openat с O_NOFOLLOW. Для явно переданных входных файлов CLI запрещена символическая ссылка последнего компонента, но родительские символические ссылки допускаются. Файл должен быть обычным, принадлежащим текущему пользователю, с одной жёсткой ссылкой и без общей записи. Протокол не защищает от злонамеренного процесса того же пользователя, который игнорирует advisory lock или переименовывает каталог. Авария создателя до полной сигнатуры оставляет отклоняемый файл; автоматического удаления такого файла нет.

## Сборка и CLI

Из корня этого репозитория:

```sh
swift test --package-path Packages/КонтейнерНаблюдений --build-system native --jobs 2
swift build --package-path Packages/КонтейнерНаблюдений --build-system native --jobs 2 -c release
```

Native backend применён из-за отказа codesign у default backend на кириллическом XCTest bundle в использованном Swift 6.4. Native помечен SwiftPM устаревающим; это ограничение проверенной среды, не исправление общего toolchain.

Исполняемые файлы находятся в .build/release внутри пакета:

```text
писатель-контейнера добавить <абсолютный корень> <ID> <тип> <абсолютный файл байтов> [абсолютный файл спецификации]
читатель-контейнера извлечь <абсолютный корень> <ID>
восстановитель-контейнера <абсолютный корень>
профиль-контейнера записать <новый синтетический корень> 64 524288
профиль-контейнера восстановить <тот же корень>
```

Writer выдаёт JSON-квитанцию только после подтверждения; reader выдаёт точные бинарные байты в stdout. Ошибки идут в stderr с ненулевым exit status. CLI использует синтетические значения источника/времени по умолчанию; полные метаданные доступны в библиотечном API. Команда writer «удерживать» предназначена для теста блокировки: выводит готовность и держит замки до байта stdin/EOF.

## Проверки и профиль

Тесты покрывают произвольные байты/неизвестный тип, все метаданные, срез Data, пустой объект, короткие/нулевые write, EINTR, ENOSPC, ошибку fsync файла и каталога, повтор после неопределённого исхода, каждый байт усечения второй группы и повреждения полного файла, неверные кадры с правильными хэшами, лимиты, небезопасные пути, два процесса, SIGKILL владельца lock и восстановление отдельным процессом.

Профиль выдаёт JSON fum.метрики-контейнера.1: длительность, каждую задержку подтверждения, вложенные этапы и Darwin peak RSS в байтах. Вход детерминирован: byte[i] = (i × 131) mod 256. Измерение записи исключает создание файла и генерацию входа. Восстановление измеряет открытие/сканирование + повторную проверку/sync чистого файла; SHA-256 до/после исключён из времени, но входит в RSS и прогревает кэш. Это не холодное чтение и не измерение ремонта хвоста. Родительский этап включает дочерние: складывать их как независимые нельзя.

## Граница результата

Это один ограниченный сегмент, а не завершение FUM-STEP-0156. Ротация, индексы нескольких сегментов, миграция старой памяти и интеграция датчиков не реализованы. Убийство тестового владельца lock не моделирует аварию в середине write: восстановление усечённой группы проверяется отдельным процессом на синтетической фикстуре.

Перезапуск ОС, авария ядра и отключение питания не проверялись. Здесь используется fsync, не F_FULLFSYNC; успешный fsync не доказывает физическую сохранность при потере питания. См. [описание Apple fsync(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html) и [advisory flock(2)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html).
