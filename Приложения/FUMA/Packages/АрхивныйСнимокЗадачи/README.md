# Архивный снимок задачи

Swift-адаптер явно указанного Codex JSONL к долговечному снимку одной записанной задачи. Результат имеет частичный охват: **по состоянию прочитанного префикса**. Код и открытые фикстуры предоставляются под CC0 1.0 Universal.

В примерах `$1` — физический абсолютный корень чистого клона FUM, `$2` — заранее созданный пустой физический каталог вне Git. Временные сборки, контейнеры и сырые профили находятся в `$2`.

~~~sh
mkdir -p "$2/архив-задачи"
swift run --package-path "$1/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи" \
  --scratch-path "$2/сборка-архива" --jobs 2 архивный-снимок импорт \
  "$1/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи/Примеры/записанный-префикс.jsonl" \
  "$2/архив-задачи" 11111111-1111-4111-8111-111111111111
swift run --package-path "$1/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи" \
  --scratch-path "$2/сборка-архива" --jobs 2 архивный-снимок replay \
  "$2/архив-задачи" 11111111-1111-4111-8111-111111111111 --markdown
~~~

Полный XCTest-набор сохраняет историческую привязку исполняемых фикстур к `Package.swift/.build/debug`, а файловых фикстур — к `.build/фикстуры`. Поэтому для него используется точная приватная выгрузка трёх пакетов из одного явно выбранного коммита `$3`; прежние `.build` и `.swiftpm` в неё не переносятся. Каталоги остаются соседними, сохраняя объявленные относительные зависимости. Манифест проверки связывает каждый исходный файл с Git-blob, режимом и SHA-256. Эта выгрузка — вход проверки того же монорепозитория.

~~~sh
git -C "$1" archive "$3" \
  Приложения/FUMA/Packages/АрхивныйСнимокЗадачи \
  Приложения/FUMA/Packages/СнимокАгентскойЗадачи \
  Приложения/FUMA/Packages/КонтейнерНаблюдений | tar -xf - -C "$2"
swift test --package-path "$2/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи" \
  --scratch-path "$2/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи/.build" --jobs 2
~~~

UUID в примере принадлежит открытой фикстуре. Для реального источника ожидаемый UUID задаётся явно. Каталог контейнера должен существовать. Ошибка не печатает исходную строку или аргументы. Приложение не ищет сессии автоматически, не читает UI, Accessibility, ScreenCapture и не сохраняет диалог, инструкции, аргументы либо вывод инструментов.

## Нейтральные рамки JSONL

`выделитьРамкиПотока(_:пределы:)` принимает `Data` и возвращает полные LF-рамки, их исходные байты и позиции, границу завершённого префикса, точный незавершённый хвост и максимальную длину накопленной строки. LF входит в SHA и размер рамки; CR перед LF и пустая LF-рамка сохраняются. EOF не добавляет LF. Позиции относительны началу переданных данных, включая `Data` с ненулевым `startIndex`. Этот слой не разбирает JSON, не проверяет UTF-8 и не выбирает смысл или полномочия сообщения.

Новый фасад ограничен 1 048 576 байтами входа, 262 144 байтами строки вместе с LF либо хвоста и 128 полными рамками. `ПределыРамокПотока` позволяет только уменьшить положительные пределы. Пик означает длину строки, а не RSS или память всего результата. Результат выдаётся только после успешного полного сканирования.

Метод результата `префикс(до:)` возвращает проверенную границу первых указанных рамок, включая нулевую границу и полный LF-префикс. Число вне диапазона от нуля до числа рамок отклоняется. Граница строится по исходным байтам рамок, без добавления хвоста.

Data и прежний файловый читатель используют один потоковый LF-сканер. Файловый путь сохраняет собственный `БюджетАрхива`, буфер чтения 256 КиБ, проверки безопасного пути и обычного файла, прежней границы до соответствующего обработчика рамки и изменений файла после успешного EOF. Новый предел Data не сужает прежние файловые бюджеты. Весь очередной блок чтения проверяется перед вызовом обработчиков рамок; ошибка обработчика рамки остаётся исходной и прекращает чтение до завершающего stat. Смысловой архивный контракт ниже остаётся отдельным слоем.

## Поддержанная форма

UTF-8 JSONL, завершение строки — LF (CR перед LF допустим как пробел JSON). Первая завершённая строка — единственная `session_meta`, `payload.id` — lowercase UUID. Верхние ключи: `type`, `timestamp`, `payload`, `ordinal`, `metadata`. Поддержанные верхние типы: `session_meta`, `turn_context`, `event_msg`, `response_item`, `compacted`, `world_state`, `token_usage_record`, `inter_agent_communication_metadata`. Дубли декодированных ключей, неизвестная верхняя форма и неверная полная строка отклоняются. Версия CLI сама по себе не доказывает поддержку формата.

`type` и объект `payload` обязательны для всех восьми типов. `timestamp`, `ordinal` и `metadata` необязательны для совместимости с прежними источниками. Присутствующий `timestamp` — непустая строка до 128 байтов UTF-8 без управляющих символов; `metadata` — объект. `ordinal` проверяется по исходной JSON-лексеме: десятичное целое от 0 до Int64.max без знака, дроби, экспоненты и ведущего нуля, кроме самого `0`. Bool, null и строковая запись числа отклоняются. Повторные или убывающие значения разрешены: это непрозрачная аннотация, не счётчик LF, идентичность или порядок полномочий.

`world_state`, `token_usage_record`, `inter_agent_communication_metadata` и верхние `ordinal`/`metadata` участвуют только в байтовой границе и SHA исходного префикса. Из них не выбираются `cwd`, модель, ход, человеческие полномочия или живой статус, даже если соответствующие поля встречаются в payload. Вложенные объекты проходят прежние бюджеты и проверку повторных ключей. Произвольные новые верхние ключи и типы по-прежнему отклоняются.

Из `session_meta` берутся идентичность и необязательный `cwd`; из `turn_context` — обязательный `turn_id`, необязательные `cwd` и `model`. `event_msg` с явным `turn_id` меняет только идентичность последнего хода. Сравнение идентификаторов побайтовое. Модель сбрасывается при смене хода; отсутствие модели в `turn_context` также сбрасывает её. Неподдержанные поля внутри известных payload учитываются лишь как байты префикса. Они не создают дополнительные факты.

Последний ход означает последний ход, явно идентифицированный поддержанными `turn_context` или `event_msg`; чужой `turn_id` внутри нейтрального типа не меняет эту проекцию. Существование означает наличие записи сессии. Завершение задачи, выполнение обязательств, ожидание человека, активность процесса, назначенное рабочее дерево и UI-эффекты неизвестны. EOF, тишина, final-ответ и HookPrompt этих состояний не доказывают.

## Архивный контракт версии 1

Отдельный контейнерный тип `архивный-снимок-задачи/завершённый-префикс` использует публичные `Редуктор`, `Наблюдение` и `Сегмент`; синтетическое хранилище исходного пакета не используется. Оба исходных пакета остаются без изменений на базе `dd172958b0128cba73361eeac136e8bc66190230`.

Один объект содержит версию адаптера, ожидаемый UUID, идентичность и позицию/SHA исходной `session_meta`, байтовую и строчную границу и SHA завершённого префикса, выбранные факты с позициями/SHA исходных строк, не более трёх публичных наблюдений, SHA снимка и SHA предыдущего объекта. SHA строки включает LF. Сырые строки отсутствуют. Курсор не существует отдельно от данных.

Импорт подтверждается после fsync файла и каталога. Повтор точного префикса повторяет синхронизацию без роста. Любое дополнение завершёнными строками создаёт следующий объект. Неполный хвост — включая корректный JSON без LF и неполный UTF-8 — не входит в курсор. Подмена принятого префикса закрывает продолжение.

Replay проверяет схему, канонические байты, идентичность, позиции, переходы фактов и SHA снимка, исходник ему не нужен. Новый импорт перечитывает прежний префикс и сверяет SHA. Повторный JSON-разбор уже принятой части пропускается; `полныйРазбор: true` сохраняет эталон для сравнения. Времена тактов являются логической позицией префикса.

Replay также проверяет выполнимость промежутков между выбранными строками, прежней границей и конечным курсором. Одно число завершённых строк соответствует одному байтовому смещению; на каждую пропущенную строку требуется от 34 байтов до лимита строки, включая LF. Первая `session_meta` с UUID требует минимум 80 байтов. Минимумы относятся к поддержанным JSON-формам; пробелы перед LF позволяют заполнить допустимые интервалы. Это проверка внутренней геометрии, а не восстановление исходных строк или доказательство их подлинности по SHA.

Добавление необязательных оболочек не меняет сохранённую схему 1 и семантику прежних пяти типов. Прежние контейнерные байты не переписываются; дополнение новыми нейтральными строками и replay проверены синтетически. Минимумы 34/80 сохраняются, поскольку прежние минимальные формы остаются допустимыми. Если будущая версия начнёт выбирать факты из прежних нейтральных записей, совместимость потребует отдельного решения о версии и полном разборе.

После I/O-ошибки экземпляр становится недоступным. Повторное открытие восстанавливает видимые завершённые объекты, но новый импорт обязан повторно подтвердить fsync. Неполный контейнерный хвост запрещает обычное открытие. Явный API `восстановитьХвост: true` сначала проверяет идентичность и семантику всех завершённых объектов, затем разрешает контейнеру удалить доказанный незавершённый хвост. CLI эту операцию не выполняет автоматически.

## Бюджеты

Источник до 256 МиБ; строка до 8 МиБ; до 1 000 000 строк, глубина JSON 32, до 65 536 узлов строки и 4096 ключей одного объекта. Читаемый блок — 256 КиБ. Архив — до 1024 объектов по 64 КиБ. Бюджеты можно уменьшить. Cwd ограничен 1024 байтами, модель и идентичность хода — 128. Все ограничения проверяются до сохранения.

Полный исходник не загружается в память. Декодируется одна ограниченная строка; непрофильные payload существуют лишь во временной памяти разбора. Файл должен оставаться стабильным на время одного вызова: изменение обнаруженных размера/метаданных или замена inode дают отказ. Символические ссылки и NUL в пути запрещены. Защита от враждебной согласованной подмены всех файлов локальным пользователем не обещается.

## Проверки и профиль

Открытые XCTest-фикстуры покрывают идентичность, пределы, неполные хвосты, Unicode, подмену, повторы, replay, ложное завершение, модель хода, ENOSPC, нулевой write, fsync файла и каталога и SIGKILL до/после долговечной записи. Дополнительный исполняемый target `АварийнаяФикстура` генерирует только известный синтетический источник; он отделён от команды импорта.

Профиль создаёт новый каталог и детерминированный источник, сравнивает первый импорт, полный повтор, повтор с пропуском разбора и replay без исходника. В профиле исходник удаляется после открытия архива, перед выдачей восстановленного снимка. Открытие архива при уже отсутствующем исходнике отдельно подтверждается XCTest. Каталог должен отсутствовать до запуска.

```sh
swift run -c release --package-path "$1/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи" \
  --scratch-path "$2/сборка-профиля" --build-system native --jobs 2 \
  профиль-архивного-снимка "$2/новый-профиль-105МБ" 105000000
```

По умолчанию максимальная строка профиля — 3 326 896 байтов. Новый явный режим добавляет `ordinal`/`metadata` и чередует три служебных типа, ограничивая строку 256 КиБ, поэтому все три типа проходят и на 1 МБ:

```sh
swift run -c release --package-path "$1/Приложения/FUMA/Packages/АрхивныйСнимокЗадачи" \
  --scratch-path "$2/сборка-профиля" --build-system native --jobs 2 \
  профиль-архивного-снимка "$2/новый-профиль-оболочек-1МБ" 1000000 --служебные-оболочки
```

Это синтетическая проверка поддержанных оболочек, а не воспроизведение содержимого реального источника. JSON отделяет чтение/хэширование, разбор, редукцию, запись, оба fsync, replay и повтор. `ru_maxrss` — накопленный пик всего процесса в байтах macOS, включая создание фикстуры. Кэши файловой системы не очищаются; охватывающие времена не складываются с вложенными. Результаты четырёх режимов сравниваются через `Equatable`; SHA снимков выводятся отдельно. Это не проверка побайтового равенства канонически закодированного полного результата.

В текущем выборочном переносе все 43 Debug-теста прошли на точной приватной выгрузке трёх пакетов. Среда — macOS arm64, Apple Swift 6.4 (`swiftlang-6.4.0.34.1`). Парный профиль рамок отдельно измеряет 25 вызовов Data и 25 файловых вызовов на том же 1 МиБ; файловое время дополнительно включает read/stat. Этот профиль и проверка равенства не дают оснований менять общий сканер или заявлять ускорение. Большие Release-профили из примеров в этом этапе не повторялись. Источник результатов — [Журнал переноса](../../../../Журнал/2026-10-03_02-25-08_MSK_перенести-интерпретатор-FUMA/запрос.md).

Исторический отказ стандартного `swiftbuild` на CodeSign предшествовал предметному RED исходного этапа. Текущий набор выполнен системой `native`, которую toolchain отмечает как deprecated; будущие версии требуют проверки подготовки.

## Продолжение

Поставка проверена только открытой синтетикой. Координатор сообщил об отказе прежнего адаптера на закреплённом реальном префиксе и передал только структуру оболочек. Новый этап поддерживает указанные формы на синтетике; успешный повтор реального импорта ещё не подтверждён. Остальные формы runtime и доказательство live-состояния требуют отдельной приёмки. На стабильном статистическом коммите `85dccce282821a890e5e65539b4f22b895b52887` общий байтовый reader не выделен: `прочитатьПрефикс` возвращает статистические события. Этот адаптер сохраняет отдельную границу чтения и не импортирует статистическую семантику или незакоммиченные байты.
