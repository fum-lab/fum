# Статистика вызовов по записанному JSONL

Первый ограниченный Swift-адаптер завершённого префикса Codex JSONL: потоковое чтение, проверяемое происхождение, долговечное накопление и JSON/Markdown-отчёт. 35 адресных тестов, отдельные процессы CLI и публичные профили. Принятые пакеты контейнера и снимка не изменены. macOS 14+, Swift 6; проверено Apple Swift 6.4 на arm64.

## Запуск

Выход — существующий физический каталог вне обычного, linked-worktree и bare Git-репозитория, принадлежащий пользователю и без групповой/общей записи. Контейнер не следует символическим ссылкам. Пример из каталога пакета создаёт только публичную синтетику:

```sh
swift build --build-system native --jobs 2 -c release
mkdir -m 700 /private/tmp/профиль-статистики
.build/release/статистика-вызовов профиль --выход /private/tmp/профиль-статистики --размер малый
.build/release/статистика-вызовов импорт --вход /private/tmp/профиль-статистики/публичная-фикстура.jsonl --выход /private/tmp/профиль-статистики/контейнер --задача 11111111-1111-4111-8111-111111111111
.build/release/статистика-вызовов отчёт --выход /private/tmp/профиль-статистики/контейнер --задача 11111111-1111-4111-8111-111111111111 --формат markdown
```

Для каждого профиля нужен новый пустой каталог: размеры `малый`, `большой`, `рабочий`. CLI не ищет задачи, каталоги журналов или живые API. `импорт` требует явного абсолютного входа, выхода и lowercase UUID; `отчёт` читает только контейнер и не требует исходного файла. JSON по умолчанию либо `--формат markdown`. Неизвестные/повторные флаги отклоняются. Код 2 — отказ с конечной диагностикой без исходных аргументов/содержимого; код 0 подтверждает только принятый завершённый префикс, не весь файл или окончание задачи.

## Выбранный контракт

Первая завершённая строка обязана быть `session_meta` с тем же `payload.id`; повторная метаинформация не может сменить UUID. Контракт `fum.codex-jsonl-вызовы.1` выбирает только `response_item` с `function_call`, `custom_tool_call`, `function_call_output`, `custom_tool_call_output`. Поля внешнего JSON сохраняют его написание; `sha256` сохраняется как точное поле уже версионированной модели.

Строка завершается LF. Полуоткрытый диапазон [начало, конец), индивидуальный SHA-256 и подтверждённый SHA всего префикса включают LF. CRLF имеет собственные точные байты. BOM, пустая/неверная завершённая строка, неверный UTF-8, повторный ключ после JSON-unescape и чрезмерная вложенность отклоняются, включая нерелевантные строки нового префикса. Недописанный хвост возвращается без ожидания и не продвигает границу.

Сохраняются только семейство, направление, ограниченные call_id/имя, качество и числовое время, номер/байтовый диапазон/хэш строки и контракт. Системные сообщения, reasoning, arguments и output не переносятся в нормализованные события или диагностику. Полный исходный JSON временно разбирается по одной ограниченной строке; отдельный autoreleasepool освобождает временные объекты Foundation каждой строки. Ограниченная дельта и учёт остаются в памяти — неограниченный поток и нулевое копирование не заявлены.

Ключ вызова — UUID + call_id; направление отделяет вызов от результата. Точные дубли на новых строках сохраняют происхождение, но не увеличивают число вызовов. Изменённые байты того же ключа/направления конфликтуют, даже если изменены только отброшенные arguments. Новое настоящее call_id с прежним именем — отдельный вызов. Call без ID остаётся отдельным неизвестным наблюдением; output без ID не становится вызовом. Токены — ASCII-буквы, цифры и `_.:/-`, 1–256 байт; остальные значения не копируются и считаются неизвестными.

Timestamp v1: только UTC `YYYY-MM-DDTHH:MM:SS[.1–9 цифр]Z`, календарный диапазон 1970–2100, без leap second. Missing/invalid различаются и не заменяются нулём. Epoch-ns — наблюдённая отметка журнала; совместимая пара даёт задержку лишь при двух известных временах и неотрицательной разности. Output не доказывает успешность, задержка не является временем исполнения, универсальных порогов автоматизации нет.

## Долговечность и ограничения

Один actor владеет синхронным non-Sendable `Сегмент`; между preflight, append/fsync и публикацией учёта нет await. Полный повторный потоковый проход проверяет SHA на прежней подтверждённой границе. Новые события и новая граница записываются одной атомарной группой контейнера; отдельного cursor-файла нет. Новые нерелевантные строки тоже могут создать группу с пустыми событиями. Первый неверный UUID/JSON не создаёт сегмент.

Точный повтор без новых строк заново синхронизирует исходный последний пакет, не создавая новый. После ошибки записи или fsync экземпляр требует закрытия/replay и не выдаёт успешного подтверждения. Видимая после ошибочного fsync группа при повторе снова проходит fsync. Повреждение, неполная группа или неподходящий конверт отклоняются без автоматического ремонта. Replay проверяет версию, UUID, канонические байты, метаданные, порядок, переход границы, выполнимость промежутков строк/байтов и каждое событие до арифметики. Это тесты I/O/restart, не доказательство устойчивости к потере питания.

| Ограничение | Предел |
| --- | ---: |
| Блок чтения | 64 КиБ |
| Строка и незавершённый хвост | 4 МиБ |
| Явный входной файл | 256 МиБ |
| Завершённые строки | 100000 |
| Нормализованные события за историю, включая дубли | 8192 |
| Атомарный пакет | 8 МиБ |
| Пакеты | 256 |
| Глубина JSON | 16 |
| Ключи одной исходной строки / конверта | 8192 / 200000 |

Сериализация дельты выполняется до проверки размера пакета; эти структурные пределы не являются жёстким ограничителем RSS. Нижний контейнер дополнительно ограничен 256 МиБ сегмента и 4096 записями; при открытии его сканирование предшествует более узким лимитам адаптера. История не вращается и не очищается автоматически: переполнение требует отдельного решения.

Источник и пространство имён выхода предполагаются неизменными во время операции, остальные писатели — согласованными. Начальный размер, один fd и проверки inode/size/mtime/ctime отклоняют наблюдённую подмену входа; конечный symlink не открывается, родительские каталоги входа доверены. Проверки идентичности корня/сегмента до и после append отклоняют перенос с подменой между операциями. Атомарная защита от враждебной namespace/in-place гонки не заявлена. Хэши — не анонимизация и не подпись источника.

## Проверки и профиль

`swift test --build-system native --jobs 2` проверяет дубли, настоящие разные call_id, неизвестные поля/времена, хвост, смену префикса, restart, file/directory fsync, короткую запись, повреждённые конверты, числовые края, лимиты, read-only/владение и CLI. Native SwiftPM сообщает предупреждение об устаревании. В FUM проверки запускаются через обязательную v4-обёртку.

Малый профиль: 32 разных инструмента/64 события. Большой: 2048 инструментов/4096 событий и 16 игнорируемых строк по 524376 байт, всего 9054449 байт/4113 строк. Рабочий — только публичная синтетика с переданными размерами 105356966 байт/16609 строк/max3326896, не копия структуры или содержимого живого журнала. В каждом случае измеряются импорт, полный повтор, отчёт в памяти, кодирование и replay. Источник прогрет генерацией и fsync; время — DispatchTime, память — ru_maxrss всего процесса. Точные результаты, исходники до оптимизации и хэши отчётов хранятся в собственном FUM Журнале.

Группировка по инструменту выполняется один раз: прежние повторные проходы по всем вызовам заменены словарём групп при сохранении сортировки и счётчиков. Временные объекты Foundation ограничены строкой и при генерации фикстуры, и при импорте.

Источник задания — корневая задача FUM `01a07d3d-d376-7ad2-aafc-67e4c25a67eb`, этап `2026-09-09_14-58-37_MSK_накапливать-статистику-вызовов-из-журнала`; первичный источник закреплён FUM `670a1fda352b34668d87000602e76e246aefa22f`. FUM-REQ-0045/0160, общую приёмку и реальный разрешённый импорт выполняет корень. V4 и runtime item_completed — будущие отдельные адаптеры. Контракт происхождения/границы может быть переиспользован, но EOF, final, HookPrompt и временная близость не доказывают завершение задачи или родительство.
