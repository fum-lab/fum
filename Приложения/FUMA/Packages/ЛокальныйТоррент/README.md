# Локальный торрент-адаптер

Пакет содержит Swift-ядро для подготовки метаданных явно выбранного локального файла. Ядро принимает внедрённый `ОбработчикМетаданныхТоррента`, проверяет обычный файл и ограничения, независимо считает SHA-256 содержимого до и после вызова обработчика, проверяет непустоту и размер возвращённых данных и шестнадцатеричную форму infohash версий v1/v2. Обработчик получает исходный SHA-256 и полный `ОграниченияПодготовкиТоррента`: предел размера файла, длину части и предел метаданных. Реализация backend должна привязать свой снимок источника к этому хэшу и применить ограничения до работы библиотеки.

В этой контрольной точке реализация libtorrent backend отсутствует. Ядро само не создаёт bencoded-метаданные: это обязанность обработчика. Текущие тесты используют внедрённые обработчики и не доказывают совместимость, линковку или runtime с libtorrent.

`ПроверкаМетаданныхТоррента` полностью разбирает bencode, требует канонические числа и строки, строгий порядок ключей без повторов и точный конец ввода. Пределы: глубина 8, 256 узлов с ключами, ключ не длиннее 1024 байтов. Для одного непустого обычного файла проверяются имя, размер, длина части, гибридные v1/v2-поля, достаточность `piece layers` и их корень Меркла. Оба infohash независимо вычисляются из исходного байтового диапазона `info`. Ядро применяет этот валидатор перед возвратом артефакта.

`ОбработчикЛибторрента` вызывает C ABI в отдельном worker, связывает Swift-токен и отмену Task, копирует owned-метаданные до уничтожения владельца и проверяет их. Производственный C-провайдер явно сообщает «libtorrent не зарегистрирован; backend недоступен». Тестовый провайдер для `a/abc` проходит настоящий POSIX-снимок и создаёт ровно 200 байтов гибридных метаданных. Production-цель не зависит от тестового продукта `ПробыМоста`.

Именованный канал отклоняется без ожидания писателя; при росте источника чтение прекращается после исходного размера и одной проверочной пробы байта. Снимок привязан к исходному SHA-256, а не к повторному чтению имени источника. Очистка сверяет device/inode и не удаляет обнаруженную подставленную запись. Ошибка очистки перед успешным возвратом отклоняет результат. Полная защита от враждебных гонок другого процесса с тем же UID между проверкой имени и удалением не доказана.

## Сборка и тесты

Пакет собирается локально через SwiftPM:

```sh
swift test \
  --package-path Приложения/FUMA/Packages/ЛокальныйТоррент \
  --scratch-path "$TMPDIR/fum-local-torrent-core"
```

## Проверенные исходники backend

Проверены существующий fork `fum-lab/libtorrent` на OID `56ae8caba38bf154ffc210403cb23f91d0ecaa49` и созданный по указанию пользователя fork транзитивной зависимости [`fum-lab/try_signal`](https://github.com/fum-lab/try_signal) на OID `105cce59972f925a33aa6b1c3109e4cd3caf583d`. Локальное зеркало `try_signal` сверено с upstream и fork. Оба исходника пока не подключены к Swift-пакету.

Локальный зеркальный инвентаризатор поддерживает C++17. Отдельный пакет `Мост` содержит границу исключений, атомарную отмену, снимок и владение метаданными. Предложения точных закреплений и происхождения находятся в `Зависимости/*.json`; они не регистрируют зависимость. Для продолжения нужны допуск корня, регистрация, сборка и линковка libtorrent v2.1.1, библиотечный провайдер и прямое сравнение на том же корпусе. До этих проверок backend, интеграция в FUMA и поставка из чистого клона с библиотекой не подтверждены. Сеть и раздача файла не запускались.

## Воспроизвести профиль офлайн-границы

Сборка отделена от замеров. `-enable-testing` нужен для внутреннего внедрения тестового C-провайдера; публичный производственный API не расширяется.

```sh
swift build --build-tests -c release -Xswiftc -enable-testing \
  --package-path Приложения/FUMA/Packages/ЛокальныйТоррент \
  --scratch-path "$TMPDIR/fum-local-torrent-profile"
env ФУМ_ПРОФИЛЬ_ТОРРЕНТА=1 swift test --skip-build -c release -Xswiftc -enable-testing \
  --package-path Приложения/FUMA/Packages/ЛокальныйТоррент \
  --scratch-path "$TMPDIR/fum-local-torrent-profile" --filter test_ПрофильОфлайнГраницы
```

Строка `ФУМ-ПРОФИЛЬ:` содержит JSON с двумя прогревами и девятью пробами каждого интервала: C ABI со снимком/фикстурой/копированием/очисткой, 256 проверок Swift-валидатора и полный вызов ядра с фикстурой. Подготовка файла и оракула вне таймеров; проверки результата включены в первый и третий интервалы. Память — максимум всего процесса XCTest в байтах на macOS. Профиль настоящего libtorrent и прямое сравнение отложены.
