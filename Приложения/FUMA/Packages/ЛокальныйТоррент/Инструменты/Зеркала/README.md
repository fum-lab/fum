# Зеркала инструментов локального торрента

В этой области сохранены необходимые исходники проверяющего контура и отдельные кандидаты инвентаризатора и проектора с ограниченной поддержкой C++. Исходная база — commit `e1c3ab638c2b995905ae476c31c7822309451a0f`. Общие инструменты текущего checkout не изменены.

## Состав и происхождение

Неизменяемое зеркало содержит 33 обычных файла, 1 215 297 байтов: инвентаризатор объявлений и его зависимости, проектор с контрактами и схемами, анализатор Markdown-ссылок, зависимости проверки связности и структуры папок, Swift-пакет преобразователя названий. Файлы извлечены штатным `git archive` из одного commit. Перед сохранением манифеста каждый файл побайтово и по режиму сверен с исходным Git-объектом.

[Манифест](манифест-исходного-зеркала.json) закрепляет исходный путь, путь зеркала, blob, SHA-256, режим и размер каждого файла. Базовые материалы находятся в `Источники/e1c3ab638c2b995905ae476c31c7822309451a0f/Инструменты/`; их функциональность не редактируется. CJS, кэши, бинарники, SDK и внешние исходники в этот снимок не включены. Общие навыки из снимка не устанавливаются.

Кандидат инвентаризатора находится в `Кандидат/Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/`. Основной вход, три прежних вспомогательных файла и перечень исключений первоначально скопированы из той же базы; новое расширение — `scripts/разбор_си.py` и адресные изменения основного входа.

## Ограниченный инвентарь C++

Расширения `.cpp`, `.cc`, `.cxx`, `.hpp`, `.hh`, `.hxx`, `.h` разбираются через C API libclang: по умолчанию C++20, явно допускается C++17 для моста. На текущем macOS используется `/Library/Developer/CommandLineTools/usr/lib/libclang.dylib`; библиотека является установленным инструментом среды и не копируется в Git. На хосте без этого инструмента разбор закрывается отказом.

Проверяются собственные именованные типы, поля, функции, параметры и местные переменные. Собственные имена вне русского кириллического шаблона попадают в остаток; Python-исключения к C++ не применяются. Внешние объявления включённых заголовков отделяются по физическому файлу. Имена сверяются с UTF-8-байтами исходника; spelling и expansion locations должны совпадать. libclang получает уже прочитанный ограниченный снимок через `CXUnsavedFile`, а путь, идентичность и содержимое повторно проверяются после разбора.

Ошибки синтаксиса, ссылки на исходник, изменение источника, собственные макросы, пропущенные препроцессором диапазоны, метки переходов и неизвестные виды именованных объявлений закрывают допуск. Включённые файлы внутри проверяемого корня должны иметь одно из поддержанных расширений; `.inc`, `.inl` и прочие форматы закрываются отказом. Включения проверяются через `clang_getInclusions`. Предел одного файла — 4 МиБ. UCN-запись имён, namespace aliases, using declarations и C++-переименование пока не поддержаны; это ограниченный контур будущего bridge.

Из физического корня FUM запускать новым процессом Python:

```text
python3 -B Приложения/FUMA/Packages/ЛокальныйТоррент/Инструменты/Зеркала/Кандидат/Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/scripts/перевести-объявления-кода.py инвентаризировать --корень-репозитория Приложения/FUMA/Packages/ЛокальныйТоррент
```

Явные `-I`, `-D`, `-U`, `-isystem`, `-iquote`, `-isysroot`, `-target`, `-resource-dir`, `-stdlib=libc++`, `-pthread` `-std=c++17`, `-std=c++20` и переключатели exceptions/rtti передаются повторяемым `--аргумент-компилятора-си=<значение>`; значение с начальным дефисом обязательно задаётся через `=`. Их состав должен соответствовать проверяемой сборке. Ответные файлы аргументов, PCH, модули, плагины и остальные флаги не допускаются: скрытый ввод не доказывает полноту исходного инвентаря. Встраивание в уже работающий Python-процесс не доказывает происхождение импортов: `sys.modules` может содержать чужую ранее загруженную копию.

## Проверенные сценарии и следующий шаг

Первый RED выявил четыре отказа среди шести сценариев, первое расширение прошло все шесть. Независимое ревью добавило сценарии Python-исключений, Unicode Latin, меток, скрытых ветвей после комментария и склейки строк, подмены источника и передачи аргументов через CLI. Второй RED подтвердил семь отказов; отдельный RED подтвердил Unicode Latin. После исправлений прошли все 14 сценариев. После уточнения точного ctypes-контракта и русского имени теста адресно прошли два затронутых сценария. Затем RED подтвердил три пропуска собственных включений неизвестного формата; GREEN прошёл новый тест и два затронутых случая. Отдельный RED подтвердил четыре недопущенных формы аргументов; после конечного разрешённого перечня прошли три затронутых теста. Новый общий инвентарь зеркала и тестов пуст. Затем отдельный RED/GREEN закрепил C++17: прошли новый сценарий и отказ непрозрачных аргументов. Сейчас в исходниках 17 сценариев; вся серия после поздних правок повторно не запускалась. Эти запуски сохранены в машинном журнале задачи; [профиль измерений](../../../../../../Журнал/2026-09-30_16-46-07_MSK_реализовать-адаптер-libtorrent-для-локального-файла/материалы/профиль-зеркального-инвентаризатора.md) закрепляет границы и хэши.

## Кандидат зеркального проектора

В `Кандидат/Инструменты/fum-bratislavskaya-proyekciya-pamyati/` расширены контракт, схема и валидатор для `.cpp/.hpp`: исходные байты кода и технические расширения сохраняются. Полный прежний контракт сохранён в `совместимость/контракт-v2-до-форматов-си-плюс-плюс.json`, его канонический SHA-256 — `f8d5cad4c9dac3bb787949b7dbfc00f948b607f2ce7f0ebee5aecebe4bcaf72c`. Старое владение подтверждается этим объектом, не реконструируется удалением новых полей.

Сборщик выбирает ровно два Swift-исходника из закреплённого манифеста; каноническая обёртка из текущего HEAD не выбирается. Архив строится из проверенных байтов, а ключ кеша включает вычисленное Git-дерево, исходный commit и SHA манифеста. Сохраняются проверки LinguisticKit, toolchain/SDK, приватного кеша и изолированного продукта. Обе ветви контекстного API проверяют границу также при выходе. Машинный результат печатается после успешного выхода, CLI закрывает копию, снимает только принадлежащие ему модули и сохраняет исходную ошибку при отказе cleanup.

Три помощника проектора и шесть их транзитивных модулей загружаются из исходного зеркала. До загрузки проверяются все 33 файла и точный физический состав; для исполнения создаётся приватная закрытая копия всех проверенных байтов, `__file__` указывает в неё. Это исключает небезопасное повторное чтение baseline при вычислении самоотпечатков; Python-код исполняется через `compile()` проверенного снимка. Состояние чужих модулей в `sys.modules` закрывает загрузку: использовать свежий `python3 -I -B`. Ленивый анализатор ссылок связывается с проверенным модулем. Полная сверка исходного зеркала выполняется до/после загрузки и при завершении контекстной операции; частые вызовы проверяют объекты модулей без повторного чтения всего снимка.

Адресные фикстуры подтвердили расширение политики, выбор двух исходников, отказ подмены/лишнего файла/ссылки, происхождение импортов и завершение контекста. Запись 104 с отключённым кешем подтвердила новую независимую Swift-компиляцию и два одинаковых результата для `.cpp/.hpp`. Объявленный LinguisticKit материализован штатным init. Переход устанавливаемого поколения ещё не подтверждён. Контракт gitlink по-прежнему допускает только закреплённый LinguisticKit: `libtorrent/try_signal` отдельно требуют точного расширения и проверки. Этот кандидат не устанавливает `Proyekcii/**` и не является финальной приёмкой FUM. [Профиль и границы проверки](../../../../../../Журнал/2026-09-30_16-46-07_MSK_реализовать-адаптер-libtorrent-для-локального-файла/материалы/профиль-моста-и-зеркального-проектора.md).

Для live-проектора нужны объявленные Git, Swift, toolchain/SDK и `LinguisticKit@837e2ce107b97ee7b9d3344c9fe99142281fe393`; Node требуется только для точных CJS-путей основного репозитория. Скопированные вспомогательные CLI также требуют собственных входов, реестров и конфигураций; их исходный снимок не является готовым автономным продуктом. Полнота зеркала исходников не доказывает доступность этих внешних зависимостей на другом хосте.
