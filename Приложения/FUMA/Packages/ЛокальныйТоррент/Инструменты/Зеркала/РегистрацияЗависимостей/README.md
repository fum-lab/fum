# Зеркальный регистратор зависимостей

Источник — три обычных файла канонического `fum-proverka-git-zavisimostej` из commit `e1c3ab638c2b995905ae476c31c7822309451a0f`, 114 885 байтов. Отдельный манифест закрепляет пути, blob, SHA-256, режим и размер. Исходный 33-файловый снимок проектора сохранён отдельно и не расширяется.

`scripts/регистратор.py` проверяет полный состав и точные байты этого зеркала перед загрузкой и после выхода из контекста. Канонический регистратор исполняется из прочитанных байтов в отдельном объекте Python-модуля. Внутренний активный контекст хранит его идентичность и значения namespace; перед записью они сверяются вместе с исходным зеркалом. Прежние проверки происхождения URL, Git-индекса, clone, remote, refspec, shallow, скрытых изменений и достижимости сохраняются. Прежний `materialize_dependency` в исходном снимке остаётся историческим кодом; новая регистрация его не вызывает.

## Ограниченная регистрация

Новый вход `зарегистрировать` принимает физический корень linked worktree, описание зависимости и текущий проверенный модуль зеркала. Он требует отдельный Git-каталог под `worktrees` и ветку `refs/heads/codex/`. Первичный checkout, symlink, занятый путь, конфликтующая регистрация и остаточный module Git-dir закрываются отказом. Пустой каталог разрешён; ответ родительского Git-корня не считается clone зависимости.

До записи проверяются исходные HEAD/ref, индекс, `.gitmodules` и общая конфигурация. Предварительная проверка клонирует fork и получает оба remote в приватном временном каталоге. После повторной сверки добавляется точный раздел `.gitmodules` с `path/url/fumUpstream` и stage-0 gitlink на закреплённый OID. Затем вызывается неизменённый защищённый `init`: URL и active передаются через временные аргументы Git без `--init`. Git-каталог зависимости принадлежит текущему worktree. Общая конфигурация и остальные записи индекса отдельно сверяются на всех исходах фаз установки; диагностические ошибки добавляются к исходному отказу.

Установка файла и записей индекса состоит из нескольких фаз. Отказ сохраняет собственную наработку и название незавершённой фазы. Частичная или конфликтующая регистрация не возобновляется автоматически. Точный повтор готового состояния выполняет строгую проверку без переписывания индекса. Автоматического rollback нет.

## Остаток допуска

Живая регистрация libtorrent в FUM ещё не запускалась. Нужны независимое ревью, дополнительные отказные случаи загрузки и прерывания фаз, сохранённые свидетельства GitHub-линии fork, публичности и лицензии до использования зависимости. Канонический Git-проверяющий инструмент проверяет URL и клон, но сам не устанавливает лицензионную допустимость и линию fork.

Вложенный `deps/try_signal` пока не материализуется этим входом. Его исходная `.gitmodules` должна сохраняться побайтно; нужен отдельный строгий контракт fork/upstream и закреплённого gitlink. Остальные три вложенные зависимости libtorrent не инициализируются. CLI, подключение к сборке backend и общий smoke-check ещё не подтверждены.
