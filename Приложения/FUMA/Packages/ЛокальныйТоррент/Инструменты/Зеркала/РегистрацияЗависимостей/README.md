# Зеркальный регистратор зависимостей

Источник — три обычных файла канонического `fum-proverka-git-zavisimostej` из commit `e1c3ab638c2b995905ae476c31c7822309451a0f`, 114 885 байтов. Отдельный манифест закрепляет пути, blob, SHA-256, режим и размер. Исходный 33-файловый снимок проектора сохранён отдельно и не расширяется.

`scripts/регистратор.py` проверяет полный состав и точные байты этого зеркала перед загрузкой и после выхода из контекста. Канонический регистратор исполняется из прочитанных байтов в отдельном объекте Python-модуля. Внутренний активный контекст хранит его идентичность и значения namespace; перед записью они сверяются вместе с исходным зеркалом. Прежние проверки происхождения URL, Git-индекса, clone, remote, refspec, shallow, скрытых изменений и достижимости сохраняются. Прежний `materialize_dependency` в исходном снимке остаётся историческим кодом; новая регистрация его не вызывает.

## Ограниченная регистрация

Вход `зарегистрировать` принимает физический корень linked worktree, описание зависимости, текущий проверенный модуль зеркала, параметры исполнителя `.7` и отдельно выбранное поручение координатора. Он требует отдельный Git-каталог под `worktrees` и ветку `refs/heads/codex/`. Первичный checkout, symlink, занятый путь, конфликтующая регистрация и остаточный module Git-dir закрываются отказом. Пустой каталог разрешён; ответ родительского Git-корня не считается clone зависимости.

До записи проверяются исходные HEAD/ref, индекс, `.gitmodules` и общая конфигурация. Предварительная проверка клонирует fork и получает оба remote в приватном временном каталоге. После повторной сверки добавляется точный раздел `.gitmodules` с `path/url/fumUpstream` и stage-0 gitlink на закреплённый OID. Затем вызывается неизменённый защищённый `init`: URL и active передаются через временные аргументы Git без `--init`. Git-каталог зависимости принадлежит текущему worktree. Общая конфигурация и остальные записи индекса отдельно сверяются на всех исходах фаз установки; диагностические ошибки добавляются к исходному отказу.

Установка файла и записей индекса состоит из нескольких фаз. Отказ сохраняет собственную наработку и название незавершённой фазы. Частичная или конфликтующая регистрация не возобновляется автоматически. Точный повтор готового состояния выполняет строгую проверку без переписывания индекса. Автоматического rollback нет.

## Привязка исполнителя

`scripts/привязка_исполнителя.py` предоставляет `проверить(параметры, независимый, *, зеркало=None, профиль=None)`; аргументы `зеркало` и `профиль` передаются только по имени. Самостоятельного CLI нет. Вход требует ровно 12 полей:

| Поле | Значение |
| --- | --- |
| `схема` | `fum.создание-коммита.7` |
| `режим` | `контрольная-точка` |
| `выбранное_поручение` | Точная копия отдельно полученного выбора |
| `задача` | UUID координатора |
| `исполнитель` | Собственный нативный UUID |
| `корень` | Абсолютный физический корень checkout |
| `ветка` | Полный собственный `refs/heads/codex/...` |
| `источник_модели` | Абсолютный физический путь собственного нативного JSONL |
| `исходный_коммит` | Полный текущий HEAD этапа |
| `разрешённые_цели` | Неповторяющийся список 1–1024 точных относительных путей внутри акта |
| `запрос` | Собственный относительный `Журнал/.../запрос.md` |
| `история_модели` | Относительный путь в материалах этого этапа |

Независимый аргумент содержит ровно `координатор`, `исполнитель`, `коммит`, `путь`, `sha256`, полученные из проверенного выбора ROOT. Копия в параметрах не создаёт независимого полномочия. Фактический `CODEX_THREAD_ID` уже должен соответствовать исполнителю; UUID среды не подменяется. Проверяются акт и первоначальная постановка из Git, нативное начало и поручение, физический корень, HEAD/ref и единственный владелец ветки. Перенаправляющие переменные Git запрещены. Строки, список и словари проверяются до сериализации; вход удерживается и повторно сверяется перед положительным ответом. Профиль требует отдельного словаря, не совпадающего с проверяемым входом.

Перед загрузкой проверяются закреплённый манифест и точный состав 17 файлов. Частная копия создаётся вне любого Git-предка, её файлы имеют режим `0400`. Новый процесс Python `-I -B -S` загружает только удержанные проверенные проектные байты и стандартную библиотеку. Это относится и к помощникам через `exec_module`; частный байткод и чужие модули не используются. Исходное зеркало и частная копия повторно сверяются после reader; копия удаляется при завершении вызова. Процессная изоляция не является песочницей против другого процесса того же пользователя.

Общий тайм-аут обмена с reader — 20 секунд; вход и каждый выходной канал ограничены 256 KiB. Переполнение прерывает работающую группу сразу при чтении; тайм-аут также прекращает группу и её обычных потомков. Это не тайм-аут всей регистрации, preflight или init.

Обычный вызов Python API при отдельно разрешённой регистрации:

```python
from pathlib import Path
import sys

корень = Path.cwd().resolve()
пакет = корень / "Приложения/FUMA/Packages/ЛокальныйТоррент/Инструменты/Зеркала"
sys.path.insert(0, str(пакет / "РегистрацияЗависимостей/scripts"))
from регистратор import исходник, зарегистрировать

with исходник() as модуль:
    ошибки = зарегистрировать(
        корень, описание, модуль,
        параметры_исполнителя=параметры,
        независимый_выбор=выбор)
```

Описание имеет внешние поля `fork_url`, `upstream_url`, `path`, `revision`; `описание`, `параметры` и `выбор` готовятся отдельно по разрешённой постановке. Успех проверяется после выхода из контекста: завершающая сверка тоже может отказать. Внешняя обёртка учитывает список ошибок и исключения. Привязка проверяется при входе и после preflight непосредственно перед началом записи; удержанный вход должен совпадать между ними. После второго reader повторно сверяются метаданные, индекс, общая конфигурация и HEAD/ref, чтобы сохранить наблюдённую позднюю пользовательскую запись.

Восстановление зависит от причины отказа. При нарушении целостности зеркала сохранить подменённое назначение и воспроизвести точные байты из закреплённого Git-снимка в новом каталоге; существующее зеркало автоматически не перезаписывается. При неверных UUID, native, HEAD/ref или выборе сверить соответствующий первичный источник; новый независимый выбор выдаёт ROOT. При тайм-ауте разобрать причину остановки и повторить read-only проверку в согласованном состоянии. После частичного отказа регистрации сначала разобрать сохранённые метаданные, индекс и Git-каталог; удаление либо слепой повтор не являются восстановлением.

## Захват конечного зеркала

`scripts/захват_зеркала.py` снимает конечный перечень обычных файлов из точного Git-коммита. Он сохраняет исходные пути, режимы, blobs, размеры и SHA-256 в детерминированном манифесте. Рабочие файлы источника не читаются; replace refs, перенаправляющие переменные Git и автоматическая загрузка отсутствующих объектов исключены. Нужен физический корень checkout; подкаталог и symlink не подходят. `снять` ограничивает перечень 64 файлами и 2 MiB на файл; `сохранить` дополнительно проверяет предел 8 MiB всего зеркала. Регистровые и Unicode-коллизии проверяются также для компонентов каталогов.

Снимок `../ПривязкаИсполнителя/` содержит 17 файлов, 757 458 байтов из `e8112e88e0a574ade47ab560324af834dc6e2d00`. SHA-256 его канонического манифеста — `d2eb066ccc9faf612b1f4b754c73c662810c34b4f29af04b1019fc5ff8447fb4`. Его предметный загрузчик и подключение к регистратору реализованы; это reader, не полный коммитный контур.

Для воспроизведения из корня FUM передайте новый абсолютный путь назначения. Закреплённые Git-объекты должны уже присутствовать локально; команда не получает их из сети.

```sh
python3 -B - /абсолютный/путь/к/новому-зеркалу <<'PY'
from pathlib import Path
import hashlib
import json
import sys

корень = Path.cwd().resolve()
пакет = корень / "Приложения/FUMA/Packages/ЛокальныйТоррент/Инструменты/Зеркала"
sys.path.insert(0, str(пакет / "РегистрацияЗависимостей/scripts"))
from захват_зеркала import байты_плана, снять, сохранить

план = json.loads((пакет / "ПривязкаИсполнителя/манифест.json").read_bytes())
хэш = "d2eb066ccc9faf612b1f4b754c73c662810c34b4f29af04b1019fc5ff8447fb4"
if hashlib.sha256(байты_плана(план)).hexdigest() != хэш:
    raise ValueError("манифест не совпал с закреплённым хэшем")
сохранить(корень, план, Path(sys.argv[1]), хэш)
PY
```

Установка сначала сверяет весь план с Git-объектами, затем собирает и синхронизирует закрытый временный каталог и один раз переименовывает его. Требуется один кооперативный писатель: проверка отсутствия назначения и `rename` не образуют CAS. Точный повтор сверяет состав, байты и режимы без переписывания файлов и повторяет синхронизацию каталогов. Подмена существующего зеркала закрывает повтор отказом и сохраняется на диске. Ошибка после `rename` сообщает, что назначение сохранено, а синхронизация родителя не подтверждена. Общие refs, индекс и Git-конфигурация этим входом не меняются.

Адресные сценарии текущего этапа подтверждают отказ подменённого плана, неверных типов размера, Git symlink, replace-подмены и коллизии каталогов; отдельно проверены частичный отказ записи и повтор после ошибки синхронизации родителя. Три усиленных оракула подтверждают конкретный inode родителя при `fsync`, отсутствие временного каталога после отказа и сохранение inode/режима готовых файлов при повторе. Последний профиль чтения этих 17 файлов — 0,638–0,659 с; установка в него не входит. Алгоритм сохранён: редкий конечный захват не обосновал дополнительного усложнения.

Предметный кандидат инвентаризатора распознаёт внешний `setUp` только как обычный синхронный метод с прямо подтверждённым импортом `unittest.TestCase`. Он закрывает исключение при звёздочном импорте, перепривязке, подмене атрибута или непрозрачном использовании импорта до класса. Форма `from` отдельно проверяет модуль до импорта базы. Консервативный отказ оставляет имя в инвентаре; полное исполнение произвольного Python и доказательство его динамических эффектов не заявляются. Исходный снимок и общий инвентаризатор не изменены. Пять адресных сценариев прошли; профиль сохранён в текущем Журнале.

## Остаток допуска

Живая регистрация libtorrent в FUM ещё не запускалась. Нужны отдельный допуск настоящих фаз init/fetch/build и их прерывания, сохранённые свидетельства GitHub-линии fork, публичности и лицензии до использования зависимости. Канонический Git-проверяющий инструмент проверяет URL и клон, но сам не устанавливает лицензионную допустимость и линию fork.

По акту продолжения `6a32d994` прошли 16 адресных случаев loader и 17 потребителей регистратора, включая прежний RED отсутствующего выбора и позднюю подмену между привязками. Последующий RED/GREEN подтвердил сохранность поздних метаданных после второго reader, добавив восемнадцатый случай регистратора. [Текущий профиль reader](../../../../../../../Журнал/2026-10-01_05-14-41_MSK_закрепить-привязку-регистратора-зависимостей/материалы/профили/привязка-исполнителя-после-сверки.json) связывает SHA кода, тестов и манифеста после этой правки: три полных вызова 0,354–0,360 с, внутренняя загрузка 0,131–0,133 с; каждый вызов использует новый worker, реально импортированы 16 из 17 закреплённых файлов. Вложенные интервалы не складываются. Алгоритм сохранён без кэширования доверенных решений; ускорение не заявляется. Эти числа отдельно от профиля захвата зеркала выше.

Акт `.7` подтверждает исполнителя и предметную область; скрытая `.gitmodules` его областью не допускается. Живая регистрация требует отдельного контракта. Общий ремонт `add` закреплён за координатором в FUM-STEP-0241; этот пакет его не дублирует. До принятого ремонта и независимого допуска живой вход регистрации закрыт.

Вложенный `deps/try_signal` пока не материализуется этим входом. Его исходная `.gitmodules` должна сохраняться побайтно; нужен отдельный строгий контракт fork/upstream и закреплённого gitlink. Остальные три вложенные зависимости libtorrent не инициализируются. CLI, подключение к сборке backend и общий smoke-check ещё не подтверждены.
