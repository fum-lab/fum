# Исходники FUMA

Каталог собирает собственную реализацию FUMA обычными файлами единого FUM. На первом этапе перенесены четыре самостоятельных SwiftPM-пакета. Они ещё не подключены к macOS-приложению; такой связи не было и в исходной реализации.

- [Контейнер наблюдений](Packages/КонтейнерНаблюдений/README.md) хранит один ограниченный сегмент бинарных наблюдений.
- [Снимок агентской задачи](Packages/СнимокАгентскойЗадачи/README.md) воспроизводит синтетические сценарии и восстанавливает снимок.
- [Архивный снимок задачи](Packages/АрхивныйСнимокЗадачи/README.md) импортирует явно переданный завершённый префикс журнала.
- [Статистика вызовов](Packages/СтатистикаВызовов/README.md) учитывает вызовы по открытому контракту событий.

Пакеты объявляют Swift tools 6.0, Swift 6 и macOS 14. Это граница нынешней реализации, а не заявление о поддержке всех целевых ОС. Руководства пакетов пока сохраняют исходный текст; их команды с `Packages/` выполняются из этого каталога. Приёмка из чистого клона и общее руководство воспроизведения относятся к следующему этапу.

## Сохранение происхождения

[Манифест переноса](../../Журнал/2026-09-11_01-28-44_MSK_перенести-исходники-FUMA/материалы/манифест-переноса-пакетов.json) связывает каждый исходный путь с полными commit, blob OID, SHA-256, размером, режимом и местом в FUM. Исходники и фикстуры извлечены без изменения байтов. В README штатно добавляются только служебные метки свежести; их полный канонический хэш учитывается отдельно.

Реализация признана собственной прямым поручением пользователя и включается под общую [CC0 FUM](../../LICENSE). В исходном наборе нет отдельного LICENSE; это не устанавливает лицензию сторонних библиотек. LinguisticKit остаётся внешней зависимостью с прежним gitlink. Ни runtime, ни локальные кэши, ни частные журналы в перенос не входят.

## Повторение переноса

Вспомогательный [сценарий извлечения](сценарии/перенести-исходники.py) требует существующий корень назначения и явный путь к исходному Git-репозиторию. Он не создаёт клон, не меняет исходные refs и не читает рабочие или неотслеживаемые файлы. Каждый `--выбор` имеет вид `полный-commit:путь`, точка означает всё дерево. Без `--применить` выводится только JSON-план; с флагом сначала проверяются все назначения и исходные объекты, затем создаются файлы. Уже существующая цель, конфликт исходных версий, ссылка или несовпадение хэша дают отказ. Диагностический stderr содержит измерения построения плана и применения в наносекундах; stdout — манифест.

Для повторного извлечения нужен пустой целевой каталог. После импорта сырой манифест сохраняется; обязательная обработка канонических Markdown выполняется отдельно штатной автоматизацией свежести. Сценарий ограничен обычными файлами Git SHA-1, согласованным единственным писателем и исходным репозиторием без конкурентной подмены. При ошибке записи созданные им файлы удаляются; пустые каталоги могут остаться. Это вспомогательный механизм переноса данной реализации, не автоматическое включение неизвестного стороннего репозитория.
