# Исполнение оператора в FUMA

Основной бинарник FUMA принимает явное определение структурирующего оператора и входной файл, сохраняет их исходные байты, вызывает существующий Swift-интерпретатор в своём процессе и сохраняет результат в накопительную память. Командный режим завершается до создания сцены и обработки разрешений. Вызов не запускает помощника или IPC.

## Первый сценарий: UTF-8 → UTF-32LE

Сохранённое [требование FUM-REQ-0067](../../../../Требования/🟡-чистое-исполнение-операторов-и-UTF-32.md) задаёт первый предметный сценарий: исходные байты UTF-8 → Unicode-скаляры → UTF-32 с явным порядком байтов. Ниже выполняется его вариант UTF-32LE без нормализации и BOM. Потоковая обработка порциями этим конечным вызовом не подтверждается.

Нужны зависимости и сборка из [руководства приложения](../README.md#зависимости-и-сборка): macOS с Xcode/Swift 6, системные mpv и pkg-config. Локальные библиотеки входят в чистый клон FUM; отдельные репозитории собственного кода не нужны. SwiftPM использует пакет интерпретатора из `Прототипы/память-структурирующих-операторов` и пакеты `КонтейнерНаблюдений` и `АрхивныйСнимокЗадачи` из `Приложения/FUMA/Packages`.

Команды ниже выполняются из физического корня FUM. `FUM_BUILD_ROOT` — заранее выбранный существующий абсолютный физический каталог вне любого Git checkout. Каталог журнала должен существовать, принадлежать текущему пользователю, иметь права `0700` и не содержать символических ссылок в пути. Приложение не выбирает место хранения автоматически.

```sh
: "${FUM_BUILD_ROOT:?Задайте физический каталог вне Git}"
swift build --build-system native --package-path Приложения/FUMA/macOS --scratch-path "$FUM_BUILD_ROOT" --jobs 2 --product fum
mkdir -m 700 "$FUM_BUILD_ROOT/наблюдения"
printf '%s' 'Aё🙂' > "$FUM_BUILD_ROOT/вход-UTF-8.txt"
"$FUM_BUILD_ROOT/debug/fum" --выполнить-оператор \
  --определение "$(pwd -P)/Прототипы/память-структурирующих-операторов/Sources/FUMStructuringOperatorMemory/Определения/UTF-8-в-UTF-32LE.json" \
  --вход "$FUM_BUILD_ROOT/вход-UTF-8.txt" \
  --тип-входа байты --журнал "$FUM_BUILD_ROOT/наблюдения"
```

В stdout возвращается JSON `fuma.результат-исполнения.1` с `наблюдение` и `квитанция`. Результат содержит 12 байтов UTF-32LE: `41 00 00 00 51 04 00 00 42 F6 01 00`, а трасса — три правила декодирования. Код `0` возвращается после подтверждённого сохранения и записи ответа. В `квитанция.описание.идентификатор` находится идентификатор долговременной записи.

Повтор использует сохранённые принятые данные; исходные файлы больше не нужны. Подставьте полученный идентификатор:

```sh
"$FUM_BUILD_ROOT/debug/fum" --повторить-оператор 'идентификатор-из-квитанции' \
  --журнал "$FUM_BUILD_ROOT/наблюдения"
```

Успешный повтор сверяет детерминированный хэш и создаёт новое наблюдение с новым идентификатором и временем. Сами принятые данные и детерминированный результат сохраняются без изменения. Исходные байты повторного вызова получают отдельный приём со ссылкой на прежнее исполнение. Расхождение не создаёт производного результата, но принятые байты остаются в памяти.

Для Xcode выполните [штатную сборку FUMA.app](../README.md#зависимости-и-сборка). Те же аргументы принимает основной файл `"$FUM_BUILD_ROOT/xcode/Build/Products/Debug/FUMA.app/Contents/MacOS/FUMA"`. Xcode подключает библиотеки как локальные пакетные продукты, включая ресурсы интерпретатора.

Дополнительный текстовый сценарий использует `Определения/нормализация.json`, вход `Приложения/FUMA/macOS/проверки/фикстуры/вход-оператора.txt` и `--тип-входа текст`. Его результат — `привет ёж`; на нём измеряется профиль ниже.

## Принятый вход и память

После проверки аргументов, приватного каталога и ограниченного чтения файлов, до разбора JSON, UTF-8 и исполнения, FUMA последовательно сохраняет два наблюдения: `сырые-байты/вход-оператора` и `сырые-байты/определение-оператора`. Их payload — точные бинарные байты без Base64 и нормализации. Общий UUID приёма связывает записи с идентификатором последующего результата. Порядок хранится в контейнере; новый приём одинаковых байтов получает новую запись.

Необязательный `--источник-входа человек|LLM|система|неизвестно` сохраняет заявленное происхождение данных; по умолчанию оно неизвестно. Это метка вызывающей стороны, а не доказательство авторства. Автор определения отдельно остаётся неизвестным. У повторного приёма сохраняется `повторЗаписи` — идентификатор прежнего исполнения. Содержимое, включая незавершённый или неверный UTF-8, сохраняется до проверки кодировки.

Для первого байтового оператора укажите [тождество байтов](../Операторы/тождество-байтов.json) вместо определения UTF-8 и `--тип-входа байты`. Интерпретатор возвращает все входные байты без преобразования, в том числе NUL и значения, не являющиеся UTF-8. Пустой список шагов — тождественное преобразование; побочный эффект долговременного хранения выполняет входной адаптер FUMA. Полное описание всего тракта графом остаётся следующим этапом.

Поддерживаются два явных типа входа: `текст` — строгий UTF-8, `байты` — точные байты файла. Определение разбирается существующим `ОпределениеОператора.разобрать`; новая копия декодера или интерпретатора не вводится. Для байтового сценария пригодно сохранённое определение `UTF-8-в-UTF-32LE.json`. Отдельный вход для массива скаляров или готового структурного объекта в этой вертикали не объявлен; структурный контракт можно передать текстом соответствующему существующему оператору.

Payload записи `fuma.исполнение-оператора.1` содержит:

- `принятыеДанные`: точные исходные байты определения, его проверенное каноническое представление, исходные байты входа, тип и полный профиль пределов;
- `наблюдение`: результат существующего исполнителя, идентичность/версию определения, хэши, следы шагов, имеющуюся трассу правил, число пропущенных записей и выполненных операций.

Поля `Data` сериализованы стандартным JSONEncoder как Base64. Идентификатор и время находятся в описании контейнера и не входят в детерминированный payload. Профиль измерений также не входит в него. Профиль исполнителя версии 1 закрепляет пределы: определение до 65 536 байтов, вход до 262 144 байтов, результат до 1 048 576 байтов, до 16 777 216 операций и до 256 записей трассы. Изменение профиля требует новой версии; повторы неизвестного профиля отклоняются. Повтор Unicode-преобразований предполагает совместимый Swift/Foundation runtime; хэш выявляет расхождение между версиями.

Контейнер дописывает группы в `сегмент.fumobs`, проверяет прежнюю историю и возвращает квитанцию только после записи и `fsync` файла и каталога. Сегмент ограничен 256 МиБ и 4096 наблюдениями; автоматическая ротация не включена. Библиотека удерживает неблокирующий межпроцессный замок; занятый журнал даёт отказ. `latest.json` AX-сенсора в этом сценарии не участвует.

## Отказы

Неподдержанный оператор, некорректное определение/UTF-8, неверные, повторные или смешанные аргументы, приватный путь внутри Git и отказ памяти дают код `2`, пустой stdout и объяснение в stderr. Флаги `--request-permissions` и `--permission-status` нельзя смешивать с исполнением: такой вызов отклоняется до обработки разрешений.

Ошибки содержимого оставляют исходные байты в памяти без производного результата. Ошибки аргументов, доступа к файлам и превышение входных пределов возникают до приёма и записи; сохранение недоступного или ещё не прочитанного источника не обещается. Две сырые записи не составляют общую транзакцию: после отказа второй может остаться только первая. Обработка начинается только после обеих квитанций. История не очищается при ошибке интерпретатора.

При ошибке записи прежний подтверждённый префикс сохраняется. После отказа синхронизации новая запись может быть видима, хотя квитанция не выдана; отсутствие ответа не доказывает отсутствия записи. Не повторяйте такой запуск вслепую. Прочитайте контейнер через его [штатные инструменты](../../Packages/КонтейнерНаблюдений/README.md), проверьте историю и выберите дальнейшее действие. Неполный хвост запрещает новое добавление; CLI исполнения не удаляет и не восстанавливает его автоматически. Аппаратная гарантия при отключении питания этим этапом не проверена.

Отдельная граница — вывод ответа в stdout после подтверждённого долговременного сохранения. Если эта запись в stdout выбрасывает перехватываемую ошибку, процесс возвращает код `2`, хотя наблюдение уже сохранено. Ответ может отсутствовать или быть частичным; метка `сохранение=успешно` относится к памяти. Отказ вывода не откатывает запись, поэтому слепой повтор может добавить ещё одно наблюдение. Идемпотентная доставка квитанции — повторная выдача того же подтверждения без нового добавления — пока не реализована.

## Проверки и профиль

```sh
swift test --package-path Приложения/FUMA/macOS --scratch-path "$FUM_BUILD_ROOT" --jobs 2 --filter 'ПроверкиИсполнения/'
python3 -B Приложения/FUMA/macOS/проверки/проверить-исполнение-оператора.py \
  --бинарник "$FUM_BUILD_ROOT/debug/fum" --профиль-выход "$FUM_BUILD_ROOT/профиль-SwiftPM.json"
python3 -B Приложения/FUMA/macOS/проверки/проверить-исполнение-оператора.py \
  --бинарник "$FUM_BUILD_ROOT/xcode/Build/Products/Debug/FUMA.app/Contents/MacOS/FUMA" \
  --профиль-выход "$FUM_BUILD_ROOT/профиль-Xcode.json"
```

Swift-тесты проверяют накопление, повтор после удаления исходных файлов и инъекции ENOSPC/ошибки `fsync`. Сценарий Python запускает настоящий бинарник последовательно, проверяет текстовый и байтовый результат с трассой, повторы обоих сценариев после удаления определения и входа, смешанные флаги разрешений, ошибки данных, приватность каталога и сохранность неполного хвоста. Байтовый повтор сохраняет ожидаемые 12 байтов UTF-32LE, три записи трассы и детерминированный хэш, создаёт новый идентификатор и дописывает историю без изменения прежнего префикса. Обычные пути приложения намеренно заданы недопустимыми: обращение к ним до раннего CLI не пройдёт проверку. Тестовый процесс ограничен 15 секундами; временные данные удаляются после проверки. Граница отказа stdout описана по порядку вызовов; отдельная инъекция этого отказа в данном наборе отсутствует.

Флаг `--профиль` выдаёт JSON-метки в stderr: вход, открытие памяти, сохранение исходных байтов, декодирование, исполнение и сохранение результата, а также вложенные этапы интерпретатора и контейнера. В каждой метке есть монотонная длительность, исход и глубина. Складывать родительские и вложенные интервалы нельзя. Диагностическая ошибка вывода не заменяет основной исход. Пять профильных образцов используют один открытый вход и накапливаются последовательно; полный процесс включает запуск рантайма, а сборка измеряется отдельно. Выход профиля связывает бинарник и фикстуры SHA-256.

Эта вертикаль не включает графический Metal-рендер и дальнейшие подсистемы FUMA. Наличие сборки и проверок ветки не означает интеграции в `master` или приёмки всей FUMA.

## Конечный срез JSONL

Отдельный режим исполняет полные строки явно указанного файла через тот же интерпретатор. Он сохраняет весь прочитанный вход, включая незавершённый хвост, а затем обрабатывает рамки по порядку. Этот вызов завершается после одного ограниченного среза; удержание живого источника до следующей строки и приём stdout Codex CLI пока не подключены.

Команды выполняются из физического корня FUM, с зависимостями и приватным каталогом, описанными выше. Программа [сообщений журнала Codex](../Операторы/сообщения-журнала-Codex.json) является определением языка версии 2 с замкнутыми дочерними определениями. Входная [открытая фикстура](../проверки/фикстуры/срез-журнала-Codex.jsonl) синтетически воспроизводит native rollout и не является исходным диалогом человека.

```sh
: "${FUM_BUILD_ROOT:?Задайте физический каталог вне Git}"
swift build --build-system native --package-path Приложения/FUMA/macOS \
  --scratch-path "$FUM_BUILD_ROOT" --jobs 2 --product fum
mkdir -m 700 "$FUM_BUILD_ROOT/наблюдения-JSONL"
"$FUM_BUILD_ROOT/debug/fum" --исполнить-JSONL \
  --определение "$(pwd -P)/Приложения/FUMA/macOS/Операторы/сообщения-журнала-Codex.json" \
  --вход "$(pwd -P)/Приложения/FUMA/macOS/проверки/фикстуры/срез-журнала-Codex.jsonl" \
  --журнал "$FUM_BUILD_ROOT/наблюдения-JSONL" --профиль
"$FUM_BUILD_ROOT/debug/fum" --повторить-JSONL 'идентификатор-из-квитанции' \
  --журнал "$FUM_BUILD_ROOT/наблюдения-JSONL" --профиль
```

Режим принимает только показанные аргументы; `--тип-входа` и `--источник-входа` к нему не относятся. Повторные, неизвестные и смешанные флаги отклоняются. Для Xcode используются те же аргументы основного файла FUMA.app; обязательные пути mpv берутся из штатной инструкции сборки.

До декодирования определения сохраняются три отдельных объекта: точные байты входа, исходное определение и профиль пределов. После проверки определения сохраняется его каноническое замыкание; лишь затем выделяются рамки и начинается их проверка и исполнение. Производная запись `fuma.исполнение-JSONL.1` ссылается на эти четыре квитанции. Сырые байты лежат в отдельных объектах контейнера и не дублируются внутри производного JSON. Части не составляют общую транзакцию: отказ второй сырой записи может оставить первую, а ошибочное определение — вход, определение и профиль без замыкания и результата.

Байтовая граница и хэш исходника охватывают весь принятый файл. `границаLF` описывает все полные рамки; `исполненныйПрефикс` — только принятые исполнения. LF входит в размер и SHA рамки, CR перед ним сохраняется, EOF не добавляет перевод строки. Незавершённый `сыройХвост` не декодируется и не исполняется. После отказа `неИсполненныйСуффикс` начинается с начала отказавшей рамки и включает весь остаток файла, в том числе хвост. Позиции относятся к исходным байтам, а число LF-рамок не выводится из native `ordinal`.

Каждая полная рамка проходит строгую проверку UTF-8 и всего JSON до исполнения. Повторные декодированные ключи, дроби, экспоненты, выход за Int64 и превышение глубины или числа узлов дают отказ рамки. Проверка распространяется и на ветви, которые программа не выбирает. Предметный выбор сообщения остаётся ленивым внутри графа: сначала `type=response_item`, затем `payload.type=message`; остальные события дают пустой массив. Выбранное сообщение требует строку `role` и массив `content`. Части `input_text` и `output_text` требуют строку `text`; иной типизированный объект части даёт `null` на прежнем индексе. Неверная выбранная форма, включая скалярную часть, даёт отказ интерпретатора. Выход содержит `{роль, части}`; порядок, повторы и цитаты сохраняются. Строка роли является производным значением и не подтверждает человеческие полномочия.

Профиль `fuma.профиль-JSONL.1` ограничивает весь исходник 1 048 576 байтами, строку вместе с LF или хвостом — 262 144 байтами, число полных рамок — 128. Исходное определение и его каноническое замыкание ограничены 65 536 байтами каждый. Общие пределы исполнения: 16 777 216 операций, 256 записей трассы, глубина JSON 16 от нулевого корня и 8192 узла рамки. Выходной предел 1 048 576 байт охватывает весь кодированный ответ `fuma.результат-JSONL.1`, включая квитанцию, метаданные и Base64 наблюдений. До очередного исполнения резервируется место для записи возможного отказа. Внутренний профиль может только уменьшать пределы; слишком малый выходной предел способен запретить исполнение ещё до первой рамки, если метаданные и отказ не помещаются. Старый одиночный режим сохраняет свой профиль и входной предел 262 144 байта.

Операции и трасса учитываются совместно для всего среза, без сброса между рамками. После успешного исполнения вычитается фактический расход. Отказ до вызова исполнителя имеет известный нулевой расход; при исключении исполнителя фактический расход и частичная трасса неизвестны, поэтому учитывается весь выданный остаток и дальнейших вызовов нет. Трасса включает шаги, правила и применения составных операторов; усечение отмечается `трассаПолна=false`. JSONL передаёт текстовые входы, поэтому байтовая трасса правил в этой вертикали не возникает. Счётчик операций отражает единицы интерпретатора, а не CPU-инструкции или полную стоимость хэширования и хранения.

Код `0` означает подтверждённое сохранение производной записи и вывод ответа. Такая запись может содержать `отказ`, а также незавершённый хвост: потребитель проверяет запись и исполненную границу. Ошибки аргументов, определения, входных пределов и хранения до подтверждённого результата дают код `2`. Отказ рамки прекращает срез и сохраняется вместе с принятым префиксом и полным суффиксом. Ошибка `fsync` может оставить видимую запись без квитанции; ошибка stdout после сохранения также даёт `2` и не откатывает память. Отсутствие ответа не разрешает слепой повтор.

Повтор читает исходник, оригинальное определение, замыкание и профиль из контейнера. Он проверяет идентичность, тип, версию, происхождение, размер и SHA каждой ссылки, канонические байты записи и профиля, повторно получает замыкание из оригинального определения и пересчитывает всю детерминированную запись. Только полное равенство разрешает новое сохранение. Файлы входа и всех определений больше не нужны. Повтор создаёт новую производную квитанцию с новым UUID и временем, сохраняя прежние четыре ссылки; это операция записи, а не просмотр архива.

## Проверки среза JSONL

`ПроверкиИсполненияСреза` получает два явно переданных входа: `ФУМА_ПРОГРАММА_ЖУРНАЛА` и `ФУМА_СЫРАЯ_ФИКСТУРА_ЖУРНАЛА`. Требуются физические абсолютные пути обычных непустых файлов без символических ссылок. Программа ограничена 65 536 байтами и SHA-256 `6bb83002feb375d36b96c25d6b7a34820e3482188ddb2c6ac11c4deb21fa61f7`; фикстура ограничена 1 048 576 байтами и SHA-256 `5fd0dc50d932b62c15ccea0bb4e56974834bfc80e65a54d1fb63a65e320cc646`. Отсутствующий, относительный, неподходящий или изменённый вход вызывает ошибку теста. Поиск по рабочему каталогу, запасной путь и пропуск проверки не используются.

В примерах `$1` — физический корень FUM, `$2` — абсолютный приватный каталог сборки вне Git. Адресный запуск оформляется отчётной обёрткой текущего этапа; дочерняя команда тестов:

~~~sh
env "ФУМА_ПРОГРАММА_ЖУРНАЛА=$1/Приложения/FUMA/macOS/Операторы/сообщения-журнала-Codex.json" \
  "ФУМА_СЫРАЯ_ФИКСТУРА_ЖУРНАЛА=$1/Приложения/FUMA/macOS/проверки/фикстуры/срез-журнала-Codex.jsonl" \
  swift test --package-path "$1/Приложения/FUMA/macOS" \
  --scratch-path "$2" --jobs 2 --filter ПроверкиИсполненияСреза
python3 -B "$1/Приложения/FUMA/macOS/проверки/проверить-и-измерить-JSONL.py" --самопроверка
~~~

Коллектор профиля запускается только через штатную отчётную обёртку: она задаёт канонический `FUM_CHECK_RUN_ID`. Python с `-O` или `-OO` отклоняется до подготовки каталогов и запуска `fum`. Для каждого сборщика нужны собственные новые приватные выходы, точные бинарники и `--повторов 25 --конфигурация Debug`. Бинарник хэшируется до и после 102 процессов. Сырые профили имеют схему `fuma.свидетельства-JSONL.2`; их UUID связывается с исходной успешной записью `fum.test-run.v4` этого этапа.

Публичную сводку `fuma.свидетельства-конечного-JSONL-среза.2` формирует `--сводка <приватный-вход> --выход <абсолютный-путь-выбранного-свидетельства>`. Приватный вход содержит два оригинальных профиля, две оригинальные записи v4 и независимо проверенные ожидания. Команда `--проверить-сводку` побайтно сверяет тот же результат без записи. Агрегатор проверяет исходные SHA, схемы, UUID, адрес Журнала, Debug/Darwin, бинарные и четыре входных хэша, полный состав 25 пар каждого корпуса и расширенную пару; распределения пересчитываются из исходных длительностей. В публичный результат не переходят PID, сырые каналы, приватные метки или локальные пути. Четыре хэша коллектора не доказывают происхождение сборки: оно проверяется отдельно по собственным исходникам, объявленным зависимостям, ресурсам и результатам сборки.

Текущие [публичные свидетельства](../проверки/JSONL/свидетельства.json) содержат 204 успешно завершённых процесса. Медианы полного процесса в миллисекундах:

| Сборщик | Корпус | Прямое исполнение | Повтор |
| --- | --- | ---: | ---: |
| SwiftPM Debug | 782 байта | 86,518208 | 86,304583 |
| SwiftPM Debug | 1 МиБ | 306,635375 | 307,890792 |
| Xcode Debug | 782 байта | 89,173167 | 89,274208 |
| Xcode Debug | 1 МиБ | 310,320833 | 310,181792 |

Все 25 замеров каждого режима, включая первый запуск, сохранены в сводке. Это измерение двух сборок, без вывода об ускорении или стоимости отдельной операции. Собственные объявленные входы сборок, ресурсы, продукты и объявленный Mach-O граф совпали до и после процессов; полное содержимое Apple SDK/shared cache и динамические загрузки через `dlopen` этой сверкой не доказаны.

Публичная агрегация оригинальных профилей дала три полных вызова 73,791375, 63,688708 и 62,919084 мс с теми же выходными байтами. Отдельный запуск с `tracemalloc` показал пик 7 162 185 байтов; это не RSS, его длительность не сравнивается с обычными вызовами. Ограниченный пересчёт по двум профилям сохранён: измерения укладываются в заранее выбранные пределы одной секунды на вызов и 64 МиБ отдельного пика, основания менять алгоритм отсутствуют. Корректность дополнительно подтверждают девять самопроверок и сравнение с оригинальными входами.

Сценарий запускает по 25 пар прямого исполнения и повтора на каждом из двух корпусов: native-фикстуре и точном входе 1 МиБ с четырьмя рамками по 262 144 байта. Перед повтором удаляются исходник и все файлы определения, затем запускается другой процесс. Отдельная пара подтверждает повтор исходника 262 150 байт, превышающего старый одиночный предел. Проверяются буквальные оракулы и равенство всей записи. Всего на один сборщик приходится 102 завершённых процесса; таймаут одного — 60 секунд. Полные каналы и измерения сохраняются вне Git, а [публичные свидетельства](../проверки/JSONL/свидетельства.json) связывают исходники и бинарники хэшами и сохраняют все 25 замеров каждого режима.

Сценарий рассчитан на Debug на Darwin отдельно для SwiftPM и Xcode; актуальные результаты связываются с исходными записями запусков текущего Журнала. Полный процесс включает запуск runtime, чтение и `fsync`; подготовка и сравнение исключены. Вложенные метки не суммируются с родительскими, пик строки означает длину в байтах, а не RSS. Проверки этого среза не подтверждают live/tailing, формат stdout Codex CLI, оптимизированную сборку, другие платформы или преимущество над LLM. Общий языковой остаток, 213 употреблений и дальнейшая миграция DTO остаются отдельной работой. Полная братиславская проекция и общий smoke-check остановлены; этот перенос сохраняет контрольную точку.
