# Исполнение оператора в FUMA

Основной бинарник FUMA принимает явное определение структурирующего оператора и входной файл, вызывает существующий Swift-интерпретатор в своём процессе и сохраняет наблюдение в накопительную память. Командный режим завершается до создания сцены и обработки разрешений. Вызов не запускает помощника или IPC.

## Первый сценарий: UTF-8 → UTF-32LE

Сохранённое [требование FUM-REQ-0067](../../../../Требования/🟡-чистое-исполнение-операторов-и-UTF-32.md) задаёт первый предметный сценарий: исходные байты UTF-8 → Unicode-скаляры → UTF-32 с явным порядком байтов. Ниже выполняется его вариант UTF-32LE без нормализации и BOM. Потоковая обработка порциями этим конечным вызовом не подтверждается.

Нужны зависимости и сборка из [руководства приложения](../README.md#зависимости-и-сборка): macOS с Xcode/Swift 6, системные mpv и pkg-config. Обе локальные библиотеки входят в чистый клон FUM; отдельные репозитории собственного кода не нужны. SwiftPM использует пакет интерпретатора из `Прототипы/память-структурирующих-операторов` и пакет `КонтейнерНаблюдений` из `Приложения/FUMA/Packages`.

Команды ниже выполняются из физического корня FUM. `FUM_BUILD_ROOT` — заранее выбранный существующий абсолютный физический каталог вне любого Git checkout. Каталог журнала должен существовать, принадлежать текущему пользователю, иметь права `0700` и не содержать символических ссылок в пути. Приложение не выбирает место хранения автоматически.

```sh
: "${FUM_BUILD_ROOT:?Задайте физический каталог вне Git}"
swift build --package-path Приложения/FUMA/macOS --scratch-path "$FUM_BUILD_ROOT" --jobs 2 --product fum
mkdir -m 700 "$FUM_BUILD_ROOT/наблюдения"
printf '%s' 'Aё🙂' > "$FUM_BUILD_ROOT/вход-UTF-8.txt"
"$FUM_BUILD_ROOT/debug/fum" --выполнить-оператор \
  --определение "$(pwd -P)/Прототипы/память-структурирующих-операторов/Sources/FUMStructuringOperatorMemory/Определения/UTF-8-в-UTF-32LE.json" \
  --вход "$FUM_BUILD_ROOT/вход-UTF-8.txt" \
  --тип-входа байты --журнал "$FUM_BUILD_ROOT/наблюдения"
```

В stdout возвращается JSON `fuma.результат-исполнения.1` с `наблюдение` и `квитанция`. Результат содержит 12 байтов UTF-32LE: `41 00 00 00 51 04 00 00 42 F6 01 00`, а трасса — три правила декодирования. Код `0` возвращается после подтверждённого сохранения и записи ответа. В `квитанция.описание.идентификатор` находится идентификатор долговременной записи.

Повтор использует сохранённые принятые данные; исходные файлы больше не нужны. Подставьте полученный идентификатор:

```sh
"$FUM_BUILD_ROOT/debug/fum" --повторить-оператор 'идентификатор-из-квитанции' \
  --журнал "$FUM_BUILD_ROOT/наблюдения"
```

Успешный повтор сверяет детерминированный хэш и создаёт новое наблюдение с новым идентификатором и временем. Сами принятые данные и детерминированный результат сохраняются без изменения. Расхождение при повторе завершается отказом до добавления записи.

Для Xcode выполните [штатную сборку FUMA.app](../README.md#зависимости-и-сборка). Те же аргументы принимает основной файл `"$FUM_BUILD_ROOT/xcode/Build/Products/Debug/FUMA.app/Contents/MacOS/FUMA"`. Xcode подключает обе библиотеки как локальные пакетные продукты, включая ресурсы интерпретатора.

Дополнительный текстовый сценарий использует `Определения/нормализация.json`, вход `Приложения/FUMA/macOS/проверки/фикстуры/вход-оператора.txt` и `--тип-входа текст`. Его результат — `привет ёж`; на нём измеряется профиль ниже.

## Принятый вход и память

Поддерживаются два явных типа входа: `текст` — строгий UTF-8, `байты` — точные байты файла. Определение разбирается существующим `ОпределениеОператора.разобрать`; новая копия декодера или интерпретатора не вводится. Для байтового сценария пригодно сохранённое определение `UTF-8-в-UTF-32LE.json`. Отдельный вход для массива скаляров или готового структурного объекта в этой вертикали не объявлен; структурный контракт можно передать текстом соответствующему существующему оператору.

Payload записи `fuma.исполнение-оператора.1` содержит:

- `принятыеДанные`: точные исходные байты определения, его проверенное каноническое представление, исходные байты входа, тип и полный профиль пределов;
- `наблюдение`: результат существующего исполнителя, идентичность/версию определения, хэши, следы шагов, имеющуюся трассу правил, число пропущенных записей и выполненных операций.

Поля `Data` сериализованы стандартным JSONEncoder как Base64. Идентификатор и время находятся в описании контейнера и не входят в детерминированный payload. Профиль измерений также не входит в него. Профиль исполнителя версии 1 закрепляет пределы: определение до 65 536 байтов, вход до 262 144 байтов, результат до 1 048 576 байтов, до 16 777 216 операций и до 256 записей трассы. Изменение профиля требует новой версии; повторы неизвестного профиля отклоняются. Повтор Unicode-преобразований предполагает совместимый Swift/Foundation runtime; хэш выявляет расхождение между версиями.

Контейнер дописывает группы в `сегмент.fumobs`, проверяет прежнюю историю и возвращает квитанцию только после записи и `fsync` файла и каталога. Сегмент ограничен 256 МиБ и 4096 наблюдениями; автоматическая ротация не включена. Библиотека удерживает неблокирующий межпроцессный замок; занятый журнал даёт отказ. `latest.json` AX-сенсора в этом сценарии не участвует.

## Отказы

Неподдержанный оператор, некорректное определение/UTF-8, неверные, повторные или смешанные аргументы, приватный путь внутри Git и отказ памяти дают код `2`, пустой stdout и объяснение в stderr. Флаги `--request-permissions` и `--permission-status` нельзя смешивать с исполнением: такой вызов отклоняется до обработки разрешений.

При ошибке записи прежний подтверждённый префикс сохраняется. После отказа синхронизации новая запись может быть видима, хотя квитанция не выдана; отсутствие ответа не доказывает отсутствия записи. Не повторяйте такой запуск вслепую. Прочитайте контейнер через его [штатные инструменты](../../Packages/КонтейнерНаблюдений/README.md), проверьте историю и выберите дальнейшее действие. Неполный хвост запрещает новое добавление; CLI исполнения не удаляет и не восстанавливает его автоматически. Аппаратная гарантия при отключении питания этим этапом не проверена.

## Проверки и профиль

```sh
swift test --package-path Приложения/FUMA/macOS --scratch-path "$FUM_BUILD_ROOT" --jobs 2 --filter ПроверкиИсполнения
python3 -B Приложения/FUMA/macOS/проверки/проверить-исполнение-оператора.py \
  --бинарник "$FUM_BUILD_ROOT/debug/fum" --профиль-выход "$FUM_BUILD_ROOT/профиль-SwiftPM.json"
python3 -B Приложения/FUMA/macOS/проверки/проверить-исполнение-оператора.py \
  --бинарник "$FUM_BUILD_ROOT/xcode/Build/Products/Debug/FUMA.app/Contents/MacOS/FUMA" \
  --профиль-выход "$FUM_BUILD_ROOT/профиль-Xcode.json"
```

Swift-тесты проверяют накопление, повтор после удаления исходных файлов и инъекции ENOSPC/ошибки `fsync`. Сценарий Python запускает настоящий бинарник последовательно, проверяет текстовый и байтовый результат с трассой, повтор, смешанные флаги разрешений, ошибки данных, приватность каталога и сохранность неполного хвоста. Обычные пути приложения намеренно заданы недопустимыми: обращение к ним до раннего CLI не пройдёт проверку. Тестовый процесс ограничен 15 секундами; временные данные удаляются после проверки.

Флаг `--профиль` выдаёт JSON-метки в stderr: вход, декодирование, исполнение и сохранение, а также вложенные этапы интерпретатора и контейнера. В каждой метке есть монотонная длительность, исход и глубина. Складывать родительские и вложенные интервалы нельзя. Диагностическая ошибка вывода не заменяет основной исход. Пять профильных образцов используют один открытый вход и накапливаются последовательно; полный процесс включает запуск рантайма, а сборка измеряется отдельно. Выход профиля связывает бинарник и фикстуры SHA-256.

Эта вертикаль не включает графический Metal-рендер и дальнейшие подсистемы FUMA. Наличие сборки и проверок ветки не означает интеграции в `master` или приёмки всей FUMA.
