# Приложение FUM для macOS

Канонические исходники приложения находятся в `Приложения/FUMA/macOS` монорепозитория FUM. Здесь сохранены 39 файлов собственной наработки из коммита `39eb66a29c0be6844e73bcb8072e68b914ea7387` с адаптацией путей и сборки. Исторические имена продуктов сохранены. Исходные и конечные хэши перечислены в [манифесте переноса](манифест-переноса.json).

## Состав

- `fum` — приложение с экранным присутствием, Accessibility, монитором ввода и видеопамятью; встроенная вкладка Camera временно выключена.
- `fum-mcp` — файловый stdio MCP-шлюз к приложению: состояние, экранные команды, AX-снимки, события ввода, заметки и поиск памяти.
- `fum-attention-loop` — цикл чтения снимков и записи сжатых событий внимания.
- `fum-ax-vision-sense` — сохранённый самостоятельный Accessibility-сенсор.
- [Векторный формат монтажа](docs/vector-video-format.md) — ссылки на медиаматериалы, дорожки и эффекты без обязательного экспорта видео.

Монитор приложения сохраняет также символы клавиатуры и использует настенное время. Цикл внимания удаляет поля символов из собственных агрегатов. Контракт физических переходов клавиш отдельного прототипа FUM этим переносом не реализован.

## Зависимости и сборка

Нужны macOS, Xcode с SDK macOS и Swift 6, а также системные `mpv` и `pkg-config`. SwiftPM получает заголовки и библиотеку через `.systemLibrary`, `pkgConfig: "mpv"` и собственный модуль `CMpvSystem`. Заголовки и исходники mpv в FUM не копируются. При использовании Homebrew зависимости подготавливаются отдельно:

```sh
brew install mpv pkgconf
export PKG_CONFIG_PATH="$(brew --prefix mpv)/lib/pkgconfig${PKG_CONFIG_PATH:+:$PKG_CONFIG_PATH}"
```

Эта команда выбирает доступную версию Homebrew, а не закрепляет проверенный bottle. Сборка из корня чистого клона FUM:

```sh
: "${FUM_BUILD_ROOT:?Задайте абсолютный каталог сборки вне Git}"
swift test --package-path Приложения/FUMA/macOS --scratch-path "$FUM_BUILD_ROOT" --jobs 2
swift build --package-path Приложения/FUMA/macOS --scratch-path "$FUM_BUILD_ROOT" --jobs 2 -c release
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Приложения/FUMA/macOS/проверки -p 'test_*.py'
```

Swift-тесты используют только временные фикстуры конфигурации путей. Python-проверки подставляют собственный `swift` для проверки runner и не запускают настоящий helper. Артефакты сборки должны находиться вне Git. Сборка не устанавливает и не запускает приложение.

Профиль общей конфигурации воспроизводится отдельно: пять образцов по 1000 разрешений абсолютных путей, отказов относительного пути и поисков отсутствующей команды в заданном `PATH`, без создания runtime-файлов. Каталог `FUM_BUILD_ROOT` должен быть заранее создан вне Git.

```sh
swiftc -O -parse-as-library Приложения/FUMA/macOS/Sources/ПутиИсполнения/ПутиПриложения.swift \
  Приложения/FUMA/macOS/проверки/профиль-путей.swift -o "$FUM_BUILD_ROOT/профиль-путей"
"$FUM_BUILD_ROOT/профиль-путей"
```

Проверка и профиль C-адаптера используют подставные `dlsym` и `dlopen`. Системный mpv участвует в линковке, его функции не вызываются:

```sh
clang -IПриложения/FUMA/macOS/Sources/CMpvShim/include \
  -I"$(pkg-config --variable=includedir mpv)" Приложения/FUMA/macOS/проверки/проверка-C-адаптера.c \
  -L"$(pkg-config --variable=libdir mpv)" -lmpv -framework OpenGL -o "$FUM_BUILD_ROOT/проверка-C-адаптера"
"$FUM_BUILD_ROOT/проверка-C-адаптера"
```

Нативный `FUM.xcodeproj` содержит цели приложения и MCP helper. Общий файл путей включён в обе цели; системные каталоги передаются при вызове, а не хранятся в проекте:

Обычный Xcode build также регистрирует собранный bundle в LaunchServices внутри каталога сборки. Это наблюдённый системный шаг сборки; приложение при этом не запускается.

```sh
xcodebuild -project Приложения/FUMA/macOS/FUM.xcodeproj -scheme FUM \
  -configuration Debug -derivedDataPath "$FUM_BUILD_ROOT/xcode" -jobs 2 \
  FUM_MPV_INCLUDEDIR="$(pkg-config --variable=includedir mpv)" \
  FUM_MPV_LIBDIR="$(pkg-config --variable=libdir mpv)" \
  CODE_SIGNING_ALLOWED=NO build
```

## Конфигурация данных

Все процессы используют общую конфигурацию `ПутиИсполнения`. Переменные задают абсолютные каталоги; отсутствующие значения получают следующие значения по умолчанию. Пустое значение отклоняется.

| Переменная         | Назначение            | Значение относительно домашнего каталога |
| ------------------ | --------------------- | ---------------------------------------- |
| `FUM_RUNTIME_ROOT`  | Текущие снимки        | `Library/Application Support/FUM/run`    |
| `FUM_MEMORY_ROOT`   | Долговременная память | `Library/Application Support/FUM/memory` |
| `FUM_DOCUMENTS_ROOT`| Библиотека документов | `Documents`                             |

Runtime и память отклоняются внутри Git checkout, включая его символические псевдонимы. Конфигурация сама не создаёт каталоги. Путь документов служит выбранной пользователем библиотекой. Прежние `FUM_MCP_ROOT`, `FUM_ATTENTION_ROOT` и привязка к конфигурации Codex больше не определяют пути: для переноса существующих данных явно задайте новые переменные. Автоматического перемещения старых данных нет. `FUM_RUNTIME_ROOT` указывает непосредственно на каталог снимков, дополнительный `run` к нему не добавляется.

В runtime находятся `mcp/screen.json`, `senses/ax-vision/latest.json`, `senses/input/latest.json`, `realtime/attention/latest.json` и `camera/known-people.json`. В памяти сохраняются JSONL под `senses/input`, `senses/ax-vision`, `video-player`, `mcp` и `realtime/attention-loop`. Эти данные не являются исходниками.

`script/fum_mcp.sh` разрешает пакет относительно собственного файла и перед запуском проверяет актуальность release helper через SwiftPM во внешнем `FUM_BUILD_ROOT`. Для явно выбранного уже установленного helper можно задать `FUM_MCP_APP_HELPER`; автоматического выбора прежней установки нет. Запуск runner начинает живой MCP-процесс и выполняется отдельно от проверок переноса.

MCP получает `pgrep` из абсолютных каталогов `PATH` либо из явно заданного `FUM_PGREP_EXECUTABLE`; текущий каталог не подставляется. `FUM_APP_BUNDLE` задаёт путь установленного bundle для поля статуса, при отсутствии конфигурации поле равно `null`. Исторические шаблоны требуют явных `FUM_APPLICATIONS_DIR`, `FUM_LAUNCH_AGENTS_DIR`, `FUM_KEYCHAIN_PATH` и `FUM_PLIST_BUDDY`; системные команды разрешаются через `PATH`. Значения по умолчанию для runtime и памяти вычисляет общий Swift-модуль через Foundation.

OpenGL.framework явно линкуется в SwiftPM и Xcode; обычный поиск символов использует `RTLD_DEFAULT`. Только для дополнительной библиотеки при отсутствующем символе можно явно задать `FUM_OPENGL_LIBRARY`. Синтетическая проверка C-адаптера подменяет загрузчик и не подтверждает воспроизведение видео. Шаблон подписи дополнительно требует `FUM_NULL_DEVICE` и `FUM_CERT_SUBJECT`; их значения не вычисляются и системные операции здесь не выполняются.

## Неприменённые шаблоны установки

Три `script/install_*.sh` сохранены как исторические шаблоны и немедленно завершаются кодом 2 до установки. В `launchd/*.plist` используются незаполненные маркеры `${FUM_RUNTIME_ROOT}`, `${FUM_MEMORY_ROOT}`, `${FUM_BUILD_ROOT}` и `${FUM_APP_BUNDLE}`. Launchd сам эти маркеры не раскрывает. Файлы не готовы к загрузке: подстановка, подпись, установка, Keychain и выдача системных разрешений требуют отдельной подготовки. Sandbox в исторических entitlements выключен; перенос это не изменяет. Приложение, сенсоры, установка и запросы разрешений при проверке переноса не запускаются.

## Наблюдённая среда и лицензии

Проверенная локальная зависимость — Homebrew mpv `0.41.0_9`, `pkg-config` `3.0.7`, клиентский API mpv `2.5` (`mpv.pc` сообщает `2.5.0`, это не версия самого mpv). Установленный bottle содержит arm64 dylib с минимальной macOS `26.0` и SDK `26.5`. Объявленная в проекте macOS 14 не доказывает работоспособность этого bottle на macOS 14/15 или Intel. Динамическая библиотека и её зависимости сохраняют абсолютные Homebrew install names: собранное приложение зависит от системной установки и не является автономной переносимой поставкой `.app`.

В исходной наработке отдельного LICENSE не было. Собственный код сохраняется в монорепозитории FUM под его CC0; лицензии системных библиотек остаются самостоятельными. По [Copyright mpv 0.41.0](https://github.com/mpv-player/mpv/blob/v0.41.0/Copyright) режим по умолчанию — GPLv2+, LGPL применяется лишь к соответствующей сборке. У наблюдённой формулы нет `-Dgpl=false`; установленный FFmpeg собран с `--enable-gpl --enable-version3`. Отдельный заголовок `client.h` имеет ISC. Этот набор нельзя описывать как LGPL-only или CC0, и перенос собственного кода не означает готовность бинарной публикации.

Механизм зависимости описан в [документации SwiftPM](https://github.com/swiftlang/swift-package-manager/blob/main/Sources/PackageManagerDocs/Documentation.docc/Dependencies/AddingSystemLibraryDependency.md). Машинные значения Xcode передаются снаружи; [xcconfig](https://developer.apple.com/documentation/xcode/adding-a-build-configuration-file-to-your-project) самостоятельно shell-команды не исполняет.
