# Подготовка FUMA для iOS

Пользователь активировал направление iOS. Первая поставка — приложение FUMA в Simulator с общими Swift-пакетами интерпретатора и контейнера. Запуск ещё не подтверждён. [Исходная команда и ответ](../../Журнал/2026-09-15_20-55-24_MSK_сохранить-медийный-план-и-запуски-платформ/отчёт.md).

## Первый воспроизводимый результат

Автоматизация собирает и запускает приложение на явно выбранном установленном iOS Simulator. Действие интерфейса выполняет существующее операторное преобразование строки «Aё🙂» в UTF-32LE, сохраняет определение, вход, результат и трассу в контейнер внутри sandbox. После перезапуска приложение воспроизводит те же значения по сохранённым данным без исходных внешних файлов. Ошибки записи видны человеку; успешная квитанция при отказе не появляется.

Срезы принимаются последовательно: сначала общий runtime, сохранение и replay в приложении; затем минимальный Metal-кадр из операторной сцены. Отсутствие готовой общей сцены не блокирует первую проверку runtime и не разрешает её дублирование в iOS.

Собственный графический путь iOS — Metal. Первый графический срез переводит минимальную общую операторную сцену в наблюдаемый кадр. Системная оболочка отвечает за поверхность, ввод и жизненный цикл. Шрифтовой рендер не подменяется CoreText. Доступность Metal в выбранном Simulator проверяется отдельно; его успех не доказывает работу физического iPhone.

## Владение и проверки

Платформенные импорты и реализации выбираются через #if canImport и #if os в соответствующих компонентах; условия линковки задаются и в общем манифесте. Наличие модуля не доказывает наличие конкретного API или возможности GPU. Разделение по сущностям сохраняется, отдельных деревьев кода на ОС нет.

Позднее уточнение пользователя отменило отдельный каталог Swift-кода iOS. Целевая структура — единый Приложения/FUMA/Package.swift с общими Sources и Tests по модулям и сущностям. iOS пишет только явно назначенные новые файлы этой общей структуры и необходимые настройки сборки приложения. Общий манифест, перенос существующих исходников и переносимость контейнера/интерпретатора принадлежат одному владельцу Android. До его поставки iOS не изменяет перемещаемые файлы; может независимо проверять установленный Simulator и готовить конфигурацию без дублирования ядра.

Проверки устанавливают точные байты, replay после перезапуска, сохранность при отказе и отсутствие ложного успеха. Исполняемые изменения проходят TDD и профиль. Измерения разделяют сборку, запуск, преобразование, запись и replay; решение об оптимизации относится к сопоставимому сценарию.

Версии Xcode, SDK и Simulator наблюдаются перед сборкой. Сборки и данные приложения остаются вне Git. Платная регистрация, App Store, подпись для распространения и действия с физическим устройством этим срезом не назначены. Недостающая среда или несовместимость пакета сохраняются как конкретное препятствие.

Постановка связана с существующими [платформенным требованием](../../Требования/🟡-запуск-FUMA-на-целевых-платформах.md), [графическим требованием](../../Требования/🟡-графические-интерфейсы-FUMA.md) и [FUM-STEP-0182](../../Планирование/карточки-шагов/🟡-FUM-STEP-0182-определить-платформенные-сборки-и-первый-сценарий-FUMA.md); новых номеров этот этап не выдаёт.
