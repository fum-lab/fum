# Подготовка FUMA для Android

Статус: принято в работу отдельное направление подготовки runtime. Запуск FUMA на Android пока не подтверждён. Основание — [поручение и ответы](../../Журнал/2026-09-15_20-33-17_MSK_принять-обновлённое-постоянное-планирование/запрос.md).

FUMA развивается на единой собственной кодовой базе в монорепозитории. Общие Swift-пакеты содержат интерпретатор структурирующих операторов, форматы наблюдений и переносимую логику. Платформенные адаптеры предоставляют хранение, ввод, жизненный цикл, графическую поверхность и системные возможности. Исключения доступности обозначаются явно; модули macOS не импортируются в общее ядро.

## Первый ограниченный результат

1. Проверить уже существующие пакеты и зависимости, выделить минимальный переносимый срез без дублирования интерпретатора.
2. Подготовить воспроизводимую автоматизацию установки согласованных Swift toolchain, Swift SDK for Android и Android NDK; версии и хэши закрепить после фактической проверки. Учесть существующий план зеркал, лицензии и автономную поставку.
3. Собрать общий сценарий UTF-8 → Unicode-скаляры → UTF-32 и запись/повтор наблюдения для явного Android ABI и уровня API.
4. Выполнить сценарий на доступном эмуляторе либо устройстве через автоматизацию. Сохранить полный вход, ожидаемые и фактические байты, код процесса, платформу и происхождение. Компиляция отдельно от запуска.
5. Выполнить необходимые RED/GREEN, измерить время запуска, исполнения и перехода через платформенный мост, оценить оптимизации. Сборки и тесты macOS не повторять без затронутого контракта.

Минимальное Android-приложение может потребовать тонкой Java/Kotlin-оболочки и JNI. Предпочтение — общая логика на Swift; объём платформенного кода определяется реальными ограничениями SDK. Нет обещания единственного бинарника для всех ОС и отсутствия любого моста.

## Собственный интерфейс

Интерфейс по возможности полностью собственный. Общее описание сцены и поведения строится структурирующими операторами; платформенные исполнители выдают команды Metal или Vulkan. Для Android первым графическим путём планируется Vulkan. Системная поверхность, ввод, доступность и жизненный цикл требуют отдельных контрактов и проверки. Пиксельное совпадение разных GPU заранее не объявляется.

Первый runtime-срез не включает завершённый графический интерфейс. Следующий срез связывает общий граф сцены с Vulkan, проверяет событие ввода и один наблюдаемый кадр. Прежняя цель DirectX остаётся для применимых профилей; последнее уточнение не было её явной отменой.
