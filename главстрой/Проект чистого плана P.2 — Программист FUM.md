Автор предметного результата — Программист FUM. Сохранено Главстроем по согласованию с автором как личная проектная память, не канонический код. Два diff ниже — инертные исторические цитаты, не запускать и не устанавливать по этой записи. Код не принят, тесты NOT_RUN, доверенный вызывающий и установка HOLD; первый кандидат допускает подмену callable. Второй diff применяется к тесту после первого.

## Границы проекта

Кандидат: отдельный промежуточный план собственной пары без соседей.
Он не устанавливает пару, не меняет закрытые guards и не подтверждает право записи.

## Контракт и остатки

Состояние: проект проверок и контракта; исполнимый доверенный вызывающий ещё
не выделен. Не является приёмкой 46cf, разрешением установки или открытием
обёртки. Код кандидата, Git и тесты этим исследованием не запускались;
маршрутизатор правил собственного checkout вызван только для выбора маршрута.

Тестовое дополнение после candidate 46cf:
дополнение-к-46cf.patch.DATA SHA-256
4ce215278da7bbe0773ec1e183680dccbca5012ee0f5e32104e985ad037f4a58
Предобраз теста 9dca8af94e0ff97a9dece6da4876d98ef6c36259f448a4b448b7fe85e1dc9f3b;
итог теста 3a41731d64040e3c4b2d1b7df14d3592600c0b1b4f7665e85636d478d729c8cf.
Исходный candidate.patch.DATA остаётся без изменений, SHA-256
46cf96643e994c8bd10265a46fd19c5a3ad92b0024bd1f4eb69a82c0be646139.

Ожидаемые запрос и отчёт целиком заданы отдельными фиксированными текстами,
которые код проверки кодирует UTF-8 и сравнивает с обоими полученными файлами.
Они не вычисляются из результатов renderer или его шаблонов во время теста.
Фикстура содержит CRLF внутри одного сообщения и повтор текста. Байты и
ожидаемый результат следует дополнительно независимо сверить при допуске:
проверка не выполнялась.

Отрицательный случай оборачивает настоящий _новый_запрос вызываемым объектом,
возвращающим тот же результат. Исходные четыре ресурса и их SHA не меняются;
ожидается отказ до вызова этой обёртки. Статически 46cf обращается к ней через
изменяемый словарь globals и отказа не делает. Это прогноз RED, не результат
выполненного теста. Существующий вызов напрямую в одном интерпретаторе также
не является испытанием доверенного bootstrap.

Почему сейчас нет безопасного исполнимого prerequisite:
- Существующий Контур исполняет проектный K из заранее принятого commit/blob,
  а источник 46cf не входит в принятый K. Самохэш после импорта доказывает
  только прочитанный файл, а не реально исполненные функции.
- Контур запускает вход как __main__; существующий CLI не направляет этот
  вход к новой чистой функции. До отдельной проверяемой точки входа скрытый
  доступ к обычному установщику, подмена guard или ad-hoc запуск запрещены.
- Не закреплены доверенный bootstrap, полный набор проекта и зависимостей,
  интерпретатор/stdlib и модель изменяемых globals. Четыре SHA данных сами
  по себе не привязывают их к коду и не удостоверяют происхождение сообщений.

Минимальный будущий вызывающий, который можно отдельно реализовать и принять:
1. Принятый заранее изолированный bootstrap выбирает по утверждённому
   commit/blob точный K: существующий CLI с явно выделенным только чтением
   действием чистого плана и request_folder_layout.py. У P.2 ожидаемый
   SHA-256 f90ecab2b75cfc86d095d93036d498be399e77a45cba4741914e3389ebd268e2.
   Пин patched CLI, bootstrap, все проектные импорты и доверенная область
   CPython/stdlib/нативных библиотек задаются и проверяются независимо до
   запуска; здесь они не выбраны. Нельзя брать их из поля входа caller.
2. Новый процесс -I -S -B запускается с явно заданной средой. До первого
   проектного импорта должны отсутствовать занятые имена из реестра K;
   импорт request_folder_layout ведёт исключительно к байтам K. Вызывающий
   не принимает произвольную функцию, модуль или callback от входа.
3. Действие вызывается через явный подрежим CLI, принимает только ограниченный
   типизированный синтетический вход по stdin и возвращает пару по stdout;
   код/ресурсы не выбираются произвольными путями вызывающего. Нет чтения
   ROOT JSONL, поиска соседей, записи, установки или вызова прежнего start.
   Передаваемые файлы проверяются по трём закреплённым SHA шаблонов: f1cf28e4…,
   6db76ec5… и 87d23d0c…; их полные значения уже находятся в candidate 46cf.
   Поле разрешения установки всегда false; происхождение сообщений остаётся
   неподтверждённым до отдельного принятого источника.
4. До вызова контролировать не только идентичность функции и code object из
   принятого K, но и её globals, вызываемые вспомогательные функции, константы
   и стандартные зависимости. Модель должна исключать недоверенный код,
   повторный вход и конкурирующие мутации между проверкой и вызовом.
   Обратная подмена code object, globals или зависимости должна закрывать
   исполнение до первого вызова; один тест wrapper не доказывает весь граф.
   Самочтение P.2 через __file__, проверка имён импортов, совместимость
   выбранного runtime и политика чтения в Контуре требуют отдельных проверок.
5. P.1 проверяется отдельно из его принятого K с точным SHA строителя
   9f30f1720438c09b36b6dc64686f65bde632d0c3796c846ab06f01ddc28e9305:
   прежний CLI, байты, исключения и эффекты сравниваются до/после изменения
   на собственной фикстуре. Непопадание P.1 в patch само по себе не доказывает
   поведение изменённого CLI. Исполняемые пробы выполняет только ROOT по
   принятому маршруту проверок и без добавления новых .py.

Перед любым эффектом дополнительно требуется отдельный контракт безопасного
создания пары без перезаписи и неоднозначного повтора, учёт ошибок/UNKNOWN,
доказательство точного текста человека и обратной ссылки. Ни план, ни этот
контракт, ни успешные в будущем синтетические тесты не дают этого допуска.
