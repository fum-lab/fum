# [Открытый вопрос](../Глоссарий/открытый-вопрос.md): развилка гиперсети и агентского цикла [FUM](../Глоссарий/FUM.md)

Вопрос частично прояснён. Ближайший действующий прототип [FUM](../Глоссарий/FUM.md) можно вести по двум разным траекториям, и они проверяют разные свойства проекта.

Первый путь - быстрее развернуть прототип [нейронной гиперсети FUM](../Глоссарий/нейронная-гиперсеть-FUM.md) на текущей Git-инфраструктуре, Codex и локальной [памяти FUM](../Глоссарий/память-FUM.md). Такой путь даёт уже действующий контур требований, документов, запросов, журналов, проверок, коммитов и пошагового отбора. Его риск в том, что собственный [агентский цикл](../Глоссарий/агентский-цикл.md) FUM остаётся не полностью доступным: внешний цикл Codex ведёт работу, а FUM пока наследует его через правила репозитория, а не исполняет собственный вложенный цикл.

Второй путь - начинать с реализации минимального агентского цикла. Он ближе к архитектурному ядру FUM, потому что позволяет явно управлять наблюдением, выбором действия, модельным шагом, проверкой, остановкой и записью трассы. Его риск в том, что для вложения циклов друг в друга нужен управляемый чистый модельный шаг: локальная LLM, проверяемая заглушка или режим `Codex CLI`, где он работает как простой LLM-провайдер, а не как самостоятельный агентский цикл.

## Неоднозначность

Неясно, какой первый прототип даст более честное основание для дальнейшей [коробочной реализации FUM](../Глоссарий/коробочная-реализация-FUM.md).

Прототип на Git + Codex быстрее показывает гиперсетевую природу FUM: память развивается, запросы связываются, производная документация уточняется, локальные автоматизации проверяют результат, а Git фиксирует наследование изменений. Но такой прототип может подтвердить только внешнюю организацию памяти и отбора, если не отделить слой FUM от управляющего агентского цикла Codex.

Прототип собственного цикла лучше проверяет рекурсивность и возможность вложения циклов: один цикл может вызвать, ограничить, наблюдать или оценить другой. Но для этого нельзя полагаться на непрозрачный внешний агентский runtime как на модельный шаг. Нужно понять, доступна ли чистая LLM локально, достаточно ли она качественна для задач FUM, или можно использовать `Codex CLI` строго в режиме LLM-провайдера без делегирования ему всего цикла.

## Вопросы для прояснения

- Какой минимальный результат доказывает, что прототип на Git + Codex является прототипом гиперсетевой FUM, а не только хорошо оформленной рабочей сессией во внешнем агенте?
- Как будущий реальный провайдер должен подтвердить совместимость с контрактом чистого модельного шага: идентичность модели, параметры генерации, предел времени, отмену и отсутствие скрытых действий?
- Можно ли использовать `Codex CLI` как простой LLM-провайдер без передачи ему всего агентского цикла, и как это проверить локально без сетевых секретов в тестах?
- Если нужен локальный LLM-провайдер, какие минимальные требования к качеству, контексту, скорости и стоимости достаточны для первого ограниченного цикла?
- Как сравнивать два пути на одной фикстуре: гиперсетевой прототип на Git + Codex и минимальный runtime цикла с чистым модельным шагом?
- Может ли первый этап принять промежуточную форму: трассировщик цикла с модельной заглушкой, пока реальный LLM-провайдер выбирается отдельно?

## Практическая рамка

После оценки выбора архитектурного подхода планирование должно различать три уровня результата:

- гиперсетевой прототип на текущей инфраструктуре, который доказывает связность памяти, происхождение, Git-наследование и пошаговый отбор;
- спецификацию и фикстуру агентского цикла, которые доказывают формат трассы, остановку, ошибки и проверяемость без обязательного реального LLM-провайдера;
- runtime агентского цикла с чистым модельным шагом, который только после отдельной проверки может использовать локальную LLM или `Codex CLI` как провайдера.

## Частичное прояснение

[Оценка выбора архитектурного подхода к реализации FUM](../Оценки/оценка-выбора-архитектурного-подхода-к-реализации-FUM.md) уточняет порядок реализации. Первым шагом выбирается репозиторный гиперсетевой контур на текущей Git/Codex/локальной памяти, потому что он уже подтверждён кодом локальных автоматизаций, проверками, правилами сессии и Git-наследованием. Минимальный трассировщик агентского цикла становится следующим проверяемым артефактом, а единое локальное приложение - более поздним интегратором коробочной стадии.

Текущая граница теперь сформулирована точнее: преобладающий смысловой слой нынешней [памяти FUM](../Глоссарий/память-FUM.md) состоит из дословного текста человека и производного текста LLM, порождаемого во внешней агентской сессии Codex. Тем самым документационный прототип доказывает совместно формируемую текстовую память и её внешнюю организацию, а не собственный runtime цикла FUM.

[Теневой редактор продолжений](../Прототипы/теневой-редактор-продолжений/README.md) добавляет второе частичное свидетельство: локальная LLM уже проверена как чистый ограниченный subprocess-шаг, который получает только текстовый контекст через стандартный ввод, не имеет инструментов и возвращает продолжение в наблюдаемый пользовательский контур. Это снимает вопрос о принципиальной доступности локального модельного шага для узкой текстовой фикстуры, но сам редактор не реализует полный цикл наблюдения, выбора действия, подтверждения, проверки и обновления памяти.

[Контракт чистого модельного шага](../Документация/41-контракт-чистого-модельного-шага.md) версии `1` и [детерминированный Swift-прототип](../Прототипы/чистый-модельный-шаг/README.md) проясняют общий интерфейс: весь контекст передаётся явно, провайдер не получает эффектных возможностей, результат остаётся инертным текстом, а идентичность, лимиты, хэш входа и ошибки наблюдаемы. Это доказывает границу на заглушке, но не качество реальной LLM и не наличие у `Codex CLI` режима без собственного агентского цикла.

Вопрос не закрывается полностью. Остаётся проверить реальный LLM-провайдер по общему контракту, определить место отдельного модельного вызова в трассе и runtime, подтвердить отмену и тайм-аут внешнего процесса и установить границу, после которой узкий локальный провайдер становится достаточным для вложения циклов.
