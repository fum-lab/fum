# Удержание замков при SIGINT до GO

По сообщению Управляющего остановленный контекст и обе действительные блокировки действительно удерживались при неизвестном исходе; старый тест оставлял их обычной финализации Python. Сценарий перенесён в отдельный процесс по существующей схеме: проверяется сохранение первичной ошибки и контекста после GC. Внешний процесс подтвердил оба inode, занятость двух замков до выхода, доступность обоих после выхода и неизменность active. Три адресных теста завершились exit 0 за 9,792 с, ошибки финализации нет.

Первый прогон новой проверки слишком строго требовал пустой stderr у старого диагностического сценария; исправлено только ожидание. Рабочая обёртка и её допуск не изменены, правка стенда и Журнал не закоммичены. Это переданные сведения, не самостоятельная проверка Летописца.
