# Запуск кастомного интерфейса

## Диалог

### 1. Пользователь

Нужно запусть полностью кастомный интерфейс на Mac Studio с возможностью использования всех вычислительных возможностей железа. Запускать обязательно на macOS или есть варианты?

### 2. Ассистент

Разберу нативную macOS, замену оболочки, Linux в виртуализации и на самом железе, отдельно сравнив доступ к GPU, Neural Engine и медиадвижкам.

### 3. Ассистент

Ключевой вывод: кастомный UI не требует смены ОС; для полного доступа к ускорителям разумнее оставить macOS скрытым системным слоем, тогда как возможности Linux зависят от поколения чипа.

### 4. Ассистент

## Итог

**Технически macOS не обязательна. Но если требование — использовать максимально полный набор возможностей Mac Studio, то на практике macOS должна остаться основной системой или хотя бы хост-системой.**

При этом интерфейс совершенно не обязан выглядеть как macOS. Можно скрыть Dock, строку меню, рабочий стол и Finder, автоматически входить в специальную учётную запись и сразу запускать полноэкранное приложение. Пользователь будет видеть только ваш интерфейс.

## Почему macOS предпочтительнее

Именно macOS предоставляет штатный доступ ко всем специализированным блокам Apple Silicon:

- **CPU** — обычная многопоточность и оптимизированные библиотеки Accelerate;
- **GPU** — Metal и Metal Performance Shaders;
- **Neural Engine** — Core ML;
- **Media Engine** — аппаратное кодирование и декодирование через VideoToolbox;
- общая память CPU/GPU — через модель памяти Metal.

Apple прямо позиционирует Metal как низкоуровневый графический и вычислительный API для полного использования Apple silicon; Core ML может распределять совместимые модели между CPU, GPU и Neural Engine, а VideoToolbox даёт доступ к аппаратным видеокодерам и декодерам.

Здесь есть важная оговорка: **Neural Engine и Media Engine — не универсальные сопроцессоры**. На Neural Engine нельзя отправить произвольный вычислительный kernel, как на GPU; нужны совместимые Core ML-графы. Media Engine предназначен для поддерживаемых видеокодеков. Поэтому «использовать всё железо» означает правильно разделить нагрузку между специализированными API, а не вызвать один универсальный интерфейс.

## Полностью кастомный интерфейс поверх macOS

Для промышленной системы, терминала, визуальной инсталляции или управляющей панели обычно делают такую схему:

1. Полноэкранное borderless-приложение на Swift/AppKit, C++/Qt, SDL или другом UI-стеке.
2. Отрисовка через `CAMetalLayer`/Metal.
3. Скрытие Dock и строки меню через presentation options.
4. Автоматический вход в системную учётную запись.
5. Автозапуск приложения через login item или `launchd`.
6. Отдельный фоновый сервис для вычислений, мониторинга и автоматического перезапуска интерфейса.
7. Для жёсткого kiosk-режима — управление Mac через MDM и Autonomous Single App Mode.

macOS позволяет приложению скрывать системные панели, а для управляемых компьютеров Apple предоставляет Autonomous Single App Mode, при котором приложение может фактически контролировать рабочую сессию Mac.

Ограничение: обычное приложение начинает работать после запуска пользовательской сессии. Экран начальной загрузки, Recovery, boot picker и низкоуровневая цепочка загрузки остаются под контролем платформы Apple.

## Другие варианты

| Вариант | Возможности | Основное ограничение |
|---|---|---|
| **Нативное приложение на macOS** | CPU, GPU, Neural Engine, Media Engine, все штатные драйверы | macOS остаётся под интерфейсом |
| **Fedora Asahi Linux напрямую** | Свой Wayland-композитор, свой shell, нативный ARM64 CPU, GPU на поддерживаемых моделях | Не все аппаратные блоки поддерживаются |
| **Linux или Windows в VM** | Хорошая CPU-производительность, изоляция, привычное окружение | Нет эквивалентного прямого доступа ко всем ускорителям |
| **Полностью собственная ОС** | Абсолютный контроль над интерфейсом и системой | Необходимо самостоятельно реализовывать драйверы Apple Silicon |
| **Windows напрямую** | Практически не вариант | Boot Camp поддерживает Intel Mac, но не Apple Silicon |

### Linux напрямую через Asahi

На Mac Studio с **M1 Max/M1 Ultra и M2 Max/M2 Ultra** Fedora Asahi Remix является реальным bare-metal-вариантом. Linux запускается непосредственно на машине, а не внутри macOS. Для M1/M2 доступны нативный ARM64 CPU и аппаратно ускоренный GPU.

Но полного использования железа там пока нет:

- аппаратный видеодекодер всё ещё находится в разработке;
- видеокодер обозначен как TBA;
- ProRes-блок — TBA;
- драйвер Neural Engine пока находится вне основного дерева;
- Thunderbolt и DisplayPort Alt Mode остаются частично реализованными.

Именно поэтому Asahi подходит для собственного Linux-интерфейса, CPU/GPU-вычислений и стандартной графики, но не для требования «использовать абсолютно все ускорители Mac Studio».

### Mac Studio 2025: M4 Max или M3 Ultra

По состоянию на **14 июля 2026 года** для этих моделей производственный Linux-вариант пока не готов. В отчёте Asahi от 30 июня 2026 года сказано, что на M3 уже работают многие базовые компоненты, включая частотное управление CPU, NVMe, PCIe, Wi‑Fi и Bluetooth, но поддержка установки через Asahi Installer ещё не включена. Для M4 пока ведётся подготовительная работа; официальная таблица поддержки указывает отсутствие установщика и отсутствие готового GPU-драйвера.

Следовательно:

- **Mac Studio M4 Max / M3 Ultra — выбирать macOS**;
- **Mac Studio M1/M2 — Linux возможен, но только с осознанным отказом от части ускорителей**.

### Виртуальная машина

Linux можно запустить через Apple Virtualization Framework, Parallels, VMware или UTM. CPU-код ARM64 будет работать достаточно эффективно, но гостевая система получает виртуальные устройства, включая Virtio-графику. Это не равно прямому доступу ко всему Apple GPU, Neural Engine и Media Engine. Поэтому VM подходит для серверной логики, контейнеров, баз данных и переносимых компонентов, но не как основной слой для максимальной аппаратной производительности.

Windows напрямую на Apple Silicon штатно не устанавливается: Boot Camp предназначен для Intel-based Mac.

## Оптимальная архитектура

Для вашего требования я бы использовал:

```text
Mac Studio
└── macOS как скрытый hardware/driver layer
    ├── Полноэкранный кастомный интерфейс
    │   └── AppKit / SwiftUI / Qt / SDL + Metal
    ├── Native Compute Service
    │   ├── CPU: Accelerate / C++ / Rust
    │   ├── GPU: Metal / MPS
    │   ├── ML: Core ML / MLX
    │   └── Video: VideoToolbox
    ├── Watchdog / launchd
    └── Опциональная Linux VM
        └── Серверные и переносимые компоненты
```

Таким образом macOS остаётся техническим фундаментом, но **в пользовательском опыте её можно практически полностью исключить**. Это наиболее надёжный способ одновременно получить собственный интерфейс, kiosk-поведение и доступ к CPU, GPU, Neural Engine и видеоускорителям.
