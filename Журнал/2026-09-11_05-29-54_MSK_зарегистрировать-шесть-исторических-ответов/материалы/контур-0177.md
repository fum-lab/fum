## Среда и воспроизведение

Наблюдены Python 3.14.7 и Git 2.54.0 (Apple Git-157). Интерпретатор закреплён абсолютным физическим путём в приватной квитанции, Git разрешается через ограниченный PATH /usr/bin:/bin. Python запускается с -E -S -B: без влияния переменных Python, site-кода и записи байткода; соседние импорты выполняются из закреплённого комплекта. Простое -I исключило бы необходимые соседние импорты.

Для повторения нужны эти восемь blobs того же коммита, сохранённая структура каталогов, полный локальный Git DAG целевого checkout, исходный приватный root JSONL и сохранённые свидетельства. Вызов обработать-сообщения-задачи.py получает отдельные --корень-репозитория, --исходник и --codex-thread-id исходной задачи. Первое чтение: остаток --без-записи --перепроверить. Для каждой записи: сохранить --решение с ровно восемью полями и --ожидаемая-история из актуального остатка; кэш расположен вне Git. После записи остаток читается заново.

Путь истории определяется UUID исходной задачи: Планирование/задачи/01a07d3d-d376-7ad2-aafc-67e4c25a67eb/обработка-сообщений.jsonl. Технический замок относится только к физическому Git-каталогу нашего worktree. Сравнение SHA истории является проверкой поколения адресной записи, а не возобновлением исторического автоконвейера.
