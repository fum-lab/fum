# Отчёт 2026-07-20 22:05:19 MSK - Сделать повторное архивирование источника атомарным

Повторное архивирование одного ChatGPT share URL больше не смешивает файлы прежнего и нового снимков. Автоматизация `fum-request-materials` строит новый результат отдельно, проверяет его точный манифест и только затем целиком устанавливает канонический каталог.

## Решения

- Каждый снимок собирается в скрытом соседнем staging-каталоге на той же файловой системе.
- `snapshot-manifest.json` схемы `fum.request-materials.snapshot-manifest.v1` перечисляет все управляемые файлы, включая себя; установка разрешена только при точном совпадении перечня с фактическим содержимым.
- Первый снимок устанавливается атомарным переименованием, а повторный использует `RENAME_SWAP` на macOS или `RENAME_EXCHANGE` на Linux.
- Если атомарный обмен каталогов недоступен, повтор закрывается до изменения канонического снимка. Резервная двухшаговая схема с временно отсутствующим каноническим путём намеренно не используется.
- Ошибка до установки оставляет прежний снимок побайтно неизменным. После успешного обмена новый снимок уже считается зафиксированным; очистка прежнего staging выполняется best-effort, а ошибка связывания файла запроса выводится отдельным предупреждением.

## TDD

Исходные 15 тестов прошли до изменения реализации. Красная фаза добавила сквозные последовательности `полный снимок -> неполный снимок` и `полный снимок -> поздний сбой генерации`: прежний код не создавал манифест и успевал частично перезаписать канонический каталог.

После первой зелёной реализации независимое ревью обнаружило неатомарный резервный путь через два переименования. Новый красный тест потребовал fail-closed при недоступном атомарном обмене, а поздний генератор стал проверять старые байты прямо во время staging. Ещё один красный тест отделил post-commit ошибку ссылки от уже успешно установленного снимка. Финальные красные проверки закрепили атомарную запись самого файла запроса, предупреждение об оставшемся старом staging и независимость основного набора от поддержки exchange конкретной файловой системой. Итоговый автономный набор содержит 21 проходящий тест.

## Проверки

- `fum-request-materials`: 21 автономный тест проходит без сети и секретов.
- Полный и затем неполный снимки оставляют ровно файлы нового `snapshot-manifest.json`; старые initial-state, script, decoded-data, messages и оформленный Markdown отсутствуют в каталоге, индексе и отчёте.
- Поздний сбой staging сохраняет прежний канонический каталог побайтно, а недоступный directory exchange закрывается без backup-каталога и без записи.
- Атомарная запись ссылки не усекла файл запроса при инъекции сбоя `os.replace`; оставшийся после commit старый staging выводится как явное предупреждение.
- Полный smoke-check прошёл все 26 этапов без сети и секретов, включая recency, граф Obsidian, связность сессии и проверки публикационной чистоты.

## Продолжение
