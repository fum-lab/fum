# Отчёт 2026-08-01 19:37:43 MSK - Замкнуть возобновление и живую приёмку одноагентного эпизода

Рабочая сессия замыкает один узкий сквозной одноагентный сценарий в собственном runtime FUM. Сценарий объединяет два model-only-варианта от общего предка, конечный бюджет, отдельное внешнее подтверждение, разрешённое локальное Git-действие, изолированный кандидат, независимую приёмку, два неграциозных межпроцессных возобновления и единственный терминальный исход.

Результат относится только к закреплённому синтетическому сценарию. Он не доказывает готовность универсального или распределённого FUM, продуктового runtime, устойчивость к потере питания либо преимущество над контрольным агентом.

## Результат

Версионный execution-passport точно закрепляет цель, синтетический контекст, identity provider, раскрытие данных, совокупные и резервируемые бюджеты, allowlist действий, проверки, checkpoint и допустимые терминальные исходы. При новом запуске runtime создаёт два model-only-предложения от одного подтверждённого предка, строго разбирает и проверяет намерения, выбирает вариант только по закреплённым данным и сохраняет недоступность третьего предложения без нового вызова. Внутренний выбор сам по себе не повышает статус допуска: Git-переход остаётся закрытым до отдельного видимого подтверждения, связанного с точным первым checkpoint и паспортом.

Headless worker исполняет собственный цикл runtime и подтверждает состояния через `CURRENT`. Harness перед каждым убийством канонически сверяет marker с текущими generation/state SHA и смысловым событием, после чего дважды посылает фактический `SIGKILL`. Продолжение выполняют процессы с новыми PID, которые получают только каталог эпизода, роль и видимый файл подтверждения; прежние чат, stdin и скрытые переменные процесса не используются.

Разрешённое действие создаёт детерминированный commit только в изолированном clone и отдельной кандидатной ветке. Отдельный процесс приёмки заново проверяет точные parent, tree, diff, checker и candidate object и сохраняет `accepted`; merge, rebase, push и автоматическая интеграция отсутствуют. Сохранённая трасса завершается ровно одним `completed`, а автономные тесты воспроизводят остальные допустимые терминальные исходы.

Recorded harness дважды прошёл без сети и живой модели. Оба запуска дали одну закреплённую каноническую семантическую проекцию, подтвердили конечный budget no-call и no-call replay без model-, tool-, Git- и workspace-эффектов. Один opt-in живой прогон тем же runtime использовал уже установленный локальный `qwen/qwen3-0.6b` через LM Studio без скачивания весов, новых секретов, платного доступа или пользовательских данных; после прогона server и список загруженных моделей возвращены в исходное выключенное и пустое состояние.

Требование FUM-REQ-0029 переведено в `✅`: оно буквально требовало как минимум один такой проверенный эпизод. Смежное FUM-REQ-0035 остаётся `🟡`, потому что harness создаёт внешнее машинное свидетельство, но не доказывает живой пользовательский канал подтверждения.

## Решения и ограничения

Runtime сохраняет только подтверждённые поколения и связывает исполнение с полным паспортом, а не с набором отдельных совпавших полей. External confirmation является видимым каноническим артефактом, который создаёт harness после проверки первого checkpoint; worker не может синтезировать его из собственного модельного вывода. Перед каждым `SIGKILL` harness заново сопоставляет marker с фактическим `CURRENT`, а новый процесс продолжает только из подтверждённого поколения.

Каноническая recorded-проекция исключает переменные PID и временные абсолютные пути, но сохраняет семантические события, exact identity, бюджеты, выбор, candidate object, приёмку и терминальный исход. Сырой аудит остаётся отдельным и хэшируется. Replay не создаёт адаптеры действий и проверяет неизменность снимка дерева эффектов.

Живой прогон был разрешён только для уже доступного локального provider и синтетических данных. Это полномочие не переносится на другую модель, сеть, скачивание весов, новые секреты, платные вызовы или пользовательские данные. Кандидат остаётся локальным и изолированным; публикация либо интеграция не входит в карточку.
