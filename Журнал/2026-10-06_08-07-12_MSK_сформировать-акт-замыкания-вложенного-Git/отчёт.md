## Решения и ограничения

<!-- FUM-КАРТОЧКА:НАЧАЛО решения -->
Ровно четыре прежних предметных продукта. Общие зависимости, SKILL, правила, guard, builder, modeltransfer, STEP0235 и Issue213 не менять. Исходная постановка, первоначальное поручение, модель gpt-6.1-sol/ultra, прежний исполнитель и назначенный ref сохраняются буквально. Новый этап обычной .7 разрешается только после нового независимого A; .19 не применяется. Новый собственный Журнал: Журнал/2026-10-06_08-07-12_MSK_устранить-дрейф-после-вложенного-Git/. Фактические соседние request по чистому штатному подготовить_начало: Журнал/2026-10-06_06-42-25_MSK_устранить-поздний-дрейф-контрольной-точки/запрос.md. Только их штатная навигация может изменяться при неизменном человеческом теле. Остальные закрытые J C976/a56, старые исходы и профили — только чтение. Интеграция, приёмка и закрытие STEP принадлежат ROOT, не исполнителю. Не реконструировать допуск, не перечитывать полный native JSONL, не создавать новое Issue и не запускать новый большой фасад. Отрицательный или неизвестный producer блокирует потребителя; отказ дополнительной сверки не повторяет push. Будущие RED/GREEN, новый профиль, ready/create и доставка пока неизвестны. Устранить поздний ROOT HEAD/ref-дрейф после последнего зависимого вложенного Git-чтения исходного STEP0245, без нового функционального объёма. В точном a56effc99a960bd64f1a490a2aa810301c85f0c5 scripts/сверить-контрольную-точку.py сначала сверяет ROOT состояние на строке 335, затем вызывает наблюдения на строке 340; для допустимого gitlink эти наблюдения выполняют вложенный rev-parse HEAD на строке 242, после чего закрытие FS на строке 343 и return на строке 348 проходят без заключительной ROOT-сверки. Последовательность должна замыкать последнее зависимое Git-чтение, затем проверять FS с удержанными дескрипторами, затем терминальные ROOT HEAD/ref, затем ещё раз FS без нового зависимого Git-чтения, освобождать дескрипторы в finally и только после всех проверок выдавать успешный return/stdout. Та же дисциплина и освобождение ресурсов сохраняются на путях отказа. Удержание FD означает логическую сверку FS, а не физическое освобождение до терминального Git. Сохранить прежние FS-категории, Git-mode/локальные права, раздельные author/committer и producer gate; кооперативная RO-граница не обещает атомарность против враждебного процесса или remote. Предварительно смысл нового ACT принимается ROOT в отдельном содержательном коммите; actual генерация A не выполняется этим черновиком.
