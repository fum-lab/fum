# [Журнал работ](../Глоссарий/журнал-работ.md)

[Журнал работ](../Глоссарий/журнал-работ.md) хранит хронологическую последовательность [папок запросов](../Глоссарий/папка-запроса.md). Каждая запись объединяет дословный [исходный запрос](../Глоссарий/исходный-запрос.md), человекочитаемый отчёт и принадлежащие только этому запросу материалы общей временной идентичностью. Так развитие [памяти FUM](../Глоссарий/память-FUM.md) читается как связная история без синхронизации нескольких параллельных каталогов по совпадающим именам.

Внутри папки `запрос.md` хранит первичный пользовательский текст, `отчёт.md` фиксирует смысл работы на обзорном уровне, а необязательный каталог `материалы/` содержит собственные артефакты запроса. Эти файлы не заменяют [производную документацию](../Глоссарий/производная-документация.md), проверки или Git-коммит. Ранние исторические запросы, появившиеся до введения отчётов, остаются без вымышленного `отчёт.md`.

Новые отчёты, начиная с рабочей сессии 2026-07-23 14:47:43 MSK, содержат раздел `## Профиль времени выполнения`. В нём не менее двух стадий показываются таблицей `Стадия | Длительность | Границы и способ измерения`, а отдельная строка `Граница профиля:` объясняет охваченный интервал. Значения относятся к прошедшему wall-clock-времени, не подменяются CPU-временем и не складываются без поправки на параллельность. Ожидание FIFO отделяется от активной работы; не измеренное задним числом время честно остаётся неизвестным.

Начиная с рабочей сессии 2026-07-27 16:12:29 MSK, профиль дополнительно содержит подраздел `### Прямые запуски проверок`. Таблица `Вызов | Длительность | Результат` сохраняет каждый прямой проверочный вызов отдельной строкой, включая неуспешные, прерванные и повторные, а строка `Общее время прямых запусков проверок: <N> с` показывает их проверяемую арифметическую сумму. Это совокупное время процессов: при параллельном выполнении оно может быть больше календарной длительности сессии, а вложенные шаги составного runner не прибавляются повторно к внешнему запуску.

Начиная с [рабочей сессии 2026-08-04 20:45:26 MSK](2026-08-04_20-45-26_MSK_формировать-отчёты-о-запусках-тестов/запрос.md), источником этого подраздела служит машинный журнал [автоматизации отчётов о запусках проверок](../Инструменты/fum-otchyotyi-o-zapuskakh-proverok/SKILL.md). Каждый прямой верхнеуровневый вызов получает отдельную атомарно устанавливаемую JSON-запись, а Markdown-блок между marker-строками строится из упорядоченных записей детерминированно и вручную не редактируется. Готовый отчёт закрывается снимком `снимок.json`, который фиксирует порядок, имена и точные SHA-256 хэши байтов записей и сам связан хэшем из начального marker. В ходе работы открытый предпросмотр может существовать между запусками, но строгая проверка принимает его только при активно выполняющейся записи; коммитить такое рабочее состояние нельзя.

## Правила именования

Каждая папка запроса размещается непосредственно в `Журнал/`; в корне журнала единственным Markdown-файлом остаётся этот `README.md`. Имя папки точно повторяет прежние правила имени файла запроса без расширения `.md` и обязательно начинается с префикса московского времени `YYYY-MM-DD_HH-MM-SS_MSK`. Новая папка имеет вид `YYYY-MM-DD_HH-MM-SS_MSK_<краткое-название-запроса>/`, а ранняя историческая папка может состоять только из временного префикса. Вложенные файлы всегда называются `запрос.md` и, когда отчёт существует, `отчёт.md`.
