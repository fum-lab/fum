# Отчёт 2026-09-15 20:57:04 MSK - Подготовить Android runtime FUMA

Подготовлен и реально исполнен общий Swift runtime на Android ARM64/API 36, целевой ABI/API бинарника — aarch64/API 23. Это контрольная точка предметного результата; финальная приёмка и интеграция не выполнены.

## Результат

- Общий пакет СценарийRuntime переиспользует AutomationExecutor и Сегмент. Три корректных входа (0, 8 и 1792 байта) дали точные UTF-32LE и повтор после закрытия/повторного открытия контейнера. Четыре неверных UTF-8 отклонены без создания контейнера.
- Swift Crypto 4.5.2 и Swift ASN1 1.6.0 подключены штатной проверкой как подмодули проверенных публичных fork `fum-lab`, upstream `apple`. SHA256 не реализован заново, внешние LICENSE/NOTICE сохранены без изменения.
- На Android промежуточные каталоги открываются через O_PATH, конечный через O_RDONLY с прежними проверками владельца/прав/ссылок, блокировкой и fsync. macOS системные флаги сохранены.
- Подготовлены автоматизация установки закреплённых архивов и автоматизация сборки/семи запусков. Проверены RED/GREEN и профиль. Холодная установка целиком из нового клона ещё не принята; проверен повтор установки по реальному кэшу.

## Проверки

Сырые логи остались вне Git. [Открытые байты, профили и манифест](материалы/Android-прогон) сохранены без путей машины и serial устройства. Манифест включает наблюдённый бинарный SHA256, версии, ABI/API и коды всех семи процессов.

Наблюдённые отказы не скрыты: первоначальный RED отсутствующего метода; новый backend Xcode не подписал XCTest с кириллическим именем; временный путь Foundation не заменял realpath; Android не имел Darwin; native SwiftPM не передал C sysroot; Android обход /data через O_RDONLY получил EACCES. GREEN получен с проверенным native host backend, физическим корнем и Android SwiftBuild/O_PATH. Старый native кэш не перестроил граф после добавления Crypto; свежий граф прошёл.

Первый расширенный тест контейнера использовал внешний scratch, тогда как существующий процессный тест требует .build/debug; повтор выполнен с документированным размещением: 22 теста в трёх наборах прошли. Проверка зависимостей без SWIFTCI_USE_LOCAL_DEPS показала сетевое разрешение upstream ASN1: этот режим не используется для принимаемой сборки, обязательная переменная включена в автоматизацию и документацию. Побочные полученные checkout остались вне Git; они не стали подключённой зависимостью.

До первой машинной записи обёртка отклонила неоформленный вложенный клон. Клон сохранён вне checkout, затем зависимости подключены штатным add; отказ до запуска не представлен фиктивной записью проверки.

## Решения и ограничения

Профиль входа 1792 байта: исполнение 0,076 мс, трасса 1,664 мс, полный вызов adb 43,024 мс. Алгоритмическая оптимизация не оправдана этим профилем; реализация сохранена. fsync не удаляется ради ускорения. JNI отсутствует; измерен процессный мост adb. Профиль установщика сохраняет проверку полных архивов; ослаблять SHA-проверку ради скорости не решено.

Усиление Telegram из a9951ddcb0edc167a4928d69c99d49c5fb30bafb (Приватность.swift, приватныйДоступ:true, ACL) отсутствовало в исходной базе. O_PATH не доказывает эквивалент ACL. При семантическом объединении частный режим Android должен закрываться отказом до доказанного адаптера; macOS-усиление и новые API нельзя заменять целым файлом. iOS sandbox и UID обычного Android-приложения ещё не проверены.

По указанию координатора полная проекция не запускалась. Существующий манифест поколения имеет SHA256 `7bb832cb4bf99cbfe598867ed05051a6c7bc923e07a16b5e582ad7509a3bab47`; он сохранён из исходного коммита и отстаёт от этого среза. Это не финальная проверка нового содержимого.

Остаток: независимая проверка из чистого клона, холодный установщик, полная проекция/финальный smoke в согласованное окно, семантическая интеграция приватности Telegram и платформенных оболочек. Дальнейший Vulkan-кадр идёт после этого runtime, отдельным этапом. Полное зеркало Swift/LLVM этим срезом не выполняется.
