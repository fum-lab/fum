# Сохранить контролируемый вход

Добавлена отдельная опытная CLI-команда `запустить-controlled` с явными путями рабочего дерева, Git, private конфигурации, замка и квитанций, закреплёнными исполнителями observer и заданной командой. Она создаёт no-clobber active под lock, вызывает controlled cycle и возвращает UNKNOWN с кодом 3 и наблюдённым кодом цели. Active остаётся на диске; неопределённая ошибка после начала его создания удерживает процесс в HOLD. Публичная обычная команда запуска остаётся закрыта.

Namespace замка закреплён как `gitdir/fum-controlled-lock`, при этом до active проверяются .git, backlink и commondir. Гарантия единичности предполагает неподменённую linked topology и кооперацию участников; legacy писатели active не проверяют, защита от ABA и глобальная custody не доказаны.

Synthetic CLI lifecycle на live W выполнил `test -f .git` с кодом цели 0, семь Git-пакетов и observer raw 0, итог UNKNOWN; terminal SHA-256 `f766eb83d4068472bc590e8972261bde8138b8b4a155bde2a3fcc86e76b4fe85`. Отдельный межпроцессный тест показал отказ второго controlled CLI по существующему active без Popen, пока первый находился в mocked cycle (`125a6956f283d3e7d18ffa81016d234a5212b691a8d508b963decf13ce343c12`). Это не два полных конкурентных цикла. Два адресных теста точного кандидата прошли; полный regression, exec image и production admission не подтверждены.

Это source-only bootstrap по прямому поручению корня, не обычная приёмка. ACT/S, Creator и ROOT JSONL не проверялись. Модель собственных метаданных: gpt-6.1-terra, effort low; полная история моделей неизвестна. Посторонний WIP не включён.
