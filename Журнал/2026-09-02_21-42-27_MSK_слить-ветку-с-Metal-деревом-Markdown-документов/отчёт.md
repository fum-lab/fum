# Отчёт 2026-09-02 21:42:27 MSK - Слить ветку с Metal деревом Markdown документов

## Проверки

- Точная ветка-кандидат содержит один уникальный коммит поверх общей базы `249d076b1857f4e1727e5448587d13f16b15a30a`; при подготовке слияния `MERGE_HEAD` был равен `f821f3b55e0c3eab2cf1ea05d01cf02ffd571e1f`, неразрешённых путей после семантического разрешения нет.
- Четыре конфликта находились только в старой журнальной навигации, общем индексе свежести и снимке объявлений. Для них сохранена актуальная сторона `master`, затем текущие генераторы построили объединённый результат.
- Адресный `swift test` собрал пакет и выполнил `17` тестов без отказов: `5` тестов безопасного разрешителя пути, `9` тестов сканера и `3` теста раскладки.
- Плановый реестр схемы `9` пересобран после изменения FUM-REQ-0002. Полный инвентарь объявлений после объединения содержит `43 091` запись: `460` Mermaid, `16 038` Python и `26 593` Swift; снимок обновлён только после просмотра области нового кода.
- Первый полный smoke-check прошёл SwiftPM-манифесты, структуру, плановый реестр, применение и независимую проверку проекции, но остановился на проверке машинно-локальных путей: отрицательная тестовая фикстура содержала буквальный абсолютный путь из временного каталога. Фикстура переведена на путь из `FileManager.default.temporaryDirectory`; во втором полном профиле та же проверка обнаружила дословный запрещённый пример уже в этом отчёте. Буквальный пример удалён, после чего адресная проверка машинно-локальных путей прошла успешно. Полные профили фиксируются в машинной таблице выше; целостность закрытого снимка и одноразовые завершающие проверки фиксируются отдельно после закрытия.

## Решения и ограничения

- Ветка интегрируется настоящим merge-коммитом с двумя родителями: кандидатная история и её 34 машинные квитанции остаются проверяемым происхождением, а не подменяются squash-коммитом.
- Исторический отчёт кандидата сохраняет прежний отказ проверки локального Obsidian-графа; доказательством совместимости с текущим `master` считаются только новые проверки этой сессии, где `.obsidian/graph.json` является игнорируемым пользовательским состоянием.
- Прототип строит файловую иерархию, а не семантический граф FUM. Он не выводит смысловые рёбра из Markdown и не замыкает действия пользователя в событийный контур.
- Повторная проверка пути защищает статичное дерево и замену файла после сканирования, но `NSWorkspace.open(URL)` не даёт атомарной защиты от злонамеренной одновременной подмены пути; сильная граница потребовала бы обхода относительно файлового дескриптора и другого контракта открытия.
- Прототип ограничивает один проход 200 000 путей, 20 000 документов, глубиной 128 компонентов, 2 МиБ на документ и 64 МиБ текста. Пиксельное обратное чтение, измерение FPS и полноэкранная поставка остаются за его границей.
- Результат остаётся локальным: push, удаление кандидатной ветки и другие внешние действия в запрос не входят.
