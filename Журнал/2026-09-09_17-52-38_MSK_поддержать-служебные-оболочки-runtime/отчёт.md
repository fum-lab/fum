## Основание и точный контракт

Координатор сообщил об отказе прежнего Swift `8ff9ede` на его закреплённом приватном префиксе: 117 069 638 байтов, 17 968 LF, максимум строки 3 326 896 байтов, SHA `486031a8304d82cd2cf7a1e24696d7b39bc22985cce3322aedace90fafb78a46`. Импорт вернул код 2 и пустой stdout; его первая попытка записана в корневой v4. Это внешнее свидетельство из поручения, а не наш повторный запуск на приватном источнике. Переданы только структурные свойства оболочки; значения payload не запрашивались и не переносились.

Все восемь известных типов требуют объект payload. Metadata, если присутствует, требует объект. Ordinal проверяется по исходной лексеме до NSNumber: десятичное целое 0…Int64.max без знака, дроби, экспоненты и ведущего нуля, кроме самого 0. Bool, null, строка, -0 и переполнение отвергаются. Значения ordinal могут повторяться и убывать: они не задают порядок LF или полномочий. Timestamp при наличии остаётся непустой строкой до 128 байтов без управляющих символов. Timestamp/ordinal/metadata необязательны для сохранения прежних допустимых форм. Неизвестные верхние ключи и типы по-прежнему закрывают импорт.

Вложенные metadata и payload проходят прежние бюджеты и проверку декодированных повторных ключей. Из трёх новых типов не извлекается даже встретившийся turn_id. Последний ход означает последний ход, явно идентифицированный поддержанными turn_context/event_msg; это ограниченная проекция. Схема архива и версия адаптера остаются равны 1, прежняя семантика и минимумы геометрии 34/80 байтов сохраняются. Будущее извлечение фактов из ранее нейтральных типов потребует отдельного решения о версии и полном разборе.

## Проверки

Новые синтетические тесты проходят все восемь типов с новыми полями, отвергают неизвестные формы, неверные виды объектов, дубли декодированных ключей, неподходящие лексемы ordinal, превышения глубины и узлов внутри metadata. В служебные записи помещены заведомо синтетические поля чужого хода, модели, каталога, завершения, роли и разрешения: они не меняют выбранные факты и не попадают в архив.

Тест прежней формы сначала создаёт архив без новых полей, проверяет точный повтор без изменения контейнерных байтов, дополняет его тремя служебными строками, проверяет каноническое побайтовое равенство полного и инкрементального результата и неизменность прежнего контейнерного префикса. Источник удаляется до нового init; replay возвращает те же канонические байты результата. Это прямое сравнение Data в XCTest, отдельное от Equatable в профиле.

Read-only-ревью текущего кода и синтетики не выявило предметных замечаний; рецензент самостоятельно ничего не запускал и не менял. Все 35 XCTest прошли. Два реальных RED остаются отдельными записями v3, не заменяются успешными. Отчёты, материалы и v3 обоих прежних этапов сохранены побайтно; меняется только штатная навигация предыдущего запроса.

Воспроизведение из нового Swift-коммита:

```sh
swift test --package-path Packages/АрхивныйСнимокЗадачи --build-system native --jobs 2
swift run -c release --package-path Packages/АрхивныйСнимокЗадачи --build-system native --jobs 2 профиль-архивного-снимка .build/новый-профиль-оболочек 1000000 --служебные-оболочки
```

Каталог профиля должен отсутствовать. Native — прежний ограниченный штатный путь Apple Swift 6.4, отмеченный toolchain как deprecated. Trust и подпись не отключаются, прежний CodeSign-сбой FUM-СБОЙ-0038 и подготовка FUM-STEP-0163 этим этапом не закрываются.

## Решения и ограничения

Успешный импорт нового адаптера на реальном префиксе ещё не подтверждён; прочие причины отказа за пределами переданной структуры не исключены. FUM-STEP-0164 остаётся активным. Новый постоянный идентификатор не создаётся. Приватный JSONL, соседние диалоги, UI, Accessibility и ScreenCapture в этой задаче не читались. Поддержка указанных форм не означает поддержку всех будущих форм runtime или наблюдение живого состояния.

По поручению сохраняется ограниченная контрольная точка с открытой историей, без активных запусков и без снимка полной приёмки. Известные 282 прежние ссылки на отсутствующий игнорируемый `.obsidian/graph.json` остаются оговоркой; глобальный checker не повторяется. Финальное адресное замыкание проверяет собственные Markdown-ссылки, журнал, точный preview, recency, происхождение, охват запроса, индекс и сообщение коммита. Это не полный smoke и не полная связность. Для разрешённых checker/reportmodule повторно сверяются SHA, чужие SKILL не читаются, правила ради допуска не меняются.
