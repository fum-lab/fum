# Поручение ROOT: typed-аргументы `create_thread`

## Источник и граница

Это отдельное адресное поручение ROOT code-owner по штатной фабрике FUMA. Операционный владелец интеграций уже назначен; его задачу не дублировать. Основание source wave — merge-коммит `cfe38399072f43a7ba214b32804ae5a53e1705ca`, дерево `07caea4210731e74751fc1502e824d96bc63642f`. Рабочая ветка источника: `fum-lab/fum/instrumentyi/fabrika-agentov/pokryitiye/master`.

Разрешённые failure-свидетельства показывают два неверных уровня: `projectId` оказался вне `target`, а `startingState` — рядом с `environment`. Реальная схема помещает `projectId` внутрь `target`, а `startingState` — внутрь `target.environment` типа `worktree`. Содержимое приватных аргументов и результатов не копировать.

## Задача ребёнка

Добавить в штатную фабрику чистое типизированное представление и сериализацию запроса Codex `create_thread` для проекта в worktree, начинающегося от уже существующей проверенной ветки. Добавить regression-тесты сериализованной формы.

Разрешённая форма запроса:

```json
{
  "title": "<title>",
  "model": "gpt-6-luna",
  "thinking": "low",
  "prompt": "<assignment>",
  "target": {
    "type": "project",
    "projectId": "<fresh list_projects result>",
    "environment": {
      "type": "worktree",
      "startingState": {
        "type": "branch",
        "branchName": "<verified existing branch or ref>"
      }
    }
  }
}
```

`projectId`, `branchName`, title и prompt должны передаваться вызывающей стороной; реальные значения из этого чата или private evidence не фиксировать в Git. Regression проверяет вложенность обоих полей, отсутствие ошибочных верхнеуровневого `projectId` и соседнего `target.startingState`, а также отсутствие лишних ID-полей в request.

`clientThreadId` не является `threadId`. Если Native create возвращает только client ID, до thread-only операций вызывающая сторона отдельно разрешает его через `list_threads` и использует полученный UUID. Это задание не вызывает Native API и не добавляет runtime разрешения ID.

## Дополнение ROOT: FUM namespace для delivery ref

ROOT сообщил о дефекте прежнего конструктора/шаблона: при выбранном FUM namespace пилот получил `refs/heads/codex/ishjyusyi-20261101-01a195e6`. Исправить генерацию в том же `komanda.swift`, а не только добавить пояснение.

Проверяемый пример выбранного владельцем FUM ref: `refs/heads/fum-lab/fum/instrumentyi/format-dereva/ishjyusyi/master`. Конструктор должен сохранить такой явно переданный полный ref, проверить, что все компоненты непустые и ref не сталкивается с другим выбранным ref, и не подставлять `codex/` fallback при наличии FUM namespace. Regression в `proverki.swift` покрывает положительное принятие и отрицательные malformed/collision/fallback случаи.

Для Native `create_thread` `target.environment.startingState.branchName` всегда получает существующий проверенный родительский ref, переданный вызывающей стороной; здесь это база `fum-lab/fum/instrumentyi/fabrika-agentov/pokryitiye/master`. Этот source ref не является будущей delivery-веткой, которую собственный писатель выбирает после setup. Уже опубликованный `refs/heads/codex/ishjyusyi-20261101-01a195e6` и его история сохраняются; force и удаление запрещены.

## Уточнение ROOT: второй материальный regression

Уточнение ROOT из потока `01a17797-519b-73c1-bcc8-fd295cdfe9b0` сохранено дословно в [сообщении координатора](материалы/сообщения/уточнение-координатора-2026-11-01.txt). ROOT передал результат чтения родительского потока Художественного: два `create_thread` вызова с идентификаторами `exec-8a35f030-4f41-41ea-b26c-dc39b48eb0a4` и `exec-092ead64-5554-4e0c-b7ae-6dd9635e5a6a` вернулись как `invalidarguments/nochildIDs`; в обоих `projectId` находился на верхнем уровне, а `target` не содержал `target.projectId`. Это известный отказ схемы, а не неизвестный успешный исход.

В существующий генератор добавляется отдельная положительная и отрицательная фикстура, проверяющая его реальный сериализованный вывод: `target.projectId` из свежего результата `list_projects`, `target.environment.startingState.branchName` из существующей проверенной родительской ветки, путь задачи в `title`, `gpt-6-luna` и `low`, а также переданную вызывающей стороной непересекающуюся область `prompt`. Одной подсказки валидатору перенести поле недостаточно. Новый генератор или Native-вызов не создаётся. Уже созданный родителем независимый runtime-child не дублируется; его client ID не передаётся в thread-only инструменты.

## Исход и проверки

Добавить regression-код, но не запускать compiler/build/tests: для текущего этапа слот проверки закрыт. Исход запуска — `NOT_RUN`/`UNKNOWN`, не `GREEN`. Не выполнять `create_thread`, не использовать старый неуспешный client ID, не читать ROOT RAW, не запускать Python и не менять общую Git-конфигурацию.

Запрошенная модель — `gpt-6-luna`, усилие — `low`; фактические model/thinking фиксировать отдельно по доступному readback. Повышать усилие не более чем на один поддерживаемый шаг только после наблюдаемой трудности; дополнительных детей не создавать.

## Использованные инструменты

- `functions.exec` и вложенный `exec_command` — чтение Git-состояния и файлов; версия контракта среды не раскрывается.
- [`git`](../../Инструменты/реестр-системных-приложений-и-инструментов.md) — чтение OID, refs и blob-идентичностей; фактическая версия — Git 2.54.0 (Apple Git-157).
- `jq` 1.7.1-apple — однократный разбор `контракт.json` без изменения файла.
- `shasum` 6.04 — вычисление SHA-256 содержания Markdown без служебного блока recency.
- `date` среды macOS — фиксация настенного времени в `Europe/Moscow`; отдельная версия не раскрывается.
- `apply_patch` — точечные правки файлов через `functions.exec`; версия контракта не раскрывается.
- `mcp__codex_app.read_thread` — read-only статус/сводка текущей задачи; версия контракта не раскрывается. ROOT RAW JSONL не читался.
- Контракт `mcp__codex_app.create_thread` прочитан из каталога доступных инструментов; первый вызов отклонён до создания задачи из-за неверных уровней аргументов. Повторного вызова не было. По последнему прямому указанию ROOT новый Native-агент для последующего resource ACT не создаётся; исходное typed-поручение остаётся сохранённой наработкой и не дублируется.
- Контракт `mcp__codex_app.list_projects` прочитан из каталога доступных инструментов; свежий вызов не выполнялся, так как новый Native-агент в продолжении исключён ROOT.
