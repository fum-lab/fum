# Контрольная точка приоритета точечных исключений

## Основание и граница

Этап начат от `0e4022c131bcd779da5e1254205c0ee3442746e3`, родительский базис этой частичной ветки — `df60f239c178a6b3bd9274ce190385089579b706`. Первый коммит уже отправлен обычным точным push в `origin`; отдельный `git ls-remote` подтвердил тот же OID на этой ветке. Работа ограничена тремя правилами ядра N000001, N000003 и N000032, их записями инвентаря и этой парой Журнала. N000028 из предыдущей контрольной точки не меняется.

Передача ROOT разрешает точечное исключение из общей процедурной команды в его явной границе, но не даёт общей замены или дополнительных прав. В root-visible `df60` команда N000003 содержит singular literal `проверить-декомпозицию-правил.py`. RO-аудитор сообщал о plural literal в отдельном дочернем сообщении, которого нет в root-visible контексте; это расхождение происхождения не меняет исходный literal этой ветки. Исполняемый контур не запускался.

## Изменения

- N000001 теперь задаёт приоритет прямого человеческого исключения и точного N000032 только над противоречащими процедурными командами AGENTS в установленной границе; остальные ограничения сохраняются.
- N000003 допускает исключение конкретного legacy-инструмента или источника, сохраняет `UNKNOWN` и запрещает запасную автоматику. Исходная команда маршрутизатора из `df60` оставлена без изменения.
- N000032 явно ограничивает приоритет профиля его точной границей; запасная проверка не считается прохождением.
- Краткие записи N000001/N000003/N000032 обновлены в инвентаре. Записи других правил, снимок основания и тема N000028 не затронуты.

## Свидетельства и неизвестное

- Исходный literal N000003 сверен чтением `AGENTS.md` из точного Git blob `df60f239c178a6b3bd9274ce190385089579b706`; команда не исполнялась.
- `jq -e` структурно разобрал инвентарь; количество исходных единиц/правил — `265/236`. Это не запуск валидатора декомпозиции. В SKILL базы указано 227 правил, поэтому полная согласованность остаётся `UNKNOWN`.
- Локальный нативный Swift recency helper имеет исходный SHA-256 `53b721faa081b39d88bb74b72ad63908303e66fe1fb05daeb9c7a1a6dc0bd1b3`. Сохранённый бинарник обновил `AGENTS.md` с кодом 0. Первый вызов для нового запроса отказал с `причина=git`, потому что файл ещё не был в индексе; второй — с `причина=повреждённаяМетка` из-за моего некорректного placeholder. Placeholder удалён, после индексирования запрос успешно обновлён с кодом 0. `отчёт.md` helper исключает, поэтому его recency остаётся `UNKNOWN`; Python-обновитель не использовался.
- В предыдущей контрольной точке уже зафиксирован единичный read-only запуск Python-маршрутизатора в старом worktree после запрета Python. Здесь он не повторяется.
- ROOT JSONL и `остаток --без-записи` не читались/не запускались. Python, маршрутизатор, полный валидатор, тесты и профиль не запускались; эти проверки и профиль остаются `UNKNOWN`, не `GREEN`. Финальная приёмка не заявляется.
- Первая локальная фиксация этой точки получила автора `FUM Писатель` из переменной окружения; OID `0a91f183f5efec4e3aef06eeb25a5bff56c64941` не отправлялся. Первый `--amend` без `--reset-author` сохранил неверного автора в промежуточном OID `b3a1009d0`; он тоже не отправлялся. Remote оставался на родительском `0e4022c131bcd779da5e1254205c0ee3442746e3`. Последующий `--reset-author` дал правильные author/committer `FUM Codex [gpt-6.1-sol; effort=high] <fum@local>`; readback перед push записан отдельно.
- `git diff --check` прошёл до финальной сверки коммита; точный diff/index, OID текущего коммита и его remote readback ещё предстоит зафиксировать.
