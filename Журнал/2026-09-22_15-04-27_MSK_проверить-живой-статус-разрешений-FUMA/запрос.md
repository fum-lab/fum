## Происхождение и граница этапа

Это продолжение после коммита `e7e5bd3295aeaa1250659bd5ae2d3ca7128ec33c`. Реестр показал доступный наблюдательный этап; headless-статус FUMA уже получает Accessibility и Input Monitoring через macOS API без открытия настроек, но его сохраняемый JSON не имел схемы и источника. Этап добавляет `fum.permission-state.1`, сохраняет live-ответ и проверяет его адресной сборкой. Запрос разрешений, GUI, event tap, братиславская проекция и полный smoke-check не выполняются.

## Проверки

- Release-сборка продукта `fum` выполняется во внешнем scratch-каталоге.
- `--permission-status --permission-status-output` запускается без `--request-permissions`, поэтому не вызывает prompt и не открывает настройки.
- Сохранённый JSON проверяется на точные `schema`, `source` и фактические boolean/string-поля.
- `git diff --check`, recency, структура Журнала и связность текущей сессии выполняются перед коммитом.
