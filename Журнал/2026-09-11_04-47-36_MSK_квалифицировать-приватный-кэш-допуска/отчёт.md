## Проверки

[Полные безопасные метаданные](материалы/квалификация-кэша.json) связывают исходник, версию кода, времена, профили, ресурсы и исходы. Измерительный сценарий выполнил ровно один контрольный guard без кэша на окончательном пути, один reader для подготовки, один guard и один адаптер с кэшем. Префикс, его метаданные, код двенадцати исполняемых файлов, HEAD данных `406c6ba1d0b3373403fefd14d5f7faf8e0665b7d` и реестр стабильны на всей последовательности.

Контрольный guard вернул code 3 и `продолжить` за 4,647207 с. Внутри 1,673429 с заняли обязательства, 2,880043 с — сообщения без записи. Подготовка reader прочитала все 296 513 041 байт и 37 564 строки за 2,760285 с полного процесса; её внутреннее время — 2,672534 с. Полнота подтверждена, незавершённой строки и поздних байтов нет. CLI запускался с `-E -S -B`: переменные Python исключены, импорт соседнего модуля сохранён; `-I` этому CLI не подходит.

Guard с индексом вернул тот же code 3 и полное решение wire v3, совпадающее после разбора JSON за 1,972376 с. Его внутреннее время — 1,914145 с: обязательства 1,591813 с, сообщения со всей историей и сверками 0,295329 с. Наблюдаемое сокращение полного времени относительно контроля — 2,674831 с в этой единственной паре; повторяемая статистическая оценка не заявляется.

Адаптер с тем же кэшем завершился за 2,043376 с, code 0, `decision:block`, с нормальной причиной требования продолжения. Backend занял 1,978150 с и успел в родные 3 с. Внешний предел измерителя 30 с не достигался ни одним процессом. Нативный hook этим синтетическим событием не проверяется.

Частное состояние адаптера размещено отдельно и создаётся ожидаемо. ## Решения и ограничения

Минимальная конфигурационная мера перед FUM-STEP-0154 подтверждена для этого неизменного снимка: заранее подготовить штатный приватный индекс тем же кодом для окончательного пути JSONL и передать его через уже существующий `--кэш` guard и адаптеру. Реализация остаётся точным 6b186059; timeout, hooks, Trust и production не меняются.

Быстрая ветвь доверяет неизменным метаданным локальной ФС после проверки индекса; она не доказывает повторное криптографическое чтение всех байтов при каждом вызове. Изменение метаданных требует полного хэширования прежнего префикса и разбора хвоста; смена реализации требует полного разбора. Сам guard с `без_записи=True` индекс не обновляет. Холодный старт, допись и изменение реализации этим тёплым результатом не квалифицированы. Отдельный кэш границ не создавался и обычным индексом не заменяется.

Диагностическая контрольная точка содержит открытый журнал терминальных записей. Код не менялся; повторная общая приёмка не запрашивалась. Проекция остаётся на принятом поколении 6b186059 и отстаёт от новых канонических материалов этой и предыдущей диагностик. Финальная связность с `--контрольная-точка`, recency без записи и `git diff --check` выполняются после предпросмотра вне границы измерения. Собственный составной допуск перед final отдельно сверяет конечный объём после коммита и точной публикации.
