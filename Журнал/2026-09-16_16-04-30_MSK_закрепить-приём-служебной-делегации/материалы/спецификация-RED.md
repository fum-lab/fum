# Спецификация адресного RED

Это план проверок после получения выбранной координатором неизменяемой записи разрешённой связи. Исполняемый тест ещё не написан и не запущен. Реальный приём запрещён текущим уточнением до передачи якоря.

## Немаскирующий исходный случай

Использовать устройство фикстуры из [test_допуск_сообщений.py](../../../Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_допуск_сообщений.py): временный собственный Git-репозиторий, корректный JSONL исполнителя, разовый план v1 с завершённой прежней работой и полноценным собственным основанием. Человеческий остаток равен нулю. Контрольный вызов старого guard без нового принятия должен иметь exit 0 и решение завершить; иначе фикстура маскирует дефект посторонним отказом.

Внести проверяемую служебную доставку в её реальной оболочке function_call_output. Подготовить отдельное типизированное принятие только относительно независимо выбранного полномочного якоря. План остаётся прежним, связанной работы нет. Единственная целевая причина отказа — непокрытое действительное принятие, ожидаемый exit 2; недействительная фикстура, неизвестный флаг или повреждённый JSON не считаются нужным RED.

После штатной регистрации невыполненной работы, связанной с тем же принятием и исходным основанием, ожидать exit 3, решение продолжить и точный ID этой работы. Постоянный v1 и частичный v3 не использовать вместо основного случая: они уже требуют продолжения.

## Соседние адресные проверки

| Изменение входа | Ожидаемая граница |
| --- | --- |
| XML или source_thread_id без выбранного якоря | Полномочие не подтверждено; регистрация не происходит |
| Разговорное assistant «принял» | Не создаёт типизированного принятия |
| Чужой UUID исполнителя или координатора | Отказ, без записи |
| Изменён диапазон/SHA доставки или исходное основание | Отказ, без записи |
| Повтор ровно того же явного принятия | Идемпотентность, без второго обязательства/статуса |
| Удаление/переназначение принятия в достижимой истории | Отказ через существующий полный DAG |
| Работа отсутствует либо связана с другим принятием | Exit 2, а не завершить |
| Источник, связь или реестр меняются между первым чтением и выдачей guard | Отказ при заключительной сверке |
| Завершён только этап/ребёнок | Родительское обязательство координатора не погашается |

Статусы работы и доказательства её приёмки остаются существующими; типизированное принятие не дублирует жизненный цикл. Отдельно сохранить штатный приоритет действительной остановки человека. Полнота только по проверенному долговечному набору принятий; отсутствие незаписанного разговорного принятия не доказывается.

## V3 и отдельная работа

В [проверке v3](../../../Инструменты/fum-svyaznostj-rabochej-sessii/scripts/обязательства_задачи.py) определение работы включает ID, обязательство, действие, основание, предпосылки, ожидание и точные пути результатов. Основание равно основанию родительского обязательства. Определения неизменяемы на рёбрах истории, кроме ожидания; приёмка связывается с конкретной работой. Поэтому уже принятую FUM-ОСТАТОК-РЕЕСТР нельзя переименовать или использовать её приёмку как доказательство нового приёма делегации. Выбор новой root-работы и её принятие остаётся координатору.

## Профиль

На одной открытой фикстуре сохранить версию кода, входные хэши и раздельные длительности чтения источника, проверки выбранного якоря/диапазонов, истории принятий, покрытия работой и заключительной сверки. Сначала корректность RED/GREEN, затем исходный замер и оправданная оптимизация либо решение оставить код по измерению. Этот профиль не измеряет нативный Stop и не обещает его бюджет.
