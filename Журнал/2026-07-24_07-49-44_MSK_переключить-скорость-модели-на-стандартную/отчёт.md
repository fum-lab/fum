# Отчёт 2026-07-24 07:49:44 MSK - Переключить скорость модели на стандартную

Проектный слой Codex больше не запрашивает повышенную скорость Fast. В нём сохранены модель `gpt-5.6-sol`, рассуждение `ultra` и изоляция локальных навыков. Само это изменение не доказывает итоговый выбор Desktop при создании новой задачи.

## Изменение конфигурации

В `.codex/config.toml` значение `service_tier = "fast"` заменено на `service_tier = "default"`. Отдельное значение `standard` не используется: схема Codex называет базовый стандартный сервисный уровень `default`. Флаг `features.fast_mode = true` оставлен как возможность ручного выбора Fast через интерфейс Codex и сам по себе не включает повышенную скорость.

Реестр системных приложений и инструментов синхронизирован с новым состоянием конфигурации и наблюдаемыми версиями поверхности, встроенного runtime и самостоятельного CLI. Исторические запросы и отчёты, описывающие прежний Fast-снимок, не переписывались.

## Последующее уточнение

Новая Desktop-задача после этого изменения всё равно получила явный `service_tier = "priority"` из управляемого системного профиля `models.new_thread`. Этот более приоритетный выбор соответствует Fast и перекрыл проектный `default`; поэтому прежняя приёмка подтвердила только проектный слой, но не фактический дефолт новой задачи. Диагностика и исправление системного профиля описаны в [последующем отчёте](../2026-07-24_08-19-09_MSK_исправить-скорость-новых-задач-по-умолчанию/отчёт.md).

## Проверки

- Локальный разбор TOML подтверждает `service_tier = "default"` и сохранность остальных проектных инвариантов.
- Встроенный и самостоятельный runtime Codex проходят строгую загрузку обновлённой конфигурации и модельного каталога.
- Recency-метки, граф Obsidian, сессионная связность, `git diff --check` и полный smoke-check проходят.
