# Отчёт 2026-08-03 18:46:53 MSK - Добавить изолированный пишущий подузел и кандидатный commit

В проверяемый многоагентный Swift-контур добавлен `WritingSubnodeExecutor`, который исполняет один уже проверенный WorkPackage v1 в отдельном клоне от точного `base_oid`. Типизированный запрос связывает запуск с эпизодом, поколением шага, карточкой, подузлом и репозиторием, задаёт целевой ref и конечный набор детерминированных записей. Перед первой записью в кандидатный checkout исполнитель повторяет предпусковую проверку хэшей обязательных входов, области, исключений, зависимостей, проверок, маршрута передачи и бюджетов пакета.

Для запуска резервируется отдельное устойчивое пространство, создаётся клон без локальных hardlink и alternates, удаляется исходный remote и проверяется независимость Git directory и common-dir. Перед клонированием закрываются исполняемые и сетевые настройки локальной Git-конфигурации, а источник получает полный побайтовый снимок вместе с HEAD, индексом, refs и достижимыми объектами. Исполнитель назначает уникальные полные branch ref и result ref, допускает только обычные файлы внутри `listed_paths_only`, повторно сверяет фактический staged diff и выполняет только закрытые декларативные проверки, чьи спецификации входят в хэш запроса.

Файловый аудит предшествует Git-командам над источником и восстановленным клоном: `.git` не может быть ссылкой и не содержит FIFO или других специальных объектов, config читается через `O_NOFOLLOW | O_NONBLOCK`, а его ключи сверяются с закрытым списком. Крупный безопасный config подаётся Git в отдельном системном потоке при одновременном чтении вывода, поэтому заполнение двух pipe не образует взаимной блокировки. Восстановление также отвергает ссылочные компоненты `runs`, изменённую квитанцию, annotated tag вместо прямого commit ref и конфигурацию filter или `alternateRefsCommand` до возможного внешнего процесса.

Канонический паспорт связывает точные байты пакета и preflight-отчёта, снимок источника, устойчивые идентификаторы, commit, tree и родителя, оба refs, входы, зависимости, бюджеты, фактические пути и хэш diff, проверки, ограничения и подготовленный, но не принятый и не опубликованный маршрут передачи. Машинные пути остаются во внешнем runtime-контексте. Оба refs публикуются одной Git-транзакцией; паспорт и квитанция исхода фиксируются атомарно через эксклюзивное переименование. Точный повтор успешного `run_id` не доверяет одному файлу: он заново проверяет паспорт, клон, direct refs, commit, tree, родителя, scope, обязательные артефакты и diff. Оборванная попытка возобновляется в новом клоне, а прежний клон сохраняется как диагностический артефакт.

Отрицательные сценарии различают `no-op`, блокировку до записи, выход за разрешённую область и Git-метаданные, грязный источник, изменившийся вход, секрет, публикационный отказ, провал проверки, смену базы и конфликт запуска. Устойчивые квитанции сохраняют тот же отрицательный исход при точном повторе; искусственный commit или result ref не создаются. Исходный checkout во всех проверенных сценариях остаётся неизменным по полному побайтовому инвентарю, HEAD, символическому HEAD, статусу, refs, достижимым объектам и индексу.

FUM-STEP-0085 завершена и удалена из whitelist `master`. Единственным вычисленным готовым продолжением стала FUM-STEP-0086, которая отдельно добавит CAS-интеграцию бесконфликтного кандидата. Текущая поставка не интегрирует кандидатный commit, не выполняет push, не запускает модель или сетевой сервис и не подключает субагентов общей рабочей копии к новому исполнителю.

## Решения и ограничения

- Исполнитель принимает только один конечный проверенный пакет и не выдаётся за параллельный runtime нескольких пишущих подузлов.
- Путь клона, путь хранилища паспортов и другие машинно-локальные значения остаются во внешнем контексте и не входят в сохраняемый паспорт.
- Устойчивый result ref сохраняет кандидат доступным для следующего шага, но состояние `prepared` не означает принятие, интеграцию или публикацию.
- Сериализованная CAS-интеграция, разрешение конфликтов, долговечный fork-подузел, проектный submodule и сквозная приёмка остаются отдельными карточками FUM-STEP-0086–FUM-STEP-0090.
