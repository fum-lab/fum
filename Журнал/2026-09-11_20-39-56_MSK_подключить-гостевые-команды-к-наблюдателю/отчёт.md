# Отчёт 2026-09-11 20:39:56 MSK - Подключить гостевые команды к наблюдателю

Гостевые команды подключены к принятому Python-адаптеру. готовность.py получает две точные UTF-8 строки через данные единственного stdin, проверяет каждую до 256 KiB и загружает обязательную функцию родителя в отдельном namespace без __file__. Гость открывает свои FD каталога и захваченного flock, явно передаёт их метрикам и адаптеру; численные FD с macOS не переносятся.

ИзмеренияГостя.команда сохраняет прежний этап, передаёт UUID текущей командной фазы как родитель, проверку и источник, точные argv/cwd/env/stdin и пределы. Старые Popen/poll/killpg/TemporaryFile удалены. Любой непринятый результат остаётся ошибкой этапа; CLI наблюдателя 0 не подменяет исход команды. Сообщение принятого отказа содержит причину, UUID и код, включая None при истёкшем до запуска сроке. Пустая среда не заменяется средой по умолчанию.

Offpath Git без активных метрик закрыто отклоняется. Автономные clone-тесты получили явный test-only контекст локального исполнителя. В рабочем гостевом пути все пять инфраструктурных команд, Git клона, четыре набора и два индекса проходят через метрики. Названия операций, три ветви, 35/40 командных листьев и матрица 38/43 сохранены; отдельные helper-квитанции не становятся фазами.

## Проверки

- Исходный RED: отсутствующий загрузчик и прежний конструктор дали один отказ и десять ошибок в шести методах. Подключение адаптера дало GREEN шести сценариев с настоящими процессами.
- Отдельный RED раннего срока показал потерю причины/UUID при корректной квитанции с кодом None. Исправление допускает отсутствие кода для отказа, но успешный результат требует точного int 0, причины завершение и исхода успех; Bool отклоняется.
- Расширенный прогон девяти методов прошёл восемь. Ошибочным было ожидание теста полной точки входа: команда возвращала код 0 и JSON {}, поэтому её командная фаза законно успешна; проверка смысла cloud-init затем должна завершить внешний этап ошибкой. Исправлен тест, а не production-семантика; отдельный прогон точки входа прошёл.
- После удаления implicit Git fallback старые clone-фикстуры дали пять ошибок в шести методах. Явный test-only runner восстановил GREEN всех шести: точные байты/индекс, отказ скрытых флагов, сохранность прерванного клона и запрет подмены опубликованных объектов. Production fallback не возвращён.
- Независимый RO-обзор не обнаружил блокирующих регрессий в трёх файлах. Он уточнил SIGKILL-фикстуру: используются допустимые имена Готовность Linux и Завершение cloud-init; после wait не требуется заведомо ещё занятый lock, поскольку планировщик может дать наблюдателю закончить cleanup раньше проверки. Когда lock впервые наблюдён свободным, финальная квитанция уже обязана подтвердить исчезновение группы. Адресная проверка изменённого SIGKILL-сценария прошла.
- Тесты проверяют источник через exec без __file__, точные UTF-8, argv/cwd/env/stdin, удержанные FD, parent/check/source квитанции, нормализацию ошибки наблюдателя, ненулевой код, deadline/outputcap и строгий исход. SIGKILL отправлен только собственному живому процессу родителя; контрольный процесс остаётся жив. После cleanup heartbeat не растёт, два начальных файла сохраняют bytes/hash, конечные фазы не синтезируются, повтор экспорта ничего не меняет и не запускает команду.
- Девять сценариев подключения и шесть clone-сценариев подтверждены общим и необходимыми адресными GREEN. После исправления одной тестовой ожидаемой величины и уточнения SIGKILL-фикстуры неизменённые сценарии повторно не запускались. Swift reducer и полная матрица не исполнялись в дочернем дереве; неизменность production-формы сверена по exact diff и независимому RO.
- Первый профиль сохранён отдельно: медиана 145,120167 ms. После уточнения имён фаз фикстуры актуальные три измерения 145,552292 / 139,536000 / 141,802959 ms, медиана 141,802959 ms < заранее заданных 500 ms. Алгоритм не оптимизировался: профиль не оправдывает усложнения; ускорение не заявляется.

## Решения и ограничения

- Публичный готовность.py сохраняет вызов подтвердить_готовность(данные); обязательные новые поля наблюдатель и родитель_наблюдателя — непустые UTF-8 строки ≤256 KiB каждая. загрузить_исполнителя возвращает callable; конструктора ИзмеренияГостя без явных замок/наблюдатель/исполнитель больше нет. Runtime argv/env/stdin/manifests остаются только в личном гостевом каталоге вне checkout.
- Экспортировать_измерения остаётся прежним независимым четырёхполевым запросом машина/план/проверка/исходник. Он не требует новых исходников, не исполняет helper или готовность, не создаёт недостающие конечные фазы. При активном наблюдателе личный lock препятствует экспорту; повтор после cleanup сохраняет исходные байты. Схемы фаз и пакет экспорта не менялись.
- На SIGKILL нельзя выполнить finally родителя. Начальные фазы активной цепочки остаются неполными; отдельная долговечная квитанция наблюдателя связывается с UUID командной фазы, но не подменяет её конец. Неполный пакет не является подтверждённой готовностью.
- Проверенная среда Python 3.14.7 / Darwin arm64. Guest рассчитан на Linux Python 3.12 с waitid/WNOWAIT; реальный Linux-прогон не выполнялся. Отказ самого наблюдателя, непрерываемый ввод-вывод и ушедшие из PGID процессы сохраняют ограничения принятого адаптера; эта интеграция их не переопределяет.
- Новая Swift-схема манифеста должна включить точные bytes двух helper-ресурсов в source fingerprint и данные stdin. Хостовый SSH, восстановление VSOCK и интерактивный SSH находятся вне гостевой глобали метрик. Корень реализует и принимает манифест/обмен отдельно; собственный коммит этой части не подтверждает доставку в VM или интеграцию в master.
- Сохраняющая контрольная точка допускается с прежним точным исключением исторического LICENSE неразвёрнутого LinguisticKit по FUM-ПРАВИЛО-000178. Gitlink 837e2ce107b97ee7b9d3344c9fe99142281fe393 и общая Git-конфигурация не меняются; submodule не подготавливается. Полной приёмки нет. Проекция Proyekcii сохраняется из базы d4ee3ee0 и не включает новые канонические байты.
