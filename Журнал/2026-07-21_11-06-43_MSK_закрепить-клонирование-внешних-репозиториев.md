# Отчёт 2026-07-21 11:06:43 MSK - Закрепить клонирование внешних репозиториев

Внешний Git-репозиторий теперь подключается к FUM только через явную цепочку: полноценный локальный клон, сверка upstream и выбор проверенной ревизии, затем регистрация существующего клона как Git submodule. Основной репозиторий сохраняет `.gitmodules` и gitlink на точный коммит, поэтому локальная доступность зависимости сочетается с воспроизводимой фиксацией её состояния.

Актуальная локальная копия и автоматически обновляемая зависимость не смешиваются. Перед использованием выполняется явный `git fetch` и проверка выбранной ревизии; submodule фиксирует результат этой проверки и сам по себе не следует за удалённой веткой.

## Границы решения

Конкретная внешняя зависимость не добавлена: запрос задаёт общий порядок, но не называет репозиторий, URL, путь, ревизию, условия доступа или лицензию. Выбор произвольного upstream вышел бы за границы решения. До появления первой зависимости порядок остаётся ручным и проверяемым по `AGENTS.md`.

## Решение по автоматизации

В оперативное планирование добавлен кандидат на TDD-помощник, который при первом реальном подключении должен автономно проверить цепочку `clone -> fetch/verify -> git submodule add`, совпадение remote, чистоту клона, `.gitmodules`, gitlink и точный коммит. Реализация отложена до конкретного случая, чтобы не закреплять неиспользуемый интерфейс и сетевые допущения.

## Проверки

- Перед первой записью подтверждены чистый `master`, отсутствие блокирующих путей и готовый следующий шаг ветки.
- Автономный локальный Git-сценарий подтвердил добавление уже существующего клона как submodule, запись `.gitmodules` и gitlink режима `160000` на тот же точный коммит.
- Плановый реестр пересобран и валиден; сохранённая содержательная задача master получила свежий `step_id` без изменения приоритета.
- Recency, индекс Markdown-файлов, тепловая карта Obsidian и связность сессии прошли штатные проверки.
- Два последовательных полных smoke-check прошли все `29` шагов; второй прогон завершился явным маркером успеха и кодом `0` на финальном содержательном снимке.
- `git diff --check` не обнаружил ошибок пробелов.

## Продолжение

При первой фактической внешней Git-зависимости нужно применить новый порядок, добавить submodule на явно выбранный коммит и через TDD превратить ручные проверки в локальную автоматизацию. Содержательная задача `master-refresh-developer-entrypoints` сохраняется следующим шагом ветки без изменения приоритета.
