# Отчёт 2026-09-11 01:45:23 MSK - Адаптировать приложение FUM для монорепозитория

Подготовлена проверяемая контрольная точка: 13 из 39 исходных файлов сохранены побайтно, 26 адаптированы; добавлены 9 файлов, включая конечный манифест. Файлы находятся в `Приложения/FUMA/macOS`. Канонический каталог не пересекается с четырьмя пакетами FUMA, которые переносит корень. В FUM на базе `406c6ba1d0b3373403fefd14d5f7faf8e0665b7d` нет побайтных совпадений с этими 39 blob. Самостоятельный прототип физических клавиш сохраняется отдельно: его контракт переходов/монотонного времени отличается от CGEvent-монитора приложения, который также сохраняет символы, мышь и прокрутку.

Источник — точный main `39eb66a29c0be6844e73bcb8072e68b914ea7387`, дерево `c31fc5711fc0e90898ce102eec8cecc5f190d110`: 39 обычных файлов, 429019 исходных байтов. Читались только закреплённые Git blobs. Исходный репозиторий и его работа не изменялись. Публичного промежуточного коммита с прежними машинными путями нет. Фактическая среда сборки — macOS 27.0 arm64, Xcode 27.0 beta; версия 26 в ограничениях mpv относится к его bottle, а не текущему хосту. Первичный манифест сохраняет исходные commit/blob/SHA/mode, конечный манифест — точные адаптированные байты и отдельный список новых файлов.

Общие пути вынесены в Foundation-модуль `ПутиИсполнения`, подключённый во все SwiftPM-продукты и обе Xcode-цели. Runtime и память находятся вне Git, параметры общие для приложения и помощников. Runner собирает свой пакет из любого рабочего каталога, обновляет ранее собранный helper и использует внешний scratch. Системный mpv подключён через pkg-config и локальный C-модуль без копирования внешних заголовков. OpenGL.framework остаётся явной линковкой; дополнительный dlopen возможен только по заданному параметру. Три установщика завершаются до системных операций, три launchd plist содержат нераскрытые маркеры.

- Python RED/GREEN подтвердил устранение путей, корректный package/scratch из чужого cwd, обновление старого helper, неприкосновенность внешних действий установщика, shell-синтаксис и миграционные границы. Конечный набор сверяет также все исходные и новые SHA/mode по манифесту.
- SwiftPM: пять синтетических тестов конфигурации, Git/symlink-границ и поиска команды по PATH прошли; команды из PATH не исполнялись. Четыре продукта собраны в Debug и Release. После последней правки resolver/C-адаптера Release выполнен повторно на изменённом входе.
- C RED воспроизвёл попытку открыть неуказанную библиотеку, GREEN подтвердил отсутствие такой попытки и явный fallback. dlsym/dlopen подменены; функции mpv и OpenGL не вызывались.
- Xcode собрал обе цели с отключённой подписью, jobs 2 и каталогами mpv из pkg-config. Первое построение явно завершилось BUILD SUCCEEDED. Повторная сборка изменённого кода вернула 0, но quiet-вывод Xcode 27 beta содержал две строки о команде с exit code 0 без вывода и 46 предупреждений. Это ограничение диагностики сохранено, а не объявлено отсутствующим.
- [Read-only-сверка артефактов Xcode](материалы/артефакты-Xcode.json) подтверждает четыре существующих arm64 Mach-O: основной executable, Debug dylib, встроенный helper и отдельный продукт helper; SHA обоих helper совпадают. Наличие файлов само по себе не отменяет сохранённые ограничения диагностики.
- Штатная проверка plutil подтвердила project.pbxproj и plist. Публикационный сканер выявил рабочие системные привязки: они устранены. Остались только 25 точных определений распознавателя и синтетических фикстур, оформленных штатным обновителем политики.

## Решения и ограничения

- Наблюдённый mpv — Homebrew 0.41.0_9, API 2.5, pkg-config 3.0.7; bottle arm64 с minimum macOS 26.0. Предупреждение линковки о macOS 14/26 ожидаемо и не доказывает совместимость с macOS 14/15 или Intel. Динамические зависимости Homebrew не упакованы в автономный bundle.
- Исходная собственная наработка не содержала LICENSE; она сохраняется под лицензией FUM. Внешний mpv не становится CC0: режим наблюдённой сборки GPL, FFmpeg имеет GPL/version3. Заголовок client.h отдельно ISC. Бинарная публикация требует отдельной оценки состава зависимостей.
- Xcode выполнил стандартную регистрацию временного bundle в LaunchServices. Живое приложение, Accessibility-сенсор, цикл внимания, установка, launchd, Keychain и запросы разрешений не запускались. Это не испытание органов, разрешений, UI и видеопроигрывания.
- Первый RED runner имел ошибку изоляции: пустой override допускал выбор существовавшего установленного helper. Ему достался пустой stdin, инструментальные команды не отправлялись; живых записей/GUI не наблюдалось. Исправленная фикстура задаёт явно отсутствующий helper, подставной Swift и временные пути. Неуспешная запись сохранена, отдельный номер сбоя не выдуман.
- Первый массовый перенос путей изменил 15 файлов, затем ошибся при формировании отчёта относительно точки. Регрессия воспроизвела дефект; корень нормализован до абсолютного и отчёт подготовлен до записи. Новый запуск из закреплённых исходников в временном каталоге подтвердил все 15 результатов. Исходный отказ не заменён успешной записью. Поздняя параметризация шаблонов имеет отдельные до/после-хэши.
- Изолированное дерево использует прежнее поколение братиславской проекции базы 406c6ba1: SHA256 манифеста `cc02a0482eeddea16d44b9049b9f062dc9004f3c09f97b47c9b71c288b7dde98`, входной инвентарь `544a1e4a110118a3a9e8957b50a3c4a8330380136ef524186f0892861bf62ff2`. Оно отстаёт от новых файлов; контрольная точка не выдаёт его за финальное. Общий smoke-check, актуальная проекция, воспроизведение из чистого клона, интеграция в ведущую ветку и решение по всему объёму FUM-STEP-0176 остаются корню.
- Во время восстановления один вызов справки получил ошибку из-за опечатки в имени инструмента; инструмент не запускался и записи не было. Чтение однострочного большого манифеста проекции было обрезано выводом; затем нужные поля прочитаны структурно, без догадок по обрезанному тексту.
