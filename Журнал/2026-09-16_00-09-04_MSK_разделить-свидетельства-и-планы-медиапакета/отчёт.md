## Проверки и наблюдаемые отказы

- Итоговый полный набор: **39 тестов, OK, 12,898 с**, [дословный stdout](материалы/вывод-final-green-006.txt), producer завершён с кодом 0. Проверены цель и материал, отдельное основание результата и протокол, типы и нули, соответствие каждого финансового поля включая null, дубликаты полного JSON, встроенные записи, пути и Git-типы, replacement refs, отсутствие дозагрузки, повторяемость, CLI без байткода и граница коррекции ссылок.
- Первый RED: 32 теста, пять failures и 11 errors; четыре контекста старого финансового хвоста воспроизвели принятие встроенной записи. Следующий набор из 32 прошёл. Независимый обзор затем выявил разделяемую ссылку на вход, некорректную подпись отчёта без свидетельства и запись байткода CLI; все три воспроизведены и исправлены.
- Два неуспешных запуска из 38 тестов завершились на предусловии partial-clone-фикстуры: blob уже присутствовал до генератора. Это ошибка построения проверки, а не доказанная загрузка генератором. Фикстура заменена явным локальным promisor-набором без blob; положительный контроль обычным Git подтвердил возможность загрузки, а генератор отказал без её выполнения. Последующие наборы прошли.
- Для helper отдельно сохранены отказ до появления модуля и два RED границы следующего раздела. Итоговый отказ охватывает отступ, tab, пустой ATX и Setext. Семь вариантов находятся в одной регрессии; конкретный применённый патч не выходил за разрешённый раздел.
- [Реестр вывода](материалы/свидетельства-вывода.json) связывает самостоятельные артефакты с кодом производителя и хэшами обоих полных приватных потоков. Для обычного runner stdout скопирован побайтно; для прямых unittest с пустым stdout отдельно обозначена замена локального пути в stderr. Историческая подпись «SHA-256 полного stderr» относилась только к тексту unittest: предупреждения дочернего Git могли идти в stderr отдельно. Текущий producer называет эту границу точно; полный поток подтверждается манифестом захвата.
- У записи порядка 5 название шире фактического вызова: выполнены только два теста `-k коррекция`, Git-контроль в неё не входил. В одном позднем вызове имя каталога обёртки было набрано с заглавной P; локальная ФС разрешила тот же файл, запуск завершился и сохранён. Итоговый набор выполнен с точным каноническим регистром. Эти ограничения не скрываются переименованием прежних записей.
- После переноса связность на дереве индекса `49d4d023e3a033d1c48b6fd32709c219dcda85b1` завершилась с кодом 0; [stdout](материалы/успех-связности-002.txt) сохранён. Дополнительная смысловая сверка затем обнаружила две устаревшие строки индекса сбоев: обновлены число проявлений 0071 и статус, число и основной шаг 0078. Поэтому этот успех не переносится автоматически на окончательный снимок: заключительный допуск повторяется перед коммитом.
- Первая заключительная связность терминально завершилась с кодом 1 до коммита: layout не допускает отдельный файл коррекции рядом с запросом и отчётом. [Полный отказ](материалы/отказ-связности-001.txt) сохранён; файл перенесён в материалы, ссылки обновлены. Успешный исход не подставлен вместо отказа.
- Первоначальная сборка реестра отклонила ещё оформляемый раздел источников STEP0174: добавленный абзац не имел маркера списка. Маркер восстановлен до сохранения реестра; наблюдённый код 1 не считается успешной генерацией.
- Первый импорт истории модели отказал из-за отсутствовавшего каталога материалов; после его создания штатный импорт завершился с кодом 0. Это подготовка артефакта, а не успешный тест. [Независимый обзор кода](материалы/независимый-обзор-кода.json) связан с SHA восьми файлов. После адресного повторного чтения существенных замечаний не осталось. Обзор не заменяет формальный допуск. Ранние поля пары, реестр, recency и заключительная связность выполняются на подготовленном снимке; коммит допускается только после терминального кода 0.
