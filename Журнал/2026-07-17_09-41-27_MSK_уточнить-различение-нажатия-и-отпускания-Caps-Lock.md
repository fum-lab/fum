# Отчёт 2026-07-17 09:41:27 MSK - Уточнить различение нажатия и отпускания Caps Lock

В [требовании о максимально сырой записи событий устройств ввода](../Требования/🟡-максимально-сырая-запись-событий-устройств-ввода.md) физическая фаза клавиши отделена от состояния модификаторов и логического состояния режимов фиксации. Для Caps Lock целевая трасса должна по возможности различать нажатие и отпускание клавиши, а включение или выключение режима сохранять самостоятельно и не выдавать за физическую фазу.

Если публичный API предоставляет только переключение режима, адаптер обязан явно зафиксировать потерю физической фазы и не придумывать событие отпускания. Фактически доступный и публикационно допустимый источник или сочетание источников, сохраняющее обе фазы, получает преимущество при выборе вместе с оценкой разрешений, ограничений sandbox, задержки, устойчивости и стоимости. Так ограничение конкретного API остаётся наблюдаемым и не искажает исходный поток.

## Решение по автоматизации

Существующее предложение о сравнительном Swift-прототипе источников ввода дополнено обязательным сценарием Caps Lock. Прототип должен начинать циклы из обоих логических состояний режима, отдельно сопоставлять переходы «нажато» и «отпущено» с состоянием режима и автоматически помечать источник, который их сворачивает. Отдельная автоматизация в этой документационной сессии не создавалась: воспроизводимая проверка требует реализации через платформенные API и реальных клавиатур.
