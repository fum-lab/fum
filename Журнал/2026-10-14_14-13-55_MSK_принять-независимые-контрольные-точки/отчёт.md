## Решения и ограничения

<!-- FUM-КАРТОЧКА:НАЧАЛО решения -->
Слияние Git заняло 0,612 с; три конфликта относятся только к навигации запроса, README и индексу. Их исходные байты сохранены, защищённые тела M/H совпали; применяется прежняя штатная регенерация. Отдельный source M сохраняет весь набор правил до кандидата. 80 pins K совпали с сырыми Git-байтами M; явные checker argv выбираются из K. Единственный найденный default W callback recency не изменён и совпадает с M/K; сверяется перед и после CLI. Это прежний ROOT.5, а не неподдерживаемый запуск ROOT через consumer.2. Новые шесть дополнений норм сохраняют исходные ограничения и полный ROOT JSONL. Производственные S/ROOT9/child10, реальный B/ACT_B/state2 и восстановление всех чатов не объявляются выполненными. Следующий этап после принятого merge — первый самостоятельный производственный S и два принимающих ROOT этапа по принятому контракту. Полный Creator B и исправление автора271 выполняются независимо; Issue264 и consumer cache продолжаются. Для двух новых исполнителей independently selected собственные D из проверенных receipt, без записи в чужие admin. Все 1075 человеческих оригиналов, три unknown и девять старых обязательств остаются в учёте. Замеченная избыточная выдача двух JSON вызвана собственным неверным использованием cat; большие JSON впредь раскрываются через полный захват и заранее ограниченное представление. Эти отказы не скрыты и не считаются успехом автоматизации.

Первый RO-план2326 использовал обычный одно-родительский контур и правильно отказал при MERGE_HEAD. Новый отдельный вход выбирает прежний двухродительский merge ROOT.5 без запрещённого ordinary transfer; старый вход и отказ сохранены. Это исправление выбора существующего контура, не изменение допуска.
