# Отчёт 2026-07-21 13:19:18 MSK - Подтвердить доступ к созданию форков в FUM lab

Текущая GitHub-авторизация позволяет создавать в организации `fum-lab` форки публичных репозиториев. Проверка выполнена без внешних изменений: новый репозиторий или форк не создавался.

## Подтверждённая возможность

Read-only проверка через GitHub CLI и REST API подтвердила, что текущая авторизация имеет достаточное право создавать публичные форки в `fum-lab`. Точная учётная запись, роль членства, атрибуты токена и закрытые настройки организации не сохраняются в публичной памяти. Официальный контракт GitHub разрешает публичный форк в организацию, где у пользователя есть право создавать репозитории.

Для каждого будущего форка всё равно требуется явно назвать исходный репозиторий и проверить, что GitHub разрешает его форкнуть в организацию. Для публичного upstream текущего доступа достаточно. Для приватного upstream создание форка в текущей конфигурации недоступно; для внутреннего upstream возможность не подтверждена и зависит от enterprise-контекста.

## Граница сессии

Проверка отвечает только на вопрос о возможности. Она не создаёт форк, не выбирает источник, имя и видимость репозитория, не клонирует зависимость и не меняет remote или `.gitmodules`. Уже закреплённый порядок внешних Git-зависимостей остаётся прежним: после отдельного указания источника постоянный форк `fum-lab` должен стать `origin`, а оригинальный репозиторий — отдельным `upstream`.

## Проверки

- GitHub CLI и REST API подтвердили достаточность текущего доступа к публичным форкам в `fum-lab`, не раскрывая приватное состояние в файлах сессии.
- Внешняя проверка выполнена без записи и без создания репозитория.
- Официальная документация GitHub подтверждает, что владельцы организации могут создавать репозитории независимо от запрета для обычных участников, а приватные форки дополнительно ограничены тарифом и политиками.
- Локальная связность сессии, recency, граф Obsidian и полный smoke-check проходят.
