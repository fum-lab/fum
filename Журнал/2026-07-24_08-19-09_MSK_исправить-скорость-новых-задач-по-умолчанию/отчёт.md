# Отчёт 2026-07-24 08:19:09 MSK - Исправить скорость новых задач по умолчанию

Конфигурационная причина Fast по умолчанию устранена на том уровне, который Desktop фактически применяет к новой задаче. Управляемый системный профиль теперь задаёт стандартный сервисный уровень `default`, согласованный с проектным конфигом, а модель `gpt-5.6-sol` и рассуждение `ultra` сохранены.

## Причина расхождения

Предыдущее изменение затронуло только `.codex/config.toml`. Оно было корректным для проектного слоя, но Desktop создавал задачу с явным `service_tier = "priority"` из отдельного управляемого профиля `models.new_thread`. Runtime-журнал текущей задачи непосредственно показывает этот override, а модельный каталог называет уровень `priority` режимом Fast. Поэтому проверка TOML и строгая загрузка CLI не могли доказать фактический выбор новой Desktop-задачи.

## Исправление и граница проверки

В системном профиле новых задач `service_tier = "priority"` заменён на `service_tier = "default"`. Ответ `configRequirements/read` нового локального app-server подтвердил исправленный дефолт вместе с сохранёнными `gpt-5.6-sol` и `ultra`. Проектная возможность ручного Fast-переключателя не отключена.

Текущая задача уже получила прежний Fast-override при запуске. Создание отдельной задачи ради проверки не выполнялось: контракт приложения разрешает это только по явному запросу пользователя. Для гарантированной перечитки управляемого профиля нужно полностью перезапустить Desktop; наблюдение новой задачи после перезапуска остаётся пользовательской проверкой результата, а не скрытым действием этой сессии.

## Проверки

- Сопоставлены проектный, пользовательский, управляемый и стартовый слои конфигурации.
- Runtime-журнал подтвердил прежний override `priority`, а модельный каталог — его отображение как Fast.
- Декодированный системный профиль и `configRequirements/read` подтвердили новое значение `default`.
- Recency-метки, граф Obsidian, сессионная связность, `git diff --check` и полный smoke-check проходят.
