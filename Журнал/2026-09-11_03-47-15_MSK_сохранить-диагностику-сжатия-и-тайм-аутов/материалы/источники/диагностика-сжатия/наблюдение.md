# Пауза при сжатии контекста FUMA

Записи основной задачи показывают начало сжатия контекста, два отказа удалённого потока с тайм-аутом WebSocket и последующее возобновление событий. Они объясняют непосредственный механизм длительной паузы. Причина отсутствия ответа соединения не установлена: эти данные не позволяют выбрать между сервером, сетью и клиентом.

## Подтверждённая последовательность

Все времена ниже относятся к 11 сентября 2026 года, зоне Europe/Moscow, UTC+03:00.

| Время МСК         | Наблюдение                                                                            |
| ----------------- | ------------------------------------------------------------------------------------- |
| 03:00:13          | auto_compact_scope_tokens=256258; total_usage_tokens=256258; token_limit_reached=true |
| 03:05:15          | remote compaction v2 stream failed; idle timeout waiting for websocket                |
| 03:10:22          | Второй remote compaction v2 stream failed; idle timeout waiting for websocket         |
| 03:20:48          | Новое событие задачи; auto_compact_scope_tokens=57566; total_usage_tokens=57566       |
| 03:21:04–03:21:54 | Ещё пять событий той же задачи в адресном снимке                                      |

Ранний диагностический отчёт завершён в 03:12:38 и ещё не подтверждал восстановление. Более поздний снимок добавляет события начиная с 03:20:48. В предыдущем этапе Журнала уже сохранены реальная команда с изображением в 03:20:48.584 и видимый ответ в 03:20:55.752. Продолжение после паузы поэтому наблюдаемо; успешность конкретной попытки сжатия, восстановление без нового ввода и устранение первопричины из этого не следуют.

## Границы выводов

Значение token_limit_reached относится к контексту сжатия; оно не доказывает исчерпания квоты аккаунта. Разность времён двух отказов не является установленным параметром всех будущих тайм-аутов. Снимок API с пустым items или устаревшим interrupted не доказывает отсутствия работы, когда первичный JSONL содержит более поздние события.

Отсутствие четырёх реплик со снимка — отдельное более раннее наблюдение. 02:55:36 взято из имени PNG, а не из восстановленных времён отправки этих реплик. Причинной связи между их отсутствием в JSONL и последующим сжатием не установлено. Их актуальность по-прежнему уточняется основной задачей.

## Передача в существующую работу

Основная задача передала кандидатные детекторы через 0201 в существующий FUM-STEP-0165: затянувшееся сжатие без видимого прогресса, повторные тайм-ауты, расхождение API с первичным JSONL и, при доступном разрешённом наблюдении интерфейса, отсутствие видимого сообщения в долговечной записи. Здесь сохранён вход этой работы. Действующие детекторы, изменение настроек Codex или исправление runtime этим этапом не заявляются.
