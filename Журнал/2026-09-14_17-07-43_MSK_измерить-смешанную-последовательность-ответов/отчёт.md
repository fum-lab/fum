# Отчёт 2026-09-14 17:07:43 MSK - Измерить смешанную последовательность ответов

Существующая API/cache-обёртка проверена на семи смешанных циклах: два новых ответа разных размеров и по два сохранённых чтения каждого. Всего 42 вызова вернули 116214 байтов компактного JSON+LF. Условное повторение полного JSON на каждом из тех же шагов составило бы 84026964 байта. Снижение полезной выдачи на 99,862% относится к этой явно заданной смеси 1:1; частота реальной эксплуатации не наблюдалась.

[Профиль](материалы/профиль-смешанной-последовательности.json) хранит каждый шаг, счётчики, время, SHA исходников и оригиналов. [Исполняемый сценарий](../../Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль-смешанных-ответов.cjs) использует существующий адаптер, настоящий shell/Python CLI и файловую запись; только `read_thread` заменён открытой фикстурой. [Команды воспроизведения и границы](../../Инструменты/fum-svyaznostj-rabochej-sessii/компактный-ответ-задачи.md).

## Раздельный учёт

| Наблюдение | Семь циклов | Что именно посчитано |
| ---------- | ----------- | -------------------- |
| Краткая выдача | 116214 байтов | Каждый возвращённый JSON с фактическим приватным путём и LF |
| Условные полные выдачи | 84026964 байта | Размер собственного полного JSON+LF при каждом из 42 чтений, включая повторы |
| Уникальные файлы | 14 / 28008988 байтов | Два новых файла в каждом цикле; повторные чтения не добавляют дисковый объём |
| Симулированный API | 14 | По одному на каждый новый ответ |
| Живой API | 0 | Сеть и нативный MCP-сервис не вызывались |
| Файловые записи | 14 | Настоящие записи полных артефактов |
| Локальные команды | 70 | Три команды на новый ответ и одна на сохранённый |
| Кэш | 28 чтений / 56 записей | Новый режим инвалидирует запись и сохраняет результат, повторный читает и обновляет запись |

Каждый шаг проверил доступность полного файла и SHA. Все 28 сохранённых вызовов совпали с первоначально принятым срезом, без API и новых файлов. Очистка удаляет только созданный профилем временный каталог после всех измерений. Это не политика хранения пользовательских артефактов.

Малый ответ увеличился 642 → 2763 байта, крупный уменьшился 4000642 → 2771. При одних таких малых ответах объём вырос бы примерно в 4,30 раза. Состав, размеры и две повторные выдачи на снимок заданы до замера; начальный размер чередуется. Сценарий не калиброван по реальному распределению задач.

## Проверки и решение об оптимизации

Два теста сводки сначала воспроизвели отсутствие модуля, затем прошли. Они различают повторную выдачу полного источника и уникальный дисковый файл, проверяют сумму времени/эффектов и отклоняют недопустимые измерения. Сам профиль также является исполняемой приёмкой: каждый цикл обязан дать ровно 2 симулированных API, 2 записи файла, 10 команд, 4 чтения и 8 записей кэша; проверяются SHA и смысловой результат каждого вызова. Производственный адаптер и прежний Python-срез не изменены, поэтому их широкая регрессия повторно не запускалась.

Решение: сохранить текущую обёртку и явное повторное использование. Новая оптимизация производственного кода не обоснована этим сценарием: измерено уменьшение полезной выдачи, но не стоимость живого API, сети или полных инструментальных конвертов. Служебные поля остаются даже при росте малого ответа. Выдача компактного результата и сохранение полного оригинала решают разные задачи; их байты не суммируются в один показатель экономии.

RO-проверка сверила опубликованные суммы и медианы с исходными шагами, подтвердила отдельный учёт живого/симулированного API и отсутствие приватного пути в материалах. Замечаний к методу и границам не найдено; проверяющий не запускал тестов и не менял файлы.

## Ограничения и остаток

Токены, RSS, реальный API, сеть и полный транспорт инструментов не измерялись. Полезная выдача включает путь и LF, но сам приватный путь не опубликован. Полные байты — собственная сериализация MCP-объекта, а не транспортные байты сервера. Повторное чтение проверяет сохранённый SHA; признак перепроверки живого состояния и доказательство завершения остаются ложными.

Измерен прежний Python в общей обёртке. [Новые порождённые Swift/Python-модели](../../Проекты/рабочий-контекст/операторные-модели-ответа.md) уже приняты отдельным ограниченным этапом и имеют собственный профиль генерации/применения; этот замер не объявляет их подключёнными к API.

[План](материалы/план-этапа.json) завершает согласованный смешанный профиль. Доступной независимой реализации в этом объёме больше нет; совместная окончательная приёмка с полным smoke и проекцией остаётся ожидающей снятия прямого ограничения. Контрольная точка своей ветки и её push не являются интеграцией в master и не закрывают всё направление 0165.
