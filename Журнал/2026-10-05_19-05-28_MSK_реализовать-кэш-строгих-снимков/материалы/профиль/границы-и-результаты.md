# Границы и результаты кэша строгих снимков

Этот этап обычной дочерней контрольной точки `.7` сохраняет ограниченный результат в собственной ветке. ROOT `01a07d3d-d376-7ad2-aafc-67e4c25a67eb` продолжает учёт человеческого диалога, глобальный guard и интеграцию. Исполнитель: `01a10cce-d8ef-70e2-8c5a-2692c416715e`, наблюдённая модель `gpt-6.1-sol`, режим `ultra`, встроенный runtime CLI `0.160.0`; версия поверхности Codex Desktop отдельно не подтверждена.

Постановка закреплена в C `a271b4af8c2600bfa6eb0476d98aba01a7cc6db9`. Независимо выбранный ACT A `847c579324472cc783fb4b827bb3c9d8cd902886` имеет raw SHA `40e3b0e2b007ed78f1acf2a115e418c536585f279b3f2756449463c85adcff77`. Буквальное нативное агентское поручение проверено по SHA `33335a9a1a82b748e5f03650b8b28d5b4e247b584b7efe5397b5dafadd01d058`; оно не выдано за сообщение человека. Ветка: `refs/heads/codex/dir/uskoritj-strogiye-snimki-katalogov`; начальный HEAD равен C. До ACT велись только чтение и приватные свидетельства. LinguisticKit подготовлен прежним защищённым `снимок → подготовить` на объявленной ревизии `837e2ce107b97ee7b9d3344c9fe99142281fe393` без изменения pin/config/gitlink.

## Изменение и регрессия

В производственном фасаде изменено только тело `снимок_обновления`: каждый вызов создаёт новый словарь каталогов и передаёт его прежнему `точный_путь`. Вне тела AST совпадает с C. Полные чтения, SHA256, режимы, три сверки Журнала и инвалидация device/inode/mtime/ctime сохранены. Новый набор использует настоящие Git и ФС: проверяет точные результаты, свежесть байтов и режимов, добавление и удаление, смену inode, регистр, ссылки, ошибки метаданных и перечисления, недопустимые цели и дрейф при построении/переиндексации.

Штатные v4-записи сохраняют все семь первоначальных запусков, включая неуспешные. Первый RED выявил ожидаемое повторное перечисление и две ошибки собственных ожиданий фикстуры: missing index имеет ключ `null`, а `Path` нормализует повторный разделитель. После исправления фикстуры чистый RED содержал один ожидаемый отказ: семь перечислений Журнала вместо одного. Первый прогон после правки обнаружил ещё одну ошибку фикстуры: повторная запись существующего файла не меняет состав каталога. Каждый случай теперь создаёт отдельную новую запись. Итоговый GREEN: 11/11. Прежний адресный набор фасада: 54/54 за 185,027 с по unittest; длительность его процесса в v4 — 185,240 с.

Первый профиль закрыто отказал до замеров из-за ошибочно переданного агентом SHA аргумента. Исправленный запуск использовал независимо прочитанный SHA и завершился успешно; первоначальный отказ не удалён. Предварительный start с календарём вместо суффикса `--label` отказал без записи; исправленный штатный start выполнен за 0,965 с. Генератор входов до start отказал из-за отсутствующей пары; после start исходный D_ACT отказал из-за единственной стадии профиля. Эти приватные исходы сохранены, координатору передана необходимость двух стадий и одной адресной команды в исправленном D_ACT. Предметная область и C не расширены.

## Парный профиль

[Точный JSON](парный-профиль.json) имеет raw SHA `679d2083692ba58185aae8d6101d0947ecd6b04dc20433980ec1a996bc78a5dc`. Исходник наблюдателя: `555503cab5978d99c2d8a6793eda290f026c04bba4e7e6eda4f12835a0b2aace`. A извлечён из C, B — сохранённый до измерения файл0400 с raw SHA `fa79e2ff35ec91ffe25cba51da35939bf1e5fb82936158fa5ad2b556cc47ecec`. OID B до коммита неизвестен; профиль содержит `коммит_кандидата: null` и впоследствии не переписывается. Поздняя сверка B/blob сохраняется отдельно.

Двенадцать свежих процессов в трёх блоках A–B–B–A выполнили по три снимка Журнала и два recency: всего 60. Общие импортированные исходники сверены по SHA; pinned Git-вход из 300 сессий, все SHA/режимы/чтения/байты и HEAD/ref/сырой индекс/метаданные ФС совпали до и после каждого снимка. Файлы входа не изменялись. Система, интерпретатор и наблюдаемая конкуренция процессов приведены в JSON без приватных путей и PID.

| Журнал | 697,636 мс | 123,356 мс | 5,66 | 601 | 27 129 |
| Recency | 759,870 мс | 181,940 мс | 4,18 | 603 | 27 184 |

Медианы вложенного подтверждения путей: Журнал 641,697 → 67,548 мс; recency 646,689 → 67,342 мс. В каждом неизменном снимке каталог Журнала перечислен 601 раз в A и один раз в B. Все каталоги перечислены 1802 → 302 раза для Журнала и 1805 → 303 для recency. Чтения и SHA — по одному на каждый существующий файл в обоих вариантах. Стабильность результатов и существенное уменьшение времени подтверждают полезность локального кэша на этой фикстуре.

Внешний процесс профиля занял 45,720 с и включает подготовку, импорт и проверочные manifest-чтения. Таблица измеряет только снимки; вложенные времена не складываются с их общим временем. Подготовка, импорт, сверки, запись и агрегация исключены из таймеров снимка. Предсверки прогревают вход, кэш ОС не сбрасывается. Физический I/O и ускорение всего фасада остаются неизвестными; эта фикстура не доказывает ускорения всех реальных деревьев.

## Сохранённая граница ROOT

При восстановлении повторно вызван штатный `остаток --без-записи` с явным закреплённым S31 и актуальным кэшем. Граница LF-префикса 6 705 735 475 байтов, SHA `499ac90d671ca6db03c1262990b60f19618c449ad4b6126b8349dc5aabe48871`: 982 сообщения, 982 остатка, три неоднозначных экземпляра, непроверенный хвост0, код3. Первая попытка живого ROOT JSONL ранее остановлена тайм-аутом; её полный неуспешный захват сохранён приватно. Сырые ROOT/native JSONL, кэши, локальные пути и capture остаются вне Git. Координатор отдельно учитывает поздний человеческий ввод. Учёт и выполнение полного ROOT-объёма этим этапом не доказаны.

Полный smoke-check и братиславская проекция в этой ограниченной `.7` не выполнены; существующая генерация `Proyekcii/**` сохраняет прежнюю дату и не выдаётся за обновлённую. Контрольная точка, точный push/readback и отдельный PR в `fuma` сохраняют результат; интеграция принадлежит принимающему координатору.
