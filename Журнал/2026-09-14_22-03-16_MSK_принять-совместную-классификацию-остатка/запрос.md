Это новый этап той же корневой задачи после опубликованной контрольной точки `28ae7e3425af487256c49fda858c4b8884349870`, дерево `4ca13ad4c94b0e3de397ece53eca08cf524376ef`, ref `refs/heads/codex/рабочий-контекст-0165-01a0930d`. Дерево было чистым; корень остаётся единственным писателем, дети выполняют только чтение.

Четыре управляющие команды дословно перенесены из [предыдущего этапа](../2026-09-14_21-11-44_MSK_сверить-общую-границу-приёмки/запрос.md); это продолжение, не четыре новых сообщения человека. Позднее сообщение 0173 о конечной Python-классификации извлечено из неизменённого завершённого префикса JSONL корневой задачи. Частный журнал и курсор остаются вне checkout.

## Принятое решение

До получения окончательного C/T задачи 0173 выполнить независимую read-only-сверку трёх сохранённых свидетельств Python-дельты. Грязное рабочее дерево исполнителя не объединяется и не объявляется принятым. После точной поставки нужны совместная классификация, согласованное обновление снимка и один полный профиль с новой проекцией по прежней команде координатора. До этого отдельное сканирование всей реплики и повтор независимых наборов не выполняются.

После предыдущего коммита два предварительных read-only-вызова guard были собраны с неверными входами: сначала неизвестное имя параметра UUID, затем отсутствие явного пути исторического плана. Ни один не давал разрешения завершения. Штатный вызов с `--codex-thread-id` и точным `--план` вернул код 0 и решение ожидать только совместную приёмку. Старый отчёт не дополняется задним числом; исходные терминальные ответы сохранены в частном JSONL, эти отказы не являются новыми проверками Swift.
