## Решения и ограничения

- Переход v1 → v2 сохраняет исходные 19,6 и 48,3 МБ в достижимых Git-объектах с проверяемыми OID файлов, размерами и SHA-256, вместо копирования событий в новый файл. Заголовок результата компактен; будущие события продолжают локальную проверяемую цепочку.
- Потоковое SHA-256 устранило квадратичное повторное сложение префикса истории; пакет сверяет общую границу JSONL один раз, но проверяет свидетельства каждого решения отдельно.
- При первом адресном запуске этой папки я не указал `--приёмочные-раунды`, поэтому журнал уже содержит v3. Переписывать или удалять записи ради перехода на v4 нельзя; штатный создатель коммита требует v4. Контрольная точка будет зафиксирована действующим явным допуском связности и ручным Git-вызовом с проверкой полей; новый этап после неё получит пустую v4-историю для штатного создателя коммита. Для предотвращения повторения нужен ранний выбор v4 до первого запуска постоянной сессии.
- Сверка связанных инструкций выполнена в [руководстве по обработке сообщений](../../Инструменты/fum-svyaznostj-rabochej-sessii/обработка-сообщений.md). Корневой README не описывает этот внутренний API и в этом срезе не меняется. Полная документационная и проекционная приёмка нужна на объединённом дереве.
- Незавершённый остаток: настоящий merge `[fuma, codex/derived-pipeline-v1]`, разрешение непересекающихся документов и истории, финальные проверки, коммит и точный push в `fuma`; `master` остаётся отдельной границей.
