## Решения и ограничения

Передача по API XML-экранирует теги блока; одно декодирование даёт точный исходный prompt, что отдельно подтверждено сравнением и обратным escape с quote=False. Старые буквальные фикстуры требуют сохранения совместимости, а буквальные сущности внутри исходного текста — отсутствия повторного декодирования.

Независимая рецензия отклонила первый GREEN 37/37: эвристика обратного экранирования меняла буквальный текст &lt;тег&gt;. Отдельная регрессия воспроизвела дефект. Выбор формата теперь явный: общий читатель и v1 — буквальный, дочернее назначение, ранняя квитанция с поручением и координатор v2 — xml-v1. Повторная рецензия блокирующих замечаний не нашла.

Следующий набор дал 52 успешных теста из 53. Единственный отказ — устаревшее ожидание текста ошибки в отрицательном тесте v1: новый код отклоняет его раньше, на неканоническом XML. Ожидание исправлено, добавлена отдельная проверка отказа буквального v2; затем выполнен итоговый набор на завершённом коде.

После успеха 56 тестов составная проверка отказала на двух полях Журнала: заголовке столбца профиля и отсутствующей точной ссылке на навык времени. Исправлены только документационные поля. Исполняемый код и тесты не менялись; повторяется узкая проверка полей, свидетельств профиля, свежести и индекса. Полный адресный набор повторно не запускается.

Штатного завершения неудачного запуска и замены его поколения пока нет. Первый настоящий ответ API сохранён; второй допуск не выдаётся за выполненный create_thread и не получает фиктивного ответа. Исходный ref остаётся на C; исправления не сдвигают его.

Первый вызов генератора папки получил неполный session-stem без суффикса и был отклонён до записи Журнала. Исправлен вход штатной команды; новая ветка к тому времени уже создана и не создавалась повторно.

Первый запуск тестовой фикстуры остановлен защитой символических ссылок macOS во временном пути. Путь фикстуры приведён к физическому; этот исход не считается RED транспортного дефекта.

Дополнительная составная проверка сначала получила пустую таблицу детей: параметр наблюдать=False фикстуры исключает их создание. Исправлена подготовка самой фикстуры: реальное экранирование теперь задаётся при создании источника до раннего подтверждения. Этот исход не является новым производственным дефектом.
