# Граница подключения хостового наблюдателя

Это проектируемое подключение в продолжение [исходного запроса](../запрос.md). Оно ещё не исполнено и не подтверждает готовность VM.

## Низкоуровневой договор

Дочерний результат имеет public `СнимокPythonНаблюдателя: Codable, Equatable`: путь, реализация, версия, контрольнаяСумма (CodingKeys sha256), возможности. Его `проверить()` читает закреплённый физический executable без нового процесса. `КонтекстНаблюдения` содержит заимствованные FD каталога и уже удержанного flock, физический cwd, UUID родителя и проверки, SHA происхождения, точные Data наблюдателя и снимок Python. Контекст не Codable и не владеет FD.

`НаблюдаемыйПроцесс.выполнить` принимает программу и argv, обязательный контекст, предел времени, точное окружение, Data stdin и предел вывода. Возвращается прежний `РезультатПроцесса`. Корень подключает прежние точки вызова к обязательному контексту, формирует наследованное окружение отдельно и передаёт его как окончательный вход; низкий уровень ничего не добавляет неявно.

Наблюдатель запускается непосредственно закреплённым CPython с семью различными FD. Единственный life writer остаётся в Swift. До запуска долговечно сохраняются точные вход и отправка; результат требует обеих проверенных квитанций, а не одного exit 0. При исключении Swift закрывает writer и ожидает своего наблюдателя; чужие либо исторические PID не сигналятся.

## Выбор источников исполнения

Обычная поставка читается рядом с физическим исполняемым файлом. `поставка.json` имеет схему fum.поставка-VM.1, `вход.python` и инвентарь файлов. Проверяются привязка фактического binary и загруженного ресурса наблюдателя, точный снимок Python и его неизменность на границах команды. Повреждённая имеющаяся поставка не позволяет переключиться на PATH.

Для dev/test-вызова нужен явно переданный снимок fum.python-наблюдателя.1. Реализованный `собрать.py --описать-python` описывает собственный текущий интерпретатор и печатает канонические байты без поиска Swift, создания каталога и второго Python; это подтверждено [пятью проверками](TDD-снимка-python.json) и [профилем](профиль-снимка-python.json). Тестовый запускатель сможет сохранить эти байты вне Git и передать путь через явный `FUM_СНИМОК_ПИТОНА`. Этот параметр содержит путь к полной оболочке схемы, а не к отдельно извлечённому объекту python. Приём снимка Swift пока не реализован. Это объявленная граница доверия внешней CPython-установке; хэш всей стандартной библиотеки не заявляется.

Имеющийся `поставка.json` имеет приоритет над переменной среды: только ENOENT допускает явный dev-снимок. Нечитаемость, symlink и повреждение поставки запрещают обход через окружение. Фактические URL и Data загруженного наблюдателя должны принадлежать соседнему bundle и совпадать с `файлы` и `вход.исходники["Sources/ЯдроМашины/Ресурсы/наблюдатель.py"]`. Бинарник сверяется с `файлы["машина"]`; сам `поставка.json` в инвентарь не входит. Оба размещения ресурса — корень bundle и `Contents/Resources` — уже поддержаны упаковщиком.

Swift чтением сверяет физический обычный исполняемый файл Python, одну жёсткую ссылку, предел 64 MiB и SHA, но не требует личных прав 0600 или владельца VM. Реализация, версия и возможности остаются полями исходного снимка; без нового процесса они не объявляются заново наблюдёнными фактами. Для выбора runtime не нужны checkout, Swift, SDK или пересборка инвентаря исходников.

## Владение и точки подключения

| Место | Контекст и граница |
| --- | --- |
| Подготовка VM | Runtime разрешается перед созданием нового состояния подготовки. Команды метрик получают удержанные FD собственного Хранилища и текущее измерение. Само конструирование объекта подготовки не должно запускать Python. |
| Готовность и экспорт | Контекст удерживающей службу VM; проверка идентичности предшествует первой отправке, включая восстановление старой истории. |
| Восстановление SSH | После проверки runtime создаётся отдельная личная попытка вне Git: 0700, маркер UUID/VM/плана и собственный flock 0600. Замок работающей VM не захватывается. Две SSH-команды используют этот контекст. |
| Интерактивный SSH | Ограниченное получение публичных ключей использует личную попытку до execv. Сам интерактивный SSH сохраняет прежний жизненный цикл. |
| План и снимок хоста | Ресурсы и версия ОС читаются Foundation/Darwin без subprocess. Присутствие CLI определяется без их запуска, неизвестные версии так и обозначаются. Обогащение версиями возможно только после получения контекста. |
| Состояние и остановка | Не требуют пригодной SSH-идентичности или запуска Python. |

Завершённые и незавершённые квитанции собственных попыток сохраняются вне Git. План VM, массив пакетов qemu/gnupg, существующий паспорт и формат EFI этим подключением не меняются. CLI не получает скрытые тестовые режимы отказов.

## Проверяемый остаток

Нужны компиляция, настоящий RED/реализация/GREEN, смерть только Swift с удержанием замка до очистки, срок/переполнение и строгая проверка квитанций. Отдельно проверяются физический runtime, read-only план, отсутствие конкуренции с VM-lock и настоящий ssh-keygen на stdin из личного обычного файла. Полный цикл новой поставки и Linux VM остаётся последующим доказательством.
