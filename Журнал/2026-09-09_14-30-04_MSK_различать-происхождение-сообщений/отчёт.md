# Отчёт 2026-09-09 14:30:04 MSK - Различать происхождение сообщений

Реализован небольшой чистый классификатор происхождения одного сырого сообщения с четырьмя исходами. Служебное «остановись» внутри hook не становится человеческой остановкой, а буквальная разметка при полной пользовательской аннотации остаётся UserInput. Модуль не подключён к приватному архивёру и не запускает native hooks. Guard v2 сохранён без изменений.

## Решение и граница передачи

Публичная функция — `классифицировать_сообщение(сообщение) -> str`; точные результаты: `человек`, `служебный hook`, `служебный контекст`, `неоднозначный`. До классификации проверяются `type=message`, `role=user`, отсутствие фазы либо `phase=null` и корректность каждого элемента `content`. Только полный позиционно согласованный набор `user.text/image/audio` даёт «человек». Это свидетельство runtime UserInput, не удостоверение физической личности или независимой подлинности аннотации.

При отсутствии `content_item_kinds` допускается только отдельный полный `input_text` XML hook на каждой позиции. Явное `content_item_kinds=null`, частичные, неизвестные и смешанные виды закрываются неоднозначностью; дополнительные passthrough-поля не доказывают происхождение. XML-фрагменты разбираются Expat без DTD, сущностей внешнего происхождения, вложенности, комментариев, инструкций обработки, CDATA, BOM и окружающего текста. Исходный объект не меняется; декодированные значения парсера используются только для проверки формы и не возвращаются взамен raw.

Три известных служебных вида принимаются только с `input_text`. Эвристик по префиксу старой оболочки нет. Пределы: 256 фрагментов, 262144 Unicode-символа на XML-фрагмент, 1048576 суммарно, 1024 символа идентификатора; глубина — один корневой элемент. Аннотированный пользовательский текст не проходит XML-разбор и не ограничивается его размером. Медиа и URL остаются непрозрачными строками.

Корень отдельно внедрит API до нормализующего runtime-декодера: pinned Rust `DefaultOnError` способен заменить повреждённые kinds отсутствием, после чего исходное повреждение уже нельзя восстановить. Сырой журнал и повторные сообщения сохраняет вызывающий слой. Тест минимального фильтра экспортирует только `response_item` и не считает typed `HookPrompt` второй копией; повторяемый `hook_run_id` не используется для удаления отдельных raw-сообщений. Пустой hook-текст — допустимая форма общего builder, но не доказательство пригодного Stop block. Полнота native-истории не заявляется.

## Профиль классификации

Восемь точных синтетических входов дают по два случая каждой категории. Малый набор повторяется 100 раз (800 вызовов), увеличенный — 10000 раз (80000 вызовов). После отдельного прогрева выполнено по пять замеров; измерены только чистая классификация, цикл и счётчики, без импорта и сериализации результата. Python 3.14.7, Expat 2.7.4, сборщик мусора включён; общий хост не изолирован от других задач.

| Набор          | Исходная медиана | Повторная медиана | Проверенный состав исходов                    |
| -------------- | ---------------- | ----------------- | -------------------------------------------- |
| 800 вызовов    | 2,041542 мс      | 2,131000 мс       | По 200 каждой из четырёх категорий            |
| 80000 вызовов  | 198,508417 мс    | 211,975125 мс     | По 20000 каждой из четырёх категорий          |

Пик дополнительной памяти отдельного прогона 800 вызовов — 10214 байт в обоих профилях. Код обоих запусков имеет SHA-256 `a3fdf3e04d9cb023489b60ecabe87428c652cfca92b6336f99a66bb55122fd23`; точные входы, их хэши, хэш сценария и все замеры сохранены в материалах. Исходный критерий предлагал оптимизацию при медиане увеличенного набора выше 2 с, росте более 150 раз на стократном входе либо пике выше 1 МиБ. Ни один порог не достигнут; рост близок к линейному. Решение — сохранить алгоритм. Разница повторного замера не выдаётся за ускорение или деградацию на контролируемом стенде.

Прямой исторический snapshot-check № 11 честно завершился отказом: сохранённый старый снимок содержит 43091 объявление, наблюдаемый — 43132. Эта проверка включается только в явный широкий профиль smoke, а не в стандартный документационный контур.
- Последующая локализация № 13 показала ноль латинских объявлений во всех трёх новых исходниках. [Проверка дельты относительно базы](материалы/неизменность-объявлений.json) доказала нулевой вклад всех изменённых старых Markdown до и после и новых исходников. Наблюдаемый инвентарь `sha256:f88df28720bc3cf99b235ce3d3728c1a6495ef6cd81016f728624603343b6baa` уже принадлежит базовому состоянию. Старый snapshot не обновлялся; неуспех не скрыт и передан корню как внеобластная граница широкого профиля.
- Публикационные проверки № 9 и № 15 прошли без изменений `policy.json`; последняя охватила завершённые код, описания и оба профиля. Все 15 машинных записей терминальны. Субагент проверял только чтением; проверки за пределами обёртки в охваченном этапе не запускал.

Иных сообщений — ноль, текущий запрос отсутствует среди ошибок. После фиксации этого результата выполняется только повторное замыкание, без повторного полного тестового контура. Его время отдельно не измерено и в машинную сумму не подставляется.

## Решения и ограничения

- Техническое поручение получено от корневой задачи, не от нового физического автора пользовательской команды. Ответ исполнителя: поручение принято в назначенном дереве, дополнительная граница личности и native-доказательств соблюдена; scope ограничен новым модулем и его доказательствами. Старые исходные команды не импортированы повторно в корневой приватный архив. Полный JSONL корня не читался: это прямо исключённая область данной дочерней работы.
- Контрольный коммит оставляет v4-журнал открытым с точным предпросмотром. Стандартный smoke и пересборку проекции выполняет принимающий корень на интегрированном снимке. Исходное поколение проекции сохранено от `7a5f77c0e00b291338c737d227119975857155af`, его план — `sha256:448211f8b8fccef2c8c4f471cb0c9b62bcd9dcc431352f5a8de33b03803d912f`, исходный инвентарь — `sha256:27d0770a13d4af0a0f4c9228c89ba597a26050ea1e1f805f3097d53e603e13dc`. Оно отстаёт от новых файлов; полная приёмка не заявляется.
- Прежняя узкая неприменимость 282 унаследованных ссылок на отсутствующий игнорируемый `.obsidian/graph.json` разрешена корнем повторно. Файл не создавался/не копировался, проверка связности не изменялась; после точного staging и предпросмотра допускается только этот фактический класс ошибок, любые другие сообщения требуют устранения или решения корня.
- Guard v2, его контракт и прежние тесты, правила, реестры, карточки, Git-конфигурация, Trust и чужие деревья не менялись. Предыдущий запрос изменён только по навигации и recency, прежний отчёт и машинные записи не затронуты. После обычного точного push и передачи API, OID, RED/GREEN и профиля запись прекращается по границе поручения; интеграция архивёра остаётся корню.
