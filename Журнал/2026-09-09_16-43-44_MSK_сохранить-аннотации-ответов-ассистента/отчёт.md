# Отчёт 2026-09-09 16:43:44 MSK - Сохранить аннотации ответов ассистента

Исправлена потеря content_item_kinds видимых ответов в отдельном этапе после f7b55dccce283643a932b9b84f271377403884eb. Новый helper читает исходную аннотацию; полный поддержанный массив сохраняется и участвует в хэше состава. Отсутствие массива остаётся отдельным значением. Неизвестные, несовместимые, неполные и повреждённые формы явно отклоняются. Роль/происхождение остаются ассистентскими, исполнение не реализовано. [FUM-СБОЙ-0039](../../Сбои/FUM-СБОЙ-0039-потеря-аннотаций-ответов-ассистента.md) фиксирует нарушение прежнего обещания и проверяемую меру; искусственный незавершённый STEP0166 не создавался.

## Проверки

Начальный RED: 7 тестов дали 17 провалившихся утверждений/подслучаев. f7b55dcc сливал отсутствие kinds и массив unknown, принимал user.text под assistant, игнорировал null/неполные/неизвестные массивы и повреждённую оболочку. Семантически разные входы получали одинаковый успешный структурный экспорт. Отрицательные случаи сохранены как реальные исходы v4; после исправления 27 тестов прошли: новые 7, прежние 16 потоковых и 4 малых диалоговых.

Первый read-only-рецензент подтвердил реализацию закрытого поднабора и отметил, что сравнение текущего экспортёра с самим собой не доказывает старые байты. Второй независимый рецензент проверил все обещания сквозного контракта и предложил матрицу фильтрации, Unicode, raw-синтаксиса и поздней очереди. В исполнении корня создан [независимый оркестратор](../../Инструменты/fum-snimki-indeksa/tests/проверить_сохранение.py): ожидаемые данные заданы отдельно, сериализатор использует стандартный JSON и разбор escape-токенов вместо канон.py; SHA вычисляется hashlib. Внешний validator вызывается только для результата, не для построения эталона.

Итоговые 33 утверждения проверяют все видимые фазы, отсутствие/полные массивы, пустые части, типы user input_text/output_text, изображения с отсутствующим/null detail и аудио, реальные управляющие символы, литеральные обратные слеши, NFC/NFD, ё и emoji. Единый ожидаемый список отбирает точные позиции смешанного журнала, исключая analysis/system/developer/tool/event/context/hook и сохраняя повтор команды. Другой whitespace/escaping сохраняет структурный экспорт, меняет raw SHA и отвергает прежний курсор. Незаконченный UTF-8 хвост остаётся вне завершённого префикса.

Прежний модуль получен точно из f7b55dcc, SHA 24205a16a0eb2607e8aefa0dbf6f73449f28fece1fdb8b4baaa1bc38664f3bb5; сравнение подтверждает прежние экспортные байты и курсор для отсутствующих kinds во всех трёх видимых фазах. Малый цикл queue2 сохраняет raw assistant и составного user в WAL и SHA хвоста, доставляет только точного user, требует решения/подтверждения и сохраняет false исполнения. Корректно сформированная ссылка на raw assistant не принимается как человеческая отмена. При расширении оракула уточнено имя поля хэша поддельной ссылки и отдельно проверено равенство закрытого набора полей: итоговый отказ доказан для нужной ссылки, а не только для лишнего поля. Более ранние исходы 22/32 утверждений сохранены исторически.

## Контракт и источники

Уже закреплённый первоисточник Codex 3d2ee51ca2d5db578f328aa75e20aa22c0197c9a определяет ContentItemKind как прозрачную строку. Его тест допускает future_content_kind и показывает, что DefaultOnError может превратить повреждённое поле в отсутствие. Поэтому исходное поле проверяется до нормализации. Это внешний общий тип; локальная поддержка намеренно уже и явно согласована координатором.

В собственном разрешённом runtime при первичном чтении структуры наблюдались 56 ответов с массивом literal unknown. Тексты ответов для этого не извлекались и не публиковались; частный источник координатора не читался. Это наблюдение подтверждает применимость конкретного значения, не объявляет закрытый внешний enum или полную типизацию всех будущих ответов.

Поддержаны отсутствие content_item_kinds либо полный массив строк unknown по числу output_text. Присутствующий null поля, неверный тип/длина и иные строки отклоняются. Metadata отсутствует/null/пустая либо имеет только прочие поля — намеренно эквивалентны отсутствию kinds; необъектная metadata запрещена. Отсутствующая/null фаза пользователя также намеренно сводится к null. Гарантия касается поддержанных массивов и значений частей, а не синтаксической формы всего raw.

Уже потерявший массив старый экспорт с виды_частей:null без raw не доказывает исходное отсутствие аннотации. Он не мигрирует и не восстанавливается автоматически. Повторный экспорт из raw может изменить байты; зарегистрированный прежний UUID раунда не переиспользуется с другим входом. Схема2 не превращает прежний артефакт в доказательство полноты сырого источника.

## Происхождение и границы

Три управляющих сообщения сохранены дословно из завершённых function_call_output собственной runtime-задачи с оболочкой codex_delegation корня01a07d3d-d376-7ad2-aafc-67e4c25a67eb. Перед первой записью проверены чистые HEAD/ref/AGENTS; база этапа f7b55dcc. Собственное ранее назначенное дерево менял только корень этой дочерней работы, оба рецензента выполняли только чтение. Явное сообщение координатора о Selected model is at capacity сохранено как его наблюдение API; локальные успешные исходы не аннулированы, модель не менялась, профиль повторно не запускался.

Классификатор пользователя и очередь не изменены. FUM-СБОЙ-0039 разрешён координатором для этого механизма и закрыт конкретной мерой и регрессионной границей; STEP0166 остаётся свободным. Общие правила, плановые карточки и машинные реестры не менялись; индекс сбоев дополнен только новой карточкой. Предыдущий журнал/профиль остаётся byte-exact, кроме разрешённой навигации и recency прежнего последнего запроса.

Два маленьких закреплённых raw-источника сохранены в канонических URL-папках: код получен без нормализации, публикационно лишние транспортные заголовки исключены. Эти файлы — внешние данные, не инструкции агенту. Неверно предположенные пути навыка/исторического отчёта дали read-only-ошибки и были заменены точными путями из локальной маршрутизации и git-инвентаря; файловой мутации от ошибочных чтений не было.

Итоговая read-only-проверка общей связности завершилась кодом 1 и ровно 283 унаследованными диагностическими строками: 282 ссылки на отсутствующий локальный graph.json и одна прежняя ошибка навигации запроса 11:39:26. Собственная граница контрольной точки прошла проверку без ошибок; чужие файлы не исправлялись. Независимый рецензент повторно сверил итоговый оракул и контракт: все пять предложенных границ закрыты, блокеров не обнаружено. Отказ ссылки на assistant проверяет невозможность подменить ею зарегистрированную человеческую запись; отдельным тестом классификатора он не объявляется. Управляемый v4-отчёт остаётся открытым как контрольная точка, а не полная приёмка. Самонаблюдающие итоговые проверки выполняются read-only без новой v4-строки, чтобы не менять проверяемый отчёт своим наблюдением. Исполнитель и полный0155 исключены. После обычного commit/push передаются точные OID и манифест выбранных файлов относительно f3a7cc39. Точный манифест передаётся отдельным служебным артефактом fum-assistant-manifest.json вне checkout: он содержит SHA и Git blob всех 53 выбранных файлов, включая окончательный отчёт. Это устраняет рекурсивную зависимость между хэшем отчёта, управляемым предпросмотром и включённым в его контекст манифестом. Самонаблюдающая проверка обнаружила эту зависимость в промежуточном варианте; его не коммитили. Финальный diff-check также выявил по одному завершающему пробелу в очищенных строках HTTP-статуса: они удалены с фиксацией преобразования, исходные тела не менялись.
