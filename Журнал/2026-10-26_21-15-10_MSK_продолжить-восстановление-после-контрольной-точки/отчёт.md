# Отчёт 2026-10-26 21:15:10 MSK - Продолжить восстановление после контрольной точки

Контрольная точка `d01c27126bdd9b0c025d4aa04a7d1d186f25a0be` независимо
прочитана и доставлена в собственный remote ref. Первая попытка была отклонена
на удалённом `unpack`, после чего `ls-remote` подтвердил сохранение parent
`94b5266…`. Только после независимой работы и нового readback один exact retry
завершился кодом `0`; заключительный `ls-remote` равен `d01c271…`.

Позднее уточнение ROOT исправило контракт Codex identity gate: ожидаемые
model/effort выбираются из явно проверенного снимка конкретного этапа, а не
обязательно из последнего UI-наблюдения. Допустима любая подтверждённая модель;
пустой, чужой или подменённый источник закрыто отклоняется. Уточнение и новый
случай утраченного `25fe/FUM` направляются тому же materializer без второго
писателя, нового продукта или переписывания опубликованной истории.

Materializer затем опубликовал checkpoint `6b7c72d21899874a6ab48d85250ae1e698eb8da8`:
raw commit, tree `4975873810f3542d3d7aae6ba0aeae00a5306ae4`, parent
`2a81742d9c8d44683ac5971b8bcdd17b7315a25c` и exact remote ref независимо
совпали. Его 19 файлов сохраняют Package bridge, две постановки, точки
включения и журнал проверок; product tests и GREEN не заявлены. Это
поставленный промежуточный материал: сам checkpoint не доказывает результаты
observer/packetexecutor, реализованный общий CLI или identity gate.

Снимок состояний `2026-10-26T18:22:34Z` показал: sync продолжает работу в
грязном собственном `9d58/FUM` без нового checkpoint; observer начал новый
этап в чистом `3c8f/FUM`; packetexecutor ACK-нул прежние UUID/ref/HEAD и grant,
но ещё не выдал реализацию. Auditor опубликовал `eb341ada…`; raw readback
подтвердил неправильный Author `FUM Писатель`, поэтому этот commit добавлен
как отрицательный экземпляр существующего identity defect, без переписывания.

Bounded-инвентарь Python отделил доказанные режимы от недоказанных обобщений.
Чрезмерно медленными подтверждены полный сканер машинных путей и чтение
огромного ROOT JSONL; функционально дефектны старый Git Creator и пообъектный
GitHub CLI. Адресный сканер работает, RAW и typed Git уже имеют владельцев.
Физическое удаление отложено до принятого Swift/FUMA-эквивалента. Read-only-
аудит не нашёл доступных Swift/FUMA-писателей ни для полного сканера, ни для
STEP-0237; ROOT получил точные границы двух новых ACT без возобновления
закрытых Python-ветвей.

Полный сканер закреплён на commit `90ebaf9a…`, tree `db910682…`, blob
`de47c8c…`, SHA-256 `a32eb5ca…`; его CLI имеет только `--repo-root` и
`--policy`. Адресная staged/index проверка — inline-обвязка того же модуля,
а не отдельная версия CLI. Для STEP-0237 локальный и live remote кандидат
нового ref отсутствуют; это доказывает свободный адрес, но не созданный узел.

ROOT также указал существующий task-local legacy author guard. Private path
не публикуется; независимо совпали размер 3664 байта и SHA-256 `84e162cc…`.
Guard проверяет лишь последнее полное native-наблюдение и один raw author
header. Он сохранён как корпус поведения, но не покрывает body, ROOT UUID,
email, committer, tree, parents, ref/remote и не называется Swift-внедрением.

Identity gate связан с открытой [Issue 363](https://github.com/fum-lab/fum/issues/363)
и проверенным [комментарием 6424283501](https://github.com/fum-lab/fum/issues/363#issuecomment-6424283501).
[Issue 271](https://github.com/fum-lab/fum/issues/271) корректно закрыта через
PR 279 и не переоткрывается; [Issue 284](https://github.com/fum-lab/fum/issues/284)
остаётся отдельной зависимостью наблюдения модели. Дублирующая issue не
создаётся, а caller identity validator не выдаётся за доказательство живого
model/effort.

ROOT добавил различающий identity fixture: правильный `user.name` вместе с
унаследованным неверным `GIT_AUTHOR_NAME`, чтение `git var GIT_AUTHOR_IDENT` в
том же ограниченном process env и raw header. Наследованный env пока лишь
гипотеза причины `eb341ada…`. Новый адаптер должен задавать полный Author
адресно, не печатать секретные env и не оставлять env leakage.

В чужом sync-worktree read-only обнаружен первый untracked Swift parser
`adapter-git-avtor-commita.swift`: 43 строки, SHA-256 `2707821d2e10…`.
Связанный `proverki.swift` уже содержит 1639 строк и случаи raw/default
Author, но дерево грязное. Независимое [read-only-ревью](материалы/ревью-identity-gate.json)
показало пять незакрытых границ: вызов только из private-fixture тестов,
явную передачу лишь `GIT_AUTHOR_NAME` вместо полного scoped Author/Committer,
самодекларируемый native-stage source и отсутствие real-process inherited-name
distinguisher, а также зависимость commit argv от local `commit.cleanup` из-за
отсутствия `--cleanup=verbatim`. ROOT запретил второго parser-writer и
потребовал декомпозицию тестов без дорогого переписывания. Первый commit,
source pins, реальные RED/GREEN и подключение к ordinary/merge/new push path
не доказаны.
Sync-владелец отдельно исправляет различимость отказов: неверный body должен
сохранять правильный Author, а неверный Author — правильный body, иначе ранний
author guard маскирует проверяемую причину.

ROOT повторно закрепил исходное Swift/FUMA-поручение и потребовал довести тот
же путь через materializer → sync до ordinary/merge private-Git сценариев,
raw commit readback и запрета push при неверных Author/body. Маршрут передан
materializer; второй parser-writer не создан. Последний ход sync-владельца
завершился без Swift-запуска и без commit: ветка осталась на `3f286543…`,
дерево dirty. Materializer затем установил фактическую координацию: последним
holder был сам sync-владелец, release ACK не было и ROOT слот не принимал.
Тому же владельцу адресно продлён слот под приоритетный малый identity-набор;
ожидаются точные run/outcome и ближайший commit. Green и delivery не заявлены.

Для packetexecutor materializer локально подготовил grant v2 с раздельными
closed 34-pin maps; обе карты независимо совпали, canonical target SHA
`d511f6fb…` подтверждён. Checkpoint этой коррекции ещё не передан, поэтому
leaf driver не запущен и реализация packetexecutor не заявляется.

`25fe/FUM` восстановлен тем же UUID как tracked-only positive fixture:

## Проверки

- После первой неуспешной попытки независимый read-only-аудит подтвердил
  локальный commit, чистый checkout и несовпадение с live remote ref; это не
  доказывает причину серверного отказа. Поздний exact retry и заключительный
  remote readback отдельно подтвердили доставку.
- Новая пара Журнала начата только после повторного preflight и использует тот
  же `Codex-Thread-ID`.
- История модели перенесена штатным инструментом с полной сверкой прежнего
  префикса; последнее наблюдение — `gpt-5.6-sol`, `ultra`.
- Raw Git-объект materializer checkpoint прочитан независимо: Author равен
  `FUM Codex [gpt-6.1-sol; effort=ultra]`, committer — `FUM <fum@local>`,
  дерево и parent совпадают с сообщением владельца. Remote ref указывает на
  тот же `6b7c72d…`; состав содержит ровно 19 изменённых путей.
- Остаток human-сообщений пуст, но доступные работы прежнего плана остаются;
  отсутствие остатка диалога не означает завершения подузлов.
- Новый полный план синтаксически проверен и распознан штатным continuation
  reader: решение — `продолжить`; delta-файл остаётся пояснением, а не
  отдельным недоказанным механизмом наложения.
- Первый повтор reader после добавления двух Python-замен честно отказал на
  неподдерживаемом состоянии `ожидает-ROOT-назначения`; оба пункта переведены
  в каноническое `ожидает-ответа`, исправленный повтор вернул `продолжить` и
  сохранил `УНИВЕРСАЛЬНАЯ-ДОСТАВКА` следующей доступной работой.
- Materializer получил actual leaf ACK observer и packetexecutor. Observer
  только подготовил `--no-ff --no-commit` merge, а packetexecutor сохранил
  source-pinned c6af 34 pins и отдельные current-source hashes; ни merge, ни
  GREEN, ни application readback ещё не доказаны.
- Полный smoke-check, сборка Swift/FUMA и полный session coherence в этом
  открытом срезе не запускались.

## Решения и ограничения

- `d01c271…` — доставленная контрольная точка собственной ветки, но не
  ROOT-приёмка, fullPUB, интеграция или завершение задачи.
- Expected identity валидатора связывается с независимо выбранным и проверенным
  источником этапа. Старый достоверный снимок проходит со своим Author даже при
  новом текущем UI; смена UI не разрешает переписывать автора.
- Whitelist семейств моделей запрещён: любая подтверждённая модель допустима.
  Пустой/неизвестный источник, чужой snapshot, подмена и default
  `FUM Писатель` закрыто отклоняются без fallback.
- Случай `25fe/FUM` добавляется к тому же tracked-only materializer. UI handoff
  не становится обязательным путём; пользовательский draft не отправляется и
  не удаляется, private/untracked остаётся `unknown`.
- Checkpoint `6b7c72d…` доказывает публикацию ограниченной постановки и точек
  включения. Фактические ACK двух листьев получены позднее, однако их
  commit/result/GREEN, application readback, прошедшие product tests, готовый
  `vosstanovitj-uzel` и внедрённый identity gate ещё не доказаны.
- ACK materializer доказывает маршрут поправки до того же sync-владельца,
  а ROOT подтвердил существующего sync-писателя; это ещё не кодовый checkpoint
  или подключение gate к реальному Git path.
- Auditor `eb341ada…` опубликован и читаем, однако неправильный Author не
  исправляется переписыванием истории; требуется добавочная коррекция.
- Сам Python не признан дефектом. До эквивалентной замены используются
  работающие адресные маршруты; исторические 77 ошибок для 26 путей не
  превращены в недоказанный список удаления.
- ROOT получил оба read-only-аудита Python-замен, но нового чата, UUID,
  worktree, ref, базы или первого checkpoint для полного сканера и STEP-0237
  пока нет. Оба писателя остаются неназначенными.
- Legacy guard допускается как временная работающая защита отдельного Journal,
  но его last-current семантика не заменяет independently selected stage
  snapshot и не разрешает новый zsh/Python путь.
- Восстановление `25fe` доказывает exact tracked Git state и bind собственного
  ref, но не remote-публикацию или восстановление private байтов.
- Pins-аудит подтвердил один точный target drift — `Package.swift`. Source
  provenance c6af/34 pins и target compatibility 9909/33+1 разделены; до
  versioned amendment process count остаётся `0`, wildcard и удаление pin
  запрещены.
- D22 остаётся закрытым. Новый Python-код не добавлялся.
