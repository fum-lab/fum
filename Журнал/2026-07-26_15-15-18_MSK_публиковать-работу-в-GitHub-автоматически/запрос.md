## Результат

Рабочий контракт репозитория изменён так, чтобы каждая обычная сессия с осмысленным коммитом автоматически предпринимала попытку опубликовать свой точный результат в настроенную GitHub-ветку. Публикация следует после атомарного commit+handoff, принимает только `new_head`, полный `branch_ref` и заранее сохранённый credential-free HTTPS push URL, отклоняет применимую Git URL rewrite-конфигурацию, а затем отправляет единственный непринудительный refspec. `finish-clean` ничего не публикует.

В существующую автоматизацию `fum-ocheredj-zadach-git-vetki` добавлена команда `publish`. Она загружается из самого публикуемого коммита, не читает подвижный `HEAD`, отключает локальный pre-push hook и интерактивные запросы терминала и менеджера учётных данных, не обновляет локальные refs и умеет доказать, что более поздний удалённый потомок уже включает прежний коммит. При тайм-ауте команда завершает всю группу транспортных процессов до контрольного чтения удалённой вершины. Расхождение, серверный отказ и неподтверждённый сетевой исход не приводят к force-push, переписыванию истории или возврату FIFO-владения.

Текущая рабочая сессия завершает тот же протокол: после локального атомарного коммита точный полученный object ID должен быть отправлен в `refs/heads/master` GitHub-репозитория `fum-lab/fum`. Поскольку публикация происходит после создания этого файла и самого коммита, её фактический результат сообщается пользователю отдельно и не утверждается внутри ещё не опубликованного снимка.
