# Отчёт 2026-07-26 15:15:18 MSK - Публиковать работу в GitHub автоматически

Рабочие сессии FUM теперь завершаются не только локальным commit+handoff, но и обязательной автоматической попыткой публикации созданного коммита в настроенную GitHub-ветку. Правило охватывает ручные и диспетчерские корневые задачи; no-op-путь `finish-clean` по-прежнему ничего не коммитит и не отправляет.

## Контракт завершения рабочей сессии

Локальная FIFO-транзакция осталась сетенезависимой: она атомарно создаёт коммит, продвигает локальную ветку и снимает владельца очереди. До этой передачи корень сохраняет единственный безопасный push URL. После результата `committed` прежняя задача получает узкое исключение из запрета внешних действий и запускает публикатор из точного `new_head`.

Публикатор принимает только полный commit object, полный `refs/heads/...` и credential-free HTTPS GitHub URL без применимой `url.*.insteadOf` или `url.*.pushInsteadOf` конфигурации. Он отправляет ровно `<new_head>:<branch_ref>`, не читает текущий `HEAD`, не использует remote по имени, отключает локальный pre-push hook и интерактивные запросы терминала и менеджера учётных данных, не передаёт теги и не применяет force. При тайм-ауте вся группа транспортных процессов завершается до контрольного чтения удалённой вершины. После результата публикации прежняя задача окончательно прекращает внешние мутации.

## Безопасность удалённой публикации

Разделение handoff и push оставляет неизбежное неатомарное окно между локальным Git и GitHub, но не расширяет публикуемый результат. Если следующая задача уже продвинула и опубликовала потомка, прежний коммит распознаётся как уже достижимый. Если история разошлась, сервер отклонил запись или сеть оставила неоднозначный результат, локальный коммит сохраняется, очередь не откатывается, а сбой явно сообщается без `pull`, merge, rebase или force-push.

Проверка неизвестного локально удалённого object ID выполняется во временном bare-репозитории с явно пустым каталогом hooks. Общие checkout, индекс, refs и object database после handoff не меняются. Автономные тесты используют локальный bare-remote и внутренний тестовый допуск Git URL rewrite, недоступный из CLI, поэтому не требуют GitHub, сети или секретов.

## Проверки

- TDD-красная стадия: исходные новые сценарии завершились девятью ожидаемыми assertion-failure, потому что CLI ещё не содержал `publish`.
- TDD-зелёная стадия и последующее усиление по результатам ревью: четырнадцать сценариев post-handoff-публикации прошли за ≈ 11,4 с.
- Итоговый полный набор автоматизации очереди прошёл 49 из 49 тестов за ≈ 55,2 с.
- Recency и граф, связность сессии, `git diff --check` и полный smoke-check из 58 этапов прошли; sandbox-ограничение первого smoke-запуска не было дефектом репозитория, а повтор вне песочницы выявил и позволил исправить пять публикационно небезопасных тестовых/runtime-литералов до итогового зелёного прогона.
