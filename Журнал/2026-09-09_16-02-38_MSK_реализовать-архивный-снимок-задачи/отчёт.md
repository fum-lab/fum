## Проверки

Итоговая регрессия включает 24 XCTest: идентичность и повторный UUID, неполный JSON/UTF-8 хвост, подмену префикса, ограниченные ресурсы и неоднозначные ключи, ошибки записи и подтверждения, SIGKILL во время записи и после fsync, повтор после restart, ложное завершение, перенос модели между ходами, CLI и происхождение архивной цепочки. Все 24 прошли после последнего изменения Swift. Команды и минимальная открытая фикстура включены в README отдельного пакета; из корня поставленного Swift-коммита:

```bash
swift test --package-path Packages/АрхивныйСнимокЗадачи --build-system native --jobs 2
swift build --package-path Packages/АрхивныйСнимокЗадачи --build-system native -c release --jobs 2 --product профиль-архивного-снимка
```

Затем профиль запускается согласно README с путём ещё отсутствующего каталога и размером `105000000`; повторное использование каталога профиля не подменяет первый импорт. Для CLI каталог архива создаёт вызывающий пользователь; команды `импорт` и `replay` принимают явно указанный ожидаемый UUID.

Первый стандартный `swift test` завершился CodeSign-отказом до предметного RED. Применён документированный `--build-system native` из локального help и принятой поставки; защита, подпись и Trust не отключались. Причина NFC/NFD не доказана. Системный сбой остаётся в [FUM-СБОЙ-0038](../../Сбои/FUM-СБОЙ-0038-отказ-CodeSign-стандартного-SwiftPM.md), а мера повторяемой подготовки — в [FUM-STEP-0163](../../Планирование/карточки-шагов/🟡-FUM-STEP-0163-подтвердить-подготовку-SwiftPM-на-macOS.md).

Read-only-ревью выявило некорректное восстановление чужого архивного хвоста, перенос модели между канонически эквивалентными, но побайтно разными ID и слабую проверку выбранных позиций/старой модели при replay. Предметные RED и последующие GREEN сохранены отдельными записями. Проверка NUL-пути уже проходила до дополнительной явной защиты; отдельная воспроизведённая уязвимость для неё не заявляется.

Для документационной контрольной точки применяется адресная проверка планового реестра, публикационных путей, exact diff и связности документов с открытой историей. Координатор явно разрешил проверенный внешний исходник инструмента из коммита `11d71fdd5ea8b958d8e3fc9aa028b8720024b853`: SHA-256 модуля отчётности `52d6e215a05612d801bcd28a69c96033b2a9b86bf8a9feede15998ba48f94e55`, checker `4af845c1d056043475805f10b6308bdc77e6221dd4d511fa13ef70add800725b`. До использования оба SHA сверены; чужие SKILL не читались. Старые записи не мигрируют в v4. Заключительная связность проверяется с `--контрольная-точка`; окончательный результат фиксируется при передаче коммитов.

Заключительный независимый checker контрольной точки завершился кодом 1: 282 исторические Markdown-ссылки на отсутствующий локальный `.obsidian/graph.json`; других ошибок не выдал. [Полный результат замыкания](материалы/отказ-замыкания-контрольной-точки.txt) сохранён отдельно от неизменяемой v3-истории. Эта команда явно назначена координатором вне охваченной границы; её длительность отдельно не измерялась. Пользовательский граф не копировался, фиктивный файл для успешного допуска не создавался. Глобальная связность не объявляется успешной. Координатор явно принял этот внешний остаток для ограниченной передачи. После фиксации отказа заключительное адресное замыкание проверяет только собственные Markdown-ссылки, открытый точный предпросмотр, recency, индекс и неизменность прежних записей; глобальный запуск не повторяется. ## Решения и ограничения

Бюджеты и точный поддержанный набор JSONL описаны в [контракте архивного снимка](../../Документация/архивный-снимок-задачи-FUMA.md). Снимок сохраняет только идентичность, явно записанный cwd и модель последнего явно идентифицированного хода. Тишина, EOF, final и HookPrompt не означают завершения, ожидания человека или живой активности. Происхождение — «по состоянию прочитанного префикса». Содержимое диалога, аргументы/вывод инструментов, UI и назначенное рабочее дерево не сохраняются.

Публичный API читателя статистики изучен по устойчивому коммиту `85dccce282821a890e5e65539b4f22b895b52887`: `прочитатьПрефикс` возвращает `[СобытиеВызова]` и статистическую границу. Он не является общим потоком архивных строк. Отдельный ограниченный байтовый читатель оставлен обоснованно; общая реализация может выделяться позднее без смешения семантики. Незакоммиченные файлы чужой задачи не импортировались.

Реальный журнал, первичный диалог пользователя, другие сессии и macOS UI не читались. Файловые SHA и внутренняя согласованность не доказывают внешнюю подлинность при согласованной подмене архива и источника. Первый реальный импорт и дальнейшие формы runtime остаются в [FUM-STEP-0164](../../Планирование/карточки-шагов/🟡-FUM-STEP-0164-принять-формы-runtime-и-реальный-архив.md). Родительский шаг 0159, находящийся в ветке координатора, здесь не дублируется.

Единственная материализация Git-зависимости — уже зарегистрированный LinguisticKit в собственном FUM worktree по закреплённому `837e2ce107b97ee7b9d3344c9fe99142281fe393`; gitlink и `.gitmodules` не изменены. Переход на собственные ветки и отдельный Swift worktree основан на прямом поручении этой задачи; первичный checkout, master, чужие файлы и refs не изменялись.
