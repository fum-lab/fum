## Решения и ограничения

<!-- FUM-КАРТОЧКА:НАЧАЛО решения -->
Конечный Q содержит 64 проектных файла и объявленные ресурсы. До audit загружаются все объявленные полные stdlib-модули, включая urllib.parse; шаблоны, типы, режимы и байты сверяются перед эффектами. Git не вызывается из повторного file guard. PATH имеет только абсолютные непустые элементы; Git выбран до hooks и перепроверяется по executable и argv. В читающем процессе формы symbolic-ref, worktree, config и merge-base конечны; пишущие формы запрещены. DEVNULL допускается по конкретному символьному устройству; целочисленные PIPE — только как IPC. Подготовка G2 пишет три заранее объявленных новых файла без отложенного flush; штатный importer истории модели не изменён. Вложенная проверка пишет диагностический JSON в stderr; смена и повтор дают по одному итоговому JSON в stdout.

Первые отказы обнаружили недостающие ресурсы полной фикстуры, фоновый Git gc, поздние stdlib-импорты, слишком узкое описание DEVNULL/PIPE и реальных читающих Git-вызовов. Затем исправлены данные старой фикстуры: настоящие recency и индекс создаются до её базовых коммитов, добавляются только изменённые отслеживаемые файлы и индекс, присутствует глоссарная цель. Приёмочный checker не подменялся. Вспомогательный наследованный тестовый набор исключён через load_tests; выбираются все шесть собственных сценариев. Последний отказ вызван file= внутри json.dumps вместо print; исправлен прямой вызов. Независимый читающий обзор не нашёл новых блокирующих дефектов; сам проверок не запускал. Legacy-сценарий регрессии сохранил отказ автообзора неподдерживаемой подготовки отдельно от созданного проверенного коммита; успех набора не объявляет такой автообзор выполненным.

Полный цикл подтверждён на открытой изолированной фикстуре. Это не наблюдение реального узла, не возврат его RAW-каталога и не восстановление после перезагрузки ОС. U/A/ACT/T8/C429 и старые RAW рабочего исполнителя данным этапом не изменялись. Штатные guards G1→G2, v4 и Creator сохраняются. Следующий конечный этап: возврат сохранённого пустого каталога только после запечатанной G2 под двумя замками, затем адресный запуск владельцем и новый читающий процесс. Заполнение отчёта сначала отказало до записи: reader с режимом 0600 ошибочно применён к диагностическому профилю 0644 внутри приватного каталога 0700. Повтор проверяет фактический режим, владельца и физический путь; профиль и исходный отказ не изменялись. Пользовательский README внутренний ремонт не меняет; связанные пояснения обновлены. Новые чаты, деревья, heartbeat и автоматические повторы не активировались.
