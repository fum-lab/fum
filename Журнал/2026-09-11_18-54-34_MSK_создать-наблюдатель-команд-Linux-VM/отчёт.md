# Отчёт 2026-09-11 18:54:34 MSK - Создать наблюдатель команд Linux VM

Создан отдельный Python-наблюдатель одной команды. Унаследованный канал жизни обнаруживает смерть родителя, включая SIGKILL; отдельный PGID получает TERM и затем KILL при EOF, сроке или переполнении вывода. Лидер остаётся waitable через WNOWAIT до последнего сигнала. Наблюдатель дожидается статуса и исчезновения группы, долговечно устанавливает отдельную квитанцию UUID и последним закрывает унаследованный flock. Swift fork, сеть и VM не нужны.

CLI принимает семь личных FD. Он до запуска отклоняет чужую схему, повтор UUID по любой старой квитанции, файловые алиасы, нечитаемые источники, непустые или недоступные приёмники. Вывод читается блоками до 64 KiB, на диске ограничен каждым заданным пределом; исходные argv, среда и сырые потоки не попадают в квитанцию. Наблюдатель работает с точным текстом через `-c`, без `__file__`.

## Проверки

- Исходный RED: отсутствующий модуль дал пять отказов. Первая реализация сохранила два отказа из пяти: macOS возвращает EPERM при сигнале группе с завершившимся unreaped лидером. Исправление не трактует EPERM как очистку: обязательное исчезновение PGID проверяется после wait. Следующий запуск прошёл пять сценариев.
- Независимый RO-обзор обнаружил слабый допуск файловых дескрипторов и опасное использование сохранённых PID при аварийной очистке тестов. Добавленный RED получил пять отказов на восьми тестовых методах. Исправлены алиасы файлов, доступ, размер и смещение; повтор конечного UUID отвергается до команды. Тесты сигналят только своим живым непосредственным Popen-детям; семейная фикстура сама ограничена восемью секундами.
- Итоговый GREEN: восемь методов, включая SIGKILL только родителя, TERM-игнорирующего потомка, контрольный посторонний процесс, удержание flock до очистки, deadline, output cap, ранний EOF, обычный ненулевой код, старую квитанцию и чужую схему. Все наблюдатели запускаются через `-I -S -B -c`.

## Решения и ограничения

- Алгоритм после профиля сохранён: заданный предел выдержан, измерения не оправдывают усложнение. Ускорение не заявляется.
- Код CLI 0 означает установленную квитанцию, а не успех команды; вызывающий сверяет схему, все UUID, источник и SHA-256 конфигурации, исход и код. Невалидный контракт и ошибки установки дают 125, ошибка аргументов argparse — 2. Поля сигнал_TERM/KILL описывают попытки; отдельное поле группа_исчезла появляется только после подтверждения.
- На macOS нужен Python >= 3.13 из-за waitid/WNOWAIT. Linux Python 3.12 имеет используемые API; реальный Linux-прогон в этой дочерней части не выполнялся. Проверенная среда — Python 3.14.7 / Darwin / arm64.
- Родитель сохраняет манифест до запуска, передаёт ровно семь FD и единолично держит пишущий конец pipe; остальные процессы его не наследуют. Родитель не меняет конфигурацию, stdin и выходы после передачи. Конечные квитанции не перезаписываются и не считаются фазами гостевых метрик. Автоматический повтор команды и удаление поставки не выполняются.
- Процессы, самостоятельно ушедшие из PGID, SIGKILL самого наблюдателя, отказ носителя и непрерываемый ввод-вывод остаются за границей. Если группа не исчезает после KILL либо сигнал недоступен, замок удерживается без конечной квитанции; это отказ, а не ложная готовность. Ошибки носителя могут оставить начальную запись и временную конечную запись. На Linux зомби чужого потомка требуют нормального reaping со стороны ОС.
- Это промежуточный коммит отдельного результата. Подключение в готовность.py, собрать.py и Swift, реальная VM и общая приёмка остаются корню. Полный и стандартный smoke-check не запускались по границе поручения. Проекция сохраняется из базы `01ce243e1be997d87ca40f0a76ea24336d049774` и отстаёт от новых канонических файлов; её готовность для этого снимка не заявляется.
