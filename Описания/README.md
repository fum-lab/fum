# [Описания FUM для адресатов](../Глоссарий/описание-FUM-для-адресата.md)

Эта папка хранит адресные описания [FUM](../Глоссарий/FUM.md), построенные на основе [документации](../Глоссарий/производная-документация.md), [глоссария проекта](../Глоссарий/глоссарий-проекта.md), [открытых вопросов](../Глоссарий/открытый-вопрос.md) и [исходных запросов](../Глоссарий/исходный-запрос.md).

Описание для адресата не является новым источником требований. Оно является производным слоем [памяти FUM](../Глоссарий/память-FUM.md): выбирает релевантные тезисы, меняет порядок подачи и объясняет проект языком конкретной аудитории.

Отдельные описания могут иметь жанровую форму. [Художественное самоописание FUM](../Глоссарий/художественное-самоописание-FUM.md) относится к таким производным материалам: оно описывает FUM через прозу, стихи, музыкальные треки, сценарии фильмов и другие формы, но должно сохранять паспорт источников, статус художественных допущений и границу между образом, требованием и прогнозом.

## Правила описаний

- Каждый файл описания должен фиксировать адресата, цель, статус, источники, применённую [автоматизацию FUM](../Глоссарий/автоматизация-FUM.md) и ограничения.
- Описания должны ссылаться на документы и глоссарные термины, из которых выведены ключевые тезисы.
- Если описание выявляет новую проектную мысль, её нужно отдельно внести в `Документация/` или `Глоссарий/`; само описание не заменяет эту работу.
- При изменении базовой документации затронутые описания должны пересобираться или проверяться по воспроизводимой схеме.
- Описания не обновляются точечной ручной правкой: для создания, исправления или обновления нужно вызвать соответствующую автоматизацию и пересоздать результат.
- Неподтверждённые факты о статусе, метриках, внедрениях, юридических обязательствах или коммерческих результатах нельзя добавлять ради убедительности адресного текста.
