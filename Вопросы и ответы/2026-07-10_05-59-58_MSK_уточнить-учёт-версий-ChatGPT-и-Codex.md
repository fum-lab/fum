# Почему не записывалась версия ChatGPT или Codex

Версия не была забыта случайно: вместо неё в каждом новом файле запроса повторялась формулировка «версия Codex не раскрывается средой». Это было честным fallback при создании реестра, но слишком широким: ChatGPT и Codex рассматривались как один неделимый инструмент, хотя рабочая среда состоит из нескольких независимо версионируемых слоёв.

## Вопрос

```text
Pochemu myi ne zapisyivayem v ispoljzuyemyiye instrumentyi versiyu ChatGPT/Codex?
```

## Ответ

Потому что 2026-06-24 при создании реестра мы не зафиксировали доступный способ проверки версии агентской среды и выбрали безопасную запись «версия не раскрывается». Затем шаблон стал механической практикой: во всех 102 файлах запросов с разделом `## Использованные инструменты` Codex указан именно так, а ChatGPT отдельно не указан ни разу.

Проблема не в отсутствии версии вообще, а в смешении разных сущностей. На 2026-07-10 локально наблюдаются:

- desktop bundle `/Applications/ChatGPT.app`: отображаемое имя `ChatGPT`, bundle id `com.openai.codex`, версия `26.707.31428`, сборка `5059`;
- встроенный в пакет приложения `codex-cli 0.144.0-alpha.4`;
- отдельно установленный `codex-cli 0.144.1`;
- сконфигурированная модель по умолчанию `gpt-5.6-sol` с режимом `ultra`.

Ни одно из этих значений не является универсальной «версией ChatGPT/Codex». Версия приложения не доказывает версию встроенного runtime или активной агентской сессии; версия CLI не определяет модель; значение модели в конфигурации может быть переопределено текущей сессией и поэтому не доказывает активную модель. Отдельный версионированный идентификатор активной агентской сессии, возможной удалённой сервисной части и контрактов инструментов по-прежнему не предоставляется доступным способом наблюдения.

Практика исправлена. В новых файлах запросов отдельно записываются фактически участвовавшие слои и их наблюдаемые версии. Формулировка «не раскрывается» используется только для конкретного слоя с указанной границей наблюдаемости, а `fum-session-coherence` отклоняет прежнюю общую запись для новых запросов. Старые запросы массово не переписываются, потому что они являются историческими снимками того, что было записано в соответствующих сессиях.
