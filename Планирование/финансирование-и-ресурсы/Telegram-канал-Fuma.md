# Telegram-канал Fuma

Ближайший прикладной результат — Fuma ведёт канал о своей разработке:
объясняет проверенные результаты, показывает эксперименты, признаёт ошибки
и рассказывает о следующих задачах понятным человеку языком. Это продолжение
[медийного направления](медийное-сопровождение-пожертвований.md); новости могут
поддерживать привлечение ресурсов, но канал полезен и без сбора пожертвований.

Канал обслуживает адаптер Telegram внутри рантайма FUMA: публикации, правки
и проверка фактического результата проходят через него, а тексты и квитанции
сохраняются в памяти FUM. Реальный сквозной путь ещё предстоит подтвердить.

## Очерёдность

1. После текущего конечного пилота конвейера вернуть в активную работу
   существующий Telegram-адаптер. Сначала найти и принять уже сохранённую
   реализацию и её тесты, не создавать второй клиент параллельно ей.
2. Создать новый канал Fuma: пользователь подтвердил, что канала пока нет.
   Подключить назначенную учётную запись и проверить права публикации. Для
   Telegram сохраняется выбранный клиентский API с TDLib; смена на бот не
   предполагается. Название, описание и первое сообщение готовятся до запуска.
3. Реализовать автоматизацию полного цикла: принятый результат в памяти FUM
   → черновик поста с происхождением → публикация → чтение опубликованного
   сообщения → сохранение ID, версии, текста и ответа API в памяти.
4. Проверить неопределённый исход отправки без дублирующего поста, исправление
   опубликованной неточности, отсутствие прав и восстановление после перезапуска.
   Подготовить первую новость на основании фактически принятого результата.
5. Провести разрешённую сквозную публикацию в указанном канале. После её
   проверки определить темп следующих постов по содержательным результатам.

## Критерий первого результата

Пост реально доступен в назначенном Telegram-канале; его текст, идентификатор,
происхождение и свидетельство последующего чтения сохранены. Повтор операции
не порождает второй пост. Из материала ясно, что Fuma — ИИ-агент проекта FUM,
какую работу он выполнил и что ещё не проверено. Черновик, мок API и локальный
коммит отдельно не доказывают ведения канала.

## Текущее состояние

Это постановка ближайшего результата, а не выполненная активация интеграции.
В текущем checkout найдены общие планы мессенджеров и медийного тракта;
поставка рабочего Telegram-клиента здесь пока не подтверждена. По текущему
API-списку 50 задач отдельная задача Telegram не найдена; это не доказательство
её отсутствия в архиве или более ранних задачах. Её точное состояние следует
восстановить до возобновления. Учётные данные сохраняются вне публичного Git.
