# Первый цикл проверки самофинансирования FUM

Пул [Issues №25–32](https://github.com/fum-lab/fum/issues/32) принят в работу по [прямой команде пользователя](../../../Журнал/2026-10-03_16-59-08_MSK_принять-пул-самофинансирования/запрос.md). Точное содержание координирующей Issue сохранено [отдельным источником](../../../Источники/URL/https/github.com/fum-lab/fum/issues/32/source-index.md). Состояние на 3 октября 2026 года: постановки прочитаны, результаты новых экономических экспериментов ещё не получены.

Продолжаются [FUM-REQ-0069](../../../Требования/🟡-финансирование-и-ресурсы-развития-FUM.md), [существующий финансовый поток](../README.md), [бизнес-план](../бизнес-план-FUMA.md), [пакеты поддержки](../пакеты-поддержки.md) и [эксперимент первого сценария](../../эксперимент-пользы-первого-сценария-FUMA.md). Исторический реестр организаций и выбранный продуктовый сценарий сохраняются. Этот файл координирует работу; второго реестра денег, организаций или разработок не вводит.

Первые три назначения подготавливаются параллельно в отдельных видимых чатах и рабочих деревьях. До адресного акта с реальным native UUID каждый новый исполнитель только читает и предлагает конечную область. Начальный коммит содержит постановку, а не объявляет реализацию выполненной. Чужие ветки и общие финансовые файлы не редактируются несколькими писателями. Корень принимает изменения через проверенные merge-коммиты и PR в `fuma` по действующему порядку; публикация дочернего checkpoint не равна интеграции.

## Общая граница первого цикла

Первый срез — минимальные согласованные входы: определения денежных событий и полной стоимости, структура бюджета, паспорт неизвестных данных получателя и датированные первичные условия выбранных маршрутов. Их подготовка не требует завершения всей технической Issue №24. Используемые в платном опыте компоненты проверяются отдельно.

До оцениваемого опыта фиксируются один результат, критерии качества, цена предложения, число и порядок попыток, предел денег и часов, период наблюдений и правило остановки. Конкретные значения пока не утверждены и не подставляются из аппаратной сметы. Подтверждённый регулярный доход, бюджет расходов и зарегистрированный получатель сейчас не установлены. Реальные заявки, регистрация, счета, оферты, договоры, сборы, кредиты, закупки и платежи этим приёмом Issues не разрешены.

Успех разделяется на покрытие следующего этапа, повторяемую оплату эксплуатации, полную стоимость с трудом и заменой оборудования, свободный остаток на развитие и разрешённую степень автоматизации. Долг, внутренний перевод, бонус и обещание поддержки не становятся выручкой. Разовый платёж не доказывает регулярности; неизвестное не равно нулю. Отрицательный результат и доказанный блокер допустимы.

По готовности общих входов корень выдаёт следующую конечную постановку №28–31; уже подготовленные направления не исследуются заново. Если требуются решения человека, сохраняются конкретный вопрос, основание и блокируемое действие. Задачи остаются открытыми до подтверждённого результата, а не закрываются после написания плана.
