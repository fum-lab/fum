## Продолжение подготовки

Продолжение существующей финансовой задачи включает адресную проверку практических вариантов по актуальным первичным условиям, подготовку бюджета и материалов с явными неизвестными данными заявителя. Донаты и другие формы безвозвратной поддержки сохраняются рядом с лизингом, кредитами и региональными займами; долговые обязательства и стоимость оборудования показываются отдельно.

Сравнение охватывает полную стоимость, платежи, обеспечение, требования к получателю, совместимость конкретных условий с CC0 и ближайшее действие. Каналы сбора средств не считаются найденными донорами. Реестр и датированные исследования сохраняются; новая дата постановки не обновляет дату проверки программы.

Назначение отражено в [постоянном плане](../README.md#ближайшие-согласованные-поставки), основание — [команды и поздние уточнения](../../Журнал/2026-09-15_19-02-24_MSK_подключить-допуск-постоянной-ветки/запрос.md). Подготовка не включает внешнюю подачу, переписку, регистрацию, заключение договоров и платежи и не подтверждает получение финансирования.

## Как читать результат

Организация и конкретная программа различаются. Итог организации показывает наиболее продвинутый из её вариантов; условия остальных видны ниже. Статус «подходит для следующего шага» у технического партнёра означает только указанную локальную подготовку. Поле `доступная_программа` отдельно требует свежих прямых официальных источников, подтверждённого приёма, проверенного срока и отсутствия неизвестных условий заявителя.

По прямому уточнению пользователя рассматриваются все формы финансирования при сохранении народного достояния CC0. Долевое финансирование записано как форма «деньги» с явным указанием доли и встречных прав в варианте; денежный долг — «кредит». Совместимость конкретного договора с CC0 не предполагается.

Деньги, пожертвования, спонсорство, кредит, облачные бонусы, скидка, кешбэк бонусами, компенсация расходов, оборудование и техническое сотрудничество имеют разные значения. Исходные исследования не дали проверенной самостоятельной программы передачи оборудования или прямого спонсорства; пустота не заполняется вымышленной организацией. Все категории и формы разрешены контрактом для последующей предметной работы.

Для программы срок актуальности равен 30 дням, для подготовки сотрудничества — 90 дням. Возраст считается от самого раннего прямого чтения среди необходимых источников; в день достижения порога требуется новая проверка. Индекс поиска и неудачная загрузка не обновляют свежесть. Истёкший дедлайн означает недоступность; в последний день требуется сверить точное время. Интервал требует даты окончания, начало может быть неизвестно. Постоянный приём должен быть прямо установлен источником. Исторический отрицательный результат сохраняется с отдельной отметкой устаревания.

Исходный набор имеет устойчивые ID, вычисленные из исходного имени исследования и названия организации. Проверяется точное покрытие всех исходных кандидатов, дубли и неизменность исходного исследования. SHA-256 исходной передачи, заявленный исследователем, сохраняется как происхождение; он не выдаётся за проверенный хэш нынешнего JSON. Хэш входа для обновления вычисляется после канонической сериализации JSON, а хэши файлов свидетельств — по точным байтам.

## Воспроизведение без сети

Нужны Python 3.11 или новее и обычный чистый клон FUM. Дополнительные пакеты для выпуска реестра не нужны. Фактическая проверка выполнена на macOS arm64 с Python 3.14.7; отдельный профиль памяти использует POSIX-модуль `resource`. Все команды выполняются из корня своего checkout.

```bash
python3 -B Инструменты/fum-reyestr-planirovaniya/scripts/реестр-организаций-поддержки.py сформировать \
  --корень-репозитория . \
  --исследования Планирование/финансирование-и-ресурсы/исследования.json \
  --вход Планирование/финансирование-и-ресурсы/карточки.json \
  --дата 2026-09-15 --выход Планирование/финансирование-и-ресурсы
```

Заменить `сформировать` на `проверить`, чтобы сверить сохранённые результаты без записи. Дата обязательна и не подставляется из часов компьютера. При другой дате генератор использует последнее наблюдение не позднее неё; он не делает нового веб-чтения. Служебный конечный блок Markdown-recency исключён из сравнения текста, но не из проверки его собственным инструментом.

Код 0 означает успешное выполнение выбранной операции. Код 2 означает отказ контракта, неверные параметры или недоступный файл; положительный финансовый допуск из кода завершения не следует. Полный вход проверяется до записи. Выходам запрещено пересекаться с карточками, исследованиями и связанными свидетельствами. Каждая замена файла атомарна; два выходных файла не составляют общую транзакцию. После сбоя между заменами `проверить` обнаружит неполный выпуск, который можно повторить.

## Добавление нового наблюдения

Сначала адресно прочитать актуальные официальные условия, сохранить источник существующим механизмом [материалов запросов](../../Инструменты/fum-materialyi-zaprosov/SKILL.md) и подготовить JSON наблюдения той же структуры, что последний элемент `проверки` выбранного варианта. Автор, дата, способ получения, неизвестные и минимальный следующий шаг заполняются явно. Дата нового чтения не приписывается старому исследователю.

Для неизменяемого свидетельства сохранить байты извлечённого текста в каталоге канонического URL: `свидетельства/<sha256>/извлечённый-текст.txt`. Вложенный снимок содержит прежний настоящий URL в `source-url.txt`, происхождение и собственный `snapshot-manifest.json`; суффикс хранения не является новым URL. Манифест создаётся существующим `write_snapshot_manifest` после записи файлов и включает самого себя. `install_snapshot` сохраняет самостоятельные вложенные снимки при обновлении родителя. Родительский манифест не включает их файлы.

В `снимок` указать точный относительный путь текста и SHA-256 его байтов. Манифест проверяет состав файлов, а реестр отдельно проверяет SHA; он не заменяет сверку публикационной чистоты источника. Старые байты и хэш не переписывать. `снимок: null` честно обозначает отсутствие сохранённых байтов именно этого чтения; официальный адрес и свидетельство всё равно обязательны. [Карта первого переноса](исходные-данные/перенос-свидетельств.json) связывает прежние пути из исторических входов с текущим хранением без изменения дат, авторов и условий.

Получить ожидаемый канонический хэш карточек:

```bash
python3 -B - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, 'Инструменты/fum-reyestr-planirovaniya/scripts')
import реестр_поддержки as реестр
print(реестр.хэш(реестр.разобрать(Path('Планирование/финансирование-и-ресурсы/карточки.json').read_bytes())))
PY
```

Вызвать `обновить` с общими `--корень-репозитория`, `--исследования`, `--вход` и дополнительными `--организация FUM-ORG-…`, `--вариант <ид>`, `--наблюдение <путь.json>`, `--ожидаемый-хэш <полученный хэш>`. Первый вызов без `--применить` показывает хэши до и после без записи. Повтор с `--применить` добавляет наблюдение после проверки ожидаемого хэша. Старое чтение остаётся в истории; новая проверка той же даты добавляется после прежней. Идемпотентно только совпадение с последним наблюдением, поэтому возврат состояния после промежуточного изменения сохраняется. Защита рассчитана на одного писателя дерева; это не блокировка конкурентных процессов.

Операция `импортировать` создаёт незаполненную заготовку для заданного корпуса исследований и не перезаписывает заполненные карточки. Заготовка ещё не проходит выпуск. Изменение самого корпуса организаций или юридического профиля требует отдельной явной миграции: этот первый контракт не разрешает незаметно удалить кандидатов или объявить регистрацию подтверждённой.

## Расширение корпуса 14 сентября 2026 года

Новый поиск и уточнения о всех формах финансирования дали явное основание расширить корпус. Первые два конверта исследований и первые 16 карточек сохранены без смыслового изменения. Третий конверт — консолидация корня по прямым чтениям и материалам трёх исследователей; его хэш вычислен по каноническому JSON и не выдаётся за исходную передачу ребёнка. Юридический профиль FUM не изменён. [Карта миграции](../../Журнал/2026-09-14_14-19-35_MSK_найти-дополнительное-финансирование-работы-FUM/материалы/миграция-корпуса.json) фиксирует старый и новый хэш, ID, 23 первичных свидетельства и два раздельных свидетельства Boosty после ревью.

Часть свидетельств — явно обозначенные пересказы прямого чтения, а не полные документы. HTML Boosty даёт оболочку, поэтому условия взяты из отрисованного браузером текста, прочитанного исследователем. PDF Росмолодёжи повторно не загрузился. Это ограничение не скрыто за хэшем снимка.

После изменения наблюдений повторяется та же команда выпуска с явной датой; перед продолжением заявок адресно перечитываются действующие условия. Приоритеты — отдельное редакционное решение о порядке подготовки с прямыми ссылками в сформированный список. Получение средств, готовность подачи и законность конкретной сделки из успешного выпуска не следуют.

## Проверки и профиль

```bash
python3 -B -m unittest discover -s Инструменты/fum-reyestr-planirovaniya/tests -p test_реестр_поддержки.py
python3 -B Инструменты/fum-reyestr-planirovaniya/tests/профиль_реестра_поддержки.py \
  --дата 2026-09-14 --повторы 7 --выход .build/профиль-реестра-поддержки.json
```

Профиль измеряет чтение сохранённых данных, проверку свидетельств, оценку и шаблонный выпуск в прогретом процессе. Сеть, запуск Python и запись выходных файлов за границей. Отчёт содержит версии, хэши входов и кода, повторы, память и хэши результата. Вложенные интервалы не складываются с общим временем.
