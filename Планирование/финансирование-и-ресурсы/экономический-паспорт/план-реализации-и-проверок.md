# Реализовать и проверить первый расчёт паспорта

Этот план завершает ограниченный [контрактный срез](README.md). Команды ниже описывают будущую поставку: названных исполняемых файлов пока нет, команды ещё не проверены. Новый компонент сохраняется в тематической области монорепозитория FUM; общий Swift V2 backend и зависимости не меняются.

## Конечная область следующей реализации

От корня FUM, в `Планирование/финансирование-и-ресурсы/экономический-паспорт/`:

| Будущий файл | Результат |
| --- | --- |
| `адаптер-паспорта.py` | Строгое чтение JSON на стандартной библиотеке Python; проверка типов, ссылок, импортных дублей/конфликтов и исправлений; подготовка чистого операторного входа; отдельный публичный экспорт |
| `оператор-расчёта.json` | Декларативный расчёт существующими примитивами FUMA: баланс по валютам, известные части стоимости, `null`, явные доли и точное деление |
| `примеры/ожидаемые-отчёты.json` | Независимые полные и неполные исходы; разница поступления и приёмки; приёмочные равенства |
| `проверки/test_паспорт.py` | Содержательные проверки импорта, классификации и двух отчётов, включая отказы |
| `проверки/профиль-паспорта.py` | Повторяемые измерения чтения, проверки, операторного расчёта и сериализации; хэши входа/выхода/исходников |

Приватные runtime-журналы, исходные клиентские подтверждения, кэши и подробные профили сохраняются вне Git. Нового банковского адаптера, сетевого импорта или платёжного эффекта в этой области нет.

## Порядок и содержательная приёмка

Сначала тесты ожидаемого поведения и независимые ожидаемые итоги; сохранить действительный RED. Затем валидатор и адаптер, GREEN и профиль. Отдельно проверить граф через существующий путь исполнения оператора FUMA. При отсутствующей зависимости или ошибке сборки сохранить конкретное препятствие и доступные независимые результаты; успешное чтение JSON не выдавать за работающий расчёт.

| Сценарий | Независимый ожидаемый исход |
| --- | --- |
| Повтор того же события | Баланс и число действующих событий не меняются |
| Один ID с другими данными | Диагностика конфликта, без скрытой замены |
| Аванс до приёмки | Касса растёт; услуга и обязательство остаются отдельно |
| Частичная оплата | Учитываются только фактические платежи, остаток обязательства сверяется с ними |
| Возврат и комиссия | Отдельные выплаты; прежняя оплата остаётся в истории |
| Неизвестная ставка | Секунды сохранены; полная стоимость и полный итог `null` |
| Несколько валют | Раздельные суммы; отсутствующий курс не создаёт общий итог; нецелая конвертация отвергается |
| Бонус, оборудование, заём и взнос | Неденежная поддержка не меняет кассу; финансирование не подменяет оплату работы |
| Внутренний перевод | Между узлами контура внешний доход `0`; неверная граница диагностируется |
| Зарплата и оценка времени | Стоимость одной записи труда не суммируется дважды |
| Покрывающая оплата | При подтверждённом полном покрытии известная сумма труда сохраняется даже при неизвестной длительности или ставке |
| Неполные экономические входы | Известная часть сохранена; пропущенный труд не создаёт нулевую полную стоимость |
| Общий пул | Единственная выплата, одна доля на работу, явный нераспределённый остаток |
| Исправление расхода | Конечная версия цепочки, оригинал сохранён; цикл и конкурирующая замена отвергаются |
| Неуспешные попытки | Все затраты остаются в полной стоимости; приёмка не фабрикуется |
| Повторное применение | Затраты учитываются по ID один раз; без сопоставимой базы экономия неизвестна |
| Публичный агрегат | Обязательные схема, режим и граница; разрешённые поля и открытые основания; закрытые данные и локальные адреса отсутствуют |
| Числовые границы | `bool`, `float`, строка, отрицательная сумма и переполнение отвергаются; ноль отличается от неизвестного |
| Неполные движения и ограничения | Неизвестные полный баланс или свободный остаток сохраняются явно |
| Синтетический контроль | `0 + 15000 + 5000 − 600 − 3000 − 9000 = 7400`; известная часть полной стоимости `6600`, труд `4500` секунд |

Дополнительная фикстура с известной ставкой должна независимо сверить вклад до общих затрат и итог после их распределения. Отдельная проверка сравнит синтетический агрегат с арифметикой медиапакета, сохранив явное различие схем и режима; синтетический документ не становится `fum.свидетельство-поддержки.1` с видом «фактический учёт».

## Будущие воспроизводимые команды

Плановый тестовый вход, из чистого клона FUM с объявленной версией Python, без сторонних Python-пакетов:

```sh
python3 -B -m unittest discover -s Планирование/финансирование-и-ресурсы/экономический-паспорт/проверки -p 'test_паспорт.py'
python3 -B Планирование/финансирование-и-ресурсы/экономический-паспорт/проверки/профиль-паспорта.py --вход Планирование/финансирование-и-ресурсы/экономический-паспорт/примеры/синтетический-паспорт.json --выход "${TMPDIR:?задайте внешний временный каталог}/профиль-паспорта.json"
```

Перед будущим запуском вызывающий задаёт `TMPDIR`: существующий разрешённый временный каталог с абсолютным путём, который после разрешения символических ссылок находится вне checkout. Раскрытие переменной проверяет только наличие непустого значения; выбор каталога вне checkout остаётся условием вызывающего. Команда остаётся плановой.

CLI измерителя ещё предстоит реализовать по этому контракту. Определение расчёта передаётся существующему `fum --выполнить-оператор`; приватный runtime-журнал и публикационный экспорт остаются отдельными эффектами. Успех записи вывода не заменяет приёмку чистого расчёта.

Профиль: прогрев и три чередующихся повторения на одном входе; отдельно чтение/валидация, расчёт, сериализация и запуск процесса. Начальная целевая фикстура — до 400 событий; предполагаемый предел одного запуска — 30 секунд и 128 МиБ, без полной Swift-сборки. Это плановые пределы, не измеренная производительность. Полный smoke и братиславская проекция в первом срезе не выполнялись; их приёмка этим срезом не подтверждается.

## Входы, без которых нельзя перейти к фактическому учёту

Подтверждённые первичные события и полнота контура, владелец учёта, согласованные ставки и время, правило общего пула, стоимость принятой услуги, условия целевых средств и авансов, права и измерения повторного применения, разрешение на конкретные публичные агрегаты. До получения этих входов проверка использует открытые синтетические числа. Бухгалтерская и налоговая применимость подтверждаются отдельной работой по текущим официальным источникам.
