# Проверка штрафов ГИБДД в FUMA

FUMA должна по запросу пользователя получать и показывать сведения о штрафах из официального доступного источника. Принято требование FUM-REQ-0076. Реального подключения пока нет: первый шаг FUM-STEP-0223 сохраняет поиск и подтверждение допустимого доступа.

## Первый сценарий

Пользователь просит проверить штрафы своего автомобиля. FUMA определяет доступный официальный источник и минимально необходимые реквизиты по его актуальной форме или документированному интерфейсу. До подтверждения этого интерфейса состав входа не закрепляется по старой сторонней инструкции. Данные реального пользователя в публичной памяти проекта не хранятся.

При успешном получении FUMA показывает только поля, действительно предоставленные источником: идентификатор постановления, сумму, статус и другие доступные сведения. Рядом указывает источник и время получения. Подтверждённое отсутствие штрафов отличается от недоступности сервиса, ошибки доступа и неполного ответа. Несостоявшаяся проверка никогда не отображается как отсутствие штрафов.

## Наблюдаемый доступ на 11 сентября 2026 года

- [Госуслуги](../../Источники/URL/https/www.gosuslugi.ru/source-index.md): браузерный вход перенаправляет на страницу ограничения доступа с просьбой отключить VPN. Подтверждённого входа к услуге и формы запроса в текущем сеансе нет.
- [Госавтоинспекция](../../Источники/URL/https/госавтоинспекция.рф/check/fines/source-index.md): [старый адрес](https://госавтоинспекция.рф/check/fines) открыл главную. Доступный [раздел нарушений и штрафов](https://госавтоинспекция.рф/mens/fines) содержит справочник санкций. Работа индивидуальной проверки не подтверждена.
- Документированный программный интерфейс и допуск FUMA к нему не установлены. Доступность главной страницы и ранее составленный план входа через ЕСИА не заменяют такого допуска. Отсутствие найденного контракта не доказывает отсутствия API вообще.

## Следующая работа после снятия препятствия

1. Повторно открыть официальный пользовательский сервис из доступного сетевого окружения либо получить опубликованный программный контракт оператора. Зафиксировать фактическую форму, назначение, условия и минимальный набор данных.
2. Подтвердить применимость выбранного способа к FUMA. Для недокументированного программного подключения остаётся предметный вопрос оператору: какой официальный интерфейс допускает чтение штрафов по поручению пользователя, кто имеет право подключаться, какие полномочия, идентификаторы и условия тестирования требуются? Внешнее обращение в этой сессии не отправлялось.
3. Реализовать один ограниченный путь получения и отображения. Открытые фикстуры должны проверить найденные штрафы, явное отсутствие, отказ доступа, недоступность и неполный ответ; отдельно проверить непопадание персональных реквизитов в публичные артефакты.
4. Подтвердить реальное чтение разрешённым способом. До этого синтетические проверки подтверждают только локальное поведение. Время ожидания внешнего доступа не считается доказательством реализации.

## Границы

Команда пользователя назначает просмотр штрафов. Оплата, обжалование, массовый поиск и регулярный мониторинг не включены в этот первый сценарий. Настройки сети, права доступа и учётные данные не изменялись. Выбор браузерного или программного способа остаётся открытым до появления проверенных условий доступа.
