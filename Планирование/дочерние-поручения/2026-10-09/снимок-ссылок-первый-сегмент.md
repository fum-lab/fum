# Закрыть снимок ссылок перед переиспользованием связности

Первый автономный сегмент [FUM-STEP-0244](../../карточки-шагов/🟡-FUM-STEP-0244-проверить-переиспользование-связности-в-одном-допуске.md), уже связанного с [Issue №214](https://github.com/fum-lab/fum/issues/214). Это исходная постановка будущего отдельного писателя; его ACT, UUID и ref будут закреплены после фактического создания. ROOT: `01a07d3d-d376-7ad2-aafc-67e4c25a67eb`.

## Основание и актуальная база

Текущая база чтения — `14452218127fdaf407a375ef30e4c2214282f222`, ветка `refs/heads/fuma`. Новый исполнитель начинает ровно от будущего проверенного коммита этой постановки; точный OID передаётся как Git starting state, а не заменяется базой проекта по умолчанию.

[Три необходимые приёмки](основание-снимка-ссылок.json) подтверждены: перенос модельного контекста C277/PR215, единый лексер C278/PR216, публикационный допуск полного дочернего состава C305/PR220. Их квитанции завершены кодом0; реальные tree/parents и ancestry C387 совпали. Прежнее условие ожидания не удерживает этот срез. Согласованный объём и поздние ограничения сохраняются в [постановке STEP0244](../../решения-постановки/2026-10-05/переиспользование-связности-в-одном-допуске.md).

Человеческое основание — [сохранённые команды об оптимизации без потери строгости](../../../Журнал/2026-10-05_23-19-35_MSK_сохранить-сбои-и-следующие-оптимизации/запрос.md). Два оригинала адресно сверены по RAW: `Ispravlyaj etot istochnik lishnego raskhoda.\n` и `Nuzhno izuchitj vsyo i optimizirovatj bez poteri strogosti, da.\n`. Поручение ребёнку — команда координатора, не новое сообщение человека.

## Конечный результат

Реализовать автономный закрытый снимок Markdown-инвентаря и целей ссылок, чистую проверку ссылок на нём и живую сверку тождества. Независимый нынешний `validate_markdown_links` задаёт сравнимые положительные и отрицательные исходы, включая порядок ошибок. Это часть STEP0244: полный read set `validate_session` ещё не замкнут; production reuse в ready/create этим сегментом не вводится.

Снимок хранит неизменяемые исходные байты выбранных Markdown, полный инвентарь по существующей политике Git/исключений, точные имена/типы компонентов путей, наблюдения каталогов и разрешённых либо отсутствующих целей, параметры и закреплённый исполняемый код поднабора. Для отсутствующей цели наблюдаются существующий предок и состав его детей, включая регистр. Неполнота, неизвестный вход или дрейф запрещают использование снимка. Один HEAD, разрешённые targets, inode, размер или stat-метки тождества не доказывают.

Чистая функция получает только снимок: checkout, Git, среду и часы не читает. Результат связывается с этим снимком и вызовом; новый вызов не принимает прежнее свидетельство. Необходимая повторная сверка перечитывает байты, инвентарь и списки значимых каталогов. Отсутствие нового самостоятельного рекурсивного обхода изучается, а не обещается при несовместимом текущем интерфейсе. Прежний общий лексер ссылок переиспользуется; новая грамматика не создаётся.

Внутри пакета сущности разделяются по файлам: модель, чтение, чистая проверка и сверка по необходимости. Собственный код и новые имена — русские с орфографической ё. Существующие consumers, `check-session-coherence.py`, общий лексер, project_files, схема готовности, создатель, правила и четыре предметные области параллельного Q-загрузчика остаются read-only. Если без изменения чужого интерфейса результат невозможен — сообщить ROOT конкретное препятствие, сохранить отрицательный результат исследования и не расширять свою область.

Свой новый Журнал, его история модели/v4, навигация и recency входят только в последующий конечный ACT. Старый ROOT-запрос может получить только штатное навигационное/recency обновление. Любой изменённый исходный текст требует отдельного решения. Корень чужие checkout/индексы/refs не меняет.

## Решающие проверки

Подлинный RED до реализации и GREEN на окончательных байтах:

- одинаковые упорядоченные результаты независимой прежней и чистой функций для корректных и некорректных ссылок;
- внецелевой Markdown, добавление/исчезновение кандидата и изменение ignored/untracked состояния меняют снимок; ранее отсутствующий tracked путь не исчезает из учёта;
- появление отсутствующей цели, исчезновение цели, файл/каталог/symlink, предок, регистр и casefold-коллизия не проходят как тождество;
- изменённые байты при прежнем размере/stat, повреждённый UTF-8, неполнота, параметры и закреплённый код отвергаются;
- сохраняются дословные области и специальный необязательный `.obsidian/graph.json`;
- новый вызов не переиспользует результат прежнего; сборщик не объявляет готовность и не вызывает creator.

Для проверки pure-функции закрыть доступ к файловой системе/Git во время самого вычисления тестовой оградой. Такая ограда доказывает отсутствие обращений в проверяемом срезе, а не создаёт глобальную Python sandbox. Редактирование проверяемых байтов между снимками проверяется отдельно.

## Профилирование и решение

Парные одинаковые открытые фикстуры: небольшой набор и более широкий пакет. Отдельно сбор снимка, чистое вычисление, живая сверка, их полная последовательность и прежняя функция; setup исключается. Учесть удержанные байты, каталоговые обращения, Git-вызовы и доступную память с точным методом. Вложенные интервалы и независимые медианы не складываются. Показать source SHA и число повторов; после изменений повторить необходимые измерения окончательного кода.

Завершение допускает полезную ограниченную реализацию или проверенный отрицательный результат с прежним production механизмом. Ускорение всего ready, creator, интеграций или всего рабочего цикла этим профилем не объявляется. Имеющиеся126,780с повторных измерений C385 — основание исследования, а не обещание выигрыша.

## Передача и границы

Один писатель своего дерева/ref; отдельный видимый чат. Модель по текущему выбору пользователя запрашивается явно `gpt-6.1-sol / ultra`; фактическое наблюдение берётся из собственного native JSONL. Штатные отчёты и запросы недостающих фактов отправляются ROOT без нового разрешения человека. Необходимая предметная неоднозначность уточняется с координатором в разрешённой области; новая внешняя полномочность не выдумывается.

Перед первой проверкой применить каноническую подготовку только зарегистрированного окружения при необходимости и сохранить исходы; не использовать ручное recursive-init. Папка материалов создаётся штатно до maker; ранний отказ wrapper не объявляется RED теста. Не удалять свидетельства для восстановления. Незавершённый результат регулярно фиксируется проверенными контрольными точками; собственный точный обычный push и remote readback, затем PR в `fuma` по поручению ROOT. Окончательную предметную приёмку и интеграцию выполняет получатель.

D22 остаётся на паузе. LiveW7964, полный Q/восемь consumers, projection, master, heartbeat/dispatcher/autostart и общая приёмка ROOT не входят. Первый staged-snapshot до терминальных свидетельств не пригоден для будущего reuse. Отдельный creator сохраняет независимость; межвызовного кэша нет.
