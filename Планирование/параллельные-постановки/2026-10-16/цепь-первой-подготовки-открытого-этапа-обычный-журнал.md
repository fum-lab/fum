# Подготовить цепочку для открытого этапа

Реализовать [Issue №327 — «Цепь первой подготовки открытого этапа»](https://github.com/fum-lab/fum/issues/327) в четырёх существующих файлах фасада. План327 и общий контракт328 приняты; универсальный runtime не вводится.

Добавить ограниченный режим ROOT для существующей открытой пары P.1 с настоящими терминальными RAW до первой maker-подготовки. Сначала строить неизменяемый читающий план всей цепи, затем исполнять принятые prepare/fill/recency/staging/проверки/связность/READY. Сохранить пару, RAW, ordinary/merge, прежние допуски и частичные результаты. Для обрабатываемого существующего этапа не вызывать start, не требовать вымышленной прежней .7 и не удалять историю. Creator остаётся отдельной конечной границей. Проверка внутри v4 отличает текущую running-запись от прежних закрытых исходов.

Выполнить настоящий RED нового случая, GREEN, прежние регрессии, сопоставимый профиль и инструкцию. Исполнитель использует собственный обычный Журнал с поздней политикой.1. Допускаются только четыре предметных файла, собственная папка и точные служебные изменения stock start, отдельно принятые ROOT в ACT. S/nav, планы327/328, правила, master, реальный узел и прочие чужие области не изменять. Результат доставить отдельным PR в fuma; приёмка и интеграция выполняются ROOT. Сообщать ROOT результат и препятствия; без решения координатора чат не архивировать.
