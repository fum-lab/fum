# Создать нативный мост читающей подготовки базиса

Подтвердить одно настоящее исполнение читающей подготовки через фиксированный вызов Codex. Результат — отдельный типизированный мост и строгое свидетельство процесса; он не записывает состояние узла, не выдаёт новый эффект и не возобновляет чаты.

## Принятый источник и ограниченный состав

Принятая база C490: `4d23e365c05fe5d2565b5727887acb78994f4961`, PR №250 слит. Старые `запуск_приёма_базиса_узла.py` и `приём_базиса_состояния_узла.py` остаются точными читаемыми зависимостями; схемы `.1/.2` не меняются. Источник новой ветки — точный опубликованный коммит этого ACT19, который ROOT отдельно передаст после своей фиксации. Первоначальные C и native назначение ребёнка сохраняются.

Новый состав: валидный фиксированный CJS-шаблон, детерминированный генератор, наблюдатель единственного процесса, строгий читатель свидетельства, адресные тесты, профиль и руководство. Три существующих файла языкового допуска изменяются только для точного нового CJS-пути и обязательной формы внешнего API с `shell` и `login`; свободные латинские объявления не разрешаются. Точные пути указаны в ACT19.

## Неподменяемое свидетельство

Независимый выбор содержит принятые версии и SHA полного проектного замыкания, входа, exact JS, операции и поколения; он не выводится из проверяемого результата. Раздельно сверяются владелец, физический корень, полный ref, R/A/ACT/G, nonce, канонический вход, фактически прочитанные байты и идентичности. ROOT после приёмки кода отдельно выберет live вход; сам ребёнок не объявляет свой код независимо принятым.

Генератор заменяет только конечные строковые placeholder значения JSON-экранированными литералами. Произвольные команды, JS, callback, import-path, eval или параметры shell из manifest запрещены. Внешний `tools.exec_command` получает точный `cmd`, физический `workdir`, явный `shell: '/bin/sh'`, `login: false` и конечные бюджеты. Внутренняя среда очищается фиксированным запуском и `Popen(env=...)`; несуществующее поле host API `env` не вводится. Исполняются те же выбранные и прочитанные байты, а не повторно открытый путь после hash. Внешний Python отдельно проверяется по физической идентичности; symlink и неизвестная подмена не принимаются.

Наблюдатель запускает ровно существующий CLI `--подготовить-запуск`, сохраняя полные stdout/stderr до разбора, настоящий исход, монотонные метки, ошибки, сигналы и конечную квитанцию. Приватный слот вне Git создаётся с O_EXCL/NOFOLLOW; mode/uid/nlink/physical path, fsync файлов и каталога, атомарный terminal и сохранность прежнего намерения обязательны. Неизвестный или частичный исход закрывает новый запуск вместо retry. Заявленное поле `процесс` старой функции само по себе не доказывает subprocess.

Exact JS допускает один exec_command и, только при выданном им живом session_id, ограниченные последовательные пустые write_stdin ровно этой session. Сохраняются все настоящие исходные host-объекты в порядке. Никаких вторых запусков либо чужих session. Бюджет и число ожиданий заданы независимым выбором. Внешний functions.exec должен завершиться одним настоящим native результатом; `Script running with cell ID` является неполным исходом. Версия с functions.wait в этот ACT не входит.

Читатель связывает фактические native custom_tool_call/custom_tool_call_output, точные spans/raw SHA, owner/turn/call_id и порядок. Формы input_text разбираются закрыто; лишние, повреждённые, отсутствующие или повторные блоки не скрываются. Успех требует настоящего terminal host exit0 без живой session, отдельно supervisor0 и preparation0, полных каналов и стабильности выбранного поколения. Подпись OpenAI не требуется: доверяется закреплённая семантика host-tool и независимо принятый код; защита от враждебного same-uid процесса не заявляется. Поколение/пауза после исторического исполнения не превращаются в новый допуск эффекта.

## TDD и профиль

Сначала сохранить реальные падающие адресные тесты, затем довести их до успеха через свою отчётную обёртку. Положительные сценарии используют настоящий подготовительный subprocess и временный Git с полными необходимыми фикстурами; успешный matching JSON без subprocess не принимается. Проверить подмену JS/argv/кода/входа; чужие owner/turn/call/session; повторы и пропуски; старый nonce/G; outer0 при inner nonzero; truncation; timeout/signal; неполные каналы/receipt; drift/pause; точный языковой путь и форму API, отрицательные соседние формы, spread и дубли.

Профиль различает подготовку, процесс, capture, native parsing и повторное чтение. Сохранить длины, SHA, условия и известные границы; внешний callback/model/network в замер не подставлять. Ресурсные пределы прежнего источника 131072 рамки и 120 с не повышать. Принятые57/315/137, профиль ACT18, RO R1 не повторять без конкретного нового основания. Сначала конечная лабораторная поставка; один настоящий ROOT live пилот — отдельный следующий допуск.

## Контрольная точка и ограничения

Новому этапу — назначенный Журнал, новая история/cache модели и неизменяемый завершённый LF-префикс собственного native. Прежняя ACT18 закрыта, её исходы не переписываются. Использовать обычную .7/v4, точные автор/модель/усилие, exact diff/index, recency, документы, контрольную точку и обычный exact push/readback собственной новой ветки. Сохранять текущие отказы и промежуточные содержательные коммиты; неизвестность не превращать в retry. ROOT отдельно проверяет поставку, PR и merge; ребёнок чужие refs и принимающую ветку не меняет.

R1/state2, новый эффект, live runtime, массовое восстановление, master, проекция, иная русификация и изменение правил не входят в ACT19. Пробел вне точного состава передать ROOT; закрытие этапа согласовать с координатором.
