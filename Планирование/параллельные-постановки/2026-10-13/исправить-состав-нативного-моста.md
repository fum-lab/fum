# Исправить точный состав поручения нативного моста

Продолжить тот же конечный кодовый этап по ACT20: десять продуктовых путей, собственные ref и J19, первоначальные C/native сохраняются. ACT19 из C491 остаётся происхождением ошибочного состава и не подменяется. Новый акт исправляет только служебный путь соседнего запроса; дополнительной предметной работы, изменения правил или эффекта состояния нет.

## Исполняемый состав вместо предположения

ROOT вызвал штатное подготовить_начало без установки на C491. Получены собственные запрос/отчёт, Журнал/README.md и запрос ROOT Журнал/2026-10-13_16-30-34_MSK_поставить-нативный-мост-подготовки/запрос.md. Этот точный сосед определён сортировкой каркаса; старый C490J из ACT19 для такого начала не нужен. После создания текущего J ROOT появляется также точный следующий запрос Журнал/2026-10-13_17-04-48_MSK_исправить-состав-поручения-нативного-моста/запрос.md. ACT20 дополнительно включает этот будущий выход собственного штатного фасада. Адресная RO-проверка уже после установки ROOT J повторно вычисляет пять путей и до публикации требует их полного покрытия, без установки childJ. Исполнитель остаётся на C491 и не обязан автоматически вливать новую ROOT-основу. Исходный четырёхпутевой план C491 сохранён [машинным наблюдением](../../../Планирование/решения-постановки/2026-10-13/точный-состав-начала-нативного-моста.json); новый [ACT20](../../../Планирование/дочерние-поручения/2026-10-13/повторный-цикл-состояния-узла-этап-20.json) включает все полученные служебные пути и будущий индекс recency.

Первоначальная постановка и native привязка остаются прежними. Новый ACT выбирается исполнителем из точного ROOT коммита этой коррекции с независимым SHA; ветка уже создана и проверена от C491, её историю не переписывать и ROOT HEAD в неё автоматически не вливать. Закрытая ACT18 не возобновляется. Фактические bytes/W/ref/head/index и native снова сверяются до первой записи. Предыдущие plans были только читающими; отказ и обе коррекции статуса сохраняются.

## Фиксированное асинхронное исполнение

В ACT20 сохраняется принятое уточнение ACT19: CJS-шаблон — валидное фиксированное async function-expression без самостоятельного запуска. После конечных JSON-экранированных строковых подстановок генератор добавляет один неизменный outer await/call для async module functions.exec. Независимый выбор связывает буквальные bytes/version шаблона, генератора, wrapper и полный exact JS/SHA; reader проверяет всю композицию. Произвольные команды/JS/wrapper/eval в manifest запрещены. Удалённый или заменённый await, иной запуск и неполный cell закрывают приём. CJS/Node harness — синтаксис и синтетическая фикстура, не свидетельство настоящего host.

## После лабораторной поставки

RO --подготовить-запуск не вызывает native ledger с 131072 рамками и общим120с. Его собственные Git readers имеют отдельные пределы, а не общий120с всегоCLI. После независимой приёмки моста ROOT выберет acceptedbytes/input/operation и выполнит один настоящий RO transport pilot. Затем отдельно требуется версионированно подключить bridge к эффектному допуску, проверить совместимость полного ROOT с native бюджетом и разрешить новое состояние. Старый .2 требует literal namespace fum/function_call; generic exec туда не подставляется. Bridge сам не разрешает B/state2/массовый запуск.

R1/57/315/137 и профиль ACT18 не повторяются. Принятые .1/.2/caps, parent/sourceR1, первоначальные C и actor сохраняются. Действующие остальные ограничения и TDD/профиль/коммиты/exact push/readback берутся из [полной постановки ACT19](создать-нативный-мост-подготовки.md).
