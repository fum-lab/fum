# Сделать назначение писателя ожиданий публикуемым

## Конкретная проблема

Принятый писатель ожидаемого состояния требует в Git-назначении fum.назначение-писателя-ожиданий.1 абсолютный физический корень. Публикационная проверка отклоняет настоящий локальный путь с error.posix-user-home. Точное назначение просто в приватном JSON код не принимает; непубликуемый собственный commit не допускается порядком публикации. Первое живое испытание блокируется этим стыком.

## Конечный результат

Ввести явный совместимый переход к публикуемому назначению, которое сохраняет проверяемую связь с настоящими физическим корнем, native UUID, владельцем и ref. Настоящие локальные адреса остаются в приватном runtime-входе. Публикационная проверка не ослабляется. Историческая схема .1 читается по прежнему строгому контракту; неизвестные схемы и лишние поля отклоняются.

Предпочтительный вариант для проверки: отдельная версия Git-назначения с SHA-256 канонического физического корня вместо самого локального пути. Хэш не удостоверяет полномочия; прежние проверки ACT, решения ROOT, native корня/UUID, владельца, ref, индекса, control OID и закрытой .7 сохраняются. Байты кодирования и вычисление привязки должны быть явными, чтобы разные строки пути не принимались случайно за один корень. Выбор окончательного контракта обосновывается RED и ревью.

## Переиспользование и область

Исходная основа — поставленный писатель C365, обычные ACT, решение ROOT, .7/.9, намерение, квитанция и exact push. Новый реестр, новая приватная Git-ветка, маскирование обязательного поля и исключение публикационного сканера не вводятся.

Допускаемые предметные файлы будущего независимого писателя:

- Инструменты/fum-svyaznostj-rabochej-sessii/scripts/обновление_ожиданий_узла.py
- Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_обновление_ожиданий_узла.py
- Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_обновления_ожиданий_узла.py
- Инструменты/fum-svyaznostj-rabochej-sessii/состояние-задач-узла.md

Общий читатель expected, иные правила/валидаторы/создатель коммита не меняются без отдельного конечного расширения. Собственная пара Журнала, её история модели и номерные v4, реальные навигационные соседи и два индекса выбираются до ACT. Новое исходное поручение, настоящий UUID чата, ветка и дерево ещё оформляются ROOT; эта постановка сама не разрешает запись.

## RED, GREEN, профиль и поставка

RED должен показать реальный отказ публикации прежнего назначения и отсутствие принимаемого публикуемого варианта. Добавить случаи неверного хэша корня, подмены private root/native root/ref/owner/control/ACT, лишних полей, неизвестной схемы, невозможности обхода через старую .1, дополнительного предметного файла и повторного UUID/каталога при неизвестной попытке.

GREEN подтверждает прежние 14 сценариев писателя, reader/catalog с настоящими принятыми бинарниками без новых сборок, строгую публикационную проверку нового открытого назначения и process retry без повторного коммита. При необходимости состав тестов выбирается по реально изменённому контракту; не дублировать готовые проверки механически.

Профиль обязателен: минимум три независимых процесса, прежний корпус, явные SHA всего исполняемого контура, отдельные интервалы валидации/плана/установки/фиксации/повтора. Показать дополнительные Git-вызовы и байты новой привязки. Сеть, настройка и подготовка вне чистых таймеров; вложенные интервалы не складываются.

Сохранить ограниченную контрольную точку, exact push и PR в fuma; ROOT принимает только проверенный объём. Production-expected, полномочия первого живого писателя и массовое возобновление не развёртываются этой разработкой.
