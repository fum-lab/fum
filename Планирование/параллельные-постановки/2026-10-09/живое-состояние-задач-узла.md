## Принятая основа

Писатель одного expected принят ограниченной контрольной точкой PR237: слияние 4962e784f77800d5ff83dc3b9cb905b8c9a96df1. Хранение полных наблюдений, восстановление каталога новым процессом и чтение без API уже проверены. Принятый механизм не реализуется повторно.

## Назначение первого испытания

ROOT назначает устойчивый ID узла fum-lab/fum и ID репозитория fum-lab/fum. Поколение полномочий конечного испытания: 2026-10-09-первое-живое-состояние. Путь одного expected: Память/конвейер/ожидаемое-состояние-узла.json.

Планируемый ref писателя: refs/heads/codex/dir/pamyatj--konvejyer--sostoyaniye-uzla--proba. Это отдельная ветка состояния: обычное продвижение fuma не выбирает новое поколение доверия. Физическое дерево и настоящий UUID видимого чата ещё не назначены. До независимого ACT, Git-назначения и открытого решения ROOT запись не допускается.

Первый перечень содержит одного явно выбранного живого исполнителя. Используются прежние expected, предпросмотр v2, ACT, решение ROOT, поставка и контейнер. Полнота перечня остаётся ложной; входные снимки равны null. Новый реестр задач не создаётся.

## Подготовка до эффекта

1. Сохранить исходную постановку коммитом и начать видимый чат из него в своём дереве, первоначально только для чтения.
2. Сверить настоящий native UUID, исходный OID, физический корень, ref, модель и effort. Назначить ровно один expected и конечный состав собственной пары Журнала.
3. Подготовить обычный ACT и открытое решение ROOT с реальными Git-источниками. После коммита решения D закрепить отдельный контрольный ref на D; сформировать кандидат и его raw SHA; Git-назначение A сохранить отдельно, не продвигая контрольный ref. Фикстура подтверждает отсутствие циклической ссылки.
4. Проверить публикационную границу абсолютного корня Git-назначения. Не маскировать обязательное поле и не обходить строгую схему.
5. Подготовить обычную пару Журнала штатным start до передачи писателю так, чтобы соседние запросы были сохранены исходным коммитом. Применимость этой последовательности ещё проверяется; отложенная навигация конечной передачи не заменяет обычную .7.
6. Назначить физические приватные каталоги контейнера и операции вне Git с устойчивым сохранением входа, UUID, намерения, .7/.9, квитанции и нового доверия. Временный каталог не доказывает восстановление после сбоя ОС.
7. Перед эффектом заново подтвердить актуальность ROOT-команд, владельца, источников, HEAD/ref, индекса и кандидата.

## Конечные рубежи проверки

- Создать один expected, штатно проверить и зафиксировать его; прочитать сырой коммит и подтвердить удалённую доставку.
- Запустить новый процесс с прежним входом и каталогом операции; подтвердить повтор без второго коммита.
- Прочитать expected и прежние полные наблюдения новым процессом по явному новому доверию.
- Проверить, что обычное продвижение fuma не инвалидирует доверие неизменному state ref.
- Отказ прежнему действительному доверию после обновления требует второй отдельно разрешённой конечной операции либо настоящего предшествующего trusted expected. Первое создание этого не доказывает.
- Сохранить монотонные интервалы, число API/Git-вызовов, байты, результаты и SHA. Вложенные таймеры не складываются.
- Отправки команд восстановления и массовое возобновление сессий не входят в испытание.

## Условие первого эффекта

До живого запуска исправить [публикационный контракт назначения](публикуемое-назначение-писателя-ожиданий.md): реальный абсолютный корень .1 отклоняется действующим сканером. Отдельный контрольный ref устраняет циклические ссылки. Обычная открытая пара готовится ROOT до исходного C и не получает закрытого снимка проверок.
