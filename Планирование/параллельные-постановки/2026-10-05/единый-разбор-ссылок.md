4. `Инструменты/fum-struktura-papok-zaprosov/единый-разбор-ссылок.md` — контракт и воспроизведение.

Достаточно местного объединённого прохода с прежними библиотечными helpers: reference definitions обрабатываются прежним helper, затем один монотонный внешний cursor хранит независимые границы пропуска обычного и расширенного режимов. Уже найденный обычный результат можно переиспользовать расширенным режимом. Нельзя просто заменить обычный matcher расширенным. Контрпример:

```text
[наружная [внутренняя](Запросы/old.md) `код`](target.md)
```

Прежняя реализация даёт оба destination; расширенный matcher один пропустит внутреннюю активную legacy-ссылку. Дедупликация только по прежней паре destination offsets, прежние kind/line/raw/angle и порядок сохраняются. Никакого файлового или межпроверочного кэша.

Библиотека переименования остаётся неизменной; её default lexer, mask, destination resolver и matcher не переписываются. Все чтения файлов, path/case/symlink-проверки, protected original, порядок обхода и диагностик сохраняются. Непересечение с планом переноса модели: ни подготовка_этапа_коммита.py, ни подготовка_дочернего_поручения.py, ни перенос_модели_этапа.py, ни их тесты/документации не входят. Общие фасады, guard, правила, SKILL.md, обычный остаток, продукты локальных решений и закрытые Журналы исключены. Стандартный собственный Журнал будущего исполнителя оформляется отдельно при настоящей постановке/ACT; этот черновик не расширяет полномочия.

## Адресный RED/GREEN

RED на прежнем исходнике: наблюдатель вызовов полного библиотечного inline-токенизатора на длинной открытой строке без ссылок видит 1 повторный вызов из layout; требование нового пути — 0. Одновременно проверяются неизменные mask и полный ожидаемый список токенов. Этот счётчик доказывает устранение вызова полного библиотечного токенизатора, но сам по себе не доказывает единственный обход текста. Монотонность общего cursor и отсутствие второго полного inline-обхода дополнительно проверяются обзором реализации; walltime остаётся отдельным измерением.

Семантическая матрица: inline/image/reference, angle destination/title, escapes и nested brackets; CRLF и line offsets; balanced/unbalanced backticks; вложенная внутренняя legacy-ссылка из примера выше; дубли destination spans и порядок всех полей. Ожидаемые токены задаются явно, плюс независимый старый oracle, взятый из закреплённых байтов C265. Старый oracle не импортирует новую функцию и не требует будущего OID B.

Матрица оград: backtick/tilde, разная длина, незакрытая ограда, HTML comments, indented code и front matter; active legacy снаружи отклоняется, внутри ограды/защищённого original не становится активным. Для `validate_layout` и навигации совпадают полный результат либо точный тип/текст ошибки и неизменность fixture-байтов/Git. Дрейф: успешный вызов → изменение содержимого того же пути на активную legacy-ссылку → следующий вызов отказывает → восстановление опять проходит; кэш прошлого текста не допускается. Wrong-case navigation и portable collision сохраняют прежний отказ; symlink в Журнале/пути сохраняет прежний отказ. Эти проверки не вводят новую политику регистра или symlink.

## Парный профиль

Новая процедура: 3 блока ABBA, каждый образец в новом процессе, один и тот же физический открытый corpus и точный `validate_layout(corpus)`; дополнительно прямой lexer на длинных корпусах без ссылок, с частыми ссылками и с inline-code labels. A — неизменяемые байты C265; B до коммита — неизменяемые приватные candidate-байты/SHA. После коммита B сверяется с соответствующим Git blob; будущий OID до записи профиля не требуется. Все общие first-party зависимости закреплены одинаковыми SHA. Импорт, подготовительный Git и внешние контрольные сверки HEAD/tree/index и SHA выполняются вне таймера. Штатные Git-вызовы внутри точного validate_layout(corpus), включая git ls-files, остаются внутри его walltime одинаково для A и B; выносить или подменять их нельзя. Если зависимости, corpus, H/tree/index либо argv сдвинулись, пара недействительна.

Сохраняются для каждого образца: последовательность A/B, Python, raw SHA исходника и зависимостей, SHA corpus до/после, точный argv, wall ns/exit, полный результат/ошибка и stdout/stderr SHA; ncalls полного библиотечного inline lexer и layout wrapper, mask/reference helper, число файлов/байтов/ссылок по классам. Сравниваются полные исходы и отсутствие записи. Небольшой публичный JSON — только русские ключи и относительные first-party пути, исходные ns и диапазон/медиана каждой версии; сырые pstats и локальные пути приватны. Штатное время и cProfile время не смешиваются. Профиль `validate_layout` измеряет этот предметный этап, не весь фасад и не повтор принятой приёмки C265. Выгода до будущего парного профиля — unknown.

## Порядок конечной задачи

Это самостоятельная ограниченная задача. ROOT сохраняет точные решение и постановку; приглашение создаётся штатным генератором только из их закоммиченных байтов. Настоящий видимый исполнитель получает отдельные worktree и ref от коммита постановки; до независимого ACT разрешено только чтение. Предусмотрены gpt-6.1-sol и ultra, фактическая модель и идентичность подтверждаются нативным наблюдением. UUID исполнителя, будущие коммиты, результаты RED/GREEN и выгода ещё неизвестны. Штатное Swift/LinguisticKit-преобразование закрепило имя направления «Realizovatj yedinyij razbor ssyilok» и ref `refs/heads/codex/dir/realizovatj-yedinyij-razbor-ssyilok`. Создание этого ref в собственном worktree разрешается лишь настоящему исполнителю после независимого ACT.

Четыре предметных продукта остаются единственной областью реализации. В production изменяется только тело `_markdown_link_tokens`; сигнатура, остальные тела этого файла, семантическая библиотека и фасады `.5`/`.7` сохраняются побайтно. Изменения общего допуска или правил в эту задачу не входят.

## Неизменяемая приёмочная зависимость

Существующий `Инструменты/fum-struktura-papok-zaprosov/tests/test_request_folder_layout.py` включается отдельным точным листом в ACT и в цели рецепта только для чтения, адресного запуска и штатной индексации тех же исходных байтов. Это не пятый предметный продукт. Правки, удаление, переименование и изменение режима этого файла запрещены. Закреплённая основа — `edabf43260b47c0ec3b0c8d7726e0c6fa37722c6`, raw SHA-256 — `9fdc76f6e71ea48b3a82343ddce9ba7310b32b5ccb2cdde8f299df76c74486fb`. До и после работы и перед коммитом требуется совпадение полных рабочих байтов, stage-0 и режима с исходным Git blob основы; SHA до и после сохраняются. Если будущий коммит постановки содержит другой blob, остановиться и передать противоречие ROOT, не обновляя закрепление молча. Это удовлетворяет существующему resolver `.7` и не ослабляет проверки.
