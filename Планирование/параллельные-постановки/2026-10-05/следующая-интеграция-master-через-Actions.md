# Подготовить следующую интеграцию в master через GitHub Actions

Целевой способ следующей поставки — GitHub Actions. Готовность workflow и фактическая доставка master пока не подтверждены. Работа продолжает FUM-STEP-0178 и [Issue №1](https://github.com/fum-lab/fum/issues/1), без второго общего STEP или Issue.

## Ближайшая ступень

[Поздний комментарий Issue №1](https://github.com/fum-lab/fum/issues/1#issuecomment-5979983002) задаёт один предметный CI-профиль: одна среда, ограниченная сборка FUMA, тесты JSONL либо лингвистического оператора, один сквозной сценарий сохранения и повтор в другом процессе. Первый режим работает без секретов и прав публикации. Он не заменяет полную приёмку master. Окончательный предметный профиль ещё нужно выбрать по принятому коду и зависимостям.

## Последующая проверка и доставка

Для первой поставки предпочтителен заранее созданный точный merge-коммит C с родителями [L, M]. CI повторно проверяет закрытые доказательства и доставляет тот же C, сохраняя author и committer. Создание нового merge-коммита самим CI остаётся отдельным будущим контрактом авторства; модель инициатора не приписывается bot/App.

Проверяющий комплект и policy/provenance сначала принимаются по правилам исходного master M₀. Новый workflow не разрешает собственную приёмку. После ограниченного bootstrap фиксируется M₁, выбирается точный L, создаётся C и проводится полный master gate инструментами M₁. Actions использует принятый в M₁ читатель, не исполняя приёмочный код кандидата. Отдельный режим доставки проверяет ожидаемый серверный M₁, выполняет нефорсированное продвижение именно M₁→C и подтверждает C/tree/parents/identity удалённым чтением. Новый merge поверх C не создаётся. Неизвестный исход сначала сверяется, а не повторяется вслепую.

## Наблюдённые границы

На чтении 5 октября master M=ac78d0b410395358797663dcc028150938839f06; Actions включён, отслеживаемых и зарегистрированных workflows нет. Это свидетельство среза, а не выбранная окончательная основа. Контур M закрепляет прежний L=14044dfd…; для нового L сначала нужны принятые exact policy/provenance. Старый закрытый читатель поддерживает v3-запуски/v2-снимок, а не сегодняшнюю историю v4/v3. История не преобразуется в старый формат: нужен свежий поддерживаемый отчёт либо заранее принятая совместимость. Общая пауза smoke/проекции для промежуточных fuma-коммитов не заменяет полного master gate.

Предлагаемые продуктовые выходы: один ручной workflow; конечный JSON-вход без произвольных argv; тонкий адаптер старого закрытого читателя, guard/push/readback; адресные Git-фикстуры; воспроизводимый профиль; обновление существующего руководства; policy и её provenance для выбранного L. Права записи и среда runner проверяются отдельно. Серверная защита от дрейфа, реальное выполнение workflow и будущий C остаются неизвестными до соответствующих наблюдений.
