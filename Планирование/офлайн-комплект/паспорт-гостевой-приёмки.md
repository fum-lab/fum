# Паспорт гостевой приёмки без сети

Паспорт задаёт один кандидат macOS arm64 и конечную программу проверки полного офлайн-комплекта FUM. Запуск закрыт до выполнения условий допуска. VM, модель, отключение сети и сборка продукта в первом срезе 0221 не выполнялись. [Инвентарь и границы комплекта](README.md) остаются обязательным входом, а [открытые условия](../../Вопросы/2026-09-12_03-34-42_MSK_замыкание-офлайн-комплекта-FUM.md) не считаются успешными результатами.

Ранний кандидат 0220 с macOS 15.5/Xcode 16.4 и отдельным OSS bootstrap не принят: позднее сообщение исполнителя заменило его более доказательным историческим CI-профилем. Выбранный гость 27 beta и сборочный профиль Xcode 16.2 RC/SDK 15.2 пока не имеют подтверждённой совместимости. Ни копирование бинарника, ни наличие SDK хоста не снимают это условие. Подготовка совместимого arm64 toolchain принадлежит 0220.

Последнее координационное уточнение 0220 выбирает native host macOS 15.2 `24C101`: манифест содержит 49 репозиториев и 45 SwiftPM-рёбер, либо 81 ребро вместе с build/native-связями; это сообщение владельца до проверенного коммита, а не принятый набор байтов. Замыкание остаётся отрицательным из-за DocC dist provenance, прав integration-tests, точных законных Xcode RC/SDK-байтов, установщиков Bison/CMake/Python и native-приёмки. Новый OID 0220 не является условием сохранения этого первого плана, но требуется для допуска будущего опыта.

Для альтернативного гостя 15.5 нельзя молча применять provisioning API 27 из 0216: по ответу владельца более ранний гость игнорирует эти настройки. Нужны отдельные закреплённый IPSW, подтверждение совместимости и маршрут Setup Assistant/SSH с явно учтённой ручной частью либо принятая автоматизация. Поэтому альтернатива не подменяет выбранный паспорт и остаётся закрытым условием.

Жизненный цикл, идентичность и восстановление установки получает только 0216. Сохраняются hardware model, machine identifier, auxiliary storage и диск. Прерванная VZMacOSInstaller-установка не считается поддержанно отменённой обычным pause/stop; используется отдельный принятый контракт 0216. Принятый общий Linux OID/API, подготовка macOS 0179 и их фактическая интеграция пока не подтверждены и не дописываются по аналогии.

## Допуск до первого опыта

- Получены точные принятые версии результатов 0216 и 0220; их параметры совместимы с выбранным гостем и источниками FUM. Лицензии Apple OS/SDK/инструментов прочитаны для выбранных файлов, способ личного переноса подтверждён; публичная раздача не подразумевается.
- Каждый объект из состава имеет реальные байты, размер/hash, происхождение и применимые LICENSE/NOTICE. Закрыты транзитивные зависимости, build-time загрузки, системные frameworks, исполняемые ресурсы SwiftPM, модель/tokenizer/config и toolchain bootstrap. Неполученный обязательный лист запрещает старт.
- Выбрано и поставлено собственное приложение/интерфейс с проверяемой связью с памятью и Журналом. Просмотрщик Markdown допускается как отдельная частная проверка, но не закрывает отсутствующую редакторскую функцию.
- Проверены возможность GPU/Metal либо явно выбранный совместимый CPU runtime внутри гостя, все его байты и ресурсы. Историческая работоспособность LM Studio на host не доказывает работу в VM. CPU-замена не выбирается молча.
- В комплекте нет неучтённых символических ссылок, host-путей, глобальных кэшей, скрытого git alternates или remote fallback. Предварительная установка базового гостя отделена от опыта. SDK, toolchain, runtime и модель устанавливаются из комплектных файлов после подтверждения запрета внешней сети; требующая сети активация или установка остаётся препятствием. Перенос уже установленного образа подтверждает лишь автономное использование образа и не закрывает этот критерий автономной установки.
- В начале опыта сохранены идентичность гостя, версии, полный манифест комплекта, пустое начальное рабочее состояние, ограничения времени/RAM/диска и источник измерений. Отдельно подтверждается изоляция внешней сети и ограничение общего канала.

## Карта сетевых переходов

| Потребитель               | Что может обратиться к сети                                         | Поведение автономной стадии                                                                                                 |
| ------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Git и подмодули           | clone/fetch, удалённые refs, alternates                             | Только материализованные Git-объекты/локальный bundle; проверка exact OID. Штатный сетевой init остаётся онлайн             |
| SwiftPM и 0220            | package resolve, update-checkout, bootstrap, build-script downloads | Только полный предзагруженный граф 0220 и локальные path-пакеты FUM; любое сетевое разрешение отклоняется                   |
| Cargo/Rust                | registry, git sources, rustup, build.rs                             | Полный локальный source-набор, frozen lock и offline-режим; build.rs не получает исключение из сетевого запрета             |
| Codex workspace/V8        | native archives, bindings, Bazel repositories                       | Архивы и checksum manifest уже в комплекте; исходная сборка требует полного отдельного графа                                |
| Node/npm/pnpm             | registry, postinstall, платформенные payload                        | Только выбранный npm-профиль с локальными байтами и блокировкой install hooks, пытающихся скачать недостающее               |
| LM Studio/Ollama          | каталог моделей, pull, обновление runtime                           | Модель и runtime уже установлены; разрешён только точный loopback API. Отсутствующая модель даёт отказ без pull             |
| Codex `--oss`             | подготовка модели и проверка совместимости Responses                | Один флаг не доказывает отсутствие загрузок; проверяется фактическая ветвь выбранного провайдера по закреплённым исходникам |
| ОС, Homebrew, утилиты     | softwareupdate, brew, фоновые обновления                            | Не используются для восполнения комплекта; фоновые обращения тоже попадают в наблюдение изоляции                            |
| Torrent/I2P и внешние API | peers, tracker, SAM/router, облачные endpoints                      | Используются только на отдельной онлайн-стадии. Сетевое намерение сохраняется как незавершённое                             |

Офлайн-флаги необходимы там, где они есть, но не заменяют фактическую изоляцию VM. Фиксируются попытки всех дочерних процессов, DNS и proxy/tunnel; контрольный запрос к заведомо внешнему адресу должен получить наблюдаемый отказ. Его отказ не считается полезным результатом FUM. Доступ к loopback модели не даёт разрешения обращения модели к внешнему каталогу.

## Последовательность будущей приёмки

1. Проверить комплект в чистом базовом гостевом состоянии и подтвердить отсутствие внешнего доступа. Сверить каждый файл и объявленную Git-историю. Под действующим запретом сети установить SDK, toolchain, runtime и модель из включённых файлов; сохранить отдельные исходы установки, версии, установленные пути и подписи/hash. Запустить повторный диагностический контроль изоляции. Сохранить самостоятельные результаты проверки комплекта и автономной установки.
2. Прочитать в собственном интерфейсе конкретные память, исходный запрос и отчёт; создать новую открытую запись памяти и Журнала. Закрыть и заново открыть интерфейс, проверить точные сохранённые байты и происхождение. Открытие файла внешним редактором не выдаётся за реализованный собственный интерфейс.
3. Выполнить `bootstrap`, `continue` и `show` прототипа воспроизводимого пополнения памяти разными процессами в отдельном каталоге опыта. Сверить принятые remember/compose и вывод из встроенного журнала поколения. Журнал этого прототипа и человеческий `Журнал/` проверяются отдельно.
4. Выполнить `fixture exact_roundtrip` и `fixture automation_projection` памяти структурирующих операторов. Сравнить исходные и восстановленные SHA-256 и исполненное действие. Источник операторов должен оставаться детерминированным; токены LLM для этого шага не нужны.
5. Выполнить один настоящий model-only вызов существующего LM Studio REST v0-профиля. Точный prompt — `Return the single letter A.`, `max_tokens=1`, ожидаемые аттестованные счётчики 14 входных/1 выходной токен. Сохранить реальный response hash, model/runtime identity и фактические параметры. Записанный ответ и `DeterministicEchoProvider` не принимаются.
6. Выполнить заявленные build/test собственных пакетов и выбранного профиля Codex из чистого локального source-набора. Swift toolchain используется по версии и командам 0220; пути swift/swiftc, linker/SDK и ресурсы явно сверяются. Системный toolchain не подменяет заявленный. Проверки остальных Codex-профилей имеют отдельные результаты.
7. На открытом синтетическом эпизоде проверить прерывание worker и восстановление новым процессом из долговечного состояния; затем штатную остановку и повтор VM по 0216. Сохранить входы и уже принятый результат, исключить двойное исполнение завершённых действий. Записанный harness проверяет отказный контракт, а полноценный live-сценарий требует настоящей локальной модели.
8. Попросить заведомо сетевую функцию, убедиться в понятном отказе и сохранении намерения. Повторить весь опыт на новом чистом гостевом состоянии с тем же неизменным комплектом. Сравнить логический результат и хэши детерминированных выходов; побитовую повторяемость LLM и сборок не обещать без собственного доказательства.

Будущие команды собственных прототипов берутся из их README на том же FUM OID. Точки входа: `Прототипы/воспроизводимое-пополнение-памяти/запустить.sh`, `Прототипы/память-структурирующих-операторов/запустить.sh`, `Прототипы/дерево-Markdown-документов-с-Metal/запустить.sh`, `Прототипы/живой-одноагентный-эпизод/запустить.sh`. Обёртки могут запускать SwiftPM: сначала допуск всех инструментов и сети, затем исполнение. Само перечисление команд не означает их запуск в текущей сессии.

Исторический model-профиль указывает `qwen/qwen3-0.6b` Q8_0 и `llama.cpp-mac-arm64-apple-metal-advsimd@2.27.1`. Точный весовой artifact, размер/hash, tokenizer и лицензионные условия ещё неизвестны. Transport закрепляет model/messages/max_tokens/stream, но не temperature/top-p/top-k/seed. Эти значения или явно наблюдаемые defaults должны войти в паспорт нового опыта; записывать вымышленные seed/temperature запрещено. Исторический live-эпизод допускает два вызова, бюджет 512/512 токенов и 60 секунд; эти пределы относятся к тому эпизоду, а не ко всем функциям FUM.

## Отказные сценарии RED/GREEN

| Воздействие на независимую копию набора                                            | RED — требуемый наблюдаемый отказ                                         | GREEN — восстановление без подмены опыта                                                |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Удалён обязательный файл или ресурс SwiftPM                                        | Отказ до потребителя, точный недостающий объект, работа сохранена         | Внести исходные байты с прежним hash и повторить                                        |
| Файл, Git-object или модель подменены при прежнем имени                            | Несовпадение hash/OID, результат не принят                                | Восстановить точную версию из комплектного источника                                    |
| Отсутствует crate, Git-транзитивный вход или часть V8                              | Нет fallback/download, явный незамкнутый граф                             | Исправить комплект на отдельной онлайн-стадии; новый versioned manifest и чистый повтор |
| Нет SDK/bootstrap либо PATH ведёт к иному swiftc                                   | Отказ проверки версии/пути до сборки                                      | Законно доставить закреплённые байты; подтвердить инструменты                           |
| Присутствует только прогретый кэш                                                  | Чистый гость обнаруживает неполноту; успех старой машины не засчитывается | Явный полный source-набор с hash и лицензиями                                           |
| build.rs/postinstall/model adapter пытается fetch                                  | Сетевая попытка видна, действие отказало, intent сохранён                 | Устранить скрытый fetch или пополнить объявленный набор; повтор под тем же запретом     |
| Модель отсутствует или provider не поддерживает протокол                           | Явная недоступность без pull и без фиктивного ответа                      | Совместимый уже доставленный runtime/model и настоящий вызов                            |
| Нет Metal или превышены RAM/время/диск                                             | Самостоятельный отказ функции, сохранённое незавершённое состояние        | Отдельно принятый ресурсный/CPU-профиль; не объявлять ограниченный GUI полным успехом   |
| Повреждена часть либо раздача недоступна при отсутствии полного локального объекта | Отказ до использования полного файла; offline не достраивает объект       | Полностью проверенный файл из законного онлайн-получения                                |
| SIGKILL или остановка VM между фазами                                              | Сохраняется различимая незавершённая стадия; нет двойного commit действия | Новый процесс/VM восстанавливается по принятым исходным данным и журналу                |

Недоступность раздачи при наличии полного проверенного локального файла не блокирует его автономное использование.

## Измерения и результат

Для онлайн-подготовки, упаковки/переноса, установки, полезной работы, модельного вызова, сборки/проверок и восстановления сохраняются отдельные интервалы wall-clock/монотонного времени, максимальная RAM, прирост и пик диска, объём переданных байтов и состояние кэша. Вложенное время не суммируется с родительским. Лимиты VM 4/8/80 не объявляются результатом измерения; до тяжёлой сборки требуются оценка полного набора и соразмерный пробный профиль 0220. Выход за лимит сохраняется отказом, а не скрытым увеличением ресурсов.

Итог содержит manifest SHA, версии 0216/0220/FUM, входной снимок гостя, измерения, исходы каждого пункта и точный остаток. Четыре раздельных статуса: план подготовлен; все байты получены и юридически допущены; комплект перенесён; заявленный сценарий принят без сети. Частный GREEN и исторический SUCCESS не повышают следующие статусы автоматически.
