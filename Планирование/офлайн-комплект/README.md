# Первый офлайн-комплект FUM

Первый срез FUM-STEP-0221 задаёт конечный состав переносимых материалов и программу гостевой приёмки. Это план с измеренным инвентарём исходного дерева, а не готовый дистрибутив. Подготовка полного комплекта, физический перенос и исполнение без сети ещё не приняты. [REQ0075](../../Требования/🟡-полная-переносимая-офлайн-автономность-FUM.md) действует целиком, включая три профиля Codex CLI и локальную модельную функцию.

Первый срез сохраняется промежуточной контрольной точкой по координационному решению: собственный финальный smoke и новая проекция не выполнялись. Документационные критерии ожидают совместной приёмки по правилам master в интеграционном дереве; прежняя проекция отстаёт от этого канонического плана. Подробности и точные свидетельства — в [отчёте](../../Журнал/2026-09-12_03-34-42_MSK_спланировать-офлайн-комплект-FUM/отчёт.md).

Вход для инвентаризации — FUM `01b329cb49f4c5a5655fab4c16d7ea3a3ebf55a5`. [Полный файловый инвентарь](инвентарь-дерева-FUM.txt) содержит 14 684 blob и один gitlink; сумма размеров blob — 277 045 582 байта. [Наблюдение](наблюдение-дерева-FUM.json) хранит дерево, команду, SHA-256 инвентаря и разбиение по каталогам. Это размеры распакованных файлов выбранного дерева: Git-история, бинарники инструментов, SDK, модель, VM и будущая упаковка сюда не включены. Большие файлы не переносились. Позднейшая поставка этого плана имеет собственный коммит и не меняет выбранный вход задним числом.

Историческая постановка `d3b1a2d6d1804af028211353592e5d4b205dc990`, дерево `9015f8153a0b45e77df7a21d024ab2bc068c2443`, отличается от базы запуска. Её десять файлов, текущие десять файлов запуска и поздние уточнения рассмотрены как источники. Исторический реестр не является поставкой исполнителя.

## Что должен сделать человек в госте

Человек открывает переданную память, находит исходный запрос и связанный отчёт, сохраняет новую открытую запись своего опыта, выполняет детерминированный оператор над известным входом, проверяет его результат и запускает одну настоящую локальную модельную функцию. После прерывания другой процесс восстанавливает принятые входы, результат и незавершённое намерение. Сборка и проверки используют только перечисленные байты. Кнопка или команда сетевого действия сообщает: «Недоступно без сети. Намерение сохранено; выполнение не начато». Это требуемое поведение будущего опыта, а не уже подключённая функция приложения.

Успех частного оператора не закрывает интерфейс, модель, сборку и восстановление всего FUM. Записанное предложение модели допускается только как тестовая фикстура. Оно не засчитывается в строку локального модельного исполнения.

## Правило учёта каждого объекта

У каждой строки есть потребитель, точная идентичность, происхождение, перечень непосредственных входов, размер и хэш реального файла, путь внутри комплекта, лицензии/уведомления и допустимый способ доставки. Размер или SHA-256 ещё не полученного бинарника записывается как неизвестный, а не как ноль. Полный OID исходников не становится хэшем собранного бинарника. Нижний уровень зависимостей раскрывается рекурсивно до файловых листьев; неизвестное ребро запрещает утверждение о замкнутости.

Проверяются пять независимых признаков: идентичность установлена; лицензии прочитаны; байты получены; байты включены в комплект; потребитель принят в госте. Между ними нет автоматического перехода. Статус раздачи учитывается отдельно. Реестр источников хранит неизменные исходные байты; манифест сборки — версии преобразований и параметры; результат — собственные хэши; неизвестное — конкретное условие получения свидетельства. Так применяется принцип сообщения 252 без заявления, что весь принцип уже реализован.

## Онлайн-подготовка, перенос и автономная работа

1. На отдельной разрешённой онлайн-стадии закрепить все версии, проверить зеркала штатным механизмом Git-зависимостей, материализовать полные Git-объекты и не-Git входы. 0220 строит toolchain своим способом; 0216 предоставляет VM своим способом. Фиксируются активные условные ветви, лицензии, хэши, размеры, symlink targets и отсутствие неучтённых внешних путей.
2. Создать комплект с неизменяемым манифестом: исходники/история, устанавливаемые продукты, runtime, SDK, данные/модель, уведомления, конфигурация, открытый вход опыта и команды проверки. Обязательный недоставленный объект закрывает выпуск. Прогретый кэш не засчитывается; допустим лишь явно экспортированный, полностью инвентаризованный и проверенный локальный источник пакетов.
3. Передать реальные файлы через ограниченный read-only носитель/образ данных. В госте сверить каждый размер/hash, OID checkout и отсутствие ссылок наружу. После копирования отключить общий каталог; исходник комплекта остаётся неизменяемым, рабочая память и результаты лежат отдельно. SSH-конфигурация не даёт гостю proxy/tunnel к интернету.
4. Только после подготовки гостя запретить его внешний сетевой доступ средствами принятого 0216 backend. Глобальная сеть хоста остаётся прежней. Loopback допускается только для заявленного локального model server. Изоляция, DNS, маршруты и счётчики попыток являются отдельными свидетельствами; пустой список сетевых интерфейсов сам по себе не является успешным модельным опытом.
5. Установка и повтор используют исключительно комплект. Git fetch/clone по URL, SwiftPM resolution по сети, Cargo/rustup downloads, npm/pnpm install по реестру, Homebrew, softwareupdate, model pull и Torrent запрещены. Вызов необходимого сетевого действия сохраняет понятный отказ и незавершённое намерение.

## Крупные объекты вне Git

Git хранит описатель, а файловая система вне Git — полный объект. Описатель содержит тип/версию, происхождение, точный размер, SHA-256 полного файла, формат и порядок частей, размер/hash каждой части, параметры Torrent, лицензии и потребителей. Информационный хэш Torrent и SHA-256 полного файла имеют разные роли. При сборке частей проверяются порядок, отсутствие пропусков/лишних частей и полный хэш результата.

Недокачанный файл хранится отдельно от принятого. Прерванное получение продолжается только для того же описателя; повреждённая часть изолируется и получается заново на онлайн-стадии; смена версии создаёт новый объект и не затирает принятый. Недоступная раздача не отменяет существующий проверенный локальный файл и не доказывает его наличие. В госте повторное получение не выполняется: неполнота даёт отказ до использования. Публичный torrent создаётся лишь для объекта с подтверждённым правом распространения; SDK, приватные runtime-данные и ключи получают отдельный разрешённый маршрут либо остаются препятствием.

## Зависимости и следующий конечный срез

Версии планов 0220/0216 и несовместимость их первых профилей фиксирует [паспорт гостевой приёмки](паспорт-гостевой-приёмки.md). Ни текущая постановка, ни сообщение исполнителя не являются принятой реализацией. Открытые условия сведены в [вопрос о замыкании комплекта](../../Вопросы/2026-09-12_03-34-42_MSK_замыкание-офлайн-комплекта-FUM.md).

Следующий исполняемый срез — локальная проверка комплектности одного заранее подготовленного набора без запуска VM и без скачивания. Вход: принятые версии 0216/0220, полный манифест байтов, собственные исходники интерфейса, законно полученные SDK/runtime/модель, открытая фикстура и разрешённый путь данных вне Git. Выход: отчёт о каждом объекте и ребре, отказ до исполнения при пропуске/подмене, сохранённое незавершённое состояние и воспроизводимые команды. Инвентаризацию сборочного графа переиспользовать из 0220; здесь допускается лишь композиция результатов для FUM. Эта постановка не запускается автоматически и не назначает общий оркестратор.

После замыкания набора отдельно принимается гостевой опыт по паспорту. Текущий срез сохраняет исходники плана, конечные критерии, полученные наблюдения и явный остаток. Он не объявляет выполненными полный STEP0221, REQ0075, все платформы или принцип полного воспроизведения состояния.
