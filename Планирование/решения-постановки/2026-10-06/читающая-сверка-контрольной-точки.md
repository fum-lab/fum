# Читающая сверка контрольной точки и доставки — STEP0245

Статус: согласованный ROOT предметный контракт, не ACT и не допуск исполнителя. ROOT UUID 01a07d3d-d376-7ad2-aafc-67e4c25a67eb. Начало — после приёмки C278, в отдельном видимом чате, worktree и своей ветке codex/. ROOT закрепляет фактический следующий коммит fuma, новый UUID исполнителя, каноническую пару времени и новый ACT. Эти неизвестные значения не подставлены. Интеграция и приёмка — только ROOT. Чужие деревья целиком read-only.

Штатная собственная пара Журнала, история модели, первичное поручение и реальные v4 ограничиваются новым J исполнителя, который ROOT задаст в ACT; служебные правки — Журнал/README.md, Индексы/markdown-файлы-по-времени-редактирования.md и точные соседние ссылки, только если они перечислены ROOT заранее. Другие README/индексы, карточки, правила, существующие production/test/profile и общий builder не входят в предметную область. Это не резервирование служебных путей. Если холодному CLI для корректности нужна правка существующей production-зависимости, исполнитель сохраняет конкретный предел и запрашивает расширение у ROOT, а не исправляет её самовольно.

## Первая поддержанная операция

Один холодный вход: python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/сверить-контрольную-точку.py --вход <приватный JSON> --sha256 <SHA256 его точных байтов>.

Новый узкий выбор имеет только: схема; корень; ветка; коммит; файлы {подготовка {путь, sha256}, квитанция {путь, sha256}}; публикация. Публикация = null для локальной сверки либо {адрес_sha256} для отдельного чтения точного origin/ref/OID. Имена схемы выбора/успеха/отказа объявляются в инструкции и фиксируются тестами, без притворства существующим stock schema. Отдельные параметры создания, descriptor, native JSONL, cursor и новая подготовка не принимаются. Корень физический, ref полный refs/heads/…, C полный буквальный OID; пути входа/подготовки/квитанции приватные физические обычные файлы с точным SHA. Не принимать повторные JSON-ключи, NaN, неизвестные поля/схемы или повреждённый JSON.

Поддержка только завершённой ROOT fum.создание-коммита.5 / режим контрольная-точка, сохранённой fum.подготовленный-коммит.7 и fum.квитанция-создания-коммита.1. Обычная точка с одним родителем и настоящий merge с прежним порядком двух родителей. Текущие HEAD/ref обязаны совпадать с независимо выбранными C/ref до и после чтения. Поздний HEAD, дочерние .7/.9 и прежние схемы — явный отказ без подбора другого читателя; историческая .7/.9 уже имеет отдельный инструмент.

Сначала чтение закреплённого комплекта и проверка схем/адресов/подготовка_sha256. Процесс квитанции должен иметь ровно штатные поля код/тайм_аут/исполнение_завершено/прерывание, значения 0/false/true/null; состояние проверен. Отрицательный, активный или неизвестный производитель блокирует объектную и удалённую сверку. Полный результат квитанции — ровно шесть штатных полей: коммит, дерево, родители, автор, коммиттер, сообщение_sha256. Сверить ожидание с сохранённой подготовкой, затем raw Git и полное равенство этих шести полей, отдельно author/committer и явные даты. Подготовка и квитанция повторно сверяются при закрытии удержанных читающих дескрипторов, включая отказ. Дрейф HEAD/ref/байтов — отказ.

Списки сохраняют исходные значения и штатный смысл: не сортировать только одну сторону; родители остаются упорядоченными. Конечный состав коммита проверяется на подмножество разрешённых целей, не на равенство: разрешённые неизменённые цели допустимы. Git-mode и локальный stat.S_IMODE не приравниваются: Git100644/FS0600 разрешён. Контроль типа/режима Git и закреплённого снимка сохраняется; chmod отсутствует. Не запускать предкоммитный ранний состав после коммита вместо чтения квитанции и не перечитывать native/model/v4 для реконструкции допуска. Результат сверки не обновляет готовность и не доказывает завершение всей ROOT.

При публикация != null: один origin, одинаковые fetch/push адреса, выбранный SHA адреса; ls-remote --refs для точного полного ref даёт ровно выбранный C; адреса и локальные C/ref неизменны после чтения. Это самостоятельный факт remote readback. CLI не принимает/запускает push и не подтверждает его exit code: неизвестный исход старого push остаётся неизвестным. Не выводить общий Boolean «вся доставка успешна» из одного OID. Ошибка или неизвестный результат remote даёт отказ; повтор push отсутствует.

Успех: JSON только stdout, code0; отказ: JSON только stderr, code2, без частичного успешного JSON. Успех содержит штатный шестипольный результат и отдельно null либо подтверждённые ref/OID/адрес_sha256 remote. Нет output/cache/lock путей и записей самого CLI. Запуск работает из чистого клона по документированной команде, без частного sys.path/PYTHONPATH; Python bytecode отключён самим поддержанным входом до загрузки зависимостей. Валидация не опирается на assert и сохраняется при -O.

## Имеющиеся API и важные пределы

создание_коммита.py:124 разобрать_подготовку; 522–553 сверить_ожидание_квитанции — чистая связь ожидания с подготовкой; 498–519 проверить_объект — raw OID/дерево/порядок родителей/message/раздельные identities; 555–580 восстановить — успешный процесс/полный результат/ref/HEAD/raw. Однако восстановить НЕ проверяет подготовка_sha256: штатный вызывающий путь делает это отдельно на 695–696. Создать/_создать_проверенный_коммит использовать нельзя: до восстановления он создаёт .lock (690–691), а публичный создать затем выполняет автообзор (805–810).

историческая_квитанция.py:156–210 Снимки.читать/закрыть — O_RDONLY/NOFOLLOW, стабильность дескриптора/пути/режима/байтов; 221–231 Гит.читать — --no-optional-locks/--no-replace-objects/--no-lazy-fetch, очищенная GIT-среда, выключенные trace2-приёмники. Это существующие примитивы для чтения; контракт/прочитать исторического .7/.9 не вызывать для ROOT .5. Создание_коммита.гит (174–234) — общий transport без этих RO-флагов; прямой вызов восстановить не освобождает от доказательства отсутствия lazy-fetch/trace/index-lock записей. Узкий локальный RO-адаптер в новом CLI допустим, правка общего создателя не входит в область. При использовании исторической сырая_сверка учесть её более узкие raw-заголовки/даты (461–489): нельзя незаметно ужесточить поддержанный stock контракт; паритет со stock raw-проверкой обязателен.

типизированная_контрольная_точка.py:76–87 сверить_вход показывает точную связь ROOT .5 с подготовкой .7 и физическим адресом. Его ранний_допуск/готово/создать не являются новым читающим CLI. Проверенная_поставка_сообщений.py в fum-konvejyer-proizvodnyikh-vetok:132–143 — имеющаяся точная проверка origin/ref/OID; использовать сам проверочный принцип/функцию, не запускать старый конвейер.

## Конечные проверки

Один новый модуль test_сверки_контрольной_точки.py. Реальные маленькие Git-фикстуры .5 создаются штатным producer до запуска читателя; подготовка/profile setup не входят в измеряемое чтение. Обязательные независимые группы RED/GREEN:
1. 0184: существующая подготовка + успешная квитанция; отсутствие/подмена SHA/повреждённый либо unsupported комплект. Проверить, что start/prepare/ready/create не вызваны.
2. 0185: Git100644/FS0600 проходит без chmod; реальная подмена режима/типа/зафиксированных байтов/символическая ссылка отвергается; index/refs/файлы/права до/после сохраняются на успехе и отказе.
3. 0186: модельный author и committer FUM различаются и проходят; отдельно автор, committer, явная дата, дерево/message/parents подменяются и отвергаются; обычный и настоящий merge результаты совпадают с шестью stock полями.
4. 0187: несортированный штатный разрешённый список и неизменённая разрешённая цель проходят; путь вне списка/нарушенный обязательный порядок родителей отвергается. Никакой асимметричной сортировки.
5. 0188: холодный subprocess из чистого клона, отсутствующие PYTHONPATH/частные sys.path, отсутствие pyc/lock/cache; local bare remote совпадает/не совпадает/двусмысленный origin; неизвестный push не превращается в code0 процесса push и не повторяется.
6. 0079/0002: receipt producer code!=0/unknown/unfinished блокирует все зависимые чтения; drift C/ref/байтов до и во время сверки; refusal JSON/code2 и отсутствие новых файлов. Исторический 0079/0001 не переписывается.
7. CLI/API паритет полного результата, повторные JSON-ключи/неизвестные поля, -O без потери валидации; профиль отказывает при -O/PYTHONOPTIMIZE1/2 до любых фикстур/выходов, занятые/символические и поздно занятые output paths не перезаписываются.

Адресный argv: python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_сверки_контрольной_точки.py. Зафиксировать реальный RED и затем GREEN каждой группы. Старые test_создание_коммита.py и test_типизированной_контрольной_точки.py сохраняются байт-в-байт; их fixture/API материалы можно переиспользовать без импорта TestCase в discovery как новых тестов. Не повторять уже принятые 131/40 тестов либо профили PR215/216 без новых изменений/concerns. Новый контур и его реальные зависимости проверяются собственными адресными тестами; full smoke и проекция не входят в поручение.

Профиль: один новый профиль_сверки_контрольной_точки.py; малые обычная .5 и merge .5; минимум четыре чередующиеся ABBA-раунда stock читающих примитивов / нового API на одних неизменных fixture-байтах, плюс отдельный диагностический запуск счётчиков вне таймера. Сравнивать полные результаты/отказы с явной проверкой, не assert. Счётчики, Mock и observer hooks вне чистых измерений. Setup/import, local read, cold CLI overhead и bare-remote readback сохраняются отдельными интервалами; не складывать их и не заявлять ускорение всего рабочего цикла. Записывать ns/code, реальные полученные байты/число чтений/вызовов Git, SHA входов/исходных dependency bytes и отсутствие записи. Все выходы профиля заранее перечислены, новые приватные O_EXCL/0600; занятое имя, symlink и поздняя коллизия дают отказ, прежний результат сохраняется. Публичная сводка не содержит локальных приватных путей.

## Возврат результата

Ребёнок передаёт точные base/commit/tree/parents/full ref, состав четырёх продуктов + фактического собственного J/заранее объявленных служебных целей, сохранённые RED/GREEN/чистый профиль/сырые исходы и приватный manifest передачи. Ограничения и неуспешные попытки сохраняются; локальный коммит не объявляется доставкой, доставка подтверждается отдельным readback. ROOT независимо проверяет до интеграции. Карточки сбоев и STEP0245 не закрываются исполнителем автоматически. STEP0235 повторная .5-композиция, общий builder/preflight, modeltransfer, guard и новые кэши исключены из этого поручения.
