# Конечный вход проверки состояния задач узла

ROOT закрепляет ограниченный вход H4 для наблюдения и повторного чтения двух существующих чатов.

- Устойчивый ID узла: 7a1fbd87-f9cb-4de4-9614-356d6ac3bb91.
- Устойчивый ID репозитория: a781b08d-ffbf-4732-83de-de97b58d5ddc.
- Координатор и владелец ожидаемого состояния: 01a07d3d-d376-7ad2-aafc-67e4c25a67eb.
- Поколение полномочий для этого конечного входа: 1.

ID назначены координатором отдельно; они не вычислены из URL, пути каталога или UUID чата. Это закрепление конечной проверки; рабочая ветка состояния production и её единственный писатель ещё не развёрнуты.

## Выбранные задачи

1. «Выбирать следующую работу между этапами», 01a11b86-3064-7152-9df2-eda220ebc004, получает [сохранённое решение H4](состояние-задачи-восстановления.json). Поручение уже принято, работа не завершена. Ход взят из реального наблюдения Codex Desktop этого среза, без утверждения его будущей актуальности.
2. «Soglasovatj obratnuyu dostavku i kontroljnuyu…», 01a11c7c-0789-7350-a989-7d3a05dd5406, получает [сохранённое решение доставки](состояние-задачи-доставки.json). Ремонт поставлен коммитом ec5532bfe5518c29cbae34ff3bf1fb29e31b540e; исполнитель остановил запись и ожидает решения координатора. Наблюдённый результат «готов» не объявляется приёмкой. Ход взят из адресного наблюдения Codex Desktop этого среза; новый ход потребует повторной сверки.

Полнота перечня равна false: это два явно выбранных чата, а не полный список активных задач узла. Старое состояние «открыт» и остаток этапа сверяются с новым наблюдением; закончившийся ход не доказывает завершения задачи. Поля эффектов относятся только к выбранному событию подготовки конечного читающего входа H4: контроллер не отправлял сообщений и не изменял репозиторий. Уже состоявшиеся ROOT-доставка ACT и Git-публикация сохранены прежними свидетельствами и этим значением не отрицаются. Новую отправку эта запись не разрешает.

## Порядок конечной проверки

После фиксации этого решения ребёнок вправе создать ожидаемый манифест fum.ожидаемое-состояние-узла.1 только внутри своей уже назначенной новой папки Журнала. Источник основания, независимый выбор, ACT и решения ROOT привязываются к точным принятым Git-объектам, путям и SHA. У обоих исполнителей снимок=null, доставка=null; необязательная_инфраструктура=false.

Ребёнок сохраняет манифест контрольным коммитом своей ветки и возвращает его полный OID, путь и SHA. ROOT отдельно выбирает приватный вход доверия к точному childref и этому OID. До отдельного выбора это только кандидат, а не действующий источник ожидаемого состояния. Во время конечной проверки ref остаётся неподвижным. Дрейф, пропавший объект, несовпадение ACT или решения закрывают допуск без fetch и без молчаливого обновления ожиданий.

Новый процесс читает выбранное ожидаемое состояние из Git, получает адресные ответы реального MCP read_thread, сохраняет полный доступный объект до компактного разбора и повторяет чтение сохранённого контейнера после перезапуска процесса. Выдача MCP может содержать ограниченную историю; она не объявляется полным HTTP-потоком или всей историей чата. Ответы и приватный trust остаются вне публикуемого Git-слоя. Применяется лимит H4 без усечения переполненного результата.

Ни send, ни create, ни автоматическое возобновление чатов этой проверкой не разрешаются. Перезапуск относится только к процессу контроллера; восстановление после аварии Codex Desktop, ОС или питания требует отдельного свидетельства. Производственный запуск остаётся следующим этапом после приёмки кода H4 и проверки этого входа.
