# Возобновить автоматические шаги после активации веточного барьера

Проектные `UserPromptSubmit`, `PreToolUse` и `Stop` настроены, но текущий runtime показывает их как `untrusted` и поэтому пропускает до исполнения. Автоматический запуск следующей проектной задачи при таком состоянии запрещён. Пауза снимается только после явного пользовательского одобрения точных определений hooks и проверки фактического сигнала допуска в новой задаче.

## Задача

После отдельного явного одобрения пользователя активировать текущие хэши трёх проектных command hooks, проверить полный разрешённый список hook-источников и фактическое исполнение барьера. Затем заменить эту паузу готовым шагом подготовки паспорта первого коробочного среза со свежим `step_id`; сам паспорт в рамках активации hooks не создавать.

## Критерии завершения

- Пользователь просмотрел и явно одобрил точные определения `UserPromptSubmit`, `PreToolUse` и `Stop` из `.codex/config.toml`; агент не выводит такое одобрение из общей просьбы исправить барьер.
- Новый read-only снимок `hooks/list` показывает все три текущих project handler как `enabled` и `trusted`, без предупреждений и ошибок; полный список не содержит второго активного `Stop`, способного продолжить ход.
- Новая задача получает `FUM-BRANCH-TASK-GATE: admitted-v1` именно из дополнительного developer-контекста `UserPromptSubmit`, а состояние барьера подтверждает владение текущего хода до первой записи.
- Автономные тесты `fum-branch-task-gate`, проверка записи следующего шага и полный smoke-check проходят без сети и секретов.
- Запись `master` получает новый готовый шаг подготовки паспорта первого коробочного среза со свежим `step_id`; до выполнения этих критериев состояние остаётся `paused`.

## Отложенный проектный шаг

После активации нужно восстановить подготовку `Документация/36-паспорт-документационного-прототипа-и-первого-коробочного-среза.md`. Этот шаг должен отделить наблюдаемый контур человек — Codex — Obsidian-хранилище и принятый CLI-архиватор от пока проектируемого коробочного сервиса, задать первый пользовательский сценарий и автономную приёмку, довести checklist стадии `01` до `5 из 6`, не начинать реализацию коробочной стадии и затем поставить ветку на отдельную паузу перед переходом к стадии `02`.
