# Восстановить автозапуск после неоднозначного результата резервации

[Карточка шага](../../Глоссарий/карточка-шага.md) сохраняет один атомарный плановый шаг и его происхождение отдельно от веточного выбора.

## Задача

Через TDD сделать heartbeat-диспетчер устойчивым к потере ответа мутирующего `claim`: добавить идемпотентное fenced-восстановление собственной попытки, которое либо безопасно продолжает создание задачи, либо останавливается без дубля и без снятия чужого поколения.

## Результат

Через TDD введён клиентский `lease_id`: heartbeat создаёт свежий канонический UUID до claim, а точный повтор той же пары `branch_ref` и `step_id` с тем же UUID идемпотентно подтверждает собственную попытку после потерянного ответа. Другой UUID получает `already_claimed` без раскрытия чужого lease, а в пределах одной ветки прежний UUID нельзя переиспользовать для нового поколения.

Оба recent-снимка и поиск сохранённого проекта перенесены до claim, поэтому зависание долгого read-only host-вызова больше не оставляет резервацию. Повтор claim разрешён только до первого `create_thread`; неоднозначный результат создания по-прежнему сохраняет бессрочный claim и требует внешне подтверждённого fenced-восстановления без TTL и без ручного изменения Git-ссылки.

Шаблон heartbeat, локальный контракт, активная автоматизация и автономные тесты согласованы. Прежняя зависшая резервация `FUM-STEP-0024` снята точным compare-and-delete после повторного подтверждения отсутствия созданной задачи; следующий плановый тик может заново пройти полный fail-closed-протокол.
