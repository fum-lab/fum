# Автоматически разделять точные публикационные исходники и Markdown-представления

## Задача

Автоматизировать сохранение точных байтов публикации и SHA в неизменном поле JSON и отдельного Markdown-представления с собственными метаданными. Исправление J166 вручную локализовало сравнение; общего автоматического механизма ещё нет.

## Почему сейчас

Адресная проверка J166 7f5b6dfc сравнивала SHA опубликованного текста PR с Markdown после добавления recency. Проверка отказала; исходник не потерян.

## Критерии завершения

- Оригинал после recency остаётся побайтно тем же; изменение оригинала выявляется отдельно. Управляемое представление воспроизводится из оригинала и проверяется по своему контракту, без повторного отказа на добавленных метаданных.
