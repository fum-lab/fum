# Карточки шагов FUM

Каталог хранит атомарные [карточки шагов](../../Глоссарий/карточка-шага.md), из которых формируется общий пул практических продолжений и выбирается [следующий шаг ветки](../../Глоссарий/следующий-шаг-ветки.md). Одна карточка имеет неизменяемый `FUM-STEP-NNNN`; её положение в индексе, описательное имя файла и веточный выбор не задают идентичность.

Карточка со статусом active описывает задачу, причину актуальности, критерии завершения и источники. Исторические статусы completed, absorbed и withdrawn сохраняют задачу, итог и происхождение. Статус карточки не равен режиму веточного кандидата automatic, paused или blocked, вычисленному runtime-статусу ready/paused либо состоянию набора done.

## Правила

- Новый практический кандидат создаётся отдельной карточкой и добавляется в этот полный индекс.
- card_id назначается один раз, не меняется и после удаления карточки не переиспользуется.
- Имя файла имеет вид `<эмодзи>-FUM-STEP-NNNN-<краткое-название>.md`: `🟡` соответствует `active`, `✅` — `completed`, `🧩` — `absorbed`, `🗑️` — `withdrawn`.
- Номер в имени точно совпадает с `card_id`, а краткое название остаётся непустым описанием из букв и цифр, разделённых одиночными дефисами; полное имя не превышает 255 байт UTF-8.
- Каталог остаётся плоским: карточки лежат непосредственно рядом с индексом, а точный корневой `README.md` — единственный Markdown-файл, не являющийся карточкой.
- Смена жизненного статуса или уточнение краткого названия выполняется командой `rename-step-card.py` автоматизации `fum-reyestr-planirovaniya`; она использует `git mv` и обновляет живые текстовые пути. Режим веточного кандидата и вычисленный статус запуска не меняют эмодзи карточки.
- Актуальная карточка должна иметь проверяемые критерии до выбора веткой.
- Перед включением в рабочий набор ветки широкая задача декомпозируется на карточки с одной независимо проверяемой поставкой. Карточка, аттестованная как `dispatch=automatic`, допустима для прямого выбора задачей-продолжением, учитывает обязательное чтение, проверки и атомарную передачу и с высокой вероятностью должна помещаться в одно свежее контекстное окно; неизвестная помещаемость требует дальнейшего разбиения, а не выдуманного токен-бюджета.
- Выполненная, поглощённая или снятая карточка не удаляется и не может быть выбрана следующим шагом.
- Веточный селектор хранит только выбор, его состояние и версионный step_id; задача и критерии читаются из карточки.

## Смена статуса или имени

Сначала приведи разделы карточки к целевому статусу. Если старый путь выбран веточным рабочим набором, удали выполненного кандидата либо заранее запиши новое имя и свежий `step_id`; автоматизация не переносит старое поколение запуска молча. Затем выполни:

```bash
python3 Инструменты/fum-reyestr-planirovaniya/scripts/rename-step-card.py \
  --card-id FUM-STEP-NNNN \
  --status completed
```

Для одновременного уточнения имени добавь `--description новое-краткое-название`. Команда синхронизирует TOML-статус, эмодзи имени, строку этого индекса и точные вхождения прежнего имени в живых UTF-8 файлах. Дословный раздел исходного пользовательского запроса и сырые материалы `Источники/` сохраняются; машинный реестр, recency и граф после операции пересобираются штатными генераторами.

## Легенда статусов

- `🟡 Актуально` — карточка доступна для планирования;
- `✅ Выполнено` — шаг завершён и хранит результат;
- `🧩 Поглощено` — шаг реализован или учтён другой карточкой;
- `🗑️ Снято` — шаг осознанно исключён из пула.
