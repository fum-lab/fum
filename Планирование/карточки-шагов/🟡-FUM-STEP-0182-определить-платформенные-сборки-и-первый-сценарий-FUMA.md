# Определить платформенные сборки и первый сценарий FUMA

## Задача

Подготовить проверяемую матрицу и воспроизводимый первый пользовательский сценарий FUMA для всех целевых платформ. На этой основе выделить платформенные реализации с отдельными свидетельствами запуска и общей проверяемой логикой.

## Почему сейчас

Пользователь потребовал запускаемый проект FUMA на 14 платформах и дополнил перечень PlayStation и Xbox, затем исключил Microsoft Windows Holographic. Текущая цель охватывает 15 платформ и семейств, а последующее поручение добавляет Web в Safari, Chrome и Firefox. Автоматизации настройки GitHub Actions, macOS, Linux и Windows уже запланированы, но подготовка среды не заменяет продуктовую поддержку.

## Критерии завершения

- Матрица полностью покрывает FUM-REQ-0046. Для каждой строки установлены версия, архитектура, сборочная среда, устройство или симулятор, способ установки и доступность инструментов.
- До архитектурной реализации определён первый полезный сценарий и способ взаимодействия на каждом классе устройств. Влияющие на смысл вопросы о самостоятельности приложения и распределённом исполнении уточнены с пользователем.
- Выделены общая логика, совместимые данные и платформенные адаптеры. Переносимость Swift-пакетов проверена; неподтверждённая возможность одной интерфейсной технологии на всех платформах не используется как предпосылка.
- Для SDK, подписания, магазинов, консолей и устройств проверены официальные актуальные источники и условия доступа. Ограниченные SDK и учётные данные не копируются в открытый репозиторий.
- Собственные реализации и открытые фикстуры находятся в монорепозитории; общее описание зависимостей используется автоматизациями окружения и CI.
- Для каждого профиля задан автоматизируемый сценарий из чистого клона: подготовка, сборка, установка, запуск и проверка результата. Различаются локальная проверка, физическое устройство, симулятор и публикация.
- Первый проверенный вертикальный сценарий сопровождается RED/GREEN, профилем, решением об оптимизации и свидетельствами точного коммита. Остальные платформы получают непересекающиеся шаги с критериями приёмки; первый успех не объявляет готовность остальных.
- Человек получает понятную инструкцию выбора платформы, запуска и чтения результата. Незавершённые строки матрицы, внешние зависимости и следующие действия видны явно.

- Для графических путей матрица включает Metal, DirectX и Vulkan согласно FUM-REQ-0047; Mantle заменён пользователем на Vulkan. Версии и применимые возможности выбираются после проверки. Браузерный путь задаётся отдельно и проверяется в каждом целевом браузере.

## План применения Swift System

Пользователь выбрал Swift System для системных интерфейсов Swift-части FUMA. План относит к библиотеке только явно предоставленные ею низкоуровневые интерфейсы и дескрипторы ресурсов. Остальные нужные функции определяются отдельно по платформенным API. Это уточняет выбор системного слоя в существующей FUM-STEP-0182 и не заменяет её полные критерии завершения.

Опорное чтение закреплено на версии 1.8.1. Это версия исследования, окончательный выбор зависимости ещё не выполнен. Согласно [README этой версии](https://raw.githubusercontent.com/apple/swift-system/1.8.1/README.md), пакет отражает платформенные системные интерфейсы, а единая межплатформенная абстракция не обещана. Darwin/POSIX API названы стабильными, Windows API — нестабильными. Для семейства 1.7.0–1.8.x указаны Swift 6.1 и Xcode 16.3 или новее; отдельные API имеют дополнительные условия.

| Предметная область | Подтверждённый интерфейс и граница |
| --- | --- |
| Представление пути | [FilePath](https://raw.githubusercontent.com/apple/swift-system/1.8.1/Sources/System/FilePath/FilePath.swift): синтаксис и представление пути; сравнение не доказывает тождество файлового объекта. |
| Файловый ввод-вывод | [FileDescriptor и операции](https://raw.githubusercontent.com/apple/swift-system/1.8.1/Sources/System/FileOperations.swift): open, close, seek, read, write и другие объявленные операции; доступность проверяется для конкретной перегрузки и ОС. |
| Ошибки и файловые атрибуты | Errno и [FilePermissions](https://raw.githubusercontent.com/apple/swift-system/1.8.1/Sources/System/FilePermissions.swift); биты доступа не предоставляют приложению системных полномочий. [Stat](https://raw.githubusercontent.com/apple/swift-system/1.8.1/Sources/System/FileSystem/Stat.swift) в этой версии исключён для Windows. |
| Ресурсы Darwin | [Mach.Port](https://raw.githubusercontent.com/apple/swift-system/1.8.1/Sources/System/MachPort.swift) и права receive/send/send-once относятся к Darwin. |
| Асинхронный ввод-вывод Linux | [IORing](https://raw.githubusercontent.com/apple/swift-system/1.8.1/Sources/System/IORing/IORing.swift) требует Linux, compiler 6.2 или новее, Lifetimes и реальную возможность io_uring; возможен notSupported. Одного общего минимального Swift 6.1 недостаточно. |

Ближайший результат уточнения — матрица: нужная операция → точное объявление API и версия пакета → toolchain и ОС/SDK → условия доступа → требуемый платформенный адаптер → проверяемый сценарий. Неподтверждённая поддержка остаётся неизвестной. Эта карта не доказывает наличие GUI, драйверов, управления службами, полного сетевого стека или работоспособности всех строк платформенной матрицы. Из неё также не следует отсутствие любых сетевых примитивов. Поддержка WASI не доказывает готовность приложения в Safari, Chrome и Firefox.

Самостоятельный сетевой объём FUM-STEP-0195 сохраняется. Для следующего ограниченного сценария можно предложить чтение открытой файловой фикстуры через FilePath/FileDescriptor с явным результатом и Errno; это кандидат плана. До реализации задаются фикстура, независимый ожидаемый результат, RED/GREEN и профиль. Текущий приём сохраняет уточнение постановки; пакет не подключён, системные операции не выполнялись, вся FUM-STEP-0182 не объявлена завершённой.

## Первый интеграционный срез macOS

В рамках первого сценария выделено подключение готового Swift-интерпретатора к основному рантайму FUMA: вход приложения → типизированное выполнение оператора в том же процессе → результат → долговечное наблюдение. Исполняющая логика и контейнер наблюдений переиспользуются из существующих собственных реализаций.

Ограниченный результат требует сквозной проверки, сохранения ошибок и пределов, воспроизведения подтверждённой записи, сборок SwiftPM и приложения и профиля точного снимка. Одна зависимость не доказывает подключения. Подробные границы — в [операторном плане](../операторный-интерфейс-FUMA.md), источник — [постановка рантайма](../../Журнал/2026-09-15_18-29-25_MSK_закрепить-восемь-решений-обработки/запрос.md). Первый успех macOS не закрывает остальные платформы и полную карточку.

## Первые срезы tvOS, visionOS, Android TV, Android XR, Wear OS и watchOS

Для шести платформ требуется воспроизвести общий полезный сценарий FUMA: действие пользователя → выполнение структурирующего оператора → сохранение входа, результата и трассы → повторное чтение и replay после перезапуска. Начальный сценарий использует преобразование UTF-8 в Unicode-скаляры и UTF-32LE по [Android-плану рантайма](../../Приложения/FUMA/план-Android-runtime.md); входная фикстура и независимый ожидаемый результат задаются до реализации. Это выбранный проектный сценарий, а не дословная формулировка пользователя.

Срезы уточняют FUM-REQ-0046 и FUM-REQ-0047. Общая логика переиспользуется; различия ограничиваются платформенными адаптерами. Общий `Package.swift` и миграция исходников остаются у Android-владельца до принятой поставки. Реализация каждого среза начинается от явно принятого общего коммита; отдельные ОС-форки кодовой базы не создаются. Историческая опубликованная поставка сама по себе не доказывает актуальную общую базу.

| Платформа  | Проверяемый первый срез                                       | Среда и графическая граница                                                                                                |
| ---------- | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| tvOS       | Ввод с пульта, фокус и подтверждение действия общего сценария | Установить доступный профиль SDK и Simulator либо устройства; Metal-кадр проверять отдельно от рантайма.                   |
| visionOS   | Общий сценарий в минимальном окне                             | Проверить SDK, среду запуска и конкретные Metal API; пространственное взаимодействие выделить следующим срезом.            |
| Android TV | Общий сценарий с управлением пультом и фокусом                | Проверить ABI, уровень API, TV-образ либо устройство и графические возможности выбранного профиля.                         |
| Android XR | Общий сценарий в оконной оболочке                             | Проверить доступ к SDK, ABI/API и XR-среде; XR-взаимодействие и графику подтвердить отдельно.                              |
| Wear OS    | Общий сценарий с доступным вводом часов                       | Проверить профиль часов, самостоятельность и зависимость от телефона; поддержку GPU со смартфона не переносить.            |
| watchOS    | Общий сценарий в доступной оболочке часов                     | Проверить SDK, среду и самостоятельность; графический путь установить отдельным SDK-пробником, Metal заранее не назначать. |

### Общие критерии приёмки среза

- Указаны точный исходный коммит, версии toolchain и SDK, ОС, архитектура, устройство либо образ среды. Доступность SDK, Simulator, API и GPU подтверждается отдельно; неизвестные и недоступные возможности сохраняют явный статус.
- Из чистого клона воспроизводятся подготовка, сборка, установка, запуск и проверка результата. Команды, исходы, сборочные артефакты и необходимые внешние условия сохранены; успех одного этапа не заменяет остальные.
- Полезный сценарий рантайма сохраняет вход, ожидаемые и фактические байты, результат оператора и трассу. После перезапуска проверяются чтение записи и replay; ошибки и ограничения остаются наблюдаемыми.
- Графический результат имеет отдельное свидетельство: фактически используемый API и устройство, отображение согласованной сцены и обработка ввода. Поддержка графики не выводится из успешной сборки или сценария рантайма.
- Запуск на Simulator или эмуляторе, запуск на физическом устройстве и публичная поставка учитываются раздельно. Непроверенные границы не объявляются достигнутыми.
- Для изменённого кода выполнены применимые RED/GREEN, профиль и обоснованное решение об оптимизации. Собственные исходники, открытые фикстуры, конфигурации и инструкции воспроизведения сохраняются в монорепозитории.
- Результат каждого среза оценивается самостоятельно. Он не закрывает остальные платформы, полную STEP0182 или требования FUM-REQ-0046/0047.

## Связанные работы и порядок

Для первого диагностического сценария macOS принята [постановка операторного интерфейса FUMA](../операторный-интерфейс-FUMA.md): Swift запускает Codex CLI, сохраняет наблюдаемый поток в памяти, а структурирующие операторы преобразуют состояние в команды Metal. Язык операторов и GUI имеют общую семантическую основу. Приоритет реализации остаётся у обработки контекста; уточнение не закрывает эту карточку и не подтверждает работающий экран.

Сначала уточняются матрица и общий сценарий; затем платформенные результаты могут выполняться параллельно в отдельных рабочих деревьях. Полная реализация всех платформ остаётся объёмом требования и не подменяется завершением этой карточки.

## Проверка пользы первого сценария

Идеи BO-01 и BO-04 из [учёта книг](../учёт-применения-идей-из-книг.md) связываются с уже выбранным в этой карточке первым сценарием. Конкретный сценарий и платформа в протоколе пока не закреплены; полезность, спрос и готовность остальных платформ не заявляются. Эта запись сохраняет условие возврата и не запускает отложенную реализацию.
