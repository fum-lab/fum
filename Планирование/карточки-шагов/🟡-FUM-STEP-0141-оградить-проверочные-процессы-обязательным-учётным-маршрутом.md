# Оградить проверочные процессы обязательным учётным маршрутом

[Карточка шага](../../Глоссарий/карточка-шага.md) сохраняет один атомарный плановый шаг и его происхождение отдельно от веточного выбора.

## Задача

Добавить проверяемый сессионный шлюз, который до дочернего запуска машинно распознаёт команды с проверочной семантикой, направляет их через обязательную обёртку и сверяет доступную инструментальную трассу с машинными записями текущего запроса.

## Почему сейчас

После закрепления обязательной обёртки две независимые параллельные диагностики всё равно выполнили три Git-проверки непосредственно: `git fsck`, `git merge-base --is-ancestor` и `git diff --check`. Второе проявление `FUM-СБОЙ-0014/ПРОЯВЛЕНИЕ-0002` доказывает, что свободное различение «read-only-чтение» и «проверка» не является устойчивой границей предотвращения.

## Критерии завершения

- Красная автономная фикстура воспроизводит оба проявления: отдельную проверочную Git-команду и `git diff --check` внутри составной read-only-инспекции; дочерние процессы исполняются без машинных записей текущего запроса.
- Версионированный классификатор различает простое чтение состояния и проверочный исход по закрытым признакам команды, аргументов и ожидаемого результата; `fsck`, проверка достижимости и проверка diff входят в базовый инвентарь.
- Штатный сессионный шлюз принимает точную привязку текущего запроса, до запуска преобразует распознанную проверку в вызов обёртки и не позволяет внешней команде самой подменить путь, идентичность запуска или запись результата.
- Составная команда разбирается по дочерним процессам: наличие хотя бы одной проверки требует учётного маршрута для неё и не скрывается соседними диагностическими чтениями.
- Доступная авторитетная трасса инструментальных дочерних процессов сверяется с закрытым машинным снимком запусков; проверочный процесс без записи, запись без процесса, несовпавшие argv или порядок дают явный отказ полноты.
- Если среда не предоставляет полную авторитетную трассу, отчёт и smoke-check явно фиксируют непроверенную границу и не заявляют, что все прямые проверки учтены только по отсутствию известных нарушений.
- Классификатор расширяется данными без ослабления закрытых базовых классов и покрывает ранее неизвестную тестовую команду по её объявленной семантике, а не только по буквальному имени.
- Автономные тесты покрывают одиночный и составной запуск, допустимое чтение, скрытую проверку, изменённые argv, отсутствующую трассу, повтор ответа и точную сессионную привязку; общий smoke-check проходит без сети и секретов.
