# Спланировать офлайн-комплект FUM и приёмку в macOS VM

## Задача

Подготовить конечный план переносимого офлайн-комплекта FUM и его первой сквозной приёмки в macOS VM с отключённым интернетом. Результат — матрица функций, манифест всех необходимых байтов и входов, программа проверки в госте и ограниченная следующая исполняемая постановка.

## Почему сейчас

Пользователь потребовал полностью автономную работу репозитория FUM без интернета и указал будущее окружение macOS VM. Отдельные автономные тесты, локальные операторы и gitlink зависимостей уже полезны, но не доказывают переносимость всего комплекта с интерфейсом, сборкой, данными и модельными функциями.

## Критерии завершения

- Для выбранной ревизии каждого внешнего компонента и всех нужных транзитивных входов прочитаны реальные LICENSE/NOTICE, отражены обязанности сохранения уведомлений, условия сборки и распространения исходников/бинарников. Собственный код FUM под CC0 не изменяет внешнюю лицензию. Конкретная Torrent-библиотека выбирается по официальным источникам отдельно; до завершения выбора название не выдаётся за принятое решение.
- Для непригодных Git бинарных объектов спроектированы хранение в файловой системе вне Git и распространение через Torrent: устойчивый описатель, версия, размер, хэш полного файла, связь частей, происхождение, допустимость распространения и проверка полученных байтов. Раздельно фиксируются доступность раздачи, локальная полнота и фактическое включение в офлайн-комплект. Предусмотрены неполный объект, повреждённая часть, смена версии, недоступная раздача и повтор после прерывания. Приватные runtime-данные и ключи не становятся раздачей; ограниченные лицензией необходимые объекты получают явный допустимый маршрут либо препятствие. Сам Torrent-клиент и раздачи в этом плановом этапе не запускаются.
- Выбран первый точный профиль host/guest, архитектуры, FUM OID, ресурсов и полезного сценария. Для каждого компонента памяти, Журнала, интерпретатора, интерфейса, сборки и проверок зафиксированы фактическая готовность и независимые входы. Отсутствующая функция не заменяется пустым интерфейсом или сохранённым чужим выводом.
- Составлен конечный манифест переносимых материалов и всех прямых/транзитивных зависимостей с реальными байтами, версиями, хэшами, размером, лицензией, способом доставки и потребителями. Неполученные элементы отмечены явно; URLs/gitlinks не считаются доставкой. Bootstrap/SDK и ограниченные по распространению материалы остаются обязательными строками с решением либо препятствием.
- Для модельных функций определены локальный исполнитель, необходимые параметры и данные, ресурсы и наблюдаемый сценарий; новые модели и зависимости не выбираются без обоснования. Для детерминированных операторов LLM не вводится как искусственная предпосылка. Открытые model-only/remote профили не выдаются за доступный офлайн runtime.
- Подготовка комплекта онлайн отделена от автономного переноса, установки и работы. Составлена проверяемая карта сетевых переходов, инструментов резолюции и кэшей; runtime не обращается к источникам за недостающими байтами. Разрешённая локальная проверка зависимостей переиспользуется; сетевой init не попадает в офлайн-стадию.
- По существующей постановке macOS VM и подготовке macOS определён безопасный гостевой стенд: изоляция только VM, точная идентичность гостя, ограниченный канал переноса и отсутствие доступа к неучтённым host-данным. Жизненный цикл VM не реализуется вторым движком; пока backend не готов, это открытая зависимость следующего исполнения.
- Программа будущей приёмки выполняет в госте чтение/изменение собственной памяти и Журнала, интерфейсный сценарий, операторное исполнение, заявленную локальную модельную функцию, сборку и проверки. Подтверждаются сохранение результата, прерывание и продолжение другим процессом; сетевые функции дают понятную недоступность и сохраняют незавершённое намерение.
- Предусмотрены RED/GREEN для отсутствующего и подменённого файла/зависимости/модели, скрытого fetch, недостающего SDK, неучтённого кэша и превышения бюджета. Повтор на чистом гостевом состоянии не опирается на предыдущие сетевые загрузки. Профили переноса, установки, работы, сборки/проверок и восстановления имеют отдельные границы времени, памяти и диска.
- Итоговый документ содержит конечный следующий срез, все открытые условия с ожидаемыми свидетельствами и отдельные статусы подготовки, переноса и настоящей офлайн-приёмки. Отсутствие доступного SDK/модели не превращается в молчаливое исключение. Текущая поставка — план, без создания VM, отключения сети хоста, clone/build/native и расширения двух детекторов внимания.
