# Реализовать изолированный кандидатный коммит и отдельную приёмку

[Карточка шага](../../Глоссарий/карточка-шага.md) сохраняет один атомарный плановый шаг и его происхождение отдельно от веточного выбора.

## Задача

Добавить к одноагентному runtime узкий Git-адаптер, который по явно подтверждённому намерению создаёт кандидатный коммит в изолированной рабочей копии и отдельной ветке, но никогда не интегрирует его автоматически. Независимый проверяющий процесс должен принять или отклонить точный кандидат по сохранённым критериям и наблюдениям.

## Почему сейчас

Хранилище и безоконные интерфейсы должны сначала доказать чистое возобновление. После этого кандидатный Git-эффект можно отделить от модельного выбора и проверить, что ни текст модели, ни внутренний отбор не подменяют пользовательское подтверждение, полномочия, preflight, наблюдение или приёмку.

## Критерии завершения

- Allowlist содержит одно точное действие `create_candidate_commit` с ограниченными путями, зарегистрированными checker ID и фиксированной argv-грамматикой без shell, базовым commit object и веткой-кандидатом; модельный текст остаётся недоверенным входом.
- `transition_user_confirmed`, `authorized`, `preflight_passed`, `executed` и `observed` возникают только из независимых свидетельств с одинаковыми `(episode_id, transition_id, schema_version, object_id, expected_effect_sha256)` в заданном порядке; отсутствие, перестановка или cross-transition-подмена любого свидетельства закрывает действие отказом.
- Отдельный локальный clone с собственным Git-каталогом создаётся из точного базового коммита вне пользовательского checkout, а кандидат — в отдельной ветке; основной ref, индекс, рабочее дерево и Git-метаданные исходного репозитория не изменяются.
- Паспорт закрепляет детерминированные tree, parent, author/committer, timestamp, message, branch и result ref. Публикация result ref использует CAS; после crash точный существующий OID восстанавливается идемпотентно, а иной OID закрывает продолжение.
- Версионный JSON-интерфейс отдельного headless-процесса приёмки получает только каталог эпизода и точный candidate OID, загружает паспорт и допуск из подтверждённого `CURRENT`, независимо перечитывает parent/tree/diff, повторно запускает зарегистрированные проверки и сохраняет типизированное принятие или отклонение без merge, rebase, push и изменения основной ветки.
- Автономная Git-фикстура покрывает успех, абсолютный путь, traversal, symlink escape, неожиданный diff, изменившуюся базу, провал проверки, cross-transition- и ложное модельное подтверждение, crash до receipt, повтор и отказ приёмки; все временные репозитории создаются локально и удаляются после теста.

## Результат

В live-контракт добавлено единственное разрешённое действие `create_candidate_commit`: оно закрепляет безопасные относительные пути, закрытую регистрацию checker ID с точным отображением в argv-грамматику и реализацию без shell, базовый commit object, отдельные candidate/result refs и детерминированные метаданные коммита. Пять свидетельств имеют общие координаты, разные доверенные producer ID, хэшированную связь с предшественником и строгий порядок; общий интерфейс добавления событий не может их подделать. Начиная с preflight журнал неизменяемо связывает SHA-256 команды с заданным ею ID подтверждения observation.

Runtime создаёт отдельный локальный clone с собственным Git-каталогом вне исходного checkout, до записи проверяет ownership marker, каноническую config и descriptor-safe `objects`/`refs`, строит точный tree и commit, публикует прямой result ref через compare-and-swap и сохраняет неизменяемый паспорт. Точный существующий OID и ровно один собственный same-inode temp-alias паспорта с точными байтами восстанавливаются после обрыва, а symbolic или иной OID, чужой или неоднозначный alias, изменившаяся база, неожиданный diff, metadata-alias, небезопасный путь или провал checker закрывают продолжение. Исходные ref, индекс, рабочее дерево и Git-метаданные остаются неизменными.

Отдельный headless-процесс приёмки получает только каталог эпизода и точный candidate OID, неблокирующе и descriptor-relative проверяет подтверждённый `CURRENT`, точное поколение и паспорт, полную цепочку свидетельств и точную непосредственную пару observation/подтверждение с закреплённым ID и дайджестом предыдущего поколения, parent, tree, diff, modes, blobs, direct refs, всё clone metadata и зарегистрированные проверки. Он повторяет проверку изоляции после Git-наблюдения, требует единственный стабильный inode паспорта и атомарно публикует типизированное принятие или отклонение no-replace rename без hardlink-окна, но не выполняет merge, rebase, push и не изменяет основную ветку. Автономные 19 core- и 53 runtime-теста покрывают положительный путь, все требуемые подмены, crash/retry, FIFO/hardlink/symlink, hostile Git config, отказ приёмки и удаление временных репозиториев.
