# Собрать снимок агентского runtime и интерфейса

## Задача

Реализовать на Swift первый ограниченный слой [наблюдаемого состояния runtime](../../Требования/🟡-наблюдаемое-состояние-агентского-runtime-и-интерфейса.md): собрать разрешённые сведения одной задачи, сохранить происхождение и расхождения и показать одинаково понятный человеку и агенту результат. Сначала воспроизводить записанный синтетический сценарий, затем отдельно подключать доступные живые каналы.

## Почему сейчас

При создании трёх видимых задач интерфейс и их JSONL уже отражали выполнение, а список задач API их ещё не возвращал. Выбранная модель соседнего checkout также не определила модель первого хода. Для координации потребовалась ручная сверка разрозненных источников. [Наблюдение и подтверждённая передача](../../Журнал/2026-09-09_11-39-26_MSK_предотвратить-потерю-обязательств-постоянной-задачи/отчёт.md) сохраняют конкретный сценарий.

## Критерии завершения

- Определён версионированный снимок с идентичностью задачи, значениями, источниками, временем, областью охвата и различимыми неизвестностью, устареванием и конфликтом.
- RED/GREEN проверяет несовпадение списка API и JSONL, различие выбранной и активной модели, отличие среды задачи от каталога команды, задержанный эффект интерфейса и отсутствие полномочий канала.
- Представление показывает текущую работу, ожидание и последнюю подтверждённую корректировку; пользователь может перейти от значения к его источнику.
- Наблюдения и переходы записываются в долговечный контейнер и восстанавливаются без прежнего контекста модели. Неподтверждённый эффект остаётся неподтверждённым после восстановления.
- Профиль измеряет задержку сборки снимка, размер сохраняемых данных и стоимость повторного наблюдения на одном входе; решение об оптимизации связано с измерениями.
- Живое подключение проверено отдельно от фикстур, с явной границей доступных API; недоступный канал не объявлен подключённым. Статус полного требования не выводится из одного синтетического сценария.
