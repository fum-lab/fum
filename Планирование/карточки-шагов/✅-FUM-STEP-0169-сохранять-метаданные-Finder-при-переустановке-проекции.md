# Сохранять метаданные Finder при переустановке проекции

## Задача

Устранить блокировку проекции служебными файлами Finder с сохранением строгой границы управляемого содержимого. Исходная гипотеза раннего обнаружения уточнена после команды пользователя об игнорировании этих файлов: для известных метаданных выбран отдельный жизненный цикл.

## Результат

Обычный файл с точным именем `.DS_Store`, игнорируемый Git по своему физическому пути, исключается из управляемого снимка. В сохраняемом каталоге он остаётся на месте. При удалении принадлежащего генератору каталога его содержимое атомарно переносится в приватный каталог проверенного Git-dir. Символические ссылки, каталоги, FIFO, неигнорируемые и отслеживаемые файлы, иные неизвестные имена сохраняют отказ; отсутствие квитанции не даёт владения служебным каталогом.

RED/GREEN подтвердили первоначальную установку при метаданных в корне, повтор без изменений и смену поколения с сохранением байтов. Проверены четыре фазы прерывания, повторное восстановление и следующий apply, а также порядок синхронизации файла и имени архива, сохранение источника при отказе файлового `fsync` и граница фактического регистра имени. Профиль сравнил одинаковые снимки на 14 каталогах: около 0,00088 с без метаданных и 0,199 с с ними, соответственно 0 и 14 вызовов Git-ignore. Это адресная измеренная граница, не испытание отключением питания.

Основания — FUM-СБОЙ-0042/ПРОЯВЛЕНИЕ-0001 и FUM-СБОЙ-0042/ПРОЯВЛЕНИЕ-0002. Ручная очистка больше не является штатным решением.
