# Добавить читающую сверку контрольной точки и доставки

## Задача

Добавить узкий поддержанный CLI только чтения для сверки готовой контрольной точки ROOT .5 и её доставки. Переиспользовать действующие проверки подготовки, квитанции, сырого объекта, полного ref и удалённого OID; не реконструировать допуск и не создавать побочных записей.

## Почему сейчас

Шесть первично подтверждённых отказов дополнительных читающих вызовов C272/C273 показали раздельные ошибки композиции и неверные дополнительные требования. Дочерние результаты этим не объявляются повреждёнными; C273 доставлен по наблюдённому удалённому OID, код первоначального процесса push после отказа помощника неизвестен. Пять новых карточек имеют самостоятельные границы;0079 сохраняет прежнее проявление и получает второе.0009 и0069 не изменяются.

## Граница и возврат внимания

Приоритет — после приёмки текущих исправлений профилей PR215/216, до следующей самостоятельной ручной сверки результата. Это план реализации и её последующей приёмки. Карточка не разрешает запуск нового писателя, изменение чужих деревьев, повтор push или завершение ROOT. Один общий интерфейс не объединяет классы сбоев и не закрывает их без отдельного подтверждения критериев.

## Критерии завершения

- 0184: готовая подготовка используется без повторного start и реконструкции сообщений из descriptor; отсутствующая подготовка даёт читающий отказ.
- 0185: Git100644/FS0600 не даёт ложного отказа, фактические права не меняются; действительное расхождение Git-режима или закреплённого снимка отклоняется.
- 0186: author и committer сверяются раздельно с подготовкой; модельное имя автора совместимо с сохранённым committer FUM, подмена отклоняется.
- 0187: исходные штатные списки целей сверяются без асимметричной сортировки; действительное нарушение их контракта отклоняется.
- 0188: документированный холодный вход загружает транзитивные зависимости без частной настройки sys.path; отказ после push не вызывает повторный push.
- 0079/0002: отрицательный исход производителя блокирует зависимого потребителя, успешный результат разрешает ровно следующее действие; неизвестный исход и дрейф HEAD/ref/байтов отказывают. Исторический критерий0079/0001 сохраняется.
- Отдельные RED/GREEN для каждого основания и сопоставимый профиль подтверждают отсутствие записи и равенство результата штатным проверкам. Создание нового этапа, коммита, push, новой подготовки, изменяемого кэша или записывающего lock отсутствует. Полное ускорение рабочего цикла не заявляется.
- Проверка точного удалённого OID отделена от исхода процесса push; успешный readback не восстанавливает неизвестный exit code задним числом. Отсутствие квитанции, её повреждение или неподдерживаемая схема дают отказ, а не новый эффект.

## Опубликованная постановка

[Issue217](https://github.com/fum-lab/fum/issues/217) сохраняет первоначальную постановку. Ниже её тело приведено дословно; выполнение критериев ещё не заявлено.

**FUM Codex**

Основание: FUM-STEP-0245, шесть подтверждённых отказов дополнительных читающих вызовов координатора при C272/C273. Дочерние результаты не объявляются повреждёнными; штатный push C273 доставлен, его код процесса после сбоя дополнительного помощника остаётся неизвестным.

Нужен узкий поддержанный CLI для read-only сверки готовой контрольной точки ROOT .5 и её доставки. Он использует существующие проверки подготовки/квитанции/объекта/ref и удалённого OID, не создаёт start, коммит, push, lock с записью либо новую подготовку.

Критерии:
- Повторно использует сохранённую подготовку и точный результат штатного создания, без реконструкции исходных сообщений из descriptor.
- Различает Git-mode и локальные права; сверяет author и committer отдельно; не сортирует один из штатных списков произвольно.
- Работает через документированный холодный вход с транзитивными импортами. Отказ дополнительной сверки после push не запускает повторный push.
- Отрицательный исход производителя блокирует зависимого потребителя; неизвестный исход и дрейф HEAD/ref/байтов отказывают. Исторические критерии FUM-СБОЙ-0079 сохраняются.
- Отдельные RED/GREEN регрессии и сопоставимый профиль подтверждают отсутствие записи и равный результат. Полное ускорение рабочего цикла пока неизвестно.

Приоритет: после приёмки текущих исправлений профилей PR215/216, до следующей самостоятельной ручной сверки результата. Это план реализации, а не объявление уже работающего CLI.
