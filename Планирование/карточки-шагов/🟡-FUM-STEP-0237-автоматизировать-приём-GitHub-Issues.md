# Автоматизировать приём GitHub Issues

## Задача

Создать воспроизводимую процедуру приёма GitHub Issues в рабочую очередь FUM: получить проверенный снимок, сопоставить с памятью и активными назначениями, зарегистрировать принятую работу, ответить от имени FUM Lab / Codex и назначить разрешённого исполнителя. Независимая реализация получает отдельные ветку, worktree и видимый чат от точного коммита постановки.

## Почему сейчас

Пользователь разрешил периодический приём, назначение и ответы. Ручная сверка выявила 13 открытых Issues и ограниченный кандидат #13; #1 соответствует существующей FUM-STEP-0178. Нужен устойчивый учёт, предотвращающий повторную работу и повторную публикацию при неизвестном исходе API.

## Критерии завершения

- Вход сохраняет URL, номер, заголовок, точное тело и updated_at; запросы и ответы API имеют происхождение, секреты не публикуются.
- Повтор того же входа возвращает прежнее назначение; новое содержание требует сверки, отмена и уже выполненная работа различаются.
- Перед внешним эффектом сохранено намерение; после неизвестного исхода проводится readback вместо слепого повтора комментария/создания чата.
- Назначение, старт чата, результаты, проверка и интеграция имеют разные подтверждаемые состояния. Текст Issue не даёт дополнительных полномочий.
- Проверка очереди включена при выборе этапа в активной сессии; снятый heartbeat/dispatcher не возобновляется. За пределами активного хода фоновая работа не заявляется.
- TDD, профиль до/после и воспроизводимый CLI входят в монорепозиторий; причины отказа и выигрыш контекста измеряются.
