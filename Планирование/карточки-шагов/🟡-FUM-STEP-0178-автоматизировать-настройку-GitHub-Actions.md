# Автоматизировать настройку GitHub Actions

## Задача

Создать автоматизацию, которая анализирует репозиторий, готовит проверяемый план настройки GitHub Actions, применяет согласованную конфигурацию и проверяет фактический результат CI. Первый сценарий — монорепозиторий FUM.

## Почему сейчас

Пользователь поручил запланировать автоматизацию настройки GitHub Actions. В текущем дереве нет каталога `.github` и подходящей карточки: настройка должна стать воспроизводимой процедурой, пригодной для следующих репозиториев.

## Критерии завершения

- Определены входы: точный репозиторий и ревизия, требуемые проверки, платформы и события запуска. Отчёт о текущем состоянии отличает отсутствующую настройку, пригодную существующую и конфликт.
- Сухой план показывает файлы и удалённые настройки с причинами изменений. Применение сверяет исходное состояние; повтор не создаёт лишнего diff, а пользовательские workflows и настройки сохраняются. Проверены прерывание и безопасное возобновление.
- Используется общее описание инструментов и проверок с задачами macOS, Linux и Windows. Поддерживаемые версии и происхождение Actions фиксируются по проверенным официальным источникам; обновление меняет их явно.
- Для FUM воспроизводится проверка точного коммита из чистого checkout с закреплённым LinguisticKit и нужными Swift/Python. Состав документационного и полного профилей обозначен отдельно; собственные пакеты FUMA подключаются по факту поставки FUM-STEP-0176.
- Оформлен проверяемый контракт CI без вымышленного Codex-UUID и без изменения закрытого отчёта задачи. Пропуск связности сессии не называется полной приёмкой; сгенерированные результаты сравниваются с проверяемым коммитом, а отстающая проекция обнаруживается.
- Полномочия workflow минимальны и явны; проверочный сценарий работает без секретов. Разделены доверенные и внешние PR, права кэшей и артефактов. Изменения удалённых политик, защищённых веток и секретов представлены отдельными явными действиями.
- Локальная валидация отличается от живого запуска. Для успешного, отказавшего и незавершённого запуска сохраняются commit, workflow, run/attempt, событие, исполнители, обязательные jobs и ссылки на результаты.
- Есть RED/GREEN, открытые фикстуры, профиль подготовки и выполнения, анализ оптимизации и статистика вызовов с происхождением. Руководство объясняет человеку запуск, результат и исправление ошибок без чтения реализации.

## Связанные работы и порядок

Планирование выполнено по прямому поручению; реализация этим документом не объявляется начатой. Общий первый этап новых автоматизаций — описание профилей среды и требований проверок; платформенные адаптеры можно реализовывать независимо после согласования общей части.
