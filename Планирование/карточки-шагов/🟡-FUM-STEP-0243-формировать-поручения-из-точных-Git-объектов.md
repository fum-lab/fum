# Формировать поручения из точных Git-объектов

## Задача

Расширить существующий механизм формирования дочернего поручения генерацией из полного OID коммита и точного пути. Раздельно обозначать сырой SHA-256 всех байтов, хэш содержимого Markdown и Git blob OID; значение каждого поля получать алгоритмически из выбранного объекта. Использовать действующий контур поручений и шаблонов, сохраняя границы допуска.

## Почему сейчас

Подтверждено [FUM-СБОЙ-0180/ПРОЯВЛЕНИЕ-0001](../../Сбои/FUM-СБОЙ-0180-подмена-сырого-хэша-хэшем-содержимого-в-поручении.md). Ребёнок защитил границу записи, но ручное исправление не предотвращает повторную задержку. Мера дополняет существующие этапы автоматического заполнения и проверяемой обработки сбоев, не вводя второй реестр.

## Критерии завершения

- Проверены подмена хэша содержимого вместо сырого SHA-256, изменение только recency, расхождение checkout с выбранным коммитом и точный повтор.
- Неверный вход отклоняется до отправки внешнего сообщения; неизменённый выбранный объект даёт тот же результат.
- Источники, адресные проверки, профиль и решение об оптимизации сохранены воспроизводимо.
- Связанный сбой закрывается только отдельным доказательством против его границы.

## Уточнение этапа подготовки поручений

Готовый исполнитель ожидал ручной композиции технических полей у корня. [Конечная постановка](../параллельные-постановки/2026-10-05/подготовка-дочерних-поручений.md) расширяет этот же шаг генерацией ACT и проверочных входов из сохранённого решения и точных Git-объектов. Принятый фасад корневой подготовки сейчас поддерживает только merge; новый явно выбранный обычный контур должен сохранить прежний допуск и историческое поведение.

Дополнительные критерии: восемь конечных продуктовых путей, отказ при дрейфе и неизвестном исходе без повторного внешнего эффекта, полный календарный профиль и отдельный возраст ожидания поручения. Порог внимания выбирается после базового замера. Это план реализации, не объявление готовности. ## Новое проявление при передаче H6

[FUM-СБОЙ-0194/ПРОЯВЛЕНИЕ-0001](../../Сбои/FUM-СБОЙ-0194-устаревший-хэш-решения-при-передаче-поручения.md) актуализирует генерацию из точного committed blob: ROOT передал SHA из подготовительного плана до последующего обновления recency. Ранний отказ ребёнка сохранил границу записи; отдельная коррекция восстановила поручение, но системная мера ещё не реализована. Перед следующей аналогичной передачей вернуться к этой границе. Регрессия должна отклонять устаревший подготовительный SHA до внешнего эффекта и выводить raw SHA из выбранного OID+path без ручного копирования.

## Ранняя проверка смыслового рецепта

[FUM-СБОЙ-0195/ПРОЯВЛЕНИЕ-0001](../../Сбои/FUM-СБОЙ-0195-пустой-профиль-рецепта-постановки.md) выявил пустой профиль до установки. До следующей фиксации D нужна читающая проверка полного рецепта прежним рендером, включая две явно неизмеренные стадии с null. Строгий генератор уже защищает установку; его успешный повтор не доказывает раннее предотвращение. Это дополнение существующего шага и Issue148, не второе назначение.

## Область публикационного рецепта

[FUM-СБОЙ-0196/ПРОЯВЛЕНИЕ-0001](../../Сбои/FUM-СБОЙ-0196-полный-публикационный-контур-вместо-конечного-состава.md) требует до нового D сопоставлять выбранный контур с конечным составом. Адресная контрольная точка не выдаёт накопленные нарушения HEAD за проверенные; полный приёмочный контур сохраняется отдельно. Автоматический выбор и ранняя проверка пригодности рецепта ещё не реализованы. Это дополнение существующего шага и Issue148.
