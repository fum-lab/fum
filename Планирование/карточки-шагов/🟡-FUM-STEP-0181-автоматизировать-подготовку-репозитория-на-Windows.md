# Автоматизировать подготовку репозитория на Windows

## Задача

Создать автоматизацию настройки репозитория и установки всех инструментов, необходимых для выбранного сценария работы с FUM на Windows, с явным различением нативного окружения и WSL.

## Почему сейчас

Пользователь поручил запланировать подготовку Windows. Существующие локальные автоматизации содержат платформенные предпосылки; готовность Windows нужно подтвердить, а не выводить из работоспособности macOS или Linux.

## Критерии завершения

- Определена матрица выпусков и архитектур Windows и поддерживаемых режимов работы. Нативный Windows и WSL описаны как отдельные профили с понятным выбором; их пути, репозитории и инструменты не смешиваются неявно.
- Используется общее описание инструментов и проверок с macOS/Linux, а платформенные адаптеры определяют проверенные источники и способы установки. Уже подходящие версии обнаруживаются; неподдерживаемый инструмент или режим обозначается до изменений.
- План подготовки показывает состояние Git, интерпретаторов, SDK/toolchain и зависимостей выбранного профиля, место на диске и необходимые действия. Повышение прав, включение компонентов системы и перезапуск имеют отдельные явные этапы; незавершённый этап не выдаёт готовность.
- Проверены пути с пробелами и кириллицей, ограничения длины, регистр, кодировки, окончания строк, выполнение команд и платформенные блокировки/атомарная запись. POSIX-зависимые автоматизации отдельно адаптированы либо явно ограничены поддерживаемым профилем WSL.
- Настройка репозитория сохраняет пользовательские Git-параметры, существующие окружения, незакоммиченные изменения и чужие рабочие сессии. Материализуются точные внешние зависимости; повтор и восстановление после прерывания не дублируют установки и не затирают данные.
- Готовность различает переносимые проверки FUM, поддерживаемые пакеты и компоненты, которым требуется macOS. Собственные исходники и команды берутся из монорепозитория после поставки FUM-STEP-0176; недоступность платформенного компонента не скрывается.
- Проверен сценарий новой системы или изолированной виртуальной машины и повтор в уже настроенном окружении. Проверки из чистого клона согласованы с выбранным Windows- либо Linux-профилем GitHub Actions.
- Есть RED/GREEN, сценарии отказа и повтора, открытые фикстуры, профиль времени и ресурсов, решение об оптимизации и статистика с происхождением. Человек получает понятный итог, список оставшихся действий и способ повторной проверки.

## Связанные работы и порядок

[Постановка Windows VM на macOS](../Windows-на-macOS.md) конкретизирует нативный Windows ARM64 внутри VM как испытание повторно вызываемой автоматизации. Она использует общий цикл Linux-постановки и отдельный Windows-адаптер. Статус active, широкие критерии и различение нативного Windows/WSL сохраняются.

Планирование выполнено по прямому поручению; реализация этим документом не объявляется начатой. Общий первый этап новых автоматизаций — описание профилей среды и требований проверок; платформенные адаптеры можно реализовывать независимо после согласования общей части.
