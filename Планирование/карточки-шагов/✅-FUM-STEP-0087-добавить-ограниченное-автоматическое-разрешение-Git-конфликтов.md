# Добавить ограниченное автоматическое разрешение Git-конфликтов

[Карточка шага](../../Глоссарий/карточка-шага.md) сохраняет один атомарный плановый шаг и его происхождение отдельно от веточного выбора.

## Задача

Расширить CAS-интегратор версионированным реестром ограниченных resolver-правил. Первая версия должна уметь пересобирать объявленные производные файлы из канонических источников и объединять записи с устойчивыми идентификаторами только при согласованной схеме и непротиворечивых нормативных полях. Любой другой конфликт должен сохранять исходные commit и завершаться состоянием `resolution_required` с диагностическим артефактом.

## Результат

`CandidateCommitIntegrator` расширен реестром `fum.candidate-conflict-resolver-registry` версии `1`. Каждое правило закрепляет устойчивые идентификатор и версию, точный путь, предусловия, детерминированный алгоритм, инварианты результата и обязательные проверки. Первая версия содержит ровно два класса: полную пересборку объявленного производного manifest из проверенных канонических regular-file-источников и base-aware-объединение канонических JSON-записей по устойчивому ID при уникальных ключах, точной схеме, непротиворечивых нормативных полях и отсутствии смыслового дублирования.

Неизвестный либо неоднозначный путь, нарушение предусловия, нормализованная коллизия любого компонента пути, расхождение схемы, повтор ID, противоречивое нормативное поле, смысловая несовместимость и провал обязательной проверки дают `resolution_required`. Каноническая диагностика сохраняет входные commit, tree и blob OID, причины и результаты проверок; целевой ref не меняется, а прямые refs клона попытки удерживают исходные варианты. Модельное предложение остаётся обычным кандидатным commit и не получает повышенного статуса.

Успешное разрешение создаёт отдельный интеграционный commit с ожидаемой вершиной и всеми исходными кандидатами как прямыми родителями. Паспорт версии `2` сохраняет binding применённого правила, хэш его спецификации, входные и выходной хэши, инварианты и два прогона обязательных проверок. Восстановление в отдельном клоне полностью повторяет merge и resolver из закреплённых commit и сверяет весь итоговый tree, resolver-записи и точный commit object.

Тридцать автономных Git-сценариев покрывают оба разрешённых класса, неизвестное и конкурирующие правила, противоречивое поле, смысловую несовместимость без текстового конфликта, сбой после разрешения, подмену подготовленного дерева, commit payload, происхождения и диагностики, небезопасный тип источника и нормализованные коллизии компонентов пути. README и архитектурная документация явно ограничивают resolver зарегистрированными классами и не обещают автоматического разрешения любого конфликта.
