# Реализовать возобновляемое исполнение цепочки в универсальном fork-подузле

[Карточка шага](../../Глоссарий/карточка-шага.md) сохраняет один атомарный плановый шаг и его происхождение отдельно от веточного выбора.

## Задача

Расширить локальный runtime от одного заранее подготовленного пишущего пакета до линейной конечной цепочки в одном универсальном fork-подузле. Вся цепочка должна использовать один физический живой checkout и точный полный рабочий ref: корень создаёт только начальную host-задачу, каждый допущенный владелец выполняет один шаг с собственными проверками и перед осмысленным commit создаёт ровно одно продолжение того же checkout и ref, а `commit+handoff` атомарно продвигает ветку и строгую FIFO. Отдельные проверяющая и интеграционная задачи подключаются только после готовности диапазона и не владеют веткой между последовательными шагами. Готовый диапазон материализует точный локальный пакет передачи для заранее объявленного маршрута и только отмечает маршрут общего вклада fork — core без создания pull request.

Среда выполнения этой карточки намеренно остаётся линейной внутри одного [ветвевого fork FUM](../../Глоссарий/ветвевой-fork-FUM.md). Порождение двух дочерних fork и последующая модерация являются отдельными переходами, запланированными карточкой FUM-STEP-0145, и не изменяют правило одного продолжения на коммит.

## Результат

Добавлены возобновляемый runtime, живая локальная фикстура и адресный набор Swift-тестов конечной цепочки. В одном физическом checkout на точном `refs/heads/роль/писатель`, отличном от неподвижного `refs/heads/master`, три разные процессные сессии непосредственно получают состояния selector `ready`, `ready`, `not_ready`; первые две выполняют две зависимые карточки и создают ровно два непосредственных однородительских commit через связанные `commit+handoff`, а третья завершает точный допуск через `finish-clean` без нового продолжения.

Каждый коммитящий владелец заранее создаёт отдельный процесс продолжения и связывает его PID, task ID, waiting-билет, рабочую копию, полный ref и подтверждённый HEAD. Новый процесс перечитывает `AGENTS.md` и оба управляющих контракта из фактического HEAD, подтверждает вершину и восстанавливает карточку, бюджеты и зависимость только из Git, частных паспортов, FIFO и прямого selector. Шаги сохраняют отдельные канонические пакеты, фактически исполненные проверки и доверенный расход; превышение каждого бюджета, неуспешная проверка, незаявленный путь и объявленный путь вне области отклоняются до продолжения или коммита.

Живой адаптер заново связывает исходные карточки, рабочий набор и карточку цепочки с исходным Git-коммитом, читает admission-, waiting-, queue- и receipt-свидетельства из точных Git-объектов, проверяет два непосредственных родителя, исполняет обе закрытые схемы и семантический валидатор FUM-STEP-0120. После финального `finish-clean` он материализует воспроизводимые state- и handoff-refs с точными base, head, полным диапазоном, совокупным diff, паспортами, остатком бюджета, неизменной целью и будущим маршрутом общего вклада без pull request и без объявления принятия. Проверяющая и интеграционная задачи появляются только после успешной семантической проверки и не входят в FIFO ветки.

Остановка после подтверждённого продолжения, подмена staged-tree, неоднозначный ответ создания, потерянный ответ связанного коммита и потерянный финальный результат восстанавливаются или блокируются без второго продолжения и второго коммита; изменённый повтор конфликтует. Семантическая подмена вершины, бюджета, области или принятия отвергается даже тогда, когда package-ref уже указывает на поддельный blob.

## Граница результата

Доказательство автономно и использует временную local-bare топологию, реальную локальную очередь и selector, но детерминированный host-адаптер вместо Codex Desktop API, сети и живой модели. Машиночитаемые записи создания не являются авторитетным readback реальных именованных fork-задач. Результат не создаёт постоянную сборку дерева, pull request, независимое ревью или CAS-интеграцию и не расширяет полномочия до внешних remotes; эти границы остаются следующим плановым слоем.
