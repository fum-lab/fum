# Автоматизировать Windows VM на macOS

Создать повторно вызываемую автоматизацию FUM для подготовки Windows VM на Mac, проверки гостевого окружения и дальнейшего управления им. Конкретная установленная VM служит испытанием этого способа. Результат разработки включает собственные исходники, открытые фикстуры, профиль и понятное руководство в монорепозитории.

Это постановка расширения [FUM-STEP-0181](карточки-шагов/🟡-FUM-STEP-0181-автоматизировать-подготовку-репозитория-на-Windows.md), а не выполненная установка. Она переиспользует общий цикл [Linux VM на macOS](Linux-на-macOS.md). По сообщению координатора Linux-реализация только начата; готовая общая Swift-библиотека ещё не принята. В этом этапе Windows не устанавливается, лицензии не покупаются, реализация не начинается.

## Первый профиль и проверка реализуемости

Первый предлагаемый профиль: Mac с Apple silicon, первоначальное испытание на M1 Max; Windows 11 Pro ARM64 одного закреплённого выпуска; UTM с QEMU/HVF под управлением собственного Swift-инструмента FUM. Это предложенный вариант, а не испытанный Windows-backend. Вариант Apple Virtualization.framework, выбранный для Linux, сюда не переносится: исследованные Apple/UTM Apple Boot описывают macOS и Linux.

**Первое решающее испытание:** из пустого собственного каталога автоматизация создаёт свежую версионированную конфигурацию .utm, которую UTM принимает, и при пробной загрузке подтверждает UEFI, TPM 2.0 и Secure Boot. Новые идентичности VM и собственное состояние EFI/TPM создаются воспроизводимо. Поля конфигурации и успешный импорт без проверки фактических возможностей недостаточны. Ручное создание исходной VM, копирование чужой установленной машины и повторное кликанье не заменяют этот результат.

Адресное чтение 11 сентября 2026 года подтвердило ограничение: [scripting-контракт UTM](https://docs.getutm.app/scripting/reference/) содержит make, import, start, stop, status и гостевое выполнение через QEMU Guest Agent; в опубликованных полях есть UEFI, но нет TPM. Исследование координатора также отмечает неполноту utmctl. В прочитанном [исходнике UTM](https://github.com/utmapp/UTM/blob/main/Configuration/UTMQemuConfigurationQEMU.swift) TPM по умолчанию выключен, флаг предварительной установки Secure Boot keys не сериализуется вместе с обычными полями, а создание EFI выбирает отдельный шаблон. Поэтому возможность полностью подготовить нужную VM одной командой utmctl не предполагается.

До этого испытания закрепляются версия UTM, поставляемого QEMU, формат конфигурации и нужные firmware/драйверы; чтение изменяемой upstream-ветки не считается проверкой установленного выпуска. Если автоматическое создание или необходимые возможности не подтверждаются, сохраняется конкретное препятствие и обоснованный выбор дальнейшего backend. Требования Windows не обходятся.

## Общий цикл и отдельный Windows-адаптер

Общая часть расширяет уже определённые операции Linux-постановки, а при появлении принятой реализации использует её точный OID и интерфейсы. Не требуется сначала создавать универсальную библиотеку; повторяемый механизм выделяется по проверенному общему поведению.

| Общая операция         | Сохраняемый результат                                                    | Особенность Windows                                                 |
| ---------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Проверить и план       | Состояние хоста, ресурсы, зависимости, план без записи                   | Версии UTM/QEMU/HVF и возможность целевой конфигурации              |
| Подготовить            | Проверенные артефакты, владение каталогом, устойчивое состояние операции | ISO, .utm, EFI/TPM, единый файл ответов, драйверы                   |
| Запустить и состояние  | Ограниченные ожидания, явные переходы, диагностика                       | Установщик, перезагрузки, установленная ОС и готовность различаются |
| Доступ и готовность    | Подтверждённый гость и точный набор проверок                             | PowerShell и испытанный канал управления                            |
| Остановить и повторить | Штатная остановка, сохранение данных, продолжение после прерывания       | Сохраняются идентичность VM, диск и EFI/TPM                         |
| Профиль и журнал       | Монотонные этапы, исходы и статистика без двойного учёта                 | Раздельные измерения установки, перезагрузок и гостевой настройки   |

В Windows-адаптере отдельно определяются backend, EFI/TPM, носители, драйверы, гостевые команды и доступ. NoCloud, VZEFIVariableStore и Linux VSOCK/socat не объявляются переносимым Windows-механизмом. Общая диагностика и состояние операций отделены от платформенных способов их выполнения.

## Установочный носитель и настройка гостя

[Microsoft публикует ARM64 ISO](https://www.microsoft.com/en-us/software-download/windows11arm64); при чтении страница указывала выпуск 25H2 и таблицу SHA-256 по языкам. Это первый кандидат выпуска. Перед подготовкой должны быть закреплены редакция Pro, архитектура ARM64, язык, полный номер сборки и SHA-256 конкретного ISO. Язык, сборка и хэш выбранного файла здесь ещё не утверждены: ISO не получен. Временная ссылка сроком до 24 часов не является идентичностью образа; повтор связывается с закреплёнными байтами. Несовпадение хэша прекращает использование файла без автоматической подмены выпуска.

Действительная лицензия Windows — отдельный вход будущей установки; доступность ISO не подтверждает наличие лицензии. Её ввод и проверка не раскрывают ключи в Git или журналах. Покупка не является действием этой постановки.

Windows-адаптер формирует один Autounattend.xml из версионированных открытых параметров и частных входов. На установочных носителях не должно быть конкурирующих файлов ответов. Подготовка включает нужные ARM64-драйверы загрузки и сети, гостевые инструменты и PowerShell-настройку. Источники, версии, подписи или хэши этих зависимостей объявляются и проверяются. Первичная установка и перезагрузки должны выполняться автоматизацией; обязательный шаг человека, если он обнаружен, явно показывает незавершённость.

Канал управления выбирается и испытывается вместе с гостем. Предлагаемый первый путь — QEMU Guest Agent и UTM guest execution после установки агента; наличие установочного пакета не доказывает работающий канал. Автоматизация подтверждает принадлежность гостя, выполнение команды и получение её результата с ограниченным ожиданием. Отказ управляющего канала и отказ гостевой сети различаются.

## Состояние, ресурсы и профиль FUM

Проверка хоста показывает фактические версии macOS, архитектуру, доступные CPU, RAM, диск и нужные разрешения. Ресурсы выбранной VM и место для ISO, драйверов, установки и рабочего диска явно рассчитываются; неподдержанный хост или недостаток ресурсов обнаруживаются до записи.

Личные диски, ключи, EFI/TPM, конфигурации с частными данными и журналы гостя находятся вне Git. Открытый шаблон и описание профиля хранятся в FUM. Собственная VM имеет проверяемую принадлежность и защиту от второго писателя. Повтор сохраняет её идентичность и данные; новая VM создаёт новое состояние. Существующие VM, пользовательские настройки, незакоммиченные изменения и чужие worktree не присваиваются и не перезаписываются.

Для гостя определяется конечный нативный Windows-профиль STEP0181: необходимые инструменты, поддерживаемые версии, сценарии FUM и точные команды проверки. Рабочий клон внутри гостевой файловой системы привязан к OID FUM; общий каталог хоста подключается только явно, чужой checkout остаётся доступным для чтения. Весь реестр инструментов безусловно не устанавливается. Поддержка POSIX-автоматизаций, Swift-пакетов или компонентов macOS не выводится из наличия Windows либо эмуляции процессора; неподдержанные части перечисляются отдельно.

WSL2, вложенная виртуализация, игры, GPU-сценарии и вся переносимость FUMA не входят в первый срез. Более широкий STEP0181 сохраняет различение нативного Windows и WSL; данная VM-постановка не закрывает его целиком.

## Приёмка будущей реализации

- Из чистого клона FUM воспроизводятся сборка автоматизации и раннее испытание свежей .utm-конфигурации; далее через неё выполняется чистая установка Windows ARM64 без ручной подготовки исходной VM. Проверены редакция, сборка, устройства, UEFI/TPM/Secure Boot, доступ и конечный профиль FUM.
- План не пишет состояние. Повтор на подготовленном хосте и госте не дублирует установки; изменение входов сначала показывает новый план. Проверены штатная остановка, повторный запуск с сохранёнными данными и восстановление после прерывания подготовки, установки и гостевой настройки.
- Локальные RED/GREEN на открытых фикстурах покрывают план, владение каталогом, несоответствие артефакта, недостаток ресурсов, изменение конфигурации, прерывание и повтор. Реальные VM-испытания отделены от автономных тестов; ограничения и отказы не заменяются общим успешным статусом.
- Руководство содержит проверенные команды, необходимые входы, ожидаемые состояния, гостевой доступ, диагностику, остановку, повтор и восстановление. Состояние started не равно готовности Windows или профиля FUM.
- Профиль отдельно измеряет подготовку артефактов, создание конфигурации, установку, перезагрузки, гостевую настройку, проверки и повтор при объявленных CPU/RAM, условиях сети и кэшей. Сохраняются монотонные интервалы, диск, исходы и решение об оптимизации по сравнимым измерениям.
- Прямые и вложенные вызовы имеют происхождение и не считаются дважды. Неизвестные поля обозначены, повторный импорт не увеличивает счётчики. Сбор статистики не подменяет выполнение сценария.

Parallels остаётся значимой альтернативой при выборе и подходящей лицензии: [Microsoft описывает конкретные авторизованные версии для Windows 11 Pro/Enterprise ARM на M1/M2/M3](https://support.microsoft.com/en-us/windows/experience/platform-variants/options-for-using-windows-11-with-mac-computers-with-apple-m1-m2-and-m3-chips). По исследованию координатора prlctl требует Pro/Business/Enterprise; перед выбором сверяются фактические версия, редакция и доступный CLI. Эта альтернатива не вводит обязательную покупку в текущий этап.

Постановка передаётся отдельным коммитом после Linux-постановки 4dd5a7f33913b17f705e512be1826314da89a4c4. Закреплённый вход текущей интеграции восьми поставок 186b0360a31b97184773757634976257d0f86495 сохраняется; этот этап не меняет чужой снимок.
