# Проверить совместимость принятых сообщений с событиями пилота

Предметная сверка связывает семь уже принятых сообщений с новым опубликованным потоком событий. Она доказывает сохранение порядка, ролей, дословных текстов, полных объектов происхождения и boolean false. Чтение, совпадение и классификация не доказывают исполнения цитируемых указаний.

Три прежних файла — [README.md](README.md), [значимые-сообщения.jsonl](значимые-сообщения.jsonl) и [связи-происхождения.json](связи-происхождения.json) — используются только как входы. Их байты, blobs и режимы сверяются одновременно с первоначальным C и прежним принятым коммитом; они не пересоздаются.

## Назначение новых файлов

- [проверка_совместимости.py](проверка_совместимости.py) читает точные Git-объекты, проверяет прежние файлы checkout и выполняет предметный алгоритм. Каждая запись commit и каждый уникальный blob читаются один раз внутри прохода.
- [проверить-совместимость.py](проверить-совместимость.py) принимает явные OID, tree и полные пути трёх файлов. Код 0 означает совместимость в указанной границе; код 2 — закрытый отказ. Результат выдаётся в stdout, исходные данные и refs не меняются.
- [tests/test_совместимости.py](tests/test_совместимости.py) проверяет допустимый поток и адресные отрицательные семейства. Временный Git использует доступные неизменяемые объекты через локальный alternate; подготовка фикстуры не входит в стоимость предметного алгоритма. Сеть в тестах не требуется.
- [квитанция-совместимости.json](квитанция-совместимости.json) сохраняет свидетельство ребёнка версии `fum.совместимость-сообщений-пилота.1`, хэши, реальные результаты тестов и профиль. Проверяющий не читает её и не принимает успешную квитанцию вместо повторной сверки. Самоссылки на будущий собственный коммит нет.

## Закреплённый вход

- C: `fde24399d912d530f9f359b8022f8e40fb7c151d`.
- Прежний коммит сообщений: `daa53209ebafe4208e26e70953d5adf8ad4a7b12`.
- Полный ref событий: `refs/heads/codex/dir/pamyatj--konvejyer--sobyitiya--g-0fff5c07292e84b88339e9808c20cdd9fb55359cde0986fb4f7b3e707a0a2104`.
- H: `f2b0b806f6c4b89a4c626ad40cd5e900df794ad7`.
- Tree H: `0803a525c791fb5856ed437977b536f7a2f9886c`; родители ровно `[C]`.
- Origin: `https://github.com/fum-lab/fum.git`; при первоначальном наблюдении удалённый OID точного ref совпал с H.

Публичный [контрольный вход](../../../Журнал/2026-09-24_22-51-12_MSK_поставить-пилот-с-читателем-ответов/материалы/постановка/вход.jsonl) читается из C. Поток H должен совпадать со всеми его 5790 байтами, семью полными строками и SHA256 `13f9aa5ff934479832276255569ed98d1fe831e4714407a7f2b253b1a2c48162`. Свидетельство событий проверяется по точному шестиполевому контракту поручения. Каждый диапазон происхождения читается из публичного файла C; SHA ответа включает LF всей опубликованной строки, а вложенная прежняя native-позиция не заменяет этот хэш.

Предметная проверка использует закреплённые OID и не зависит от будущего состояния сети или ref. Наблюдение публикации отдельно проверяет единственность origin, живой локальный ref до и после сети, удалённый OID, tree и родителей. Сдвиг или неоднозначность дают отказ; fetch и изменение refs не выполняются. Допустимое значение H должно указывать на коммит с единственным родителем C и точными контрольными данными; полномочия писателя и принятие всего его diff остаются отдельной проверкой координатора.

## Повторить предметную сверку

Запуск из физического корня checkout требует Python стандартной библиотеки, Git и доступных локальных объектов C, прежнего коммита и H. Недостающие объекты приводят к отказу; команда не получает их из сети.

```sh
python3 -B Память/конвейер/сообщения/проверить-совместимость.py \
  --корень "$(pwd -P)" \
  --база fde24399d912d530f9f359b8022f8e40fb7c151d \
  --прежний-коммит daa53209ebafe4208e26e70953d5adf8ad4a7b12 \
  --события f2b0b806f6c4b89a4c626ad40cd5e900df794ad7 \
  --дерево-событий 0803a525c791fb5856ed437977b536f7a2f9886c \
  --README "$(pwd -P)/Память/конвейер/сообщения/README.md" \
  --сообщения "$(pwd -P)/Память/конвейер/сообщения/значимые-сообщения.jsonl" \
  --происхождение "$(pwd -P)/Память/конвейер/сообщения/связи-происхождения.json" \
  --повторы 5
```

Для отдельного актуального наблюдения публикации к этой команде добавляются:

```sh
  --проверить-публикацию \
  --ref refs/heads/codex/dir/pamyatj--konvejyer--sobyitiya--g-0fff5c07292e84b88339e9808c20cdd9fb55359cde0986fb4f7b3e707a0a2104 \
  --origin https://github.com/fum-lab/fum.git
```

Адресные тесты:

```sh
python3 -B -m unittest discover -s Память/конвейер/сообщения/tests -p test_совместимости.py
```

В рабочей сессии команды проводятся через отчётную обёртку своего запроса с классом `адресная`; первая запись новой истории использовала `--приёмочные-раунды`. Эти команды воспроизводят предметный результат и не заменяют конечный допуск коммита.

## Выполненные проверки и профиль

После исправления синтаксической ошибки нового теста сохранён RED: 21 ошибка из-за отсутствующего алгоритма. GREEN: 21 тест успешно. Проверены изменения каждого прежнего файла и режима, чужие C/H/tree и родители, повреждения потока и свидетельства, пропуски, перестановки, дубликаты, лишние записи, текст, Unicode, пробелы, полный исходник, классификация, тип false, LF диапазонов и ложная успешная квитанция. Число 0 не принимается как boolean false. Номер может отсутствовать в предметной записи; если он сохранён, его значение и тип должны точно совпадать со входом. Принятые файлы в настоящем checkout всё равно сохраняются побайтно.

Профиль пяти проходов: чтение Git и трёх рабочих файлов — 0,317–0,354 с; сравнение семи записей и диапазонов — 0,000707–0,000879 с; четыре повторных полных прохода — 0,326–0,355 с. В проходе прочитаны три commit и семь уникальных blobs, выполнены 25 Git-вызовов. Стоимость сети, подготовки фикстуры, ожидания Desktop, Журнала и публикации исключена. Полный проход включает обе фазы, повторная сверка включает свои фазы; их нельзя складывать повторно.

Решение об оптимизации: сохранить реализацию с кэшем объектов в пределах прохода. Профиль показывает преобладание отдельных вызовов Git, но для контрольного потока из семи записей не обосновывает расширение читателя до нового пакетного протокола. Отсутствие повторных чтений проверено тестом. Сопоставимого замера без кэша нет; ускорение не заявляется.

## Ограничения и остаток

Это проверяющий открытого контрольного потока, без новой реализации рантайма и новых зависимостей. Квитанция ребёнка не является независимым принятием координатора. Общая навигация, индексы, входящие ссылки, актуальная проекция, приёмка объединённого результата и возможный отдельный адресный обратный приём остаются координатору. Имеющееся поколение проекции сохраняется с отставанием от новых файлов.
