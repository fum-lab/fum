# Приём четырёх сигналов окна на FUMA

[Первичный исходник](определение.json) — чистый шаг состояния для последовательности открыть → запросить предъявление → сообщить пиксель → закрыть. [Восемь синтетических ожиданий](примеры-проверок.json) закреплены до запуска и сохраняются неизменными. Все восемь фактических результатов полностью совпали с ними; [результаты проверок](результаты-проверок.json) хранятся отдельно. Вход — предыдущее состояние, один сигнал fum.сигнал-окна.2 и явные ожидаемые экземпляр/поколение.

Семь вложенных определений версии1 проверяют каноническое предыдущее состояние, номер и редакцию. Единственный вход для существующего [чистого планировщика кадра](../okno-metal/README.md) выдаётся при принятом открытии. Остальные звенья сохраняют состояние без нового кадра; четвёртое закрытие снимает кандидат. Поздний/чужой сигнал не создаёт новый вход планировщика.

Caller должен передавать фактическое принятое состояние предыдущего результата. Чистое вычисление не является физической дедупликацией, а новыйКандидат и входПланировщика не разрешают графический эффект. Памятный алгоритм не копируется: полученный DTO предназначен отдельной существующей FUMA-программе.

Профиль ограничен успешным порядком четырёх событий с номерами1..4 и редакциями1/1/1/2. Раннее закрытие, resize, смена окна и дробная геометрия не поддержаны. Дополнительные поля сигнала могут игнорироваться; весь вход должен укладываться в целочисленный профиль. Сообщение пикселя не является новой проверкой GPU или видимости окна.

После восьми примеров выполнен новый чистый проход по четырём уже сохранённым фактическим сигналам ОС. Между вызовами переносилось именно фактическое принятое состояние, не ожидание. Получено закрытое состояние: следующий номер5, редакция2, кандидатfalse. Окно повторно не открывалось. Реальные идентификаторы и полные сигналы остаются в приватных входах; публично сохраняются только синтетические данные и безопасные выводы.

Исходник23384/SHA2567af5934c6d33134bf11f28a1b8544a3b923c12d5820bb0a224b27a9d928ab788 перенесён точно и не менялся после закрепления ожиданий. Существующий bootstrap исполнил восемь примеров и четыре реальных звена по одному разу, все raw0/stderr0/полный JSON MATCH. Независимое ревью всей композиции проверило68 исходных и вспомогательных файлов: восемь примеров, четыре реальных звена с actualstatecarry и исторический расчёт планировщика. Реальные IDs остались приватными.

Фактический входПланировщика из первого результата передан отдельной существующей программе okno-metal. Для640×480пикселей и двух BGRA8-поверхностей она вернула исторический расчёт2457600байт. Ресурсов не выделялось. Расчёт выполнен после прохода четырёх событий и относится к снимку открытия с редакцией1; состояние уже закрыто с редакцией2 и не получает новый кандидат из этого результата. Это композиция двух программ через реальные вход/выход, а не разрешение текущего кадра.

В служебном Node-коде потерялся binding, объявленный внутри условного блока. Сборка manifest остановилась; первый stdout для восстановления прочитан второй раз с тем же хэшем. FUMA и CLI не запускались повторно, ожидание не подставлялось как фактический вывод.
