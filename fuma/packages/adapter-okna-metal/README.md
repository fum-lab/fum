# Оконный адаптер из программы FUMA

[Первичный компилятор FUMA](определение.json) переводит закрытый AST окна в полный производный Swift target на AppKit, Metal и QuartzCore. Ровно два размера320×240/640×480 points и срок1..3с входят в действительные константы target. Исходник Swift хранится как backend-шаблон этой программы FUMA, не отдельный вручную изменяемый Swift-компонент. Это конечный профиль адаптера, не общий AOT или FFI.

## Вход и диагностика

Точный вход имеет схему `fum.программа-окна.1`, версию1, узел `окно-с-полотном`, поля `ширинаПунктов`, `высотаПунктов`, `срокСекунд`. Сравнение строгое: строка320 не равна целому320, перекрёстная пара320×480 не поддержана, срок4 не ограничивается молча. Лишние поля дают диагностику. Неизвестная версия или узел отклоняется лениво до чтения недостающей геометрии. Испорченная форма/JSON может вызвать типизированный отказ bootstrap; исходника при нём нет.

Положительный результат содержит языкSwift, полный target, параметры, максимум32сигнала, отдельный runtime-аргумент для абсолютного metallib пути и флаги `компиляцияВыполнена:false`, `выполнениеРазрешено:false`. Генератор сам не собирает и не запускает target.

## Target и сигналы

Производный target создаёт одно NSWindow/NSView/CAMetalLayer. Он загружает готовую metallib отдельным argv через `MTLDevice.makeLibrary(URL:)`, выбирает `вершинаЦвета`/`фрагментЦвета`, bgra8Unorm, triangle3, cullingnone, две поверхности. Shell, загрузки, runtimeMSLcompile, watcher и повторный запуск отсутствуют.

Конечные stdoutJSON-сигналы сообщают UUID экземпляра/поколение/редакцию, фактические frame/bounds points, backingScaleFactor, convertToBacking size и drawableSize. Перед nextDrawable и перед present повторно сверяются снимок и фактические размеры texture; нулевой размер не рисуется. Сигнал `предъявление-запрошено` сохраняет `предъявлениеПодтверждено:false`: запрос не доказывает GPU completion или видимые пиксели.

Фактический `номерОкна` добавляется только при существующем NSWindow. Он не является идентичностью агента/репозитория; соответствие глобальному WindowServer/CGWindowID остаётся UNKNOWN. Из одного номера не следует право или правильность захвата окна; глобальный список не запрашивается.

Максимум32строки до4095байт+LF каждая. Timer1..3с cooperative, не whole-job deadline/RSS защита: main-loop API/IO могут задержать его. Корень выбирает отдельный bounded execution profile. Ошибка target может сопровождаться raw0 от NSApplication.terminate, поэтому проверяются сигналы/ошибки/закрытие, не только код.

## Корпус и воспроизведение

[Восемь примеров](примеры-проверок.json): два полных [малых](ожидание-малого-окна.json)/[больших](ожидание-большого-окна.json) expected результата и шесть отрицательных случаев. Исходная метка NOT_RUN сохраняет подготовку до запуска. Отдельные [реальные результаты](результаты-проверок.json) фиксируют последующие8/8совпадений: два полных Swift-target и шесть диагностик, без повторов и смены ожиданий. Только basenames expected-артефактов заменены на реальные канонические имена этого пакета; входы и ожидаемые значения не менялись.

Существующий `FUMStructuringOperatorMemoryProbe исполнить --определение <этот файл> --вход текст` получает конечный JSON одного входа через stdin→EOF. В наблюдении проверяются schema, текстовый результат и весь JSON из `результат.значение`, включая полные байты Swift. Большой observation принимается отдельным bounded consumer без увеличения Root intake; фактический извлечённый Swift затем собирается отдельно.

## Реальный запуск

Большой target640×480/3с извлечён из фактического вывода FUMA, побайтно сопоставлен с полным golden, затем скомпилирован Swift6 без ошибок/предупреждений. Полученный бинарник170320байт/SHA256 `1cad6e5a22a59c3bbedc7659297310e1e409c2ee54c47f7182fd6261e38e62b2` выполнен один раз на уже собранной Metal-библиотеке.

Фактически получены `открыто` → `предъявление-запрошено` → `закрыто`, raw0, stderr0. Размер полотна640×480points, наблюдавшийся backingScale2 и поверхность1280×960pixels; номера/редакции/привязка/границы всех сигналов проверены. Сигналов3 из допустимых32. Внешний deadline15с отделён от cooperative Timer3с.

Это наблюдение ОС-геометрии и запроса Metalкадра, не GPUcompletion или снимок пикселей. Снимок экрана из одного windowNumber не выполнялся. Большие observations31748байт приняты bounded consumer126; Root не увеличивал24KiB intake.

### Воспроизводимая последовательность

Из чистого checkout сначала собирается объявленный SwiftPM-продукт [пакета bootstrap](../../../Прототипы/память-структурирующих-операторов/Package.swift) с собственным scratch/cache; внешних package dependencies/plugins у него нет. Для этого ограниченного опыта нужны локальные Apple SDK/Swift6 и отдельный Metal toolchain, без автоматической установки. Далее форма команд такова; угловые значения — заранее выбранные собственные пути, не буквальные argv:

```text
<bootstrap> исполнить --определение fuma/packages/adapter-okna-metal/определение.json --вход текст < input.json > observation.json
jq -jr ' .результат.значение | fromjson | .исходник ' observation.json > main.swift
<swiftc> -swift-version 6 -module-name FUMAWindowAdapter -module-cache-path <cache> -sdk <SDK> -o <adapter> main.swift
<adapter> <готовая-библиотека.metallib>
```

`input.json` берётся из поля `вход` большого позитивного примера. До сборки весь фактическийJSON сравнивается с [полным expected](ожидание-большого-окна.json), затем извлекается именно фактическийSwift, не expected/template. Новые выходы не перетирают прежние. Запуски исполняются с внешним deadline и машинным учётом, как в текущем отчёте; Timer не обеспечивает этот deadline. Путь библиотеки связан с [реальной FUMA→MSL цепочкой](../metal-cvet/README.md): породить фактическийMSL, `metal -c` вIR, затем `metallib` вбиблиотеку. Разные байты JSON-входа дают другой inputhash наблюдения; сравнивать надо полный результат программы, не всё наблюдение с прежним hash.
