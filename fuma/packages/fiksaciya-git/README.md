# План фиксации Git на FUMA

[Определение](определение.json) составляет данные команды фиксации из ожидаемой и отдельно наблюдаемой привязки. Оно использует существующие `fum.определение-оператора.2` и `fuma.граф-JSON.2`, включая одно вложенное определение.

## Отрицательное требование

При создании исходной точки `f36a5f6e7ff84e3ac74d484c69e824a0bec9d2bb` обычная очистка сообщения Git изменила 4563 байта подготовленного текста на 4561 байт. Наблюдаемое содержимое совпало с очисткой `git stripspace`; исходные сообщения сохранились в Журнале. Это отдельный факт от проверки автора и дерева. На момент исходного опыта доставка ожидала отдельного решения пользователя. Позднее человек разрешил доставку с явным отклонением, и она выполнена; текущего ожидания по этой точке нет. Новый план не повторяет её эффекты.

Запрещённое поведение: молча нормализовать подготовленное сообщение либо подменять файл, HEAD или привязку перед фиксацией. Проверяемое предотвращение: сохранять `--cleanup=verbatim`, передавать тот же проверенный файл отдельным аргументом `--file`, а после настоящего коммита независимо сравнить полные байты сообщения с подготовленными. Флаг не заменяет последнюю проверку: внешние хуки и другие участники исполнения тоже могут изменить сообщение.

## Вход и вложение

Вход `fum.вход-плана-фиксации-Git.1` содержит идентификатор нового намерения, ожидание и наблюдение. Ожидание и наблюдаемая привязка имеют ровно шесть полей: `корень`, `ветка`, `head`, `файлСообщения`, `sha256Сообщения`, `байтыСообщения`. Строковые поля требуют строк; число байтов — целое от 1 до 16384. Логическое значение вместо числа отвергается. Дополнительные поля внутри привязки не принимаются.

Внешний граф проверяет схему, состояние наблюдения `ПОДТВЕРЖДЕНО` и предыдущий эффект `НЕ_НАЧАТ`. Только затем он вызывает вложенную программу `сопоставить-вход-плана-Git` версии 1. Ленивый отказ до вызова сохраняет HOLD даже при неверном типе неиспользованной привязки. Вложенная программа проверяет типы и точное равенство двух закрытых объектов. Это конкретная композиция двух программ через вход и результат.

Результат ПЛАН содержит `cwd`, массив `argv` со значениями `git`, `commit`, `--cleanup=verbatim`, `--file` и точным именем проверенного файла. Аргументы не соединяются в строку оболочки. HOLD содержит код причины и не содержит `argv`. Ошибка типа прерывает получение результата; вызывающая сторона должна сохранить отказ, а не запускать запасную команду.

## Граница исполнения

`допускИсполнения` всегда равен `false`. Совпавшие строки не доказывают фактические Git/FS-состояние, содержимое файла, синтаксическую допустимость OID, владение, свежесть, полномочия или неиспользованный бюджет эффекта. Эти наблюдения и право на новый эффект предоставляет реальный адаптер в собственной допустимой области. Программа не читает файл, не вычисляет его SHA256, не вызывает Git, не получает автора, не создаёт коммит и не отправляет ветку. Поля автора отсутствуют. Неизвестный либо уже начатый предыдущий эффект не повторяется.

## Состояние проверок

[Примеры](примеры-проверок.json) сохраняют исходный снимок одного положительного и шести отрицательных ожиданий; их метки `NOT_RUN` относятся к первоначальной подготовке. Фактические последующие [результаты](результаты-проверок.json) отделены от ожиданий: после исправления исходника все семь исполнены и соответствуют ожиданиям. Шесть CLI-вызовов завершились кодом 0; последний дал ожидаемый код 1 без успешного stdout-наблюдения. Сырая неуспешная строка этого вызова в Журнале сохранена. Синтетическое сообщение содержит настоящие LF: 21 байт UTF-8, SHA256 `a417ae170e2e1090a89f7f62f0e49f6f0da2cd83d1216f235991d421f0deec7c`. Это не настоящая авторская метаинформация. Ожидание первоначально не закрепляло точного кода последней ошибки. В реальном вызове наблюдались код `схема` и пояснение «Ожидалось целое число».

## Существующий путь исполнения

Текущий bootstrap уже содержит нужное преобразование. Его CLI принимает `--вход текст`; шаг `вычислить-JSON` разбирает полученный текст как JSON и передаёт объект графу. Отдельный режим `--вход json` не поддержан и для этого пути не требуется. Это подтверждено по существующим исходникам, а не выполненным вызовом.

Объявленная исполняемая цель — `FUMStructuringOperatorMemoryProbe` в [пакете bootstrap](../../../Прототипы/память-структурирующих-операторов/Package.swift). Аргументы после проверенного физического исполняемого файла, при рабочем каталоге в корне репозитория:

```json
["исполнить", "--определение", "fuma/packages/fiksaciya-git/определение.json", "--вход", "текст"]
```

В stdin передаётся один конкретный входной объект, сериализованный UTF-8 JSON, затем EOF. Это базовый вход с изменениями выбранного случая; весь документ примеров не является входом программы.

После успешного вызова stdout содержит наблюдение `fum.наблюдение-оператора.2`. Нужно проверить `результат.тип == "текст"`, разобрать JSON-строку из `результат.значение` и сравнить полученный объект с ожидаемым результатом. Всё наблюдение и наружная JSON-строка не равны самому результату графа. Случай неверного типа реально завершился неуспешно без stdout-наблюдения, с кодом `схема` и пояснением «Ожидалось целое число».

Существующий bootstrap реально собран одной адресной попыткой в отдельной приватной области. Его SHA256 и исходное дерево закреплены в результатах. Собственная исходная папка пакета и обычный каталог сборки не изменены; бинарник, SDK и кэши не включены в Git. Семь случаев исполнены через этот физический бинарник. Нового нативного моста, CLI или нативного исходника для них не добавлялось.

## Происхождение и следующий опыт

[Новый этап Журнала](../../../Журнал/2026-11-03_23-09-12_MSK_сохранить-план-фиксации-Git-на-FUMA/запрос.md) продолжает ранее сохранённые прямые указания человека; новой команды от человека для этого этапа не добавлялось. Первоначальный исходник был перенесён побайтно из отдельно проверенного предложения A10: 13077 байт, SHA256 `d6b808292e8ad076cac57cb54e25cfc22cb7d529b17e91edfcb6a577362402e3`. Реальный первый запуск отверг его на byte2363: закрытый формат определения и графовые выражения запрещают литерал `false`. Проверка обычного JSON и статическое ревью не доказывали допустимость этого синтаксиса. Первоначальный отказ и исходник сохранены.

Исправлены только семь полей `допускИсполнения`: вместо литерала используется существующее выражение `["равно", 0, 1]`, вычисляющее тот же `false`. Новое определение — 13182 байта, SHA256 `2583aa9fea14b3e8254c786a5b34a4f4617ff983797b8c0e5d0d5e77cd9c8b9a`; остальные байты и ожидаемые выходные значения не изменены. Это правка программы FUMA, без изменения bootstrap. Технические приватные пути и квитанции не перенесены в пакет.

Подтверждённый результат ограничен интерпретацией этой программы и семью случаями. Команды Git из выданного плана не исполнялись; сохранение реального сообщения будущего коммита, Git/FS-адаптер, Metal/GPU, AOT и self-hosting этим набором не проверены. Историческое ожидание доставки прежнего `f36` позднее разрешено человеком и закрыто; оно не является текущим препятствием. Следующий предметный шаг — применить работающий bootstrap к оконной программе и её собственным случаям.
