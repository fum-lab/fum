# Имя рабочего дерева по ветке

Первичный исходник FUMA: [определение.json](определение.json). [Примеры](примеры-проверок.json) — ожидаемые случаи, ещё не исполненные.

Программа проверяет буквальную пару `полныйRef = refs/heads/ + ветка` и вычисляет `кореньДеревьев + / + ветка`. Слеши, регистр и кириллица сохраняются. Например, `fum-lab/fum/master` образует три одноимённых уровня в объявленном корне; дополнительный лист FUM не добавляется.

Используется существующий профиль `fum.определение-оператора.2` / `fuma.граф-JSON.2`: вложенное определение, ленивое `если`, `равно`, `соединить`, `путь` и ограничение длины. `путь` читает поле JSON, а не файловую систему. Новых нативных примитивов нет.

## Вход адаптеров

Краткое имя и полный ref должны происходить из одного фактического Git worktree. Корень — явно выбранный физический абсолютный каталог без завершающего слеша. Это не вычисляется из названия чата.

`факты` связывают наблюдение с точными `полныйRef`, `источник` и вычисленным `назначение`. `веткаДопустима` подтверждает допустимое имя Git и безопасное относительное отображение в выбранном корне. `границыПроверены` подтверждает физический корень, отсутствие symlink и регистрового псевдонима, выходов за корень и вложения в другое worktree. Значение `true` само по себе не создаёт такое свидетельство: его обязан предоставить проверенный Git/FS-адаптер. Строки не очищаются и не исправляются по эвристике.

`состояниеНазначения` принимает `свободно`, `это-дерево`, `занято`; остальные строки дают неизвестное назначение. `это-дерево` требует подтверждённой идентичности того же checkout. `переносПоддержан` относится к конкретному методу с учётом submodule и привязки исполнителя; существование команды Git недостаточно. Неизвестные условия не подменяются положительными фактами. Текущий путь проверяется как строка до выбора ветви; источник фактов — при достижении проверки его привязки. Строковые примитивы и условия требуют свои типы. Несоответствие остальных полей при сравнении даёт блокировку. Отсутствующее поле в реально вычисляемой ветви даёт ошибку существующего интерпретатора. Ленивый отказ по несовпадающей паре ref намеренно не читает факты; отсутствующие в этой ветви поля не являются ошибкой.

Пределы исходного профиля этой программы: имя 1–1024 Unicode scalar, корень 1–4096. Они не заменяют ограничения Git, байтовые ограничения файловой системы или бюджет интерпретатора.

## Результат и граница

Результат содержит рассчитанное назначение и один статус: `предложение`, `уже-соответствует`, `блокировано`. Во всех случаях `файловИзменено: 0`, `gitИзменён: false`: программа ничего не переносит, не связывает чат и не выдаёт разрешение записи. Смена Git/FS-состояния после наблюдения требует новой проверки непосредственно перед эффектом.

Сохранённое старое дерево на желаемом пути — `НАЗНАЧЕНИЕ_ЗАНЯТО`. Оно не переименовывается и не перезаписывается этой программой. Для текущего старого detached-дерева с инициализированным LinguisticKit обычный `git worktree move` не является подтверждённым методом.

Семнадцать ожидаемых случаев различают вычисление иерархии, другую ветку, сохранение регистра, совпадение с текущим путём, занятие, неизвестность, несоответствие ref/фактов и неподтверждённые границы и два случая числового исходного пути. Точный runtime-код ошибки типов не установлен. Тесты FUMA, сборка и реальный перенос **не запускались**.
