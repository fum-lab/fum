# Живая геометрия окна с завершением Metal-команд из FUMA

Первичный FUMA-оператор версии 2 порождает Swift окна. Существующий FUMA-помощник версии 1 переносит фактическое состояние между шестью нативными сигналами и передаёт только фактические DTO существующему планировщику. Новая версия дополнительно наблюдает завершение двух собственных Metal command buffers.

В [контракте](контракт.json) закреплены замкнутый AST, конечный профиль и порядок 16 записей. [Каталог случаев](примеры-проверок.json), [полный положительный пример](положительный-пример.json) и [пять отрицательных](отрицательные-примеры.json) сохраняют историческое EXPECTED_ONLY_NOT_RUN; фактическое исполнение записано отдельно в [результатах генератора](результаты-генератора.json) и [живого завершения](результаты-живого-завершения.json).

Реально выполнены все шесть случаев генератора по одному разу: полный Swift и пять диагностик без исходника. Все коды 0, stderr пуст, весь JSON совпал с заранее закреплёнными ожиданиями. Фактический Swift извлечён только из stdout положительного случая, целиком совпал с golden и без ручной правки собран вместе с прежним фактическим Helper.swift и существующей библиотекой FUMStructuringOperatorMemory.

Один новый запуск создал окно 320×240 пунктов, запросил 400×300, затем получил реальный resize callback. Масштаб 2 наблюдался; drawable изменился 640×480→800×600. Все шесть полных результатов приёмника совпали с независимыми ожиданиями после единственной замены синтетической идентичности фактической. Предыдущее состояние каждой записи целиком равно предыдущему фактическому результату. Два фактических DTO дали планы 2457600 и 3840000 байтов; это чистая арифметика, её resourcesAllocated0 не описывает нативные GPU-аллокации.

Для кандидатов 1/revision1 и 4/revision2 тот же command buffer получил present, commit, waitUntilCompleted, после чего status оказался completed (фактический rawValue 4). Отдельные две записи связывают фактические размеры drawable, экземпляр/поколение, редакцию и полный использованный снимок. Затем сформированы прежние нативные предъявление-запрошено. Итоговое состояние закрыто: next7/revision3/candidatefalse. Во всех нативных и GPU-записях presentationConfirmed=false.

Завершение команд не доказывает видимые пиксели окна, подтверждение WindowServer или показ на экране. getBytes, offscreen-текстура и screenshot здесь не добавлены. Нет независимого driver/syscall-аудита. Исходник и API-маршрут связывают тот же локальный буфер; реальные статусы и снимки наблюдены в trace. Частные UUID, номер окна и позиция рамки исключены из публичной проекции.

## Воспроизведение

Нужны macOS с AppKit/Metal, Swift 6, собранные существующие библиотека и Probe из [загрузочного пакета](../../../Прототипы/память-структурирующих-операторов/Package.swift), модуль/объект библиотеки, jq, SDK и красная metallib по [существующей FUMA→MSL цепи](../metal-cvet/README.md). В этом этапе использованы ранее собранные зависимости; чистый клон и все сочетания ABI/ресурсов не аттестованы. Значения FUMA_PROBE, FUMA_JQ, FUMA_PRODUCTS, FUMA_SWIFTC, FUMA_SDK, FUMA_BUILD, FUMA_AST и FUMA_RED_METALLIB задаёт воспроизводящий запуск, а сборки/кэши остаются вне Git.

```bash
"$FUMA_PROBE" исполнить --определение fuma/packages/zhivaya-geometriya-okna-v2/определение-окна.json --вход текст < "$FUMA_AST" > "$FUMA_BUILD/window-observation.json"
"$FUMA_JQ" -j '.результат.значение | fromjson | .исходник' "$FUMA_BUILD/window-observation.json" > "$FUMA_BUILD/main.swift"
```

FUMA_AST содержит ровно вход положительного примера: схема fum.программа-живой-геометрии.2, версия 2, единственный узел окно-геометрии-А/профиль2. Helper.swift также получается только исполнением [прежнего первичного FUMA-исходника](../zhivaya-geometriya-okna/определение-помощника.json) с его замкнутым helper-AST версии1; в фактическом этапе повторная генерация не выполнялась. Перед сборкой обязательны проверка схемы наблюдения, текстового результата и полного ожидаемого JSON, а не извлечение произвольной строки после ошибки. jq -j сохраняет точные байты строки без добавленного LF.

```bash
"$FUMA_SWIFTC" -swift-version 6 -parse-as-library -module-name FUMALiveGeometryGPUAdapter -sdk "$FUMA_SDK" -I "$FUMA_PRODUCTS" "$FUMA_BUILD/Helper.swift" "$FUMA_BUILD/main.swift" "$FUMA_PRODUCTS/FUMStructuringOperatorMemory.o" -framework Foundation -framework AppKit -framework Metal -framework QuartzCore -o "$FUMA_BUILD/FUMALiveGeometryGPUAdapter"
"$FUMA_BUILD/FUMALiveGeometryGPUAdapter" "$FUMA_RED_METALLIB" fuma/packages/priyom-geometrii-okna/определение.json fuma/packages/okno-metal/определение.json
```

Конкретный фактический build использовал собственные TMPDIR/module-cache и один внешний compiler invocation. Внутренняя параллельность компилятора не ограничена и не измерена. Фактический Host работал с независимым внешним сроком 15 с через существующую отчётную обёртку. Таймер закрытия 2200 мс совместный: синхронные FUMA и GPU wait могут задержать UI и таймеры. waitUntilCompleted не даёт жёсткого срока. Код не ловит ObjC/driver trap как Swift error; частичный/неизвестный внешний исход сохраняется без слепого повтора. CPU/RSS/network/GPU-memory enforcement не заявляется.

Проверены текущая машина, один размерный переход и два завершённых буфера. Новое изменение backing scale, смена поколения, раннее нативное закрытие, общий live lifecycle, видимые пиксели и NativeStop остаются открытыми.

Независимый consumer167 целиком принят ROOT: шесть результатов генератора, 30 исходных IO, весь trace16, carry6/planner2/GPU2; итоговые границы выше сохранены.
