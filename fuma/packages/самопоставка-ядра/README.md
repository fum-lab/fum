# Самопоставка минимального ядра FUMA

Получен работающий самостоятельный интерпретатор ограниченного подмножества FUMA. [Первичный FUMA-генератор](определение.json) выдал исходник и целую программу как данные. Фактический Swift9093Б собран в строгом режиме Swift6 без предупреждений; прежний AutomationExecutor не подключён.

Два самоприменения фактически полученной программы дали одинаковые21631Б пакета и точные байты собранного исходника. Другая программа вычислила24 и выдала новый FUMA-код; именно сохранённый фактический код затем вычислил24×7=168. Проверены13 исполнений:9raw0 и4 заранее ожидаемых типизированных отказа; все целые JSON совпали с заранее закреплёнными ожиданиями. Пять проверок подготовлены независимым рецензентом. [Полные данные](результаты-исполнения.json) отдельно описывают границы приёмки.

Первый вариант успешно прошёл6 проверок генерации, но не собрался. [Исходный отказ](первоначальный-отказ-сборки.json) и [диагностики](диагностики-первой-сборки.json) сохранены. Исправлены26 недопустимых return перед вызовом throws→Never только внутри первичного FUMA-литерала. Прочие7 возвратов, семантические ожидания и ограничения не менялись. [Новая генерация](результаты-исправленной-генерации.json) выполнена6 раз по одному с новым исходником; прежние вызовы не повторялись.

Семантика интерпретатора пока задана Swift-синтаксисом внутри первичного FUMA. Самопоставка пакета отличается от общего семантического перевода FUMA в Swift и от переноса всех алгоритмов рантайма в графы FUMA. Вложенные определения этим профилем не поддерживаются. Смена программы и вычислимый изменённый генератор проверяют, что получен интерпретатор, а не только печать фиксированного текста.

## Воспроизведение

Нужны Swift6 для macOS, существующая загрузочная основа из `Прототипы/память-структурирующих-операторов` и jq. Сборки и фактические выходы размещаются в собственной временной области вне Git. Конечные JSON-входы из `проверки/` передаются до EOF.

1. Собрать существующий продукт FUMStructuringOperatorMemoryProbe с отдельным scratch-path и одним заданием. Его команда `исполнить --определение` получает текущее определение этого пакета и `--вход текст`; вход — `проверки/генерация-260-01.вход.json`.
2. Сохранить целое фактическое наблюдение. Из `результат.значение` разобрать внутренний JSON. Через `jq -j` извлечь `исходник` без добавления лишнего LF, через `jq -c` сохранить его `программа`. Ожидание Swift служит только сравнению.
3. Собрать фактический исходник: `swiftc -swift-version 6 -strict-concurrency=complete -warnings-as-errors -parse-as-library -j 1 -module-name FUMASelfKernel main.swift -framework Foundation -o FUMASelfKernel`. Кэш модулей и TMPDIR задать своей временной областью.
4. Полученный бинарник принимает ровно два пути: фактическая программа и `проверки/самовход-260.json`. Сохранить вывод и его фактическую `программа` до следующего шага; повторить с этой программой. Сравнить целые JSON и исходники.
5. Для петли24→168 использовать программу и вход `проверки/независимые/независимый-1.*`. Из фактического результата сохранить `программа`, затем исполнить её с входом `независимый-2.input.json`.

Прямые исполнения ограничивались внешним сроком15с, отдельной группой процессов и очисткой TERM→KILL существующей обёртки. Это не ограничитель всей памяти, сети или доказательство полного профиля проекта. [Контракт](контракт.json) задаёт точные поддержанные операции, пределы JSON и отказы.
