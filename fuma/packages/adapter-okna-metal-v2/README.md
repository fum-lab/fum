# Окно и проверка пикселя на FUMA, профиль 2

[Первичный исходник](определение.json) задаёт отдельную версию оператора, AST и профиля; [версия 1](../adapter-okna-metal/README.md) сохранена. Swift получается трансляцией FUMA и не редактируется отдельно.

## Поведение

Поддерживаются размеры 320×240 и 640×480 точек и срок работы от 1 до 3 секунд. AST имеет схему `fum.программа-окна.2`, версию 2 и узел `окно-с-полотном`. Версии 1 и 3, лишние поля и неверные типы явно отклоняются. [Корпус проверок](примеры-проверок.json) содержит два полных ожидаемых результата ([малое окно](ожидание-малого-окна.json), [большое окно](ожидание-большого-окна.json)) и шесть отрицательных случаев. Все восемь случаев исполнены по одному разу: два полных Swift-результата и шесть диагностик совпали с ожиданиями. Каждый процесс завершился с кодом 0 без stderr. [Фактические результаты](результаты-проверок.json) хранятся отдельно от исходного корпуса ожиданий.

Производный адаптер использует AppKit, CAMetalLayer и библиотеку metallib, переданную отдельным аргументом. Дополнительно он один раз рисует в текстуру 1×1 вне окна: `bgra8Unorm`, режим `shared`, устройство семейства Apple. Используются те же очередь и pipeline, viewport 1×1 и треугольник из трёх вершин. После `commit`, `waitUntilCompleted` и проверки `status == .completed` адаптер читает четыре байта через `getBytes` и выдаёт событие `пиксель-прочитан` с порядком каналов BGRA. Начальные нули CPU-буфера не считаются прочитанными данными; ожидаемый красный цвет не подставляется в вывод.

Ограничение — 30 обычных сигналов, один сигнал пикселя и один завершающий сигнал, всего не более 32. Каждая строка содержит не более 4095 байт JSON и LF. Таймер и ожидание GPU не обеспечивают жёсткий внешний срок или ограничение RSS. Отказ создания ресурса, неподдержанный формат или незавершённая команда заканчивают попытку без повтора. `getBytes` возвращает Void и не имеет собственного кода ошибки; исключение Objective-C или сбой драйвера остаются внешним отказом процесса с неизвестным частичным исходом.

Генератор возвращает признаки отсутствия сборки и исполнения: он не запускает полученный Swift и не выдаёт права на эффекты. Реальному заданию нужны привязка исходника, владение областью, проверенные артефакты и внешний срок. Прочитанный пиксель вне окна не доказывает видимые пиксели окна или снимок экрана. Глобальные списки окон не запрашиваются.

## Фактическая сборка и GPU

Для сборки выбран уже проверенный фактический вывод малого окна: 320×240 точек, таймер 1 секунда. Его 17387 байт Swift точно совпали с полным ожидаемым результатом; SHA256 `84dd65a8d3fdd7b20d514af6aca632b5ca6c8355cd90ba4bc8f1d773076990ce`. Один вызов Swift 6 собрал текущую машинную цель без вывода ошибок. Один запуск адаптера с ранее полученной красной metallib завершился с кодом 0, stderr пуст.

Наблюдались четыре сигнала: `открыто` → `предъявление-запрошено` → `пиксель-прочитан` → `закрыто`. ОС сообщила масштаб 2 и поверхность 640×480 пикселей для содержимого 320×240 точек. Сигнал пикселя содержит `командыЗавершены: true` и четыре фактических байта BGRA `[0, 0, 255, 255]`. Они совпали с ожидаемым красным цветом точной Metal-библиотеки. Это чтение отдельной текстуры 1×1 после завершения команд GPU; флаг подтверждённого предъявления окна остался false.

Большой Swift-результат 640×480/3 секунды тоже полностью проверен, но отдельно не собирался и не запускался. Прежняя версия адаптера не изменялась и повторно не запускалась. Генератор не менялся после закрепления ожиданий.

## Воспроизведение

Нужны macOS, Swift 6 с AppKit/Metal/QuartzCore и существующая библиотека цвета из [пакета metal-cvet](../metal-cvet/README.md). Сборку, кэш, stdin, полученный Swift и бинарник размещают вне checkout. Существующий продукт `FUMStructuringOperatorMemoryProbe` собирается из `Прототипы/память-структурирующих-операторов`; его команда имеет вид `исполнить --определение <определение.json> --вход текст`. В stdin передают полный JSON из поля `положительные[0].вход` каталога и EOF.

Из реального stdout разбирают наблюдение, проверяют схему `fum.наблюдение-оператора.2` и тип результата `текст`, затем разбирают JSON в `результат.значение`. Весь объект сравнивают с полным ожиданием малого окна. Только после совпадения сохраняют точные UTF-8 байты фактического поля `исходник`, без добавления LF. Ожидаемый Swift не используется как вход сборки.

Полученный `main.swift` собирают `swiftc -swift-version 6 -o <бинарник> <main.swift>` и запускают с одним аргументом — путём к metallib. Текущий опыт использовал явный SDK и отдельные TMPDIR/module-cache; это свидетельство текущей машины, а не проверка всех поддержанных SDK или чистого клона. Внешняя обёртка ограничивает запуск 15 секундами и завершает его группу процессов при превышении срока.

Приёмка требует единственного сигнала `пиксель-прочитан`, четырёх целых байтов в диапазоне 0..255, порядка BGRA, размера 1×1 и `командыЗавершены: true`. Затем байты сравниваются с цветом закреплённой библиотеки. Ненулевой код, обрыв, ошибка драйвера или отсутствие сигнала сохраняются как отказ либо неизвестный частичный исход, без автоматического повтора.
