# Прямая композиция геометрии на FUMA

Первичный [FUMA-генератор](определение.json) выдаёт небольшой Swift6-клиент одного шага: существующий приёмник геометрии → его явный фактический DTO → существующий планировщик кадра. Swift получается из реального результата FUMA; отдельный первичный Swift или новый интерпретатор не создаются.

[Шесть исходных ожиданий](примеры-проверок.json) сохраняют исторический EXPECTED_ONLY_NOT_RUN. [Два предварительных библиотечных ожидания](примеры-прямого-вызова.json) также сохранены отдельно от [фактических результатов](результаты-проверок.json). Статус исходного корпуса не заменяет реальный исход.

## Полученный результат

Генератор реально выполнен шесть раз: один полный Swift и пять диагностик без исходника. Все шесть полных JSON результатов совпали с заранее закреплёнными ожиданиями, rawexit0 и stderr0. Проверенная цель — предел вывода16384; конечная ветвь4096 не исполнялась.

Из положительного ACTUAL наблюдения извлечён Swift9548Б/SHA256 aa692a2460fb015b9d93c7ca70bab4e1f0da7447288d1cb42e77c4cce7ef524c. Он побайтно совпал с полным эталоном. Одна сборка Swift6 с прежними object/module существующей библиотеки действительно завершилась rawexit0/stdout0/stderr0. Бинарник3005880Б/SHA256216c302e58cedcb47bbab7cf4457d46cbc42cf331ef90f2b3c1b6765d7e407fa.

Два независимых синтетических примера реально выполнены новым клиентом по одному разу. Внутри каждого процесса существующий public API вызвал приёмник, затем планировщик с ACTUAL DTO результата. Полные результаты и точные UTF8 JSON+LF совпали с предварительными ожиданиями: каждый2118Б. Получены планы2457600 и3840000Б, ресурсовВыделено0. Это два отдельных входа open/resize; переноса фактического состояния между ними нет.

Независимая проверка158 приняла весь конечный состав:35 оригинальных IO, шесть результатов генератора, точное извлечение Swift, одну сборку/import/link и два полных библиотечных результата с побайтным совпадением. Root прочитал и принял конечный пакет19291Б/SHA256d655c230a648faf41cd401286c60f35f8a5a77aad9b3595c10b77c8fe2dbe6a5. Проверка остаётся Source/producer свидетельством, не независимым OS-аудитом.

## Контракт

[Машинный контракт](контракт.json) ограничивает AST схемой fum.программа-прямой-композиции-геометрии.1, версией1, одним узлом геометрия-затем-планировщик и целым пределом4096/16384. В Swift интерполируются только проверенные цифры, входные строки не становятся кодом.

У клиента ровно три явных файловых аргумента: определения [приёмника](../priyom-geometrii-okna/) и [планировщика](../okno-metal/), затем один JSON вход. Чтение ограничено65536/65536/262144Б с отдельным байтом обнаружения превышения. Caller до запуска закрепляет regular/nofollow/owner/физические пути/свежие SHA и права. Эти данные прав не создают.

Используется существующий синхронный public API библиотеки FUMStructuringOperatorMemory:

1. ОпределениеОператора.разобрать(Data).
2. AutomationExecutor.выполнить(definition, вход: .текст(JSON), пределы: ..., профиль: nil).
3. Публичный результат должен быть .текст с JSON объектом. Только его ACTUAL входПланировщика передаётся второму существующему определению.

AutomationExecutor — enum, не actor; await/автоматической сериализации нет. Клиент не создаёт файлы, дочерние процессы, окно или GPU-задачу. Его цикл чтения ограничен байтами и не является очередью событий. Ошибка даёт малый JSON stderr и exit1; сбой записи stdout может оставить частичный stdout. Повторы и усечение успешного результата не применяются.

## Воспроизведение

Нужны исходники [существующего bootstrap](../../../Прототипы/память-структурирующих-операторов/README.md), совместимый Swift6/macOS SDK и собранные той же библиотекой object/module. Фактическая проверка использовала уже существующие артефакты build110; чистый клон и иная ABI этим запуском не квалифицированы. Бинарные артефакты и кэши хранятся вне Git.

Следующие переменные выбирает caller: fum_bootstrap — закреплённый существующий Probe; fum_private — новый собственный частный каталог; fum_swiftc/fum_sdk — проверенные физические compiler/SDK; fum_product_dir — каталог совместимых FUMStructuringOperatorMemory.o и FUMStructuringOperatorMemory.swiftmodule. Каталоги tmp/module-cache заранее создаются в fum_private; реальные абсолютные служебные пути не публикуются.

Из корня FUM сначала вычислите положительный вход и сравните полный результат с ожиданием; строку Swift извлекайте только из ACTUAL наблюдения:

```sh
jq -c '.случаи[0].вход' fuma/packages/pryamaya-kompoziciya-geometrii/примеры-проверок.json > "$fum_private/compiler.input.json"
"$fum_bootstrap" исполнить --определение fuma/packages/pryamaya-kompoziciya-geometrii/определение.json --вход текст < "$fum_private/compiler.input.json" > "$fum_private/compiler.observation.json"
jq -e -j 'if .схема == "fum.наблюдение-оператора.2" and .результат.тип == "текст" then (.результат.значение | fromjson | .исходник) else error("Неверное наблюдение") end' "$fum_private/compiler.observation.json" > "$fum_private/main.swift"
```

Точные аргументы проверенной формы линковки:

```sh
TMPDIR="$fum_private/tmp" CLANG_MODULE_CACHE_PATH="$fum_private/module-cache" "$fum_swiftc" -swift-version 6 -parse-as-library -module-name FUMADirectGeometryClient -module-cache-path "$fum_private/module-cache" -sdk "$fum_sdk" -I "$fum_product_dir" "$fum_private/main.swift" "$fum_product_dir/FUMStructuringOperatorMemory.o" -framework Foundation -o "$fum_private/FUMADirectGeometryClient"
```

Для каждого отдельного синтетического входа сохраните его точные байты, предварительное полное ожидание и hash входа до запуска. Пример первого вызова:

```sh
jq '.случаи[0].вход' fuma/packages/pryamaya-kompoziciya-geometrii/примеры-прямого-вызова.json > "$fum_private/direct.input.json"
"$fum_private/FUMADirectGeometryClient" fuma/packages/priyom-geometrii-okna/определение.json fuma/packages/okno-metal/определение.json "$fum_private/direct.input.json"
```

Форматирование входного JSON меняет его hash; не заменяйте ожидаемые hash после исполнения. Runtime-ограничения задаются внешней отчётной обёрткой: фактический compiledeadline120с, purecalldeadline10с и отдельная группа процессов. Ни bytecap, ни jobs1 не являются ограничителем RSS или сетевой песочницей.

## Граница результата

Проверена конечная библиотечная композиция на текущей машине. Живые сигналы ОС, resize/backing/replacement внутри нового обратного контура, физическая дедупликация, выделение поверхностей, видимые пиксели окна, полный AOT/selfhosting и ремонт NativeStop этим этапом не доказаны. Поля effectsfalse и ресурсовВыделено0 остаются данными.

[Apple: ограниченное чтение FileHandle](https://developer.apple.com/documentation/foundation/filehandle/read%28uptocount%3A%29) и [запись DataProtocol](https://developer.apple.com/documentation/foundation/filehandle/write%28contentsof%3A%29) проверены при подготовке Source156; они не заменяют внешнего deadline и проверки владения.
