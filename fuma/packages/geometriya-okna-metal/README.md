# Геометрия окна через FUMA и Metal

[Первичный исходник FUMA](определение.json) порождает полный Swift-адаптер AppKit/CAMetalLayer для двух конечных профилей:320×240→400×300 и480×360→640×480 точек. Один отложенный setContentSize и отдельный таймер закрытия задают конечный опыт. Существующая Metal-библиотека передаётся отдельным аргументом; runtime-компиляции MSL и offscreen-чтения в этом профиле нет.

[Контракт](контракт.json) разделяет событие запроса размера и фактические callback-снимки окна. Запрос не содержит observed geometry. Реальные bounds, backingScale, convertToBacking и drawableSize читаются из собственных объектов AppKit/Metal; редакция повышается при изменении снимка. Ожидать обязательную backing notification при неизменном дисплее нельзя.

[Каталог8 ожиданий](примеры-проверок.json), [полный эталон малого профиля](ожидание-320-в-400.json) и [второго профиля](ожидание-480-в-640.json) закреплены до исполнения. Все восемь CLI-вызовов завершены с кодом0 и пустым stderr; оба полных Swift и шесть диагностик полностью совпали. Независимый consumer проверил все32 IO-файла и извлёк два actual-derived target только из фактического stdout. Исторические NOT_RUN-поля корпуса не переписываются; [фактические результаты](результаты-проверок.json) сохранены отдельно.

Используется существующий [bootstrap](../../../Прототипы/память-структурирующих-операторов/README.md): `FUMStructuringOperatorMemoryProbe исполнить --определение fuma/packages/geometriya-okna-metal/определение.json --вход текст`. stdin — один вход из корпуса как конечный UTF8 JSON. Результат.значение наблюдения fum.наблюдение-оператора.2 разбирается как JSON и целиком сравнивается с полным ожидаемымРезультатом. Swift берётся только из фактического положительного вывода.

Старые [адаптер1](../adapter-okna-metal/README.md), [адаптер2 с readback](../adapter-okna-metal-v2/README.md) и [чистый приёмник](../priyom-signalov-okna-v2/README.md) сохранены. Новый профиль пока не доказывает живой ОС→FUMA-контур, видимость кадра, полный AOT или NativeStop.

[Запрос этапа](../../../Журнал/2026-11-04_05-19-02_MSK_проверить-изменение-размера-окна-из-FUMA/запрос.md), [отчёт](../../../Журнал/2026-11-04_05-19-02_MSK_проверить-изменение-размера-окна-из-FUMA/отчёт.md).

[Фактический прогон геометрии](результат-изменения-размера.json) использовал первый actual-derived Swift17013байт/SHA25619e4aece8aa7cc68b490e9c04d8f82dc3d3ba9337267e83842622d7097d30796. Он собран Swift6 и запущен один раз с существующей Metal-библиотекой. Наблюдались6сигналов: открытие→presentrequest→запрос размера→native resize→presentrequest→закрытие. Content320×240→400×300точек, наблюдённый scale2 и поверхность640×480→800×600пикселей. Request не содержит observed geometry; фактическое изменение повышает revision1→2, закрытие→3. Видимость пикселей и GPUcompletion не подтверждены. Второй target принят как результат FUMA, но не собран/запущен.


Независимое ревью nativeпрогона проверило11 выбранных файлов, все6 IO и все6 строк trace; Source/API-bound resize и закрытие приняты. Оно не является независимым WindowServer/driver-аудитом. В trace не было backing-change callback: масштаб2 прочитан, смена масштаба не испытана.
