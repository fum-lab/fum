# Рабочая память обсуждений GitHub

Здесь FUM хранит полученные тексты Issues, комментарии и их наблюдённые редакции. Для чтения сохранённого состояния GitHub не требуется. Это рабочая память проекта; сохранение ещё не означает принятия предложения или выполнения задачи.

## Прочитать обсуждение без сети

Из корня клона FUM выполните:

```bash
python3 -B Инструменты/fum-materialyi-zaprosov/scripts/архив_обсуждений_GitHub.py \
  --корень-репозитория . --репозиторий fum-lab/fum --номер 207 прочитать
```

Без `--номер` команда возвращает весь локальный каталог. Объёмную выдачу сохраняйте в локальный файл вне публикуемой памяти. Читатель не вызывает внешних процессов, Git или сетевых API; он проверяет точные байты страниц и восстанавливает каталог из наблюдений.

## Сохранить новое наблюдение

```bash
python3 -B Инструменты/fum-materialyi-zaprosov/scripts/архив_обсуждений_GitHub.py \
  --корень-репозитория . --репозиторий fum-lab/fum \
  --метка 2026-10-05_новое-наблюдение получить
```

Нужны установленный GitHub CLI и ранее настроенный доступ. Учётные данные не сохраняются в архиве. Метка обозначает отдельную попытку; уже существующая метка отклоняется до сетевого вызова. Сначала сохраняются все страницы Issues во всех состояниях, затем все страницы комментариев. Каждая полученная страница сохраняется перед разбором. Сбой оставляет полученные байты и неполное наблюдение; повторная попытка не переписывает его.

## Что хранится

- `fum-lab/fum/данные/<sha256>.json` — точные байты тел ответов API, без нормализации и повторной записи одинаковых страниц.
- `fum-lab/fum/наблюдения/<метка>/наблюдение.json` — порядок получения, адрес каждой страницы, следующий адрес Link, длина, SHA-256, результат разбора и полнота попытки.
- В автономном представлении `обращения` ключом является номер Issue или PR. `версии` содержит различные полные записи, а `комментарии` — различные редакции по ID комментария. Повторные одинаковые версии не размножаются. Последовательность наблюдений сохраняется отдельно и остаётся источником временного порядка, включая возврат к прежним байтам.
- `связи` допускают связь с карточками шагов; `обработка: не разобрано` не подменяет смысловое ревью и назначение.

Сканер публикации проверяет принадлежность и хэш сырого обсуждения и сохраняет находки как внешние данные; соседние документы не исключаются из проверки. Литералы HTTP API и открытые фикстуры имеют отдельные конечные исключения политики.

Файлы устанавливаются атомарно с синхронизацией файлов и каталогов. Каждый собственный коммит передаёт их в историю репозитория; чтение из другого чистого клона воспроизводится тестом с запрещёнными внешними процессами и удалённым исходным архивом.

## Проверенное покрытие и границы

Наблюдение 5 октября 2026 года сохранило 186 Issues, 21 PR как записи обсуждений и 124 комментария; завершены обе цепочки страниц. Две предшествующие неуспешные попытки сохранены отдельно. Завершение пагинации не является атомарным снимком GitHub. Редакции между наблюдениями, удалённые до наблюдения данные, вложения, отдельные ревью PR, diff, настройки, workflows и история Actions этим контуром не восстановлены. Необходимо последовательно расширять покрытие, прежде чем заявлять устойчивость всего проекта к постоянному отключению GitHub.

Прежние снимки 4 октября остаются в опубликованной истории и в старых каталогах; их перенос с сохранением времени и происхождения ещё не выполнен. Новые обсуждения сохраняются здесь. Нельзя трактовать отсутствие свежего наблюдения как отсутствие новых предложений.
