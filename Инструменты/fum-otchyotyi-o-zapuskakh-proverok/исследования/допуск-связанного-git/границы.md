# Синтетический допуск Git diff связанного дерева

Это ограниченная fixture, не production admission. Она допускает один защищённый diff рабочего дерева с исходной формой `/bin/sh`, `ulimit`, Git argv, окружением и синтетическим pathspec. Профиль требует ненулевой совпадающий real/effective UID; root и несовпадение проверяются синтетически без смены привилегий. Требуется исходный SIGCHLD по умолчанию без SA_NOCLDWAIT; проверка SIG_IGN выполняется отдельным синтетическим helper. Профиль принимает только закреплённые файлы и каталоги связанного Git-дерева, точные конфигурации, index, refs и loose objects; неизвестные конфигурации, includes, attributes, объекты, символьные ссылки, недоступные каталоги и подмена имени отклоняются до consumer. Записи до и после обнаруживают некоторые изменения, но не защищают от ABA и враждебного same-UID writer. Единственный кооперативный писатель и стабильность всех Git-входов — внешняя предпосылка. Реальный worktree не допущен, guard закрыт.

Для воспроизведения нужны macOS, Swift 6 и точные `/usr/bin/git` SHA-256 `ed6f5284033aa2aae6a58427c25ba3ab119947b40365627b24e5d51a4b70a1cd` и `/bin/sh` SHA-256 `f338dc2ba97328cb8aa29c57a348abf3267de71ef42ee1adf293b179542f2962`; другие бинарники дают отказ. Из корня FUM собрать `swift build --product фум-проверка-кооперативного-git` с частным `--scratch-path`. В новой пустой частной директории создать `home`, `tmp`, `template`, затем выполнить `подготовить.sh` при `env -i`, отдельными HOME и TMPDIR, PATH `/usr/bin:/bin`, LC_ALL `C`, GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL=/dev/null, GIT_ATTR_NOSYSTEM=1, GIT_OPTIONAL_LOCKS=0, GIT_NO_LAZY_FETCH=1, GIT_NO_REPLACE_OBJECTS=1 и датами GIT_AUTHOR_DATE и GIT_COMMITTER_DATE `2001-02-03T04:05:06Z`. Скопировать собранный executable в эту директорию под именем `admission`, собрать `xcrun swiftc игнорировать-sigchld.swift -o /путь/частной/fixture/ignored` и запустить `проверить.sh` с минимальной средой. Фикстура намеренно изменяет только созданные ею каталоги.

Это проверка одного working-tree diff, не полного отпечатка HEAD/index/untracked и не проверки unittest. Кадры не аттестуют фактические argv/image, timestamp до exec или отсутствие конкурентных изменений. При неизвестном исходе timeout путь сперва проверяет `waitpid`: потеря владения исключает сигнал, иначе SIGKILL отправляется собственному ещё не собранному PID с ограниченным ожиданием. Синтетически проверены живой и уже собранный child, но гонка со сторонним reaper между waitpid и сигналом остаётся вне кооперативной модели. Negative nested attributes лежат в пустом каталоге и не доказывают достижимость filter. Состояние `consumer=0` следует из исходника и порядка проверок, syscall trace не записан. Сравнение ожидаемого diff не доказывает общую эквивалентность производства.

Отдельный `контроль-фильтров.sh` в новой пустой частной директории создаёт три новые fixture и запускается с той же явно заданной средой и `admission` из инструкции выше. Прямой незащищённый Git в каждой fixture демонстрирует достижимость безопасного filter с marker для local config, external include и вложенного attributes у tracked файла; затем допуск отклоняет fixture, marker остаётся прежним. Точная причина отказа не установлена, отсутствие consumer следует из исходника и наблюдаемого marker, syscall trace не записан. Контроль не открывает guard и не доказывает production custody.
