# Проверка слияния из master

Этот режим обслуживает явно разрешённое слияние по `AGENTS.md`. Первичный master M предоставляет правила, проверочные инструменты, тесты, фикстуры и зависимости. Кандидат проверяется как вход в отдельном рабочем дереве на предкоммитной основе L с `MERGE_HEAD=M`. После сохранения проверяется тот же коммит C с родителями `[L, M]` и деревом T. Команды ниже не разрешают создавать дополнительные пишущие задачи или публиковать результат.

## Подготовка

Сначала проверяющий контур принимается коммитом в master. В кандидате готовится слияние с этим точным M. Изменение M требует обновить кандидат и повторить приёмку. Архивируемая Swift-обёртка, вложенные инструменты свежести и проектных файлов и материализованный LinguisticKit сверяются с M. Остальная предлагаемая реализация передаётся тестам отдельно; тесты и шаблоны остаются из M.

В примерах используются заранее заданные переменные: `fum_source` и `fum_candidate` — разные физические абсолютные корни M и кандидата; `fum_python` — абсолютный путь текущего Python; `fum_message` — абсолютный файл сообщения коммита. `fum_request` — относительный путь `Журнал/<stem>/запрос.md`, `fum_witness` — соседний `Журнал/<stem>/материалы/контур-слияния.json`. `fum_M`, `fum_L`, позднее `fum_C` и `fum_T` содержат полные OID. `fum_thread` — UUID задачи Codex, а `fum_run` — новый UUID именно полного запуска. `fum_pycache` — отдельный пустой временный каталог вне репозитория для внешних входов Python; после команд он остаётся пустым.

После подготовки обычного запроса и отчёта сформируйте свидетельство. Генератор только проверяет состояние и выдаёт канонические байты в stdout; сначала сохраните успешный вывод во временный файл, затем перенесите в `fum_witness` и добавьте его вместе с каноническими изменениями в индекс кандидата. Ошибка генератора не должна обнулять прежнее свидетельство.

```bash
"$fum_python" -E -B -X "pycache_prefix=$fum_pycache" \
  "$fum_source/Инструменты/fum-kompleksnaya-proverka-repozitoriya/scripts/контур_слияния.py" \
  --корень-кандидата "$fum_candidate" --источник "$fum_M" --ведущая-основа "$fum_L" \
  --запрос "$fum_request" --идентификатор-запуска "$fum_run"
```

Свидетельство должно быть обычным файлом `100644` с одинаковыми байтами в рабочем дереве и индексе. Оно входит в отпечаток полного запуска и не меняется после него. В отличие от снимка запусков, оно находится вне каталога `материалы/запуски-проверок/`.

## Полный запуск

```bash
"$fum_python" -E -B -X "pycache_prefix=$fum_pycache" \
  "$fum_source/Инструменты/fum-otchyotyi-o-zapuskakh-proverok/scripts/отчёты_о_запусках_проверок.py" \
  запустить --корень-репозитория "$fum_candidate" --запрос "$fum_request" \
  --название 'Проверить кандидат слияния' --исполнитель 'Корневая задача' \
  --класс-проверки полная --идентификатор-запуска "$fum_run" -- \
  "$fum_python" -B "$fum_source/Инструменты/fum-kompleksnaya-proverka-repozitoriya/scripts/run-smoke-check.py" \
  --repo-root "$fum_candidate" --request "$fum_request" \
  --commit-message-file "$fum_message" --codex-thread-id "$fum_thread" \
  --источник-проверок "$fum_M" --ведущая-основа "$fum_L" --свидетельство-контура "$fum_witness"
```

Все три параметра происхождения обязательны вместе. Режим использует стандартный документационный план, не допускает `--list`, `--skip-session-coherence`, полный Swift-профиль или произвольную политику кандидата. Внешняя `FUM_CHECKED_CODE_ROOT` этот режим не включает. Обёртка и smoke сверяют контур до и после исполнения; управляют средой Git/Python и отдельным пустым префиксом кэша. Схема записи остаётся `fum.test-run.v3`. Обёртка подтверждает фактическое исполнение меткой `fum.контур-проверки-слияния.1:sha256:<хэш>` в поле полной записи `ожидаемое_свидетельство`: хэш относится к каноническим байтам подготовленного свидетельства. Метку нельзя передать через CLI/API; она выдаётся только при окончательном успехе. Обычный полный запуск оставляет `null`, даже при наличии подготовленного файла с правильным UUID.

После успешного финального запуска выполняется обычное закрытие отчёта, финальная пересборка проекции, проверка замыкания и фиксация C по правилам этапа. Свидетельство не переписывается. Сам успех дочернего процесса ещё не является приёмкой коммита.

## Проверка сохранённого результата

```bash
"$fum_python" -E -B -X "pycache_prefix=$fum_pycache" \
  "$fum_source/Инструменты/fum-otchyotyi-o-zapuskakh-proverok/scripts/закрытый_отчёт_из_гита.py" \
  --корень-репозитория "$fum_candidate" --коммит "$fum_C" --запрос "$fum_request" \
  --допуск-слияния --база "$fum_L" --присоединяемый "$fum_M" --дерево "$fum_T"
```

Читатель берёт закрытый отчёт и свидетельство из C, политику и её происхождение из M. Он требует подтверждение исполнения с совпадающим хэшем в финальной записи и сверяет UUID с последним успешным полным запуском, точные родители и дерево, архивируемый пакет M/L/C и gitlink M/C. Текущие файлы checkout не подменяют эти Git-объекты. Код 0 подтверждает этот уровень доказательства; код 2 означает несовпадение реконструированного отпечатка, код 1 — нарушение предусловий. Низкий режим `--слияние` происхождение проверок не проверяет.

Читатель не продвигает master и не закрывает смысловое обязательство пользователя. Продвижение до того же проверенного C отдельно требует ожидаемого прежнего M и согласованного состояния первичного checkout и индекса. [Отчёт реализации и профиль](../../Журнал/2026-09-10_17-33-36_MSK_закрепить-допуск-слияния-из-master/отчёт.md) сохраняют границы текущей проверки.
