# Проверка закрытого отчёта в коммите

[Читатель](scripts/закрытый_отчёт_из_гита.py) проверяет приёмочные свидетельства, сохранённые в конкретном коммите: полный каталог запусков, закрытый снимок, управляемый блок отчёта, готовность плана и [связь отпечатка с кодом](связь-с-коммитом.md). Это основа последующей проверки обязательств и приёмки переносимых компонентов.

```bash
python3 -B Инструменты/fum-otchyotyi-o-zapuskakh-proverok/scripts/закрытый_отчёт_из_гита.py \
  --корень-репозитория . \
  --коммит <полный-OID> \
  --запрос Журнал/<stem>/запрос.md
```

Передаётся полный OID доступного коммита и точный относительный путь запроса. Корень совпадает с реальным checkout. Без явного режима слияния допускается коммит с одним родителем; merge и начальный коммит отклоняются. Тег и сокращённый OID не принимаются в любом режиме. Отсутствующие объекты не загружаются из сети.

Для точного C с родителями `[L, M]` параметр `--слияние` проверяет закрытый отчёт и связь отпечатков, а `--допуск-слияния` дополнительно требует сохранённое происхождение проверок из M. Режимы взаимоисключающие; оба требуют полные `--база L`, `--присоединяемый M` и `--дерево T`. Подготовка и команды описаны в [проверке слияния из master](проверка-слияния-из-master.md).

| Код | Состояние | Значение |
| --- | --- | --- |
| 0 | `подтверждён` | Закрытый отчёт готов, исторический отпечаток восстановлен и совпадает с обоими свидетельствами. |
| 2 | `не подтверждён` | Отчёт проверен, но историческая реконструкция отпечатка не совпала. Это не доказательство подмены. |
| 1 | Ошибка | Вход, состав, тип объекта, формат, целостность либо готовность не подтверждены. |

Вывод имеет схему `fum.проверенный-отчёт.1`, содержит полный коммит, путь запроса, число запусков, UUID финального запуска, хэш снимка, оба отпечатка и результат их связи. Поле `завершение_обязательства_доказано` всегда равно `false`: успешная приёмка кода сама по себе не закрывает пользовательское обязательство.

## Что проверяется

Режим допуска добавляет `происхождение_проверок`: путь и blob OID свидетельства, M и его дерево, L, обёртку, зависимость, хэш политики, запрос и UUID, равный `финальный_запуск`. Метка исполнения в поле `ожидаемое_свидетельство` финальной записи должна точно связывать канонические байты этого свидетельства. Обычная полная запись с `null` не подтверждает источник M. Свидетельство читается из C; политика и её описание — из M. Проверяются одинаковые деревья архивируемого пакета M/L/C и gitlink M/C. Отсутствие свидетельства, иной режим файла, неканонические байты, другой UUID или источник означают отказ. Этот режим не меняет refs и не доказывает завершение обязательства.

Инвентарь берётся из дерева Git, включая вложенные деревья. Список внутри снимка не служит единственным источником состава. В каталоге запусков недопустимы неизвестные файлы, вложенные каталоги, даже пустые, и переходный журнал возобновления. Запрос, отчёт и свидетельства должны быть обычными blobs с режимом `100644` или `100755`; символические ссылки и gitlink отклоняются. Фактический тип каждого объекта проверяется отдельно от режима записи дерева: tag на корректный blob не подменяет сам blob.

Все JSON-объекты отклоняют повторные ключи и нечисловые константы. Проверяются схемы запусков, UUID, уникальность порядка, совместимость истории, точные хэши и состав снимка. Для самого снимка дополнительно обязательны канонические байты. Форматирование JSON записей может отличаться, если их точные байты связаны согласованными хэшами; это сохраняет контракт прежней обёртки.

Маркер и управляемый Markdown-блок совпадают с результатом существующего генератора. Затем отдельно проверяется экономный план: закрытый, но неготовый отчёт не принимается. Последняя запись должна быть единственной успешной полной v3-приёмкой на отпечатке закрытия. Допустимость предшествующих исторических записей определяется прежней проверкой порядка.

## Чтение без побочных изменений

Исторические свидетельства читаются из Git, даже если живые запрос, отчёт или снимок в checkout удалены либо испорчены. Исправленный checkout также не исправляет плохой архив в выбранном коммите. Читатель не создаёт временный checkout, журнальные lock-файлы или новые записи проверки и не меняет индекс, refs либо конфигурацию. При запуске Python используется `-B`, чтобы импорт не создавал `__pycache__`.

Git получает только полные OID объектов из выбранного дерева. Один пакетный вызов возвращает уникальные объекты, сохраняя соответствие каждому исходному пути. Парсер проверяет точный OID, тип, десятичный размер, байты заданной длины, разделительный LF и точный конец ответа. Ненулевой exit code Git, отсутствующий объект, пропуск, перестановка и лишний ответ означают отказ без частичного результата. Вывод пакета целиком хранится в памяти.

## Границы доказательства

Читатель использует доверенный локальный Git; независимый пересчёт Git OID и полный аудит повреждения объектной базы не входят в контракт. Историческая реконструкция наследует ограничения адаптера по конфигурации и буквальному diff. Проверяется управляемое свидетельство, а не истинность свободного текста отчёта.

Содержимое пользовательских команд, `Codex-Thread-ID`, полнота реестра, смысловая приёмка результата и актуальность обязательства требуют следующего слоя. Наличие обычного файла запроса ещё не доказывает происхождение команды. Читатель не выполняет merge и не подключён к завершению Codex. Сохранённые v4-поставки прежнего конвейера автоматически не становятся принятыми v3-результатами.

## Измерение

[Профиль сравнения](../../Журнал/2026-09-10_02-01-28_MSK_проверять-закрытые-отчёты-из-коммитов/материалы/профиль-сравнения.json) воспроизводится [сценарием](../../Журнал/2026-09-10_02-01-28_MSK_проверять-закрытые-отчёты-из-коммитов/материалы/измерить-чтение-отчёта.py) на принятом коммите `6fc2c7a76dd7d23a703418b4072f0fdc561a4f53`. Для отчёта с 39 запусками число процессов Git уменьшилось с 94 до 11; медианы семи чередующихся повторов составили 1405,964 и 178,280 мс. Результаты обоих вариантов совпали. Импорты и отдельный замер памяти не входят во временную серию; это не холодный дисковый кеш и не время CLI. Пиковая учтённая память Python составила 679198 и 679360 байт; память дочерних Git-процессов не измерялась. Ускорение относится к этому входу и окружению.

[Тесты](tests/test_закрытый_отчёт_из_гита.py) используют настоящий форматирующий и отчётный механизм в автономных временных репозиториях. Дочерний smoke в фикстуре синтетический: эти тесты не заявляют выполнение реального полного набора. Реальная приёмка текущего кода выполняется отдельно и сохраняется в [отчёте этапа](../../Журнал/2026-09-10_02-01-28_MSK_проверять-закрытые-отчёты-из-коммитов/отчёт.md).
