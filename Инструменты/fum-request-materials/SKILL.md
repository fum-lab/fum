# FUM Request Materials

Этот навык фиксирует прикрепляемые материалы как часть памяти FUM, сохраняя связь:
исходный запрос -> папка источников -> производная документация или инструмент -> коммит.

## Основной протокол

1. Создай или обнови файл исходного запроса `Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md` по правилам `AGENTS.md`; текст запроса сохраняй дословно. При импорте знаний из ChatGPT-диалога выбирай краткое название запроса по содержанию диалога после первичного извлечения или чтения, а не по общему факту импорта из ChatGPT.
2. Для материала с устойчивым URL используй каноническую URL-папку `Источники/URL/<scheme>/<host>/<path...>/`: цепочка каталогов повторяет схему, домен и путь URL. Повторные запросы на тот же URL должны ссылаться на эту же папку, а не создавать копию. Для материала без устойчивого URL используй папку `Источники/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>_<описательное-название>/`.
3. Сохраняй источник максимально сыро: URL, HTTP-заголовки, тело ответа, встроенные JSON/потоки приложения, извлечённые сообщения или текст, отчёт об извлечении.
4. Не коммить секреты и локальные служебные данные. Redact `Set-Cookie`, токены, локальные IP/геометаданные запроса, сессионные идентификаторы, служебные request-id распакованных потоков и другие значения, не являющиеся содержанием материала. Каждую редакцию фиксируй в отчёте.
5. В файле запроса в `Запросы/` укажи ссылку на папку источника в `Источники/` и, когда полезно, на отчёт об извлечении или основные извлечённые файлы. Если материал влияет на требования, документацию, глоссарий или инструменты, укажи эти ссылки в разделе `## Повлиял на файлы` или отдельном разделе `## Прикрепляемые материалы` файла запроса.
6. Перед коммитом выполни `git status --short` и включи только осмысленные изменения текущей сессии.

## Целостность повторного снимка

`archive-chatgpt-share.py` собирает каждый новый снимок в скрытом соседнем staging-каталоге на той же файловой системе, не записывая промежуточные результаты в каноническую URL-папку. Перед установкой скрипт создаёт `snapshot-manifest.json` схемы `fum.request-materials.snapshot-manifest.v1` и проверяет точное равенство отсортированного списка `managed_files` фактическому набору файлов staging.

Первый снимок устанавливается атомарным переименованием каталога. Повторный снимок заменяет существующий каталог одним обменом директорий: `RENAME_SWAP` на macOS или `RENAME_EXCHANGE` на Linux. Если системный вызов или файловая система не поддерживает атомарный обмен, повтор закрывается с ошибкой до изменения канонического снимка; двухшаговая замена через временно отсутствующий канонический путь не допускается.

После успешного обмена новый канонический каталог уже является зафиксированным целым снимком. Ссылка добавляется в файл запроса через временный sibling и атомарный `os.replace`, поэтому I/O-сбой не должен усекать прежний текст запроса. Невозможность добавить ссылку выводится как отдельное предупреждение `request_file_linked error` и не выдаётся за неуспешное архивирование уже установленного снимка. Очистка прежнего снимка из staging выполняется best-effort; если скрытый соседний `.staging-*` остался после commit, скрипт явно предупреждает об этом. Такой каталог не входит в новый манифест, не считается каноническим источником и должен быть отдельно проверен как локальный временный остаток перед коммитом.

## Проверки

Локальные тесты скриптов навыка запускаются без сетевых вызовов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-request-materials/tests -p 'test_*.py'
```

При изменении скриптов сначала добавляй или обновляй тест ожидаемого поведения, затем меняй реализацию и повторяй запуск тестов. Сквозной автономный контракт включает последовательности `полный снимок -> неполный снимок`, `полный снимок -> поздний сбой staging` и отказ без записи, когда атомарный обмен каталогов недоступен.

## ChatGPT share

Для расшаренных чатов ChatGPT используй скрипт:

```bash
python3 Инструменты/fum-request-materials/scripts/archive-chatgpt-share.py \
  "https://chatgpt.com/share/<id>" \
  --request-file "Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md"
```

Скрипт по умолчанию сохраняет в папку источников `Источники/URL/https/chatgpt.com/share/<id>/`. `--output-dir` используется только для явного нестандартного размещения, а `--source-name` сохранён для совместимости и не нужен для обычного URL-пути.

В папке источников сохраняются:

- `source-url.txt` - исходная ссылка.
- `chatgpt-share.headers.txt` - HTTP-заголовки с редактированными cookie.
- `chatgpt-share.html` - HTML-ответ с редактированным локальным bootstrap-состоянием.
- `chatgpt-share.script-XX.txt` - крупные скриптовые блоки и потоковые данные приложения.
- `chatgpt-share.initial-state.json` - редактированное начальное состояние страницы, если оно найдено.
- `chatgpt-share.react-router-stream.txt` - извлечённый поток React Router.
- `chatgpt-share.decoded-data.json` - распакованные данные диалога, если формат распознан.
- `chatgpt-share.messages.json` - полный структурный слой извлечённых сообщений в порядке диалога.
- `<название-диалога-в-kebab-case>.md` - оформленный человекочитаемый слой диалога.
- `source-index.md` - человекочитаемый индекс источника со ссылками на оформленный слой, отчёт и структурные файлы.
- `extraction-report.md` - отчёт о способе извлечения, количестве сообщений и редакциях.
- `snapshot-manifest.json` - точный отсортированный перечень всех файлов, которыми управляет установленный снимок, включая сам манифест.

Оформленный Markdown-файл должен быть назван по человекочитаемому названию диалога из источника или безопасному fallback-названию, например `запуск-долгоживущей-цепочки.md`. Заголовок первого уровня равен этому названию, а сообщения имеют читаемые русские подписи ролей. Служебные сообщения, выводы инструментов и машинные JSON-вызовы не включаются в оформленный слой; они сохраняются в `chatgpt-share.messages.json`.

TeX-формулы в оформленном Markdown-слое приводятся к формату, который Obsidian отображает через MathJax: блочные формулы пишутся в `$$ ... $$`, а строчные формулы - в `$...$`. Сырой структурный слой не нормализуется ради отображения.

Если в папке источника есть `source-index.md`, укажи в нём человекочитаемое название диалога и ссылку на оформленный Markdown-файл с названием диалога, чтобы источник можно было понять без открытия сырого JSON или HTML.

Скрипт также обновляет файл, переданный через `--request-file`: добавляет раздел `## Прикрепляемые материалы` со ссылками на папку источника, `source-index.md` и `extraction-report.md`. Повторный запуск для того же запроса и источника не должен дублировать эти ссылки.

Если скрипт не смог извлечь сообщения, оставь сырой HTML, заголовки, потоковые блоки и отчёт с причиной. Не выдумывай отсутствующий текст диалога.

## Другие материалы

Для нераспознанного формата сохраняй наиболее близкий к сырому слой, который реально получен:

- для URL - заголовки, тело ответа, effective URL, код ответа и дату извлечения;
- для файлов - оригинальный файл без нормализации и отдельный отчёт о происхождении;
- для динамических страниц - HTML, скриншот или текст DOM, если они доступны, плюс описание ограничения.

Если материал невозможно получить из-за доступа, истечения share-ссылки или защиты, зафиксируй это в отчёте и в файле запроса.
