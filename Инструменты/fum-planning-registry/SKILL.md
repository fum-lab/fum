# FUM Planning Registry

Этот навык описывает локальную [автоматизацию FUM](../../Глоссарий/автоматизация-FUM.md), которая собирает машинно читаемый JSON-реестр планового слоя проекта из текущих Markdown-источников:

- [сводной таблицы требований и реализаций](../../Планирование/сводная-таблица-требований-и-реализаций.md);
- [дорожной карты](../../Планирование/дорожная-карта.md);
- [направлений проектирования и развития](../../Планирование/направления-проектирования-и-развития/README.md);
- [MVP-кандидатов](../../Планирование/MVP-кандидаты/README.md);
- [предложений о следующих шагах](../../Планирование/предложения-о-следующих-шагах.md);
- [открытых вопросов](../../Вопросы/README.md).

Результат хранится в [реестре требований, стадий реализации и кандидатов](../../Планирование/реестр-требований-вариантов-и-кандидатов.json). Он не заменяет исходные Markdown-материалы, а даёт проверяемый слой для программной сверки и будущей пересборки навигации.

## Когда использовать

Используй эту автоматизацию, когда меняются плановые материалы, сводная таблица, направления, MVP-кандидаты, предложения или вопросы и нужно убедиться, что машинно читаемый слой соответствует текущему состоянию памяти.

Автоматизация также полезна перед разработкой новых плановых проверок: JSON уже содержит нормализованные требования, предполагаемую реализацию на документационной стадии, предполагаемую реализацию в коробочной FUM, кандидатов, дорожные горизонты, активные предложения, историю предложений и вопросы по статусам.

## Команды

Собрать реестр:

```bash
python3 Инструменты/fum-planning-registry/scripts/build-planning-registry.py build \
  --output Планирование/реестр-требований-вариантов-и-кандидатов.json
```

Проверить, что сохранённый реестр не устарел относительно источников:

```bash
python3 Инструменты/fum-planning-registry/scripts/build-planning-registry.py validate \
  --registry Планирование/реестр-требований-вариантов-и-кандидатов.json
```

## Что проверяется

Валидатор:

- проверяет JSON-схему `fum.planning.requirements-registry.v2`;
- пересобирает ожидаемый реестр из текущих источников и сравнивает его с сохранённым файлом;
- фиксирует хэши исходных Markdown-файлов без служебного блока `FUM-MD-RECENCY`;
- проверяет, что в источниковом инвентаре есть дорожные горизонты, направления, MVP-кандидаты, предложения и вопросы по статусам;
- проверяет, что MVP-кандидаты покрыты требованиями или очередью продуктовых кандидатов.

## Проверки автоматизации

Локальные тесты запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-planning-registry/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: сборка нормализует требование, две стадии реализации, MVP-кандидата, направление, предложение и вопрос; валидатор принимает свежесобранный JSON и сообщает об устаревании после изменения источника.

## Граница автоматизации

Скрипт не выводит новые требования из смысла документов и не решает, какой MVP выбирать в работу. Он нормализует уже записанный плановый слой и помогает обнаружить расхождение между машинно читаемым реестром и Markdown-источниками. Смысловая ответственность за формулировки требований, статусы предложений и открытые вопросы остаётся у рабочей сессии.
