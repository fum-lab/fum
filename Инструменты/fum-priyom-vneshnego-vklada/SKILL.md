# Приём внешнего вклада

Каноническое русское имя автоматизации — `приём внешнего вклада`. Навык связывает внешнего агента без пишущего checkout с единственной локальной корневой сессией FUM. Внешний агент производит предложение, но не становится писателем `master`. Успех валидатора не означает принятие, коммит, push, прохождение локальных проверок или разрешение публикации.

## Маршрут Web ChatGPT

1. Зафиксируй публичный HTTPS-адрес репозитория и полный OID опубликованного базового коммита, который читает агент.
2. Передай [шаблон запроса](шаблон-запроса-внешнему-агенту.md). Финальное текстовое сообщение должно содержать ровно одну ограду `fum-внешний-вклад-v1` с полным пакетом `fum.пакет-внешнего-вклада.v1`. Ссылка `sandbox:/...`, перечень файлов, предполагаемый SHA и самоотчёт о GitHub API не заменяют пакет.
3. В отдельной локальной корневой задаче архивируй share навыком `fum-materialyi-zaprosov`, затем проверь файл сообщений:

```bash
python3 Инструменты/fum-priyom-vneshnego-vklada/scripts/proveritj-paket-vneshnego-vklada.py \
  проверить-share \
  --корень-репозитория . \
  --запрос Журнал/<текущая-сессия>/запрос.md \
  --сообщения Источники/URL/https/chatgpt.com/share/<id>/chatgpt-share.messages.json \
  --выход-пакет Журнал/<текущая-сессия>/материалы/внешний-вклад/пакет.json \
  --выход-патч Журнал/<текущая-сессия>/материалы/внешний-вклад/предложение.patch \
  --выход-проверка Журнал/<текущая-сессия>/материалы/внешний-вклад/проверка.json
```

4. Прочитай stdout и все три материала. Только локальная корневая сессия решает, какие строки принять, и сама формирует `Журнал/`, recency, индексы, `Proyekcii/**`, проверки и единственный коммит. Push остаётся отдельным явным действием пользователя.

Отдельный JSON-пакет проверяется командой `проверить` с теми же `--корень-репозитория` и `--запрос`, обязательным `--пакет <пакет.json>` и необязательным `--выход-патч` в точное место текущей сессии.

## Контракт версии 1

[Схема JSON](схемы/пакет-внешнего-вклада-v1.schema.json) задаёт переносимый структурный слой. Валидатор не исполняет её как библиотеку: он сам закрыто проверяет все поля и добавляет Git-инварианты. Пакет содержит UUID v4, `репозиторий`, утверждение, критерии, ограничения, отсортированный манифест, честные статусы проверок и патч размером не более 256 КиБ с Base64, исходным размером и SHA-256. Перед построением патча каждый новый непустой путь ставится в intent-to-add командой `git add -N -- <новые-пути>`; иначе обычный `git diff` его не увидит. Затем выполняется каноническая команда `git -c core.quotePath=false diff --binary --full-index --no-renames --no-color --src-prefix=a/ --dst-prefix=b/ --no-ext-diff --no-textconv`; после сохранения точных байтов intent-to-add можно убрать командой `git reset -q -- <новые-пути>`. `Codex-Thread-ID` в пакет не входит. Версия 1 принимает только содержательные изменения с обычными текстовыми hunks либо двумя каноническими binary-fragments; пустой файл без hunk и чистая смена режима остаются за её пределами.

## Закрытая граница

До любой выходной записи валидатор требует:

- первичный checkout на `refs/heads/master` и точное совпадение `HEAD`, локально наблюдаемого `origin/master` и базы пакета;
- точный обычный `Источники/URL/https/chatgpt.com/share/<id>/chatgpt-share.messages.json` без символических ссылок, совпадение `<id>` с `source_url` архива и отсутствие известных секретов как в сырых JSON-байтах, так и после декодирования JSON;
- HTTPS-адрес `origin`, Base64, размер, SHA-256, full-index OID и полное совпадение манифеста с diff;
- UTF-8 и NFC, безопасные пути и обычные режимы, без path traversal, rename/copy, symlink, gitlink, управляющих Unicode-символов и NFC/casefold-коллизий между префиксами предложения либо с префиксами базового дерева;
- отсутствие известных сигнатур секретов в метаданных, патче и конечных распакованных объектах;
- собственное ограниченное декодирование Git Base85 и zlib обоих binary-fragments до запуска Git: для `literal` проверяется точный результат, для `delta` — размер программы, размеры источника и результата и весь поток copy/insert-команд; суммарная распаковка и результаты каждого направления ограничиваются немедленно;
- привязку delta-источников и reverse-результатов к фактическим размерам базовых blobs, а forward-результатов — к вычисленным Git размерам новых blobs; до применения проверяются также уже существующие объекты заявленных новых OID и консервативная верхняя граница текстовых результатов;
- ограничение размера файлов, процессорного и wall-clock-времени дочернего Git и `cat-file --batch-check` до чтения содержимого;
- применимость патча только во временном `GIT_INDEX_FILE` и отдельном `GIT_OBJECT_DIRECTORY`, где реальная база объектов доступна только для чтения;
- точное совпадение каждого бинарного раздела с локально регенерированным каноническим diff и возврат полного базового дерева при обратном применении;
- не более 8 МиБ на каждый базовый или конечный объект и 32 МиБ суммарно по путям, распакованным фрагментам и результатам каждого направления;
- выходы только по точным именам в `Журнал/<текущая-сессия>/материалы/внешний-вклад/`, привязанные к точному `запрос.md`.

Любой компонент `.git*`, `.codex`, `.github`, `.obsidian`, любой вложенный `AGENTS.md`, а также корневые `Правила/агентов/**`, `Инструменты/**`, `Журнал/**`, `Источники/**`, `Proyekcii/**` и `Зависимости/**` запрещены. Валидатор вызывает прямой и обратный `git apply --cached` только в изолированных временных индексе и базе объектов; реальные checkout, index, refs, remote и `.git/objects` не меняются. Выходные файлы создаются без перезаписи только после полной проверки.

`проверка.json` связывает кандидат с SHA-256 архива сообщений, индексом финального сообщения, адресом share и хэшами сырого и канонического пакета и патча. Статусы `применено`, `закоммичено` и `опубликовано` в нём заведомо ложны: это свидетельство происхождения, но не квитанция принятия.

## Большой вклад и граница подтверждения

Патч больше 256 КиБ передаётся через отдельный fork/ветку и закреплённый неизменяемый черновик pull request, созданный средой с write-доступом, например Codex web/cloud. Такой PR остаётся недоверенным предложением и не разрешает автоматический merge.

Автономный набор тестов синтезирует структурный share-архив и проверяет маршрут без сети. Это не живой canary Web ChatGPT. Исходный диалог создан до введения протокола и не содержит пакета v1; его предметные изменения эта сессия не импортирует.
