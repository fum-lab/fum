# Шаблон запроса внешнему агенту Web ChatGPT

Скопируй текст ниже в Web ChatGPT, замени значения в угловых скобках и добавь предметную задачу. Внешний агент должен вернуть предложение, а не имитировать локальную сессию FUM.

---

Работай как внешний производитель недоверенного предложения изменения для публичного репозитория `<HTTPS-URL-РЕПОЗИТОРИЯ>` на точном опубликованном commit `<40-СИМВОЛЬНЫЙ-BASE-COMMIT>`.

Предметная задача:

`<ОПИШИ ОЖИДАЕМОЕ СОДЕРЖАТЕЛЬНОЕ ИЗМЕНЕНИЕ>`

Изучи репозиторий и его действующие правила в указанном снимке; не пытайся писать в `master` через штатное GitHub-подключение ChatGPT; не объявляй commit, push, branch, pull request, `git am` или локальные проверки успешными без наблюдаемого результата соответствующего инструмента; не создавай `Codex-Thread-ID`: это поле может получить только реальная локальная корневая задача Codex; не используй `sandbox:/...` как единственный носитель результата и не подменяй полный payload перечнем файлов или описанием.

Подготовь публикационно чистое предложение только для содержательных путей. Не включай `.git*`, `.codex/**`, `.github/**`, `.obsidian/**`, любой `AGENTS.md`, `Правила/агентов/**`, `Инструменты/**`, `Журнал/**`, `Источники/**`, `Proyekcii/**` и `Зависимости/**`. Не включай секреты, cookie, токены, приватные URL и машинно-локальные пути.

В последнем обычном текстовом сообщении выведи ровно один полный JSON-объект внутри одной ограды `fum-внешний-вклад-v1`. Объект обязан соответствовать `fum.пакет-внешнего-вклада.v1` из `Инструменты/fum-priyom-vneshnego-vklada/схемы/пакет-внешнего-вклада-v1.schema.json` и содержать:

- канонический случайный UUID v4 в `идентификатор_предложения`;
- точные `репозиторий.адрес` и `репозиторий.базовый_коммит`;
- непустые `утверждение`, `критерии_приёмки` и `ограничения`;
- отсортированный по UTF-8 манифест операций `добавить`, `изменить` и `удалить`;
- единый patch: сначала поставь каждый новый непустой путь в intent-to-add командой `git add -N -- <НОВЫЕ-ПУТИ>`, затем построй точные байты командой `git -c core.quotePath=false diff --binary --full-index --no-renames --no-color --src-prefix=a/ --dst-prefix=b/ --no-ext-diff --no-textconv`; после сохранения патча intent-to-add можно убрать через `git reset -q -- <НОВЫЕ-ПУТИ>`; патч должен быть не более 256 КиБ до Base64 и сопровождаться исходным размером, lowercase SHA-256 и Base64 без изменения байтов; каждый путь должен менять содержимое обычным hunk либо точной парой forward/reverse binary-fragments, а пустой файл без hunk и чистая смена режима в версию 1 не входят;
- честные `заявленные_проверки`: статусы `пройдена` и `неуспешна` только со `свидетельством`, `не_запускалась` и `неопределённо` только с `причиной`.

Форма финального блока:

````text
```fum-внешний-вклад-v1
{
  "схема": "fum.пакет-внешнего-вклада.v1",
  "идентификатор_предложения": "<UUID-V4>",
  "репозиторий": {
    "адрес": "<HTTPS-URL-РЕПОЗИТОРИЯ>",
    "базовый_коммит": "<40-СИМВОЛЬНЫЙ-BASE-COMMIT>"
  },
  "утверждение": "<ПРОВЕРЯЕМОЕ УТВЕРЖДЕНИЕ>",
  "критерии_приёмки": ["<КРИТЕРИЙ>"],
  "манифест": [{"путь": "<ПУТЬ>", "операция": "<добавить|изменить|удалить>"}],
  "патч": {
    "формат": "полный-бинарный-патч-git-v1",
    "кодировка": "base64",
    "размер_в_байтах": 1,
    "хэш_sha256": "<64 LOWERCASE HEX>",
    "данные": "<BASE64>"
  },
  "заявленные_проверки": [{
    "название": "<НАЗВАНИЕ>",
    "статус": "не_запускалась",
    "свидетельство": null,
    "причина": "<ПОЧЕМУ НЕ ЗАПУЩЕНО>"
  }],
  "ограничения": ["Предложение не является commit, push или квитанцией принятия."]
}
```
````

Перед ответом сам декодируй Base64, повторно вычисли размер и SHA-256 и сверь манифест с каждым `diff --git`. Если полный пакет невозможно сформировать или он не помещается в одно сообщение, прямо сообщи о недоставленном результате и предложи использовать Codex web/cloud с отдельным fork и draft pull request; не выдавай частичный либо потерянный payload за доставленный.

---

Локальная задача всё равно рассматривает пакет как недоверенный кандидат, архивирует share и выполняет собственные проверки FUM.
