# Общий терминал двух отказавших обратных приёмов

Текущий срез — контрольная наработка до приёмки реального эпизода. Снимки файлов обоих детей удерживаются до последней сверки: данные первого повторно проверяются после проверки второго и после подтверждения владельца под замком, непосредственно перед записью терминала. Адресные сценарии воспроизводят удаление архива остановки и изменение замороженного входа первого ребёнка во втором плане; отказ сохраняет байты реестра.

Когда оба писателя уже опубликовали свои первоначальные коммиты, а приём объединённого среза завершился адресным отказом, [терминал `.9`](scripts/завершение_отказавшего_приёма.py) сохраняет этот исход. Он связывает два первоначальных создания и остановки, опубликованные поставки, обратные поручения, последние отдельные ожидания, первичные события CLI и сохранённые файловые основания. Один приём может быть прямым, другой — через сохранённый ответ обёртки.

Для каждого ребёнка заново читаются живой префикс и идентичность файла. [Проверка замороженного входа](scripts/замороженный_вход_отказавшего_приёма.py) сравнивает его с физическими файлами исходного пакета: конвертом, поручением, входом, снимком, описанием и их хэшами. Путь в описании должен указывать на настоящий нативный источник ребёнка. Из сохранённого основания повторно выводится нативное получение, первоначальный остановленный ход и связь с независимо найденными send и wait. Самосогласованных заявленных хэшей недостаточно.

[Физический архив](scripts/архивный_префикс_приёма.py) читается по исходному пути конверта. Архив остановки должен побайтно совпасть с первоначальным префиксом ребёнка. Архив ROOT потоково сравнивается с полным корневым снимком, независимо разбирается и повторно сверяется перед возвратом плана. Проверяются точный регистр пути, обычный файл, владелец, число ссылок, режим доступа, размер, метаданные, LF и хэши. Открытие нативного источника использует запрет перехода по symlink и неблокирующий режим; подмена на именованный канал отклоняется.

Первоначальный барьер допускает остановку первого писателя до создания второго. Узкий [селектор первоначальных передач](scripts/первоначальные_ожидания_поставок.py) применяется только в `.9`: каждый последний отдельный wait следует после своего создания; первое ожидание и второе создание не перекрываются. Направление их порядка должно совпасть одновременно по байтовым границам и интервалам runtime. Оба первоначальных ожидания завершаются до первого обратного send. Старый общий селектор и `.8` сохраняют прежний смысл.

Два обратных send идут последовательно, а приёмы могут выполняться одновременно до раздельных последних waits. Этот порядок допускается только конечным вызывающим кодом `.9`; прежний селектор по умолчанию остаётся последовательным. Общий wait не заменяет два отдельных наблюдения.

Локатор CLI сохраняет настоящий живой JSONL, переданный ребёнку через `--исходник`. Адрес замороженного файла терминал отдельно выводит из канонического поручения и передаёт файловому читателю. Сохранённый `вход.json` продолжает ссылаться на файл своего приватного пакета; описание снимка связывает его с живым источником. Переписывание исторического CLI-локатора адресом пакета отклоняется.

Кеш принадлежит одному вызову построения плана. Ключ включает полные описания источников, корневой UUID, детей и параметры чтения. Повторный потребитель получает отдельную копию результата после проверки текущих метаданных. Заключительная сверка повторно проверяет байты каждого уникального архива, первоначальные снимки дочерних файлов, отсутствие поздних результатов и сохранённый канал отказа. Снимок при повторной проверке не пересоздаётся: подмена inode с теми же байтами остаётся изменением. Новый план, включая проверку под замком, создаёт новый кеш. Постоянного кеша, который мог бы перенести допуск в следующий эпизод, нет.

Записывается только общий терминал с закреплённым хэшем входа и истории. Перед записью выполняется повторный план и проверка владельца под замком. Проверенный повтор возвращает прежний терминал без чтения живых источников. Старые квитанции и Git-эффекты сохраняются; неизвестный исход слияния остаётся неизвестным, автоматический повтор воздействия не разрешается. Отсутствие любых ненаблюдаемых вызовов этим контуром не доказывается.

## Воспроизведение

Штатная команда `scripts/запустить-слои.py` выбирает `.9` по схеме `fum.завершение-неудачного-запуска.9`. Приватный вход находится вне Git. Для предпросмотра используется `завершение-предпросмотр --вход <приватный-вход>`, для записи просмотренного результата — `завершить --вход <тот-же-вход> --sha256 <просмотренный-хэш>`, с обязательными корнем и UUID задачи. Все содержательные проверки запускаются через отчётную обёртку текущей пары Журнала.

[Адресные сценарии](tests/test_терминала_отказов.py) проверяют два опубликованных Git-коммита и синтетические первичные MCP/CLI-события, подмены источников и оснований, параллельные приёмы, гонку перед записью и повтор без живого чтения. [Отдельные проверки архива](tests/test_архивного_префикса_приёма.py) проверяют регистр, повреждение байтов, границу кеша и подмену на именованный канал. Внешние задачи Desktop этими фикстурами не запускаются; реальный эпизод принимается отдельно.

Профиль `tests/измерить_архивный_префикс_приёма.py --выход <новый-файл>` сравнивает два независимых разбора одного физического архива с двумя потребителями общего кеша. Сохраняются прогрев, три чередующихся повтора, точные входные хэши, одинаковый результат, число разборов и монотонные длительности. Измеряется компонент архива; Git, Desktop и полный терминал исключены.

Профиль `tests/профиль_заключительной_сверки_приёма.py --выход <новый-файл>` отдельно измеряет стоимость добавленной проверки восьми дочерних файлов на неизменных синтетических входах. Сравнение с режимом только ROOT показывает цену исправления пропущенной защиты; прежний режим не является допустимым вариантом приёмки.

Профиль `tests/профиль_разделения_источников_приёма.py --выход <новый-файл>` выполняет адресные сценарии разных живого и замороженного источников, подстановки локатора и исторического повтора. Он сохраняет фазы одного успешного предпросмотра на открытой фикстуре. Подготовка фикстуры и проверки после этого предпросмотра не входят в замер; парного сравнения версий, реального ROOT и Desktop здесь нет.


Профиль `tests/профиль_первоначальных_ожиданий.py --выход <новый-JSON>` измеряет чистый селектор на открытых разобранных входах. Для общего прежнего порядка результаты обоих селекторов должны совпасть; новый порядок остановки измеряется отдельно. Семь чередующихся пакетов после прогрева сохраняют длительности, хэши входа и модулей. Git, JSONL и Desktop исключены; этот профиль не доказывает ускорения полного терминала.
