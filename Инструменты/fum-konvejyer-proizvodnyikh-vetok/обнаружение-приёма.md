# Обнаружение обратного приёма

Получатель находит приватный конверт по единственному нативному поручению. Координатору не нужно отправлять второй `send` с путями: адрес вычисляется из корневой задачи, исполнителя, плана и первоначального назначения. Конверт связывает исходный план, реестр владельцев, свидетельство завершённой отправки и поля будущего коммита. Приём Git по-прежнему выполняет [существующий вход](вход-получателя.md).

Этот слой предназначен для конечного пилота. Он не включает heartbeat, dispatcher, повторный запуск задач, общую приёмку или публикацию Git. Код и действующие разрешения приёма должны находиться в первоначальной базе C.

## Координатор

Сначала сохраняются остановка получателя и точный план обратной доставки. Затем выполняется один `send_message_to_thread` с текстом `приём_интеграции.сформировать`. После его завершения сохраняется полный префикс нативного JSONL корня с фактическими идентификаторами ожидания и отправки. Само наличие подготовленного текста не доказывает отправку.

Вход публикации находится вне Git и содержит ровно `текст`, `план`, `владельцы`, `свидетельство`, `коммит`. `владельцы` — объект реестра, а не путь к изменяемому файлу. `коммит` содержит `имя_автора`, `заголовок`, `описание`. Свидетельство сохраняет прежнюю схему `fum.свидетельство-дочернего-приёма.1`.

```bash
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/подготовить-приём.py опубликовать --вход <приватный-вход.json>
```

Публиковать может только нативная корневая задача. На macOS адрес имеет вид `/Users/Shared/FUM-private-<uid>/<ROOT>/входы-приёма/<ключ>`. На остальных платформах используется приватная область `~/.local/state/FUM`. Git-предок, symlink, чужой владелец и несоответствующие права закрывают допуск. Вложенные каталоги имеют режим `0700`, неизменяемые файлы — `0400`.

Сначала сохраняется `конверт.json`, затем готовность атомарно переименовывается в `готово.json`; файлы и каталоги синхронизируются. Повтор завершённой публикации сохраняет inode и байты и повторяет синхронизацию. Частичная публикация без готовности требует разбора координатором и не перезаписывается. Писатель один; защита от злонамеренного процесса с тем же UID не заявлена.

## Получатель

Нативный JSONL собственной задачи — единственный ручной адрес входа. Точный текст поручения извлекается из его `send_message_to_thread`; происхождение, HTML-экранирование, UUID, физический корень и единственность входа проверяются программой.

```bash
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/подготовить-приём.py ожидать --исходник <свой-native.jsonl> --предел-секунд 30
```

Отсутствующая готовность возвращает `ожидается-конверт`, без создания каталогов, эпизода, индекса или Журнала. Один вызов ждёт не более 60 секунд. При согласованной подготовке координатором можно повторять только это чтение в пределах конечного окна ожидания пилота; истечение одного вызова не означает завершения задачи. Повреждённый готовый пакет возвращает отказ и требует разбора. Ожидание не разрешает Git-эффект.

После состояния `готово`:

```bash
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/подготовить-приём.py принять --исходник <свой-native.jsonl>
```

Полный существующий допуск проверяет C → H → S, приёмку, назначение, остановку, завершённый send и точный полученный текст. Только затем создаётся свой приватный пакет в `<исполнитель>/приёмы/<ключ>`. Он включает неизменяемую копию native, реестра, конверта и вычисленного входа `.1`. Старый механизм создаёт merge-состояние и четыре файла J, возвращая вход `.4`. Путь `источник_модели` указывает на сохранённые байты вне Git, даже если живой native расположен внутри Git-предка.

Получатель заполняет собственные запрос и отчёт, сохраняя импорт S без изменений. Дальнейшие фазы:

```bash
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/подготовить-приём.py подготовить --исходник <свой-native.jsonl>
```

Затем применяются прежняя собственная свежесть, назначенная адресная проверка, предпросмотр отчёта и точный индекс четырёх файлов. После них:

```bash
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/подготовить-приём.py готово --исходник <свой-native.jsonl>
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/подготовить-приём.py создать --исходник <свой-native.jsonl>
```

UUID проверки вычисляется из подтверждённого поручения. Перед новым действием наблюдается живой хвост; позднее управление, усечение, подмена и потерянный курсор закрывают его. Наблюдение после эффекта сообщается отдельно и не скрывает уже созданный результат. Атомарность между последним наблюдением и Git-эффектом не заявлена.

## Восстановление

Существующий R восстанавливается по прежним параметрам и квитанции до требования доступности живого источника. Новый merge, модельный снимок и коммит не создаются. Потерянная или неподтверждённая квитанция не разрешает повтор эффекта.

Команда `принять` возвращает также адрес автоматически сохранённого `поручение.txt`. При недоступном live тот же результат можно восстановить через `создать --поручение <этот-файл>` либо `принять --поручение <этот-файл> --исходник <прежний-адрес-native>`. Это не обход наблюдения для нового действия: исключение относится только к уже существующему результату.

## Проверяемые границы

Быстрые проверки охватывают отсутствие записи до готовности, точный повтор, прерванную публикацию, отказ `fsync` после переименования, подмены и повторный send. Холодная фикстура загружает CLI из C и проходит настоящий временный Git до R, включая источник внутри другого Git-предка, позднюю команду человека и восстановление при исчезнувшем live.

Монотонный профиль разделяет публикацию, установку J, повтор чтения, подготовку, готовность, первый R и восстановление. Это разные операции, поэтому отношение их времён не является ускорением одного действия. Реальная доставка Desktop и стоимость полного большого JSONL корня проверяются отдельно.
