# Журнал получателя после слияния

Внутренний установщик продолжает [слияние по сохранённому намерению](слияние-по-намерению.md).
Он создаёт назначенную пару запроса и отчёта в J, оставляя индекс равным S.
Проверены отдельные процессы и временные Git-репозитории. Допуск итогового
коммита, публичный вход и возобновление реального получателя ещё не подключены.

## Подготовка и восстановление

Используется канонический renderer `request_folder_layout.подготовить_собственную_пару`.
В запрос попадает подтверждённое нативное поручение; UUID Журнала остаётся
корневым, UUID ребёнка остаётся исполнителем. Общие индексы и соседний README
не изменяются. Папка J должна отсутствовать до первоначального намерения.

Приватное намерение закрепляет основание, точные UTF-8-байты, SHA, режим 0644
и два временных пути. Фазы — «устанавливается» и «установлено». Намерение
синхронизируется до создания пары. У каждого конечного файла есть только один
назначенный временный файл: продолжать можно его точный байтовый префикс,
в том числе оборванный внутри символа UTF-8. Чужие байты, символические
и жёсткие ссылки, иной владелец или режим дают отказ без удаления.

Временный файл синхронизируется перед атомарной заменой, каталог — после неё.
Повтор также закрепляет совпавший конечный файл, если предыдущая синхронизация
каталога прервалась. Неизвестные временные имена не присваиваются. Одновременное
наличие конечного и временного файлов закрывает продолжение.

После установки renderer больше не вызывается. Заполненные запрос и отчёт
сохраняются побайтово, включая время изменения. Потерянный конечный файл
автоматически не создаётся заново. До установки индекс должен быть точно S;
после неё разрешена только добавка из четырёх назначенных путей J:
пара, история модели и единственная назначенная запись проверки v4.
Чужие файлы, лишние каталоги, игнорирование этих путей и изменение полученных
из S байтов отклоняются.

## Проверка кода

До инфраструктуры замка и после первоначального renderer проверяется объединение
прежнего контура читающего приёма и явного контура установщика. В последний входят
13 модулей и два шаблона. Модули сохраняют собственный SHA при загрузке,
до проектных импортов; поздний снимок не заменяет этот отпечаток. Проверяются
происхождение из текущего checkout, неизменность после загрузки и точные blobs C.
Повтор установки проходит тот же допуск кода.

Это расширение явного контура. Проверка остальных транзитивных зависимостей
остаётся прежней; защита от произвольного исполняемого Python в доверенном
процессе не заявляется. Будущий закрытый вход должен проверять полный контур
также до первоначального merge. Произвольный JSON с хэшем не даёт полномочий.

## Проверки и стоимость

Адресный набор:

```text
python3 -B -m unittest discover -s Инструменты/fum-konvejyer-proizvodnyikh-vetok/tests -p 'test_*журнала_приёма.py'
```

В набор входят реальные аварийные завершения процесса, частичные префиксы,
неизменность чужих данных и холодные импорты из C. Проверены подмена шаблона
до входа и во время renderer, модуль другого checkout и восстановление файла
после его изменения и загрузки, включая восстановление до снимка установщика.
Реальное отключение питания и API Desktop этими тестами не проверяются.

`tests/профиль_журнала_приёма.py --выход <новый-файл.json>` измеряет три первых
установки и девять повторов на малых Git-фикстурах. Подготовка и merge выделены
отдельно; нативный допуск и сверка C заменены явно. Повтор уже исключает
renderer и повторную запись пары. Сравнение полной стоимости Desktop
и общее ускорение конвейера этим профилем не доказываются.
