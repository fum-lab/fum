# Проверенный переход координатора

Переход переносит одну активную привязку из отсутствующего размещения в текущий checkout и передаёт только закрытую цепочку конечных запусков. Он не запускает детей и не возобновляет исторические этапы.

Вход `fum.вход-перехода-координатора.1` закрепляет UUID корня, последний запуск и SHA его терминала, фактические координаторы с полными HEAD/ref, старое отсутствующее размещение без вымышленного HEAD, текущего получателя, полный первичный JSONL, проверяемое решение и кооперативное свидетельство прекращения старой цепочки. Свидетельство не доказывает отсутствие незаписанного вызова средствами ОС.

Приватный файл входа вне Git передаётся переменной `fum_vkhod_perekhoda`.

```bash
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/запустить-слои.py --корень-репозитория . --задача "$CODEX_THREAD_ID" переход-предпросмотр --вход "$fum_vkhod_perekhoda"
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/запустить-слои.py --корень-репозитория . --задача "$CODEX_THREAD_ID" перейти --вход "$fum_vkhod_perekhoda" --sha256 <SHA-предпросмотра>
```

Исполняемый код сначала коммитится. Под замком повторно проверяются источник команды, физические checkout, единственность ref, HEAD, общая Git-база, отсутствие старого размещения, происхождение нового C и точная история всех предков. Дрейф состояния меняет SHA предпросмотра и запрещает применение.

Одна транзакция сохраняет две связанные неизменяемые квитанции и явную версию состояния `fum.приём-направлений.2`. Первая квитанция перечисляет все диагностические этапы отсутствующего размещения с SHA. Вторая перечисляет все закрытые launch/terminal и попытки. Старые записи не переписываются и не отмечаются завершёнными. Активная регистрация прежнего координатора и его отдельные диагностические этапы сохраняются.

Ключи перехода не включают получателя и C: точный повтор возвращает прежний результат без записи; подмена назначения отказана. Общий API также не может изменить или удалить обе квитанции, вернуть версию `.1`, менять закрытые попытки или создавать старым координатором преемников любого переданного узла. Старые клиенты `.1` закрывают чтение отказом. Читать чужую открытую запись через механизм перехода нельзя: исторический читатель допускает только проверенного получателя и запечатанные записи.

Переход сохраняет логический граф зависимостей. Замена зависимости сообщения от событий на независимый слой требует отдельного решения и нового конвейера, не этого handoff.

Текущая версия рассчитана на одну передачу конкретной исходной привязки. Следующее физическое перемещение получателя требует отдельного расширения и проверки цепочки привязок; автоматического переопределения сохранённой квитанции нет.

Адресный контракт: [тесты перехода](tests/test_перехода_координатора.py). Профиль включает предпросмотр, применение и точный повтор на открытой Git-фикстуре; реальные процессы Desktop, сеть и большие нативные JSONL измеряются отдельно.
