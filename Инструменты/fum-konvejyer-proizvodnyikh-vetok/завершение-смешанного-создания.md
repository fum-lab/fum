# Закрытие двух созданных задач с сохранением первого писателя

Первый ребёнок H получил назначение и успел изменить свои файлы или создать
проверенный коммит. Второй ребёнок S действительно создан после наблюдения H,
но остановился до ref, ранней квитанции и первой записи. Вход
`fum.завершение-неудачного-запуска.7` закрывает именно это состояние запуска `.7`.
Результат сохраняется отдельным терминалом `fum.завершённый-неудачный-запуск.7`.

## Что подготовить

Вход содержит `схема`, `запуск`, `план_sha256`, `координатор`, `источник`,
`ожидания`, `слои`, `возобновления`, `свидетельство_координатора`.
В `слои` обязательны `события` и `сообщения`, с разными UUID и физическими
деревьями одной Git-базы. План и назначения читаются из первоначального C.
Текущий D координатора должен содержать C и исполняемый проверяющий код.

Для H выберите один из двух вариантов:

- `пакет`: собственный приватный [пакет незавершённого](сохранение-незавершённого.md)
  с раздельными рабочими байтами и индексом; поле `вид` во вход не добавляется.
  H остаётся на C и назначенном ref, результат получает
  `вид=остановлен-с-сохранением`.
- `вид=остановлен-с-коммитом`: один коммит с родителем C и успешная квитанция
  [дочерней передачи](передача-слоя.md). Вход ссылается на приватные `подготовка`
  и `квитанция`, каждая с `путь` и `sha256`. Проверяются фактический объект,
  модель, автор, исходное поручение, область файлов, история модели и чистота H.
  Раннее назначение читается координатором без смены его Native UUID.

Оба варианта H также содержат `попытка`, `задача`, `корень` и `источник`.
S содержит те же четыре поля и `вид=остановлен-до-записи`.
Наблюдение H уже сохранено; наблюдение S равно `null`. Регистрация H в реестре
не обязательна, но чужой UUID, корень или ref закрывает переход. Ref и писатель
S должны отсутствовать. Исторические sends и handoff в этом переходе не
поддержаны: `возобновления` равно `{}`.

## Как закрыть

Из корня своего worktree вызовите CLI с подготовленным приватным входом:

```sh
PYTHONPATH=Инструменты/fum-reyestr-planirovaniya/scripts:Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts \
  python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/запустить-слои.py \
  --корень-репозитория . --задача "$CODEX_THREAD_ID" завершение-предпросмотр --вход /путь/к/входу.json
PYTHONPATH=Инструменты/fum-reyestr-planirovaniya/scripts:Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts \
  python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/запустить-слои.py \
  --корень-репозитория . --задача "$CODEX_THREAD_ID" завершить --вход /путь/к/входу.json --sha256 SHA_ПРОСМОТРА
```

Первичный Native корня должен подтверждать единственные последовательные
create H → S, точные сохранённые ответы и последнее отдельное ожидание каждого
ребёнка после обоих созданий. Первичные детские источники связывают эти ожидания
с завершёнными ходами. Неучтённый человеческий ввод или транспортный вызов
требует отдельного разбора и не пропускается.

Под замком повторяются основания H/S, ранняя квитанция H, полное чтение источника
корня, refs, история запуска и владелец координатора. Добавляется только
терминал: байты детей, их индексы, коммиты, попытки и первоначальные наблюдения
сохраняются. H с коммитом возвращается с `интегрирован=false`; его последующий
приём и merge выполняются отдельно. Поздний допуск старого запуска запрещён.

Точный исторический повтор возвращает сохранённую квитанцию без повторной
живой сверки первичных JSONL, детей и refs и без изменения реестра. Сохранённый
реестр всё равно читается под замком. Повтор не подтверждает текущее состояние детей. Замок реестра
не блокирует Desktop и Git; необходима кооперативная аттестация координатора.
Поле `отсутствие_незаписанного_вызова_доказано` остаётся `false`.

## Проверка и профиль

Воспроизведение из корня чистого checkout:

```sh
PYTHONPATH=Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts:Инструменты/fum-konvejyer-proizvodnyikh-vetok/tests \
  python3 -B -m unittest -v -f test_закрытия_смешанного_создания
PYTHONPATH=Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts:Инструменты/fum-konvejyer-proizvodnyikh-vetok/tests \
  python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/tests/профиль_смешанного_создания.py \
    --выход /путь/к/новому-профилю.json
```

Профиль отдельно измеряет подготовку открытой фикстуры, три предпросмотра,
одну запись и семь исторических повторов для каждого варианта H. Повтор
проверяется с запретом вызова семи точек живой сверки JSONL, детей и refs. Desktop, сеть и большие живые
источники не входят в измерение. Подготовка использует реальные временные
Git-деревья; для варианта коммита вызывается штатная дочерняя автоматизация.
Проверка соответствия исполняемого checkout с C подменена только фикстурой.
Эти результаты не доказывают успешного перехода настоящей задачей Desktop.
