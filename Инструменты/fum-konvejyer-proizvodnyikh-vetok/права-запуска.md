# Первоначальные права до продолжения запуска

Версия `fum.запуск-двух-слоёв.7` сохраняет профиль Sol/Ultra и план `.2`, но
требует граф `события → сообщения`. Порядок двух элементов списка не задаёт
порядок исполнения. Два независимых слоя для этой версии отклоняются;
прежние версии запуска сохраняют свои условия.

## Проверка ребёнка

Первое точное поручение `.7` требует до создания ref, ранней квитанции и записи
проверить собственное назначение и первоначальную Native policy:

```text
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/scripts/запустить-слои.py --корень-репозитория . --задача <свой-UUID> проверить-права --источник <свой-первичный-JSONL>
```

Читатель проверяет UUID из среды, исходный C, чистый detached checkout,
полный манифест и точный текст поручения. Он читает ограниченный префикс до
первого `turn_context`, повторяет чтения и отклоняет смешение разных префиксов.
Максимальная граница читателя — 16 МиБ. Вывод с локальными сведениями
сохраняется приватно; он содержит `разрешение_записи=false`.

Поддержаны только следующие точные значения:

```json
{
  "approval_policy": "never",
  "approvals_reviewer": "user",
  "sandbox_policy": {"type": "danger-full-access"},
  "permission_profile": {"type": "disabled"},
  "active_permission_profile": {"id": ":danger-full-access"}
}
```

Поле `file_system_sandbox_policy` должно отсутствовать. Пропуск, `null`, иной тип,
неизвестная или противоречивая форма закрывают проверку. Остальные транспортные
поля контекста не заменяют эти значения.

Это наблюдение первоначальной конфигурации. Оно не переключает настройки
Desktop и не доказывает успешную запись Git. Слова ребёнка «Full Access» не
заменяют исходные поля. При отказе ребёнок сохраняет чистый detached C и
останавливается до ref и раннего подтверждения.

## Барьер координатора

Допуск первого слоя сохраняет одну попытку. Перед вторым используется команда
`допустить --вход <JSON> --слой сообщения --источник-первого-ребёнка <JSONL>`
с общим префиксом CLI из [контракта запуска](запуск-двух-слоёв.md).

Под замком должны совпасть настоящая первая попытка, сохранённый ответ,
наблюдение `.2`, Native UUID, назначение и неизменный префикс прав. Асинхронный
`clientThreadId` допустим только вместе с независимо наблюдённым настоящим UUID.
Противоречивый или ошибочный ответ не принимается. Без этих свидетельств вторая
попытка не записывается. Точный повтор уже выданного допуска возвращает прежнюю
попытку с `разрешён_вызов=false`.

Собственный читатель назначения понимает оба точных Sol-поручения `.6/.7`.
Это не разрешение произвольной вставки в prompt: весь текст сверяется с C.

## Проверка и граница этапа

Тесты: `tests/test_барьера_второго_запуска.py` и
`tests/test_закрытия_одного_до_записи.py`. Профиль:
`tests/профиль_барьера_запуска.py --выход <новый-JSON>`.
Построение Git-фикстуры измеряется отдельно; небольшая фикстура не доказывает
скорость на полном реестре или многогигабайтном JSONL.

Если первый ребёнок отказал до записи, применяется
[одиночное закрытие `.6`](завершение-одного-до-записи.md). Если первый уже
наблюдён, а второй реально создан и отказал до записи, нужен отдельный
смешанный терминал. Этот случай пока не покрыт; до его реализации новый
полный пилот не объявляется подготовленным.
