# Отдельные ожидания обратного приёма

Чистый [селектор](scripts/ожидания_обратного_приёма.py) проверяет наблюдённый порядок `send H → wait H → send S → wait S`. Он нужен для закрытия двух уже завершившихся адресных отказов. Прежний [контракт раздельных ожиданий](scripts/раздельные_ожидания.py), требующий оба воздействия до каждого ожидания, сохраняется.

Входом служит результат `нативные_вызовы.прочитать(..., интервалы=True)` с полным префиксом корневого источника, точные номера двух sends по UUID детей и номера последних одиночных waits по тем же UUID. Для каждого события проверяются границы первичных байтов и интервалы runtime. Вторая отправка допускается только после завершения первого ожидания; первоначальные создания завершаются до первого send.

Дополнительный send этим детям, handoff, подмена номера или адреса, позднее ожидание, общий wait, перекрытие и неполный префикс закрывают допуск. Читатель отбирает воздействия по назначенным UUID: отсутствие вызовов другим задачам или по ненаблюдаемым транспортам этим результатом не доказывается.

Выбор ожиданий ещё не закрывает поколение. Последующий терминал должен связать исходные остановленные префиксы, точное получение поручений, конечные ходы детей, сохранённые намерения и квитанции доставки, отказ CLI и фактическое состояние Git. Первичные returncode/stdout/stderr старого слияния отсутствуют в квитанции доставки `.2`; они остаются unknown. Этот селектор не повторяет Git-эффект, не редактирует старые квитанции и не запускает преемника.

[Адресные сценарии](tests/test_ожиданий_обратного_приёма.py) проверяют запрет подмен и сохранность прежнего контракта. Профиль воспроизводится через отчётную обёртку:

```sh
python3 -B Инструменты/fum-konvejyer-proizvodnyikh-vetok/tests/профиль_ожиданий_обратного_приёма.py \
  --выход /внешний/новый-профиль.json
```

Измеряется только чистый выбор на малой открытой фикстуре. Подготовка, разбор JSONL, Git, замки, расход контекста и весь цикл интеграции исключены; результат не доказывает ускорения полного конвейера.
