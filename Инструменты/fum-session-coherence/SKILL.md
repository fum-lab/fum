# FUM Session Coherence

Этот навык описывает локальную [автоматизацию FUM](../../Глоссарий/автоматизация-FUM.md), которая проверяет, что [рабочая сессия](../../Глоссарий/рабочая-сессия.md) связана с [памятью FUM](../../Глоссарий/память-FUM.md) как воспроизводимая цепочка:

исходный запрос -> затронутые файлы -> журнал -> проверки -> коммит.

## Когда использовать

Используй эту автоматизацию перед коммитом рабочей сессии, влияющей на проект, после запуска `fum-md-recency` и после того как файл запроса уже содержит разделы `## Использованные инструменты`, `## Повлиял на файлы` и `## Проверки`.

Автоматизация особенно полезна, когда сессия меняет несколько областей памяти: `Документация/`, `Глоссарий/`, `Инструменты/`, `Планирование/`, `Запросы/` и `Журнал/`.

## Команда запуска

```bash
python3 Инструменты/fum-session-coherence/scripts/check-session-coherence.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>.md
```

По умолчанию проверка читает `git status --short --untracked-files=all` через `git -c core.quotepath=false`, чтобы пути на кириллице сравнивались с разделом `## Повлиял на файлы`, а новые каталоги раскрывались до конкретных файлов.

Для изолированной проверки файлов и ссылок без Git-состояния можно использовать:

```bash
python3 Инструменты/fum-session-coherence/scripts/check-session-coherence.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>.md \
  --skip-git-status
```

## Что проверяется

- Имя и заголовок файла запроса соответствуют формату `YYYY-MM-DD_HH-MM-SS_MSK`.
- Раздел `## Навигация по запросам` текущего запроса указывает на правильные предыдущий и следующий запросы, а соседний запрос ссылается обратно.
- Для запроса существует файл `Журнал/<YYYY-MM-DD_HH-MM-SS_MSK>.md` с ссылкой на исходный запрос.
- Раздел `## Использованные инструменты` присутствует, содержит список и ссылку на [реестр системных приложений и инструментов](../реестр-системных-приложений-и-инструментов.md).
- Раздел `## Повлиял на файлы` содержит локальные Markdown-ссылки на затронутые файлы, включая текущий запрос и журнал.
- Относительные Markdown-ссылки в затронутых Markdown-файлах указывают на существующие локальные цели; внешние ссылки не проверяются.
- Затронутые Markdown-файлы вне `Запросы/` не содержат похожий на пользовательский мета-запрос о правилах [памяти FUM](../../Глоссарий/память-FUM.md), порядке [рабочей сессии](../../Глоссарий/рабочая-сессия.md), `AGENTS.md` или `Запросы/` без ссылки на конкретный файл исходного запроса.
- Автоматизация `fum-md-recency` подтверждает свежесть служебных recency-меток и индекса `Индексы/markdown-файлы-по-времени-редактирования.md`, если этот локальный инструмент есть в репозитории.
- Все пути из текущего `git status --short` перечислены в разделе `## Повлиял на файлы`; лишние временные файлы, кэши и отладочные артефакты вызывают ошибку.

## Проверки автоматизации

Локальные тесты запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-session-coherence/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: успешная сессия проходит при перечисленных изменённых файлах, а отсутствие журнала, битая Markdown-ссылка, возможный незаведённый мета-запрос без ссылки на `Запросы/`, устаревшая recency-проверка и неожиданный путь в Git-состоянии дают ошибку.

## Граница автоматизации

Скрипт проверяет структурную связность рабочей сессии, но не подменяет смысловую проверку документации. Агент по-прежнему отвечает за корректность требований, публикационную чистоту содержания, полноту списка инструментов, уместность затронутых файлов и качество коммита.

Проверка мета-запросов является эвристикой. Она ищет формулировки о вопросе, уточнении, ответе или проверке пользователя в контексте правил памяти, порядка рабочей сессии, `AGENTS.md` или `Запросы/`; это ранний сигнал, а не доказательство, что запрос действительно пропущен.

Проверка Git-состояния сравнивает только пути. Она не решает, нужно ли включать конкретное содержимое в коммит; перед staging агент всё равно должен просмотреть diff и исключить секреты, локальное состояние и машинный мусор.
