# Проверяемый переход ветки

Этот первый срез предоставляет команды `план`, `переименовать`, `сверить`. Он нужен для перехода существующего владельца в именованную ветку своего направления. Полная задача перехода остаётся открытой после локального переименования.

## Граница полномочий

План не разрешает эффект. До выполнения владелец получает отдельное адресное назначение координатора и сверяет физический checkout, UUID среды, старый и новый полный ref, S, независимо выбранный ROOT L и единственного писателя. Чужой checkout доступен только для чтения. Читающая проекция другого владельца не поддержана.

Живой переход текущим checkpoint ещё не допущен. ROOT и владелец отдельно сверяют смысловой exact plan с поручением/ACT и Журналом: effect использует выбранный SHA и сам не выводит адрес назначения из независимого ROOT selector. Сохранённая передача без исхода пока не доказывает завершение старого Git-процесса, а постусловие refs/HEAD не доказывает сохранность config/index. До реального эффекта требуется адресная доработка terminal/lifetime witness либо доказанного безопасного постусловия с config/index. Это известный блокер, а не утверждение о фактической порче.

План связывает наблюдённые GitHub ID и `full_name`, единственный адрес origin, физический common Git и его device/inode, UUID владельца и чата, первую нативную `session_meta`, точные S/L, ресурсы и SHA-256. Число хостинга поступает из независимо проверенного наблюдения; Git сам не подтверждает GitHub ID. Программа проверяет фактические origin, refs, занятость и commit-объекты. Она не подменяет независимую проверку происхождения задания.

Перед эффектом ресурсы и границы проверяются повторно. Новая ветка не должна существовать, пересекаться по D/F, NFC или свёртке регистра либо быть symbolic HEAD другого worktree, включая unborn. Допустим только чистый checkout. Одноимённый межпроцессный замок находится в административном каталоге собственного checkout. Сторонние писатели должны соблюдать то же исключение; это кооперативный протокол, а не защита от владельца машины.

## Входы и результаты

JSON-контракты определены в [исходниках документов](Sources/perekhod-vetok/Документы.swift). Задание `fum.задание-перехода-ветки.1` содержит реальную идентичность репозитория, UUID операции/владельца/чата, нативный источник, физический checkout, старый ref, S, исходные названия направления, ресурсы Git/преобразователя/кода и отдельные приватные каталоги протокола и RAW. Задание хранится в файле 0600 с родителем 0700.

Независимый документ `fum.выбор-корня-перехода.1` содержит UUID координатора, полный ROOT ref, L и ресурс основания. Его путь и SHA выбирает координатор отдельно от плана. ROOT ref задаёт конечный компонент имени; фиксированного `fuma/master` в программе нет.

Преобразователь — собранный канонический `preobrazovatj-nazvaniya` из [проверки названий](../fum-proverka-nazvanij-avtomatizacij/Package.swift) с объявленным LinguisticKit. Вход процесса — JSON-массив русских названий, выход — JSON-массив результатов братиславского алгоритма. Программа затем проверяет ASCII lowercase, дефисы и разделители. Непредставимый ввод отклоняется; ручной таблицы и подбора моделью нет.

```text
переход-веток план --задание <0600.json> --выбор-корня <root.json> --хэш-выбора <SHA256> --выход <новый-план.json>
переход-веток сверить --план <план.json> --хэш-плана <SHA256> --выбор-корня <root.json> --хэш-выбора <SHA256>
переход-веток переименовать --план <план.json> --хэш-плана <SHA256> --выбор-корня <root.json> --хэш-выбора <SHA256>
```

CLI выдаёт машинный JSON в stdout, отказ — в stderr с кодом 2. План сохраняется exclusive; повторная подготовка поверх существующего файла или каталога операции запрещена. При продолжении используется тот же сохранённый план и его точный SHA. Протокол и RAW находятся вне любого Git-предка, имеют собственные каталоги 0700 и файлы 0600; в публичный Git они не копируются.

`сверить` не создаёт протокол или Git-замок и не меняет refs, индекс либо checkout. Команды наблюдения сохраняют новые приватные RAW. Результат различает состояния до эффекта, непереданное намерение, неизвестный исход, наблюдённое переименование и подтверждённый исход. Наблюдение после потери ответа само не создаёт квитанцию: команда `переименовать` при доказанном точном постусловии сохраняет reconcile без повторного `branch -m`.

Намерение синхронизируется до передачи команды, а передача — до её запуска. Передача без исхода и без точного постусловия запрещает повтор. Повреждённый протокол, прежний отказ и дрейф подтверждённого результата сохраняются как отказ. Старый remote ref всегда сохраняется; текущий срез вообще не публикует новый ref и не меняет upstream.

## Сборка, проверки и профиль

Требуются macOS 14+, Swift 6 и Git. В Package.swift для всех собственных targets и тестов постоянно заданы Swift 6, `-warnings-as-errors` и `-strict-concurrency=complete`; проверка конкурентности не ослабляется. Сначала проверить объявленную зависимость и собрать канонический преобразователь. Все адресные build/test/profile в рабочей сессии запускаются через [отчётную обёртку](../fum-otchyotyi-o-zapuskakh-proverok/SKILL.md) своей пары Журнала. Следующие argv задают дочерние команды обёртки; путь сборки выбирается приватным и вне Git.

```text
swift build --package-path Инструменты/fum-proverka-nazvanij-avtomatizacij --scratch-path <converter-build> -j 2
swift build --package-path Инструменты/fum-perekhod-vetok --scratch-path <build> -j 2
```

Перед SwiftTesting задать `ФУМ_ИСПОЛНИТЕЛЬ_ФИКСТУРЫ=<build>/debug/исполнитель-фикстуры`. Воспроизводимый функциональный запуск:

```text
swift test --package-path Инструменты/fum-perekhod-vetok --scratch-path <build> -j 2
```

Тесты используют настоящие локальные refs и одноразовый bare origin. Каждая фикстура создаёт собственный синтетический UUID и передаёт его только своему дочернему процессу через `Process.environment`; окружение родителя не изменяется. Наличие `CODEX_THREAD_ID` в родительской среде не требуется. Подготовка протокола, сверка и отрицательные actor-сценарии проходят через тот же отдельный исполнитель. Отдельная регрессия запускает настоящий основной CLI без `CODEX_THREAD_ID` в его дочерней среде и проверяет отказ владельца до создания intent, протокола или замка. Это не разрешение подменять UUID настоящей операции.

Фикстурный преобразователь возвращает фиксированный массив: он проверяет протокол адаптера и не доказывает лингвистическое преобразование. Отдельный процесс `исполнитель-фикстуры` останавливает только себя в заданном окне; родитель посылает SIGKILL только этому PID и запускает новый процесс с тем же планом. Предметный отказ actor с кодом 2 и своей схемой ошибки отличается от ошибок argv/загрузки входа с кодом 3 и отдельной транспортной схемой, а также от аварии процесса. Это тестовый исполнитель; для настоящего checkout применяется основной CLI с настоящим UUID среды.

Для профиля задать `ФУМ_ПРОФИЛЬ_ПЕРЕХОДА=1` и выбрать только профиль:

```text
swift test --package-path Инструменты/fum-perekhod-vetok --scratch-path <build> -j 2 --filter профильПланаПереименованияИПовтора
```

Профиль сохраняет три последовательных наблюдения плана, локального rename и точного повтора. Подготовка Git-фикстуры исключена из этих интервалов; текущая обвязка включает запуск отдельного фикстурного процесса в интервалы rename и повтора. Ранний профиль первого среза измерял прежнюю внутрипроцессную обвязку и не является измерением новой. Сборка, wrapper wall, длительности SwiftTesting и интервалы операций различаются. Профиль не измеряет TDLib, сеть GitHub, merge/Creator или статистическое ускорение; сравнительной оптимизации в нём нет. Повторные проверки ресурсов и состояния сохраняются до независимого сопоставимого измерения.

## Остаток направления

Следующий срез должен явно подготовить `merge --no-ff --no-commit L`, сохранить конфликт для владельца, затем проверить штатные проверки, независимое модельное ревью и Creator перед одним коммитом с родителями `[S,L]`. Когда L уже предок S, результатом является доказанное отсутствие новых изменений, которое не называется слиянием. После принятого коммита отдельно нужны точный non-force push нового ref, readback и upstream; старый remote сохраняется.

Имя чата — отдельный внешний эффект координатора с подтверждением. Git и Codex не атомарны. Автоматизация основного ref будущего форка, массовая миграция каталогов и проекция primary отложены; primary остаётся на `master`. Исторические UUID, A/ACT, RAW и квитанции не перепривязываются. Поставка исходников и локальный commit не означают ROOT-приёмки или интеграции.
