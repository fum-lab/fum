# FUM Smoke Check

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) собирает основной проверочный контур репозитория в одну команду. Она нужна перед коммитами и публикационными сессиями, когда важно быстро подтвердить, что локальные автоматизации проходят тесты, проверяемые реестры пересобираются, Markdown-recency свежа, а выбранная [рабочая сессия](../../Глоссарий/рабочая-сессия.md) связана с запросом, журналом и Git-состоянием.

По умолчанию smoke-check работает локально: он не требует секретов, сетевых запросов и внешних сервисов. Все шаги запускаются через явные команды Python и уже существующие локальные автоматизации.

## Когда использовать

Используй эту автоматизацию, когда нужно:

- выполнить единый регрессионный прогон перед коммитом рабочей сессии;
- проверить, что новые или изменённые локальные автоматизации покрыты тестами;
- пересобрать и сверить проверяемые реестры репозитория;
- убедиться, что `FUM-MD-RECENCY` и индекс Markdown-файлов свежие;
- проверить связность выбранного файла `Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md`.

## Команда запуска

Полный smoke-check для рабочей сессии:

```bash
python3 Инструменты/fum-smoke-check/scripts/run-smoke-check.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md \
  --commit-message-file <путь-к-файлу-сообщения> \
  --codex-thread-id <корневой-CODEX_THREAD_ID>
```

Для запросов начиная с `2026-07-14_02-31-47_MSK_добавлять-идентификатор-сеанса-Codex.md` оба новых параметра обязательны; исторические запросы можно проверять без них. Список команд без выполнения:

```bash
python3 Инструменты/fum-smoke-check/scripts/run-smoke-check.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md \
  --list
```

Частичный локальный запуск без проверки конкретной рабочей сессии:

```bash
python3 Инструменты/fum-smoke-check/scripts/run-smoke-check.py \
  --skip-session-coherence
```

## Что запускается

Автоматизация выполняет шаги в устойчивом порядке:

1. Находит все каталоги `Инструменты/*/tests`, содержащие `test_*.py`, и запускает для каждого:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s <tests-dir> -p 'test_*.py'
```

2. Пересобирает машинно читаемый плановый реестр:

```bash
python3 Инструменты/fum-planning-registry/scripts/build-planning-registry.py build \
  --output Планирование/реестр-требований-вариантов-и-кандидатов.json
```

3. Проверяет свежесть планового реестра:

```bash
python3 Инструменты/fum-planning-registry/scripts/build-planning-registry.py validate \
  --registry Планирование/реестр-требований-вариантов-и-кандидатов.json
```

4. Проверяет обязательные точки входа всех устойчивых прототипов:

```bash
python3 Инструменты/fum-prototype-launch/scripts/check-prototype-launchers.py
```

5. Проверяет recency-метки без записи:

```bash
python3 Инструменты/fum-md-recency/scripts/update-md-recency.py --check
```

6. Проверяет связность выбранной рабочей сессии:

```bash
python3 Инструменты/fum-session-coherence/scripts/check-session-coherence.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md \
  --commit-message-file <путь-к-файлу-сообщения> \
  --codex-thread-id <корневой-CODEX_THREAD_ID>
```

## Проверки автоматизации

Локальные тесты самой автоматизации запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-smoke-check/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: smoke-check обнаруживает тесты локальных автоматизаций, добавляет сборку и проверку планового реестра, проверяет точки входа прототипов, запускает recency-проверку, требует `--request` для проверки связности рабочей сессии, для новых запросов требует файл сообщения и корневой Codex-Thread-ID, передаёт их в `fum-session-coherence`, сохраняет совместимость с историческими запросами и допускает частичный запуск с `--skip-session-coherence`.

## Граница автоматизации

Smoke-check не заменяет смысловую проверку изменений, публикационную чистоту diff и решение агента о том, какие файлы нужно коммитить. Он объединяет локальные структурные проверки и останавливается на первом упавшем шаге, чтобы ошибка оставалась наблюдаемой и не маскировалась следующими командами.

Если в репозитории появляется новый проверяемый реестр, его нужно добавить в `run-smoke-check.py` и закрепить ожидание тестом. Если у новой локальной автоматизации появляются тесты в `Инструменты/<имя>/tests`, smoke-check начнёт запускать их автоматически.
