# Внимание к полученным обсуждениям GitHub

[Автономный слой](scripts/внимание_к_обсуждениям_GitHub.py) читает уже сохранённый [архив](../../Issues/README.md) и ведёт отдельный учёт разбора. Получение Issue или комментария само по себе не подтверждает разбор, ревью, принятие, назначение либо выполнение. Основание разработки — [ограниченный этап FUM-STEP-0237](../../Планирование/карточки-шагов/🟡-FUM-STEP-0237-автоматизировать-приём-GitHub-Issues.md) и [Журнал реализации](../../Журнал/2026-10-14_12-38-15_MSK_учитывать-разбор-обсуждений-GitHub/запрос.md).

## Вход и состояние

Архив задаётся физическим абсолютным корнем. Он читается локально: страницы, их длины и SHA256, метаданные наблюдений, порядок и идентичность объектов перепроверяются. Слой проходит наблюдения последовательно, поэтому возврат А → Б → А восстанавливает актуальную А, сохраняя неразобранную промежуточную Б. В состоянии остаётся перечень точных отпечатков всех подтверждённых наблюдений. Потеря или дрейф любого из них переводит сбор в неизвестность и сохраняет прежний остаток.

Идентичность обращения включает репозиторий, номер, постоянный `id` и тип Issue/PR; идентичность комментария — постоянный `id` и родителя. Коллизии не склеиваются. Версия обращения связывает хэш полного объекта и хэши всех известных комментариев. Хэш объекта вычисляется по JSON с сортировкой ключей, отступом 2, UTF-8 и конечным LF; хэш страницы относится к исходным байтам ответа. `updated_at` сохраняется отдельно и не заменяет хэш: редакция при прежнем времени всё равно создаёт новую версию.

Контекст разбора — явно переданный непустой JSON-объект, например цель, полномочия и критерий. Его точный хэш участвует в применимости ревью. Изменение контекста возвращает внимание даже при неизменных исходных объектах.

Состояние схемы `fum.внимание-к-обсуждениям.1` хранится в собственной физической папке вне любого Git checkout. Обёртка `fum.сохранение-внимания.1` содержит хэш состояния. Запись использует блокировку сотрудничающих процессов, проверку SHA прочитанного файла, временный файл, `fsync` и атомарную замену. Устаревший писатель получает отказ. Точный повтор сохраняет байты, inode и время изменения. Повреждённый файл или неизвестный остаток установки не сбрасываются в пустую очередь. Это модель сотрудничающих писателей, а не защита от владельца машины, способного подменить файлы и блокировки.

## Явные операции

Из физического корня чистого клона FUM с Python 3.14 команды выполняются так; обозначения путей заменяются собственными физическими адресами:

~~~text
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/внимание_к_обсуждениям_GitHub.py --состояние <частная-папка-вне-Git> --корень-архива <корень-клона> --контекст <файл-контекста.json> сверить
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/внимание_к_обсуждениям_GitHub.py --состояние <частная-папка-вне-Git> прочитать
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/внимание_к_обсуждениям_GitHub.py --состояние <частная-папка-вне-Git> --вход <решение.json> ревью
~~~

`сверить` получает локальный архив, обновляет состояние и возвращает состояние, остаток и структурный план разбора. `прочитать` восстанавливает их из сохранённого состояния без архива, сети и записи. Для другого репозитория обязателен одинаковый `--репозиторий владелец/имя` во всех операциях. `--сейчас` позволяет явно выбрать время сверки с часовой зоной; наблюдение из будущего относительно него считается неизвестным входом.

Ревью записывается только явным решением оператора для текущих версии и контекста. Поля входного JSON:

~~~json
{
  "номер": "7",
  "версия": "<точный ключ_версии из состояния>",
  "контекст_sha256": "<точный хэш контекста из состояния>",
  "решение": "отложено",
  "основания": ["Содержательное основание оператора"],
  "время": "2030-01-01T00:00:00+00:00"
}
~~~

Допустимые решения: `рекомендовано`, `отложено`, `отклонено`. Запись сохраняет полный вход, контекст, основания, время и хэш квитанции. Она подтверждает запись решения оператора; адекватность смыслового разбора, принятие и выполнение проверяются отдельно. Неизвестный сбор и устаревший вход отказывают. Повтор ревью неизменной версии по умолчанию отказывает, сохраняя прежнее ревью; явный полный повтор требует поля `полный_повтор_основание` с содержательным основанием.

Неизменная версия в прежнем контексте переиспользует связанное ревью. Для изменённой версии план показывает изменённые поля обращения, новые и изменённые комментарии. Смена контекста требует полного рассмотрения. План является списком входов для будущей работы; он не вызывает модель и не выполняет смысловой разбор.

## Остаток и снятие исторического внимания

Остаток содержит текущие номера без применимого ревью, все неразобранные версии в их контекстах и активные сигналы. Историческая неразобранная версия сохраняется после появления более поздней, даже если новая версия уже разобрана. Сигналы имеют устойчивый ключ причины и привязки; перезапуск и неизменный повтор не создают дублей.

Отсутствие архива, повреждение, коллизия или потеря наблюдения сохраняют неизвестность. Неполный обход сохраняет сигнал неполноты. Отсутствующий в полном обходе ранее известный объект сохраняется: отсутствие не доказывает удаление. Даты последнего сбора, последнего полного сбора, изменения объекта и записанного ревью различаются. Периодичность не выбирается автоматически; только явный положительный `--период-секунд` добавляет сигнал просроченного полного наблюдения.

Оператор может отдельно снять внимание с исторической версии, явно выбрав её точный ключ остатка и более позднюю текущую замену. Операция `снять-историческое-внимание` принимает через `--вход` JSON с полями `ключ`, `замещающая_версия`, `автор`, `основание`, `время`. Первый эффект требует известного полного наблюдения. Квитанция сохраняет точное замещающее наблюдение; исходник, версия и прежние ревью остаются. Это решение не помечает версию разобранной. Повтор того же входа возвращает прежнюю квитанцию без эффекта после нового наблюдения; изменение параметров отказывает. Если снятая версия снова становится текущей, внимание возвращается. Общие принятие, назначение и выполнение этой версией слоя не выполняются.

Коды CLI: `0` — операция с известным сбором; `3` — сохранена или прочитана неизвестность; `2` — отказ входа либо операции. Код `0` не означает пустого остатка, полной приёмки или выполнения Issues. Неполный известный обход может вернуть `0` с активным сигналом неполноты.

## Проверка и профиль

~~~text
python3.14 -B -m unittest discover -s Инструменты/fum-materialyi-zaprosov/tests -p test_внимания_к_обсуждениям_GitHub.py
python3.14 -B Инструменты/fum-materialyi-zaprosov/tests/профиль_внимания_к_обсуждениям_GitHub.py --серия --число-обращений 64 --повторы 3 --каталог-RAW <новый-физический-каталог-вне-Git> --выход <новая-серия.json>
~~~

[Тесты](tests/test_внимания_к_обсуждениям_GitHub.py) проверяют версии, контекст, остаток, неизвестность, историю, повреждение состояния, конкурентный устаревший снимок и повтор. Отдельный свежий процесс читает локальный клон после удаления исходного архива; сеть и запуск внешних процессов в этом чтении заблокированы, а неизменность сохранённых байтов и метаданных проверена.

[Профиль](tests/профиль_внимания_к_обсуждениям_GitHub.py) сравнивает полный проход и дельту на одинаковом синтетическом входе: неизменность — 0 против 64 вызовов ядра; одна редакция — 1 против 64; смена контекста — 64 против 64. Совпадение SHA всего результата включает переиспользованные элементы. Время сверки и планирования отделено от времени статического ядра обработки текста. Подготовка и проверки источников исключены; пик памяти означает дополнительные отслеживаемые выделения после создания кэша.

Явная `--серия` закрепляет SHA256 сырых байтов и точные режимы трёх файлов: helper, модуль внимания и архиватор. Снимок создаётся до запуска трёх новых интерпретаторов. Каждый ребёнок проверяет его до импорта helper и исполняет helper из удержанных байтов. Проектные импорты внимания и архиватора, включая повторные импорты из модуля внимания, также используют проверенные удержанные байты; `.pyc` не читается. Ребёнок повторяет сверки перед измерениями и после всех пар; родитель — перед и после каждого процесса и после всей серии. Режим файла входит в сравнение даже при неизменных байтах.

Серия принимается только при трёх разных наблюдённых PID, совпадении PID с выдачей ребёнка, трёх полных успешных исходах, одинаковых параметрах и входных SHA. Каждый процесс сохраняет полные stdout/stderr, буквальные аргументы и исход в отдельной приватной папке. Результат серии связывает их SHA и размеры; полный RAW дополнительно сверяется после всей серии. При дрейфе источника, режима или RAW итоговая серия не выдаётся, а уже полученные RAW сохраняются. Каталог RAW должен быть новым, физическим и находиться вне любого Git-предка; результат также не перезаписывается.

Без `--серия` остаётся одиночный API/CLI-профиль `.2`: он проверяет источники предметных импортов и измерений, но не доказывает, из каких байтов ранее был импортирован сам helper. Одиночный CLI и API без явного аргумента возвращают `хэш_исполненного_профиля: null`. Явный аргумент API сверяется с закреплённым SHA и сохраняется как вход; сам по себе он не доказывает исполнение helper. В серии этот SHA вычисляет ребёнок из удержанных исполняемых байтов, а родитель связывает его с буквальным вызовом, наблюдённым PID и полным RAW. Исторические профили `.1` сохраняют свою прежнюю неполную границу; новый контракт не приписывается им задним числом. [Исходный этап](../../Журнал/2026-10-14_12-38-15_MSK_учитывать-разбор-обсуждений-GitHub/отчёт.md) и [отдельное исправление профиля](../../Журнал/2026-10-14_18-05-44_MSK_закрепить-исходники-профилей-обсуждений-GitHub/отчёт.md) сохраняются раздельно. Сверки подтверждают наблюдённые границы в сотрудничающей среде, а не непрерывную неизменность между ними.

Измерение подтверждает сокращение повторных вызовов синтетического ядра. Скорость смыслового ревью, расход токенов, стоимость модели и весь рабочий цикл им не измерены. По этим данным дальнейшая оптимизация сверки не обоснована: она продолжает проверять архив полностью, а ограниченный кэш одинаковых страниц действует только внутри одного чтения.

## Покрыть точные версии отдельных объектов

[Дополнительный CLI](scripts/разбор_версий_обсуждений.py) связывает решение оператора с каждой версией Issue/PR и комментария. Прежние архив, API и схемы `.1` сохраняются. Применимый агрегат сам по себе не подтверждает пообъектного покрытия. Новый CLI возвращает составное `внимание`: старые сигналы, неполнота, непокрытые объекты и несогласованные пакеты. Проверять его нужно через новый `план` или `прочитать`; прежнее чтение состояния этой гарантии не даёт.

Ключ покрытия связывает репозиторий, полную идентичность родителя, тип и постоянный ID объекта, канонический SHA версии, точный контекст и выбранные основания разбора. Сырые SHA страницы и наблюдения сохраняют происхождение отдельно. Поэтому другая сериализация той же страницы или новый комментарий не требуют повторного решения о неизменном объекте. Редакция при прежнем `updated_at` требует нового решения. Смена адресного основания затрагивает соответствующий объект, смена общего основания или контекста — весь состав. Полный план можно явно запросить без подмены контекста.

Архив и каталоги задаются физическими абсолютными путями. Внимание и покрытие хранятся в разных собственных каталогах вне любого Git-предка; символические и жёсткие ссылки в покрытии запрещены. Файл входа также остаётся приватным, вне Git. Команды:

~~~text
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/разбор_версий_обсуждений.py план --архив <корень-архива> --репозиторий fum-lab/fum --состояние <частное-внимание> --покрытия <частное-покрытие> --вход <план.json>
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/разбор_версий_обсуждений.py решение --архив <корень-архива> --репозиторий fum-lab/fum --состояние <частное-внимание> --покрытия <частное-покрытие> --вход <решение.json>
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/разбор_версий_обсуждений.py прочитать --архив <корень-архива> --репозиторий fum-lab/fum --состояние <частное-внимание> --покрытия <частное-покрытие> --вход <план.json>
~~~

Вход плана и чтения содержит ровно четыре поля:

~~~json
{
  "номер": "7",
  "контекст": {"цель": "Проверить обсуждение", "полномочия": "Выбор оператора"},
  "основания_разбора": {"общие": {"критерий": "Версия 1"}, "объекты": {}},
  "сейчас": "2030-01-01T00:00:00+00:00"
}
~~~

`объекты` может содержать отдельное непустое основание по метке `комментарий:90`, `Issue:70` или `PR:70`. `план` возвращает непокрытые `единицы`, `переиспользованы`, сохранённые `решения`, `несогласованные`, прежний остаток и `выбор_sha256`. Только `план` принимает `--полный`: он показывает весь состав при тех же ключах и контексте. Флаг не создаёт решений.

Оператор явно выбирает конечные ключи и суммарную оценку; смешанные пообъектные решения автоматически не сворачиваются:

~~~json
{
  "схема": "fum.решение-разбора-обсуждения.1",
  "номер": "7",
  "план_sha256": "<выбор_sha256 из точного плана>",
  "контекст": {"цель": "Проверить обсуждение", "полномочия": "Выбор оператора"},
  "основания_разбора": {"общие": {"критерий": "Версия 1"}, "объекты": {}},
  "время": "2030-01-01T00:00:00+00:00",
  "происхождение": {"оператор": "Имя или роль", "источник": "Адресное основание"},
  "решения": [{"ключ": "<ключ выбранной единицы>", "решение": "отложено",
    "основания": ["Содержательное решение"], "свидетельства": ["Проверяемое свидетельство"]}],
  "суммарное": null
}
~~~

`суммарное: null` сохраняет частичный пакет, оставляя внимание. Для полного покрытия оператор задаёт `суммарное` как `{"решение":"отложено","основания":["Явная общая оценка"],"полный_повтор_основание":null}`. До полного пообъектного покрытия суммарная запись отказывает. После нескольких частичных пакетов допустим пустой массив новых `решения` и явное суммарное решение. Для повторного агрегатного ревью неизменной версии требуется содержательное `полный_повтор_основание`. Уже существующий агрегат можно выбрать точно через `{"переиспользовать_sha256":"<SHA существующего применимого ревью>"}`: добавляется покрытие, прежнее внимание не переписывается.

Неизменяемый пакет `fum.покрытие-разбора-обсуждения.1` сохраняется до CAS прежнего внимания. Он содержит исходный ввод оператора, весь состав, собственные решения, SHA всех использованных решений, точную агрегатную квитанцию и первоначально выбранный SHA внимания. После аварии до CAS точный повтор в свежем процессе завершает только недостающую запись с прежними временем и основаниями. После аварии за CAS повтор не добавляет второе ревью. Если исходный SHA изменился конкурентно, он не выбирается заново: пакет остаётся несогласованным, чужое состояние сохраняется. Неизвестный временный файл не удаляется автоматически.

Чтение и завершённый точный повтор обходятся без записи и сети. Неоднозначный ID в одном наблюдении, несовпадение исходной страницы, состава или операторского ввода не позволяют погасить внимание. Неполнота возвращается в плане с `внимание: true`; некорректный контракт может дать явный отказ. Коды нового CLI: `0` — получен результат, `2` — отказ. Код `0` сам по себе не означает пустого внимания. Результат команды `решение` — квитанция записи; текущее составное внимание после неё проверяется отдельным планом. Исторический точный повтор не скрывает появившуюся позднее дельту.

Эта версия записывает явные решения, не вызывает LLM и не разбирает текст вместо оператора. Реальные решения Issue 151 требуют отдельного адресного выбора ROOT; готовность CLI не означает их импорта, приёмки или интеграции.

[Тесты покрытия](tests/test_разбора_версий_обсуждений.py) проверяют CLI, настоящую гонку двух процессов, сохранение исходного SHA, частичность, неизменный повтор и аварии до/после CAS. [Малый профиль](tests/профиль_разбора_версий_обсуждений.py) воспроизводится отдельно:

~~~text
python3.14 -B Инструменты/fum-materialyi-zaprosov/tests/профиль_разбора_версий_обсуждений.py --временный-корень <собственный-каталог-вне-Git> --каталог-RAW <новый-каталог-вне-Git> --выход <новый-профиль.json>
~~~

Три последовательные пары АБ/БА/АБ запускают шесть свежих процессов на ста синтетических комментариях. А возвращает полный состав из 101 объекта, Б — один новый комментарий; выбор источника общий. В каждом процессе проверяется повтор, запрещены сеть и запись, сохранены wall/CPU, счётчики, SHA результата и RAW. Исходники свежего измерения исполняются из проверенных удержанных байтов; SHA и режимы перепроверяются вокруг запусков. Подготовка, первоначальная загрузка helper/subject и запуск интерпретатора исключены из измеряемых интервалов; повторные импорты внутри плана входят. Кэш ОС не очищается. Уменьшение числа выбранных единиц не доказывает ускорения чтения архива, смыслового разбора или экономии токенов.
