# Внимание к полученным обсуждениям GitHub

[Автономный слой](scripts/внимание_к_обсуждениям_GitHub.py) читает уже сохранённый [архив](../../Issues/README.md) и ведёт отдельный учёт разбора. Получение Issue или комментария само по себе не подтверждает разбор, ревью, принятие, назначение либо выполнение. Основание разработки — [ограниченный этап FUM-STEP-0237](../../Планирование/карточки-шагов/🟡-FUM-STEP-0237-автоматизировать-приём-GitHub-Issues.md) и [Журнал реализации](../../Журнал/2026-10-14_12-38-15_MSK_учитывать-разбор-обсуждений-GitHub/запрос.md).

## Вход и состояние

Архив задаётся физическим абсолютным корнем. Он читается локально: страницы, их длины и SHA256, метаданные наблюдений, порядок и идентичность объектов перепроверяются. Слой проходит наблюдения последовательно, поэтому возврат А → Б → А восстанавливает актуальную А, сохраняя неразобранную промежуточную Б. В состоянии остаётся перечень точных отпечатков всех подтверждённых наблюдений. Потеря или дрейф любого из них переводит сбор в неизвестность и сохраняет прежний остаток.

Идентичность обращения включает репозиторий, номер, постоянный `id` и тип Issue/PR; идентичность комментария — постоянный `id` и родителя. Коллизии не склеиваются. Версия обращения связывает хэш полного объекта и хэши всех известных комментариев. Хэш объекта вычисляется по JSON с сортировкой ключей, отступом 2, UTF-8 и конечным LF; хэш страницы относится к исходным байтам ответа. `updated_at` сохраняется отдельно и не заменяет хэш: редакция при прежнем времени всё равно создаёт новую версию.

Контекст разбора — явно переданный непустой JSON-объект, например цель, полномочия и критерий. Его точный хэш участвует в применимости ревью. Изменение контекста возвращает внимание даже при неизменных исходных объектах.

Состояние схемы `fum.внимание-к-обсуждениям.1` хранится в собственной физической папке вне любого Git checkout. Обёртка `fum.сохранение-внимания.1` содержит хэш состояния. Запись использует блокировку сотрудничающих процессов, проверку SHA прочитанного файла, временный файл, `fsync` и атомарную замену. Устаревший писатель получает отказ. Точный повтор сохраняет байты, inode и время изменения. Повреждённый файл или неизвестный остаток установки не сбрасываются в пустую очередь. Это модель сотрудничающих писателей, а не защита от владельца машины, способного подменить файлы и блокировки.

## Явные операции

Из физического корня чистого клона FUM с Python 3.14 команды выполняются так; обозначения путей заменяются собственными физическими адресами:

~~~text
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/внимание_к_обсуждениям_GitHub.py --состояние <частная-папка-вне-Git> --корень-архива <корень-клона> --контекст <файл-контекста.json> сверить
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/внимание_к_обсуждениям_GitHub.py --состояние <частная-папка-вне-Git> прочитать
python3.14 -B Инструменты/fum-materialyi-zaprosov/scripts/внимание_к_обсуждениям_GitHub.py --состояние <частная-папка-вне-Git> --вход <решение.json> ревью
~~~

`сверить` получает локальный архив, обновляет состояние и возвращает состояние, остаток и структурный план разбора. `прочитать` восстанавливает их из сохранённого состояния без архива, сети и записи. Для другого репозитория обязателен одинаковый `--репозиторий владелец/имя` во всех операциях. `--сейчас` позволяет явно выбрать время сверки с часовой зоной; наблюдение из будущего относительно него считается неизвестным входом.

Ревью записывается только явным решением оператора для текущих версии и контекста. Поля входного JSON:

~~~json
{
  "номер": "7",
  "версия": "<точный ключ_версии из состояния>",
  "контекст_sha256": "<точный хэш контекста из состояния>",
  "решение": "отложено",
  "основания": ["Содержательное основание оператора"],
  "время": "2030-01-01T00:00:00+00:00"
}
~~~

Допустимые решения: `рекомендовано`, `отложено`, `отклонено`. Запись сохраняет полный вход, контекст, основания, время и хэш квитанции. Она подтверждает запись решения оператора; адекватность смыслового разбора, принятие и выполнение проверяются отдельно. Неизвестный сбор и устаревший вход отказывают. Повтор ревью неизменной версии по умолчанию отказывает, сохраняя прежнее ревью; явный полный повтор требует поля `полный_повтор_основание` с содержательным основанием.

Неизменная версия в прежнем контексте переиспользует связанное ревью. Для изменённой версии план показывает изменённые поля обращения, новые и изменённые комментарии. Смена контекста требует полного рассмотрения. План является списком входов для будущей работы; он не вызывает модель и не выполняет смысловой разбор.

## Остаток и снятие исторического внимания

Остаток содержит текущие номера без применимого ревью, все неразобранные версии в их контекстах и активные сигналы. Историческая неразобранная версия сохраняется после появления более поздней, даже если новая версия уже разобрана. Сигналы имеют устойчивый ключ причины и привязки; перезапуск и неизменный повтор не создают дублей.

Отсутствие архива, повреждение, коллизия или потеря наблюдения сохраняют неизвестность. Неполный обход сохраняет сигнал неполноты. Отсутствующий в полном обходе ранее известный объект сохраняется: отсутствие не доказывает удаление. Даты последнего сбора, последнего полного сбора, изменения объекта и записанного ревью различаются. Периодичность не выбирается автоматически; только явный положительный `--период-секунд` добавляет сигнал просроченного полного наблюдения.

Оператор может отдельно снять внимание с исторической версии, явно выбрав её точный ключ остатка и более позднюю текущую замену. Операция `снять-историческое-внимание` принимает через `--вход` JSON с полями `ключ`, `замещающая_версия`, `автор`, `основание`, `время`. Первый эффект требует известного полного наблюдения. Квитанция сохраняет точное замещающее наблюдение; исходник, версия и прежние ревью остаются. Это решение не помечает версию разобранной. Повтор того же входа возвращает прежнюю квитанцию без эффекта после нового наблюдения; изменение параметров отказывает. Если снятая версия снова становится текущей, внимание возвращается. Общие принятие, назначение и выполнение этой версией слоя не выполняются.

Коды CLI: `0` — операция с известным сбором; `3` — сохранена или прочитана неизвестность; `2` — отказ входа либо операции. Код `0` не означает пустого остатка, полной приёмки или выполнения Issues. Неполный известный обход может вернуть `0` с активным сигналом неполноты.

## Проверка и профиль

~~~text
python3.14 -B -m unittest discover -s Инструменты/fum-materialyi-zaprosov/tests -p test_внимания_к_обсуждениям_GitHub.py
python3.14 -B Инструменты/fum-materialyi-zaprosov/tests/профиль_внимания_к_обсуждениям_GitHub.py --число-обращений 64 --повторы 3 --выход <новый-профиль.json>
~~~

[Тесты](tests/test_внимания_к_обсуждениям_GitHub.py) проверяют версии, контекст, остаток, неизвестность, историю, повреждение состояния, конкурентный устаревший снимок и повтор. Отдельный свежий процесс читает локальный клон после удаления исходного архива; сеть и запуск внешних процессов в этом чтении заблокированы, а неизменность сохранённых байтов и метаданных проверена.

[Профиль](tests/профиль_внимания_к_обсуждениям_GitHub.py) сравнивает полный проход и дельту на одинаковом синтетическом входе: неизменность — 0 против 64 вызовов ядра; одна редакция — 1 против 64; смена контекста — 64 против 64. Совпадение SHA всего результата включает переиспользованные элементы. Время сверки и планирования отделено от времени статического ядра обработки текста. Подготовка исключена; пик памяти означает дополнительные отслеживаемые выделения после создания кэша. Три свежих процесса и все исходные пары сохранены в [материалах Журнала](../../Журнал/2026-10-14_12-38-15_MSK_учитывать-разбор-обсуждений-GitHub/отчёт.md).

Измерение подтверждает сокращение повторных вызовов синтетического ядра. Скорость смыслового ревью, расход токенов, стоимость модели и весь рабочий цикл им не измерены. По этим данным дальнейшая оптимизация сверки не обоснована: она продолжает проверять архив полностью, а ограниченный кэш одинаковых страниц действует только внутри одного чтения.
