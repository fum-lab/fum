# FUM README Index

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) проверяет, что раздел `Документация по темам` корневого `README.md` даёт прямой вход ко всем актуальным номерным документам и каноническим папочным индексам `Документация/`.

Проверка защищает корневой вход в [память FUM](../../Глоссарий/память-FUM.md) от тихого устаревания. Новый номерной документ или новая папочная точка входа становятся обязательными для индекса автоматически, поэтому отдельный ручной список ожидаемых имён не поддерживается.

## Контракт входов

Общий инвентарь задаёт [fum-proyektnyiye-fajlyi](../fum-proyektnyiye-fajlyi/SKILL.md). Из него выбираются только два вида файлов:

- верхнеуровневые `Документация/NN-*.md`;
- канонические `Документация/NN-*/README.md`.

Неномерные документы и вложенные файлы номерных папок, кроме их `README.md`, не входят в этот контракт. Ссылки учитываются только внутри точного раздела второго уровня `## Документация по темам`; ссылка в другом разделе, комментарии, блоке кода или inline-коде не маскирует пропуск. Пути сравниваются после безопасной URL-декодировки и лексической нормализации, но с точным регистром.

Отсутствующий или повторённый тематический раздел, ошибка общего инвентаря и любой пропущенный обязательный путь останавливают проверку.

## Команда

Из корня репозитория:

```bash
python3 Инструменты/fum-indeks-readme/scripts/check-readme-index.py \
  --repo-root .
```

Успех возвращает код `0` и число обязательных и проиндексированных входов. Пропуск возвращает код `1` и устойчивый отсортированный список отсутствующих путей. Проверка ничего не записывает, не обращается к сети, не использует секреты и не зависит от текущей даты.

## TDD-проверки

Автономные тесты запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-indeks-readme/tests -p 'test_*.py'
```

Фикстуры подтверждают полный индекс, появление нового номерного документа и папочного `README.md`, строгую границу тематического раздела, чувствительность к регистру, исключение неномерных и вложенных документов, fail-closed отсутствие раздела и стабильный CLI-вывод. Интеграционный тест применяет тот же контракт к текущему репозиторию.

Проверка также является явным шагом общего [smoke-check](../fum-kompleksnaya-proverka-repozitoriya/SKILL.md), поэтому тесты валидатора и фактическая полнота текущего README проверяются перед коммитом.

## Граница автоматизации

Автоматизация проверяет наличие прямых ссылок, но не оценивает качество тематической группировки, названия ссылок или полноту содержания документов. `README.md` остаётся человекочитаемым входом, а `Документация/` — источником производной документации.
