# FUM Smoke Check

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) собирает основной проверочный контур репозитория в одну команду. Она нужна перед коммитами и публикационными сессиями, когда важно быстро подтвердить, что локальные автоматизации проходят тесты, SwiftPM-прототипы тестируются и собираются, Git-зависимость LinguisticKit совпадает с fork/upstream-контрактом, проверяемые реестры пересобираются, реестр имён автоматизаций согласован с каталогами, содержимое не публикует машинно-локальные пути, корневой README индексирует номерную документацию, активные вопросы двунаправленно связаны с заявленными целями, Markdown-recency свежа, а выбранная [рабочая сессия](../../Глоссарий/рабочая-сессия.md) связана с запросом, журналом и Git-состоянием.

По умолчанию smoke-check работает локально: он не требует секретов, сетевых запросов и внешних сервисов. Все шаги запускаются через явные команды Python и уже существующие локальные автоматизации.

## Когда использовать

Используй эту автоматизацию, когда нужно:

- выполнить единый регрессионный прогон перед коммитом рабочей сессии;
- проверить, что новые или изменённые локальные автоматизации покрыты тестами;
- проверить тесты, исполняемые продукты и lint-контракт всех SwiftPM-пакетов верхнего уровня в `Прототипы/`;
- пересобрать и сверить проверяемые реестры репозитория;
- проверить полный учёт новых и legacy-имён автоматизаций, их slug, эталоны и состояние зависимости LinguisticKit;
- проверить действующее содержимое на машинно-локальные пути и раскрытие Swift `#filePath`;
- проверить полноту тематического индекса номерной документации в корневом `README.md`;
- проверить существование, регистр и обратные ссылки заявленных целей открытых и частично прояснённых вопросов;
- убедиться, что `FUM-MD-RECENCY` и индекс Markdown-файлов свежие;
- проверить связность выбранного файла `Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md`.

## Команда запуска

Полный smoke-check для рабочей сессии:

```bash
python3 Инструменты/fum-kompleksnaya-proverka-repozitoriya/scripts/run-smoke-check.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md \
  --commit-message-file <путь-к-файлу-сообщения> \
  --codex-thread-id <корневой-CODEX_THREAD_ID>
```

Для запросов начиная с `2026-07-14_02-31-47_MSK_добавлять-идентификатор-сеанса-Codex.md` оба новых параметра обязательны; исторические запросы можно проверять без них. Список проверочных команд без запуска тестов, сборки и lint:

```bash
python3 Инструменты/fum-kompleksnaya-proverka-repozitoriya/scripts/run-smoke-check.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md \
  --list
```

При построении списка `Package.swift` оцениваются локальным `swift package dump-package` с выключенным кэшем манифеста, чтобы показать фактические исполняемые продукты. Тесты, сборка и lint в режиме `--list` не запускаются.

Частичный локальный запуск без проверки конкретной рабочей сессии:

```bash
python3 Инструменты/fum-kompleksnaya-proverka-repozitoriya/scripts/run-smoke-check.py \
  --skip-session-coherence
```

## Что запускается

Автоматизация выполняет шаги в устойчивом порядке:

1. Находит все каталоги `Инструменты/*/tests`, содержащие `test_*.py`, и запускает для каждого:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s <tests-dir> -p 'test_*.py'
```

2. Находит все `Прототипы/*/Package.swift`, получает фактические продукты и пути целей через:

```bash
swift package \
  --package-path <путь-к-пакету> \
  --manifest-cache none \
  dump-package
```

Для каждого пакета автоматизация запускает автономные тесты:

```bash
swift test --package-path <путь-к-пакету>
```

Каждый объявленный исполняемый продукт собирается отдельно:

```bash
swift build \
  --package-path <путь-к-пакету> \
  --product <имя-продукта>
```

По умолчанию все пути целей и `Package.swift` проходят строгий lint:

```bash
swift format lint \
  --configuration Инструменты/fum-kompleksnaya-proverka-repozitoriya/swift-format.json \
  --strict \
  --recursive \
  <путь-к-пакету>/Package.swift \
  <пути-целей>
```

Центральная [конфигурация форматтера](swift-format.json) фиксирует набор правил и параметров вместо зависимости от неявного файла среды. Файлы `.swift-format-ignore` запрещены во всей применимой иерархии, потому что они могут молча исключить явно переданный Swift-файл даже из строгого lint.

[Политика SwiftPM-пакетов](swift-package-policy.json) хранит ожидаемый инвентарь пакетов и исполняемых продуктов. Исчезнувший пакет или продукт, новый незарегистрированный пакет и несовпадение с фактическим `dump-package` останавливают smoke-check. Если временное lint-исключение необходимо, оно обязано содержать причину, критерий снятия, существующий источник и SHA-256 центральной конфигурации, `Package.swift` и Swift-файлов целей. Исключение печатается в обычном запуске и `--list`; любое изменение защищённого снимка останавливает smoke-check как устаревшая политика. Текущая политика не содержит исключений: оба действующих SwiftPM-пакета проходят строгий lint вместе с обязательными тестами и сборками исполняемых продуктов.

3. Пересобирает машинно читаемый плановый реестр:

```bash
python3 Инструменты/fum-reyestr-planirovaniya/scripts/build-planning-registry.py build \
  --output Планирование/реестр-требований-вариантов-и-кандидатов.json
```

4. Проверяет свежесть планового реестра:

```bash
python3 Инструменты/fum-reyestr-planirovaniya/scripts/build-planning-registry.py validate \
  --registry Планирование/реестр-требований-вариантов-и-кандидатов.json
```

5. Проверяет реестр названий автоматизаций:

```bash
python3 Инструменты/fum-proverka-nazvanij-avtomatizacij/scripts/proveritj-nazvaniya-avtomatizacij.py \
  --repo-root . \
  --registry Инструменты/реестр-названий-автоматизаций.json
```

Канонический реестр находится в состоянии `ready`, поэтому полный smoke-check требует материализованный пакет и живой вызов LinguisticKit. После свежего клонирования сначала нужно [инициализировать submodule и локальный `upstream`](../../Зависимости/README.md); перевод реестра в `blocked` не является допустимым обходом этой операции.

6. Проверяет содержимое на машинно-локальные пути:

```bash
python3 Инструменты/fum-proverka-mashinno-lokaljnyikh-putej/scripts/proveritj-mashinno-lokaljnyiye-puti.py \
  --repo-root .
```

Проверка использует Git-инвентарь, печатает стабильные обезличенные категории и отличает действующие нарушения от типизированных системных, тестовых, исторических и внешних случаев. Полный smoke-check останавливается на любой новой first-party-регрессии.

7. Автономно проверяет Git-топологию подключённого LinguisticKit:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py check \
  --repo-root . \
  --fork-url https://github.com/fum-lab/LinguisticKit.git \
  --upstream-url https://github.com/Roman-Kerimov/LinguisticKit.git \
  --path Зависимости/LinguisticKit \
  --revision 837e2ce107b97ee7b9d3344c9fe99142281fe393
```

8. Проверяет обязательные точки входа всех устойчивых прототипов:

```bash
python3 Инструменты/fum-zapusk-prototipov/scripts/check-prototype-launchers.py
```

9. Проверяет двунаправленность открытых и частично прояснённых вопросов:

```bash
python3 Инструменты/fum-obratnyiye-ssyilki-voprosov/scripts/check-question-backlinks.py
```

10. Проверяет полноту тематического индекса корневого README:

```bash
python3 Инструменты/fum-indeks-readme/scripts/check-readme-index.py \
  --repo-root .
```

11. Проверяет recency-метки без записи:

```bash
python3 Инструменты/fum-svezhestj-markdown/scripts/update-md-recency.py --check
```

12. Проверяет тепловую карту графа Obsidian без записи:

```bash
python3 Инструменты/fum-svezhestj-grafa-obsidian/scripts/build-obsidian-graph-recency.py \
  --check
```

Проверка использует опорную дату тепловой карты из `.obsidian/fum-recency-reference-date`. Поэтому переход календарного дня сам по себе не делает неизменный снимок ошибочным; для перехода к новому календарному срезу генератор сначала запускается с явным `--today YYYY-MM-DD`.

13. Проверяет связность выбранной рабочей сессии:

```bash
python3 Инструменты/fum-svyaznostj-rabochej-sessii/scripts/check-session-coherence.py \
  --request Запросы/<YYYY-MM-DD_HH-MM-SS_MSK>_<краткое-название-запроса>.md \
  --commit-message-file <путь-к-файлу-сообщения> \
  --codex-thread-id <корневой-CODEX_THREAD_ID>
```

## Проверки автоматизации

Локальные тесты самой автоматизации запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-kompleksnaya-proverka-repozitoriya/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: smoke-check обнаруживает тесты локальных автоматизаций и SwiftPM-пакеты, сверяет инвентарь пакетов и продуктов, отклоняет зависимости без offline-контракта, читает продукты из результата `dump-package`, запускает `swift test`, отдельно собирает каждый исполняемый продукт, применяет центральный строгий lint по умолчанию, запрещает `.swift-format-ignore`, проверяет хэш временного исключения и его видимый проход через исполнитель шагов, добавляет сборку и проверку планового реестра, явные проверки реестра названий автоматизаций и машинно-локальных путей, точки входа прототипов и полноту корневого README, запускает проверку двунаправленности вопросов и recency-проверки, требует `--request` для проверки связности рабочей сессии, для новых запросов требует файл сообщения и корневой Codex-Thread-ID, передаёт их в `fum-svyaznostj-rabochej-sessii`, сохраняет совместимость с историческими запросами и допускает частичный запуск с `--skip-session-coherence`. Отдельный end-to-end-тест создаёт отслеживаемую first-party-регрессию и подтверждает остановку полного исполнителя именно на новом сканере; тест режима `--list` подтверждает, что он оценивает только манифест для построения списка, но не запускает тесты, сборку или lint.

## Граница автоматизации

Smoke-check не заменяет смысловую проверку изменений, публикационную чистоту diff и решение агента о том, какие файлы нужно коммитить. Он объединяет локальные структурные проверки и останавливается на первом упавшем шаге, чтобы ошибка оставалась наблюдаемой и не маскировалась следующими командами.

Если в репозитории появляется новый проверяемый реестр, его нужно добавить в `run-smoke-check.py` и закрепить ожидание тестом. Если у новой локальной автоматизации появляются тесты в `Инструменты/<имя>/tests`, smoke-check начнёт запускать их автоматически.

Обнаружение SwiftPM намеренно ограничено устойчивыми прототипами вида `Прототипы/<имя>/Package.swift`, поэтому кэши `.build`, `.swiftpm` и пакеты транзитивных зависимостей не становятся самостоятельными входами smoke-check. Объявленная SwiftPM-зависимость верхнеуровневого пакета в `Прототипы/` отклоняется до тестов и сборки, пока не добавлен отдельный воспроизводимый offline-контракт. Локальная служебная обёртка использует LinguisticKit только через отдельно проверяемый Git submodule. Результат `dump-package` зависит от локального Swift toolchain и платформы, поэтому неизвестная структура манифеста или отсутствие исполняемого продукта считается ошибкой, а не основанием тихо пропустить сборку.

Текущий Swift-контур предназначен для macOS: оба пакета требуют macOS 14 или новее, Swift 6.0 или новее и Xcode с командами `swift` и `swift format`, а сборки smoke-check являются отладочными сборками SwiftPM по умолчанию. Центральная конфигурация не содержит имён правил, отсутствующих в Swift 6.0, но более старый форматтер может игнорировать неизвестные ему дополнительные параметры, поэтому идентичная семантика lint между разными версиями toolchain не обещается. Принятый снимок полностью проверен на Swift 6.4 и Xcode 27.0; это наблюдаемая текущая среда, а не обещание бинарной совместимости со всеми будущими toolchain.
