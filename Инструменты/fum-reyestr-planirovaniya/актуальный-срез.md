# Актуальный срез выбранного планирования

Команда читает конечный состав из явно закреплённого полного Git OID. Она выдаёт цели, записанный приоритет с основанием, исполнителя, следующий STEP, зависимости и исторические наблюдения. Происхождение содержит коммит, дерево, режим и OID blob, SHA256 сырых байтов и их объём. Для Markdown дополнительно указан SHA256 нормализованного содержания без метки свежести. Изменённый checkout не участвует в чтении; ссылки нормализуются лексически относительно канонического пути.

## Вход и запуск

```sh
python3 -B Инструменты/fum-reyestr-planirovaniya/scripts/актуальный-срез.py \
  --корень-репозитория /путь/к/FUM --коммит ПОЛНЫЙ_OID \
  --выбор /путь/к/выбор.json --момент 2026-10-05T02:00:00+03:00 \
  --предел-байтов 65536 --профиль
```

`выбор.json` имеет ровно три поля: `схема: "fum.выбор-актуального-среза.1"`, целый неотрицательный `предел_возраста_секунд` и массив `источники` от 1 до 64 элементов. Источник содержит `вид`, канонический относительный `путь` и `наблюдение` — ISO 8601 с зоной либо `null`. Дополнительные поля: `шаг` для привязки ACT к выбранной карточке; `зависимости` — явные пути зависимостей карточки. Повторные пути и неизвестные поля отклоняются.

Виды: `карточка` из `Планирование/карточки-шагов`, `таблица` с разделом «Ближайшие согласованные поставки» и пятью текущими столбцами, `цель` с H1, `акт` схемы `fum.поручение-дочерней-контрольной-точки.1`, `свидетельство` и текстовое `основание`. Строгую таблицу и карточки разбирает общее ядро `build-planning-registry.py`; прежние файловые оболочки и реестр версии 9 сохраняются.

Свидетельство имеет закрытую схему `fum.наблюдение-планового-состояния.1` и поля `шаг`, `состояние`, `момент`, `исполнитель`, `результат`, `основание`. Состояния: `назначено`, `запущено`, `результат передан`, `принято`, `интегрировано`, `снято`. Исполнитель и полный OID результата могут быть `null`. Основание — `null` либо `{путь, sha256, цитата}` другого явно выбранного источника. Момент внутри свидетельства определяет порядок; момент в выборе не переписывает его. Открытая [фикстура](tests/фикстуры/актуальный-срез.json) содержит полный пример выбора и исходные файлы.

## Подтверждение и неизвестность

`основание_сверено` означает только совпадение SHA и точной самостоятельной строки. Для отмены это `Снято FUM-STEP-NNNN.`, для остальных состояний — `Назначено|Запущено|Передано|Принято|Интегрировано FUM-STEP-NNNN: OID.`. Дополнительно проверяется существование коммита результата; для интеграции — два родителя и включение результата в выбранный C. Эти проверки не устанавливают полномочие автора. Даже точная цитата в ответе ребёнка или блоке кода остаётся декларацией.

Поэтому `основание_проверено` всегда ложно, а `подтверждение_состояния` равно `null`. Проверенная цепочка полномочия и точная связь STEP с решением приёмки — открытая граница следующего расширения. ACT хранится целиком как историческое назначение; запуск, передачу, приёмку и интеграцию он не подтверждает. Исполнитель из таблицы или отдельной строки ACT — записанное значение источника; свидетельства не превращают его в текущее проверенное назначение. Ранняя и недатированная история сохраняется полностью. Последние датированные наблюдения показаны отдельно: это все события одного максимального момента после нормализации часовой зоны. Противоречия состояний и исполнителей отражены в неизвестности только внутри этой последней группы. Последовательные стадии, смена исполнителя и поздняя отмена сами по себе не создают противоречия.

Возраст вычисляется только из переданного времени наблюдения и явного момента оценки. Граница включительна: возраст от нуля до предела — `свежее`; отрицательный — `момент из будущего`; больше предела — `устарело`; отсутствующий момент — `неизвестно`. Это вычисление не подтверждает время реального наблюдения или смысловой приоритет.

## Полнота и пределы

Полнота относится только к выбранным источникам. Выдача явно сообщает, что весь проект и полный JSON-реестр не проверены. Невошедшие зависимости, непокрытые свидетельства и неизвестность всех строк сохраняются при сокращении вывода. При превышении бюджета убирается конечный суффикс строк, сохраняются их идентификаторы и счётчики. Если обязательные сведения не помещаются, команда отказывает с пустым stdout и кодом 2. Успех возвращает код 0 и канонический JSON с LF; профиль идёт отдельно в stderr.

Бюджет результата — от 100 до 2097152 UTF-8-байтов. Применяются прежние пределы `СрезГит`: 2 МиБ на объект, 32 МиБ суммарного чтения и 20 секунд на экземпляр. Нет обхода всего проекта, сети или долговременного кэша. Полный реестр больше 2 МиБ не выбран. Отсутствующий источник, неверный регистр/режим, symlink, ошибочный UTF-8, повреждённая таблица или JSON вызывают отказ. Недостаточное смысловое основание сохраняет неизвестность.

## Воспроизведение проверки и профиля

```sh
python3 -B -m unittest discover -s Инструменты/fum-reyestr-planirovaniya/tests -p test_актуальный_срез.py
python3 -B -m unittest discover -s Инструменты/fum-reyestr-planirovaniya/tests -p test_build_planning_registry.py
python3 -B Инструменты/fum-reyestr-planirovaniya/tests/профиль_актуального_среза.py --выход /путь/к/профиль.json
```

До подготовки Git-фикстуры и измерений профиль резервирует новый выход через `O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW` с режимом 0600 и записывает результат через удерживаемый файловый дескриптор. Занятый обычный файл, существующая или оборванная символическая ссылка вызывают отказ до измерений; для следующего запуска нужен новый путь.

Профиль использует один конечный состав, исключает подготовку Git и сравнивает новый экземпляр, новый повтор, повтор того же экземпляра и изменение одного источника. Измеряются время чтения, разбора, выдачи, Git-вызовы, прочитанные байты и объём результата. Вложенные интервалы не суммируются. Кэш ОС не очищается; повтор того же экземпляра использует только существующий кэш `СрезГит`. Токены не измерены. Эти измерения не доказывают размещение всего состояния проекта в контексте LLM.
