# Локальные черновики поддержки FUM

Генератор собирает черновики Telegram, MAX и отчёта из одного JSON-входа. Собственные результаты FUM сохраняют CC0-1.0. Подготовка текста не создаёт аккаунт, публикацию, пожертвование или подтверждение доставки.

## Запуск

Нужны Python и Git; проверенные версии указаны в [профиле этапа](../../Журнал/2026-09-16_00-09-04_MSK_разделить-свидетельства-и-планы-медиапакета/материалы/профиль-медиапакета-итог.json). Совместимость с другими версиями отдельно не измерялась. Из корня клона FUM:

```bash
python3 -B Инструменты/fum-reyestr-planirovaniya/scripts/медиапакет-поддержки.py --корень-репозитория . --вход Журнал/2026-09-16_00-09-04_MSK_разделить-свидетельства-и-планы-медиапакета/материалы/вход-медиапакета.json
```

Успех: код 0 и полный JSON в stdout. Отказ: код 2, сообщение в stderr, stdout пуст. Сохранение stdout выполняет вызывающая сторона после проверки кода завершения. Сам CLI не записывает пакет или байткод и не загружает недостающие Git-объекты. Объекты всех указанных коммитов должны уже присутствовать локально; неполный клон может быть отклонён. Уточнение окружения и получение объектов выполняются отдельно от генерации.

## Вход версии 2

Полный [пример](../../Журнал/2026-09-16_00-09-04_MSK_разделить-свидетельства-и-планы-медиапакета/материалы/вход-медиапакета.json) содержит ровно поля `схема`, `лицензия`, `результат`, `ограничения`, `цель`, `следующий_шаг`, `отчёт`. Схема — `fum.вход-медиапакета.2`; лицензия — `CC0-1.0`. Строки непустые, однострочные, до 8000 символов; ограничений от 1 до 32. JSON ограничен 524288 байтами. Повторные и неизвестные ключи отклоняются.

`результат` содержит `вид`, `источник`, `основание`. Виды `план` и `материал` требуют `основание: null` и получают соответствующую подпись. Наличие цитаты в исходнике само по себе не делает её проверенным результатом.

Адрес источника — объект с полным 40-значным `коммит`, точным относительным `путь` и `sha256` байтов Git blob. Материальный источник дополнительно содержит `цитата`. Обычный файл берётся из указанного коммита, независимо от текущего файла в checkout. Символические ссылки, каталоги, сокращённые OID, несовпадение регистра, хэша или цитаты отклоняются; Git replacement refs не меняют читаемый объект.

Для вида `проверенный результат` нужно отдельное `основание` с полями `источник` и `доверенный_автор`. Его Git blob целиком представляет один JSON-объект:

```json
{
  "схема": "fum.свидетельство-результата.1",
  "вид": "свидетельство проверки",
  "автор": "выбранный оператором автор",
  "объект": {"коммит": "полный OID материала", "путь": "путь материала", "sha256": "SHA-256 материала"},
  "утверждение": "точная цитата материала",
  "проверка": "описание выполненной проверки и её границы",
  "исход": "успешно",
  "протокол": {"коммит": "полный OID протокола", "путь": "путь протокола", "sha256": "SHA-256 протокола"}
}
```

Это схема полей с пояснениями вместо хэшей, а не исполняемый пример. Автор, объект и утверждение должны точно совпасть с входом; протокол тоже проверяется по Git-адресу и хэшу. Выход подписан «Результат по свидетельству» и показывает автора, область проверки, свидетельство и протокол.

## Финансовое свидетельство

`отчёт` содержит `период`, `получатель`, `валюта`, `начальный_остаток`, `поступления`, `комиссии`, `возвраты`, `расходы`, `источник`, `доверенный_автор`. Валюта — `RUB`; суммы — целые неотрицательные копейки до 10¹² либо `null`. Ноль означает известный ноль и требует свидетельства. Неизвестное не преобразуется в ноль. Конечный остаток вычисляется только при известных пяти суммах; отрицательный вычисленный остаток сохраняется.

При `источник: null` все суммы и доверенный автор должны быть `null`. Период и получатель могут оставаться неизвестными. Если источник задан, весь его Git blob должен быть одним JSON-объектом:

```json
{
  "схема": "fum.свидетельство-поддержки.1",
  "вид": "фактический учёт",
  "автор": "выбранный оператором автор",
  "валюта": "RUB",
  "период": "2026-09",
  "получатель": "явно названный получатель",
  "суммы": {"начальный_остаток": null, "поступления": null, "комиссии": null, "возвраты": null, "расходы": null}
}
```

Поля отчёта и свидетельства совпадают полностью, включая `null`. Любая известная сумма требует периода и получателя. Период — календарно допустимый `YYYY-MM`. Финансовый источник указывается отдельно от материала новости. JSON внутри плана, обещания, строки, массива, вложенного объекта или рядом с другим документом не принимается как самостоятельное свидетельство. Пробельное оформление полного JSON допустимо.

Оператор явно выбирает доверенного автора. Генератор проверяет формат, Git-происхождение и согласованность; он не удостоверяет личность автора, исполнение проверки или банковскую операцию. Редактор самостоятельно проверяет содержание свидетельства и протокола перед публикацией. В публичный Git попадают только допустимые агрегаты; закрытые реквизиты не являются входом этого инструмента.

## Переход и воспроизведение

Версия 1 отклоняется: автоматической миграции нет. Для перехода нужно явно определить, является прежняя цитата планом, материалом или утверждением с отдельным основанием, а финансовую цитату заменить целой записью выбранного автора либо оставить суммы неизвестными. Опубликованные старые пакеты сохраняются как история; новый пакет имеет схему `fum.выход-медиапакета.2`.

При одном входе, тех же Git-объектах, коде и шаблонах результат детерминирован. `вход_sha256` в пакете относится к канонической сериализации JSON; `вход_sha256` в профиле — к исходным байтам входного файла. Это разные границы хэширования.

Регрессии воспроизводятся командой `python3 -B Инструменты/fum-reyestr-planirovaniya/tests/запустить_проверки_медиапакета.py`. Producer сохраняет полный текст unittest в stderr и представление с заменой локальных путей в stdout; хэш в конце stdout относится к тексту unittest, а хэши обоих полных потоков даёт отдельный захват процесса. В контролируемой сессии запуск учитывается штатной обёрткой проверок.

Профильный сценарий `tests/профиль_медиапакета_поддержки.py` принимает `--корень`, `--вход`, `--выход`, `--повторы`. Он измеряет Git-чтение, проверку и шаблоны; подготовка входа и запись профиля исключены. Сравнивать профили разных контрактов как доказательство ускорения нельзя.
