# Выпускать подготовленный пакет диагностики

Узкая команда принимает явный пакет карточек с уже назначенными номерами, строит проверяемые будущие тексты и применяет сохранённый план. Смысл, число проявлений, источники и статус задаёт рабочая сессия после сверки доказательств. Файлы ограничены карточками `Сбои/`, карточками `Планирование/карточки-шагов/` и двумя соответствующими `README.md`.

## Подготовить данные

Вход — JSON с точными полями `схема: "fum.пакет-диагностики.1"`, `сбои` и `шаги`. Оба последних поля — массивы; всего допускается от 1 до 100 записей. Для каждой записи нужны:

| Поле | Значение |
| --- | --- |
| `операция` | `создать` либо `обновить` |
| `номер` | Уже назначенный `FUM-СБОЙ-NNNN` либо `FUM-STEP-NNNN` |
| `имя` | Описание имени файла из букв и цифр, разделённых дефисами; без пути |
| `статус` | Для СБОЙ: `активна`, `устранена`, `поглощена`, `снята`; для STEP: `active`, `completed`, `absorbed`, `withdrawn` |
| `заголовок` | Готовый содержательный заголовок без перевода строки и символов `[]\|` |
| `содержимое` | Готовые разделы Markdown без метаданных TOML и заголовка первого уровня |
| `до_sha256` | `null` для создания; полный SHA-256 исходных UTF-8 байтов карточки для обновления |

У СБОЙ обязательны ещё `проявлений` — явно проверенное положительное целое число, и `основной_шаг` — назначенный `FUM-STEP-NNNN` либо `null`. Активному сбою нужен основной шаг; `null` выводится в индексе знаком «—». Число не извлекается из упоминаний номера в прозе. Квалифицированная ссылка на исторический коммит и путь остаётся буквальной ссылкой: её локальный номер не переадресуется современной карточке.

Тело СБОЙ содержит восемь непустых разделов [канонического формата](../../Глоссарий/карточка-сбоя.md) и соответствующий статусу раздел подтверждения. STEP проверяется тем же парсером, что машинный реестр. Число проявлений, смысл доказательства закрытия и полнота двусторонних связей остаются отдельной смысловой проверкой; это не полный контур FUM-STEP-0114.

Для исторического входа без TOML допускается только прежняя начальная шапка: единственные заголовок `# FUM-СБОЙ-NNNN — …`, строка `- Идентификатор: ` с тем же номером в обратных кавычках и конечной точкой, и строка допустимого статуса. Номер обязан совпадать с явно заданным обновлением; исходный SHA-256 проверяется до разбора. Проза после первого раздела не объявляет идентичность. Выход нормализуется в канонический TOML.

Обновление сохраняет номер и путь: `имя` должно совпадать с существующим файлом. Переименование и смена статусного имени STEP выполняются штатной отдельной автоматизацией. Неизвестные поля, повторные JSON-ключи, дубли номеров, подмена файлов, символические ссылки и коллизии регистра или Unicode при подготовке отклоняются.

## Проверить и применить план

Работайте в своём worktree и ветке `codex/…`, сохраняя вход и план вне публикуемого checkout. Из корня FUM:

```text
python3 Инструменты/fum-reyestr-planirovaniya/scripts/пакет_диагностики.py план --корень . --задача <корневой-UUID> --вход <пакет.json> > <план.json>
python3 Инструменты/fum-reyestr-planirovaniya/scripts/пакет_диагностики.py применить --корень . --задача <корневой-UUID> --вход <план.json> > <квитанция.json>
```

Сначала прочитайте `данные.файлы` плана: для каждого пути сохранены точные `до` и `после`. Конверт связывает полный пакет, физический корень, владельца, ветку, исходный коммит и контрольные суммы. Контрольная сумма обнаруживает повреждение, а повторное построение текстов из пакета не позволяет произвольно расширить список файлов. Это не цифровая подпись смыслового решения.

Применение повторно проверяет владельца, ветку, исходный коммит и все исходные байты под общим замком хранилища. В том же замке перед циклом установки повторно сверяются имена, NFC/casefold и идентичности соседних карточек: частично записанный второй план не допускает две карточки одного номера. Собственные сохранённые будущие байты допускаются для восстановления. Намерение сохраняется до записи checkout; каждый файл устанавливается атомарной заменой с синхронизацией. Пакет не является единой файловой транзакцией: прерывание может оставить часть новых файлов, и повтор того же плана завершает сохранённое намерение. Неожиданные байты закрывают повтор. После успешного применения сохраните квитанцию и проверьте diff; перед производными изменениями завершите необходимое восстановление. Изменённые впоследствии генератором файлы не являются прежними байтами этого плана.

Далее штатно обновите машинный реестр, затем recency и связность своей сессии:

```text
python3 Инструменты/fum-reyestr-planirovaniya/scripts/build-planning-registry.py build --output Планирование/реестр-требований-вариантов-и-кандидатов.json
python3 Инструменты/fum-reyestr-planirovaniya/scripts/build-planning-registry.py validate --registry Планирование/реестр-требований-вариантов-и-кандидатов.json
```

Команда не распределяет номера, не пишет чужие ветки, не создаёт внешние задачи, не делает коммит или push. Идентификаторы резервируются до подготовки пакета существующим общим распределителем. Непротокольные ручные писатели должны быть исключены владельцем сессии.

## Воспроизвести проверку

Через отчётную обёртку своей сессии запустите адресный набор и малый профиль. Они используют только открытые временные Git-репозитории:

```text
python3 -B -m unittest discover -s Инструменты/fum-reyestr-planirovaniya/tests -p test_пакета_диагностики.py
python3 -B Инструменты/fum-reyestr-planirovaniya/tests/профиль_пакета_диагностики.py --выход <профиль.json>
```

Профиль измеряет пять отдельных пакетов по пять СБОЙ, два STEP и два индекса, затем точный повтор. Он сохраняет интервалы и хэши инструментов; подготовка временного Git исключена, наблюдение владельца, чтение, замок и синхронизация файлов включены.
