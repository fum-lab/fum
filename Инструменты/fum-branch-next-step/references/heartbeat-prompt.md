# Шаблон heartbeat-диспетчера

Этот шаблон воспроизводит внешнюю часть [автоматизации следующего шага ветки](../SKILL.md) в каждом локальном клоне памяти FUM. При регистрации heartbeat значение `<КОРЕНЬ_КЛОНА>` заменяется точным абсолютным путём сохранённого проекта Codex. Сам непрозрачный идентификатор автоматизации в репозиторий не переносится.

Heartbeat прикрепляется к отдельной диспетчерской задаче клона, запускается каждые пять минут и остаётся в паузе до чистого коммита установки. После активации он не выполняет проектный шаг сам, а создаёт обычную задачу в боковом меню только при отсутствии другой активной задачи в доступном recent-снимке.

## Шаблон

```text
Это пятиминутный тик диспетчера FUM. Не выполняй проектный шаг в этой задаче: при отсутствии другой active-задачи в доступном recent-снимке создай отдельную обычную задачу Codex в боковом меню, иначе заверши тик без изменений.

Работай fail-closed:
1. Получи собственный точный CODEX_THREAD_ID из среды. Не публикуй его и не подменяй другими внутренними идентификаторами.
2. Вызови штатный codex_app.list_threads с limit=50 и без query. Продолжай только если unavailableHosts пуст, вызов успешен, собственный id найден ровно один раз со status=active, каждая запись имеет известное состояние active, idle или notLoaded, а среди всех остальных задач нет ни одной со status=active. Любое иное состояние, системная ошибка или недоступный host означает остановку без claim и без создания задачи. Контракт возвращает recent-снимок без общего числа и признака полноты: не называй его глобальным доказательством отсутствия других active-задач.
3. В <КОРЕНЬ_КЛОНА> проверь git status --porcelain --untracked-files=all. Если есть изменение вне корневого каталога .obsidian/, заверши без claim.
4. Выполни python3 Инструменты/fum-branch-next-step/scripts/branch-next-step.py show --repo-root . --json. Продолжай только при коде 0 и state=ready; сохрани точные branch_ref, step_id, record_path, project_path, task и criteria.
5. Выполни claim той же пары с --expected-branch-ref и --expected-step-id. Продолжай только при коде 0 и state=claimed; сохрани выданный lease_id. already_claimed, mismatch, invalid или not_ready означают отсутствие запуска.
6. Снова вызови codex_app.list_threads по тем же правилам. Если после claim появилась другая active-задача, host стал недоступен, собственный id не подтверждён или снимок сомнителен, освободи только собственный claim командой release с сохранённым --expected-lease-id и заверши без создания задачи.
7. Вызови codex_app.list_projects. Требуй ровно один локальный сохранённый проект с точным path <КОРЕНЬ_КЛОНА>. Если доказать его нельзя, освободи собственный claim и заверши.
8. Вызови codex_app.create_thread для найденного projectId с target.environment.type=local. Не задавай model или thinking. Составь дочерний prompt на русском и включи в него все точные значения прочитанной записи, задачу и критерии. Потребуй: полностью прочитать <КОРЕНЬ_КЛОНА>/Инструменты/fum-branch-next-step/SKILL.md; полностью прочитать переданные record_path и project_path, считать запись шага и паспорт проекта обязательными входами и соблюдать границы действий, доступа, публикации и проверки паспорта; до любых записей выполнить fenced show с ожидаемыми branch_ref и step_id; при mismatch завершить без изменений; провести обычную рабочую сессию по AGENTS.md и сохранить этот диспетчерский prompt как исходный материал сессии; выполнить задачу и критерии; перед коммитом заменить запись новым выбранным шагом со свежим step_id либо поставить paused, blocked или done; дождаться всех писателей, прогнать проверки и создать локальный коммит. Не разрешай дочерней задаче освобождать claim успешно созданного запуска.
9. Освободи только собственный claim по сохранённому lease_id только если штатный ответ явно подтверждает, что задача не создана. При ошибке, тайм-ауте или неоднозначном результате не освобождай claim: задача могла быть создана; сохрани поколение для обычного fenced-восстановления после внешней проверки. После подтверждённого создания тоже не освобождай claim: новый step_id следующей завершённой сессии атомарно сменит поколение, а неизменившийся шаг останется защищён от повтора.

Не читай локальные базы Codex, журналы, токены, auth-файлы или списки процессов. Не архивируй, не продолжай и не отправляй сообщения существующим задачам. Не создавай обходной cron. Не раскрывай opaque project, thread, automation или lease ids в репозитории. Recent-снимок не доказывает состояние задач за его пределами, а проверка списка и create_thread не являются одной транзакцией; не утверждай абсолютную глобальную блокировку.
```

## Проверка регистрации

Перед активацией нужно подтвердить через штатные инструменты Codex, что:

- heartbeat прикреплён к диспетчерской задаче нужного клона;
- сохранённый локальный проект имеет точный ожидаемый корень;
- интервал равен пяти минутам;
- одноимённая автоматизация не продублирована;
- рабочее дерево чисто, а активная ветка имеет готовую валидную запись шага.
