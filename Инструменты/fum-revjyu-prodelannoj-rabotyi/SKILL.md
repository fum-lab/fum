# FUM Work Review

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) создаёт и проверяет сохранённые ревью проделанной работы. Она нужна, когда рабочий срез уже содержит несколько коммитов или заметное изменение [памяти FUM](../../Глоссарий/память-FUM.md), а результат ревью должен остаться не только в ответе агента, но и в репозитории.

Автоматизация собирает наблюдаемый Git-контекст, применяет устойчивую структуру отчёта и валидирует сохранённый Markdown-файл. Смысловая часть ревью остаётся ответственностью агента-ревьюера: скрипт не заменяет чтение diff, проверку связности требований и инженерное суждение.

## Когда использовать

Используй эту автоматизацию, когда нужно:

- провести ревью проделанной работы относительно выбранной базы, например `origin/master..HEAD`;
- сохранить находки, отсутствие находок, проверки и остаточные риски в `Ревью/`;
- сделать ревью повторяемым и сравнимым между рабочими сессиями;
- подтвердить, что отчёт ревью содержит ссылку на исходный запрос, автоматизацию, Git-срез и проверочный контур.

## Входы

Автоматизация принимает JSON-конфигурацию:

```json
{
  "title": "Ревью проделанной работы",
  "request_file": "Журнал/2026-07-01_17-03-14_MSK_проверить-работу/запрос.md",
  "automation_file": "Инструменты/fum-revjyu-prodelannoj-rabotyi/SKILL.md",
  "base_ref": "origin/master",
  "head_ref": "HEAD",
  "reviewed_at": "2026-07-01 17:03:14 MSK",
  "reviewer": "Codex",
  "scope": "Проверяется свежая работа относительно origin/master.",
  "review_focus": [
    "связь изменений с исходными запросами",
    "структурная связность рабочей сессии"
  ],
  "findings": [],
  "checks": [
    {
      "name": "fum-kompleksnaya-proverka-repozitoriya",
      "command": "python3 Инструменты/fum-kompleksnaya-proverka-repozitoriya/scripts/run-smoke-check.py --request Журнал/<имя-запроса>/запрос.md",
      "result": "прошло",
      "details": "Все локальные проверки прошли."
    }
  ],
  "residual_risks": [
    "Смысловая оценка физических аналогий остаётся исследовательской гипотезой."
  ],
  "decision": "Существенных замечаний не выявлено."
}
```

`request_file`, `automation_file`, необязательное `config_file` и каждое `findings[].file` указываются нормализованными POSIX-путями от корня репозитория. Абсолютные, выходящие из репозитория, URI-, home-, Windows/UNC- и символические формы отклоняются до записи отчёта. Поле `findings` может быть пустым, если существенных замечаний нет; в этом случае `decision` должен прямо фиксировать отсутствие существенных замечаний. Для замечаний используются поля `priority`, `status`, `file`, `line`, `title`, `details` и `recommendation`.

## Команды запуска

Сборка отчёта:

```bash
python3 Инструменты/fum-revjyu-prodelannoj-rabotyi/scripts/build-work-review.py build \
  --config Ревью/Автоматизации/<имя-конфигурации>.json \
  --output Ревью/<имя-отчёта>.md
```

Проверка готового отчёта:

```bash
python3 Инструменты/fum-revjyu-prodelannoj-rabotyi/scripts/build-work-review.py validate \
  --config Ревью/Автоматизации/<имя-конфигурации>.json \
  --document Ревью/<имя-отчёта>.md \
  --complete
```

## Что проверяется

Валидатор проверяет:

- заголовок отчёта;
- обязательные разделы `Граница ревью`, `Снимок Git`, `Что проверялось`, `Находки`, `Проверки`, `Остаточные риски` и `Сохранение результата`;
- ссылки на файл [исходного запроса](../../Глоссарий/исходный-запрос.md) и эту автоматизацию;
- упоминание выбранных `base_ref`, `head_ref` и итогового решения;
- наличие команды каждой заявленной проверки;
- явную фразу `Существенных замечаний не выявлено.`, если список находок пуст;
- отсутствие маркера `WORK_REVIEW_TODO` при проверке с `--complete`.

## Проверки автоматизации

Локальные тесты запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-revjyu-prodelannoj-rabotyi/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: автоматизация строит отчёт из Git-диапазона и конфигурации, валидирует полный результат и сообщает об отсутствующем обязательном разделе.

## Граница автоматизации

`fum-revjyu-prodelannoj-rabotyi` автоматизирует сохранение и структурную проверку ревью, но не делает скрытого LLM-анализа diff. Агент должен сам прочитать изменения, оценить риски, сформулировать находки или честно зафиксировать их отсутствие, а затем передать этот смысловой результат в конфигурацию.

Скрипт читает только локальный Git-срез, `git diff --check` и `git status --short --untracked-files=all`. Он не требует сетевых запросов, секретов и внешних сервисов. Если ревью зависит от внешнего CI, GitHub, приватной переписки или актуальных внешних фактов, это нужно явно внести в `checks` или `residual_risks`.
