# FUM Doc Aggregation

Этот навык описывает локальную [автоматизацию FUM](../../Глоссарий/автоматизация-FUM.md) для создания сводной статьи: одного Markdown-документа, который собирает несколько опорных статей [производной документации](../../Глоссарий/производная-документация.md) в общую карту темы.

Сводная статья не заменяет опорные документы. Она показывает общую структуру, границы темы, карту источников и маршрут поддержки, а детальные требования остаются в исходных материалах.

## Когда использовать

Используй эту автоматизацию, когда нужно:

- собрать разрозненные статьи `Документация/` в одну обзорную или архитектурную статью;
- создать новый входной документ по общей теме, которая уже раскрыта в нескольких местах;
- обновить существующую сводную статью после изменения набора источников;
- проверить, что сводная статья содержит ссылку на исходный запрос, все опорные документы и обязательную структуру.

Не используй эту автоматизацию для [описаний FUM для адресатов](../../Глоссарий/описание-FUM-для-адресата.md): для них закреплена отдельная схема `Описания/Автоматизации/построение-описания-FUM-для-адресата.md`.

## Входы

Автоматизация принимает JSON-конфигурацию:

```json
{
  "title": "Архитектура FUM",
  "topic": "архитектура FUM",
  "purpose": "Собрать разнесённые архитектурные требования в одну карту.",
  "request_file": "Запросы/2026-06-24_15-45-41_MSK.md",
  "automation_file": "Инструменты/fum-sborka-svodnoj-dokumentacii/SKILL.md",
  "source_documents": [
    {
      "path": "Документация/00-обзор-проекта.md",
      "role": "обзорный вход"
    },
    {
      "path": "Документация/05-модульная-архитектура-FUM.md",
      "role": "детальный слой темы"
    }
  ],
  "sections": [
    {
      "title": "Карта слоёв",
      "focus": "Показать, какие слои образуют общую тему."
    }
  ]
}
```

Минимальный набор источников - две опорные статьи. Пути указываются относительно корня репозитория.

## Процедура

1. Сохрани исходный пользовательский запрос в `Запросы/` по правилам `AGENTS.md`.
2. Выбери общую тему, цель сводной статьи и список опорных документов.
3. Создай JSON-конфигурацию для текущей сборки. Если сводная статья будет регулярно пересобираться, сохрани конфигурацию в [памяти FUM](../../Глоссарий/память-FUM.md) рядом с автоматизацией или в другом явно связанном месте.
4. Построй канонический каркас:

```bash
python3 Инструменты/fum-sborka-svodnoj-dokumentacii/scripts/build-doc-aggregation.py build \
  --config /path/to/config.json \
  --output Документация/<номер>-<тема>.md
```

5. Заполни смысловые разделы на русском языке кириллицей. Все существенные утверждения должны выводиться из опорных документов или быть явно помечены как интерпретация.
6. Удали все маркеры `DOC_AGGREGATION_TODO`.
7. Проверь завершённую статью:

```bash
python3 Инструменты/fum-sborka-svodnoj-dokumentacii/scripts/build-doc-aggregation.py validate \
  --config /path/to/config.json \
  --document Документация/<номер>-<тема>.md \
  --complete
```

8. Зафиксируй вызов автоматизации и результат проверки в файле исходного запроса рабочей сессии.

## Проверки

Локальные тесты автоматизации запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-sborka-svodnoj-dokumentacii/tests -p 'test_*.py'
```

Валидатор проверяет:

- заголовок сводной статьи;
- ссылку на исходный запрос;
- ссылки на все опорные документы;
- обязательные разделы паспорта, назначения, карты источников и поддержки;
- разделы, перечисленные в конфигурации;
- принцип, что сводная статья не заменяет опорные документы;
- отсутствие `DOC_AGGREGATION_TODO` при проверке с `--complete`.

## Граница автоматизации

Скрипт строит проверяемый каркас и контролирует структуру, но не подменяет смысловой синтез. Агент отвечает за чтение источников, выбор тезисов, устранение противоречий, ссылки на глоссарий и фиксацию открытых вопросов, если из источников следует неоднозначность.
