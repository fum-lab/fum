# Снимки индекса

Инструмент реализует первый ограниченный сегмент FUM-STEP-0155. Результат успешного чтения — подтверждённые сырые байты и структура входных манифестов. Поля `исполнение_разрешено` и `коммит_разрешён` всегда равны `false`. Команда `допустить` всегда отказывает, поскольку очередь доставки и связь отмены с допуском ещё не реализованы.

Использовать только канонический инструмент текущего checkout. Схема `fum.вход-снимка.1` отдельна от run-v4/report-v3. Реальный индекс FUM этим сегментом не принимался. Регистрация инструмента в общих реестрах, согласование правил и интеграция приёмочного контура остаются за координатором.

## Работа с входом

Все команды получают точный физический корень репозитория. Подкаталог, символическая ссылка вместо корня, сокращённый OID и имя ref вместо OID не принимаются.

- `scripts/снимки-индекса.py --корень-репозитория <корень> подготовить-дерево --ожидаемый-коммит <полный OID> --ожидаемая-ветка <refs/heads/...> --разрешить-запись-объектов` выполняет отдельную мутацию через `git write-tree`. Она может обновить cache-tree индекса, создаёт Git-объекты и не разрешает исполнение.
- `... ссылка --дерево <полный OID> --путь <точный относительный путь>` только читает и возвращает ссылку на blob с длиной и SHA-256.
- `... проверить --вход <файл> --конверт <файл> --реестр <каталог> --ожидаемый-коммит <полный OID> --ожидаемая-ветка <ref>` только читает. Запись, конверт и реестр находятся вне проверяемого checkout. Необязательный `--зависимости <файл>` принимает локальную карту точных путей gitlink на физические корни их репозиториев.
- `... зарегистрировать` принимает те же параметры, полностью проверяет вход и затем отдельно сохраняет его идентичность UUID в локальном реестре. Это не закрытие раунда и не допуск.
- `... экспортировать --источник <локальный JSONL> --задача <UUID> [--курсор <файл>] [--закрепить]` выдаёт локальный составной ответ с полями `экспорт` и `локальная_квитанция`. В дерево помещают только канонические байты поля `экспорт`; квитанцию оставляют вне публичного checkout. Флаг `--закрепить` воспроизводит прежнюю границу, даже если источник уже дописан.

Каноническое кодирование и создание конверта доступны в `scripts/канон.py`. Пример полного синтетического входа воспроизводит `tests/фикстуры.py`; он не обращается к индексу FUM. Все собственные манифесты описаны в [контракте](контракт.md).

## Проверка и профиль

Зависимости — Python со стандартной библиотекой и Git с `GIT_NO_LAZY_FETCH`; проверенная среда указана в журнальном профиле. Тесты работают без сети. Promisor-фикстура использует только собственный локальный временный remote и доказывает, что обычный Git действительно попытался бы загрузить отсутствующий объект.

Прямые проверки в FUM запускать через действующую `fum-otchyotyi-o-zapuskakh-proverok` со своим точным запросом, классом `адресная` и v4-историей. Дочерняя команда набора:

```bash
python3 -m unittest discover -s Инструменты/fum-snimki-indeksa/tests -p 'test_*.py' -v
```

Повторяемый профиль и сравнение тех же входных и выходных байтов:

```bash
python3 Инструменты/fum-snimki-indeksa/tests/профилировать.py --размеры 1,100,1000
python3 Инструменты/fum-snimki-indeksa/tests/профилировать.py --размеры 1,100,1000 --сравнить <предыдущий-профиль.json>
```

Профиль сохраняет версии Python/Git, хэши исходников, размеры фикстур, отдельное время подготовки и чтения, вложенные метки с исходом. Вложенные длительности не складываются. Сравнение измеряет конкретный сценарий с повторяющимися blob и не обещает такое же ускорение для всех репозиториев.

## Ограничения

Поддержан только первый раунд с `предыдущая_квитанция: null`. Вся область `.fum-приёмка` зарезервирована и запрещена во входе, включая Unicode-эквивалентные варианты. Исторические записи других раундов в этой области пока тоже не поддержаны.

Происхождение всех листьев объявляется как непрозрачные закреплённые байты без производящих рёбер. Обратные ссылки в известных схемах отвергаются; произвольный исходный код не исполняется и его содержательная независимость не объявляется доказанной. Производные узлы и генераторы требуют следующей версии.

JSONL-адаптер поддерживает ровно одно текстовое содержимое пользовательской команды с `content_item_kinds: ["user.text"]` и видимые ответы `response_item`. Он сохраняет повторы и порядок; `event_msg` не используется как дублирующий источник. Известные инструкции среды пропускаются. Неизвестные виды и составные сообщения, включая текст с изображением, дают отказ. Поэтому полный текущий диалог координатора с мультимодальной командой пока целиком не поддерживается. Отбор публикационно допустимого текста и обработка поздней отмены не автоматизированы.

Gitlink проверяется по точному commit/tree и полному манифесту сырых файлов отдельного репозитория. Живые грязные байты зависимости не используются и не объявляются проверенной материализацией. Вложенные gitlink, symlink и нестандартные режимы не поддержаны. Архив проверяется как непрозрачный blob, без распаковки.

Реестр защищает от повторного UUID с другими байтами только в переданном полном доверенном локальном каталоге. Удаление реестра, замена его целиком либо выбор пустого каталога не доказывают новую историю. Повторные проверки путей обнаруживают наблюдаемую подмену, но не создают атомарной защиты от обходящего протокол писателя. Раздельные чтения HEAD/ref также не дают атомарной гарантии. Материализация исполнения, конечная дельта, долговечное закрытие, публикация результата и точный коммит остаются следующими сегментами.
