# Адресное восстановление режимов публичных пар

[Восстановитель](scripts/восстановить_режимы_публичных_пар.py) выполняет отдельно разрешённое ROOT изменение ровно восьми tracked-файлов `Журнал/<папка>/запрос.md` либо `отчёт.md` из `0600` в `0644`. Байты, dev, inode, uid, nlink, size и mtime сохраняются; фактический ctime после `fchmod` записывается в свидетельство. Материалы, приватные входы, соседние файлы, каталоги, индекс, refs и Git-конфигурация не изменяются. Восемь файлов не образуют атомарную транзакцию.

Независимый ROOT сначала принимает код K, выбирает существующий H и точные восемь путей. Проверяемый W служит данными и отличается от физического checkout кода. K сверяется с существующими Git-blob и должен быть предком H; совпадение K/H само по себе не доказывает независимую приёмку. Перед каждой записью вновь проверяются десять физических исходников и ресурсов: восстановитель и девять файлов контура установщика. Текущий HEAD/ref, принятое дерево, индекс и конфигурация закреплены в плане. Этот инструмент не выбирает K, не принимает свою реализацию и не активирует состояние узла.

## Неизменяемые входы

API принимает селекторы `{путь, sha256}` точных сырых байтов. Выбор, план и факт завершения — обычные физические файлы `0400`, uid текущего пользователя, nlink=1, непосредственный родитель `0700` вне любого Git-предка. JSON разбирается с запретом повторных ключей. Каталог состояния заранее создаётся ROOT с режимом `0700` вне Git и должен быть пуст до первого эффекта.

Выбор `fum.выбор-восстановления-режимов-пар.1` имеет ровно следующие поля:

| Поле | Содержание |
| --- | --- |
| `схема` | `fum.выбор-восстановления-режимов-пар.1` |
| `координатор` | UUID ROOT, совпадающий с `CODEX_THREAD_ID` процесса |
| `корень` | Физический W |
| `ветка` | Полный ref `refs/heads/codex/...` |
| `принятый_коммит`, `принятое_дерево` | Полные OID существующего H и его дерева |
| `код` | Git-селектор `{коммит, путь, sha256}` ранее принятого K; путь этого восстановителя |
| `каталог_состояния` | Выбранный приватный каталог |
| `цели` | Упорядоченные восемь разных `{путь, blob, sha256}` |

Каждая цель — точный прямой публичный файл пары, Git `100644` с закреплённым blob и SHA-256, также совпадающий с stage0 индекса. Отсутствие пути, другой регистр, выход из checkout, ссылки, Git `100755`, лишняя или повторная цель закрывают допуск. Фактическая исходная цель должна иметь ровно `0600`, uid текущего пользователя и одну ссылку. Допуск материалов `0600/0644` из [установщика](установка-принятого-состава-журнала.md) сюда не переносится.

`построить_план(выбор)` только читает W. План `fum.план-восстановления-режимов-пар.1` сохраняет селектор и полную идентичность выбора, карту исходников, Git-снимок и восемь целей с полным `до`: dev, inode, st_mode, uid, nlink, size, mtime_ns, ctime_ns. ROOT сохраняет план новым приватным файлом `0400`. Поздние байты, режим, метаданные, равнобайтовая замена inode или staging требуют отказа до эффекта.

## Применение и неизвестный префикс

`применить(план, выбор)` берёт неблокирующий `flock` на неизменяемом файле выбора. Сначала перепроверяются все восемь исходных целей и публикуется `намерение.json` со схемой `fum.намерение-восстановления-режимов-пар.1`, SHA плана/выбора и PID. Публикация нового служебного имени использует существующий протокол установщика: новый временный файл `0600`, `fsync`, `link` в отсутствующее конечное имя, удаление известного временного имени, `fsync` каталога и readback. Неизвестное имя не заменяется.

Перед каждой целью проверяются Git, контур кода, все восемь файлов и полный точный префикс служебных имён, байтов и идентичностей. Цель открывается `O_RDONLY|O_NOFOLLOW`; `fstat` и `lstat` должны совпадать с полным `до`. Затем выполняются только `fchmod(fd, 0644)`, `fsync(fd)` и чтение результата. Сохранность байтов, inode и mtime сверяется отдельно от изменившихся mode/ctime.

После каждой цели публикуется `цель-N.json` схемы `fum.цель-восстановления-режимов-пар.1`: `схема`, `план_sha256`, `номер`, `путь`, `после`. После восьми целей публикуется `квитанция.json` схемы `fum.квитанция-восстановления-режимов-пар.1`, содержащая поля намерения и упорядоченные SHA восьми свидетельств. Перед возвратом выполняется полный readback целей, Git и служебного префикса.

Любая смерть или ошибка после возможного эффекта сохраняет фактический префикс. Повторный `применить` его не усыновляет и не продолжает. Смерть между `fchmod` и долговечным свидетельством цели оставляет неизвестный результат; совпадение режима или байтов его не разрешает. Нет автоматического отката, удаления временных свидетельств или восстановления на основе одного PID. ROOT отдельно рассматривает сохранённое состояние и разрешает следующий ограниченный шаг.

## Независимое завершение и свежий повтор

После реального `wait` писателя с кодом `0` наблюдатель сохраняет отдельный файл `fum.завершение-восстановления-режимов-пар.1` с четырьмя полями: `схема`, `процесс`, целочисленный `код_завершения: 0`, `квитанция_sha256`. Это факт внешнего наблюдателя. Сам писатель его не создаёт; наличие квитанции не заменяет успешного завершения последнего барьера.

`повтор(план, выбор, завершение)` запускается новым процессом. Он проверяет привязку завершения к PID и SHA квитанции, все восемь полных идентичностей после установки, исходники, Git, точный состав и содержимое служебного каталога. Неполный или чужой префикс, поздняя подмена свидетельства, режима либо inode вызывают отказ. Перед возвратом повторно замыкается readback свидетельств и завершения. Успешный результат содержит `повтор: true, записей: 0`; повтор не берёт замок, не синхронизирует и не пишет файлы.

Граница — кооперативный выбранный процесс и один писатель. Последовательные проверки не являются защитой от произвольного враждебного процесса того же uid или гарантией после отказа накопителя. Фактическую приёмку кода и восьми адресов выполняет ROOT.

## CLI и воспроизведение

CLI получает JSON-файл селектора через `--выбор`. Для команды `план` обязателен новый приватный `--выход`; stdout содержит селектор созданного плана. Для `применить` и `повтор` передаётся `--план` с JSON-селектором, для повтора также `--завершение`. Неизменяемые целевые файлы проверяются по закреплённым селекторам; файлы транспортных селекторов не дают новых полномочий.

~~~text
python3 -B <принятый-K>/Инструменты/fum-struktura-papok-zaprosov/scripts/восстановить_режимы_публичных_пар.py --выбор выбор-selector.json план --выход план.json
python3 -B <принятый-K>/Инструменты/fum-struktura-papok-zaprosov/scripts/восстановить_режимы_публичных_пар.py --выбор выбор-selector.json применить --план план-selector.json
python3 -B <принятый-K>/Инструменты/fum-struktura-papok-zaprosov/scripts/восстановить_режимы_публичных_пар.py --выбор выбор-selector.json повтор --план план-selector.json --завершение завершение-selector.json
~~~

[Тесты](tests/test_восстановления_режимов_публичных_пар.py) создают настоящие tracked-файлы `0600` через `NamedTemporaryFile` до Git-коммита H. Положительное применение и повтор выполняются разными PID. Негативы проверяют область, неизвестные режимы, ссылки, дрейф, частичную смерть, внедрённый отказ `fsync`, подмену свидетельств и квитанцию без успешного завершения. Проверка другого uid здесь не исполняется через привилегированный `chown`.

[Открытый профиль](tests/профиль_восстановления_режимов_публичных_пар.py) запускает три новых процесса на малой Git-истории, каждый с отдельными PID применения и повтора, SHA полного контура до/после и cProfile планирования. Подготовка и сохранение профиля исключены из внутренних замеров. В рабочей сессии обе команды вызываются через каноническую отчётную обёртку:

~~~text
python3 -B -m unittest discover -s Инструменты/fum-struktura-papok-zaprosov/tests -p test_восстановления_режимов_публичных_пар.py -v
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_восстановления_режимов_публичных_пар.py --выход профиль.json
~~~

Успех фикстур и профиля не доказывает изменения живых восьми файлов ROOT, повтор установки живого Журнала, ROOT9, переход состояния узла или интеграцию. После реального ремонта ROOT заново выбирает текущий исторический снимок для установщика.
