# Восстановимая установка принятого состава Журнала

[Установщик](scripts/установка_принятого_состава_журнала.py) устанавливает два производных файла в фиксированном порядке: `Индексы/состав-журнала.json`, затем `Индексы/навигация-журнала.md`. Он сохраняет байты, режимы и наблюдённую идентичность всего исторического `Журнал/**`, индекс Git, текущий ref и конфигурацию Git. Создание нового состава, приёмка кода, продвижение ветки и активация следующего режима Журнала выполняются отдельно.

В прежних режимах установщик исполняется из ранее принятого физического контура K; проверяемый checkout W служит данными. Для выбора .1 K должен быть строгим предком уже существующего H=A. Это техническая проверка происхождения, которая не доказывает смысловую приёмку кода. Независимый ROOT выбирает K, существующий Git-blob S и полный принятый H; установщик не выдаёт такой выбор и не выбирает будущий OID. S хранится в отдельном существующем коммите и описывает именно H. Отдельный явный локальный выбор ниже закрепляет текущие физические исходники W по независимому решению ROOT.

## Независимые входы

Выбор и план передаются каждый отдельным селектором с ровно двумя полями `путь`, `sha256`. Путь физический, абсолютный, без символических ссылок; файл обычный, принадлежит текущему пользователю, имеет одну ссылку и режим `0400`. Его непосредственный родитель имеет режим `0700` и находится вне любого Git-предка. SHA-256 относится к точным сырым байтам, а не к повторной сериализации JSON. Повторные ключи JSON отклоняются.

Выбор `fum.выбор-установки-состава-журнала.1` содержит ровно:

| Поле | Значение |
| --- | --- |
| `схема` | `fum.выбор-установки-состава-журнала.1` |
| `координатор` | UUID независимо выбирающего ROOT; совпадает с `CODEX_THREAD_ID` запуска |
| `корень` | Физический W, отличный от физического корня исполняемого K |
| `ветка` | Полный symbolic ref W |
| `принятый_коммит`, `принятое_дерево` | Полные OID существующего A=H и его дерева |
| `состав` | Git-селектор S: `коммит`, `путь`, `sha256` сырых байтов |
| `код` | Git-селектор ранее принятого установщика K с теми же тремя полями |
| `каталог_состояния` | Заранее созданный физический приватный каталог `0700` вне Git |

`код.путь` равен пути этого установщика. Перед проектными импортами фиксируются одиннадцать обычных физических исходников и ресурсов контура; их SHA-256, режимы и метаданные проверяются повторно у границ эффекта. Каждый исходник сверяется с байтами выбранного Git-коммита K. Общие P1, наполнитель, создатель коммитов, проверитель связности и правила этим кодом не изменяются.

План `fum.план-установки-состава-журнала.2` сохраняет полный селектор выбора, идентичность его файла, карту исходников, снимок Git, отпечаток полного исторического Журнала и ровно две цели. Для каждой цели фиксируются путь, `до`, `после`, `без_записи` и `идентичность_до`. Последняя содержит dev, inode, mode, uid, nlink, size, mtime и ctime исходной цели, либо `null` при её отсутствии. Во всех исходных и равных состояниях эта полная идентичность сверяется заново. Состояние имеет поля `существует`, `байты` в каноническом Base64, `режим`; отсутствие представляется `False`, `None`, `None`. Производный файл имеет режим `0644`. Точная равная цель объявляется заранее и сохраняет inode.

Планирование читает весь исторический Журнал, включая материалы, RAW и закреплённые исторические одиночные запросы. Лишний пустой каталог отклоняется. Допускается только штатный пустой каталог `материалы` полной принятой пары `запрос.md` и `отчёт.md`. Пустые материалы одиночного запроса не принимаются.

Обычный исторический файл `Журнал/<папка>/материалы/**`, принятый в Git как `100644`, допускает фактический режим **только `0600` либо `0644`**. Его байты должны точно совпадать с Git-blob; владелец — текущий пользователь, число ссылок — одна. Установщик сохраняет фактический режим, не вызывает для материалов `chmod` и не переписывает их. Полный исторический отпечаток включает фактический `st_mode`, uid, nlink, size, dev, inode, mtime и ctime. Изменение `0600↔0644` после плана, даже с возвратом прежнего режима, требует нового рассмотрения.

Публичные `запрос.md`, `отчёт.md`, `Журнал/README.md` и оба производных индекса остаются строгими `0644`; принятые Git-файлы `100755` — строгими `0755`. Другие режимы, специальные биты, символические и жёсткие ссылки не расширяют допуск. Восемь отдельно выявленных исторических публичных файлов `0600` исправляются только [адресным восстановителем](восстановление-режимов-публичных-пар.md) по независимому выбору ROOT до нового снимка установки. Его свидетельства не переиспользуются как старый исторический отпечаток.

Этот допуск относится к установщику. Производитель состава в `scripts/производственный_состав_журнала.py` сохраняет прежнюю строгую проверку `0644/0755`; состав готовится в свежем checkout с Git-режимами. Он не получает разрешения менять исторические `0600` живого ROOT.

Внутри каждого полного прохода используется [одноразовый строгий индекс путей](строгий-индекс-путей.md): общие родители перечисляются один раз при построении и заново при заключительной сверке. Чтение принятых байтов и число независимых проверок plan/apply/replay сохраняются. Индекс не переносится между проходами.

## Последовательность и восстановление

Публичные функции: `построить_план(выбор, ожидаемые)`, `применить(план, выбор, каталог)`, `восстановить(план, выбор, каталог, остановка)`, `повтор(план, выбор, каталог, завершение)`. Дополнительный callback отказа служит только фикстурам; штатный CLI его не предоставляет.

1. Установщик перепроверяет входы, историю, Git и совместный префикс двух целей. Допустимы только `до/до`, `после/до`, `после/после`, с учётом заранее равных целей. Обратная смесь и чужие байты сохраняются и вызывают отказ.
2. Процесс берёт неблокирующий `flock` на неизменяемом выбранном файле выбора. План связывает его имя и inode; копия выбора или замена файла с теми же байтами не сбрасывают замок. Другой каталог состояния также не принимается.
3. До записи целей публикуется неизменяемое `намерение.json`: схема `fum.намерение-установки-состава-журнала.2`, SHA плана и выбора, PID писателя. Полный служебный файл сначала записывается во временное имя с `fsync`; публикация отсутствующего конечного имени использует `link`, затем удаляется известное временное имя и синхронизируется каталог. Неизвестный конечный файл не заменяется.
4. Для каждой записываемой цели создаётся собственный временный файл, синхронизируются файл и его родительский каталог. До `rename` публикуется `цель-0.json` либо `цель-1.json` с долговечным свидетельством этого inode. Цели устанавливаются по порядку через проверенный временный файл, `rename`, чтение результата, повторные проверки и синхронизацию файла и родительского каталога. Уже равная цель не заменяется. Временный файл чужих байтов или лишний остаток уже установленной цели вызывает отказ.
5. После строгой проверки смешанного Журнала публикуется и читается `квитанция.json` схемы `fum.квитанция-установки-состава-журнала.2`. Она связывает SHA намерения, плана, выбора, исторического Журнала, два результата и упорядоченные SHA свидетельств целевых inode. Для заранее равной цели используется `null` и полная исходная идентичность. Поздняя подмена квитанции не даёт успеха.

Свидетельство `fum.идентичность-цели-журнала.1` имеет закрытые поля: `схема`, `намерение_sha256`, `план_sha256`, `создавшая_попытка_sha256`, `номер`, `после_sha256`, `идентичность`. Номер равен 0 либо 1; пути выводятся из плана, а не принимаются из свидетельства. Создавшая попытка должна принадлежать полной проверенной цепочке намерения и восстановлений. Идентичность содержит dev, inode, mode, uid, nlink, size и mtime синхронизированного временного файла. При установленном результате принимается только этот inode; чтение совпавших байтов не создаёт ему происхождение. Подмена самого индекса или временного файла с теми же байтами и режимом вызывает отказ.

Ctime временного файла не переносится как исходная Ctime после `rename`, поскольку операция может её менять. Этот срез закрывает подмену inode и проверяет байты, режим и остальные закреплённые метаданные. Он не обещает выявления произвольной враждебной правки того же inode с последующим восстановлением всех проверяемых свойств. Граница — кооперативный выбранный процесс и один писатель.

Это восстановимая последовательность. Два `rename` не дают общей POSIX-атомарности пары. Установщик не откатывает неизвестное позднее состояние и не освобождает живого писателя по тайм-ауту.

После незавершённой попытки обычное применение запрещено. ROOT сначала действительно дожидается завершения последнего процесса и независимо сохраняет вход `fum.остановка-установщика-журнала.1`: `схема`, `процесс`, целочисленный `код_завершения`, `намерение_sha256`. Это свидетельство наблюдателя, а не доказательство, которое создаёт установщик. Восстановитель дополнительно требует свободный замок и отсутствие прежнего PID; переиспользованный PID закрывает допуск.

Каждый восстановитель до записи целей публикует новую последовательную запись `восстановление-NNNNNN.json` схемы `fum.попытка-восстановления-журнала.1`. Запись содержит собственный PID, SHA неизменного намерения, SHA предыдущей попытки и отдельно выбранное свидетельство остановки. Весь упорядоченный префикс проверяется. После смерти восстановителя требуется остановка именно этого последнего PID; свидетельство первоначального писателя больше не подходит.

Поддерживаются проверенные целые префиксы намерения, последовательных попыток, опубликованных свидетельств целевых inode, связанных с ними временных файлов, установленных целей и квитанции. Свидетельство без сохранившегося временного inode при исходной цели не разрешает создать новый inode. Смерть после создания временного файла, но до публикации его свидетельства, оставляет неизвестный префикс: он сохраняется и закрывает автоматическое восстановление. Такой файл не усыновляется по совпавшим байтам. Смерть после `link` опубликованного намерения, попытки, свидетельства цели или квитанции, до удаления известного временного имени, оставляет два имени одного inode; явное восстановление проверяет этот точный префикс и завершает его синхронизацию. Обрезанное, неизвестное или отдельно подставленное временное служебное содержимое сохраняется и закрывает допуск. Этот контракт не обещает восстановления произвольной повреждённой записи либо поведения после отказа накопителя.

## Свежий повтор

Наличие квитанции само по себе не подтверждает успешный последний барьер долговечности. После фактического `wait` писателя с кодом `0` ROOT независимо сохраняет `fum.завершение-установщика-журнала.1` с ровно шестью полями:

| Поле | Значение |
| --- | --- |
| `схема` | `fum.завершение-установщика-журнала.1` |
| `процесс`, `код_завершения` | PID последней попытки и целое `0` |
| `намерение_sha256`, `квитанция_sha256` | SHA точных служебных байтов |
| `последняя_попытка_sha256` | SHA последней записи восстановления, либо самого намерения при отсутствии восстановлений |

Повтор из нового процесса проверяет это свидетельство вместе с текущими исходниками, выбором, планом, всей цепочкой попыток, обоими результатами и полным Журналом. Он не берёт замок, не создаёт новый intent, не синхронизирует и не записывает файлы. Старое успешное завершение не разрешает повтор после новой попытки восстановления. При отказе `fsync` существующая квитанция требует явного восстановления с повторным барьером, затем нового независимо наблюдённого успешного завершения.

## CLI и воспроизведение

Запуск производится из физического W, используя файл из принятого K. Для действия `план` передаются `--выбор`, `--хэш-выбора`, новый `--план`, `--ожидаемые`, `--хэш-ожидаемых`. Для остальных действий обязательны отдельные `--план`, `--хэш-плана`, `--каталог-состояния`. Восстановление дополнительно получает `--остановка`, `--хэш-остановки`; повтор — `--завершение`, `--хэш-завершения`. Неполные и неизвестные входы отклоняются.

[Тесты](tests/test_установки_принятого_состава_журнала.py) создают отдельные настоящие Git-истории K/H/S. Смерти проверяются настоящим `SIGKILL` и `wait`; отказы дополнительно внедряются в адресных границах. [Профиль](tests/профиль_установки_принятого_состава_журнала.py) использует три новых процесса, отдельные PID установки и повтора, исключает подготовку фикстуры и сохраняет SHA полного контура до и после.

~~~text
python3 -B -m unittest discover -s Инструменты/fum-struktura-papok-zaprosov/tests -p test_установки_принятого_состава_журнала.py -v
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_установки_принятого_состава_журнала.py --вариант после --выход профиль.json
~~~

В рабочей сессии эти команды вызываются через каноническую отчётную обёртку. Успех временных фикстур не доказывает установку живого Журнала, приёмку ROOT, интеграцию или готовность следующего режима.

## Отдельный выбор для двух источников

Для S.2 используется `fum.выбор-установки-состава-журнала.2`. Вместо `принятый_коммит` и `принятое_дерево` он содержит упорядоченные `источники: [{коммит: L, дерево: TL}, {коммит: R, дерево: TR}]`. Остальные прежние поля сохраняются; добавляются `корень_кода` и приватный SHA-селектор `приёмка_кода`. Источники S должны точно совпадать с этим порядком. W уже находится в фазе слияния: HEAD=L, MERGE_HEAD=R.

ROOT заранее принимает отдельный физический K. Он должен быть предком либо самим коммитом хотя бы одного источника; происхождение из правой ветки допустимо. K не выбирается по ещё не созданному merge-коммиту. Его физический HEAD, весь прежний закреплённый набор исходников и ресурсов сверяются с выбранным K. W и K различаются.

Приватный документ `fum.ROOT-приёмка-кода-установщика-слияния.1` содержит ровно `схема`, `координатор`, `код`, `корень_кода`, `исходники`. Его байты отдельно закрепляются SHA в выборе; значения должны точно совпадать с выбранным ROOT, K и загруженным набором одиннадцати файлов. Это адресное заявление о предварительной приёмке, которое формирует ROOT после проверок, а не автоматически полученное разрешение из Git ancestry.

План `fum.план-установки-состава-журнала.3` сохраняет прежние поля. Снимок Git дополнительно включает единственный родитель MERGE_HEAD, SHA и фактическую идентичность этого файла. Полный исторический слой равен точному объединению обоих Журналов. План `.2` и выбор `.1` не взаимозаменяемы с новыми версиями.

Установка, остановка, восстановление и свежий повтор сохраняют прежний порядок и форматы свидетельств. SHA плана и выбора закрепляют новый сценарий во всех фазах. [Тесты двух источников](tests/test_установки_двух_источников_журнала.py) используют K=R, который не является предком L; проверяют точные конечные индексы, дрейф источников и закрытого RAW, неверную приёмку K, промежуточную смерть и восстановление без изменения исторического Журнала.

## Явный локальный выбор одного принятого H

`fum.выбор-локальной-установки-состава-журнала.1` предназначен для отдельно
выбранных ROOT текущих локальных байтов. Физический W обязан совпадать с
физическим корнем исполняемого установщика. HEAD, полный symbolic ref и дерево
остаются уже выбранными Git H/ref/tree. Текущие байты установщика могут отличаться
от Git H: их независимый выбор не объявляет их ранее принятым Git-кодом K.
ROOT сохраняет выбор отдельным приватным входом 0400/0700 и передаёт его SHA.
Установщик не создаёт независимый выбор ROOT самостоятельно.

Новый выбор содержит ровно следующие поля:

| Поле | Значение |
| --- | --- |
| `схема` | `fum.выбор-локальной-установки-состава-журнала.1` |
| `координатор` | UUID ROOT, равный `CODEX_THREAD_ID` запуска |
| `корень`, `ветка` | Физический W, совпадающий с корнем кода, и его полный ref |
| `принятый_коммит`, `принятое_дерево` | Точные полные OID существующего HEAD H и его дерева |
| `состав` | Отдельный Git-селектор S с точными `коммит`, `путь`, `sha256`; его байты описывают именно H |
| `каталог_состояния` | Заранее выбранный приватный каталог 0700 вне Git |
| `локальные_исходники` | Точный словарь относительных путей и SHA-256 текущих физических исходников |

Словарь содержит ровно тринадцать путей `ЛОКАЛЬНЫЕ_ИСХОДНИКИ`: прежние
одиннадцать `ИСХОДНИКИ` и два достижимых исполняемых файла:

- `Инструменты/fum-pereimenovaniye-fajla-s-obnovleniyem-ssyilok/scripts/pereimenovatj-fajl-s-obnovleniyem-ssyilok.py`;
- `Инструменты/fum-proyektnyiye-fajlyi/scripts/project_files.py`.

Они достигаются при проверке ссылок исторического Журнала:
`проверить_смешанный → _validate_navigation → _markdown_targets → _link_tools → project_files`.
Каждый закреплённый файл имеет режим 0644, одну ссылку и физический путь.
Все тринадцать снимков байтов и идентичности получаются до начальных проектных
импортов. Два дополнительных снимка сохраняются отдельно: отсутствие или любой
отказ захвата оставляет недоступное состояние, которое запрещает local даже
при позднем появлении файла. Legacy .1/.2 не используют эти дополнительные
снимки и сохраняют прежние одиннадцать пинов. Local не дозахватывает зависимости
после импорта; на поздних границах свежо сверяет все тринадцать физических
состояний. Пропущенный либо лишний путь, неверный SHA, подмена узла, байтов или
режима, а также отсутствие исходного снимка отклоняются.

Модуль `переиспользование_представлений_основы.py` не исполняется установщиком,
не требуется и не закрепляется. Дочерний допуск не передаётся, поэтому lazy-import
consumer из `проверить_смешанный` недостижим; его child-only зависимости не расширяют
local-набор. Прежний consumer и шаблоны остаются среди консервативных одиннадцати
ресурсов ради сохранения старого набора. Присутствие reuse-файла не выбирает режим.

Поле `код` отсутствует. Git-K/ancestry для этого явного режима заменены точным
независимым выбором текущих байтов ROOT. Отдельный носитель S и полный исторический
Журнал продолжают проверяться по Git. Неизменяемость RAW, фактических режимов,
индекса, конфигурации и ref, а также exact before/after обеих целей сохраняется.

План имеет схему `fum.план-локальной-установки-состава-журнала.1` и прежние поля:
полный селектор выбора и его идентичность, карту тринадцати исходников, отдельные `локальные_идентичности`, Git-снимок,
исторический отпечаток и две точные цели. Карта идентичности содержит для каждого
исходника ровно dev/inode/mode/nlink/size/mtime_ns/ctime_ns, закреплённые планом
при планировании. Новый apply/recover/replay свежо сравнивает их с текущими
физическими узлами: замена теми же байтами между процессами отклоняется. Старые
планы .2/.3 этой карты не получают. Существующие CLI `план`, `применить`,
`восстановить`, `повтор` и их аргументы сохраняются; файл CLI берётся из самого
физического W. Новый явный выбор подаётся через прежние `--выбор` и
`--хэш-выбора`. План, замок, intent, свидетельства, поздние сверки, независимые
`wait`, восстановление и повтор без записи используют тот же протокол.

Старые выборы .1/.2 сохраняют одиннадцать пинов и свои требования к Git K и
разделению W/кода. Им не нужен отсутствовавший reuse-файл. Ошибка старого выбора
не включает локальный режим; неизвестная схема, лишнее локальное поле или план
другого поколения отклоняются. Локальный режим для двух источников этим дополнением не вводится.

[Отдельные локальные тесты](tests/test_локальной_установки_принятого_состава.py)
используют малую настоящую Git-фикстуру: отдельный S, отличающиеся от H локальные
байты кода, планирование и применение, новый процесс повтора без записи, неверные тринадцать SHA,
неполный и лишний набор, поздний дрейф кода/режимов/H/ref/S/RAW/цели и прерывание
между целями с восстановлением. Это лабораторные проверки, не live-установка
Журнала ROOT и не приёмка входящей ветки.

## Обновление при своей открытой паре

Явный локальный выбор `fum.выбор-локальной-установки-состава-журнала.2`
добавляет обязательное поле `открытая`: исходный проверенный `план` P.1 и
упорядоченный снимок `файлы` всех текущих файлов и каталогов своей пары,
включая материалы. Запись снимка содержит путь, тип, режим и SHA-256 файла
(`null` для каталога). `снять_открытую_пару` выполняет только чтение и
не выдаёт права установки. ROOT закрепляет полученные байты независимым
неизменяемым выбором до планирования.

План пары должен принадлежать текущему ROOT и как задаче, и как писателю.
Проверяются его основание в Git и происхождение обеих карточек. Хэши исходных
шаблонов P.1 сохраняются; заполненные текущие байты закрепляются новым снимком.
Ни один путь открытой области не может уже входить в принятый H. Закрытый
Журнал проверяется полностью, а собственная открытая область — отдельно
против снимка. Лишние пути, изменения байтов, режима, владельца либо узла
отклоняются. План установки дополнительно закрепляет полные метаданные
открытой области; все границы apply/recovery/replay повторяют сравнение.

План имеет схему `fum.план-локальной-установки-состава-журнала.2`.
Цели остаются прежними: только состав и навигация. Открытая пара не переносится,
не переписывается и не включается в принятый состав. Успешная установка не
означает закрытия этапа. Прежние схемы не принимают новое поле и не получают
исключения для открытой пары. Один писатель обязателен также во время установки.

[Проверки открытой пары](tests/test_установки_состава_при_открытой_паре.py)
охватывают заполнение штатным наполнителем, сохранение всей истории,
поздний дрейф, прерывание между целями и повтор из нового процесса.

## Ранняя сверка покрытия перед полной подготовкой

[Читающий модуль](scripts/раннее_покрытие_журнала.py) сравнивает пути закрытых
запросов и отчётов выбранного Git HEAD с независимо выбранным S.1. Он проверяет
SHA выбранного blob и HEAD до и после чтения. Добавленная закрытая пара выявляет
устаревший состав до дорогой полной подготовки; изменение только кода не требует
перевыпуска S. Незакоммиченная открытая пара в это сравнение не входит.

Результат явно содержит `полная_проверка: false`: совпадение путей не доказывает
полноты схемы, байтов карточек, материалов, полномочий или чистоты живого дерева.
После этой диагностики продолжаются прежние полные проверки. В последовательности
ROOT ранняя сверка запускается до обновления recency и подготовки Создателя.
[Регрессии](tests/test_раннего_покрытия_журнала.py) различают изменение кода,
новую закрытую пару, собственную открытую пару и поздний дрейф HEAD.
