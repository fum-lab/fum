# Строгий индекс путей Журнала

Частичная композиция исправления301 с принятым допуском344 сокращает повторное перечисление и нормализацию общих родителей внутри одного полного прохода. Он предназначен для проверки малого открытого корпуса; применение к живому ROOT требует отдельной приёмки.

`ИндексПутей` полностью перечисляет непосредственный корень, поддерево `Журнал` и непосредственных детей `Индексы`. Для каждого родителя сохраняются точные имена и все группы NFC/casefold. Метаданные закрепляются в управляемой области; корневые соседи вроде `.obsidian` остаются только именами, поэтому локальное изменение `graph.json` не блокирует проход. Поиск продолжает проверять физический корень, каждый компонент, символические ссылки и промежуточные типы прежним кодом. Перед каждым обращением сверяется живая идентичность родителя. Перед успешным возвратом независимо перечитываются все имена и закреплённые метаданные, включая ранее пройденные ветви и пустые каталоги. Наблюдённый дрейф закрывает проход отказом.

Каждый `проверить_журнал` и `проверить_смешанный` получает новый одноразовый экземпляр. Объект закрывается и при отказе; перенос между plan/apply/replay отсутствует. Все исходные проверки H/W, байтов, владельца, inode, nlink, режимов, source pins, Git/ref/index/config и поздние барьеры сохраняются. Новый исходник добавлен в закрепляемый исполняемый контур установщика. Прямой вызов прежнего `точный_путь` без индекса сохраняет полный прежний алгоритм без early return.

Это кооперативная проверка наблюдаемых имён и метаданных. Между последним наблюдением и действием остаётся прежняя граница TOCTOU; абсолютная атомарность ФС не заявляется. Кэш не доверяет только прежнему положительному исходу и не заменяет следующие независимые полные проходы.

## Внешние пути одного прохода

По [постановке358](https://github.com/fum-lab/fum/issues/358) явный параметр `внешние_родители=True` распространяет индекс на родителей действительно проверяемых путей вне Журнала. Каталог включается при первом обращении, общие предки используют уже снятые группы имён. Соседние поддеревья рекурсивно не обходятся; их содержимое не становится дополнительным входом. Метаданные закрепляются только у посещённых компонентов. Прежний режим без параметра сохраняет прежнюю область.

Режим подключён отдельно в раннем W-проходе, инвентаре Markdown, пофайловой проверке Markdown, поздней сверке снимков и полном доказательстве. Каждый получает собственный индекс; заключительное независимое перечисление, текущие FD-чтения и Git-проверки сохранены. Отсутствующая цель остаётся допустимой, когда вызывающий код не требует её существования. Первичный отказ не заменяется ошибкой заключительной диагностики.

[Адресный корпус](tests/test_внешнего_индекса_путей.py) считает и вызовы перечисления, и фактически потреблённые имена на ширине n/2n/4n. В одном широком каталоге новый проход перечисляет имена дважды: при включении и при независимой заключительной сверке. Отдельно проверяются общие широкие предки, реальные ранний W и proof на малой Git-фикстуре, поздний дрейф, коллизии, закрытие индекса и локальное состояние. Эти проверки доказывают устранение повторных перечислений в данном участке; ускорение полного рабочего цикла измеряется отдельно.

```text
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/test_внешнего_индекса_путей.py
```

## Сложность и границы

При N узлах и Q проверяемых путях глубиной до D проход стоит O(Σ dᵥ log dᵥ + QD), где dᵥ — число детей каталога; отдельно сохраняется чтение обязательных байтов. Память индекса — O(N + U) записей и строки путей, где U — число различных имён. Это оценка участка обхода, а не всего Creator.

Внешний допуск344 и его поздняя пересверка сохраняются. Отдельная проверка меняет уже существующую RAW открытой пары во время прохода: изменение тех же JSON-данных добавлением пробела обязано дать отказ по дрейфу. Число независимых проходов установщика остаётся прежним.

## Воспроизведение

Нужны Python, Git и два отдельных полных checkout точного C580 `173ecb9c5c69391bc4d83520ed6cbb3c29be865d`. Первый остаётся неизменным. Во втором заменяются только три предметных исходника из проверяемого LAB-среза. Оба клона имеют собственный Git-admin; остальные зависимости берутся целиком из C580. Скрипт проверок запускается в свежих процессах, а Git-фикстуры создаёт в приватных временных каталогах. Сам кандидат не становится принимающим кодом контрольной точки.

Через штатную отчётную обёртку своей v4-сессии запустите:

```text
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/test_строгий_индекс_путей.py --основа <полный-C580> --код <отдельный-кандидат>
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_строгого_индекса_путей.py --основа <полный-C580> --код <отдельный-кандидат> --выход <новый-профиль.json>
```

Для различающего RED добавьте к первой команде `--только-red` и выберите C580 также как `--код`. Успешный прежний путь должен не пройти ограничение повторного listing. Обычный набор сравнивает положительные и отрицательные исходы, проверяет дрейф, закрытие индекса, четырнадцать apply-проходов, mixed guard и два независимых replay-контекста. Исключение, неизвестная основа или ненулевой код работника требуют просмотра ошибки; результата не следует считать GREEN.

Обычный `unittest discover` без аргументов выполняет две автономные проверки самого индекса и явно пропускает четыре парных Git-сценария, которым нужны два полных контура. Он не подменяет показанный выше явный запуск без пропусков.

Профиль выполняет три свежие пары одного удержанного корпуса, отдельно сохраняет setup, wall/CPU, память и счётчики listing/normalization/stat/bytes/Git. Измерения включают диагностические накладные расходы. JSON фиксирует SHA корпуса и кода до/после; вложенные времена не суммируются. Вывод относится только к малому корпусу, а отсутствие выигрыша остаётся допустимым результатом.
