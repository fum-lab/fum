# Перейти к человеческому происхождению собственной пары

[Отдельная процедура](scripts/переход_происхождения_пары.py) переводит собственную открытую пару P.1, в которой раздел «Текст запроса» содержит первоначальное агентское поручение, к независимо выбранным человеческим оригиналам ROOT. Агентский текст сохраняется дословно в событии отчёта с ролью `наблюдение`, UUID исполнителя и точными байтовыми границами и SHA исходной native строки. Непустой набор оригиналов произвольной длины сохраняет порядок, LF, ограды и одинаковые тексты с разными экземплярами.

Это отдельный версионный интерфейс. Специализированный [производитель состава Журнала](производственный-состав-журнала.md), строитель P.1, шаблоны, наполнитель, Creator, состав S и закрытая история не меняются. Из принятого P.1 используется штатный рендер тела исходного запроса; формат независимой пары поверх прежней пары не устанавливается.

## Независимый выбор

Вход `fum.вход-перехода-происхождения-пары.1` содержит ровно девять полей:

- `схема`, `корень`, `исполнитель`, `координатор`, `ветка` — физический собственный checkout, native UUID и полный ref;
- `нативный_источник` — физический native JSONL исполнителя;
- `журнал` — точная собственная папка `Журнал/<время>_<название>`;
- `основа` — `коммит` и `дерево` исходного HEAD;
- `выбранное_поручение` — независимо выбранный опубликованный ACT: `координатор`, `исполнитель`, `коммит`, `путь`, сырой `sha256`.

Тот же выбор ACT передаётся отдельным файлом. Применяется прежний читатель обычной дочерней контрольной точки `.7`: он сверяет реальный UUID среды, HEAD/ref, единственное дерево ветки, native birth и firstprompt. Его контракт требует область собственного журнального каталога, включая адрес истории модели; переход историю модели не пишет. Полномочия на S и его индексы не нужны. Весь остальной фактический dirty-состав также проверяется по ACT.

Отдельный выбор `fum.выбор-перехода-происхождения-пары.1` содержит ровно `схема`, `источники`, `до`, `подготовка`, `готовность`, `квитанция`, `форма`, `поручение`.

`источники` передаются штатному читателю `корневые_команды`: каждый содержит `путь`, корневую `задача`, непустой упорядоченный массив `экземпляры`, точную `граница_снимка` и необязательный приватный `кэш`. Граница содержит `граница`, `sha256` и весь список `неоднозначные_экземпляры`. Принимаются только подтверждённые человеческие оригиналы выбранного ROOT. Неверный порядок, повтор одного ID, подмена исходника или происхождения закрывают допуск. Тексты одинаковых отдельных сообщений не сворачиваются.

`до` содержит ровно два элемента в порядке `запрос.md`, `отчёт.md`: `путь`, сырой `sha256`, целочисленный `режим` равный `420` (`0644`). Выбор полных прежних байтов не выводится из предполагаемого префикса. `форма` явно равна `буквальная` либо `маркированная`. Первая требует только точный native literal в штатной ограде P.1; вторая требует точный текст `Первоначальное агентское поручение ROOT (не сообщение человека):`, два LF и тот же literal. Любой другой текст запрещён, даже при заново выбранном SHA пары.

`поручение` содержит `источник`, `позиция`, `префикс`, `текст_sha256`. Источник совпадает с native JSONL входа; `позиция` содержит `начало`, `конец`, `sha256` точной строки первоначального `response_item/function_call_output/create_thread`. `префикс` содержит `граница` и `sha256` всего завершённого native префикса до конца этой строки. Штатный reader сверяет literal и отправителя с опубликованным ACT; отдельно сверяются сырые span и префикс. Внешний похожий текст или иная транспортная роль не принимаются.

Последние три операционных пути обозначают ещё отсутствующие подготовку Creator, READY и квитанцию. Они различаются, находятся вне Git в физических приватных каталогах `0700`. Любой существующий результат запрещает переход. Пара должна отсутствовать в HEAD; отчёт должен быть открыт, без возобновления, снимка и активного RAW. Символические и жёсткие ссылки, чужой источник, неверные режимы и занятый индекс запрещены.

## План и две замены

Операционные JSON и план находятся вне любого Git checkout: обычные физические файлы владельца, единственная жёсткая ссылка, режим `0600`, родитель `0700`, уникальные JSON-ключи. CLI выполняется из собственного физического checkout. Выбранный SHA перехода передаётся отдельно:

```sh
python3 -I -S -B Инструменты/fum-struktura-papok-zaprosov/scripts/переход_происхождения_пары.py подготовить \
  --вход <вход.json> --выбранное-поручение <ACT.json> \
  --выбранный-переход <выбор.json> --выбор-sha256 <сырой-SHA-выбора> \
  --план <новый-приватный-план.json>
```

Создание плана использует `O_EXCL`, полную запись, `fsync` файла и каталога, полный readback. Схема `fum.план-перехода-происхождения-пары.1` закрепляет все входы, точные прежние байты, два новых файла, исходные команды и агентское событие, привязку ACT и защищённые индекс/config по байтам, режиму, inode и mtime. План не разрешает сам себя: вызывающий ROOT отдельно выбирает код, входы и сырой SHA плана.

```sh
python3 -I -S -B Инструменты/fum-struktura-papok-zaprosov/scripts/переход_происхождения_пары.py применить \
  --вход <вход.json> --выбранное-поручение <ACT.json> \
  --выбранный-переход <выбор.json> --выбор-sha256 <сырой-SHA-выбора> \
  --план <план.json> --план-sha256 <сырой-SHA-канонического-плана>
```

Применение заново строит полный план из независимых входов, сверяет канонические байты и оба прежних выхода. Перед каждой заменой повторяет весь допуск и ожидаемое состояние пары. Временный файл полностью записывается и синхронизируется; после отдельного `replace` синхронизируется каталог. Меняются ровно собственные запрос и отчёт. Результат полностью читается, исходные человеческие тексты сверяются штатным Creator reader, агентское событие должно присутствовать ровно один раз.

Замены двух файлов не образуют общую транзакцию. Требуется один фактический писатель checkout; между последней сверкой и системным `replace` нет файлового CAS. Поздние чужие байты, выявленные проверками, сохраняются. В частности, изменение отчёта после первой замены запроса даёт частичный отказ с числом подтверждённых замен и признаком возможного эффекта. Широкого отката нет; смешанный или неизвестный результат запрещает автоматическое доведение и требует отдельного восстановления и решения ROOT.

При точном совпадении обоих результатов повтор возвращает `записано: 0`. Readback и заключительный контекст проверяются также в этом пути. Байты, режимы, inode, mtime, индекс, refs и config сохраняются; второй записи события нет. Повтор подтверждает наблюдаемое состояние, а не историческую установку. Следующее штатное наполнение сохраняет происхождение пары.

## Воспроизведение и граница доказательства

[Тесты](tests/test_перехода_происхождения_пары.py) переиспользуют принятую временную Git/native фикстуру только при подготовке. Флаг `--исходная-специализация` запускает ровно три реальных RED прежнего интерфейса: жёсткое число два, S-область и маркированный прежний ввод. Обычный запуск проверяет новый helper, N=1/3/4, повтор в новом PID, полные снимки неизменности, поздний чужой отчёт, неизвестный исход, отказы и совместимость штатного наполнителя в отдельном процессе.

```sh
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/test_перехода_происхождения_пары.py -v
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_перехода_происхождения_пары.py --выход <новый-профиль.json>
```

[Профиль](tests/профиль_перехода_происхождения_пары.py) содержит конечный исполняемый состав: 43 Python-файла helper и отдельный профильный entry, два P.1 ресурса и закреплённый bootstrap движка. В трёх новых `-I -S -B` PID принятый движок захватывает точные Git blobs временного K, проверяет рабочие байты до и после, закрыто связывает обычные и динамические imports и журналирует фактические `compile/exec` с raw SHA/blob/mode. Необъявленный проектный импорт отказывает. План, две замены и повтор измеряются раздельно; setup и fixture-коммиты исключены. Кэш ОС не очищается. Отказ прежней версии не даёт сравнимого успешного времени; ускорение не заявляется.

Все прямые проверки рабочей сессии запускаются через штатную отчётную обёртку. Приведённые команды обозначают внутренний воспроизводимый вызов. Для измерений используется Python 3.14; точная версия, PID и хэши сохраняются в отчёте и профиле.

Кодовая поставка и временные фикстуры не означают приёмки рабочего K/D, применения к реальному получателю, интеграции в `fuma`, Stop, архивации, ROOT9/R1 или state2. ROOT отдельно принимает точный код и readonly предложение, выбирает актуальный ACT, пару и источники, затем разрешает фактический эффект.
