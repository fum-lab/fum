# Частный архив завершённого этапа

Процедура сохраняет целиком собственный неопубликованный этап Журнала J1 вне Git, затем создаёт новый публичный этап J2 из отдельно выбранных человеческих команд. Оригиналы запроса, отчёта, RAW и проверок остаются в неизменном архиве. Новый этап получает пустую историю проверок; прежние записи не перепривязываются.

Первый срез принимает только целиком неотслеживаемый J1, последний в каноническом Журнале, и более поздний, полностью отсутствующий J2. Нужны собственные ветка `codex/…`, native UUID, закреплённый ACT с точным префиксом J1 и разрешёнными публичными целями, терминальная история проверок и отдельное подтверждение ROOT, что этап завершён и писателей нет. Активный, чужой, исторически отслеживаемый, неизвестный или неподдержанный случай закрывает допуск до переноса.

## Подготовка входов

Запускайте [архиватор](scripts/частный_архив_этапа.py) из своего физического checkout с явным `CODEX_THREAD_ID`. Нужны Python 3.10+ и POSIX. Зависимость — целый принятый технический контур этого же монорепозитория на коммите `b2ae5245fb6607f9ebff2c6f868edc8b92336cda`. Передавайте отдельный физический checkout этого коммита в `код.корень`; пользовательские данные остаются в `корень`. Инструкции чужого checkout не загружаются. Проверяются Git-байты исполняемых исходников и машинных ресурсов `Инструменты/`; Markdown, включая чужие `SKILL.md` и `AGENTS.md`, не открывается даже для SHA. Исходники импортируются из захваченных проверенных байтов без bytecode, план закрепляет также SHA самого архиватора. Массового переноса K в свою ветку нет.

Приватные вход, план, выбор и вывод CLI храните вне любого Git в собственном каталоге `0700`. JSON-файлы с приватными адресами должны иметь режим `0600`. Предок с `.git`, bare Git либо `HEAD + commondir`, символическая ссылка и другой владелец недопустимы. Архив — отсутствующий путь непосредственно под таким каталогом на той же файловой системе, что и J1. Публичные артефакты содержат только безопасные производные данные.

Вход схемы `fum.частный-архив-этапа.1` содержит ровно:

| Поле         | Содержание                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `схема`      | `fum.частный-архив-этапа.1`                                                                          |
| `корень`     | Физический собственный checkout                                                                     |
| `источник`   | Относительный `Журнал/<J1>`                                                                         |
| `архив`      | Новый физический приватный путь вне Git                                                             |
| `код`        | Объект `корень`, `коммит` принятого технического контура                                              |
| `поручение`  | Штатный direct ordinary maker `.7`; сам архиватор не придумывает машинные полномочия                 |
| `источники`  | Штатный выбор ROOT-команд: путь, задача, экземпляры, граница снимка, при наличии свежий приватный кэш |
| `новый`      | Объект `основа`, `метка`, `заголовок` для штатного `start`                                             |

Независимый selector ACT передаётся вторым входом отдельно от его копии в maker. Он выбирается координатором по реальному native literal и Git-blob. Штатный генератор дочернего поручения может подготовить maker для поддержанного initial; direct `.7 + ACT.1` также является существующим публичным API. Архиватор вызывает его читатель, не создаёт ACT, UUID или поля готовности. Переход публичного Журнала `.2` меняет отдельное событие открытого отчёта и сам по себе не архивирует J1; при необходимости его применяют отдельно к новому открытому этапу до готовности.

Человеческие команды выбирает ROOT независимо: исходный UUID, exact ID, raw-диапазон, SHA и порядок. Архиватор использует штатный `корневые_команды`; служебное поручение не становится человеческим текстом. Для большого источника нужен заранее обновлённый штатный кэш: при несовпадении он отклоняется, скрытого полного повторного разбора нет. Неоднозначные экземпляры снимка остаются неоднозначными и не выбираются как команды.

## План, независимый выбор и применение

Сначала получите полный приватный план:

```text
python3 -I -S -B Инструменты/fum-struktura-papok-zaprosov/scripts/частный_архив_этапа.py план --вход <вход.json> --поручение <выбор-акта.json>
```

Сохраните полный stdout плана без изменений в новый приватный файл `0600` под собственным каталогом `0700`; его путь затем передаётся как `--план`. Читатель проверяет эти условия для входа, плана, выбора ACT, выбора операции и квитанции.

План читает полный состав J1, включая скрытые файлы и пустые каталоги. Для каждого объекта фиксируются путь, тип, режим, владелец, группа, число ссылок, устройство и inode; для файла также размер и SHA. Точные POSIX-обозначения `uid/gid/nlink/dev/inode` сохранены в машинном манифесте. Жёсткие ссылки обычных файлов и специальные файлы отклоняются. `HEAD`, полный ref, байты и файловая идентичность index, actor/ROOT, исходные команды, код, навигационные входы и будущие публичные байты связаны одним планом.

Штатный `подготовить_начало` работает на временной минимальной Git-проекции канонических запросов без J1. Эта приватная проекция удаляется после расчёта; исходный checkout не меняется. Сохраняются исторические буквальные области и ACT. Активная ссылка на J1 вне согласованного плана навигации вызывает отказ. Будущие публичные байты проходят штатный scanner машинных путей до эффекта.

Координатор проверяет план целиком и отдельно сохраняет выбор схемы `fum.выбор-частного-архива.1` с точными полями `план_sha256`, `координатор`, `исполнитель`, `завершён_и_нет_писателей: true`, `поручение`. SHA считается по точным каноническим байтам плана: UTF-8, сортировка ключей, отступ два пробела, один конечный LF. Автоматическое согласие самого исполнителя не заменяет независимый выбор.

```text
python3 -I -S -B Инструменты/fum-struktura-papok-zaprosov/scripts/частный_архив_этапа.py применить --вход <вход.json> --план <план.json> --выбор <выбор.json>
python3 -I -S -B Инструменты/fum-struktura-papok-zaprosov/scripts/частный_архив_этапа.py проверить --вход <вход.json> --план <план.json> --выбор <выбор.json>
```

Применение удерживает собственный приватный замок и штатный замок отчёта J1. После долговечного намерения и синхронизации полного J1 оно снова сверяет состав, `HEAD/ref/index`, родителя назначения, команды, код и публичные назначения. Один exclusive rename переносит J1: macOS `renamex_np(RENAME_EXCL)` или Linux `renameat2(RENAME_NOREPLACE)`. Другой способ и другая ФС отклоняются, копирования с последующим удалением нет. Квитанция лежит рядом с архивом и не меняет его содержимое; замок находится в системном временном каталоге и не содержит исходных данных.

Только после подтверждения полного архива устанавливаются заранее проверенные байты J2. Публичные пути открываются через directory FD с `O_NOFOLLOW`; неизвестный остаток или подмена назначения останавливают установку. Затем проверяются весь архив, полный состав J2 и неизменные `HEAD/ref/index`. Никаких коммитов, staging, push или живых переходов трёх исходных поставок эта команда не выполняет.

## Отказы и точный повтор

Код `0` — полный план либо подтверждённый готовый результат; `3` — сохранённый неизвестный исход после возможного эффекта; `2` — отказ проверки или исполнения. Все потоки CLI приватны. При отказе не удаляйте intent, квитанцию, архив или оставшийся источник и не меняйте план ради повтора. Сначала сохраните наблюдение отдельной командой `проверить` и передайте ROOT точное оставшееся состояние.

Точный повтор готовой операции в новом процессе проверяет тот же независимый выбор, исходники, весь архив, полный J2 и Git-состояние; повторяет синхронизацию и возвращает прежний результат. Поле `повторного_переноса: false` означает отсутствие второго эффекта и возвращается также при первом успехе. Второго rename и коммита нет. Неизвестный исход лишь наблюдается: J2 автоматически не достраивается и J1 обратно не переносится. Неоднозначное расположение копий закрывает проверку отказом, обе доступные копии сохраняются.

Граница доверия — кооперативный единственный писатель и подтверждённый покой. Это не защита от произвольного процесса владельца машины, способного одновременно подменять все входы. Поддержаны закрытые native JSONL указанных runtime-типов и штатная история проверок; неизвестный либо незавершённый RAW отвергается. Системные `fsync` и атомарный rename проверяют границу процессов и файловой системы; безусловная гарантия против потери питания накопителя не заявляется.

## Проверки и профиль

Запускайте через отчётную обёртку собственной задачи, указав принятую зависимость переменной `FUM_КОД_ЧАСТНОГО_АРХИВА` для тестов:

```text
python3 -B -m unittest discover -s Инструменты/fum-struktura-papok-zaprosov/tests -p test_частного_архива_этапа.py
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_частного_архива_этапа.py --корень-кода <физический-K> --выход <новый-профиль.json>
```

Профиль запускает два новых процесса на одном сценарии, отдельно измеряет подготовку фикстуры, сухой план, архив, публичную пару, сверку, штатные навигацию/scanner и повтор в новом процессе. Вложенные интервалы не суммируются повторно. Сохраняются SHA исходников и зависимости; решение об оптимизации не подменяется заявлением об ускорении.
