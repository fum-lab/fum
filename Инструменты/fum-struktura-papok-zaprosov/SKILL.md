# Структура папок запросов

Навык заменяет ручной массовый перенос и повторяемое ручное создание сессий. Он сводит исходный запрос, отчёт и однозначно принадлежащие им артефакты в один агрегат:

```text
Журнал/<YYYY-MM-DD_HH-MM-SS_MSK[_краткое-имя]>/
  запрос.md
  отчёт.md
  материалы/
```

Префикс времени обязателен и должен быть календарно возможным. Историческое имя может состоять только из префикса. Новая папка получает префикс и краткое имя.

Для новой рабочей сессии обязательны и `запрос.md`, и `отчёт.md`. Историческая папка может не содержать `отчёт.md` только тогда, когда отдельного отчёта не существовало до миграции; автоматизация не создаёт такой отчёт задним числом.

## Канонические шаблоны

[Шаблон запроса](шаблоны/запрос.md.шаблон) и [шаблон отчёта](шаблоны/отчёт.md.шаблон) являются единственным каноническим каркасом новых файлов, создаваемых командой `start`. Суффикс `.шаблон`, а не `.md`, намеренно исключает эти файлы из индекса производных Markdown-документов, recency-меток и графа Obsidian.

Шаблон запроса содержит ровно по одному полю `{{метка_времени}}`, `{{заголовок}}`, `{{предыдущий_запрос}}`, `{{следующий_запрос}}`, `{{текст_запроса}}` и `{{идентификатор_сеанса}}`. Шаблон отчёта содержит ровно по одному полю `{{метка_времени}}` и `{{заголовок}}`. Неизвестное, отсутствующее, повторное, переставленное или повреждённое поле, неверный H1, изменение обязательного порядка H2, скрытие каркаса комментарием или оградой, невыровненная таблица либо отсутствие каркаса профиля времени останавливает `start` до записи. Символическая ссылка в пути шаблона и выход файла из канонического каталога также отклоняются. Подстановка выполняется одним проходом по исходному шаблону, поэтому дословный пользовательский текст с последовательностью вида `{{поле}}` не интерпретируется повторно.

Каждый требующий завершения смысловой блок создаётся с маркером `<!-- ШАБЛОН:НЕЗАПОЛНЕНО -->`. Перед коммитом агент заменяет инструкции фактическим содержанием и удаляет все такие маркеры; независимая проверка связности отклоняет любой оставшийся маркер в запросе или отчёте, кроме буквального совпадения внутри дословного `## Текст запроса`.

Команда `start` принимает только непустой массив непустых сообщений, канонический lowercase UUID корневого сеанса, сессионную метку из допустимых символов, начинающуюся с русского инфинитива, и точный заголовок, воспроизводимо выведенный из этой метки. Команда `validate` проверяет действующий контракт обоих хранимых шаблонов вместе со структурой репозитория. Она не требует, чтобы завершённые исторические документы совпадали с текущим каркасом. Автономные тесты читают те же файлы, подтверждают фактическое влияние их содержимого на генерацию, отказ до записи при повреждении и совместимость результата с независимыми проверками связности рабочей сессии.

## Команды

Все команды запускаются из корня checkout:

```bash
python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py plan --repo-root .
python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py apply --repo-root .
python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py validate --repo-root .
git show HEAD:Журнал/README.md | python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py reindex --repo-root . --baseline-markdown -
python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py repair-plan --repo-root . --base-revision <точный-full-commit-OID>
python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py repair --repo-root . --base-revision <точный-full-commit-OID>
```

- `plan` только читает checkout и выводит версионный JSON-план с относительными путями. Одинаковые деревья в разных клонах дают одинаковый план.
- `apply` строит тот же план, заранее готовит все новые байты, атомарно устанавливает файлы и при любом сбое восстанавливает байты, режимы файлов и состояние индекса.
- `validate` закрыто отклоняет неверные имена, символические ссылки, коллизии, сиротские отчёты, неполный индекс, активные ссылки на прежнюю структуру и повреждение канонических шаблонов.
- `reindex` пересобирает только раздел индекса, не меняя остальной `README.md`. Поданный через `--baseline-markdown -` прежний Markdown служит источником курированных строк; ссылка каждой строки приводится к `отчёт.md` либо `запрос.md` по фактическому составу папки. Повтор идемпотентен.
- `start` до первой записи проверяет канонические stem, метку, производный заголовок, UUID сеанса, непустой массив сообщений и сами шаблоны, затем заполняет их, атомарно создаёт `запрос.md` и `отчёт.md`, обновляет навигацию предыдущего запроса и индекс. Подпись каждого соседа берётся из его фактического H1, а не восстанавливается из slug. Повтор с теми же байтами идемпотентен; другое содержание существующей папки является конфликтом.
- `repair-plan` по точному полному commit OID восстанавливает старый инвентарь и исходный план во временном изолированном Git-снимке. Он не меняет checkout, index, refs или внешнее состояние; вывод содержит точные before/after SHA-256 затрагиваемых файлов.
- `repair` атомарно применяет тот же доказательный repair. Он заменяет только те цели semantic Markdown-ссылок, для которых старое значение и ожидаемая новая база доказаны снимком, и приводит подписи навигации к каноническим. Идентичность ссылки задаётся её строчным контекстом без destination и порядком вхождения: одинаковая строка пути в двух разных ссылках не даёт права смешивать их цели. Весь `## Текст запроса` остаётся байтово неизменным; повтор идемпотентен.

Пример старта; JSON-массив в stdin хранит каждое сообщение пользователя дословно:

```bash
python3 Инструменты/fum-struktura-papok-zaprosov/scripts/struktura-papok-zaprosov.py start \
  --repo-root . \
  --session-stem 2026-08-03_12-00-00_MSK_создать-краткую-запись \
  --label создать-краткую-запись \
  --title 'Создать краткую запись' \
  --codex-thread-id 00000000-0000-0000-0000-000000000000 \
  --messages-json -
```

## Границы переноса

Артефакт переносится только при ровно одном доказанном владельце. Для ревью и оценок доказательством служит явная ссылка `request_file` или Markdown-ссылка. Пакет источника требует двустороннюю ссылку между пакетом и запросом. Совпадение имени или времени не считается владением. `Источники/URL/` и общие тематические материалы не переносятся.

В `## Текст запроса` байты не меняются. Сырые URL-снимки и не-Markdown payload-файлы источника не переписываются. `Источники/URL/**/source-index.md` является метаданными, поэтому в нём перебазируются только semantic-ссылки; соседние `response.body.*` остаются байтово неизменными. В Markdown-метаданных переносимого пакета, включая appshot-контекст и отчёт об извлечении, перебазируются только цели semantic-ссылок; остальной текст сохраняется. Ссылки с inline-code в подписи учитываются наравне с остальными. В JSON меняются только доказанно активные `request_file`, `report_file`, `config_file`, `exceptions[].path` машинной политики и `provenance_refs` живого контура. Исторические `checks[].command`, объекты с закреплённым `git:commit` и хэш-связанные неизменяемые пакеты сохраняются.

План даёт переносимую основу для будущего выравнивания веток и форков, но сам навык не выполняет fetch, merge, rebase, commit или push.
