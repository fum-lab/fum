# Единый inline-разбор ссылок Markdown

Функция `_markdown_link_tokens` сохраняет прежний результат `(mask, tokens)` и использует один монотонный внешний курсор. Маска и reference definitions остаются прежними библиотечными операциями. Независимые границы пропуска обычного и расширенного режимов сохраняют внутренние ссылки, когда метка внешней ссылки содержит inline code. Успешный обычный разбор переиспользуется расширенным режимом; найденный closing переиспользуется также при отказе destination parser. Заведомо повторный расширенный токен не создаётся.

Полный набор reference и обычных токенов сохраняет приоритет. Расширенные токены добавляются после него только по незанятым парам destination offsets; стабильная сортировка и все поля токенов прежние. Lookahead внутри helpers сохраняется, поэтому один внешний курсор сам по себе не доказывает линейную сложность.

```text
[наружная [внутренняя](Запросы/old.md) `код`](target.md)
```

Для этого контрпримера сохраняются обе цели. Замена обычного matcher расширенным потеряла бы внутреннюю legacy-ссылку.

## Проверяемый контракт

[Адресный набор](tests/test_единый_разбор_ссылок.py) сравнивает маску и все шесть полей токенов с явно заданными ожиданиями и независимыми исходными байтами C265 `edabf43260b47c0ec3b0c8d7726e0c6fa37722c6`. Он охватывает inline, image, reference, angle/title, escapes, вложенные и пустые spans, CRLF, ограды, comments, inline code и отказ parser внутри вложенной метки. Счётчик полного библиотечного лексера на длинном видимом тексте меняется с 1 на 0.

Настоящий `validate_layout` сохраняет полный результат или тип и текст ошибки; Git и байты фикстуры сверяются после каждого вызова. Проверяются защищённый видимый оригинал, изменение того же пути на активную legacy-ссылку и восстановление, неверный регистр навигации и symlink в Журнале. Портативная коллизия проверяется прежним `_check_move_collisions` на настоящих `Move`: APFS не предоставляет два отдельных каталога для выбранных casefold-эквивалентных имён. Это свидетельство guard планируемых переносов, а не двух физических каталогов.

[Прежний набор](tests/test_request_folder_layout.py) сохранён побайтно, включая stage-0 и режим. Изменение production ограничено телом `_markdown_link_tokens`; сигнатура, docstring, остальные байты файла и семантическая библиотека сохранены.

## Воспроизведение

Каждый discovery-набор является отдельной адресной проверкой:

```sh
python3 -B -m unittest discover -s Инструменты/fum-struktura-papok-zaprosov/tests -p test_единый_разбор_ссылок.py
python3 -B -m unittest discover -s Инструменты/fum-struktura-papok-zaprosov/tests -p test_request_folder_layout.py
```

[Парная процедура](tests/профиль_единого_разбора_ссылок.py) принимает обычный сохранённый кандидат и независимо выбранный SHA-256, новый пустой приватный каталог режима 0700 вне Git и отсутствующий выход. Окончательный SHA B: `e12b472e8e72fbf581a8ad5f5efc589ba273df1fe38ea045dc65ffe1a82f84fb`.

```sh
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_единого_разбора_ссылок.py серия --корень . --кандидат <обычный-кандидат> --хэш-кандидата <SHA256> --приватный <новый-каталог0700> --выход <новый-JSON>
```

Серия создаёт неизменяемые A/B с одинаковой полной относительной структурой зависимостей и один открытый Git-корпус. Подготовка фикстуры временно очищает Git-переменные только в собственном процессе, затем восстанавливает их. Workers импортируют стандартное имя `request_folder_layout` из выбранной версии. Три блока ABBA штатного режима и три отдельных блока cProfile дают 24 свежих процесса; каждый выполняет точный `validate_layout` и три прямых лексических входа. Импорт, подготовка, сериализация и контрольные снимки находятся вне предметного таймера; штатные чтения и Git внутри `validate_layout` остаются внутри.

Полные исходы, Python каждого worker, argv, сырые stdout/stderr и pstats сохраняются приватно. До и после каждого образца сверяются зависимости, процедура, план, корпус и рабочие HEAD/tree/stage-0/сырой индекс/status. Исключения и `SystemExit` сохраняются как отказ, не превращаются в успешную валидацию. Публичный JSON содержит русские ключи, относительные first-party пути, исходные интервалы, медианы и диапазоны; штатные и диагностические времена разделены.

## Полученный результат и граница

[Публичный профиль](../../Журнал/2026-10-05_22-43-13_MSK_реализовать-единый-разбор-ссылок/материалы/профиль/парный-профиль.json) и [его интерпретация](../../Журнал/2026-10-05_22-43-13_MSK_реализовать-единый-разбор-ссылок/материалы/профиль/границы-и-результаты.md) относятся к восьми файлам корпуса и четырём измеренным вызовам. Полные исходы A/B совпали; библиотечный полный лексер у B имеет 0 вызовов, число mask и reference helper сохранено. Для прямых текстов без ссылок и с частыми ссылками наблюдается снижение медиан. Разницы меток с кодом и полной проверки невелики и не доказывают устойчивого выигрыша.

Кэш ОС не сбрасывался; контрольные чтения прогревали вход. Ускорение всего фасада и большого репозитория этим профилем не измерено. B сверяется с Git blob после создания коммита; интеграцию ветки принимает координатор отдельно.
