# Расширение шаблонов и создание вопроса

Автоматизация устанавливает описание типа и его хранимый шаблон по точному предпросмотру. Затем она создаёт вопрос из явно заполненных данных. Одинаковые входы, зависимости и режимы файлов дают одинаковые байты плана и документа; повторное применение проверенного результата ничего не записывает.

Сейчас поддерживается семейство открытых вопросов. У него обязательны неоднозначность, вопросы для прояснения, источники требований и раздел «Затронутая документация». Новый тип может добавлять смысловые разделы между основным содержанием и источниками. Изменение установленного типа требует следующей целой версии и сохраняет прежние поля в прежнем порядке. Произвольные типы документов, изменение шаблонов запроса и отчёта и автоматическая миграция существующей прозы этим интерфейсом не поддерживаются.

Нужен Python 3.10+ и обычный checkout FUM. Само расширение не вызывает модель, Git, сеть, Swift или проекцию. Обычная репозиторная приёмка использует объявленные зависимости FUM отдельно.

## Установить или расширить тип

Начните с [готового описания вопроса](примеры/расширение-вопроса.json). В нём находятся имя типа, основание `вопрос`, версия, упорядоченные разделы с именами полей и полный текст шаблона. Шаблон содержит H1 с полем `заголовок`, вводное поле `кратко`, затем по одному полю под каждым H2. Поддерживается именно показанная грамматика с пустыми строками и завершающим LF: скрытые заголовки, произвольные каркасы, повторные или неизвестные поля отклоняются.

Чтобы добавить совместимый тип, задайте новое русское имя в `тип` и версию 1. Чтобы добавить раздел к существующему типу, увеличьте версию на один и внесите соответствующие раздел и поле в оба места описания. Смысл нового поля определяет автор описания.

Из корня FUM выполните команды ниже. Перенаправляйте план и наблюдение в выбранный временный каталог вне Git. Во всех командах замените `<временный-каталог>` на путь заранее созданного временного каталога вне Git.

```bash
python3 -B Инструменты/fum-struktura-papok-zaprosov/scripts/расширение_шаблонов.py \
  план-расширения --корень-репозитория . \
  --вход Инструменты/fum-struktura-papok-zaprosov/примеры/расширение-вопроса.json \
  > "<временный-каталог>/план.json" 2> "<временный-каталог>/наблюдение-плана.json"
```

План показывает каждую операцию: относительный путь, прежний текст, точный unified diff, SHA-256 и режим до и после. `результаты` охватывает также неизменяемые выходные файлы; `зависимости` связывает применимые правила, фактически исполняемый код, базовые шаблоны, установленный тип и прочитанные ссылки. Изучите `diff` и вход плана, затем примените **тот же файл**:

```bash
python3 -B Инструменты/fum-struktura-papok-zaprosov/scripts/расширение_шаблонов.py \
  применить --корень-репозитория . --вход "<временный-каталог>/план.json" \
  > "<временный-каталог>/квитанция.json" 2> "<временный-каталог>/наблюдение-применения.json"
```

Результат установки — [описание типа](типы/вопрос.json) и [шаблон вопроса](шаблоны/вопрос.md.шаблон). В этой поставке они уже установлены через данный интерфейс; повтор примера даст пустой план. Квитанция содержит хэш применённого плана, число записанных файлов и признак повтора. Если входы изменились, команда сообщает «план устарел» и требует нового предпросмотра.

## Создать вопрос

Скопируйте [пример данных](примеры/данные-вопроса.json) в свой временный каталог и замените все примерные значения фактическими. Укажите новый непосредственный путь `Вопросы/<имя>.md`. Пример содержит условную ссылку на `Документация/модель.md`: это открытая тестовая фикстура, такого документа не создают ради проверки.

Все смысловые поля обязательны и не могут состоять только из комментария, кода или маркера незаполненного шаблона. В `источники` нужна действующая ссылка, в `документация` — хотя бы одна локальная ссылка на существующий Markdown-файл. До запуска `план-документа` подготовьте в согласованной области обратные ссылки из затронутых документов на будущий вопрос. Автоматизация проверяет эту связь, но не дописывает чужую прозу. Ссылки передаются относительно будущего файла вопроса и сохраняются буквально; якорь без файлового пути не подходит.

```bash
python3 -B Инструменты/fum-struktura-papok-zaprosov/scripts/расширение_шаблонов.py \
  план-документа --корень-репозитория . --вход "<временный-каталог>/данные-вопроса.json" \
  > "<временный-каталог>/план-документа.json" 2> "<временный-каталог>/наблюдение-документа.json"
python3 -B Инструменты/fum-struktura-papok-zaprosov/scripts/расширение_шаблонов.py \
  применить --корень-репозитория . --вход "<временный-каталог>/план-документа.json"
```

На открытой фикстуре получается документ с исходной строкой `Сохраняется ё и {{заголовок}}.`, разделами «Неоднозначность», «Вопросы для прояснения», «Источники требований» и «Затронутая документация», а также исходными ссылками. Буквальное `{{заголовок}}` из значения не выполняется повторно. Полный ожидаемый текст задан независимо от реализации в [предметных тестах](tests/test_расширение_шаблонов.py).

После создания включите вопрос в соответствующий раздел индекса `Вопросы/README.md`, обновите recency штатными средствами и проверьте сохранённые ссылки. Для нового вопроса чужие тексты, индекс и служебные метки автоматически не меняются. Приёмку выполняет существующий валидатор вопросов; стандартный smoke проверяет обязательные поля и обратные ссылки **до** генерации проекции. Повреждённый установленный шаблон отклоняется ещё проверкой структуры папок.

## Отказы и границы записи

Планирование только читает файлы. Применение полностью перепроверяет план, точные результаты, зависимости и разрешённые пути до записи. Символические ссылки, выход за checkout, регистровые коллизии, неподдерживаемый тип, повреждённый JSON, несовместимая версия и изменённый предпросмотр завершают команду ненулевым кодом. Неизменённый существующий документ допускает повтор; отличающийся документ получает отказ «миграция не поддерживается». Закрытый Журнал не является разрешённым назначением.

Подстановка и файловая транзакция переиспользуют существующий `request_folder_layout.py`. При обычном исключении установки восстанавливаются прежние байты и режимы, удаляются новые файлы и пустые созданные каталоги. Это не обещание атомарности нескольких файлов при отключении питания, SIGKILL, постоянной неисправности файловой системы или враждебной конкурентной подмене путей. Рабочий контракт предполагает одного писателя дерева. SHA-256 обнаруживает рассогласование, но не удостоверяет автора согласованно переписанного плана. План содержит исходное содержание: перед публикацией проверяйте его наравне с документом.

## Наблюдение и воспроизведение

stdout содержит только план или квитанцию. stderr содержит диагностические сообщения и отдельный JSON наблюдения: календарные UTC-границы, монотонные длительности, исходы и родительские номера этапов. CPU относится к текущему процессу; вложенные интервалы не складываются повторно. RSS, I/O и накладные расходы без отдельного измерения обозначены `unknown`, а не нулём. Наблюдение не входит в проверяемые байты плана. Недоступный stderr не меняет исход самой команды; сохранность наблюдения в таком случае не подтверждается.

Предметные проверки и профиль запускаются через отчётную обёртку своей рабочей сессии. Вложенные команды:

```bash
python3 -B -m unittest discover -s Инструменты/fum-struktura-papok-zaprosov/tests -p test_расширение_шаблонов.py
python3 -B Инструменты/fum-struktura-papok-zaprosov/tests/профиль_расширения.py --повторы 10
```

Профиль сохраняет точные хэши реализации и фикстуры, версию Python, архитектуру, условия кэша, все повторы с отказами и отдельный пик RSS процесса. На первом измерении максимумы успешных операций не превысили 7,7 мс при заранее заданной границе 100 мс на малой фикстуре. Решение — сохранить алгоритм; ускорение не заявляется. Этот результат не распространяется на массовую миграцию, которой здесь нет. Перенос проверки вопросов перед проекцией исключает её ненужный запуск при раннем отказе; стоимость самой проекции данным профилем не измеряется.
