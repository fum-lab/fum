# Подготовить зарегистрированное окружение Git

Ранний общий срез предоставляет [автономную диагностику и явную подготовку](scripts/подготовка_зависимостей.py). Подключение этих вызовов к созданию рабочих деревьев, проверкам коммита и проекции выполняется отдельно. Наличие скрипта само по себе не устраняет отсутствие зависимости во всех деревьях.

## Автономная диагностика

Все команды выполняются из физического корня своего checkout:

```text
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/подготовка_зависимостей.py проверить --корень-репозитория .
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/подготовка_зависимостей.py готовность --корень-репозитория . --путь Зависимости/LinguisticKit --ожидаемая-ревизия 837e2ce107b97ee7b9d3344c9fe99142281fe393
```

Чтение не записывает файлы и не выполняет fetch. Каждый Git-процесс запрещает ленивое получение объектов, рекурсию submodule, hooks и fsmonitor. Partial, promisor и shallow-копии отклоняются. Ошибка или тайм-аут чтения сохраняют неизвестность.

Однопутевая схема `fum.готовность-зависимости.1` содержит `готова`, `состояние`, `ревизия_индекса`, `ожидаемая_ревизия`, `фактическая_ревизия`, `корень_копии` и массив `причины`. Общая схема `fum.готовность-зависимостей.1` содержит `готова` и массив `зависимости`. Фактическая ревизия появляется только после доказательства собственного Git-корня и связанного приватного Git-каталога зависимости.

| Состояние | Смысл |
| --- | --- |
| `нет_регистрации` | Запрошенного пути нет в проверенном инвентаре |
| `нарушена_регистрация` | Регистрация, индексированный файл или локальный URL противоречат контракту |
| `не_материализована` | Регистрация есть, собственного клона и остаточного Git-каталога нет |
| `занятый_путь`, `остаток_подготовки` | Исходники или остатки сохраняются; автоматический повтор запрещён |
| `небезопасный_путь`, `неверная_топология` | Нельзя доказать свой путь и связь Git-каталогов |
| `скрывающие_флаги`, `нечистая_копия` | Индекс скрывает изменения либо клон изменён |
| `неполная_копия`, `вложенные_зависимости` | Неполная копия запрещена; вложение требует отдельно выбранного конечного графа |
| `иная_ревизия`, `нарушен_контракт` | Gitlink или остальные строгие условия не выполнены |
| `неизвестность` | Чтение, вход или отпечаток кода не позволяют доказать состояние |
| `готова` | Локальная копия прошла полный прежний строгий валидатор |

Код `0` означает готовность либо успешное получение снимка. Код `1` означает доказанное несоответствие диагностики или типизированного допуска инвентаря. Код `2` означает неизвестность, ошибку входа либо отказ защищённой процедуры подготовки; он не разрешает повтор эффекта.

Пустой каталог submodule может разрешаться Git в суперпроект. В этом случае `корень_копии=суперпроект`, но `фактическая_ревизия=null`: HEAD FUM не считается HEAD зависимости.

## Полный инвентарь перед эффектом

Читающая проверка может получить отдельно выбранный [конечный граф `.1`](добавление-зависимости.md) по зарегистрированному родительскому пути. API: `проверить_готовность_зависимости(корень, путь, граф=граф)` и `проверить_зависимости(корень, графы={путь: граф})`. Четыре поля родителя должны точно совпасть с зарегистрированным `DependencySpec`; граф другого пути и неизвестные поля запрещены. Полный parent commit/tree/index, первичная `.gitmodules`, всё разбиение gitlinks, приватные связанные leaf-копии, HEAD, чистота, полнота, две роли remote и достижимость pin проверяются без записи. Первичные ответы каждого выбранного листа читаются повторно по независимому SHA и прежнему контракту родства.

CLI для одной готовности либо общей проверки принимает `--граф <абсолютный-приватный-JSON> --ожидаемый-хэш-графа <отдельно-выбранный-SHA256>`. Эти два параметра допустимы только вместе и только для `готовность`/`проверить`. При общей проверке ключ выводится из точного `родитель.путь`; лишний ключ, не входящий в инвентарь, отклоняется. Старые вызовы без графа продолжают возвращать `вложенные_зависимости`. Исторические квитанции S `.1`/`.2` не меняют семантику; получение нового графа не разрешает им recursive init или повтор частичного эффекта. Явные листья материализует только допущенный `add .2`/`.3`.

Проверяются точные байты `.gitmodules` против blob индекса, все записи stage0, скрывающие флаги, биекция содержательных submodule-секций и gitlinks, единственные непустые `path`, `url`, `fumUpstream`, безопасные пути и компоненты ожидаемых Git-каталогов. Пересечения путей, включая регистр, отклоняются. Прежний валидатор проверяет описание каждого принятого пути. Заголовки пустых секций без ключей Git-перечисление не отражает; этот срез не заявляет отдельного разбора таких заголовков.

Для всех отсутствующих копий до первого эффекта проверяется локальный `submodule.<name>.url`: допускаются отсутствие либо единственный точный URL форка. Неверный URL второй записи не допускает материализации первой. Дополнительные стандартные поля регистрации сохраняются; прежний запрет следования `branch` действует.

## Явная подготовка

Нужны назначенное своё дерево, единственный писатель, точный native UUID исполнителя и корневой UUID задачи. `CODEX_THREAD_ID` должен уже поступить от runtime. Значение среды подтверждает принадлежность процесса, но не доказывает человеческое назначение области. Работа с чужими checkout и ref остаётся запрещённой правилами проекта.

Сначала сохранить снимок вне Git, затем передать его процедуре:

```text
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/подготовка_зависимостей.py снимок --корень-репозитория . > <приватный_снимок.json>
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/подготовка_зависимостей.py подготовить --корень-репозитория . --снимок <приватный_снимок.json> --исполнитель <native_UUID_исполнителя> --корневая-задача <корневой_UUID>
```

Снимок связывает физический корень, HEAD, полный ref, собственный и общий Git-каталоги, индекс и его флаги, `.gitmodules`, обе конфигурации и точные исходники. Владение ref проверяется по `git worktree list`. Перед каждым эффектом и успешным ответом снимок сверяется заново. Это кооперативная защита единственного писателя; внешний процесс с теми же правами не изолирован от файловой системы.

Готовые зависимости пропускаются без init и fetch. Отсутствующие копии последовательно используют прежний верхнеуровневый init: материализация, восстановление upstream, получение обоих источников, detached checkout точного gitlink, строгая проверка. Общая конфигурация FUM, индекс и `.gitmodules` сохраняются. Recursive init, partial/lazy clone, зеркала и регистрация новой зависимости этой командой не выполняются. Чистый клон с иной ревизией тоже требует отдельного решения и здесь автоматически не переключается.

## Явная подготовка с прежними графами

Для уже материализованных вложенных зависимостей применяется отдельный закрытый `fum.набор-графов-зависимостей.1`. Он содержит ровно `схема` и объект `графы`: ключ каждого графа совпадает с `родитель.путь`, а четыре поля родителя — с зарегистрированным `DependencySpec`. Лишние пути и поля отклоняются. Плоские зависимости перечислять в карте не обязательно; полная готовность всё равно проверяет весь stage0-инвентарь.

API `проверить_зависимости`, `подготовить_зависимости` и `начать_новую_попытку` принимают `набор_графов={"путь": …, "хэш_байтов": …}`. Ссылка указывает на физический абсолютный приватный файл; SHA-256 относится к его точным байтам. Передача одновременно `графы` и `набор_графов` запрещена. CLI принимает вместе `--набор-графов` и `--ожидаемый-хэш-набора-графов` для всех команд, кроме `снимок`; они несовместимы с одиночными `--граф` и `--ожидаемый-хэш-графа`. Команда `готовность` выбирает один граф и проверяет только запрошенный путь. Общую готовность выдаёт `проверить`.

Подготовка с набором создаёт `fum.подготовка-зависимостей.3`: прежние восемь полей, `набор_графов` и `предыдущая_квитанция`. Первая квитанция без истории имеет предшественника `null`; переход через `новая-попытка` сохраняет SHA прежней квитанции. Для готового повтора нужны та же ссылка на файл и тот же SHA, даже если другой файл имеет одинаковые байты. Переход к новому набору выполняется только отдельной новой попыткой. Все прежние графы должны сохраняться полностью и неизменно; исчезнувший, чужой, изменённый или незакреплённый граф закрывает переход до эффекта.

Выбранный вложенный граф должен быть уже готов. Sprep не материализует его, не вызывает recursive init и не повторяет clone/fetch. Самостоятельно валидная замена прежнего графа тоже не разрешает пересвязать историю. Байты набора перечитываются перед эффектами и после последних проверок перед успешным ответом. Повреждение файла набора любого архивного предшественника закрывает цепочку без переписывания активной квитанции.

Файлы прежних наборов и их первичных ответов сохраняются: архив квитанций не копирует внешние материалы. Расширенный набор с новым графом записывается новым приватным файлом и получает новый SHA; старый файл не заменяется. Формы S `.1`/`.2` сохраняют прежнюю семантику и не получают вложенные полномочия неявно. Даже пустая S `.3` требует add `.3` с точной ссылкой на выбранный набор.


## Прерывание и квитанция

В собственном Git-каталоге сохраняются `fum-подготовка-зависимостей-v1.json` и отдельный `.lock`. CLI создаёт собственную группу процессов. Квитанция атомарно устанавливается с fsync до каждой фазы эффекта; её точная форма и переходы истории проверяются. Замок обязателен также для успешного повторного вызова.

Неизвестный или незавершённый исход не повторяется. После доказанной остановки прежней группы допускается только явное автономное подтверждение уже готовых затронутых копий:

```text
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/подготовка_зависимостей.py возобновить --корень-репозитория . --снимок <тот_же_приватный_снимок.json> --исполнитель <тот_же_native_UUID> --корневая-задача <тот_же_корневой_UUID>
```

Если готовность не доказана, исходники и квитанция сохраняются, а повтор init отклоняется. Смена HEAD, индекса, конфигурации, кода или исполнителя не пересвязывает старую попытку автоматически. История прежних групп сохраняется, признак неизвестного исхода не стирается.

Локальная готовность подтверждает сохранённые remote-tracking refs, но не текущую доступность внешнего сервера, свежесть его веток, происхождение GitHub-форка, лицензию или публикационную приёмку.

## Новый этап после завершённой попытки

Готовая квитанция сохраняет точный исходный снимок. После смены собственного HEAD, индекса или кода обычный `подготовить` не пересвязывает её. Явная операция позволяет начать новый этап только после доказанной финализации и остановки прежней группы:

```text
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/подготовка_зависимостей.py новая-попытка --корень-репозитория . --снимок <новый_приватный_снимок.json> --исполнитель <native_UUID> --корневая-задача <корневой_UUID> --ожидаемый-хэш-квитанции <независимо_закреплённый_SHA256>
```

Ожидаемый SHA относится к точным байтам активной квитанции. Операция самостоятельно не инициализирует зависимость, не получает объекты и не переключает её ревизию. Её успешный результат `fum.результат-новой-попытки-зависимостей.1` содержит `попытка_создана=true`; это подтверждает создание попытки, готовность всего окружения затем подтверждает `подготовить`.

Под общим замком повторно сверяются байты, снимок, UUID, собственная топология, текущая полнота копий и история прежней попытки. Значение `готова=false`, в том числе при готовых отдельных состояниях, не доказывает финализацию. Живую или неизвестную группу, повреждение, исчезновение прежнего пути и смену его gitlink этот минимальный переход отклоняет. Старые OID извлекаются из сохранённого NUL-инвентаря stage0, который может отличаться от старого HEAD. Исторические отпечатки кода остаются происхождением; старый код не исполняется и не сравнивается с текущим кодом.

Исходные байты сохраняются внутри собственного Git-каталога в `fum-подготовка-зависимостей-архив-v1/<SHA256>.json` с режимом 0600 и без перезаписи. Синхронизируются файл, каталог архива и его новая запись в родительском каталоге. Совпадающий архив после прерывания допускается без замены; чужие байты либо символическая ссылка закрывают допуск. Активный файл устанавливается через новый временный файл, `fsync`, атомарную замену и `fsync` родительского каталога. Ошибка не получает успешного результата; фактически установленный префикс сохраняется. Это контракт кооперативного единственного писателя.

Чтение v1 совместимо. Закрытая v2 содержит ровно прежние восемь полей и `предыдущая_квитанция={"sha256": "…"}`. Путь архива выводится из lowercase SHA; произвольного входного пути нет. Каждое чтение v2 итеративно проверяет всю цепочку готовых предшественников до v1, их байты, историю, постоянную идентичность и топологию. Цикл, повтор SHA, ошибка чтения или повреждение любого звена отклоняются.

Новая активная квитанция имеет `готова=false`. Прежние пути сохраняют состояние `готова` и начальные события `автономное_подтверждение`; новые отсутствующие копии имеют `не_начата`. Наследуемый запрет повторного `init` проверяется по цепочке и текущей готовности перед каждым новым эффектом. Утрата старой копии после перехода отказывает с сохранением квитанций. Только новый отсутствующий путь может получить свой `init`. Прежний ожидаемый SHA после установки новой активной квитанции отказывает и не сбрасывает её состояние.

Переход разрешает подготовку уже зарегистрированного инвентаря. Добавление новой зависимости требует отдельного допуска добавления; завершённая подготовка зарегистрированного инвентаря сама его не разрешает.

## Воспроизводимые проверки

Запускать через действующую отчётную обёртку своей задачи:

```text
python3 -B -m unittest discover -s Инструменты/fum-proverka-git-zavisimostej/tests -p 'test_*.py'
python3 -B Инструменты/fum-proverka-git-zavisimostej/tests/профиль_подготовки.py --повторов 3 --выход <профиль.json>
python3 -B -m unittest discover -s Инструменты/fum-proverka-git-zavisimostej/tests -p test_новый_этап_подготовки.py -v
python3 -B Инструменты/fum-proverka-git-zavisimostej/tests/профиль_нового_этапа.py --повторов 3 --выход <профиль_перехода.json>
```

Тесты используют реальные отдельные linked worktree и локальные bare-источники. Проверка заполненного первичного `.git/modules` сохраняет его полный состав, типы, режимы и байты, общую конфигурацию, первичный индекс, разные refs и подготовленные индексы двух чужих деревьев после своей подготовки и готового повтора. Собственная зависимость получает отдельный Git-каталог внутри своего worktree.

Аварийный сценарий завершает настоящий дочерний процесс после init кодом 73; возобновление запрещает второй init тестовым перехватом. Второй процесс завершается кодом 74 сразу после настоящей материализации, до добавления `upstream` и последующих fetch. Обычный повтор и явное возобновление должны отказать и сохранить частичную копию и квитанцию побайтно. Ненулевого кода недостаточно: проверяются отдельный код отказа, JSON, отсутствие повторного init и сохранённые снимки; неизвестность чтения допускается как отказ. Профиль включает чтения Git, исключает создание фикстуры и запись результата, не очищает кэш ОС; отдельно проверяются отсутствие изменяющих команд и сохранность защищённого снимка.
