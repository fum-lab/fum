# Проверка Git-зависимостей

Автоматизация материализует внешнюю Git-зависимость как полноценный клон и Git submodule, восстанавливает уже зарегистрированную зависимость после свежего клонирования либо автономно проверяет подключённое состояние. Форк должен находиться у того же GitHub-владельца, что и публикационный `origin` актуальной рабочей копии FUM; оригинальный репозиторий сохраняется отдельным remote `upstream`.

Автономная проверка не обращается к сети. Она сверяет точные URL и роли remote, путь и URL в `.gitmodules`, сохранённый `fumUpstream`, detached `HEAD`, отсутствие shallow-режима и локальных изменений, достижимость выбранной ревизии из полученных refs форка, режим `160000` и SHA gitlink. Линия форка в GitHub, его синхронизация с родительским репозиторием, лицензия и публикационная допустимость остаются отдельными внешними предпосылками.

Git-вызовы не наследуют переменные `GIT_*`, отключают hooks, replace-объекты, fsmonitor и необязательные блокировки; проверка режима файлов включена явно. Это защита повторяемого сценария от параметров окружения, а не изоляция произвольного кода. Скрывающие изменения флаги индекса зависимости, включая `assume-unchanged` и `skip-worktree`, отклоняются. Проверка сырых байтов при коммите остаётся отдельным обязательным допуском.

## Добавление зависимости

Мутирующий `add` требует независимо подготовленный [допуск добавления](добавление-зависимости.md) и SHA-256 его точных байтов. Допуск выбирают до запуска: он связывает исполнителя, собственный linked worktree, снимок HEAD/ref/индекса/кода, готовую подготовку S, источники/OID, первичные ответы о родстве, ожидаемое описание и защищённые области.

```bash
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py add \
  --repo-root <физический-корень-собственного-worktree> \
  --fork-url <публичный-HTTPS-URL-форка> \
  --upstream-url <публичный-HTTPS-URL-оригинала> \
  --path <относительный-путь-submodule> \
  --revision <полный-Git-OID> \
  --допуск <физический-абсолютный-файл-допуска> \
  --ожидаемый-хэш-допуска <независимо-выбранный-SHA-256>
```

До первого временного клона проверяются все привязки. Родство доказывает первичная пара GitHub body: точные `full_name`, `fork=true` и совпадающие `parent.id/full_name`; имена форка и оригинала могут различаться. Достижимость OID из полученных веток `origin` проверяется отдельно. Автономный `check` не получает скрытого сетевого запроса о родстве.

Регистрация создаёт полный клон в собственном рабочем пути и отдельный Git-каталог внутри административного каталога этого linked worktree. Общий config и каталоги модулей, refs, индексы и байты чужих деревьев сверяются с предварительно закреплённой защитой. Фактические URL/refspec нового клона проверяются перед fetch; `.gitmodules` заменяется атомарно, затем обычный `git add` регистрирует только точное ожидаемое изменение описания и одного gitlink. Старый путь без допуска закрыт до эффекта.

Успешный точный повтор использует прежний допуск и собственное завершённое намерение, вновь проверяет весь результат и не выполняет clone/fetch. Частичный или неизвестный исход сохраняется и закрывает обычный повтор. Живую регистрацию новой зависимости, реальное родство GitHub и последующую общую интеграцию принимают отдельными свидетельствами; локальные bare-фикстуры этого не доказывают.

## Инициализация зарегистрированной зависимости

После свежего клонирования FUM зарегистрированный submodule и его отдельный `upstream` восстанавливаются одной командой:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py init \
  --repo-root . \
  --path Зависимости/LinguisticKit
```

Режим `init` не принимает URL или ревизию от вызывающей стороны. Он требует обычный UTF-8-файл `.gitmodules`, совпадающий с Git-индексом, и строго по одному непустому `path`, `url` и `fumUpstream` зарегистрированного пути. Полный OID выбирается только из gitlink режима `160000` и stage `0`. До материализации проверяются все существующие компоненты рабочего пути, каноническое имя Git-каталога submodule и отсутствие остаточного либо перенаправленного `.git/modules/<name>`; неверное состояние не успевает изменить локальный URL или внешний Git-каталог. У уже материализованной копии допускается чистый HEAD на другой ревизии, но не локальные изменения, shallow-режим, чужой Git-корень, лишний remote, неточный URL или нестандартный fetch refspec.

Материализация передаёт проверенные `submodule.<name>.url` и `active=true` только через `git -c` текущему вызову `submodule update`, без `--init`. Общая конфигурация superproject не записывается; в linked worktree Git-каталог зависимости находится внутри Git-каталога этого дерева. Это проверяется открытой фикстурой свежего нерекурсивного клона и связанного дерева.

После локальной предварительной проверки команда восстанавливает отсутствующий `upstream`, выполняет `git fetch --prune origin` и `git fetch --prune upstream`, выбирает gitlink через detached checkout с запретом перезаписи игнорируемых файлов и запускает тот же валидатор, что и `check`. Строгие fetch refspec и prune исключают доказательство достижимости по устаревшей remote-tracking ветке. Повторный точный запуск сохраняет выбранное состояние, но всё равно выполняет fetch и может обновить refs зависимости; это не режим чтения. Для конечного дочернего писателя применяется [подготовка окружения слоя](../fum-konvejyer-proizvodnyikh-vetok/передача-слоя.md): она связывает C/HEAD/index с назначением, готовую копию только проверяет и не повторяет незавершённую попытку.

Этот режим применим к одному явно выбранному верхнеуровневому submodule, уже зарегистрированному в отслеживаемой `.gitmodules`. Он может обращаться к сети, но не создаёт новую запись submodule, не меняет `.gitmodules` или gitlink, не выбирает вершину remote вместо gitlink, не синхронизирует форк и не инициализирует произвольную вложенную иерархию. Родство и публикация GitHub-форка, его синхронизация с оригиналом, лицензия, доступность и публикационная допустимость остаются отдельными внешними предпосылками. Завершающий `check` по-прежнему автономен и не обращается к сети.

## Проверка зависимости

Для раннего общего допуска и явной подготовки всего зарегистрированного окружения используй [отдельный контракт](подготовка-окружения.md) и [общий скрипт](scripts/подготовка_зависимостей.py). Он переиспользует строгий валидатор, различает отсутствующую регистрацию и клон, проверяет весь инвентарь до эффекта, пропускает готовые копии без fetch и сохраняет незавершённую попытку без слепого повторения. Включение общего вызова в creator, smoke и проекцию — отдельный шаг интеграции; этот навык сам его не выполняет.

Только закреплённый граф libtorrent на `56ae8caba38bf154ffc210403cb23f91d0ecaa49` допускается с [точным индексированным профилем](подготовка-окружения.md#узкий-профиль-вложенного-libtorrent), пустыми вложенными путями и отдельно готовым зарегистрированным `try_signal`. Неизвестные графы и активные вложенные копии отклоняются. Профиль не доказывает сборку; live add по-прежнему требует самостоятельного допуска и свежей готовности S.

После завершённой попытки и смены собственного снимка применима отдельная `новая-попытка` с независимо закреплённым SHA активной квитанции. Она проверяет финализацию и остановку прежней группы, сохраняет неизменяемый архив и закрытую цепочку v2→v1, наследует запрет повторного init готовых путей. Старые пути и gitlink OID сохраняются; только новые отсутствующие пути допускают последующую инициализацию. Операция перехода не выполняет init/fetch и не означает итоговой готовности. Подробный порядок, ошибка записи и границы — в том же контракте.

Для LinguisticKit используется команда:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py check \
  --repo-root . \
  --fork-url https://github.com/fum-lab/LinguisticKit.git \
  --upstream-url https://github.com/Roman-Kerimov/LinguisticKit.git \
  --path Зависимости/LinguisticKit \
  --revision 837e2ce107b97ee7b9d3344c9fe99142281fe393
```

Код `0` означает полное совпадение локальной Git-топологии и gitlink с контрактом. Код `1` сопровождается русской диагностикой каждого обнаруженного расхождения.

## Автономные тесты

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-proverka-git-zavisimostej/tests \
  -p 'test_*.py'
```

Тесты создают временные локальные bare-репозитории FUM, форка и upstream. Они проверяют успешное добавление, свежие recursive и обычный clone, восстановление `upstream`, получение и prune обоих remote, выбор gitlink, идемпотентность, допустимость несвязанных изменений, принадлежность форка владельцу актуального FUM, достижимость выбранного коммита из ветки форка, роли и refspec remote, строгую кратность `.gitmodules`, канонические Git-каталоги, безопасные компоненты пути, защиту игнорируемых файлов, точный `HEAD`, чистоту клона и CLI-диагностику без внешней сети.
