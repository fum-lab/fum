# Проверка Git-зависимостей

Автоматизация материализует внешнюю Git-зависимость или дочерний fork-снимок как полноценный клон и Git submodule, восстанавливает уже зарегистрированный снимок после свежего клонирования либо автономно проверяет подключённое состояние. Профиль определяется точным путём: обычная зависимость сохраняет прежний контракт одинакового имени у владельца FUM и отдельного владельца upstream, а непосредственный `Ядра/<имя-репозитория>` является дочерним fork того же владельца и требует `fumUpstream`, точно равный `origin` родительского FUM.

Автономная проверка не обращается к сети. Она сверяет точные URL и роли remote, путь и URL в `.gitmodules`, сохранённый `fumUpstream`, detached `HEAD`, отсутствие shallow-режима и локальных изменений, достижимость выбранной ревизии из полученных refs форка, режим `160000` и SHA gitlink. Для `Ядра/<имя>` она дополнительно требует совпадение имени каталога и fork-репозитория, общего владельца с родителем, точный родительский `origin` как upstream и отсутствие пути `Ядра` в закреплённом дочернем commit. Последняя граница не допускает прямую рекурсивную композицию при обновлении gitlink. Линия форка в GitHub, его синхронизация с родительским репозиторием, лицензия и публикационная допустимость остаются отдельными внешними предпосылками.

## Добавление зависимости

До запуска GitHub-форк уже должен существовать и быть синхронизирован с оригиналом. Мутирующий режим принимает только явные значения:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py add \
  --repo-root . \
  --fork-url <публичный-HTTPS-URL-форка> \
  --upstream-url <URL-оригинала> \
  --path <относительный-путь-submodule> \
  --revision <полный-Git-OID>
```

Перед изменением основного репозитория команда клонирует оба источника во временный каталог и подтверждает, что выбранный коммит достижим из обычной ветки полученного форка. Несвязанные изменения основного репозитория сохраняются; конфликтующий путь, gitlink, раздел `.gitmodules` или остаточный Git-каталог закрывают добавление. Повторный точный вызов проверяет уже существующую зависимость и завершается без нового изменения.

## Инициализация зарегистрированной зависимости

После свежего клонирования FUM зарегистрированный submodule и его отдельный `upstream` восстанавливаются одной командой:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py init \
  --repo-root . \
  --path Зависимости/LinguisticKit
```

Режим `init` не принимает URL или ревизию от вызывающей стороны. Он требует обычный UTF-8-файл `.gitmodules`, совпадающий с Git-индексом, и строго по одному непустому `path`, `url` и `fumUpstream` зарегистрированного пути. Полный OID выбирается только из gitlink режима `160000` и stage `0`. До материализации проверяются все существующие компоненты рабочего пути, каноническое имя Git-каталога submodule и отсутствие остаточного либо перенаправленного `.git/modules/<name>`; неверное состояние не успевает изменить локальный URL или внешний Git-каталог. У уже материализованной копии допускается чистый HEAD на другой ревизии, но не локальные изменения, shallow-режим, чужой Git-корень, лишний remote, неточный URL или нестандартный fetch refspec.

После локальной предварительной проверки команда восстанавливает отсутствующий `upstream`, выполняет `git fetch --prune origin` и `git fetch --prune upstream`, выбирает gitlink через detached checkout с запретом перезаписи игнорируемых файлов и запускает тот же валидатор, что и `check`. Строгие fetch refspec и prune исключают доказательство достижимости по устаревшей remote-tracking ветке. Повторный точный запуск идемпотентен.

Этот режим применим к одному явно выбранному верхнеуровневому submodule, уже зарегистрированному в отслеживаемой `.gitmodules`. Он может обращаться к сети, но не создаёт новую запись submodule, не меняет `.gitmodules` или gitlink, не выбирает вершину remote вместо gitlink, не синхронизирует форк и не инициализирует произвольную вложенную иерархию. Родство и публикация GitHub-форка, его синхронизация с оригиналом, лицензия, доступность и публикационная допустимость остаются отдельными внешними предпосылками. Завершающий `check` по-прежнему автономен и не обращается к сети.

Три закреплённых дочерних снимка инициализируются отдельными точными вызовами для `Ядра/fum-yadro`, `Ядра/fum-optimizator` и `Ядра/fum-pisatelj`; переносимый полный маршрут приведён в [`Ядра/README.md`](../../Ядра/README.md). Отдельные живые клоны не заменяются submodule: снимок остаётся detached и не используется как рабочая ветка исполнителя.

## Проверка зависимости

Для LinguisticKit используется команда:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py check \
  --repo-root . \
  --fork-url https://github.com/fum-lab/LinguisticKit.git \
  --upstream-url https://github.com/Roman-Kerimov/LinguisticKit.git \
  --path Зависимости/LinguisticKit \
  --revision 837e2ce107b97ee7b9d3344c9fe99142281fe393
```

Код `0` означает полное совпадение локальной Git-топологии и gitlink с контрактом. Код `1` сопровождается русской диагностикой каждого обнаруженного расхождения.

Для дочернего снимка используется тот же `check`, например:

```bash
python3 Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py check \
  --repo-root . \
  --fork-url https://github.com/fum-lab/fum-yadro.git \
  --upstream-url https://github.com/fum-lab/fum.git \
  --path Ядра/fum-yadro \
  --revision 249d076b1857f4e1727e5448587d13f16b15a30a
```

## Автономные тесты

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-proverka-git-zavisimostej/tests \
  -p 'test_*.py'
```

Тесты создают временные локальные bare-репозитории FUM, форка и upstream. Они проверяют успешное добавление, свежие recursive и обычный clone, восстановление `upstream`, получение и prune обоих remote, выбор gitlink, идемпотентность, допустимость несвязанных изменений, принадлежность форка владельцу актуального FUM, достижимость выбранного коммита из ветки форка, отказ от прямой рекурсивной композиции до материализации и при проверке существующего gitlink, роли и refspec remote, строгую кратность `.gitmodules`, канонические Git-каталоги, безопасные компоненты пути, защиту игнорируемых файлов, точный `HEAD`, чистоту клона и CLI-диагностику без внешней сети.
