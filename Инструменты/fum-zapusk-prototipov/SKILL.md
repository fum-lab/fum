# FUM Prototype Launch

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) проверяет единый контракт простого запуска прототипов. Корневой исполняемый POSIX-скрипт `prototipyi.sh` служит общей панелью, а каждый непосредственный подкаталог `Прототипы/` с паспортом `README.md` считается устойчивым прототипом и должен содержать исполняемый POSIX-скрипт `запустить.sh`.

## Контракт общей панели

Корневой скрипт `prototipyi.sh`:

- имеет намеренно транслитерированное имя для запуска без переключения раскладки;
- начинается с `#!/bin/sh`, имеет исполняемый бит и корректен для `/bin/sh`;
- сам определяет корень репозитория и не зависит от текущего рабочего каталога;
- без аргументов показывает пронумерованную панель найденных `Прототипы/*/запустить.sh`;
- принимает цифру для запуска и `q` для безопасного выхода;
- поддерживает `--list` без запуска и прямой выбор номером;
- передаёт остальные аргументы выбранной точке входа;
- автоматически включает будущие прототипы без ручного списка.

## Контракт точки входа прототипа

Скрипт запуска:

- находится в корне каталога прототипа и называется `запустить.sh`;
- начинается с `#!/bin/sh` и имеет исполняемый бит;
- корректен для `/bin/sh`;
- сам определяет каталог прототипа и не зависит от текущего рабочего каталога;
- без обязательных аргументов даёт полезный и безопасный сценарий;
- передаёт явно заданные аргументы прототипу;
- не включает чувствительное действие без отдельной явной команды;
- описан в паспорте прототипа.

Автоматическая проверка подтверждает структурные свойства корневой панели и точек входа. Автономные тесты дополнительно проверяют список панели, независимость от текущего каталога, интерактивный выбор и передачу аргументов на временных фикстурах. Полезность, безопасность сценария по умолчанию, передачу аргументов и соответствие паспорту настоящего прототипа нужно дополнительно проверять смысловой приёмкой.

## Команда запуска

Из корня репозитория:

```bash
python3 Инструменты/fum-zapusk-prototipov/scripts/check-prototype-launchers.py
```

Из другого каталога:

```bash
python3 /путь/к/FUM/Инструменты/fum-zapusk-prototipov/scripts/check-prototype-launchers.py \
  --repo-root /путь/к/FUM
```

Успешная проверка подтверждает корневую панель и сообщает число найденных точек входа прототипов. Ошибка перечисляет каждый отсутствующий или некорректный файл и возвращает ненулевой код.

## Проверки автоматизации

Автономные тесты не требуют сети, секретов, Swift-сборки или запуска прототипов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-zapusk-prototipov/tests \
  -p 'test_*.py'
```

Тесты фиксируют корректный POSIX-скрипт, отсутствие корневой панели или каталога прототипов, отсутствие файла, отсутствие исполняемого бита, неверный shebang, синтаксическую ошибку, игнорирование служебных каталогов без `README.md`, список панели, интерактивный выбор и передачу аргументов.

## Граница автоматизации

Структурная проверка намеренно не исполняет настоящие `prototipyi.sh` и `запустить.sh`. Поведение панели проверяется на временной копии с безопасными фикстурами. Настоящий прототип может открывать GUI, обращаться к заранее установленной локальной модели, читать явно выбранный файл или требовать отдельного согласия на наблюдение чувствительного ввода. Такие сценарии принимаются отдельно по паспорту, а проверка точек входа остаётся безопасной и автономной внутри явного полного профиля либо отдельного целевого запуска; стандартный документационный smoke её не вызывает.
