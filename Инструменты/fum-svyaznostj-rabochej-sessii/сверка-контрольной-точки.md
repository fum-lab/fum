# Читать готовую контрольную точку

[CLI](scripts/сверить-контрольную-точку.py) сверяет уже созданную обычную ROOT `.5`-точку по сохранённой подготовке `.7`, успешной квитанции `.1`, сырым Git-байтам и полному ref. Независимый выбор связывает конкретный комплект с C. Он не реконструирует исходный допуск и не читает заново native, модельный курсор, готовность или v4-журнал. Рабочий каталог команды — физический корень чистого клона FUM с объявленными зависимостями.

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/сверить-контрольную-точку.py --вход <абсолютный-приватный-выбор.json> --sha256 <SHA256-всех-байтов-выбора>
```

Этот холодный вход использует обычное расположение исходников, без `PYTHONPATH`, частного bootstrap или настройки `sys.path` вызывающей стороной. CLI отключает запись bytecode до транзитивных импортов. Результат не является новым `start`, подготовкой, готовностью, коммитом, push или разрешением продолжения задачи.

## Независимый выбор

JSON схемы `fum.выбор-читающей-сверки.1` содержит ровно:

| Поле | Значение |
| ---- | -------- |
| `схема` | `fum.выбор-читающей-сверки.1` |
| `корень` | Абсолютный физический checkout готовой точки |
| `ветка` | Полный буквальный `refs/heads/…` |
| `коммит` | Полный lowercase OID созданного C |
| `файлы` | Ровно `подготовка` и `квитанция`, каждая с `путь` и `sha256` |
| `публикация` | `null` либо ровно `{ "адрес_sha256": "<64hex>" }` |

Адреса трёх входных файлов абсолютные, буквальные, без symlink и Git-предка. Требуется собственный обычный файл без hardlink: режим0400/0600 либо0444/0644 внутри собственного приватного каталога. SHA — хэш всех сырых байтов, включая LF. Он отличается от Git blob OID и recency-хэша Markdown. Неизвестные поля, повторные JSON-ключи на любой глубине, NaN, дробные числа, неканонические схемы, сокращённые OID и повреждённый JSON закрываются отказом. Параметры вызова не сокращаются.

При `публикация=null` удалённое состояние не читается. Для выбора readback `адрес_sha256` — SHA256 канонического JSON строкового адреса плюс LF: UTF-8, `ensure_ascii=False`, `sort_keys=True`, `separators=(",", ":")`. Это прежнее правило хэша адреса поставки; обычный SHA UTF-8 URL без JSON-кавычек не подходит.

## Сохранённый комплект

Подготовка обязана иметь схему `fum.подготовленный-коммит.7` и ровно 12 полей: `схема`, `параметры`, `имя_автора`, `готовность`, `команды`, `модель`, `наблюдений`, `история_sha256`, `сообщение_sha256`, `исходный_автор`, `исходный_коммиттер`, `явные_даты`. Параметры — штатный закрытый ROOT `.5`-набор из `создание_коммита.ПОЛЯ_КОНТРОЛЬНОЙ_ТОЧКИ`, режим `контрольная-точка`. Дочерние `.7/.9` и исторические другие схемы не подбираются автоматически.

Корень, ref и оба адреса совпадают с выбором. Родителей один либо два; первый равен исходному коммиту, повторов нет. Второй соответствует реальному ordered merge. Родители и источники сохраняют исходный порядок. Разрешённые цели — конечный уникальный список буквальных относительных путей. Изменённые между первым родителем и C файлы должны входить в него; неизменившаяся разрешённая цель допустима. Сортировка разрешения не заменяет проверку состава.

Источник содержит ровно `путь`, `задача`, `экземпляры`, `граница_снимка`, дополнительно только необязательный `кэш`. Граница содержит `граница`, `sha256`, `неоднозначные_экземпляры`. Команда содержит `задача`, `экземпляр`, `позиция`, `текст`; порядок выбранных экземпляров совпадает с источниками. Позиция содержит `начало`, `конец`, `sha256`. Модель содержит `время`, `инициатор`, `модель`, `позиция`, `причина`, `усилие`; она связана со штатно составленным именем автора. Сохранённые адреса источников остаются метаданными, а не указанием повторить чтение.

Квитанция имеет схему `fum.квитанция-создания-коммита.1` и ровно 13 полей: `схема`, `состояние`, `ожидание`, `подготовка_sha256`, `подготовка_наносекунды`, `наблюдённый_коммит`, `индекс_sha256`, `проверки`, `допуск`, `готовность`, `профиль`, `процесс`, `результат`. Состояние `проверен`; её `подготовка_sha256` равен SHA удержанных байтов подготовки.

Процесс содержит ровно `код`, `тайм_аут`, `исполнение_завершено`, `прерывание`: соответственно целое0, false, true, null. Boolean вместо целого0, отрицательный/неизвестный код, незавершённость, тайм-аут, прерывание или другое состояние блокируют зависимые Git/raw/remote-чтения. Повтор производителя не вызывается.

Ожидание содержит `ветка`, `исходный_коммит`, `родители`, `дерево`, `сообщение_sha256`, `автор`, `коммиттер`, `явные_даты`. Stock `сверить_ожидание_квитанции` связывает его с подготовкой. Author и committer проверяются отдельно; identity — четыре строки имени, адреса, signed timestamp и offset. Явные даты связываются отдельно для каждой роли. Авторское имя модели не подставляется вместо committer. Допустимая задержка сохранённой готовности не превращается в отказ и не обнуляется.

Результат — ровно шесть полей `коммит`, `дерево`, `родители`, `автор`, `коммиттер`, `сообщение_sha256`. Выбранный C, наблюдённый OID и результат совпадают. Stock `восстановить` и `проверить_объект` сверяют все шесть полей по сырым байтам, включая идентичность объекта. Адаптер меняет только Git-транспорт отдельных функциональных экземпляров; глобальные функции производителя не переписываются.

## Неизменность и доставка

Снимки входов и обычных индексных файлов удерживают O_RDONLY-дескрипторы до последних зависимых чтений. Тип, inode/device, режим, uid, число ссылок, байты и временные метки сверяются при закрытии, включая путь отказа. Проверяются также symlink/gitlink, сырой индекс, его stage0-состав и равенство C. Git-mode100644 совместим с FS0600: пользовательские права не исправляются. Исполнительный бит проверяется по штатной семантике Git-mode.

HEAD и symbolic ref до и после равны выбранным C и ref. Заключительный порядок: все зависимые Git-чтения, включая последний вложенный HEAD, индекс и адрес → предварительная FS-сверка при удержанных исходных FD → терминальная ROOT HEAD/ref-сверка → повторная FS-сверка без Git → освобождение FD → результат. Для предварительной FS-сверки штатный метод получает по одному дубликату O_RDONLY-дескриптора; исходный остаётся открытым. Обе FS-сверки проверяют метаданные, буквальные symlink, физический родитель и отсутствие grafts через lexists. `finally` сохраняет проверки и cleanup при отказе и KeyboardInterrupt. После терминального ROOT зависимые Git-вызовы запрещены.

Для gitlink до терминального ROOT Git сообщает настоящий git-dir, common-dir и формат refs. Удерживаются gitfile, HEAD, commondir, config/worktree config, packed refs и физические файлы каталогов refs/reftable вместе с точным составом каталогов. Files-backend дополнительно замыкает файловую symref-цепь, включая pseudoref вне refs; допустимый пробельный синтаксис `ref:` сохраняется. Reftable placeholder HEAD не интерпретируется как files-ref: удерживаются реальные таблицы и их список. Объекты, логи и hooks рекурсивно не обходятся. Неизвестный backend, необычный тип метаданных и циклическая цепь дают отказ.

Config origins и кандидаты system/global, включая отсутствующие и пустые файлы, получаются штатным Git. Include-цели связываются с исходным origin.parent; относительные пути раскрываются без преждевременного сворачивания `..`. Первый отсутствующий либо компонент, не являющийся каталогом, удерживается до последующего `..`; действующий каталог перед `..` тоже наблюдается. Каждый config alias удерживается по lstat и буквальному readlink, а regular bytes — по физической цели. Успешное первоначальное чтение `--includes` позволяет пропустить заведомо неактивный условный path без значения или с неизвестным пользователем; принудительное раскрытие таких includeIf запрещено. Разрешимые условные цели наблюдаются консервативно, даже если условие неактивно: изменение такого файла может вызвать лишний отказ. `%(prefix)` раскрывает Git. LF/CR в HOME/XDG config addresses и неоднозначный вывод Git var не поддержаны. Post-FS проверяет удержанные bytes, aliases, отсутствие путей и состав каталогов, не запускает Git и не обещает атомарную изоляцию.

Git-вызовы отключают optional locks, replace objects, lazy fetch и trace2, не наследуют `GIT_*`. Grafts запрещены. CLI не создаёт журнальный lock, cache, новый файл или новый объект. Обычное чтение может изменить atime ФС; оно не входит в проверку отсутствия записи содержимого. Кооперативная сверка обнаруживает наблюдённый дрейф, но не изолирует враждебный процесс с теми же правами и не делает remote атомарным.

Readback требует единственный `origin`, одинаковые fetch/push URL и выбранный SHA адреса. `ls-remote --refs` по точному полному ref возвращает ровно C; адрес и локальная точка сверяются снова. Неверный/неизвестный remote или дрейф отказывают. Чтение подтверждает факт удалённого OID в наблюдённый момент. Оно не восстанавливает код ранее выполнявшегося push, не повторяет push и не подтверждает получение внешним адресатом.

## Выходы

После успешного закрытия всех снимков stdout содержит один канонический JSON `fum.результат-читающей-сверки.1` с ровно `схема`, `результат`, `публикация`; код0. Результат сохраняет все шесть stock полей. Публикация равна null либо содержит `коммит`, `ветка`, `адрес_sha256`, `код_push=null`.

При отказе stdout пуст; stderr содержит один JSON `fum.отказ-читающей-сверки.1` с `схема`, `причина`; код2. Повреждение транзитивного исполняемого контура тоже является отказом загрузки. API `сверить(вход, ожидаемый_хэш)` возвращает тот же успешный объект; ошибки API поднимаются вызывающей стороне. Успешный вывод не печатается до итоговых сверок.

## Регрессии и профиль

Каждый прямой запуск проводится через v4-обёртку своей открытой сессии:

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_сверки_контрольной_точки.py -v
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_сверки_контрольной_точки.py --выход <новый-приватный-JSON>
```

[Регрессии](tests/test_сверки_контрольной_точки.py) используют настоящие stock `.5`-подготовку, v4, готовность и producer, обычный и merge-коммит. Источники/готовность после setup удаляются: их отсутствие не должно мешать чтению готового результата. В холодной проверке создаётся настоящий чистый клон консервативного набора канонических `scripts`; это не полная приёмка клона FUM. API и относительный CLI читают одну отдельную Git-фикстуру без частного bootstrap. Локальный bare remote проверяет транспорт и точный readback; публичная GitHub-доставка отдельно.

Адресная регрессия позднего ref и отдельного HEAD-дрейфа сохраняет фактические каналы настоящей `главная()` в процессе теста. Producer, готовность и создание выполняются штатно до инъекции. Наблюдатель сначала получает реальный stdout четвёртого `ls-files`, затем меняет только ref либо вершину фикстуры. Индекс и отслеживаемые байты остаются прежними. Сырые исходы записываются перед assertions, поэтому RED сохраняет и ошибочный успешный JSON. Холодный процесс проверяется отдельно. Необязательное свидетельство создаётся0600 с O_EXCL/O_NOFOLLOW вне Git в собственном физическом каталоге0700; обычный discovery его не создаёт:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_сверки_контрольной_точки.py --свидетельство-позднего-дрейфа <новый-приватный-JSON> СверкаКонтрольнойТочки.test_поздний_реф_и_вершина_после_последнего_индексного_чтения
```

Поздняя смена ref после последнего optional address и предварительной FS-сверки, байтовая подмена во время терминального Git и прерывание заключительной FS-сверки имеют отдельные регрессии. Отдельные сценарии заменяют настоящий tracked symlink и HEAD настоящего gitlink, создают обычный либо dangling-symlink grafts после получения терминального Git stdout. Фикстуры проходят настоящий stock producer и успешный контроль без инъекции; индексный guard проверяет все пути, включая синтетическое производное пространство временного Git, штатно исключённое из содержательного отпечатка v4. Прерывание post-FS наблюдений также проверяет cleanup. Отказ последнего настоящего вложенного HEAD-чтения до терминальной корневой сверки сохраняет post-FS обнаружение подмены подготовки; его KeyboardInterrupt распространяется после освобождения всех исходных FD. Они проверяют отказ без успешного stdout и освобождение удержанных FD; инъекции не изображают отсутствие записи самим наблюдателем.

Новая регрессия на a56 сначала получает фактические producer0 и reader/control0. Номер последнего вложенного HEAD-вызова выводится из успешного контроля; после получения его настоящего stdout отдельные инъекции меняют только ROOT ref либо вершину. RED сохраняет ошибочный успешный JSON исходного a56; GREEN требует отказ без успешного stdout и закрытие FD. Дополнительная матрица проверяет loose/packed refs, symref-цепь, связанный worktree, reftable, include и aliases, пустой/отсутствующий global config. После терминального ROOT любые новые Git-вызовы отвергаются наблюдателем. Неактивные invalid includeIf получают отдельный успешный контроль; цепь HEAD → refs/heads/… → ORIG_HEAD проверяет разные формы `ref:`. Синтаксические и ошибочные setup-фикстуры сохраняются отдельно от semantic RED.

Отдельный запуск `python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_сверки_контрольной_точки.py --красный-контроль-производителя` временно ослабляет только in-process gate производителя. Группа0079/0002 должна реально отказать на преждевременном Git-чтении. Этот мутационный RED подтверждает чувствительность регрессии; он не выдаётся за отсутствующую предысторию реализации и не меняет production-файл. Обычный discovery сохраняет строгий gate.

[Профиль](tests/профиль_сверки_контрольной_точки.py) принимает только отсутствующий выход в собственном физическом каталоге0700 вне Git; устанавливает0600 с O_EXCL/O_NOFOLLOW. `-O`, `-OO` и `PYTHONOPTIMIZE=1/2` отказывают до загрузки фикстуры и записи. Поздняя коллизия сохраняет чужой файл.

Четыре раунда ABBA/BAAB/ABBA/BAAB сравнивают ручную композицию штатных читающих API и новый API на одних неизменных байтах обычной/merge-фикстуры. Общий контракт, обе FS-сверки и терминальный HEAD/ref одинаковы для выбранных обычных файлов; полное равенство результата обязательно. Setup/import, чистое локальное чтение, диагностические счётчики, холодный процесс и bare readback разделены. Счётчики файловых чтений и Git stdout измеряются отдельными вызовами, без диагностического monkeypatch в чистом таймере. Поздние ref, grafts и байтовые инъекции до предварительной FS-сверки и внутри терминального Git проверяют равный фактический отказ A/B вне таймеров; после них восстанавливаются выбранный ref и байты подготовки. Профиль сохраняет все измерения, сырые SHA входов и замыкания кода. Он не измеряет физический I/O, токены, полный рабочий цикл, внешнюю доставку или ускорение всей задачи. Изменение алгоритмов допуска выбирается только по измеренному основанию; прежние131/40 тестов и профили PR215/216 не повторяются этой командой.
