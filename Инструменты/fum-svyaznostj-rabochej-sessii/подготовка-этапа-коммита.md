# Подготовка этапа коммита

[Фасад](scripts/подготовка_этапа_коммита.py) составляет читающий план и последовательно вызывает прежние инструменты подготовки обычной дочерней контрольной точки `.7` либо корневой `.5`. Обычная `.7` сохраняет независимый выбор ACT и собственную нативную привязку; её готовность объявляется отдельно. Корневая `.5` доводится до настоящей готовности через [прежний API](создание-коммита.md). Создание коммита остаётся отдельным действием. Новый формат приёмки, разрешение обхода gate и дополнительный кэш не вводятся.

Новую пару предварительно создаёт штатный `start`. Действие берётся из имени этапа, заголовок — из его канонического преобразования: календарная метка не является `--label`. План сверяет фактические заголовки пары до первой записи. Закрытая история не возобновляется.

Нестейджированное удаление отслеживаемой разрешённой цели получает явный отказ до первого эффекта: последовательность рассчитана на добавление и обновление файлов. Будущие отсутствующие записи проверок разрешаются отдельно.

Вход фасада — приватный JSON с полями `вход_коммита`, `поручение`, `наполнение`, `план_наполнения`, `время`, `повтор`, `проверки`, `связность`. Первые три поля адресуют прежние приватные входы. `время` — точная метка recency вида `2026-10-04 19:59:55 MSK`; новое время начала фасад не получает. `повтор` выбирает прежний `подготовить-повтор`, сохраняя модельную историю и курсор с новыми выходами подготовки.

Каждая проверка содержит `идентификатор`, `порядок`, `название` и один элемент `наборы` с точными `каталог` и `шаблон`. Адресный каталог тестов должен быть плоским, найденные тестовые файлы входят в ACT. Команда `unittest discover` строится алгоритмически; произвольные команды вход не принимает. `связность` содержит собственные UUID и следующий номер. Будущие отсутствующие `N_UUID.json` должны точно совпадать с ожидаемыми целями прежнего наполнителя. Номер перечитывается перед каждым настоящим процессом; план его не резервирует.

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/подготовка_этапа_коммита.py план --вход <новый приватный вход>
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/подготовка_этапа_коммита.py выполнить --вход <тот же вход> --план <сохранённый план> --sha256 <SHA его точных байтов>
```

`план` печатает канонический JSON в stdout и не устанавливает файлов. Вызывающий слой сохраняет его в новый собственный файл0400, затем передаёт независимый raw SHA. Каталог приватных файлов имеет0700, изменяемые входы и курсоры —0600; разные роли требуют разных путей. Фасад не исправляет режимы чужих файлов. Родители назначения модели и всех приватных файлов должны уже существовать.

Исполнение сначала повторяет план и сверку снимка. Далее следуют прежние maker.prepare, `наполнение-план` и `наполнение-применить`. SHA наполнения берётся из stdout `план_sha256` и независимо сравнивается с байтами immutable planfile0400; в самом JSON плана такого поля нет. Любой отказ сохраняет наблюдённые stdout, stderr и код, прекращая зависимые стадии. Разрешённые предыдущие эффекты сохраняются; общей транзакции и автоматического отката нет.

Recency выполняет штатный полный читающий обход. Допускаются только ожидаемые missing/stale-диагностики точных изменяемых целей. Malformed-вход, дрейф или `changed_paths` вне ACT прекращают применение. Повторная сверка полного Markdown-инвентаря, HEAD/ref и сырого индекса предшествует прежнему apply. Общий индекс должен быть явно разрешён; эта процедура не CAS и не защита от враждебной гонки между сверкой и записью.

Полный staging предшествует настоящим адресным v4-процессам. Терминальный предпросмотр выполняется перед обёрнутой связностью с её собственным `FUM_CHECK_RUN_ID`; после терминализации следуют повторный предпросмотр, staging только исключённых текущих свидетельств и прежнее читающее замыкание000188. Чужая active-запись блокирует план. Между стадиями повторяются прежний дешёвый адресный допуск и сверки приватных входов/индекса. В обычной `.7` фасад не создаёт готовность, квитанцию или коммит.

Поздние `готово` и `создать` прежнего типизированного CLI вызываются отдельно. `--предел-секунд` принадлежит только `готово`; независимый выбор там передаётся как `--выбранное-поручение`. У maker.prepare этот параметр называется `--доверенное-поручение`. Фасад не переносит флаги между разными parser contracts.

Настоящие малые сценарии находятся в [TDD-наборе](tests/test_подготовки_этапа_коммита.py), парное измерение способов композиции — в [профиле](tests/профиль_подготовки_этапа_коммита.py). Логические байты именованных читателей не доказывают физический I/O или отсутствие чтения во всём API. Кэш ОС не сбрасывается. Ограниченная подготовка не означает полной приёмки FUM-STEP-0235 или обработки полного диалога ROOT.

Корневой режим выбирается полем `начало`. Его точный вход содержит `вход_коммита`, `наполнение`, `план_наполнения`, `время`, `повтор`, `начало`, `проверки`, `связность`, `готовность`. Maker-вход остаётся прежней `.5`, без независимого ACT и полей обычного исполнителя. `повтор` равен false: этот режим создаёт новую отсутствующую папку, не возобновляя заполненный или закрытый этап. Повторные подготовки прежними API используют отдельные новые приватные выходы; существующие файлы не перезаписываются.

`начало` содержит метку действия и канонический заголовок. Владелец заранее выполняет слияние: чистый план сверяет физический корень, полный ref, HEAD, обоих родителей и фактический MERGE_HEAD; неразрешённый индекс или dirty-путь вне конечного разрешения получают отказ до start. Фасад не выполняет merge. Штатный план start заранее объявляет пару, реальных соседей и общий индекс; назначение модели ограничено `материалы/история-модели.json` новой папки. Перед установкой callback повторно сверяет состав, SHA, режимы и компоненты каждого пути, затем вызывает прежнюю установку start. Родитель новой модели создаётся только после пары.

Команды выбирает прежний читатель из подтверждённого полного LF-префикса с SHA и точным списком неоднозначных ID. Выбор сохраняет порядок и повторы A–B–A с разными ID; повтор одного ID запрещён. Глобальные raw-позиции сравниваются по подтверждённой идентичности native, включая копии источника. Для хронологии между источниками читаются только точные выбранные raw spans и исходные метки времени с временной зоной. Неизвестное или равное время разных native не восполняется предположением. Один и тот же массив текстов передаётся start и проверяется по настоящей выдаче maker; смысл и достаточность выбора определяет ROOT.

ROOT выбирает явные argv проверок, название, класс, UUID и следующий номер. Класс «полная» сверяется со штатным распознавателем exact smoke; наборы получает сама обёртка из фактического конверта. `связность` объявляет ещё один собственный UUID. `готовность` содержит весь выбранный упорядоченный массив UUID, включая связность, и положительный предел секунд. Перестановка или будущие UUID без настоящего успешного current v4 не объявляют готовность. Прежние терминальные записи остаются в разрешении, но не входят в массив будущих отсутствующих целей.

После prepare/fill, guarded recency и literal staging выполняются настоящие v4, предпросмотры, связность, staging исключённых свидетельств и читающее замыкание. Затем прежний типизированный API проверяет текущие stage0, модель, команды, v4 и связность и объявляет готовность. Его вложенные Python-проверки наследуют `PYTHONDONTWRITEBYTECODE`; прежнее значение среды восстанавливается даже при отказе. Фасад не создаёт квитанцию или коммит, не вызывает push, PR либо завершение чата. Законные эффекты до первого отказа сохраняются.

ROOT-наполнение требует хотя бы двух различимых стадий: фактическое наблюдение либо null с непустой причиной. Фасад не придумывает метрики. Парный ROOT профиль запускается с `--контур root5 --раунды 3`; для каждого из шести наблюдений setup и слияние вынесены за таймер. Ручной baseline независимо вызывает прежние API; execute фасада там не используется. Whole wall включает диагностику обеих сторон; отдельные стадии и вложенные времена не складываются повторно. Именованные читатели и проходы наблюдаются в parent и maker CLI, физический I/O, кэш ОС и ненаблюдаемые дочерние читатели остаются unknown. Raw SHA установленного ready независимо сверяется с результатом прежнего API. Сырые каналы сохраняются в новых приватных файлах0600; результаты различающихся физических привязок сравниваются по семантике, не по равенству всех SHA. Этот профиль измеряет композицию малой фикстуры и не утверждает ускорение полезной работы FUM. Обычный профиль fresh/repeat/tail остаётся доступен по умолчанию `ordinary7`.
