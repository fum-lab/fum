# Явная передача повторяемых пояснений

Версия `пояснения-1` выносит только точные значения `полный_снимок.формат` и `граница`. По умолчанию CLI и адаптер возвращают прежнее представление. Новая версия экспериментальная: измеренное уменьшение ответа не окупило определение, конверт и подтверждения в полном обмене.

## Выбор и граница

К обычным параметрам [CLI](scripts/показать-ответ-задачи.py) добавляются `--версия-передачи пояснения-1`, `--передача-пояснений <UUID>` и необязательный `--подтверждение-пояснений <JSON>`. Выбор независим от `--профиль прежний|порождённый`. У [Node-адаптера](scripts/адаптер_ответа.cjs) соответствующие параметры называются `версия_передачи`, `передача_пояснений` и `подтверждение_пояснений`; подтверждение передаётся объектом каждого вызова.

Конверт `fum.передача-ответа.1` содержит `передача`, `форма`, `данные`, `профиль` и `определение`. В полной форме `данные` равны прежнему объекту. В ссылочной форме удалены ровно два указанных поля, а определение заменено `null`; версия и SHA остаются в `профиль`. Полный оригинал, путь, SHA и размер, текст, ошибки, UUID, состояние, метаданные, указатели, пагинация, счётчики и явные признаки границ доказательства сохраняются.

[Определение](профили/пояснения-ответа-1.json) закреплено версией 1 и SHA-256 `8e1f2fd34c04c2937137388951ec0654b85cb06b6bb4326ed9da386fcd70080e`. Хэш вычисляется из объекта без поля `sha256`: UTF-8, сортировка ключей, компактные разделители JSON и завершающий LF, как в функции `закодировать`. Это не хэш форматированного файла. Декодер требует известный хэш и целочисленную версию; `true` и `1.0` недопустимы. Перед удалением сравниваются оба точных значения. Отсутствие, `null`, пустая или изменённая строка сохраняются полной формой.

## Цикл получателя

Получатель выбирает канонический UUID передачи для текущего доступного ему определения. Начальное чтение без подтверждения возвращает полную форму с определением. Отправка или кэширование этого ответа сами по себе ничего не подтверждают. После явного принятия получатель вызывает `подтвердить`; перед каждым следующим запросом он заново вызывает `подготовить_подтверждение`, передавая действительно доступное определение.

Пример отдельных действий Python-получателя после добавления каталога `scripts` этого инструмента в `PYTHONPATH`:

```python
from пояснения_ответа import подтвердить, подготовить_подтверждение, восстановить

# первый — полученный полный конверт; передача — UUID данного цикла.
определение = первый["определение"]
подтверждение = подтвердить(первый, передача)

# Перед каждым запросом; результат передаётся CLI или адаптеру.
готовое = подготовить_подтверждение(определение, подтверждение, передача)

# ответ — полученный конверт следующего чтения.
прежний = восстановить(ответ, определение, передача)

# При утрате определения старое подтверждение не используется.
определение = None
готовое = подготовить_подтверждение(определение, подтверждение, передача)
```

Последний вызов возвращает `None`: следующий запрос получает полную форму. При новом контексте получателя также выбирается новый UUID. Неизвестное, повреждённое или неподтверждённое определение не разрешает сокращение. Если определение потеряно уже после отправки запроса и пришла ссылочная форма, `восстановить` отказывает: нужно повторить чтение без подтверждения. Для принятого снимка используется режим `сохранённый`, поэтому повтор заново проверяет SHA файла, но не вызывает API и не записывает оригинал.

Код проверяет явные данные протокола, а не внутреннюю память модели. Получатель обязан снять подтверждение при утрате определения; произвольное повторение старого подтверждения вопреки этому контракту не доказывает доступность определения. Адаптер не хранит подтверждение в кэше снимка. Широкое подключение реального принимающего контура в этот этап не входит.

Повреждённый JSON подтверждения, неверная версия или UUID приводят к полной форме. Неизвестное значение самого флага `--версия-передачи` отклоняется как неверный выбор интерфейса. Недоступное локальное определение даёт полные данные и `null` в полях определения и профиля. Полная форма восстанавливается без определения.

## Бюджет и воспроизведение

Бюджет применяется к окончательному конверту UTF-8 с путём и LF после выбора полной или ссылочной формы. В новой версии промежуточное представление ограничено 1 МиБ; этот предел не означает разрешения превысить итоговый бюджет. При превышении CLI возвращает код 2 с пустым stdout, без усечения. Адаптер сохраняет предел 16000 байтов. Проверены границы N и N−1 для двух профилей и обеих форм, включая полную резервную выдачу.

Из корня FUM, через отчётную обёртку своей сессии:

```sh
PYTHONPATH=Инструменты/fum-svyaznostj-rabochej-sessii/tests python3 -B -m unittest test_пояснения_ответа
node --test --test-name-pattern='Пояснения требуют' Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_адаптер_ответа.cjs
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_передачи_пояснений.py --повторы 7 --выход <приватный-файл-профиля>
```

Нужны стандартная библиотека Python и Node.js для адаптера. Открытая фикстура занимает 642 байта. Профиль выполняет семь чередующихся пар для серий из 6, 24 и 8 чтений; в последней определение теряется. Первые два чтения полные, затем получатель явно подтверждает определение; после утраты цикл повторяется. CLI и диск настоящие, потребитель синтетический, вызовов API нет. Один временный файл записывается до измерения и удаляется после него. Подготовка параметров, CLI, разбор и восстановление входят во время; проверка семантики и подготовка файла исключены.

## Измеренный результат

[Итоговый профиль](../../Журнал/2026-09-15_06-33-09_MSK_вынести-повторяемые-пояснения-ответа/материалы/пояснения-профиль-итог.json) учитывает все пакеты параметров и ответов с UTF-8/LF. Вложенные определения и подтверждения показаны отдельно, но не прибавлены второй раз. Пакет параметров моделирует внешний запрос; аргументы локального процесса не считаются ещё одним JSON-пакетом. Сеть, оболочки MCP, токены и RSS не измерены.

Для 6 чтений общий обмен вырос с 18768 до 21766 байтов; для 24 — с 75072 до 80122; для 8 с утратой — с 25024 до 30564. Подтверждённый ответ уменьшился с 2769 до 2483 байтов, но запрос вырос с 359 до 759. Поэтому даже каждое последующее подтверждённое чтение увеличивает обмен на 114 байтов. 550 байтов строк, 554 с кавычками и 588 удаляемых пар с разделителями не являются чистой экономией.

Медианы полного цикла составили соответственно 305,421 → 316,443 мс; 1234,864 → 1284,996 мс; 406,604 → 426,769 мс. Все прошли заранее заданный предел накладных расходов: прежнее время плюс большее из 50 мс и 25%. Это не ускорение. [Первое измерение](../../Журнал/2026-09-15_06-33-09_MSK_вынести-повторяемые-пояснения-ответа/материалы/пояснения-профиль-до-оптимизации.json) сохранено отдельно; повтор выполнен после исправления строгости ссылки, без изменения порога или сценариев. Удаление подтверждений или других полей ради положительного результата не выполнялось. Прежний формат остаётся обычным путём.
