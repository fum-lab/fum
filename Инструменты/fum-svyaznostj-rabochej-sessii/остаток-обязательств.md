# Остаток обязательств задачи

Команда отвечает на три вопроса: какие известные обязательства сохраняются, какие этапы подтверждены и какую работу можно выполнять следующей. Она читает историю Git и печатает JSON. Следующую работу команда сама не запускает.

## Использование

Из корня checkout:

```bash
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/обязательства_задачи.py
```

По умолчанию используется реестр из наблюдённого `HEAD`. Несохранённые изменения checkout не подменяют его. Для проверки подготовленного изменения доступен явный ввод:

```bash
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/обязательства_задачи.py --кандидат-из-ввода \
  < Планирование/задачи/01a07d3d-d376-7ad2-aafc-67e4c25a67eb/обязательства.json
```

`--создать-основу` выводит исходные семь определений без работ и приёмок. Это средство восстановления происхождения; оно не заменяет текущий реестр. Все режимы только читают. Код выхода `0` означает корректно проверенный результат, включая наличие незавершённой работы; `1` означает ошибку чтения или контракта.

## Как читать результат

| Поле                                   | Значение для человека                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------ |
| `остаток_обязательств`                 | Все известные обязательства; принятие отдельного этапа не удаляет обязательство            |
| `подтверждённые_этапы`                 | Проверенные приёмки с отдельным признаком актуальности                                     |
| `неактуальные_приёмки`                 | Результаты или их предпосылки изменились после приёмки                                     |
| `работы_в_ожидании`                    | Причина ожидания и ссылка на проверяемое свидетельство                                     |
| `обязательства_без_следующего_этапа`   | Направления, для которых ещё нужно выбрать конкретную работу                               |
| `доступные_работы`, `следующая_работа` | Непринятые работы без ожидания, чьи предпосылки приняты и актуальны; порядок задаёт реестр |
| `вершина`, `sha256_реестра`            | Точный Git-снимок и байты проверенного реестра                                             |

Состояние `есть-доступная-работа` означает наличие следующего действия. `ожидание` возвращается только когда оставшиеся известные работы имеют подтверждённые причины ожидания и нет направления без следующего этапа. Иначе возвращается `требуется-план`. Ожидание одной работы не скрывает независимую доступную работу.

## Сохраняемые данные

В [реестре этой задачи](../../Планирование/задачи/01a07d3d-d376-7ad2-aafc-67e4c25a67eb/обязательства.json) каждое обязательство содержит идентификатор, родителя, вид результата и целую дословную команду с путём запроса и полным коммитом. Историческое происхождение сохраняется отдельно от принятого переноса в первичный checkout. Независимая граница импорта закреплена в исходнике: проверяемый JSON не может сам назначить себе новый генезис.

Работа содержит `идентификатор`, `обязательство`, `действие`, `основание`, `предпосылки`, `ожидание` и непустой список точных путей `результаты`. Основание совпадает с обязательством. Предпосылки образуют граф без циклов. Ожидание имеет причину и свидетельство с полями `коммит`, `путь`, `sha256`; отсутствие плана не маскируется ожиданием.

Приёмка этапа содержит `работа`, `коммит`, `запрос`, `финальный_запуск` и `результаты`. Каждый результат задаёт `путь`, `sha256` и Git-режим `100644` либо `100755`. Определение работы уже присутствует в коммите приёмки; хотя бы один заявленный результат изменён этим коммитом. Приёмка записывается позднее, когда известен коммит, и проверяется [читателем закрытого отчёта](../fum-otchyotyi-o-zapuskakh-proverok/связь-с-коммитом.md). Проверяются v3-свидетельства, исходная команда, UUID задачи, последний trailer коммита и точные байты результата. Вся цепочка предпосылок проверяется как на момент приёмки, так и на текущую границу.

Удаление или изменение определения, потеря приёмки и удаление реестра обнаруживаются на каждом ребре всей достижимой истории, включая обоих родителей слияния. Исчезновение с последующим восстановлением не считается непрерывным сохранением. Пакетное чтение уникальных деревьев сокращает число процессов Git, сохраняя все версии и рёбра. Shallow-история, grafts, символические ссылки вместо обычного файла и смена `HEAD` во время чтения отклоняются.

## Граница поставки

Реестр намеренно частичный: семь сохранённых обязательств не исчерпывают весь диалог. `завершение_задачи_доказано` всегда равно `false`. Команда не доказывает смысловое выполнение всей FUMA, не подключает Stop-hook, не переносит старые приёмки автоматически и не поддерживает приёмку merge-коммита с несколькими родителями. Полное переписывание истории без независимого внешнего якоря находится за пределами этой проверки.

В первой записи спланирован этап самого реестра; остальные шесть направлений явно показаны как требующие следующего этапа. Пустой список приёмок не означает, что предыдущая работа отсутствовала: эта версия не присваивает старым коммитам задним числом новые определения работ.

Исходное основание и обсуждение соразмерности процесса: [запрос текущего этапа](../../Журнал/2026-09-10_11-51-55_MSK_сохранять-остаток-обязательств/запрос.md). Сценарии отказов закреплены адресными тестами; [парный профиль](../../Журнал/2026-09-10_11-51-55_MSK_сохранять-остаток-обязательств/материалы/профиль-сравнения.json) сохраняет границы измерения и сравнение результата до и после оптимизации.
