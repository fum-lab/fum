# Независимое назначение текущего этапа

`fum.назначение-текущего-этапа.1` — отдельный конечный документ ROOT для явно
выбранного нового пути обычного ребёнка Maker10. Он связывает нынешние ветку и
основу с настоящим первоначальным рождением чата. Старые ACT, схемы Maker,
подготовки, квитанции и исторические повторы не переписываются. Сам документ
не создаёт пару, READY, Git-коммит или новый runtime.

ROOT независимо выбирает G по пяти полям: `координатор`, `исполнитель`,
`коммит`, `путь`, `sha256`. Копия в `Maker10.выбранное_поручение` должна совпасть
с этим внешним выбором, но сама его не заменяет. G хранится обычным Git100644
blob. Его коммит может находиться вне текущей истории ребёнка: child HEAD
остаётся на C. Документ не содержит собственного будущего OID. Поэтому выбор
G не требует очередного включения G в C и новой цепочки A/ACT.

## Закрытый документ

Кроме `схема`, обязательны ровно следующие поля:

| Поле | Значение |
| --- | --- |
| `этап` | Непустой конечный идентификатор с суффиксом `-vN` |
| `координатор`, `исполнитель` | Разные канонические ROOT и own UUID |
| `физический_корень_sha256` | SHA256 UTF-8 точного физического W |
| `ветка` | Полный назначенный `refs/heads/...`, без разрешения по префиксу |
| `база` | Ровно `коммит` C и его настоящее Git-`дерево` |
| `постановка` | Точный Git-selector исходного материала в C |
| `область` | Конечная согласованная область нового этапа |
| `цели` | Полный упорядоченный список разрешённых файлов Maker10 |
| `план_пары_sha256` | Raw SHA штатного JSON-плана ordinary renderer |
| `нативное_начало` | Настоящий birth-коммит и точные `граница`, `sha256` префикса |
| `нативное_поручение` | Префикс первого `create_thread` и `sha256_текста` приглашения |
| `команды_этапа` | Упорядоченный конечный список нынешних агентских сообщений ROOT |

JSON плана пары сериализуется штатно: UTF-8, `ensure_ascii=False`,
`sort_keys=True`, `indent=2`, один конечный LF. Его основание совпадает с
постановкой G. Две цели, ROOT, писатель и идентичность пары остаются прежним
контрактом ordinary renderer. G не расширяет `область` старого ACT и не
возобновляет закрытое прежнее поручение.

## Два разных нативных основания

Первоначальные `session_meta`, первый `turn_context` и первый `create_thread`
читаются прежним нативным читателем. Проверяются own UUID, тип рождения,
физический cwd, настоящий birth-коммит, отправитель ROOT и оба закреплённых
префикса. Birth остаётся предком C и может отличаться от C. Новый C никогда не
подставляется в старое `session_meta` или первоначальное приглашение.

У каждой команды текущего этапа ровно четыре поля: `начало`, `конец`,
`sha256`, `sha256_текста`. Это настоящая целая LF-строка собственного native
JSONL, тип `response_item/function_call_output`, точные namespace `codex_app` и имя `send_message_to_thread`
и буквальный транспорт `codex_delegation` от ROOT. Human-запись, чужой sender,
иной tool, перекрытие диапазонов и перестановка запрещены. Равный текст в
разных позициях сохраняется отдельными экземплярами. После чтения повторно
сверяются оригинальные байты, inode и нативные префиксы.

Новый вход выбирает только эти агентские команды. Он не объявляет их
человеческими и не разрешает прочие инструкции из вывода инструментов.
Первичные тексты пары и сообщения коммита совпадают с выбранными оригиналами;
заголовок коммита явно обозначает агентские поручения ROOT. Прежний human-reader
без нового внешнего допуска сохраняет своё поведение.

## Явный вход

Новый wrapper принимает внешний приватный selector отдельным аргументом:

```text
<проверенный-Python> -E -s -S -B \
  Инструменты/fum-svyaznostj-rabochej-sessii/scripts/назначение_текущего_этапа.py \
  --выбор <физический-приватный-файл-selector> --контур creator -- \
  подготовить --вход <Maker10> --доверенное-поручение <копия-selector> \
  --выбранный-состав <внешний-selector-S>
```

Конечный перечень контуров: `creator`, `typed`, `facade`, `coherence`, `pair`.
Последний допускает только `обычная-пара-план`/`обычная-пара-установить`.
Старые CLI не получают новых неявных флагов или переменных среды. Для Python
API внешний вызывающий явно использует `выбрать(selector)`; контекст
гарантированно сбрасывается при выходе и не принимает вложенную замену.

Точный ref должен принадлежать единственному зарегистрированному W. Перед
новым эффектом HEAD равен C; при историческом чтении сверяются исходные C и
его дерево, поскольку HEAD уже может быть результатом. Самостоятельный
Maker7 не получает новый допуск удалением контракта Maker10.

Версионный pin G, native и исполняемого stage-кода сохраняется в привязке
поручения и READY. Параметры, ключ и эпоха прежней готовности не заменяются.
Потеря внешнего выбора, смешанный selector или изменённая привязка запрещают
новое создание и чтение новой квитанции. Старые подготовки без stage pin
сохраняют прежний путь.

Фасад закрепляет отдельный selector-файл в снимке плана и передаёт его явным
wrapper новым процессам Creator и связности. Совпадающие копии поручения и
внешний selector имеют разные приватные роли. Прежний filler `.1` запускается
своим штатным CLI, сохраняя замыкание импортов, RAW, шаблоны и проверки.

Это доверенная композиция при одном писателе и удерживаемых входах. Фасад
проверяет G до и после filler, а filler `.1` сам не читает G перед каждым
файлом. Дрейф между этими границами может обнаружиться после записи пары;
нулевой эффект или атомарная защита G этим не доказаны. Неизвестный или
частичный исход сохраняется и запрещает слепой повтор.

## Воспроизведение

`tests/test_назначения_текущего_этапа.py` проверяет настоящий Git, разные
birth/C, внешний G вне C, UUID/W/ref/C/tree/цели, занятое дерево, native,
порядок повторов, потерю контекста, отдельные процессы и реальный цикл
Prepare → READY → Create → replay. Изоляция Git-конфигурации и templates
начинается до создания временных репозиториев.

`tests/профиль_назначения_текущего_этапа.py --выход <новый-приватный-JSON>`
измеряет три неизменных читающих допуска одного малого стенда. Подготовка,
снимки и сериализация исключены; первый lazy import и cProfile включены.
Результаты, вход, код и RAW pstats закрепляются SHA; Git и нативные байты
сверяются до/после. Кэш ОС не очищается. Этот профиль не измеряет весь ROOT,
реальный runtime или холодный запуск и не доказывает ускорения Creator.
Текущий результат профиля имеет схему `.2` с русскими полями
`интерпретатор`, `сырой_профиль` и вложенным полем `флаги`; прежние результаты `.1` сохраняются отдельно.
