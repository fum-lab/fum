# Передать внешний состав в дочернюю связность

Дочерняя проверка контрольной точки использует тот же внешний селектор S,
который уже проверен контрактом независимого Журнала. Селектор содержит коммит,
путь и SHA-256 сырых байтов состава. Его коммит может отличаться от HEAD писателя;
при этом живой состав обязан побайтово совпадать с выбранным Git-blob.

`check-session-coherence.py` передаёт `выбранный_состав` в `проверить_свежесть`,
а она — в `проверить_слой_разметки`. Дополнительного разбора или восстановления
селектора нет. Необязательный аргумент помощника сохраняет прежние автономные
вызовы: отсутствие выбора при отличающемся live S даёт отказ. Корневая ветка
ROOT9 продолжает вызывать прежнюю полную проверку свежести.

Полная проверка Markdown H и W, исходный индекс H, навигация S, права, сырые
материалы и повторная проверка контракта сохраняются. Неверный rawSHA/OID,
изменение живого состава между проверками, чужая разметка и удаление принятой
разметки не получают допуска.

## Воспроизвести проверку

Нужны Python 3.12+, Git и POSIX. Исходная основа — чистый checkout точного
коммита K568 `b2ae5245fb6607f9ebff2c6f868edc8b92336cda`. Git-объекты должны
быть доступны локально; сеть и секреты тестам не нужны. Публичная доступность
этого коммита проверяется отдельно. Параметр `--кандидат` указывает на checkout
с двумя проверяемыми модулями.

Запуски выполняются через обычную отчётную обёртку своей рабочей сессии:

```text
python3 -B Инструменты/fum-otchyotyi-o-zapuskakh-proverok/scripts/отчёты_о_запусках_проверок.py запустить --корень-репозитория . --запрос Журнал/<своя-папка>/запрос.md --название 'Проверить внешний состав ребёнка' --исполнитель 'писатель' --класс-проверки адресная -- python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/независимый_контур/test_свежести_внешнего_состава_ребёнка.py --код-K <чистый-checkout-K568> --кандидат <checkout-кандидата> --исходные-регрессии --выход <приватный-результат.json>
```

Без `--исходные-регрессии` выполняются девять адресных сценариев. Этот флаг
добавляет целиком четыре исходных набора K: независимую контрольную точку,
передачу выбранного состава, исторические режимы разметки и обычную связность.
В них остаются настоящие циклы ROOT9 и CHILD10 с временным Git.

Для RED добавить `--вариант основа --тест
ВнешнийСоставРебёнка.test_внешний_raw_S_проходит_настоящий_дочерний_CLI`:
исходный K возвращает код 1 с ошибкой `подменён Git-источник принятого состава`.
Кандидат на тех же условиях должен вернуть 0. Результат `--выход` содержит
манифест исходников и сырой вывод; он остаётся приватным, если содержит локальные
пути из диагностик.

Тест создаёт полную приватную Git-копию K с локальными объектами истории, копирует
её для кандидата и заменяет только два указанных модуля. Base/candidate исполняются
в разных процессах. Положительный путь вызывает настоящий CLI со всеми
проверками и Git-status. В тестах дрейфа обёртка сначала вызывает настоящую
проверку, затем меняет только временный вход; заглушек успешного допуска нет.

## Измерить расходы

В той же отчётной обёртке передать вместо теста следующую дочернюю команду:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/независимый_контур/профиль_свежести_внешнего_состава_ребёнка.py --код-K <чистый-checkout-K568> --кандидат <checkout-кандидата> --пар 3 --выход <профиль.json>
```

Каждая пара получает один и тот же подготовленный W, контракт, сообщение
коммита и селектор. Свежие процессы запускаются попеременно AB/BA. Подготовка
исключена; отдельно сохраняются wall всего процесса, интервал main, CPU, RSS и
вложенные интервалы реальных проверок. Вложенные интервалы не суммируются.
Хэши кода и неизменность входа сверяются; кэш ОС не очищается.

Серия с прежним S сравнивает одинаковый успешный результат. В серии внешнего S
старый код отказывает, кандидат принимает: разность времени такой серии не
является ускорением. Число вызовов чтения состава показывает, что композиция
аргумента не добавляет нового разбора. Основание дальнейшей оптимизации —
измерения; правка не требует повторного полного многочасового ROOT-контура.

## Граница поставки

Два исходника взяты точными Git/raw байтами из K568, поскольку birth постановки
старше этой принятой реализации. Поверх них изменена только передача аргумента.
Другие зависимости и нормативы K остаются исходными; весь K не переносится в
историю ветки ремонта. Тестовая копия K не активирует новый production Creator.
Публикационный ACT, совместимый wholeK Creator, приёмка K′, checkpoint и
интеграция выбираются ROOT отдельно.
