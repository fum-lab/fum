# Читать все исходные сообщения задачи

Этот сегмент FUM-STEP-0177 возвращает полный индекс пользовательских сообщений JSONL, включая сообщения до прежнего курсора. Он помогает восстановить исходный контекст после сжатия и увидеть многочастный ввод. Для сопоставления с сохранёнными ответами доступен [следующий сегмент обработки](обработка-сообщений.md). [Обязательный составной допуск](SKILL.md#решение-о-продолжении-задачи) проверяет обработку сообщений и поручения отдельно; успешное чтение не означает их выполнения.

## Запуск

Из корня своего checkout укажите JSONL корневой задачи, её `Codex-Thread-ID` и файл приватного кэша. Родительский каталог кэша должен существовать и находиться вне любого Git checkout. Команда не выбирает чужую задачу по похожему заголовку.

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/прочитать-сообщения-задачи.py --корень-репозитория . --исходник <локальный-JSONL> --codex-thread-id <UUID-задачи> --кэш <приватный-файл-кэша>
```

JSON в stdout содержит точные части сообщений, непрозрачные ссылки на вложения, исходный объект сообщения, байтовые позиции и SHA-256. Он приватный: не перенаправляйте его в отслеживаемый файл и не публикуйте целиком. Для Журнала отдельно выбираются публикационно допустимые команды и содержательные ответы. Медиа не скачиваются и не декодируются.

Флаг `--без-записи` отключает создание и обновление кэша и файлов блокировок. В этом режиме `--кэш` можно опустить: индекс строится в памяти. Если кэш указан, его существующая версия проверяется и читается без изменения; повреждение не скрывается пересозданием. Запускайте Python с `-B`, как в примере, чтобы интерпретатор также не создавал байткод.

| Код | Что произошло                                                                    | Дальнейшее действие                                                     |
| --- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 0   | В завершённом префиксе все выданные сообщения имеют подтверждённое происхождение | Рассмотреть сообщения вместе с поздними уточнениями                     |
| 3   | Есть неоднозначный ввод либо незавершённая последняя строка                      | Проверить происхождение либо дождаться дописывания и повторить чтение   |
| 2   | Источник или кэш не удалось прочитать и проверить                                | Сохранить прежние данные и разобрать причину; пустой результат не выдан |

Ни один из этих кодов не является разрешением завершить рабочую задачу. Обязательства пока проверяются отдельным действующим инструментом продолжения.

## Что сохраняется

Идентичность экземпляра связывает UUID задачи, SHA-256 первой строки `session_meta`, диапазон байтов и SHA-256 сырой строки с LF. Два одинаковых текста в разных сообщениях остаются двумя экземплярами. `event_msg` не экспортируется повторно. Повтор `response_item` с тем же транспортным ID и полностью одинаковым исходным объектом записывается как дополнительное представление прежнего экземпляра; разные объекты с одним ID отклоняются, включая конфликт с hook или служебным контекстом.

Классификатор вызывается до объединения содержимого. Служебные hook и контекст не становятся командами человека; неопределённое происхождение остаётся явным. Повреждённая оболочка `response_item` даёт отказ. Скрытые рассуждения и инструментальные результаты в индекс не экспортируются. Предел 64 МиБ относится к одной строке; весь файл может быть значительно больше.

Кэш содержит все найденные экземпляры, а не только хвост. Он устанавливается атомарной заменой с `fsync`; отдельный устойчивый lock-файл сериализует обновления. После прерывания исходный JSONL остаётся источником восстановления. Исчезновение, усечение или изменение уже прочитанного префикса не погашаются новым курсором.

## Скорость и граница доверия

При неизменных устройстве, inode, размере, `mtime_ns` и `ctime_ns` повтор использует сохранённый индекс. Это наблюдение метаданных локальной файловой системы, а не криптографическое доказательство неизменности байтов. При изменении файла прежний префикс полностью хэшируется и сравнивается; повторно разбирается только хвост. Изменение кода читателя или классификатора вызывает полный повторный разбор.

Флаг `--перепроверить` всегда заново читает и разбирает весь завершённый префикс. Этот режим нужен для независимой сверки, а быстрый режим — для повторных обращений при обычном локальном добавлении записей. Чтение ограничено размером файла при открытии. При дописывании завершённая граница независимо сверяется по SHA; усечение или изменение прочитанных байтов дают отказ. Метка кэша сохраняет исходный размер, чтобы последующее чтение обнаружило хвост.

`полнота_подтверждена` относится только к выбранному снимку. `размер_снимка` показывает его исходный размер, `неполный_хвост` — незавершённую строку внутри него, `дописано_после_снимка` — замеченные поздние байты. Последние ещё не классифицированы и не считаются отсутствующими сообщениями. Файловый замок защищает кэш, но не останавливает записывающий runtime; согласованная враждебная подмена источника, метаданных и кэша владельцем машины находится вне доказанной границы.

Профиль выводится отдельно от содержимого внутри поля `профиль`: прочитанные байты, число разобранных строк, режим и монотонные длительности. Вложенные интервалы не прибавляются повторно к общей длительности.

## Воспроизведение проверки и измерений

Адресный набор: `python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p 'test_сообщения_задачи.py'`. Он создаёт временные открытые фикстуры, не читая приватную переписку. В рабочей сессии запуск проходит через обязательную отчётную обёртку.

Сценарий `scripts/измерить-сообщения-задачи.py --повторов 3 --выход <файл-профиля>` воспроизводит источник больше 70 МиБ: старое поручение, два повтора одинаковой команды и позднее уточнение. Повторите с `--полное-чтение`, чтобы сравнить полный разбор с индексом при одинаковых входах и реализации. Сбор фикстуры исключён из измерения; сохраняются хэши кода, классификатора, сценария и входа каждой стадии. Максимальная память относится ко всему процессу, кэш файловой системы не сбрасывается.
