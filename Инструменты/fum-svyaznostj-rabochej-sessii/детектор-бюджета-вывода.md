# Автоматически выбирать компактное чтение по бюджету

Локальная команда сравнивает размер сохранённого остатка с заданным бюджетом stdout в **байтах**. При превышении она сама вызывает существующий компактный читатель; повторное поручение человека для выбора не требуется. При равенстве или меньшем размере возвращаются точные исходные байты, без пересериализации. Это не измерение токенов и не перехват всех инструментов Codex.

## Запуск

Сначала сохраните полный stdout основного `обработать-сообщения-задачи.py ... остаток --без-записи` вне checkout, отдельно запомнив его код завершения. Код 2 означает ошибку: старый файл не подставляется. Затем вычислите SHA-256 фактических байтов и вызовите:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/потребить-остаток.py --результат <приватный-файл.json> --sha256 <SHA-256> --код-производителя 3 --бюджет-байтов 16000 --начало 0 --число 1
```

stdout содержит только выбранные данные. stderr содержит отдельную JSON-квитанцию: сохраните её отдельно, если вызывающий инструмент иначе объединяет оба канала. Бюджет относится только к stdout; квитанция не скрывается в этом числе. На открытом профиле она занимает 808 байтов дополнительно. Скрипт ничего не записывает, не запускает производителя, не выполняет команды из данных, Git или сеть. Привязку приватного пути, запуска производителя и его кода сохраняет вызывающая сторона.

Код CLI 0 означает успешный выбор представления, а не пустой остаток. Исходный код 0 или 3 сохраняется в квитанции и проверяется на согласованность с `разбор_сообщений_завершён`. Переданный код не доказывает подлинность внешнего запуска. Код CLI 2 означает отказ с пустым stdout и отдельной диагностикой: неверный SHA, код, JSON, схема, идентичность задачи, параметры либо превышение бюджета страницы. Ошибку нельзя заменять прежним успешным результатом.

## Границы выбора

Принимается только `fum.остаток-сообщений.1`, не более 128 МиБ, с каноническим UUID задачи. Порог — явно переданное целое от 100 до 1 048 576 байтов; булево значение не принимается API. Формула срабатывания: фактическое число байтов полного файла строго больше бюджета. LF исходника входит в его размер; LF компактной страницы входит в размер вывода.

Параметры `начало` и `число` выбирают страницу только при превышении. По умолчанию это первое сообщение; автоматического поиска последнего или самого удобного сообщения нет. Если заданная страница не помещается, уменьшите число; если не помещается одно сообщение вместе с оболочкой, рассмотрите полный приватный артефакт адресно или явно увеличьте бюджет. Содержимое не усекается и сообщения не пропускаются автоматически.

Полный файл остаётся источником всех оригиналов, повторов, поздних связей и происхождения. Страница содержит SHA полного файла, указатели, счётчики и признаки полноты по [существующему контракту](компактный-остаток.md). Следующая страница относится только к тому же файлу/SHA. Конец последней страницы не подтверждает рассмотрение предыдущих сообщений. Живой JSONL не перепроверяется, обработка и выполнение обязательств не подтверждаются.

Это ограниченная реализация реакции на измеренное превышение одного сохранённого вывода. Синтетический бюджет `Проекты/рабочий-контекст/сборщик.py` относится к другому формату. Декларативные ДЕТЕКТОР-03, 04 и 08 не объявляются полностью подключёнными или откалиброванными. Статистика вызовов JSONL не подключается к этому входу автоматически. Для реального runtime вызывающая сторона должна направлять сохранённый результат в этот CLI; общий перехват отсутствует.

## Проверка и профиль

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_детектор_вывода.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_детектора_вывода.py --выход <профиль.json>
```

В рабочей сессии команды выполняются через отчётную обёртку. Десять тестов проверяют автоматический выбор, N/N−1 полного файла и страницы, точные исходные байты, согласованность кода, ограниченную идентичность квитанции, неполноту, детерминизм и отсутствие частичного вывода.

Открытый профиль использует один файл 12 003 881 байт, семь чередующихся пар ручного и автоматического выбора одной и той же страницы. Выходы побайтово равны: 2305 байтов страницы и дополнительно 808 байтов квитанции детектора. После устранения двойного разбора медиана детектора снизилась с 38,112208 до 24,239167 мс; ручной выбор в итоговом прогоне — 19,258375 мс. Автоматическое решение имеет дополнительную стоимость. Критерий до оптимизации: та же выдача и не хуже исходной медианы плюс максимум из 5 мс и 25%; он выполнен. Подготовка, файловый ввод, запуск Python, сеть и запись профиля не входят в эти интервалы. Это не профиль всего рабочего цикла.
