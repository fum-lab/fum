# Нативная читающая подготовка базиса

Мост подтверждает один настоящий запуск прежнего CLI с `--подготовить-запуск`. Он сохраняет отдельные исходы внешнего host-процесса, наблюдателя и подготовительного subprocess. Его свидетельство не разрешает эффект B, запись состояния узла, запуск чатов или продолжение старого поколения.

## Состав и независимый выбор

[Генератор](scripts/сформировать_нативный_вызов.py), [наблюдатель](scripts/наблюдать_подготовку_базиса.py), [читатель](scripts/сверить_нативную_подготовку.py) и [точный CJS](scripts/вызов_нативной_подготовки.cjs) образуют новый слой. Прежние [CLI](scripts/запуск_приёма_базиса_узла.py) и [сырой модуль](scripts/приём_базиса_состояния_узла.py) остаются неизменными. Шесть фиксированных путей выбираются по принятым commit/blob/SHA/длине; их импорты ограничены стандартной библиотекой.

ROOT выбирает принятый код, физические корни кода и узла, отдельный UUID исполнителя host, точный восьмиполевой вход `fum.вход-приёма-базиса-узла.2`, прежний четырёхполевой ключ, K, R/A/ACT/G/nonce, свежую запись поколения без паузы, физический Python и конечные бюджеты. JSON канонический, без повторных полей и произвольных команд, wrapper, callback, import-path или eval. Вход, поколение и выбор — собственные физические файлы mode0400/nlink1; ожидаемые байты и физические идентичности проверяются раздельно.

Физические корни сессии Codex и читаемого узла могут различаться. Владелец узла из прежнего ключа не подменяется UUID исполнителя host. Независимое ожидание читателя фиксирует оба контекста явно.

## Exact JS и host API

Tracked CJS — незапускающееся async function-expression с точным окончанием `;\n`. После конечных JSON-quoted строковых подстановок генератор снимает только эти два байта и добавляет закреплённые pragma, один outer await и вызов. Хэшируется вся исполняемая композиция. Изменённый await, иной вызов либо дополнительные байты не принимаются.

`tools.exec_command` вызывается ровно один раз с полной формой `cmd/workdir/shell/login/max_output_tokens/yield_time_ms`: shell всегда `/bin/sh`, login всегда false. Полей `argv` или `env` в host API нет. Внутренняя среда очищается через фиксированный `env -i` и `Popen(env=...)`. Все подстановки — строки; команды формируются только фиксированным алгоритмом с shell quoting.

При живой session JS опрашивает только первоначальный числовой session_id, пустыми последовательными write_stdin, с заранее выбранными пределами. Каждый исходный host-объект сохраняется без пересериализации его stdout. Чужая session, terminal до конца цепи, truncation либо отсутствие terminal host0 закрывают сверку.

Нативный внешний exec должен завершиться в одном результате. `Script running with cell ID` остаётся неполным исходом; functions.wait в этой версии моста не поддерживается. Превышение внешнего времени не разрешает повтор процесса.

## Удержанные байты и сохранение исхода

Открытые source/input FD удерживаются до terminal. Первый фиксированный загрузчик исполняет выбранные байты генератора и наблюдателя. Наблюдатель запускает один отдельный изолированный Python; launcher компилируется в отдельном пространстве имён без автоматического footer.

Фиксированный адаптер входа воспроизводит физический путь, mode0400/uid/nlink1 и девять полей fingerprint прежнего читателя, читает только выбранный input из удержанного FD и передаёт остальные пути прежней функции. Фиксированная защита compile сохраняет все прежние проверки Git/Q/импортов и исполняет именно удержанные raw bytes для единственного имени K:путь. Успех требует ровно одного чтения входа и одной такой компиляции. `/dev/fd` не выдаётся за физический inputPath.

Приватный родитель выводится из owner/W/ref, слот — из R. O_EXCL/NOFOLLOW и исключительный mkdir сохраняют прежнее намерение; новый nonce не сбрасывает слот с неизвестным процессом. До Popen синхронизируются запись слота в родителе и намерение. При любом выходе после запуска сначала останавливается и собирается вся собственная process group, затем сохраняются полные stdout/stderr и аудит. Неизвестная остановка оставляет намерение без успешного terminal. Terminal устанавливается атомарно без замены. Исходная ошибка, сигнал и timeout сохраняются отдельно. Любой прежний слот закрывает новый запуск; автоматического retry нет.

Python выбирается по физическому пути, SHA и идентичности и пересверяется после процесса. Предполагается доверенный установленный toolchain и добросовестный единственный писатель. Защита от враждебной подмены same-uid во время path→exec или системных библиотек здесь не заявляется.

## Адресная native-сверка

В наблюдённом клиентском формате functions.exec хранится как response_item/custom_tool_call с name `exec`; исход — custom_tool_call_output. Читатель проверяет независимые spans/raw SHA первоначального session_meta и полного выбранного интервала turn_context→terminal output, UUID, turn_id, call_id, порядок и всю композицию JS.

Исход содержит ровно два input_text: terminal-заголовок host и один типизированный JSON с исходными host-объектами. Лишние, повреждённые, повторные и отсутствующие блоки отвергаются. Весь ограниченный интервал проходит проверку оболочек UTC/ordinal и конечных поддержанных форм reasoning, assistant message, token_count, token_usage_record и транспортных item_completed. Неизвестные формы и ключи закрывают эту версию. Метаданные вызова могут отсутствовать; client_authored:true у адресной пары запрещён, у исхода нужен false.

Предшествующие primary-пары с другими call_id должны замкнуться до выбранного вызова. Новый primary call внутри выбранного исполнения запрещён. Транспортная копия CommandExecution сама не считается вторым authoritative вызовом. Внутри выбранного интервала адресная пара единственная. Полнота всей истории ROOT и глобальная уникальность call_id за пределами этого интервала этим контрактом не утверждаются.

Успех требует host0 без живой session, наблюдатель0, preparation0, полного неизменённого намерения/receipt/каналов и стабильного поколения. Исторические файлы после паузы сохраняются; они не дают новый эффект.

## Воспроизведение и границы измерения

[Адресные тесты](tests/test_нативной_подготовки_базиса.py) используют полный временный Git, настоящие подготовительные процессы и явно синтетические native host-рамки. CJS/Node syntax-check и синтетический harness не доказывают настоящее исполнение Codex.

Из чистого клона нужны Git, Python 3.14 и Node.js с ESM. Из корня запускаются следующие команды; в рабочей сессии каждая исполняется через обычную отчётную обёртку своего Журнала:

```sh
python3.14 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_нативной_подготовки_базиса.py -v
python3.14 -B -m unittest discover -s Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/tests -p test_сценариев_полного_ответа.py -v
python3.14 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_нативной_подготовки_базиса.py --повторов 3 --выход /путь/к/новый-профиль.json
```

Генератор вызывается с `--выбор /путь/к/выбор.json --sha256 SHA_ВЫБОРА`, читатель — с `--ожидание /путь/к/ожидание.json --sha256 SHA_ОЖИДАНИЯ`. Точные закрытые формы создаёт открытая полная фикстура теста; ROOT закрепляет свои физические входы и принятый код независимо. Полученные JS-байты должны быть переданы без редактирования в native functions.exec. Это отдельный разрешённый ROOT pilot после приёмки кода.

[Профиль](tests/профиль_нативной_подготовки_базиса.py) различает подготовку, процесс, сохранение каналов, native parsing и перечитывание, сохраняет размеры/SHA и исключает создание фикстур. Внешние callback/model/network не подставляются в измерение. Тесты и профиль запускаются через обычную отчётную обёртку своей задачи.

Новый слой отдельно ограничивает файлы и адресные spans 32 MiB, глубину JSON 128 уровнями независимо от декодера Python, адресный интервал 131072 рамками, один Git-процесс 120 секундами, подготовительный subprocess выбранными 1–120000 мс и каждую попытку очистки группы 5+2 секундами. Host допускает один exec и 0–10 пустых polls с суммарным выбранным ожиданием до 55 секунд; это не общий срок CLI или reader. Незавершённый внешний host сохраняет отказ сверки и не разрешает повтор. Эти ограничения принадлежат данной версии читающего моста.

Полная постановка: [ACT19](../../Планирование/параллельные-постановки/2026-10-13/создать-нативный-мост-подготовки.md). Служебный состав исправлен независимым ACT20. Первый настоящий ROOT RO pilot выполняется после приёмки кода отдельно. Прежний эффектный допуск .2 требует literal namespace fum/function_call; generic exec туда не подключён. Прежние 131072 рамки/120 с относятся к последующему native effect; их повышение, R1/state2, массовый запуск и пересборка проекции в этот слой не входят.
