# Читать остаток небольшими страницами

Команды показывают выбранные оригиналы остатка без сокращения содержимого. Если полный результат помещается в инженерный предел, его сначала сохраняют приватно и читают по raw SHA-256. Если сериализация полного результата сама превышает предел транспорта, один живой процесс вычисляет и проверяет остаток один раз, удерживает неизменяемый снимок в памяти и обслуживает страницы без полного stdout.

## Живой сеанс без полного stdout

Запустите обязательный читатель в режиме `живые-страницы --без-записи` с теми же корнем, корневым UUID и исходным JSONL:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/обработать-сообщения-задачи.py --корень-репозитория . --исходник <JSONL> --codex-thread-id <UUID> живые-страницы --без-записи
```

После единственного вычисления процесс печатает одну строку JSON схемы `fum.сеанс-живых-страниц-остатка.1` и немедленно сбрасывает stdout. Дескриптор ограничен 64 КиБ; он содержит `снимок_sha256`, поколение истории, проверенную границу источника, счётчики и явные признаки `полный_результат_сохранён=false` и `завершение_задачи_доказано=false`, но не переносит произвольные строки причин. `снимок_sha256` — SHA-256 канонической семантической сериализации всего результата без изменчивого диагностического поля `профиль`; это не raw SHA несуществующего полного файла.

Тому же процессу передают по stdin строго по одному завершённому LF JSON-объекту. Запрос страницы повторяет SHA дескриптора:

```json
{"схема":"fum.запрос-страницы-живого-остатка.1","снимок_sha256":"<SHA-256>","начало":0,"число":20,"максимум_байтов":16000}
```

Ответ `fum.страница-живого-остатка.1` повторяет идентичность источника и содержит точные целые объекты выбранных сообщений, включая `сырой_объект` и `дубли`, их порядок и индексы, причины остатка, число поздних связей и последнюю обработку. Полный квадратичный массив поздних связей в страницу не копируется. `следующее_начало` выбирает следующую страницу того же снимка. Процесс заканчивают явной командой с тем же SHA:

```json
{"схема":"fum.завершение-сеанса-живых-страниц.1","снимок_sha256":"<SHA-256>"}
```

Команда ограничена 64 КиБ. Число сообщений страницы — от 1 до 1000, бюджет ответа с LF — от 100 байтов до 64 МиБ. Превышение бюджета, неверный SHA, повтор JSON-поля, лишнее поле, неизвестная команда, EOF без завершения и повреждённый ввод закрывают сеанс с кодом 2; частичная страница не выдаётся. Явное закрытие возвращает код 0 только для завершённого разбора и код 3 при остатке или неполном вводе. Данные не усекаются: нужно уменьшить число сообщений или явно увеличить бюджет. Признак `живой_источник_перепроверен_при_создании_снимка=true` устанавливает только CLI после заключительной сверки основным читателем; общий модуль без этого происхождения возвращает `false`. После изменения источника нужен новый процесс.

Живой режим не создаёт кэш, lock, полный результат или иной артефакт и разрешён только с `--без-записи`. Дескриптор и страницы содержат приватный ввод; их нельзя автоматически переносить в репозиторий. Успешное явное закрытие означает лишь завершение протокола чтения: оно не подтверждает просмотр всех страниц, смысловую обработку сообщений, погашение обязательств или завершение задачи.

## Страница сохранённого результата

Сначала выполнить [обязательное чтение](обработка-сообщений.md) с `остаток --без-записи` и явно сохранить stdout вне checkout. Код 0 или 3 допускает разбор полученного JSON; код 2 означает ошибку, которую нельзя заменить прежним успешным файлом. Сохранение stdout выполняет вызывающая сторона: исходный беззаписный читатель не создаёт артефакт.

Для страницы указать полный файл, заранее полученный SHA-256 именно его байтов, начальный номер сообщения с нуля и число сообщений:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/показать-остаток.py --результат <приватный-полный-результат.json> --sha256 <SHA-256-полного-файла> --начало 0 --число 10 --максимум-байтов 16000
```

Команда ничего не записывает и не запускает Git, сеть или инструменты из содержимого. Она проверяет хэш всех прочитанных байтов, разбирает JSON с запретом повторных ключей, проверяет ссылки экземпляров и возвращает новую оболочку `fum.страница-остатка.1`. Полный файл и все выдаваемые оригиналы остаются приватными. Файл ограничен 128 МиБ; число сообщений — от 1 до 1000; предел ответа — от 100 байтов до 1 МиБ, по умолчанию 16000 UTF-8-байтов, включая LF. Это инженерные пределы, не лимит токенов модели.

Код 0 означает только успешное представление страницы. Код 2 означает отказ, stdout пуст. При превышении бюджета нужно явно уменьшить число сообщений или увеличить бюджет; текст и вложения не усекаются. Если одно сообщение больше максимального бюджета, его необходимо рассмотреть непосредственно в полном артефакте. Гарантии компактности не подменяют сохранение данных.

## Как продолжить чтение

`следующее_начало` задаёт следующую страницу **того же** файла с тем же SHA. `null` означает достижение конца выбранного снимка, а не просмотр всех предыдущих сообщений и не завершение работы. `показаны_все_сообщения` истинно только для выдачи всего списка от нулевого номера. `непоказанных_необработанных`, общие причины и указатель корневого массива `остаток` показывают оставшийся за пределами страницы разбор.

Указатели имеют формат JSON Pointer: начальный разделитель U+002F, ключ `сообщения`, ещё один разделитель и номер `17` обозначают элемент 17 в полном массиве. `указатель_обработки` ведёт к его причинам, полной последовательности `поздние` и последней записи обработки. Уже обработанное позднее сообщение тоже можно выбрать по его номеру; одинаковые тексты не объединяются.

Страница сохранённого результата не подтверждает актуальность живого JSONL. Она сохраняет наблюдённые полноту, непроверенный хвост, границы и хэш источника из полного результата и отдельно указывает `живой_источник_перепроверен=false`. После нового ввода нужен новый результат обязательного читателя. Номер страницы старого файла нельзя автоматически переносить на другой файл или живой снимок: автоматический курсор между поколениями не реализован.

Все сообщения остатка по-прежнему требуется рассмотреть с поздними уточнениями и видимыми ответами. Их учёт и исполнение обязательств остаются разными состояниями. Эта команда не извлекает ответы ассистента, не распознаёт смысл отмены, не меняет историю обработки и не разрешает завершение задачи. Основной читатель и составной допуск не изменены.

## Проверка и измерение

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_компактный_остаток.py
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_живые_страницы_остатка.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_компактного_остатка.py --выход <профиль.json>
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_живых_страниц_остатка.py --выход <новый-профиль.json>
```

Открытый профиль сравнивает полную сериализацию и страницу последних 10 из 400 сообщений на одних байтах. Подготовка входа и запись результатов исключены из внутреннего времени; хэш, разбор и сериализация включены. Семь пар чередуют порядок вариантов. Память Python измеряется отдельно. Сокращение вывода не является измерением токенов, качества решений или ускорения всего рабочего цикла.
