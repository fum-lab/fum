# Загрузить конечный набор проверенного кода

Первый автономный сегмент удерживает Python-байты конечного пакета из выбранного Git-коммита Q. Внешне доверенный вызывающий код закрепляет Q, режим, Git blob OID и SHA-256 bootstrap, а также SHA-256 сырых байтов манифеста. После получения снимка контролируемая загрузка использует удержанные байты: замена checkout W, исходников и pyc не выбирает другой код.

## Независимый вход и полный инвентарь

[Вход](scripts/проверенный_код/вход.py) — часть доверенного вызывающего кода. Он не становится доверенным вследствие своего расположения в W или `__file__`. Его происхождение и независимые закрепления обязан определить вызывающий слой. `FUM_CHECKED_CODE_ROOT` не читается. Новая версия Q или манифеста не переопределяет уже выбранные закрепления.

Вход `получить_снимок(корень, закрепление, манифест)` принимает физический Git-репозиторий, независимый словарь и исходные `bytes` JSON. Словарь содержит ровно `коммит`, `начало`, `манифест_sha256`. `коммит` — полный lowercase OID. `начало` содержит ровно `путь`, `режим`, `blob`, `sha256`; разрешён обычный режим `100644`, последнее имя относительного пути — `начало.py`. Технические `blob` и `sha256` обозначают идентичность Git blob и алгоритм внешнего закрепления.

Вход читает bootstrap через Git как данные, сверяет его запись дерева и оба хэша, затем компилирует и исполняет эти же удержанные байты. Git replace refs отключены в обоих читателях. Манифест не содержит собственного Q: такой самоссылочный OID нельзя записать в тот же коммит. Q выбирается независимым входом.

Манифест схемы `fum.проверенный-код.1` содержит ровно `схема`, `пространство`, `каталог`, `модули`. Этот сегмент поддерживает один корневой Python-пакет: `пространство` — идентификатор, `каталог` ему равен. Каждая запись модулей содержит ровно `имя`, `путь`, `режим`, `blob`, `sha256`. Для `__init__.py` имя соответствует пакету; для остальных `.py` — модулю. Каждый родитель должен иметь объявленный `__init__.py`. Namespace packages, дополнительные данные и внешние зависимости внутри конечного дерева этим форматом не описываются.

[Bootstrap](scripts/проверенный_код/начало.py) до исполнения любого помощника сверяет весь рекурсивный Git-инвентарь каталога с манифестом. Удаление неиспользуемого модуля, bootstrap или `__init__.py` из списка тоже отвергается. Пути не нормализуются в разрешённые: абсолютные, повторные, с `..`, пустыми компонентами, неверным регистром, symlink, gitlink и режимом кроме `100644` дают отказ. Повтор JSON-ключа, записи модуля либо пути Git-дерева, коллизия `пакет.py`/`пакет/__init__.py` и неизвестные поля также дают отказ.

Blobs читаются одним `git cat-file --batch`. Проверяются OID, тип, десятичная байтовая длина, разделитель каждого ответа и точное завершение потока. Для каждого тела отдельно вычисляются SHA-256 и Git-хэш `blob <байтовая длина>\0<сырые байты>`. Кириллица и CRLF не декодируются для вычисления хэша. У bootstrap и помощников тот же полный инвентарь; лишь после его сверки удержанные `снимок.py` и `загрузчик.py` исполняются как начальная часть.

## Активный контекст

[Снимок](scripts/проверенный_код/снимок.py) удерживает неизменяемые отображения исходных байтов и записей. `снимок.исполнение()` компилирует набор и возвращает [контекст](scripts/проверенный_код/загрузчик.py). Пример для открытой фикстуры:

```python
снимок = получить_снимок(корень, закрепление, манифест)
with снимок.исполнение() as сеанс:
    программа = сеанс.загрузить("контур.программа")
    результат = программа.позже()
```

Finder принадлежит точному корню `контур` и префиксу `контур.`; соседний `контур2` не затрагивается. На входе удаляются все прежние записи этой области `sys.modules`, включая неизвестные имена и `None`. Пакеты получают путь без каталогов W. Объявленный модуль исполняется из кодового объекта снимка; неизвестному модулю отказано без обращения к обычному finder или pyc.

Публичный загрузчик сверяет принадлежность, объявленность и идентичность объектов кэша. Исполняемые модули получают локальную копию `__builtins__` с охраной `__import__`: обычный и отложенный import проверяют scoped-кэш до и после импорта. Вставленный после входа чужой объявленный объект либо неизвестный scoped-модуль отвергается. Проверяется также привязка объявленного дочернего модуля к атрибуту родительского пакета. Точные строковые ключи `find_spec`, `create_module`, `exec_module` принадлежат внешнему протоколу Python; собственные callbacks названы по-русски.

При нормальном выходе и исключении все новые scoped-записи удаляются, прежние объекты возвращаются по идентичности, прежний список `sys.meta_path` восстанавливается. Частично установленный finder при отказе входа также убирается. При каждом повторном входе реестр доверенных объектов очищается: сохранённый объект прежнего входа не принимается новым сеансом. Общий процессный замок на доверенном `sys` запрещает перекрытие даже разных снимков. Используются согласованные сеансы одного процесса; произвольные конкурентные мутации глобального состояния не изолируются.

Вызовы загруженных функций и отложенные импорты относятся к поддержанному свидетельству только внутри активного контекста. После выхода публичная загрузка и охраняемый import отказывают; функция без import всё ещё может вычислять значение. Сохранённый объект модуля не становится отдельным разрешением исполнять его вне контекста.

## Воспроизведение

[Решающий набор](tests/test_проверенного_кода.py) создаёт локальные Git-репозитории без сети и секретов. [Профиль](tests/профиль_проверенного_кода.py) использует те же открытые фикстуры, фиксированные авторские даты, прогрев и три измерения. Прямые команды запускаются действующей отчётной обёрткой собственной пары Журнала:

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_проверенного_кода.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_проверенного_кода.py --набор малый --выход <новый-JSON>
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_проверенного_кода.py --набор пакет --выход <новый-JSON>
```

Профиль исключает создание Git-фикстуры. `получение_снимка_нс` — внешний интервал; `чтение_сверка_нс` и `компиляция_входа_нс` вложены в него и не суммируются с ним. Затем отдельно измеряются компиляция всего набора при создании контекста и загрузка с полезным вызовом внутри контекста. Каждый опубликованный агрегат — самостоятельная медиана трёх значений; сумма медиан не выдаётся за наблюдённый общий интервал. Объём — сумма удержанных исходных байтов модулей, без повторного учёта вложенного bootstrap; это не RSS и не память кодовых объектов.

Исходный профиль серийного чтения обнаружил преобладание чтения и сверки. Поэтому выбран `--batch`; корректность и производительность повторно проверены, исходные и итоговые source SHA сохранены в [материалах сегмента](../../Журнал/2026-10-09_20-16-16_MSK_загрузить-проверенный-код/материалы/). Точные замеры и сравнение находятся в отчёте; ускорение полного контура FUM не выводится из этих фикстур.

## Граница результата

Python-интерпретатор, stdlib, Git и доверенный вызывающий вход — явные предпосылки. Это ограниченная охрана обычных импортов выбранного пространства, не глобальная песочница для произвольного Python, другого loader, прямого `exec`, `importlib.import_module` из постороннего кода или `subprocess`. Злоумышленник, способный переписать состояние загрузчика, словари уже созданных модулей, охраняемый `__builtins__`, stdlib либо одновременно мутировать Python между проверками, находится вне этой границы. Прямые альтернативные API из тела проекта требуют отдельного последующего контракта.

Полнота реального FUM Q, интеграция восьми существующих consumers, связь prepare/ready/create/v4 с argv и live W7964 не проверялись. Действующий исполнитель W7964 и D22 остаются на паузе. Коммит сегмента является дочерней контрольной точкой, а не общей приёмкой, интеграцией или завершением ROOT.
