# Контракт сохранённых обязательств v2

Реестр сохраняет исходные результаты между этапами одной задачи. Работы этапа объясняют следующий шаг, но не определяют полный остаток. Проверка читает реальный Git и обычные локальные файлы, не пишет checkout, индекс, refs или журналы.

## Входные схемы

Фиксированный путь реестра — `Планирование/задачи/<корневой-UUID>/обязательства.json`. Точные поля:

- `схема`: `fum.обязательства-задачи.2`;
- `задача`: канонический UUID, совпадающий с `--codex-thread-id`;
- `исходный_коммит`: полный достижимый OID коммита до первого появления реестра, предок каждого его первого введения;
- `план_этапа`: канонический относительный путь JSON-плана;
- `обязательства`: непустой список объектов.

Обязательство содержит ровно `идентификатор`, `родитель` (null либо известный ID), `основание`, `вид_результата` (`реализация` или `документ`), `карточка` (null либо `FUM-STEP-NNNN`), `приёмки`. Идентификаторы уникальны; циклы запрещены. Основание содержит ровно `коммит`, `запрос`, `цитата`: полный OID предшествует введению обязательства, обычный файл `Журнал/<временной-префикс>/запрос.md` существует именно в этом коммите, цитата находится в его единственном дословном разделе и принадлежит той же корневой задаче.

Каждая приёмка содержит ровно `запрос`, `запуск`, `результаты`. Запрос указывает на локальную закрытую историю; запуск — канонический UUID успешной записи `fum.test-run.v4`; результаты — непустой список объектов с точными полями `путь`, `sha256`. Хэш — 64 строчные шестнадцатеричные цифры без префикса. Повторные пары запрос/UUID и повторные пути, включая регистровые и нормализационные дубликаты, запрещены.

План `fum.продолжение-задачи.2` содержит ровно `схема`, `задача`, `режим`, `остановка`, `работы`. Режим — `постоянная` или `разовая`; для v2 это не меняет требования доказательств. Работа содержит ровно `идентификатор`, `обязательство`, `действие`, `состояние`, `основание`, `свидетельство`. Состояния — `доступна`, `ожидает-ответа`, `завершена`; доступная работа имеет null-свидетельство, остальные — непустое. Основание работы содержит `запрос` и `цитата` из текущего локального первичного источника. Неизвестные поля и повторные ключи JSON закрывают проверку отказом.

## История и результат

Исходная база и определения обязательств неизменяемы; допустимы только новые обязательства и добавочные приёмки. Проверяется каждая вершина и каждый родитель достижимого DAG. Удаление с восстановлением, новый genesis, потеря второго родителя при merge и конфликт одного ID не скрываются текущим хорошим файлом. Новый рабочий реестр может добавлять ещё не закоммиченную карточку: это незавершённый остаток, а не ошибка завершения.

Карточки читаются из HEAD с точным TOML `schema_version`, `card_id`, `status` и соответствующим именем. Для погашения обязательства с карточкой нужен статус `completed` и собственная приёмка. Ребёнок не закрывает родителя; родитель может не иметь карточки. Принятие документа не подтверждает `реализация`: нужен хотя бы один обычный исходник поддержанного языка вне документационных и журнальных областей. Это формальный фильтр, а не доказательство полезности кода.

Приёмка проверяется по каноническим байтам закрытого снимка `fum.test-run-report.v3`, точным хэшированным байтам всех записей и точному Markdown-блоку отчёта. Чистый план раундов должен быть `готов`; один успешный UUID в незавершённой истории недостаточен. С первого появления снимка весь закрытый набор, включая отчёт, остаётся неизменным во всех достижимых коммитах и на диске. Согласованная перепись JSON и отчёта тоже отклоняется.

Проверка находит достижимый коммит с той же приёмкой в реестре и тем же закрытым набором, затем восстанавливает его содержательный v4-отпечаток непосредственно из Git-объектов. Так доказывается связь предкоммитного запуска с фактическим принятым содержимым, без требования ошибочного равенства старого HEAD отпечатка новому HEAD после commit. Исключения из отпечатка точно повторяют v4: текущий отчёт, его каталог запусков и `Proyekcii/**`.

Все исторические приёмки должны быть достоверны. Для текущего погашения достаточно одной, чьи заявленные результаты совпадают с HEAD и обычными файлами на диске. Законное изменение кода требует добавочной приёмки нового этапа; старая сохраняется как история. Нельзя считать действительной старую приёмку изменённого результата. Подмена рабочего файла даже с `assume-unchanged` обнаруживается прямым чтением. Перед ответом повторно сверяются HEAD и прочитанные рабочие байты/режимы.

## Решение для Stop

Штатный stdout — один JSON-объект `fum.решение-продолжения.2` с полями `задача`, `решение`, `следующая_работа`, `ожидающие_работы`, `незавершённые_обязательства`, `HEAD`, `доказательства`, `вид_коммита`. Доказательства отображают ID обязательства в список OID актуальных приёмочных коммитов. Вид коммита — null, `контрольный` или `итоговый-этапа`; это контекст, не полномочие завершения.

- `продолжить`: есть доступная работа либо непогашенное обязательство. Если этап не покрывает остаток, `следующая_работа` может быть null: требуется восстановить план, а не завершать.
- `ожидать-ответа`: нет доступной независимой работы, все непогашенные обязательства явно покрыты ожидающими работами. Список ожидающих непустой; свободный текст причины требует смысловой проверки корня.
- `завершить`: оба списка остатка и ожидания пусты; реестр и текущий план точно сохранены в HEAD, результаты и карточки совпадают с диском.
- `остановлено-пользователем`: проверена самостоятельная команда остановиться. Здесь `HEAD` и `доказательства` могут отсутствовать, пустой остаток означает приоритет команды, а не погашение реестра.

Остановка содержит `запрос` и `цитата`. Принимается целый дословный `text`-блок в последовательности только таких блоков без внешней прозы, либо весь раздел исходного текста без оград. Окружающий текст, пример внутри сообщения и произвольный абзац не отбрасываются ради совпадения. Поддерживается конечный набор однозначных команд вроде `Остановись.`, `Останови задачу.`, `Stop the task.`; другие формулировки требуют явного уточнения, а не угадывания. После чтения указателя плана команда применяется до проверки истории и остатка, в том числе при пустом перечне работ.

С `--перед-завершением` продолжение даёт exit 3, остальные штатные решения — exit 0. Без флага любое штатное решение даёт 0. Ошибка входов или доказательств даёт exit 2, пустой stdout и stderr `ошибка: …`. Если результаты приняты, но план или реестр не совпадает с HEAD, это ошибка доказательства завершения с указанием сверить и зафиксировать границу; сочетание `продолжить`, null-следующего пункта и пустого остатка не выдаётся. `--профиль` добавляет только в stderr `FUM-PROFILE` с монотонным временем и стадиями; его сбой не превращает продолжение в успех.

## Границы и воспроизведение

V2 не удостоверяет внешнюю Swift-реализацию по копии отчёта, названию пути или обещанию. Отдельный внешний репозиторий/OID требует нового версионированного контракта; такое обязательство здесь остаётся открытым. Gitlink при восстановлении входного отпечатка требует доступных локальных объектов точного OID. Вложенные gitlink и символические входы не поддержаны и отклоняются. Git хранит только исполняемый бит: восстанавливаются канонические режимы 0644/0755; приёмка нестандартных POSIX-режимов может быть безопасно отклонена.

Shallow-история и grafts отклоняются, replace-объекты и переменные переадресации Git не используются. Межпроцессного глобального замка нет: повторное чтение уменьшает окно гонки, но не является атомарной файловой транзакцией. Смысловая полнота результатов, исходного реестра и тестов, а также независимая подлинность факта запуска не доказываются самосогласованными файлами репозитория. Эти границы нельзя представлять как универсальный перехват завершения Codex.

Профиль воспроизводится через обязательную отчётную обёртку вызовом `python3 Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_обязательств.py --вывод <локальный-JSON>`. По умолчанию — 100 коммитов этапа, 40 незавершённых обязательств либо одна закрытая приёмка, три независимых запуска CLI каждого случая. Сохраняются хэши исполняемого кода и фикстуры, версии Python/Git и сырые замеры. Кэш действует только в пределах вызова: одинаковые родительские Git-деревья читаются один раз, полный DAG и режимы сохраняются.
