# Полный локальный захват вывода

[CLI](scripts/захватить-вывод.py) запускает явно переданный список аргументов без оболочки. До выдачи в контекст [модуль](scripts/захват_вывода.py) сохраняет stdout и stderr как отдельные бинарные файлы. Общая выдача содержит состояние, размеры, SHA и адрес манифеста. Содержимое раскрывается отдельным запросом диапазона с проверкой полного SHA канала.

Нужны Python 3.10+ и POSIX с группами процессов, неблокирующими каналами, `fsync`, `O_NOFOLLOW`, `O_DIRECTORY`. Проверено на macOS с Python 3.14.7. Это явный локальный вход; MCP и недоступный runtime сами к нему не подключены. Команда сохраняет свои обычные полномочия: `shell=False` не является песочницей.

## Использование

Предусловие API и CLI — кооперативная модель: запущенный процесс доверен, этот захват является единственным писателем приватного каталога, конкурентной подмены каталога, файлов, ссылок и специальных файлов нет. Проверки физического пути, прав и SHA помогают выявлять ошибки внутри этой модели; они не защищают производителя от враждебного процесса с теми же правами. Изоляция средствами ОС и песочница не реализованы. Квитанция показывает это полем `модель_доверия`; поле объявляет предпосылку, не доказывает её выполнение.

Python-вход `захватить_с_хэшем` возвращает манифест и SHA точных сериализованных байтов, которые производитель передал устойчивой установке. CLI получает ожидаемый SHA непосредственно из этого результата, а затем проверяет прочитанный файл по нему. Повторное чтение больше не назначает самому себе ожидаемый хэш. Совместимый `захватить` по-прежнему возвращает только манифест. Переданный SHA обнаруживает расхождение при последующем чтении; это не доказательство отсутствия всех возможных подмен во время работы производителя.

Из корня FUM, заменив плейсхолдеры фактическими значениями:

```bash
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/захватить-вывод.py --каталог <новый-приватный-физический-каталог> --бюджет 16000 запустить --корень <рабочий-корень> --задача <uuid-задачи> --тайм-аут 60 --предел-байтов 134217728 -- <исполняемый-файл> <аргументы>
```

Каталог должен быть новым, его родитель — существующим; весь путь физический, без символических ссылок, вне любого Git checkout. Права каталога 0700, новых файлов 0600. Повтор имени отказывает до запуска. Вызов, аргументы, рабочий каталог и исходные потоки приватны и в Git не попадают. Передача сюда уже разрешённой команды не расширяет её полномочия.

Ответ содержит SHA `манифест.json`. Сохраните его для последующих чтений:

```bash
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/захватить-вывод.py --каталог <тот-же-каталог> --бюджет 16000 представить --sha256 <sha256-манифеста>
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/захватить-вывод.py --каталог <тот-же-каталог> --бюджет 16000 прочитать --sha256 <sha256-манифеста> --канал stderr --начало 0 --число 256
```

Диапазон передаёт точные байты в base64. Проверяются SHA манифеста и всего сохранённого канала, выборка собирается в том же проходе. Полнота исходного захвата и наличие следующего диапазона различаются. Большой запрос не обрезается молча: если результат с метаданными, base64 и LF не помещается, выдаётся отказ. Бюджет 100–1048576 байтов относится ко всему результату адаптера; отдельной квитанции в stderr нет. Справка и ошибки синтаксиса аргументов до запуска не являются протоколом результата захвата.

Код CLI 0 означает подготовленное представление и завершившуюся локальную запись; код дочернего процесса находится внутри ответа. Ненулевой код дочернего процесса не препятствует полному сохранению обоих каналов. Код CLI 2 обозначает отказ захвата, представления или записи. После частичной записи второй JSON не добавляется. Получение ответа моделью остаётся `unknown`: успешная запись в локальный канал не является квитанцией получателя.

## Полный план выходов перед запуском

`составить_план_выходов` проверяет упорядоченный список до первой записи захвата и до Popen. В него входят каталог захвата, все его фиксированные служебные выходы, необязательные четыре экспорта наблюдателя и объявленные предметные цели. Проверяются повтор роли, совпадение нормализованных адресов, NFC/casefold-алиасы, вложение файлов и чужой цели в каталог захвата, существующие файлы и каталоги, символьные компоненты, специальные файлы и доступность родителей. NFC/casefold — консервативный запрет неоднозначного плана; фактическая семантика каждого тома этим не устанавливается. Предметные роли не могут занимать пространства `захват:` и `наблюдатель:`.

Предметный план — JSON-массив объектов с точными полями `роль`, `путь`, `режим`. Адрес абсолютный; режим — целое `256` (0400) или `384` (0600). Порядок и повторы проверяются до преобразования в отображения. Отсутствие цели проверяется без открытия её содержимого. Родители предметных файлов уже существуют. Каталог захвата создаётся с 0700, его файлы и экспорты — с 0600; объявленный режим предметного файла обязан соблюдать доверенный производитель. Захват не создаёт предметные файлы за него.

Совместимые Python-входы принимают новые именованные параметры `предметные_цели` и `префикс_наблюдателя`. Прежние позиционные аргументы и значения по умолчанию сохранены. Без новых параметров остаются схема `fum.захват-вывода.1` и её прежние поля. Явный предметный план, в том числе пустой, включает `fum.захват-вывода.2`. Общий CLI принимает `запустить --предметные-цели <план.json>` перед `--` и командой. Защитные проверки не используют `assert` и действуют с Python `-O`.

Вторая схема связывает полный план через SHA `вызов.json`; его размер ограничен 1 МиБ. Добавляются закрытые поля `процесс` и `экспорт`. Первое содержит наблюдённые PID процесса и наблюдателя, монотонные границы начала подготовки, окончания предпроверки, до и после Popen, окончания наблюдения процесса/потоков и начала финальной записи. Последняя граница не включает собственную запись терминального манифеста. Окончание наблюдения при тайм-ауте или квоте не означает EOF: это показывает отдельное поле `полнота`. PID и граница после Popen неизвестны при отказе запуска. Эти метки не являются точными моментами рождения и завершения процесса в ОС. Внутреннее время API из них не выводится. Исходный манифест остаётся промежуточным снимком до обработки и экспорта; терминальным является только `манифест.json`.

## Наблюдатель и неизвестный исход

[Новый тонкий CLI](scripts/наблюдать-процесс.py) переводит прежний вход `{base,prefix,cwd,argv}` в тот же канонический захват. Список `argv` передаётся буквально, без оболочки. `base` — существующий приватный физический каталог вне Git, `prefix` — basename. Канонический каталог получает имя `<prefix>.захват`. Единственный Popen находится в общем модуле; отдельного производителя в наблюдателе нет.

```bash
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/наблюдать-процесс.py <конфигурация.json> --задача <uuid> --предметные-цели <полный-предметный-план.json>
```

Обязательный план передаётся массивом; `null` и отсутствие знания о предметных целях не заменяются пустым планом. Явный файл плана общего CLI также обязан содержать массив. Пустой `[]` означает, что доверенный вызывающий объявил отсутствие предметных выходов.

До Popen четыре имени `<prefix>.stdout`, `.stderr`, `.process`, `.json` резервируются `O_EXCL`. Открытые дескрипторы используются до конца, без повторного создания метаданных. Появление занятого имени между предпроверкой и резервированием отказывает до процесса и сохраняет существующие байты. `O_EXCL` остаётся последней защитой создания; предпроверка его не заменяет. Любой частичный отказ сохраняет фактический префикс и не разрешает повтор.

Полные бинарные потоки одновременно сохраняются в канонические `.bin` и экспорты; лимит относится к исходному stdout+stderr, поэтому дубли и метаданные требуют дополнительного диска. `.process` сохраняет прежние `argv`, `cwd`, `pid`, `observer_pid`, `start_epoch_ns`; последняя метка наблюдается перед Popen и не объявляется временем рождения ОС. `.json` сохраняет процессный `код`, длительность наблюдения `монотонные_нс`, SHA/размеры каналов и PID. Предметный JSON остаётся непрозрачным: его `код=0` может сосуществовать с процессным exit 7. Код CLI описывает подготовку ответа наблюдателя, а не внутренний API или код процесса.

Терминальный манифест устанавливается последним, после fsync экспортов и их родителей. Он связывает SHA и размеры всех четырёх экспортов. Строгий читатель второй схемы дополнительно проверяет вызов, план, канонические потоки, экспорты и согласованность PID/кодов. Экспорты `.stdout/.stderr` должны совпадать с каноническими каналами. Старый читатель первой схемы и формат диапазона остаются совместимыми.

```bash
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/наблюдать-процесс.py <та-же-конфигурация.json> --прочитать
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/наблюдать-процесс.py <та-же-конфигурация.json> --прочитать --sha256 <независимо-сохранённый-sha256-манифеста>
```

Без внешнего ожидаемого SHA инспекция возвращает `unknown`, `результат:null`, фактические SHA/размеры стабильных служебных файлов и строго читаемое сохранённое PID-наблюдение либо `null`. Она читает наблюдённый размер с проверкой метаданных до и после; изменяющийся или специальный файл помечается недостоверным. Наличие пустого либо даже полностью записанного `.json` не означает завершения. SHA, вычисленный при инспекции, не назначается самому себе ожидаемым. С внешним SHA возможен проверенный ответ `завершено`; неверный SHA или изменённые свидетельства дают отказ. Во всех ответах `повтор_разрешён:false`.

Инспекция не запускает процесс, не требует отсутствия прежних целей, не дописывает квитанцию и не делает repair. После аварии наблюдателя между успешным Popen и сохранением PID процесс мог продолжить работу; это неизвестность, а не отказ запуска. Новый запуск в том же пространстве имён отказывает по оставленным целям до Popen. Другой префикс не является глобальной защитой от повторного предметного действия. Гарантия требует полного объявленного плана, доверенного производителя и одного кооперативного писателя. Старый приватный helper и живые операции автоматически не заменяются; исторические свидетельства не переписываются.

## Полнота и наблюдения

Полный захват требует окончания обоих каналов, кода завершения дочернего процесса и устойчивой записи файлов и конечного манифеста. Сначала сохраняется вызов, затем потоки и ограниченная трасса, затем исходный манифест. Обработчик запускается после этой границы. Конечный манифест устанавливается через временный файл и переименование с синхронизацией каталога.

Тайм-аут покрывает ожидание процесса и обоих каналов. Потомок, удерживающий канал, не даёт ложного успешного окончания. При превышении времени или общего предела stdout+stderr процессная группа останавливается; сохранённый префикс явно неполон. Ровно допустимое число байтов при окончании обоих каналов принимается. Полный произведённый объём после остановки неизвестен. Потомки, вышедшие из группы, не объявляются остановленными. Неустойчивая запись не получает успешного конечного манифеста. Повторный запуск после возможного внешнего эффекта не выполняется автоматически.

`наблюдения.jsonl` хранит первые 4096 наблюдённых чтений: номер, канал, смещение, число прочитанных и сохранённых байтов, SHA сохранённой части. Остальные чтения учитываются счётчиком пропуска. Это порядок чтения адаптером, не точное чередование исходных записей двух независимых каналов. Предел хранения относится к исходным потокам; вызов, ограниченная трасса, манифесты и производное представление требуют дополнительного диска. Токены и общая стоимость задачи не измеряются.

Явный `--обработчик остаток` повторно использует [существующий детектор](детектор-бюджета-вывода.md) только после полного захвата с фактическим кодом 0 или 3. Его внутренний бюджет — 16000 байтов; результат и отдельная квитанция сохраняются приватно. В общий ответ попадают состояние обработчика, размер и SHA результата. Ошибка JSON не уничтожает оригиналы и не подменяет полноту исходного захвата. Автоматического определения схемы или отката к другому обработчику нет.

## Стык с языком операторов

Пользовательское требование: LLM видит, что выполняется автоматически и как, и настраивает это через язык описания структурирующих операторов. Сейчас [описание действия](../../Прототипы/память-структурирующих-операторов/Sources/FUMStructuringOperatorMemory/ОпределениеОператора.swift) и [исполнитель](../../Прототипы/память-структурирующих-операторов/Sources/FUMStructuringOperatorMemory/ИсполнениеОператоров.swift) поддерживают конечные вычисления над текстом, байтами и структурным контрактом. Захват процессов в них отсутствует.

Следующий согласуемый стык: типизированный шаг захвата в существующем определении, явный исполнитель эффекта в принимающем слое и вызов этого Python-модуля. Политика шага должна управлять тайм-аутом, хранением и представлением; наблюдение связывает SHA определения, точного вызова и результата. Неподдержанный шаг и неподключённый исполнитель должны отказывать до запуска. Большие потоки остаются вне значений Swift-интерпретатора. Доказательство интеграции — изменение описания меняет фактический исход сквозного Swift→Python-вызова с проверяемыми SHA.

Это адресная граница дальнейшего подключения, не реализованный оператор или новый параллельный язык. Постановку языка и наблюдаемости ведёт отдельная задача координатора; здесь сохранены наблюдаемые факты захвата. Подготовленное действие, запуск, результат и доставка не объединяются одним признаком успеха.

## Проверки и профиль

[Проверки](tests/test_захват_вывода.py) охватывают бинарные потоки, ненулевой код, повтор, тайм-аут, квоту, удержание каналов, запись, адресные SHA, обработчик и CLI. [Профиль](tests/профиль_захвата_вывода.py) запускает пять новых процессов по 4 МиБ на каждый канал и проверяет оба полных SHA. Команды выполняются через принятый учёт запусков проверок:

```bash
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_захват_вывода.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_захвата_вывода.py
```

[Сохранённый профиль](https://github.com/fum-lab/fum/blob/cb3adea7267ecb6a66c0d2399e6f1fd21afc181e/Журнал/2026-09-15_15-36-20_MSK_сохранять-полный-вывод-инструментов/материалы/профиль-захвата.json): 8388608 исходных байтов, 1492 байта метаданных представления, медиана захвата 45,651 мс, представления 0,368 мс, раскрытия 256 байтов с полным SHA канала 2,486 мс. Исходные байты не потеряны; компактные метаданные не заменяют их чтение. Ускорение против другой реализации, экономия токенов и получение моделью не измерены.

[Адресные регрессии плана](tests/test_плана_выходов.py) проверяют каждый резервированный суффикс и канонический выход, алиасы, режимы, занятые и специальные цели, O_EXCL при позднем появлении файла, обе схемы и оба CLI. Отдельная фикстура аварийно завершает наблюдатель сразу после успешного Popen до возврата из него и до PID/wait/EOF; свежий процесс читает неизвестность и отказывает повтору. Управляемое освобождение фикстуры подтверждает прекращение её отдельной группы.

[Малый профиль](tests/профиль_плана_выходов.py) делает по пять чистых предпроверок для 0/16/256 предметных целей и запускает ровно один синтетический процесс по 64 КиБ на канал. Команда через обычную отчётную обёртку: `python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_плана_выходов.py --выход <новый-профиль.json>`. Записываются полный wall-интервал захвата, отдельное проверочное чтение и вложенные стадии. Popen входит в наблюдение процесса/потоков; эти интервалы не суммируются. Подготовка временной фикстуры исключена. Это не измерение Create, большого ROOT-цикла, внутреннего API или ускорения.

Выход профиля задаётся абсолютным физическим адресом и включён в полный план до синтетического процесса. Существующий профиль сохраняется; повтор с занятым адресом отказывает до producer.

Нативный профиль содержит фактический физический путь интерпретатора и хранится приватно вне Git. Публичное представление явно объявляет производность, связывает SHA точных исходных байтов и заменяет только адрес интерпретатора на basename с отдельным SHA адреса. Измерения и исходники профиля при этом не меняются; такое представление не выдаётся за нативный RAW и не требует повторного процесса.
