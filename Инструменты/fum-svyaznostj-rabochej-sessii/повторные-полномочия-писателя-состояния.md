# Проверить повторные полномочия писателя состояния

Следующий этап принятого писателя получает собственный план Журнала и новые полномочия. Читающий API проверяет их связь по сохранённым Git-объектам без повторного разбора JSONL и без записи в дерево писателя. Это проверка предлагаемого основания, а не разрешение запустить писателя или установить карточки.

## Два режима проверки

`сверить_проект(данные, корень=...)` проверяет исходные байты предложения A.2 и независимо выбранный ранее закреплённый план P.1. До коммита A.2 невозможно доказать порядок его будущего коммита: результат содержит `строгий_порядок_Git: false`.

`прочитать(выбор, корень=...)` получает A.2 по полному OID, точному пути обычного blob и сырому SHA256. Размер проверяется до чтения; предел A.2 — один МиБ. После сверки содержания доказывается, что выбранный коммит P.1 отличается от коммита A.2 и является его предком. Результат содержит `строгий_порядок_Git: true`. Оба режима возвращают `разрешение_установки: false`.

## Проверяемая связь

Схема A.2 добавляет к прежним полям A.1 ровно `план_журнала` с полным селектором `{коммит, путь, sha256}`. Узел, репозиторий, координатор, владелец, поколение, state ref, исходный H и хэш физического дерева должны совпасть с P.1. Начальная постановка A.2 совпадает с коммитом первоначального запроса P.1. Хэш дерева относится к писателю; читающее дерево координатора не обязано иметь такой же путь.

Конечный T содержит одну новую пару из P.1, историю модели, отдельный expected и только допустимые служебные файлы и RAW-проверки этой пары. Пути канонические, без коллизий. Исторические запросы, builder и шаблоны независимо проверяются читателем P.1. При этом нынешняя пара checkout, control ref и текущий отчёт писателя не определяют исторический результат.

Прежнее структурное ядро A.1 используется только для общих полей: копия с исключённым селектором плана не является Git-источником A.1. Прежние публичные `прочитать`, `проверить_дерево` и `проверить_акт` принимают только A.1 и отвергают A.2 при обоих значениях флага эффекта. Новые ACT/N/U, maker и подготовка в этом срезе не активированы; control ref не создаётся.

## CLI и воспроизведение

`scripts/проверить_повторные_полномочия_узла.py` принимает `--корень-репозитория`, приватный файл `--вход` режима `0600` и необязательный `--профиль`. Закрытый вход имеет схему `fum.чтение-повторных-полномочий-узла.1` и поле `полномочия` с полным селектором A.2. Успех выводит SHA256, размер, доказанный Git-порядок и отсутствие разрешения установки; отказ имеет код 1 и пустой stdout. Профиль выводится отдельно в stderr.

Из корня FUM:

```sh
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_повторных_полномочий_узла.py
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_ветка_состояния_узла.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_повторных_полномочий_узла.py --выход <абсолютный-приватный-путь>
```

Профиль запускает три новых процесса с одной фикстурой Git и сохраняет SHA исходников, медианы, пик памяти Python и границу измерения. Подготовка, живые API и полный запуск писателя не входят в замер.
