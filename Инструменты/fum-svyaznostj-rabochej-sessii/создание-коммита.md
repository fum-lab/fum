# Создать проверенный коммит контрольной точки

Команда подготавливает сообщение из реальных пользовательских команд и наблюдаемой истории модели, затем создаёт один локальный коммит после проверки индекса и обязательных проверок. Она сохраняет email автора и данные committer, меняя только `GIT_AUTHOR_NAME`: к явно назначенной роли добавляет подтверждённые модель и усилие, например `FUM Писатель [gpt-6-astra; effort=max]`. Поддержаны обычный коммит и настоящее слияние с двумя упорядоченными родителями.

Это полный путь создания **контрольной точки разрешённой постоянной задачи**. Итоговый режим пока закрыто отказывает: ещё требуется отдельное проверенное включение однократного замыкания проекции по правилу 000188. Проверенная контрольная точка не означает итоговую приёмку, завершение задачи, интеграцию в `master` или публикацию. Команда не создаёт задач, расписаний или hooks.

Для конечного дочернего назначения существует отдельный [вход v3 и подготовка v5](../fum-konvejyer-proizvodnyikh-vetok/передача-слоя.md) по допуску `НОВОЕ-000019`. Проверены открытые фикстуры; реальный пилот ещё не выполнен. Описанный ниже режим контрольной точки сохраняется.

Для обратного приёма подготовлен отдельный [вход v4 и подготовка v6](../fum-konvejyer-proizvodnyikh-vetok/коммит-получателя.md). Его фикстуры не разрешают запуск настоящего получателя до отдельного допуска правил.

## Подготовить вход

Работайте из собственного физического корня. Переменная среды `CODEX_THREAD_ID` обязательна и должна совпадать с корневой задачей; отсутствие не заменяется значением входного JSON. Роль берётся из действительного назначения, например `FUM Интегратор`; обычный пробел после `FUM` обязателен. Допустимы собственная `refs/heads/codex/…` и явно разрешённые постоянные ветки `refs/heads/fuma` и `refs/heads/planirovaniye`. `master`, detached HEAD, незавершённые rebase/cherry-pick/revert и более двух родителей не поддержаны.

Сохраните JSON вне Git. Все поля обязательны; значения в угловых скобках заменяются фактическими данными:

```json
{
  "схема": "fum.создание-коммита.2",
  "корень": "<абсолютный физический корень>",
  "ветка": "refs/heads/codex/<своя ветка>",
  "исходный_коммит": "<полный HEAD>",
  "родители": ["<полный HEAD>"],
  "задача": "<корневой UUID>",
  "имя_автора": "FUM Интегратор",
  "запрос": "Журнал/<папка текущего этапа>/запрос.md",
  "источник_модели": "<абсолютный native JSONL корневой задачи>",
  "кэш_модели": "<новый приватный курсор вне Git>",
  "история_модели": "Журнал/<папка текущего этапа>/материалы/история-модели.json",
  "источники": [
    {
      "путь": "<абсолютный первичный JSONL>",
      "задача": "<UUID задачи источника>",
      "экземпляры": ["<идентичность выбранного экземпляра>"]
    }
  ],
  "заголовок": "Сохранить проверенный результат",
  "описание": "Конкретное описание сделанного и оставшейся работы.",
  "сообщение": "<новый приватный файл сообщения вне Git>",
  "подготовка": "<новый приватный файл подготовки вне Git>",
  "квитанция": "<новый приватный файл результата вне Git>",
  "режим": "контрольная-точка",
  "разрешённые_цели": ["<точный относительный путь каждого разрешённого файла>"]
}
```

`разрешённые_цели` — независимый конечный список точных относительных путей. Перечислите исходники, документы, навигацию, индексы, историю модели и все записи проверок своего этапа. Каталоги, повторения, абсолютные пути, выход за корень, symlink и неверный регистр не допускаются. Ещё не созданный файл допустим как будущая цель. Не копируйте весь Git-status как разрешение: состав задаётся принятым объёмом работы.

Будущим проверкам заранее назначьте UUID через `--идентификатор-запуска` отчётной обёртки. Имя записи имеет вид `<следующий-порядок>_<UUID>.json`; при одном последовательном писателе оно известно до подготовки. Это не резервирование. Непредвиденный дополнительный запуск меняет порядок и требует сверенного нового входа и новых приватных файлов подготовки. Прежняя подготовка не переписывается.

Для слияния сначала разрешите его в своём дереве обычным согласованным способом. В `родители` укажите ровно `[L, M]`: текущий HEAD и точный второй OID из `MERGE_HEAD`. Команда сама слияние не начинает и конфликты не разрешает.

В каждом элементе `источники` можно дополнительно указать `кэш` — точный путь существующего приватного индекса `fum.индекс-сообщений.1`, созданного штатным читателем. Это не `кэш_модели`. Без поля сохраняется полный разбор. Кэш проверяется читателем, не обновляется подготовкой и не заменяет первичный JSONL: при росте весь прежний префикс хэшируется, разбирается хвост; поздние байты, повреждение и несовпадение выбранных команд по-прежнему дают отказ. Неизменность метаданных ФС остаётся прежней границей доверия читателя.

До дорогого чтения источника подготовка проверяет непустую историю запусков: требуется v4. Отсутствующий каталог означает новую сессию; существующий каталог читается строго, включая отказ при повреждении или ссылке. Пустая история допускает подготовку сообщения, но её первый запуск необходимо явно начать с `--приёмочные-раунды`; создание без v4 всё равно запрещено. Автоматической миграции v3 нет.

Идентичности `экземпляры` берутся из [штатного читателя сообщений](обработка-сообщений.md), а не из текста или позиции в списке. Сохраняются порядок и реальные повторы; один экземпляр нельзя выбрать дважды. Каждый источник должен иметь подтверждённый завершённый снимок. При изменяющемся живом JSONL согласуйте тихое окно либо независимо проверенный неизменяемый завершённый префикс; автоматического повторения до случайного успеха нет. Область, актуальность поздних указаний и достаточность выбранных команд проверяет корень.

Раздел `Текст запроса` содержит отдельные ограждённые блоки `text` с выбранными командами в том же порядке. Перед блоком допускается единственная точная служебная метка `<!-- FUM-INTAKE: <идентичность экземпляра> -->` штатного сохраняемого приёма: её идентичность обязана совпадать с соответствующим первичным экземпляром. Чужая, повреждённая или повторённая метка отклоняется. После точного исходного текста перед закрывающей оградой добавляется один структурный LF; собственный конечный LF оригинала сохраняется отдельно. Неоднозначный ввод, вложение или неподдержанный каркас дают отказ. В сообщение коммита включается сам текст каждой команды, затем наблюдаемые `model` и `effort` и единственный последний корневой `Codex-Thread-ID`.

Запуск из корня:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/создание_коммита.py подготовить --вход <приватный-вход.json>
```

Выход подтверждает только подготовку. Приватные файлы создаются с режимом `0600`; существующие сообщение, подготовка или квитанция не перезаписываются. История модели может сохраниться до последующего отказа формирования сообщения: отсутствие коммита не означает отсутствие подготовительных записей. При неизвестных обязательных метаданных команда отказывает и не заполняет их догадкой.

## Повторить подготовку без изменения истории модели

Если нужно уточнить конечный состав разрешённых файлов или подготовить новое сообщение, а новые наблюдения модели не появились, доступен явный режим:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/создание_коммита.py подготовить-повтор --вход <новый-приватный-вход.json>
```

Вход остаётся v2; сообщение, подготовка и квитанция должны иметь новые приватные пути. История и её прежний курсор должны существовать и совпадать; их автоматического восстановления нет. Свежий JSONL читается штатным импортёром без записи. Обычный корректный хвост без новых turn_context допустим. Новое наблюдение даже с прежними model/effort, пропуск, неполный хвост, изменение старого префикса или рассогласованный курсор дают отказ. Тогда отдельно сверяют источник и выполняют обычную подготовку до staging и проверок.

Подготовка сохраняет SHA неизменных канонических байтов истории. Дополнительное поле результата CLI `сверка_истории` содержит свежую читающую сверку: её `история_sha256` относится к рассчитанному объекту истории, а не к сохранённому файлу и не к самому JSONL. Сохраните этот результат приватно как свидетельство проверки хвоста. Старые подготовка, сообщение, история и курсор не перезаписываются; обычный импорт сохраняет прежнюю семантику.

Режим предотвращает инвалидирование проверок только из-за переписывания истории при росте служебного JSONL. Он не разрешает использовать проверки другого canonical diff или индекса, не создаёт коммит и не повторяет отказ автоматически. [Парный профиль](tests/профиль_повторной_подготовки.py) с `--выход <новый JSON>` сравнивает обе подготовки на хвосте 1 МиБ через штатную отчётную обёртку.

## Совместимость подготовки

Новая команда подготавливает `fum.подготовленный-коммит.4`. Вход `fum.создание-коммита.2` сохраняет поле `имя_автора` для роли без суффикса, например `FUM Писатель`. Верхнее поле `имя_автора` содержит вычисленное полное имя; поле `готовность` — устойчивый приватный адрес состояния этапа. Они вместе со списком разрешённых целей входят в неизменяемые байты подготовки и связываются с квитанцией их SHA. Перед Git имя заново вычисляется из подтверждённого наблюдения и сравнивается целиком; неполная модель, неизвестное усилие, пробелы и разделители внутри машинных токенов отклоняются без исправления входа.

Прежние представления v1/v2/v3 допускаются только для восстановления уже существующей квитанции, после проверки её связи с исходной подготовкой. Для такого восстановления готовность не требуется. Сохранённый автор читается буквально, без назначения ему сегодняшней модели. Без квитанции создание по прежней подготовке закрыто отказывает: требуется новая подготовка v4. Не дополняйте старые файлы на месте. Схема квитанции остаётся v1; эта совместимость не разрешает повтор неизвестного Git-вызова. Имя содержит последнее подтверждённое наблюдение, полная история переключений сохраняется в Журнале и не заменяется суффиксом.

## Проверить и создать

Завершите содержательные файлы и recency, просмотрите точный diff, затем индексируйте канонический вход. После этого запустите применимые проверки через [отчётную обёртку](../fum-otchyotyi-o-zapuskakh-proverok/SKILL.md) в истории v4. Обновите предпросмотр и индексируйте только исключённые из отпечатка текущие отчёт и записи запусков. Это сохраняет связь проверок с тем же Git-отпечатком и фактическим содержимым.

Объявите готовность по фактическому индексу и UUID каждого обязательного успешного запуска, затем передайте те же UUID созданию:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/создание_коммита.py готово --подготовка <приватная-подготовка.json> --проверка <UUID-запуска> --проверка <UUID-другого-запуска> --предел-секунд 600
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/создание_коммита.py создать --подготовка <приватная-подготовка.json> --проверка <UUID-запуска> --проверка <UUID-другого-запуска>
```

600 секунд — явно выбранный пример порога, а не общая норма. Отсутствующая, повреждённая или отозванная готовность останавливает новый вызов до дорогих проверок. Перед записью намерения коммита повторно сверяются снимок и точные SHA сырых записей проверок. Прошедший порог отмечает задержку, но не отменяет необходимость фиксации уже готового этапа.

Если допуск обнаружил ошибку, явно отзовите последнее поколение, исправьте прежний объём и повторите применимые проверки:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/создание_коммита.py отозвать-готовность --подготовка <приватная-подготовка.json> --поколение 0 --основание <наблюдаемая-причина>
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/создание_коммита.py готово --подготовка <новая-приватная-подготовка.json> --проверка <UUID-нового-запуска> --замена-проверки <UUID-прежнего-запуска>=<UUID-нового-запуска> --предел-секунд 600
```

Поколения сохраняют первоначальное время, максимальный возраст, прежние снимки и SHA свидетельств. Корень, ref, исходный OID, запрос, исходные экземпляры сообщений и состав содержательных целей не расширяются. Разрешены новые записи проверок текущего этапа; замена обязательных UUID задаётся явно без сокращения списка. Это структурная проверка соответствия, а не доказательство смысловой эквивалентности двух тестовых команд. Новый независимый объём получает следующий этап. Подробнее — [контроль фиксации](контроль-фиксации.md).

Перед чтением первичных JSONL выполняется готовая ранняя сверка материалов: она сопоставляет раздел «Повлиял на файлы», полный Git-status и независимый разрешённый список. После чтения источников и метаданных снимок сверяется повторно до дорогой проверки индекса. Неполный состав, лишний файл или дрейф останавливают создание до записи намерения Git. Полная связность, обязательные проверки и заключительная сверка индекса сохраняются.

Список не может быть пустым; все выбранные записи должны относиться к текущим двум отпечаткам. Исторические RED-запуски остаются в журнале, но не заменяют обязательные успешные результаты. Определение применимых проверок и оценка их достаточности остаются обязанностью корня; один UUID не доказывает полноты выбранного контура. Открытый журнал требует точного предпросмотра, без активных, переходных и закрытых состояний.

Команда использует настоящую проверку связности без отключения Git-состояния. Дополнительно она проверяет каждый stage-0 файл, его сырые байты и исполняемый режим, ссылки, точные gitlink OID и отсутствие неиндексированного хвоста. `assume-unchanged`, `skip-worktree`, конфликты и преобразующие фильтры, при которых сырые рабочие байты отличаются от blob, не обходят этот допуск. Изменённая проекция тоже включается в полный индексный снимок, но её итоговая правильность этим не доказана.

После повторной сверки входа команда получает дерево через `git write-tree`, сохраняет приватное намерение и вызывает `git commit` с тем же файлом сообщения и `--cleanup=verbatim`. `write-tree` может создать Git-объекты и обновить cache-tree даже без успешного коммита. Проверяются сырой OID, дерево, порядок родителей, author/committer, фактическое сообщение и последний trailer.

## Прочитать результат или отказ

Успех возвращает полный OID, дерево, родителей и фактические поля. Квитанция хранит входную границу и монотонные длительности стадий. Публикация выполняется отдельно по действующему правилу 000064, после проверки точного назначения и удалённого OID; нового неявного push нет.

Повтор `создать` с той же подготовкой и существующей квитанцией выполняет только адресное чтение результата. Он не вызывает второй `git commit`. Если Git отказал до передвижения HEAD, либо исход неизвестен, сохранённая попытка запрещает автоматический повтор. Если коммит появился, но поля, сообщение, дерево или родители расходятся, квитанция сохраняет наблюдённый OID и отказ после создания. Явные даты автора и committer сохраняются при подготовке, повторно сверяются и проверяются в созданном объекте; естественное время без явного назначения остаётся наблюдением. Завершённый отказ Git и таймаут сохраняются в квитанции с кодом процесса и профилем. При таймауте, `SIGINT`, `SIGTERM` и `KeyboardInterrupt` собственная группа Git и hooks завершается до чтения результата. Локальный обработчик только запоминает сигналы во время запуска, ожидания и очистки; основной поток проверяет их между ожиданиями до 0,1 с и после завершения процесса. Общий монотонный предел Git остаётся 120 с. Повторные сигналы не прерывают остановку группы; неизвестное завершение запрещает успех. Даже при правильном созданном объекте отказ процесса требует разбирательства и не возвращает успешное создание. Команда не делает reset, amend, force push и не скрывает уже созданный объект.

Неполная квитанция без подтверждённого завершения процесса сохраняет `исход-процесса-неизвестен`; один наблюдённый HEAD не доказывает остановку поздних писателей. Не удаляйте квитанцию для обхода отказа. Сначала установите фактическое состояние и сохраните основание новой попытки. Приватный замок сериализует только вызовы с одной квитанцией; это кооперативный контракт единственного назначенного писателя, а не защита от произвольной конкурентной записи на машине.

Отказы подготовки и допуска до Git также содержат наблюдаемую длительность и профиль: в атрибутах исключения API и JSON ошибки CLI, включая отсутствующий или повреждённый вход. Вызывающая сторона сохраняет этот вывод вне Git штатным захватом; это не квитанция созданного коммита. Неперехватываемое завершение, например `SIGKILL`, может оставить неполное намерение и требует отдельной сверки. Автоматическое удаление Git-lock файлов не выполняется.

## Проверка контракта

Адресные тесты используют реальный временный Git, синтетический первичный JSONL и реальную отчётную обёртку. Они не подменяют положительный допуск заглушкой:

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_создание_коммита.py
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_допуск_автора.py
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_ранний_состав_коммита.py
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_ранний_охват.py
```

Эти прямые тестовые процессы в рабочей сессии также запускаются через отчётную обёртку. Фикстуры не доказывают полного smoke-check FUM или готовности итогового режима.

Воспроизводимый профиль двух положительных сценариев и двух ранних отказов: без native UUID и при неполном составе до чтения первичного JSONL, также через отчётную обёртку:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_создания_коммита.py --выход <профиль.json> --подробный-профиль <приватный-файл-cProfile>
```

Публичный JSON содержит стадии и хэш инструмента. Подробный профиль с локальными путями остаётся вне Git. Подготовка временного репозитория исключена; подготовка сообщения, проверки, создание и чтение результата включены.

## Профиль кэша первичных команд

[Открытый измеритель](tests/профиль_кэша_команд.py) создаёт одинаковый синтетический JSONL и сравнивает три чтения. Параметр `--с-кэшем` включает индекс, `--с-хвостом` дописывает строку после его подготовки. Выход `--выход <профиль.json>` содержит SHA входа, результата и исходников. Все варианты вызываются через отчётную обёртку. Подготовка индекса исключена; время полного создания коммита и расход токенов этим не измеряются.
