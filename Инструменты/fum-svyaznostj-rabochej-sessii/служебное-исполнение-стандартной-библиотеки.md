# Служебное исполнение стандартной библиотеки

Принятый загрузчик поддерживает native `exec(str)` конкретной stock-функции `dataclasses._FuncBuilder.add_fns_to_class` в CPython 3.14.8. Настоящий объект её кода закрепляется при загрузке bootstrap до проектных импортов. Пять классов каркаса запросов могут создаваться после установки hooks.

Компиляция создаёт одноразовое ожидание с исходными UTF-8-байтами, `<string>`, объектом кадра, потоком и его future-флагами. В пределах текущего потока завершённые кадры удаляются; живые записи не вытесняются. Общая граница — 64 записи и 4 МиБ исходников; переполнение закрыто отклоняется. Чужие завершённые потоки не очищаются предположением о завершении.

При `exec` ожидание того же кадра и потока погашается до проверочной компиляции. Байты декодируются строго в Unicode; повторная компиляция использует `exec`, явные future-флаги, `dont_inherit=True` и режим оптимизации процесса. Это сохраняет семантику Unicode даже при coding-cookie в тексте. Проверочный audit допускает только свой точный кадр, поток, байты и filename. Никакого общего обхода рекурсивных событий нет.

Code object сравнивается по полной сериализации `marshal` protocol 2 после рекурсивной проверки точных типов констант. Sharing и interning не участвуют; неизвестные типы, включая `slice`, отклоняются без запасного сравнения. Проверенный native object не регистрируется для повторного исполнения.

Проектная генерация, поддельный stdlib filename, чужой code object и повтор не получают допуска. Native `eval` и другие новые динамические функции stdlib этим изменением не разрешаются. Существующий контракт принятых файлов K сохраняется. Загрузчик остаётся механизмом происхождения доверенного кода, а не Python sandbox.

Первый реальный цикл писателя состояния требует отдельного полного состава Q и проверок ресурсов; этот этап сам его не запускает.
