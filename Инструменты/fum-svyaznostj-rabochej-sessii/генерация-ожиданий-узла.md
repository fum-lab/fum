# Построить кандидат ожидаемого состояния

[Читающий генератор](scripts/выбор_ожиданий_узла.py) заменяет ручное заполнение исполнителей в `expected`. Он принимает точное прежнее доверие, закреплённую постановку выбора и упорядоченные источники решений ROOT. Результат — детерминированные байты `fum.ожидаемое-состояние-узла.1` и их SHA. Он не выдаёт новое доверие, не пишет состояние и не продолжает чаты.

Вход `fum.выбор-ожиданий-узла.1` содержит ровно `схема`, `доверие`, `постановка_выбора`, `решения`. `доверие` имеет прежнюю [закрытую схему](состояние-задач-узла.md). Постановка и каждое решение — Git-selector с полным OID, точным относительным путём и SHA сырых байтов. В списке от 1 до 128 решений; порядок сохраняется. Пустой список не используется для объявления отсутствия работы.

Генератор загружает прежнее состояние штатным читателем и сохраняет все пять идентичностей. Каждый выбранный источник проверяется как `fum.сохранённое-решение-root.1`; координатор общий, владелец равен UUID задачи, ROOT исключён из дочернего перечня. Источники ACT и результата проверяет общий валидатор ожидаемого состояния. Дубликаты задач и JSON-ключей, неверные SHA, отсутствующие объекты и дрейф доверенного ref дают отказ.

Координатор выбирает актуальное решение после сверки позднего контекста. Генератор не ищет самое позднее решение сам: новое открытое решение в другом коммите не заменяет явно выбранное закрытие. Пауза, отмена, закрытие и неизвестный исход сохраняются в исходном решении. Снимки и доставка равны `null`, инфраструктура и полнота — `false`. Историческое решение не подменяет текущий ход и не разрешает эффект.

CLI читает явный приватный обычный файл без следования ссылкам:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/построить_ожидания_узла.py --корень-репозитория <физический-root> --вход <приватный-input.json> --профиль
```

`stdout` содержит только полный кандидат, без завершающего перевода строки; `stderr` — SHA, длину и необязательный профиль. При отказе кандидат не выводится. Захват приватных выходов принадлежит вызывающей среде. Время и измерения не входят в детерминированные байты.

Тесты и профиль:

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_выбор_ожиданий_узла.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_выбора_ожиданий_узла.py --повторов 3 --выход <новый-приватный-профиль.json>
```

Профиль разделяет загрузку доверия, выбор, общую проверку и повторное чтение ref. Git-фикстура исключена из времени; независимые процессы должны получить одинаковый SHA, сохранив байты Git. Контур не включает сетевые API, запись контейнера, установку expected или возобновление задачи.

Для следующего настоящего этапа писателя нужны новые независимые A/ACT, решение, N/U, операция и контрольное поколение с точным прежним доверием. Генератор их не создаёт. Подготовка новой собственной журнальной пары state-писателя и её адресная навигация остаются отдельным ремонтом: старый допуск рассчитан на пару, уже закреплённую в launch-C. Отложенная навигация конечного ребёнка не переносится на state-фасад без отдельного канонического допуска. Также отдельного ремонта требует автоматический обзор подготовки `.10`; успешный Creator не повторяется ради этого обзора.
