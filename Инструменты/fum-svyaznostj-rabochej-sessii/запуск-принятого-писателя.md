# Запуск принятого писателя состояния

Конечный состав кода закрепляется полным Git OID Q независимо от рабочего дерева W. Кандидат и изменяемая история W остаются данными штатного писателя. Закрытый манифест содержит физические Q/W, селекторы U и новых параметров G2, точные ID проверок и хранилище готовности; его SHA-256 передаётся отдельно.

Новый процесс Python `-I -S -B` связывает bootstrap, загрузчик, 66 проектных исходников и ресурсы с принятыми байтами. До hooks загружаются только стандартные модули, явно найденные в AST принятого кода, включая полные имена подмодулей. После допуска проектный код читается загрузчиком из захваченных байтов; изменённый файл, иной alias или непривязанный code object отклоняется.

Перед файловыми эффектами и запуском subprocess выполняется файловая сверка без Git и Popen внутри audit. Связаны закрытые входы, режимы файлов и полный перечень каталогов шаблонов и типов. Содержимое неиспользуемых блоков не объявляется прочитанным. Для Python проверяются argv и фактический executable; допускается только тот же bootstrap в режиме проверки. Для Git допускается заранее найденный исполняемый файл. Читающие формы `symbolic-ref HEAD`, `worktree list --porcelain` и `config --list` не разрешают записывающие варианты этих команд. Штатное открытие неизменного character device null для stdin=DEVNULL не считается записью файла; уже созданные FIFO-дескрипторы для input=Git batch учитываются отдельно как IPC: они не могут создать файл по пути. Остальные пишущие открытия запрещены. PATH состоит из непустых абсолютных компонентов; окружения родителя и ребёнка и выбранный executable Git сверяются перед subprocess. Диагностический JSON вложенной проверки идёт в stderr; stdout смены и повтора содержит один итоговый объект.

Штатный переход незапечатанной подготовки G1 → G2 сохраняет прежние свидетельства. Importer и parser ID истории модели остаются побайтно прежними. Адресный adapter пишет только три новых выхода G2 без буфера, проверяя каждый short-write и fsync; скрытой записи при close после отказа guard нет. Markdown проверяет принятый модуль Q через явный callback; default путь штатного checker сохраняется.

Необязательная схема манифеста 2 связывает описание возврата пустого RAW-каталога отдельным SHA-256. Назначение, сессия и существующий wrapper lock выводятся из штатного API. До G2 проверяются физические пути, пустота, dev/inode/mode/uid и отсутствие назначения; занятый lock закрыто отказывает. После genuine seal G2 повторно захватываются U → wrapper locks, проверяются исходный архив, ACT, expected, пустой индекс и свежая модель. Принятый no-replace перенос сохраняет исходный inode и синхронизирует обоих родителей. Прямой guard стоит непосредственно перед native syscall. Никакой файл в назначении не заменяется; частичный или неизвестный исход не повторяется автоматически. Замки освобождаются до v4/Creator. Читающий повтор сверяет неизменный descriptor, но не повторяет перенос и не требует пустоты уже заполненного каталога.

Затем выполняются настоящие адресные v4-проверки, terminal-preview, объявление готовности и Creator. Отдельный новый процесс читает прежний результат без новой подготовки, блокировки и записи. Открытая Git-фикстура проверяет ровно один новый коммит, сохранение прежних свидетельств и точное совпадение байтов, режимов, временных меток и inode после читающего повтора. Метки Markdown, индекс и его глоссарная ссылка создаются до базовых коммитов фикстуры; приёмочная проверка свежести выполняется без подмены. Фоновое обслуживание Git отключено только в синтетическом Q, чтобы оно не меняло область измерения.

Профиль использует три отдельные пары процессов. Подготовка Q/W находится вне таймера; capture, guards и штатный Creator входят в полную стоимость процесса. Это конечный запуск одной разрешённой операции, а не планировщик, механизм авторизации произвольного Python или sandbox ОС. Рабочий цикл первого узла остаётся неподтверждённым до выполнения владельцем ветки состояния.
