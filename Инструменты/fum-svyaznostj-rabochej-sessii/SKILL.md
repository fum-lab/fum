# FUM Session Coherence

Этот навык описывает локальную [автоматизацию FUM](../../Глоссарий/автоматизация-FUM.md), которая проверяет, что [рабочая сессия](../../Глоссарий/рабочая-сессия.md) связана с [памятью FUM](../../Глоссарий/память-FUM.md) как воспроизводимая цепочка:

папка запроса -> исходный запрос и соседний отчёт -> затронутые файлы -> проверки -> коммит.

## Когда использовать

Используй эту автоматизацию перед коммитом рабочей сессии, влияющей на проект, после запуска `fum-svezhestj-markdown` и после того как файл запроса уже содержит разделы `## Идентификатор сеанса Codex`, `## Использованные инструменты`, `## Повлиял на файлы` и `## Проверки`. Полную предкоммитную проверку запускай с тем же файлом сообщения, который затем будет передан `git commit -F`. Для новых запросов начиная с закреплённой временной границы параметры `--commit-message-file` и `--codex-thread-id` обязательны; исторические запросы сохраняют прежний контракт.

Автоматизация особенно полезна, когда сессия меняет несколько областей памяти: `Документация/`, `Глоссарий/`, `Инструменты/`, `Планирование/` и `Журнал/`.

## Команда запуска

```bash
python3 Инструменты/fum-svyaznostj-rabochej-sessii/scripts/check-session-coherence.py \
  --request Журнал/<YYYY-MM-DD_HH-MM-SS_MSK[_краткое-название-запроса]>/запрос.md \
  --commit-message-file <путь-к-файлу-сообщения> \
  --codex-thread-id <корневой-CODEX_THREAD_ID>
```

По умолчанию проверка читает `git status --short --untracked-files=all` через `git -c core.quotepath=false`, чтобы пути на кириллице сравнивались с разделом `## Повлиял на файлы`, а новые каталоги раскрывались до конкретных файлов. Явная Markdown-ссылка на существующий каталог ограниченно покрывает только его потомков; сходный строковый префикс и соседний каталог не покрываются.

Глобальные файловые проверки используют общий инвентарь [fum-proyektnyiye-fajlyi](../fum-proyektnyiye-fajlyi/SKILL.md). Поэтому `.build`, `.swiftpm`, каталоги кэшей, `.obsidian/plugins` и `.obsidian/themes` не становятся входами проверки ссылок, вопросно-ответных материалов или навигации запросов. Исключённый файл не может сделать ссылку на отсутствующий проектный документ формально корректной.

Для изолированной проверки файлов и ссылок без Git-состояния можно использовать:

```bash
python3 Инструменты/fum-svyaznostj-rabochej-sessii/scripts/check-session-coherence.py \
  --request Журнал/<YYYY-MM-DD_HH-MM-SS_MSK[_краткое-название-запроса]>/запрос.md \
  --skip-git-status
```

## Что проверяется

- Общая структура проходит `fum-struktura-papok-zaprosov`: каталога `Запросы/` нет, непосредственно в `Журнал/` из Markdown-файлов допустим только `README.md`, а каждая папка запроса имеет обязательный временной префикс `YYYY-MM-DD_HH-MM-SS_MSK`, обязательный `запрос.md` и необязательный каталог `материалы/`. У новой рабочей сессии обязателен также соседний `отчёт.md`; его отсутствие допустимо только у исторического запроса, для которого отчёт не существовал до миграции.
- Идентичность, дата и короткое название запроса берутся только из имени родительской папки; заголовок соответствует этому имени. Начиная с имени `2026-07-02_23-01-25_MSK_обновить-правило-именования-запросов` короткое название должно начинаться с глагола в инфинитиве, а исторические запросы до этого правила остаются допустимыми для обратной совместимости.
- Начиная с имени `2026-07-14_02-31-47_MSK_добавлять-идентификатор-сеанса-Codex`, ровно один раздел `## Идентификатор сеанса Codex` содержит единственную непустую строку с корректным `Codex-Thread-ID`; обязательный `--codex-thread-id` совпадает с идентификатором корневой задачи, а обязательный `--commit-message-file` - с последним одноимённым Git trailer тела сообщения.
- Раздел `## Навигация по запросам` текущего запроса указывает на правильные предыдущий и следующий `Журнал/*/запрос.md`, а соседний запрос ссылается обратно. Ссылки сопоставляются по полностью разрешённой цели, а не по общему basename `запрос.md`.
- Рядом с `запрос.md` существует `отчёт.md` со ссылкой на соседний запрос. Начиная с имени `2026-07-23_14-47-43_MSK_включать-профиль-времени-в-отчёты-журнала` отчёт содержит раздел `## Профиль времени выполнения`, таблицу с точными колонками `Стадия | Длительность | Границы и способ измерения`, не менее двух непустых строк стадий и строку `Граница профиля:`. Начиная с имени `2026-07-27_16-12-29_MSK_учитывать-все-проверочные-вызовы-в-профиле-времени` тот же раздел содержит подраздел `### Прямые запуски проверок`, таблицу с точными колонками `Вызов | Длительность | Результат` и строку `Общее время прямых запусков проверок:`. Каждый прямой запуск теста или проверки, включая неуспешный, прерванный и повторный, занимает отдельную строку; длительность записывается неотрицательным числом секунд с запятой или точкой в роли десятичного разделителя, а результат начинается со статуса `успешно`, `неуспешно`, `прервано` или `не завершено`. Итог равен арифметической сумме длительностей всех строк даже при перекрытии запусков. Один прямой вызов составной smoke-проверки учитывается один раз; её вложенные шаги могут быть показаны как детализация, но не дублируют вклад в сумму прямых запусков. Начиная с имени `2026-08-04_20-45-26_MSK_формировать-отчёты-о-запусках-тестов` проверка дополнительно вызывает [fum-otchyotyi-o-zapuskakh-proverok](../fum-otchyotyi-o-zapuskakh-proverok/SKILL.md): закрытый отчёт обязан побайтово совпадать с хэшированным снимком и всеми фактическими JSON-записями, а переходный журнал обязан отсутствовать. Открытый предпросмотр может промежуточно существовать между вызовами, но строгая проверка принимает его только при наличии хотя бы одной записи `выполняется`. Более ранние отчёты сохраняют ручной исторический контракт.
- Текущие `запрос.md` и `отчёт.md` не содержат маркер `<!-- ШАБЛОН:НЕЗАПОЛНЕНО -->`; буквальное совпадение внутри дословного раздела `## Текст запроса` не переинтерпретируется и не считается незавершённой заготовкой.
- Раздел `## Использованные инструменты` присутствует, содержит список и ссылку на [реестр системных приложений и инструментов](../реестр-системных-приложений-и-инструментов.md). Начиная с имени `2026-07-10_05-59-58_MSK_уточнить-учёт-версий-ChatGPT-и-Codex` общая запись `Codex - версия не раскрывается средой` отклоняется: приложение, runtime, CLI, модель и контракты агентской сессии должны быть квалифицированы раздельно. Начиная с имени `2026-07-17_10-25-41_MSK_предотвращать-смещение-времени-сессий` раздел обязан фиксировать использование `fum-moskovskoye-vremya-rabochej-sessii`.
- Раздел `## Повлиял на файлы` содержит локальные Markdown-ссылки на затронутые существующие файлы, включая текущий `запрос.md` и соседний `отчёт.md`. Массовое изменение может явно назвать существующий каталог и тем самым покрыть только его существующих потомков. Для отсутствующей после текущей сессии точной цели используется строка `- Удалённый файл: \`<путь>\``, для удалённых непосредственных файлов остающегося каталога — `- Удалённые непосредственные файлы каталога: \`<путь>/\``, а для целиком удалённого дерева — `- Удалённое поддерево: \`<путь>/\``. Маркер непосредственных файлов требует существующий каталог и не покрывает вложенные пути; удалённое поддерево обязано отсутствовать, находиться внутри репозитория и покрывает только собственных потомков.
- Активные локальные Markdown-ссылки во всём репозитории указывают на существующие цели, остаются внутри репозитория, а регистр каждого компонента пути совпадает с реальным именем файла или каталога. Дословный раздел `## Текст запроса` канонического `Журнал/<stem>/запрос.md` считается сырой областью происхождения и не переинтерпретируется после переноса файла; ссылки до и после него остаются активными. POSIX-абсолюты, Windows/UNC-пути, `file://` и относительные выходы за корень отклоняются; обычные внешние URL не проверяются.
- Каждый файл `Вопросы и ответы/*.md`, кроме README, содержит непустой раздел `## Вопрос`, последний содержательный символ которого равен `?`. Это формальная защита наблюдаемого признака, а не лингвистическое доказательство вопросительной семантики.
- Затронутые Markdown-файлы, кроме канонических `Журнал/*/запрос.md`, не содержат похожий на пользовательский мета-запрос о правилах [памяти FUM](../../Глоссарий/память-FUM.md), порядке [рабочей сессии](../../Глоссарий/рабочая-сессия.md), `AGENTS.md` или папках запросов без ссылки на конкретный исходный `запрос.md`.
- Затронутые Markdown-файлы, кроме канонических `Журнал/*/запрос.md`, не начинаются со справочного блока происхождения: `Источники требований`, `Источники`, `Опорные документы`, `Опорные материалы`, `Внешний материал`, `Затронутая документация` и похожие блоки должны идти после основного содержания перед `FUM-MD-RECENCY`.
- Затронутые Markdown-файлы не содержат Mermaid-подписей узлов, которые начинаются с Markdown-маркера списка вроде `1. `, `1) `, `- `, `* ` или `+ `, потому что Obsidian может отображать такие узлы как `Unsupported markdown: list`.
- Автоматизация `fum-svezhestj-markdown` подтверждает свежесть служебных recency-меток и индекса `Индексы/markdown-файлы-по-времени-редактирования.md`, если этот локальный инструмент есть в репозитории.
- Все пути из текущего `git status --short` перечислены точно либо входят в явно названный существующий каталог, множество удалённых непосредственных файлов остающегося каталога или отсутствующее удалённое поддерево из раздела `## Повлиял на файлы`; лишние временные файлы, кэши, соседние пути и отладочные артефакты вызывают ошибку.

## Проверки автоматизации

Локальные тесты запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p 'test_*.py'
```

В таблице прямых запусков экранированный Markdown-разделитель `\|` остаётся частью ячейки. Подраздел, таблица или итог внутри fenced code или HTML-комментария не считаются структурой отчёта. Арифметика и диагностика итога сохраняют фактическую десятичную разрядность всех строк, а не глобальную точность Decimal по умолчанию.

Тесты фиксируют базовый контракт: успешная сессия проходит при перечисленных изменённых файлах; идентичность и исторические временные границы берутся из имени родительской папки; папка без полного временного префикса отклоняется; навигация проверяет точные цели при одинаковом basename; новые короткие названия начинаются с инфинитива; незаполненный маркер шаблона вне дословного текста запроса отклоняется; историческая общая запись версии Codex и исторический отчёт без профиля времени сохраняют обратную совместимость; буквальный вопрос с `?` допустим. Новый журнальный профиль принимает отдельные строки повторных запусков со статусами успеха, неуспеха, прерывания и незавершённости, а также точную арифметическую сумму их длительностей; отсутствие подраздела, таблицы, строк или итога, неверная единица длительности, неизвестный статус и несовпадающая сумма дают ошибку. Для новых запросов отсутствующие обязательные аргументы, отсутствующий, перенесённый на другую строку, некорректный или дочерний `Codex-Thread-ID`, повторный раздел, лишний текст, псевдотрейлер, отсутствующий, дублированный или несовпадающий настоящий trailer в теле коммита, неквалифицированная запись версии, отсутствие `fum-moskovskoye-vremya-rabochej-sessii` после закреплённой границы, отсутствие соседнего отчёта или обязательного табличного профиля времени, битая или регистроневерная Markdown-ссылка, вопросно-ответный файл без вопроса или без конечного `?`, возможный незаведённый мета-запрос без ссылки на конкретный `Журнал/*/запрос.md`, верхний справочный блок происхождения, Mermaid-подпись узла с Markdown-маркером списка, устаревшая recency-проверка и неожиданный путь в Git-состоянии дают ошибку. Маркер действительно удалённого файла участвует при проверке Git-состояния без фиктивной ссылки, а для существующей цели отклоняется. Отдельная фикстура подтверждает, что `.build/checkouts/vendor/README.md`, `.swiftpm` и кэши не участвуют в файловых обходах и не скрывают битые проектные ссылки.

## Граница автоматизации

Скрипт проверяет структурную связность рабочей сессии, но не подменяет смысловую проверку документации. Агент по-прежнему отвечает за корректность требований, публикационную чистоту содержания, полноту списка инструментов, уместность затронутых файлов и качество коммита.

Машинный журнал позволяет доказать точное соответствие зафиксированных запусков, снимка и Markdown, но не может обнаружить процесс, намеренно запущенный в обход обязательной обёртки. За соблюдение границы запуска отвечают корень и субагенты. При перекрытии прямых запусков их арифметическая сумма является агрегированным call-time, а не календарным wall-clock; общие границы сессии и стадий по-прежнему описываются отдельно в основной таблице профиля.

Проверка локальных Markdown-ссылок и регистра их путей выполняется по всем Markdown-файлам репозитория, чтобы ошибка, скрытая на нечувствительной к регистру файловой системе, не оставалась в памяти до случайной правки конкретного файла.

Проверка каталога `Вопросы и ответы/` также выполняется глобально, а не только по списку файлов текущей сессии. Она проверяет формальный буквальный признак вопроса и не оценивает качество или полноту содержательного ответа.

Проверка мета-запросов является эвристикой. Она ищет формулировки о вопросе, уточнении, ответе или проверке пользователя в контексте правил памяти, порядка рабочей сессии, `AGENTS.md` или папок запросов; это ранний сигнал, а не доказательство, что запрос действительно пропущен.

Проверка Git-состояния сравнивает только пути. Она не решает, нужно ли включать конкретное содержимое в коммит; перед staging агент всё равно должен просмотреть diff и исключить секреты, локальное состояние и машинный мусор.
