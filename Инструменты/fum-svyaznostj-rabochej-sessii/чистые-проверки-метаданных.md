# Чистые проверки метаданных в одном доказательстве

Полное `доказательство_слоя` многократно встречает одинаковые строки и относительные пути. Одна ограниченная область сохраняет только успешно проверенные точные значения `str`. Прежние предикаты UTF-8, управляющих знаков и относительного пути остаются прежними. Ошибки, содержимое файлов, результаты Git, модели, RAW, снимки и готовые доказательства в этот кэш не входят.

Каждому новому доказательству выделяются собственные наборы, не более 65 536 строк и 65 536 путей. После заполнения новые значения проверяются без сохранения; ранее сохранённые значения продолжают использоваться. Это предел числа элементов, а не точная граница памяти Python. Вложенная область изолирована и затем восстанавливает внешнюю. `finally` очищает привязку и при исходной ошибке. За пределами области каждый вызов выполняет прежнюю проверку. Интерфейс `значение=` и типы ошибок сохранены.

Затраты чистого разбора повторных метаданных меняются с суммы длин всех повторов на сумму длин первых успешных значений плюс обращения к наборам. Для элементов сверх лимита разбор повторяется. Это не доказательство линейности всего алгоритма: хеш-таблицы имеют свои предпосылки, а остальные проверки и ввод-вывод остаются самостоятельными затратами.

## Проверка и воспроизведение

Из корня чистого checkout с Python без внешних библиотек:

```sh
python3 -E -s -S -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_чистых_проверок_метаданных.py
```

Тесты проверяют число разборов, новые и вложенные области, параллельные потоки, лимит, повторный отказ, исходную ошибку, именованный аргумент, типы и все кодовые точки Unicode. Отдельно проверяется выход профилировщика: существующий файл, checkout, bare Git и совпадение с входом отклоняются до записи.

Реальный парный профиль запускается отдельно, на macOS, с явными входами:

```sh
python3 -E -s -S -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_чистых_проверок_метаданных.py --основа <полный-OID> --вход <физический-приватный-JSON> --хэш-входа <SHA256> --выход <новый-приватный-файл-вне-Git>
```

JSON содержит параметры только читающего доказательства: `схема` обычного ROOT Maker 9, `корень`, `ветка`, `задача`, `запрос`, `исходный_коммит`, `разрешённые_цели`, `контракт_журнала` и `привязка_журнала`. Привязка получается штатным `проверить_контракт` из независимо выбранного Git-состава и собственной открытой пары. Это не полный вход Creator и не разрешение эффекта. Нужны действительные неизменные W, принятый состав, собственная пара, терминальные предыдущие RAW, актуальная каноническая разметка и индекс. Произвольная минимальная фикстура не заменяет реальный слой.

Шесть новых процессов чередуют два варианта. В прежнем используются точные тела двух валидаторов из выбранного Git-blob и прежнее тело доказательства без добавленного декоратора; допустимая дельта проверяется по AST. В новом используются текущие тела и производственная область. Общие зависимости остаются текущими. Контрольные суммы Python-исходников, входа, индекса, HEAD, ref, статуса, результатов и argv сопоставляются; внешние данные заново проверяются каждым proof. Счётчик argv не является журналом исходов дочерних процессов.

Wall-окно включает одно полное доказательство, его ленивые импорты и одинаковую оснастку наблюдения argv. Начальные прямые импорты, подготовка входа, заключительная сверка и установка S1 находятся вне окна. CPU — только SELF; RSS — максимум всего работника. Кэш ОС не сбрасывается. Временное представление H создаётся вне W. Измерение этого участка не является коэффициентом ускорения всего Prepare/READY/Create или активацией узла. Наблюдённые числа и происхождение конкретного опыта сохраняются в материалах собственного Журнала.
