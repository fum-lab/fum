# Построитель дерева базиса узла

Построитель получает закреплённые K, R и независимо выбранный ROOT документ решений, сохраняет историческую защиту первого цикла и возвращает tree OID с происхождением. Он записывает только tree-объекты в существующий собственный каталог вне Git. Исходные checkout, индекс, refs, конфигурация и объекты сохраняются. Основание — [постановка автоматизации](../../Планирование/доработки-автоматизаций/2026-10-13/построитель-реального-базиса.json).

## Вход и решения

Внешний UTF-8 JSON вход имеет точные поля `схема`, `корень`, `каталог_объектов`, `K`, `R`, `первый_цикл`; схема — `fum.вход-построителя-дерева-базиса.1`. Оба пути абсолютные физические, без символических ссылок. K и R — различные полные SHA-1 commit OID, объекты уже доступны локально. R выбирается входом. `первый_цикл` содержит точные `акт`, `полномочия`, `идентичность`, которые использует штатный `исторический_защищённый_состав`; заявленный список защиты его не заменяет.

Второй внешний JSON содержит только `коммит`, `путь`, `sha256`: точный селектор независимо выбранного документа ROOT. Документ читается как обычный Git-blob; проверяется SHA-256 исходных байтов, включая форматирование и конечный LF. Его поля:

```json
{
  "схема": "fum.решения-дерева-базиса-узла.1",
  "координатор": "UUID из идентичности первого цикла",
  "K": "полный OID",
  "R": "полный OID",
  "общий_предок": "единственный общий предок K и R",
  "решения": []
}
```

Каждое пересечение изменений X→K и X→R требует ровно одной записи `путь`, `итог`, `описание`. Это касается одинакового изменения и двойного удаления. Записи идут по UTF-8 байтам пути; пропуски, повторы, лишние и переставленные записи отклоняются. `описание` — непустая строка. `итог: null` удаляет путь. Другой итог содержит точные `режим`, `тип`, `blob`, `sha256`, `байты`; разрешены только обычные `100644`/`100755` blob. Хэш и размер сверяются с фактическим объектом. ROOT вправе выбрать K, R или третий уже существующий blob. Пустой массив допустим при отсутствии пересечений.

## Запуск

Создайте отдельный пустой каталог объектов, закрепите оба внешних JSON и запустите из физического корня чистого FUM с Python 3.10 или новее и Git в PATH:

```sh
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/построить_дерево_базиса_узла.py \
  --вход <абсолютный-физический-вход.json> \
  --выбранные-решения <абсолютный-физический-селектор.json>
```

Успех возвращает JSON `fum.кандидат-дерева-базиса-узла.1`: SHA-256 канонического входа, K/R/X, tree OID, родителей `[K,R]`, селектор и сырой SHA решений, исторические источники первого цикла, полный штатный защищённый состав и непрозрачные исторические специальные записи. Родители — данные для отдельного Creator. Коммит, приёмка, ACT_B и переход R→B этим результатом не создаются.

Код 2 и диагностика stderr означают отказ без результата кандидата. Оба внешних JSON читаются как обычные файлы не больше 1 МиБ; неблокирующее открытие и проверка типа исключают ожидание писателя FIFO. `--профиль` добавляет отдельный JSON времени в stderr; stdout результата не меняется. Расчёт включает чтение и проверку исходных объектов; сериализация и запись включает повторную сверку хранилища и синхронизацию; перечитывание использует штатные `git cat-file --batch` и `git ls-tree -r -z` для точных tree-байтов и всех листьев.

## Границы и отказ

Все шесть исторически защищённых записей сохраняются с точными режимом, типом и blob. Unicode NFC, casefold и коллизии файла с каталогом проверяются по сырым Git-таблицам до записи. Неизменённые `120000` и `160000` сохраняются как непрозрачные записи: рабочая ссылка не разыменовывается, gitlink не загружается. Их добавление, удаление, замена либо изменение R→кандидат закрыты. Наличие сохранённой специальной записи само по себе не подтверждает её допустимость в последующей семантической приёмке.

Собственный каталог не пересекается с checkout, Git-предками, git-dir, common-dir и исходным object directory. В нём допускаются только корректные собственные loose tree-объекты. Вся цепочка родителя JSON-входа, хранилища и каждого loose-префикса закрепляется дескрипторами без следования ссылкам; конечный файл читается по имени относительно своего закреплённого родителя. Подмена pathname после проверки не перенаправляет такое чтение. Новый объект сначала полностью записывается и синхронизируется во временном файле, затем публикуется атомарно без перезаписи. Корректный повтор подтверждает существующие байты.

После позднего отказа могут сохраниться уже завершённые собственные tree-объекты. После аварийного прекращения процесса возможен неизвестный временный остаток: следующий запуск отклоняет его, автоматической очистки или восстановления нет. Модель владения требует собственного каталога и единственного доверенного писателя; это не системная изоляция от другого процесса того же пользователя. Размер tree/blob ограничен 32 МиБ, собственного хранилища — 200 000 объектов. Процессы чтения ограничены тайм-аутами штатного читателя и перечитывания.

Реальный B требует отдельно созданного Creator коммита и штатных `состав_базиса`, `сверить_состав`, `сверить_первый_цикл`, `семантика_базиса`. Произвольный `git commit-tree` не доказывает Creator. Реальные K/R, ROOT решения, допуск приёмки и полномочия следующих эффектов выбирает координатор.

## Проверки и профиль

Адресная матрица [тестов](tests/test_построителя_дерева_базиса_узла.py) использует конечные настоящие Git-истории. Ожидаемый OID вычисляет отдельный `git mktree` по вручную выбранным листьям в третьем каталоге объектов; этот эталон не загрязняет исходную ODB или кандидат. Проверяются точные двоичные байты, исполняемый режим, UTF-8 порядок поддеревьев, решения пересечений, защита, специальные записи, типы/поля JSON, ошибки записи и сохранность связанного дерева с общим Git-каталогом.

[Измеритель](tests/профиль_построителя_дерева_базиса_узла.py) создаёт один синтетический корпус вне интервала замера и запускает три свежих CLI-процесса с теми же входными байтами и каждый раз пустой собственной ODB. RAW каждого исхода сохраняется отдельно до разбора; отказ останавливает серию. Публичный профиль содержит закреплённые OID/SHA, версии, хэши кода и исполняемых файлов, каналы и три раздельные фазы. Полное замыкание системных библиотек и настоящий B/Creator не измерены.

```sh
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests \
  -p test_построителя_дерева_базиса_узла.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_построителя_дерева_базиса_узла.py \
  --каталог-raw <новый-абсолютный-физический-каталог-вне-Git> \
  --выход <новый-файл-профиля.json>
```
