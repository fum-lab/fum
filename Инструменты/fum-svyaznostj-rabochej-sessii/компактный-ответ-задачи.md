# Компактный ответ нативной задачи

[Python-эталон](scripts/компактный_ответ_задачи.py) принимает сохранённую оболочку `read_thread`, проверяет полный SHA-256, разбирает вложенную строку JSON и выбирает первый подходящий ход `newest_first`, затем последний непустой `agentMessage` в его массиве `items`. Выбранный объект сохраняется целиком. Срез содержит состояние, ошибку текущего хода, метаданные выбранного хода, счётчики опущенных элементов и двухступенчатые указатели на оригиналы. Команды и рассуждения не исполняются и не передаются как ответ.

[CLI](scripts/показать-ответ-задачи.py) требует `--снимок`, `--sha256` и `--задача`. Необязательный `--путь-в-результате` добавляет абсолютный адрес приватного артефакта. `--максимум-байтов` по умолчанию равен 16000 и включает адрес и завершающий LF. Превышение бюджета означает код 2 и пустой stdout; текст не усекается. CLI не пишет и не обращается к API или Git.

[Общая обёртка](scripts/адаптер_ответа.cjs) экспортирует `прочитать_кратко(среда, параметры)`. Среда предоставляет `инструменты`, `загрузить` и `сохранить`; в `functions.exec` им соответствуют `tools`, `load` и `store`. Параметры — физический `корень` checkout, `задача`, абсолютный `снимок`, `ключ_кэша`, `режим` и `максимум_байтов`. Для этой транспортной обёртки допустимы 100–16000 байтов. Она получает нативный ответ внутри вызова, сохраняет полный JSON и передаёт наружу только результат CLI. Вызывать `text()` следует только для возвращённого среза или короткого отказа. Это явно вызываемый помощник; глобальный перехват инструментов не установлен.

Режим `новый` сначала инвалидирует предыдущее принятое состояние, проверяет новый путь вне любого Git-предка и без символических ссылок, затем делает один запрос API и одну запись полного снимка. Каталог должен существовать; существующий файл отклоняется. Приватный каталог выбирается вне Git, в том числе вне скрытого репозитория домашнего каталога. Режим `сохранённый` требует точного совпадения корня, задачи и пути с принятой записью. Он заново проверяет SHA файла и не вызывает API. Ошибка нового запроса не выдаёт прежний успех.

Пустые `items`, отсутствие ответа и `hasMore=false` не доказывают завершение или полноту истории. Живой источник при чтении снимка не перепроверяется. Неизвестная структура, дубликаты ключей и повреждённый JSON отклоняются; восстановление из фрагментов запрещено. Маленький ответ без сообщений может стать больше из-за явных метаданных и ограничений. Полный снимок содержит точные байты собственной сериализации MCP-объекта, а не доказанные транспортные байты сервера.

[Контракт соответствия](../../Проекты/рабочий-контекст/контракты/ответ-задачи.json), [входная схема](../../Проекты/рабочий-контекст/контракты/схема-входа-ответа.json) и [выходная схема](../../Проекты/рабочий-контекст/контракты/схема-выхода-ответа.json) описывают текущий эталон. Текстовые действия в контракте ещё не являются исполняемыми структурирующими операторами. Следующий срез расширяет найденный конечный исполнитель и генерирует модели Swift Codable, Python и предметную проекцию из одного описания. Codable сам не определяет выбор полей и канонические байты.

Проверки и воспроизведение из корня checkout:

```sh
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_компактный_ответ_задачи.py
node --test Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_адаптер_ответа.cjs
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_ответа_задачи.py --выход профиль.json
```

Выход профиля направляется во временный каталог или материалы собственного этапа. Независимая проверка схем `Проекты/рабочий-контекст/проверить-контракт-ответа.py` использует отдельно объявленный `jsonschema` 4.23.0; основной CLI от него не зависит. Реальные запуск и профиль: [отчёт этапа](../../Журнал/2026-09-14_15-01-38_MSK_сократить-ответы-нативных-инструментов/отчёт.md). Полный smoke-check и проекция в этой контрольной точке не выполнены.
