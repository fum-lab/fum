# Компактный ответ нативной задачи

[Python-эталон](scripts/компактный_ответ_задачи.py) принимает сохранённую оболочку `read_thread`, проверяет полный SHA-256, разбирает вложенную строку JSON и выбирает первый подходящий ход `newest_first`, затем последний непустой `agentMessage` в его массиве `items`. Выбранный объект сохраняется целиком. Срез содержит состояние, ошибку текущего хода, метаданные выбранного хода, счётчики опущенных элементов и двухступенчатые указатели на оригиналы. Команды и рассуждения не исполняются и не передаются как ответ.

[CLI](scripts/показать-ответ-задачи.py) требует `--снимок`, `--sha256` и `--задача`. Необязательный `--путь-в-результате` добавляет абсолютный адрес приватного артефакта. `--максимум-байтов` по умолчанию равен 16000 и включает адрес и завершающий LF. Превышение бюджета означает код 2 и пустой stdout; текст не усекается. CLI не пишет и не обращается к API или Git. Дополнительный `--профиль прежний|порождённый` по умолчанию выбирает `прежний`: все ранее допустимые входы сохраняют прежнее поведение. `порождённый` явно подключает общие модели и проекцию; автоматического отката при отказе нет.

[Общая обёртка](scripts/адаптер_ответа.cjs) экспортирует `прочитать_кратко(среда, параметры)`. Среда предоставляет `инструменты`, `загрузить` и `сохранить`; в `functions.exec` им соответствуют `tools`, `load` и `store`. Параметры — физический `корень` checkout, `задача`, абсолютный `снимок`, `ключ_кэша`, `режим`, `максимум_байтов` и необязательный `профиль_представления` (`прежний` по умолчанию, либо `порождённый`). Для этой транспортной обёртки допустимы 100–16000 байтов. Она получает нативный ответ внутри вызова, сохраняет полный JSON и передаёт наружу только результат CLI. Вызывать `text()` следует только для возвращённого среза или короткого отказа. Это явно вызываемый помощник; глобальный перехват инструментов не установлен.

Режим `новый` сначала инвалидирует предыдущее принятое состояние, проверяет новый путь вне любого Git-предка и без символических ссылок, затем делает один запрос API и одну запись полного снимка. Каталог должен существовать; существующий файл отклоняется. Приватный каталог выбирается вне Git, в том числе вне скрытого репозитория домашнего каталога. Режим `сохранённый` требует точного совпадения корня, задачи и пути с принятой записью. Он заново проверяет SHA файла и не вызывает API. Ошибка нового запроса не выдаёт прежний успех. Выбранный профиль применяется к каждому чтению. Уже принятый снимок можно перечитать другим профилем без нового API и записи файла: кэш хранит байты с SHA, а не готовую проекцию. Отказ строгого профиля или бюджета при сохранённом чтении не уничтожает прежнюю принятую привязку. Неуспешное первое новое чтение оставляет кэш непринятым, даже если файл уже создан. Неизвестный профиль отклоняется до изменения кэша и обращения к инструментам.

Пустые `items`, отсутствие ответа и `hasMore=false` не доказывают завершение или полноту истории. Живой источник при чтении снимка не перепроверяется. Неизвестная структура, дубликаты ключей и повреждённый JSON отклоняются; восстановление из фрагментов запрещено. Маленький ответ без сообщений может стать больше из-за явных метаданных и ограничений. Полный снимок содержит точные байты собственной сериализации MCP-объекта, а не доказанные транспортные байты сервера.

[Контракт соответствия](../../Проекты/рабочий-контекст/контракты/ответ-задачи.json), [входная схема](../../Проекты/рабочий-контекст/контракты/схема-входа-ответа.json) и [выходная схема](../../Проекты/рабочий-контекст/контракты/схема-выхода-ответа.json) описывают текущий эталон. Текстовые действия в контракте ещё не являются исполняемыми структурирующими операторами. [Отдельный действующий срез](../../Проекты/рабочий-контекст/операторные-модели-ответа.md) расширяет конечный исполнитель и генерирует модели Swift Codable, Python и предметную проекцию из одного описания. API-обёртка сохраняет прежний Python-эталон по умолчанию и подключает общую проекцию при явном выборе профиля. Codable сам не определяет выбор полей и канонические байты.

Явный порождённый профиль принимает только UTF-8 без BOM; целые числа находятся в диапазоне Int64, дробные и экспоненциальные токены запрещены. Максимальная глубина JSON — 64 от нулевого корня; внешняя оболочка и вложенная JSON-строка проверяются отдельно. Идентификатор задачи должен быть UUID с шестнадцатеричными буквами нижнего регистра. Точные дубли и канонически совпадающие Unicode-ключи отклоняются; ключи и строки не нормализуются. Эти ограничения охватывают также произвольную ошибку и опускаемые элементы. Прежний профиль сохраняет свою более широкую область, включая проверенные дроби и большие целые в `error`, глубокие опускаемые данные, различные NFC-совпадающие ключи, неканоническую непустую идентичность и внешние UTF-8 BOM/UTF-16/UTF-32. Совместимость двух профилей вне их общей области не заявляется.

Проверки и воспроизведение из корня checkout:

```sh
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_компактный_ответ_задачи.py
node --test Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_адаптер_ответа.cjs
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_ответа_задачи.py --выход профиль.json
```

Выход профиля направляется во временный каталог или материалы собственного этапа. Независимая проверка схем `Проекты/рабочий-контекст/проверить-контракт-ответа.py` использует отдельно объявленный `jsonschema` 4.23.0; основной CLI от него не зависит. Реальные запуск и профиль: [отчёт этапа](../../Журнал/2026-09-14_15-01-38_MSK_сократить-ответы-нативных-инструментов/отчёт.md). Полный smoke-check и проекция в этой контрольной точке не выполнены.

## Смешанная последовательность и повторное использование

[Профиль](tests/профиль-смешанных-ответов.cjs) вызывает тот же адаптер и настоящий Python CLI. Только `read_thread` заменён открытой фикстурой; файл сохраняется настоящей записью, ответ и SHA проверяются. Выполняются семь циклов: новый малый и крупный ответы, затем по два сохранённых чтения каждого; начальный размер чередуется. Частота реальной эксплуатации не наблюдалась, состав этого сценария задан явно.

```sh
node --test Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_смешанный_профиль.cjs
node Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль-смешанных-ответов.cjs <файл-профиля> прежний
node Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль-смешанных-ответов.cjs <другой-файл-профиля> порождённый
```

Нужны Node.js и Python стандартной поставки; измерено на Node.js 26.8.2 и Python 3.14.7. Укажите выходной файл во временном каталоге или материалах собственного этапа. Успех — код 0, JSON-профиль на диске и краткая сводка stdout; отказ — код 2. Все созданные профилем временные снимки удаляются после измерения; реальные пользовательские снимки этот сценарий не читает. Проверяемый оригинал доступен в каждом шаге до этой явной очистки. Ошибка не записывает успешный профиль.

[Измеренные 42 чтения](../../Журнал/2026-09-14_17-07-43_MSK_измерить-смешанную-последовательность-ответов/материалы/профиль-смешанной-последовательности.json) дали 116214 байтов компактного JSON+LF против условных 84026964 байтов полной выдачи на каждом шаге. Дисковый объём считается отдельно по 14 уникальным сохранённым файлам: 28008988 байтов. Выполнены 14 симулированных API-вызовов, 14 записей файлов, 70 локальных команд, 28 загрузок и 56 записей кэша. Живых API-вызовов — ноль. Каждый из 28 сохранённых шагов повторил принятый результат и проверил полный SHA без нового API и записи файла.

Медиана цикла из шести чтений — 552,216 мс. Первичное чтение малого/крупного ответа: 131,247/156,689 мс; сохранённое: 59,078/72,550 мс. Время включает фактические subprocess и I/O. Подготовка, контроль результата после вызова и удаление временного каталога исключены; вложенные времена уже входят в время шага. Файловый кэш ОС не сбрасывался. Время заглушки не является задержкой API или сети, время базового полного сценария не измерено; ускорение живой работы этим замером не доказано.

Малый ответ вырос 642 → 2763 байта, крупный уменьшился 4000642 → 2771. Снижение суммарной полезной выдачи на 99,862% относится только к заданной смеси 1:1. При одних малых ответах компактный формат здесь увеличивает объём примерно в 4,30 раза. Эти байты включают фактический приватный путь и LF, но исключают служебную оболочку инструментов, текст вызывающего кода и токенизацию. Сам путь не опубликован. Сохранённое чтение не доказывает свежести живого состояния.

[Отчёт и границы приёмки](../../Журнал/2026-09-14_17-07-43_MSK_измерить-смешанную-последовательность-ответов/отчёт.md). Этот профиль относится к прежней API/cache-обёртке; генерация и применение нового Swift/Python-контракта измерены отдельно в его руководстве.

## Подключение явного порождённого профиля

[Сопоставимые измерения](../../Журнал/2026-09-15_02-35-33_MSK_подключить-порождённые-модели/материалы/сравнение-профилей.json) сохраняют исходную серию, первоначальное превышение бюджета, устранение лишнего импорта и итоговую пару. Последние медианы цикла: прежний 464,664 мс, порождённый 574,528 мс; исходная — 466,551 мс. Во всех сериях равны входные SHA, объём выдачи, диска и счётчики; в последней паре совпали 42 SHA результатов после замены только приватного пути фиксированным маркером. Эта сверка выполняется после измеренного интервала. Полезные байты считаются повторной JS-сериализацией результата с LF; точные байты stdout и N/N−1 отдельно проверены обоими CLI-профилями.

Порождённый режим имеет дополнительную цену построения моделей. После устранения лишнего импорта одна серия прошла заранее заданный бюджет накладных расходов, но последнее крупное сохранённое чтение заняло 83,964 мс при пределе 82,019 мс; остальные группы и цикл прошли. Порог не менялся. Устойчивое соблюдение всего бюджета и ускорение не заявляются; дальнейшее изменение общего генератора ради этого среза не выполнено. Прежний профиль остаётся обычным путём.

[Применение к принятому нативному снимку](../../Журнал/2026-09-15_02-35-33_MSK_подключить-порождённые-модели/материалы/применение-принятого-снимка.json) подтвердило полное равенство результата прежнему принятому срезу: 885 → 2595 байтов, один настоящий CLI, без нового API или записи полного файла. [Отчёт подключения](../../Журнал/2026-09-15_02-35-33_MSK_подключить-порождённые-модели/отчёт.md) фиксирует проверку и её границы.

## Явная краткая выдача адаптера

Параметр `формат_выдачи: "краткий"` выдаёт `fum.краткий-ответ-задачи.1` после штатной проверки исходного снимка, SHA и выбранного профиля. По умолчанию действует `"подробный"`: прежний результат не меняется. Новый формат оставляет состояние задачи, текущий ход с ошибкой, полный выбранный ответ и его ход, `hasMore`, число ходов с ошибкой, один путь оригинала с SHA и явную границу сохранённого состояния. Временные метки, указатели и остальные поля восстанавливаются прежней выдачей из того же оригинала; новый файл ради сокращения не создаётся.

`максимум_байтов` ограничивает конечный `JSON.stringify(результат) + "\n"` в UTF-8. Ответ и ошибки не усекаются: превышение даёт отказ. Промежуточный подробный CLI по-прежнему ограничен 16000 байтами; если он не помещается, краткий режим также отказывает. Это отдельная транспортная граница, даже если сокращённый объект мог бы поместиться. Первый неуспешный новый вызов не принимает кэш; неуспешное чтение ранее принятого снимка не уничтожает его прежнюю привязку. Один saved-вызов использует один прежний CLI и не вызывает API или запись файла.

Для наблюдения за текущим выполнением используйте нативное ожидание с курсором; краткая сохранённая выдача не доказывает свежесть, полноту истории или завершение задачи. Профиль воспроизводится через отчётную обёртку командой `node Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль-краткой-выдачи.cjs <новый файл профиля>`: три чередующиеся пары используют одну открытую пустую страницу, реальные subprocess и проверку SHA, без живого API.
