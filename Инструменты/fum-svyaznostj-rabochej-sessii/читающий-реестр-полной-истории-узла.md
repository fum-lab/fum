# Читающий реестр полной истории узла

Новая версия читает два нативных потока от рождения до независимо выбранных конечных срезов. Она сохраняет строгий старый автомат копий, глобальных идентификаторов, порядка и пар инструментальных вызовов. Конечный ресурсный документ выбирает ROOT отдельно по полному Git-коммиту, точному пути обычного blob и SHA-256 его сырых байтов. Копия выбора внутри входа не принимается.

Результат доказывает учёт выбранных префиксов. Он всегда содержит `разрешение_эффекта: false`, `полный_LIVE_хвост_доказан: false` и `полнота_истории_доказана: false`. Это читающая граница, не ACT_B, приёмка реального цикла, переключение базиса или разрешение записи состояния.

## Запуск

Нужны Python 3.10+, POSIX и полный локальный Git-репозиторий с выбранным ресурсным документом. Вход и независимый выбор остаются приватными физическими обычными файлами вне публичного Git. Каждый нативный источник принадлежит текущему пользователю, имеет одну жёсткую ссылку и не допускает чужой записи; символические ссылки, алиасы, FIFO и усечение запрещены.

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/читающий_реестр_полной_истории_узла.py --корень-репозитория <физический-корень> --вход <приватный-вход.json> --выбранный-ресурс <независимый-выбор-ROOT.json>
```

Код 0 сопровождается единственным полным JSON-результатом в stdout. Код 2 сопровождается отказом в stderr и отсутствием успешного результата. Прерывание не даёт успешного доказательства. Полный stdout/stderr сохраняйте штатным приватным захватом; в публичный отчёт переносятся только допустимые метрики.

## Вход и независимый ресурс

Вход `fum.вход-читающего-реестра-полной-истории-узла.1` имеет ровно поля `схема`, `координатор`, `владелец`, `контроль`, `корни`, `источники`. UUID координатора и владельца различаются. `корни` связывает обе роли с их физическими W. `источники` содержит ровно два разных упорядоченных источника: координатор, затем владелец. Каждый задаёт `роль`, `задача`, `путь`, `начало`, `конец`, `промежуточные`; граница содержит положительное целое `граница` и сырой `sha256`. Промежуточные границы тоже должны быть точными LF-префиксами.

Отдельный selector имеет ровно `коммит`, `путь`, `sha256`. Выбранный обычный blob содержит `fum.ресурсы-читающего-реестра-полной-истории-узла.1` и ровно поля `схема`, `координатор`, `владелец`, `контроль`, `рождения`, `пределы`. `контроль` содержит полный `refs/heads/codex/...` в поле `ветка` и ожидаемый полный `коммит`; он совпадает с независимым входом и фактическим ref до чтения и перед выдачей. Коммит контроля является предком коммита ресурсного документа. Старый доступный документ не получает допуска после отзыва поколения.

`рождения` содержит обе роли с `задача`, `хэш_корня`, `коммит`. Сверяются полный UUID, SHA-256 UTF-8 физического W, исходный C и поддержанная оболочка `session_meta`. Для владельца обязательна версия рождения `agent_created_thread`. Репозиторий рождения — точный `https://github.com/fum-lab/fum.git`.

Все пределы обязательны и являются положительными целыми; bool, float, неизвестные версии и поля отклоняются:

| Поле                         | Граница                                                       |
| ---------------------------- | ------------------------------------------------------------- |
| рамок_на_источник             | Общий счётчик после рождения, без сброса на границах            |
| сырых_байтов_на_источник       | Весь выбранный RAW-префикс каждого источника                    |
| байтов_строки                 | Одна завершённая LF-строка, не более старых 64 МиБ парсера       |
| байтов_чтения                 | Суммарные RAW-байты разбора и заключительного повторного чтения  |
| идентификаторов_на_источник   | Все сохранённые ID в прежних нативных пространствах ключей      |
| байтов_идентификаторов        | UTF-8 сохранённых ID с конечным запасом 64 байта на ключ         |
| незавершённых_вызовов         | Суммарные pending RPC и MCP                                    |
| управляющих_оригиналов        | Сохранённые управляющие оригиналы                              |
| сжатий                       | Учтённые исторические рамки сжатия                             |
| промежуточных_границ          | Дополнительные конечные префиксы каждого источника              |
| байтов_результата             | Полный сериализованный JSON вместе с LF                        |
| время_нс                     | Общий монотонный срок от начала вызова, включая выбор ресурса  |

Загрузка ещё неизвестного ресурсного документа имеет отдельный конечный bootstrap-предел 120 секунд и прежние ограничения доверенного чтения Git-объектов. После получения ресурса все следующие Git-чтения используют оставшийся общий срок. Превышение срока, размера либо любого счётчика отравляет новый учёт и не создаёт частичного успешного результата. Бюджеты удерживаемых ID и записей ограничивают данные; максимальная резидентная память Python измеряется отдельно и не объявляется жёсткой квотой RSS.

## Сохранность и точность

Используется один новый экземпляр сжатого строгого автомата на источник. Его новые лимиты не меняют старый класс, launcher, raw-module, bridge или схемы `.1/.2`. Birth не входит в число рамок реестра; число строк результата учитывает его отдельно. IDs не забываются после копии, сжатия или освобождения завершённого payload. Раздельные пространства response/event/RPC/MCP сохраняют допустимые совпадения строковых номеров.

Сначала весь выбранный префикс разбирается и хэшируется; затем после чтения обоих потоков оба RAW перечитываются с независимыми SHA и физической сверкой. Контроль повторяется после ограниченной сериализации. Проверенные байты выдаются один раз. Входы и выданный объект не имеют общих изменяемых ссылок.

Рост за выбранным срезом остаётся `непроверенный_хвост` и не расширяет учёт. Изменение после заключительной сверки закрывает выдачу отказом. Это кооперативная граница единственного писателя и наблюдённой сохранности, не глобальная блокировка всех производителей или доказательство LIVE.

## Тесты и профиль

Запускайте через отчётную обёртку своей разрешённой сессии:

```text
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_читающего_реестра_полной_истории_узла.py -v
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_читающего_реестра_полной_истории_узла.py --каталог <новый-приватный-каталог-вне-Git>
```

Профиль создаёт одну открытую конечную Git/native-фикстуру с 131 073 рамками координатора и одной рамкой владельца. Три новых процесса отдельно измеряют подготовку, parse, учёт, сериализацию, readback, полный внутренний и внешний интервалы и максимальную резидентную память. Setup фикстуры исключён из повторов; кэш ОС не сбрасывается. Все RAW-каналы, отказы и хэши сохраняются приватно. Отказ или тайм-аут не запускает автоматический повтор.

Настоящий ресурсный документ ROOT выбирает после рассмотрения профиля. Открытая фикстура не измеряет реальный ROOT JSONL, bridge-бюджет 120 секунд или пригодность следующего эффекта узла. Профиль и контрольная точка сами этого выбора не выполняют.
