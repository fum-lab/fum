# Контроль границы готового этапа

Команда сохраняет объявленный состав этапа и время готовности. Повтор с теми же данными возвращает прежнюю запись, включая время. Изменение состава, отпечатка, набора проверок или предела ожидания через повтор отклоняется. Поздние экземпляры сообщений возвращаются отдельным списком для следующего этапа; текущая граница остаётся неизменной.

Самостоятельный CLI ниже проверяет структуру объявленных данных и вычисляет решение; сам по себе он не подтверждает Git и прохождение проверок. В штатное [создание коммита](создание-коммита.md) отдельно подключён адаптер поколений: команда `готово` принимает фактический индекс, первичные сообщения и успешные записи проверок, а `создать` требует совпадения с ними перед новым Git-коммитом. Восстановление существующей квитанции остаётся отдельным читающим путём.

## Готовность в создании коммита

Файл схемы `fum.поколения-готовности-коммита.1` имеет устойчивый адрес по каноническому физическому корню, полному ref, исходному OID, UUID задачи и запросу. Имена файлов сообщения, подготовки и квитанции не меняют этот адрес. На macOS хранилище находится в каталоге `FUM-private-<uid>/готовность-коммитов` внутри общего каталога пользователей; на остальных POSIX-платформах — в `.local/state/FUM/готовность-коммитов` домашнего каталога. Оно должно находиться вне Git; символические ссылки и неканоническое написание корня отклоняются. Файлы приватны, запись сериализована замком и атомарной заменой с `fsync`.

Готовность можно явно отозвать с номером поколения и основанием. Новое объявление после исправления сохраняет исходное время, наблюдённый возраст и старые сырые свидетельства. Допускаются исправления в прежнем содержательном составе и дополнительные записи запусков; новый запрос, сообщение или содержательный файл не включаются в старый этап. Строгое равенство действует внутри активного поколения. При замене проверок сохраняется явное соответствие прежних и новых UUID; достаточность проверок и смысл исправления оценивает корень.

В каждый новый допуск включена ранняя проверка наличия и активности готовности, затем окончательное сравнение снимка и всех UUID/SHA записей. Даже одно изменение форматирования прежней записи проверки закрывает допуск. Изменение часов назад не уменьшает уже наблюдённый возраст. Порог и решение сохраняются в квитанции создания.

Автоматическая классификация новых человеческих сообщений, очередь позднего ввода и детектор остановки ещё не подключены к этому адаптеру. Команды `готово` и `создать` вызываются явно. Нельзя объявлять весь механизм предотвращения задержек завершённым только по наличию этого стыка.

## Вход и сохранение

Снимок — JSON с точным набором полей:

- `задача` — корневой UUID; `ветка` — полный ref; `исходный_коммит` — полный OID.
- `запрос` — относительный путь текущего запроса; `разрешённые_цели` — непустой список точных относительных путей.
- `экземпляры` — непустой упорядоченный список идентичностей первичных сообщений, без повторов одного экземпляра.
- `отпечаток_содержимого` — SHA-256 подготовленного содержимого; `проверки` — непустой список UUID обязательных проверок.

Вход описывает только идентичности и границы. Оригиналы сообщений остаются в первичном JSONL и памяти Журнала; хэши не заменяют их. Символические ссылки и правильность регистра файлов снимок сам не доказывает: это относится к существующему допуску материалов.

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/контролировать-фиксацию.py объявить --снимок <снимок.json> --готовность <новый-приватный-файл.json> --предел-секунд 600
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/контролировать-фиксацию.py сверить --снимок <текущий-снимок.json> --готовность <приватный-файл.json> --поздние-экземпляры <список-идентичностей.json>
```

Порог задаётся явно; 600 секунд — пример, не установленная для всех задач норма. Запись готовности создаётся вне Git штатным приватным сохранением с правами `0600` и запретом перезаписи. Повтор из другого процесса не обнуляет время. Повреждённый или неполный файл закрыто отказывает; после сбоя записи нужен осмотр фактического результата. Отсутствие автоматического повторения не означает отсутствия уже созданного файла.

## Решение

При совпадении снимка действие — `зафиксировать-этап`: это приоритет штатного допуска и фиксации, а не вызов Git. По достижении предела дополнительно включается `задержка`. Изменение снимка возвращает `повторно-проверить-этап`; прежняя готовность при этом не заменяется. Явный флаг `--остановлено` возвращает `остановиться` независимо от возраста. Во всех этих состояниях начало следующего этапа не разрешается этим контролем.

Возраст вычисляется по времени эпохи Unix в наносекундах. CLI сохраняет максимальный наблюдённый возраст в соседнем приватном файле `.возраст.json`, привязанном к SHA-256 неизменной записи готовности. Сверка и сохранение сериализованы файловым замком. Уже возникшая задержка не исчезает после перезапуска или отката часов. Это календарное ожидание, включающее сон компьютера. Откат часов за время объявления отклоняется; скачок часов вперёд может дать ранний сигнал, который затем сохраняется. Сигнал не запускает расписание и не гарантирует срок, если контроллер не вызывается.

Список поздних экземпляров должен относиться к сообщениям после принятой границы. Самостоятельное сообщение об отмене, остановке или исправлении требует интерпретации контекста вызывающей стороной; его нельзя автоматически считать независимой новой работой. Переданный `--остановлено` имеет приоритет. Остановка и поздний ввод передаются заново в каждом вызове и пока не образуют устойчивую очередь внутри этого CLI. Следующий адаптер свяжет эти входы с первичным читателем и действительными проверками.

## Проверка и профиль

Адресные тесты покрывают неизменность границы, поздний ввод, порог, повтор без сброса возраста, остановку, дрейф, небезопасные входы и повторное чтение другим процессом. [Измеритель](tests/профиль_готовности_этапа.py) сравнивает решения с нулём и тысячей поздних сообщений через обычную отчётную обёртку. Он не измеряет весь цикл создания коммита.

[Профиль поколений](tests/профиль_поколений_готовности.py) измеряет 1, 10 и 100 поколений, приватную сверку с замком и `fsync`, объявление по настоящему индексу и создание Git-коммита. Сценарии и исходные SHA сохраняются в JSON; подробные границы и результаты находятся в [отчёте интеграции](../../Журнал/2026-09-23_13-13-13_MSK_подключить-готовность-к-созданию-коммита/отчёт.md).
