# Обычная независимая контрольная точка Журнала

Обычный ROOT и адресно допущенный обычный ребёнок получают собственную пару `запрос.md`/`отчёт.md`. Она сохраняет исходные команды и прежние проверки Creator, а навигация выводится из закреплённого Git-состава. Первоначальная установка создаёт только два файла собственной папки. Принимающий ROOT отдельно обновляет общие индексы.

Это явный профиль `fum.обычный-независимый-журнал.1`. Он не переопределяет прежние `start`, Creator `.7`, подготовку `.9`, ключ READY, мост нативного тела или ветку состояния узла. [Первый чистый сегмент](независимый-журнал.md) сохраняет собственные форматы и измерения.

## Четыре разные основы

| Обозначение | Что закреплено | Где проверяется |
| --- | --- | --- |
| C | Исходная постановка этапа; у обычного ребёнка она совпадает с прежним nativebirth по действующему ACT | Восьмиполевой план пары, Git blob и прежний ordinary guard |
| H | Полное принятое дерево Журнала, включая пары, материалы, RAW, типы и режимы | `fum.состав-принятого-журнала.1` |
| S | Независимо выбранный Git-коммит, путь и raw SHA файла состава H | Отдельный внешний selector и его совпадающая копия в контракте |
| A | Точный принятый родитель собственного нового коммита | `исходный_коммит`, дерево A и фактическое наложение W относительно A |

C, H, S и A не заменяют друг друга. Уже принятые данные A не требуют нового разрешения только потому, что появились после H. Новое изменение W относительно A вне конечной разрешённой области закрывает допуск. Индекс Git не является основанием этой авторизации.

Закрытый контракт `fum.контракт-независимой-контрольной-точки.1` имеет ровно `схема`, `открытая`, `состав`. `открытая` — план `fum.план-обычной-независимой-пары.1`; `состав` — копия selector. Копия не выбирает S: все новые API требуют отдельный вход `выбранный_состав`.

## Состав и первоначальная пара

`независимый_журнал.состав_принятого_дерева(корень, H)` читает полное Git-дерево до отбора записей. `построить_принятый_индекс` повторяет проверку состава и выводит точный `Индексы/навигация-журнала.md`. `Индексы/состав-журнала.json` закрепляет H; оба файла являются данными, а не полномочиями писателя.

`подготовить_пару` требует отсутствующую собственную пару. `отрендерить_пару` воспроизводит её начальные байты без установки, в том числе для сверки уже существующей пары. Оба используют неизменённый строитель P.1 и два закреплённых шаблона. `установить_пару` создаёт ровно два объявленных файла и допускает точный повтор начальной установки. Другие остатки папки закрывают установку.

Единственный видимый маркер `<!-- FUM-ОБЫЧНЫЙ-ЖУРНАЛ: 1 -->` и машинные метаданные находятся вне дословных команд и управляемого итога. Штатное наполнение сохраняет их через предусмотренные управляемые блоки; повтор наполнения не переопределяет основание этапа. План с `разрешение_установки: false` остаётся чистым объявлением.

Все принятые файлы H сохраняют точные байты, типы и режимы. Допустим только известный пустой непосредственный каталог `материалы/` принятой парной записи: Git не хранит его как blob. Лишние пустые каталоги, включая вложенные или чужие, закрывают проверку. Непустые вложенные каталоги принятого H сохраняются по точному составу. Полная фактическая структура каталогов и их режимы входят в доказательство слоя.

## Creator, READY и свежесть

| Контур | Вход Creator | Подготовленный результат |
| --- | --- | --- |
| Обычный ROOT | `fum.создание-коммита.9` | `fum.подготовленный-коммит.11` |
| Обычный ребёнок | `fum.создание-коммита.10` | `fum.подготовленный-коммит.12` |

Новые формы добавляют контракт к прежним закрытым параметрам контрольной точки. Ребёнок сохраняет прежнее independently selected ordinary поручение, nativebirth, полный ROOT JSONL, точные RAW/SHA, модель, stage0 scanner и фактический Git diff. Коммит имеет одного родителя A. Состав Журнала не заменяет ни одну из этих проверок.

ROOT использует неизменённый полный канонический `update_repository(W, check=True)`. Ребёнок сохраняет общий Markdown-индекс байтово равным H: полный экспорт всех Markdown-данных H с исходным индексом проходит тот же канонический checker без исполнения кода H. Затем проверяются все фактические WMD, имена, NFC, регистр, режимы и каноническая свежесть. Неизменённые чужие WMD равны H; собственные новые или изменённые WMD лежат в конечной области ACT. Индекс H не объявляется полным текущим индексом W.

Новая внешняя обёртка `fum.готовность-независимой-контрольной-точки.1` имеет четыре поля: `схема`, `привязка`, `готовность`, `доказательства_поколений`. Прежние пятикомпонентный ключ этапа, восьмиполевой внутренний снимок, четырёхполевое поколение и исходный epoch сохраняются. Каждая запись списка доказательств содержит номер поколения, SHA всего прежнего поколения и закрытое восьмиполевое доказательство слоя. Прошлые поколения и их контекст неизменяемы; READY повторно сверяет активное поколение и фактический слой перед эффектами.

`полная_свежесть_основы(корень, H)` — отдельная операция чтения тех же точных Markdown-данных H. Она не устанавливает состав, не выбирает S и не разрешает запись.

### Фактические права закрытых материалов Markdown

Исторический материал допускает `0600` или `0644` только при точном пути внутри принятой записи H, обычном Git blob `100644` и совпадении всех байтов. Само имя каталога `материалы/` не предоставляет исключения. Новые и открытые Markdown, запросы, отчёты и индексы требуют `0644`; неизвестные права, executable bits, символические и жёсткие ссылки, чужой владелец или подмена файла закрывают допуск. Consumer читает историю без `chmod` и без обновления её содержания. На время канонической проверки чтением устанавливается `GIT_OPTIONAL_LOCKS=0` с восстановлением прежнего окружения: проверка не обновляет Git-индекс вслед за поздней сменой режима файла.

Доказательство `fum.доказательство-наложения-независимого-журнала.2` добавляет явный список `историческая_разметка`: путь, SHA256 байтов и восемь полей фактической identity — устройство, inode, полный режим, владелец, число ссылок, размер, mtime и ctime в наносекундах. FD и точный адрес сверяются до и после чтения; перед возвратом proof повторяются снимки всех проверенных Markdown. READY связывает эти данные с поколением, поэтому поздний переход `0600↔0644` или замена inode запрещают следующий эффект при сохранённых Git-байтах.

Прежнее доказательство `.1` сохраняет ровно восемь прежних полей и читается без миграции. Оно не превращается в `.2` на месте: новая готовность использует обычный явный отзыв и следующее поколение с сохранением прежнего префикса. Старые квитанции и их буквальное чтение сохраняются. Независимый selector S проверяется повторно при чтении полного слоя; автономный инвентарь допускает историческое исключение лишь из неизменённого файла состава в Git HEAD принятого родителя.

При проверке области записи фасад и Creator передают тот же независимо выбранный S отдельным аргументом. Это позволяет установить состав из отдельного коммита поставщика, сохранив HEAD принимающей ветки на H. До инвентаризации повторно проверяются Git-байты, рабочие байты и строгий режим `0644`; исходная идентичность файла сохраняется до заключительной сверки. Копия S внутри maker не заменяет внешний выбор. Без него автономный режим сохраняет прежний отказ, если рабочий состав отличается от принятого HEAD.

При проверке свежести обычный публичный дочерний контур передаёт тот же независимо выбранный S через связность и READY. Разрешения ACT, точные цели и фактическое состояние Git сохраняют прежние проверки. Двухаргументный вызов `проверить_свежесть(корень, пути)` сохраняет поведение `выбранный_состав=None`: источник выбирается от HEAD, а отличающийся рабочий состав закрывает допуск. Полный CHILD-фасад сохраняет отдельный строгий отказ на глобальные индексы, даже когда обычный публичный контур разрешает их по ACT. Адресные тесты проверяют внешний S, несовпадающие selectors без подстановки HEAD, прежний вызов, полный отказ CHILD-фасада и изменение только собственного отчёта при обновлении recency.

Для адресной проверки запускается `python3.14 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_передачи_выбранного_состава.py -v`. Профиль стандартного `cProfile` повторяет этот набор в трёх свежих Python-процессах; файлы `pstats` сохраняются в новом приватном каталоге вне Git. Профиль включает подготовку временных фикстур и ожидания подпроцессов. Кэш ОС не очищается; интервалы вложенных вызовов не складываются. Этот замер не определяет стоимость живого ROOT и не доказывает ускорения всей контрольной точки.

Адресные сценарии находятся в `tests/test_исторических_режимов_разметки.py`. Команда `tests/профиль_исторических_режимов_разметки.py --выход <новый JSON>` запускается через отчётную обёртку и создаёт три свежих процесса: парное сравнение прежнего и нового инвентаря на `0644`, затем новый инвентарь на `0600`. Подготовка малой Git-фикстуры и контроль отсутствия эффектов исключены из таймера. Замер не характеризует стоимость полного ROOT, Creator или холодного кэша ОС.

## Подготовка и CLI

Фасад `fum.фасад-независимой-контрольной-точки.1` содержит прежние технические входы своего ROOT/child контура, `начало`, `схема` и путь `контракт_журнала` к отдельной приватной копии контракта. ROOT явно выбирает `контур: обычный` и готовность; ребёнок содержит приватный путь обычного поручения. Поля глобальных обновлений, готовности ROOT и переноса модели не входят в новую дочернюю форму.

`подготовка_этапа_коммита.построить_план(вход, выбранный_состав=путь)` только читает; результат — `fum.план-фасада-независимой-контрольной-точки.1`. `выполнить` получает тот же внешний путь и SHA плана. Отдельные файлы выбора S и копии контракта должны принадлежать писателю, иметь режим 0600 и находиться в его приватном каталоге 0700. Их raw SHA и идентичность файла закрепляются в плане и пересверяются перед эффектами. Immutable план имеет режим 0400.

Фасад последовательно устанавливает собственную пару, создаёт собственный каталог модели, вызывает прежнее наполнение и v4, ставит точные цели в индекс, выполняет терминальный предпросмотр и полную связность. ROOT отдельно объявляет READY. Ребёнок обновляет свежесть только фактически изменённых разрешённых MD и затем читает полный слой H/W. Фасад сам не создаёт коммит.

Обёртка структуры предоставляет два явных режима `обычная-пара-план` и `обычная-пара-установить`. Они принимают `--repo-root`, `--вход`, `--выбранный-состав`, `--план`; установка дополнительно требует `--sha256`. Первый режим сохраняет приватный план, второй устанавливает только объявленные два файла. Прежний CLI передаётся неизменённому P.1. Неизвестный, частичный, изменившийся или чужой вход закрывает установку до записи.

## Генератор и позднее собственное время

Генератор `fum.подготовка-дочернего-поручения.7`, план `fum.план-подготовки-дочернего-поручения.4` и смысл `fum.смысл-дочернего-поручения.5` выбираются явно. Внешний приватный файл S передаётся отдельным keyword/CLI аргументом, его raw SHA и идентичность входят в план. Старые формы и поздний `start` не используются как скрытая проекция новой версии.

Политика `fum.политика-позднего-журнала.2` сохраняет метку и заголовок; её `служебные_цели` — пустой список. Фаза `начало` читает настоящий собственный CLI `--format both`, связывает C с прежним nativebirth и создаёт только приватное свидетельство `fum.свидетельство-позднего-журнала.2` с чистым планом пары. Публикационная папка до ACT отсутствует. ROOT отдельно рассматривает время, первоначальные RAW и полный поздний LIVE, коммитит review и адресный ACT с одной собственной папкой. Затем дочерние входы `.10` и фасад `.1` устанавливают два файла этой папки.

Намерение, объявленные выходы и завершённая квитанция имеют разные роли. Частичный либо неизвестный исход запрещает новый эффект. Точный повтор проверяет весь выведенный результат квитанции и сохранённые установки; для ACT/входов повторяет review B1 и полный LIVE-guard. Новое человеческое сообщение после B1 требует нового рассмотрения. Полный пересчёт композиции перед эффектами сохраняется; измерения первого сегмента и Creator/READY не являются замером стоимости генератора.

### Пересмотр актуальности до начала ребёнка

Позднее человеческое сообщение между коммитом постановки и запуском не требует переписывать первоначальный текст поручения. Для смысла `.5` и генератора `.7` предусмотрен отдельный явный выбор `предстартовое_решение` и `предстартовый_хэш`; CLI принимает `--предстартовое-решение` и `--предстартовый-хэш`. Оба аргумента передаются вместе в приглашение, план и применение фазы `начало`. Прежние формы, фазы `постановка`, `акт` и `входы` их отклоняют. Без выбора сохраняется прежняя строгая проверка исходной границы.

Выбранный файл `fum.предстартовое-рассмотрение-root.1` имеет режим `0600` в собственном каталоге `0700`. Его закрытые поля: `схема`, `координатор`, точные Git-селекторы `решение` и `постановка`, `исторический_контекст` и полная `координация` нового пересмотра. SHA выбирается извне. Пересмотр сохраняет исходные основания, уточнения, текст поручения, ветку и область. Проверяются все оригиналы, неоднозначности и настоящий LIVE; два префикса дополнительно связываются общей сырой цепочкой SHA, включая служебные байты.

Приглашение остаётся побайтно историческим. План начала получает явную версию `fum.план-подготовки-дочернего-поручения.5` и поле `предстартовое_рассмотрение`: отдельно закреплены историческая основа и новый актуальный контекст. Применение и точный повтор требуют тот же внешний выбор и пересверяют его перед эффектами; план не выбирает собственный SHA. Частичное намерение по-прежнему запрещает повторный эффект. Начало создаёт только приватное свидетельство, без публикационной пары.

Последующий ACT сохраняет прежний отдельный коммит позднего решения ROOT. Предстартовый пересмотр проверяется исторически; новый контекст ACT должен продолжать его по экземплярам и общей сырой цепочке. Код проверочного модуля, выбранный файл и RAW входят в закреплённый контур также для ACT и дочерних входов. Историческое начало не объявляется текущим разрешением на запись. Этот контракт сам по себе не подтверждает запуск живого ребёнка или приёмку всего узла.

Адресный набор: `tests/test_предстартового_рассмотрения.py`. Он проверяет отказ на изменённые основания и служебные байты, сохранение исторического приглашения, собственное начало, повтор без новых установок и отдельный поздний ACT.

## Ограниченное запоминание позднего разбора индекса

Читатель цепочки подготовки сохраняет только последний успешно проверенный файловый Git index внутри идентичности одного подлинного допуска. Слабый ключ не удерживает допуск; значение содержит собственные неизменяемые байты и глубоко неизменяемую регистрационную проекцию. Между допусками и процессами результат не переносится. Короткий процессный замок защищает только таблицу и её учёт, а файловое чтение остаётся вне него.

Каждая поздняя граница полностью читает индекс заново и сохраняет прежние проверки путей, дескриптора, владельца, числа ссылок, режимов, физической идентичности и дрейфа. Попадание требует точного равенства всех новых байтов сохранённым, затем проекция повторно сравнивается с ожидаемой. Изменение обычных записей при прежней регистрации даёт законный промах с полным разбором и checksum. Повреждённый checksum, иной gitlink и изменение регистрации сохраняют прежний отказ. Новый результат публикуется после всей поздней сверки; первичный допуск дополнительно сохраняет свой внешний дедлайн. Отказ или тайм-аут не устанавливает кандидат.

Пределы удержания: 16 МиБ на запись, 64 МиБ суммарно, не более восьми записей. Вес консервативно включает `sys.getsizeof` байтов, всех элементов tuple-проекции, строки и числа, резерв 1024 байта на запись и 4096 байтов на активную таблицу. Исчерпание любого предела сохраняет полный разбор без нового запоминания и не вытесняет другой допуск. Это предел удерживаемого memo, а не RSS или временных буферов полного чтения и parser. Диагностическая функция `профиль_запоминания_индекса` возвращает свежие скаляры: процессные попадания/промахи и удержание собственного допуска/всей таблицы.

Воспроизводимый парный профиль вызывается через отчётную обёртку текущего Журнала:

```text
python3.14 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_принятого_создателя.py --цепочка поздний-индекс --повторы 3 --выход <новый-приватный-JSON>
```

Профиль сравнивает исходный читатель из `712da538a86171cbcbf9b10827bedb1c97a87354` с текущим читателем на одном неизменном файловом индексе из 33 405 записей. Индекс синтетически расширен обычными записями в воспроизводимой временной Git-фикстуре с сохранением её настоящей регистрационной проекции; это не индекс живого ROOT или READY. Три пары АБ/БА/АБ используют шесть свежих процессов `-I -S -B`. Первичный допуск, уже включающий внутреннюю позднюю сверку, измеряется отдельно от трёх явных поздних границ. Сохраняются вызовы и время parser, попадания/промахи, прочитанные и удержанные байты, полный поздний интервал и пик RSS каждого процесса. Проверяются равные исходы, порядок чтений, число границ, обязательный объём чтения и неизменность фикстуры/наблюдённых исходников. Сырые каналы, копии исходного читателя и исполняемого профиля, хэши остальных наблюдённых исходников и корпус остаются рядом с результатом в приватном каталоге; при отказе сохраняется неполный итог. RSS включает импорты и первичный допуск. Кэш ОС не очищается; время этого участка не доказывает ускорения всего восстановления или узла.

## Проверяемая граница

Открытые фикстуры проверяют ROOT9 и child10 через настоящее Git-дерево, штатное наполнение, v4, связность, READY, Creator и точный повтор квитанции. Отрицательные случаи проверяют подмену S, контракта, исторического доказательства, режима каталога, принятого материала, чужую RAW и новую запись вне ACT. Нормативная матрица отдельно сохраняет полные шесть тел, 265 исходных единиц и 227 правил.

`tests/профиль_независимой_контрольной_точки.py --контрольная-точка` запускает три новых процесса и сохраняет отдельный формат `fum.профиль-независимой-контрольной-точки.2`. Он добавляет к интервалам API точные записи штатного измерителя создателя, включая историческую привязку, повторные сверки независимого Журнала, активный слой и три последних допуска перед эффектами. Номера локальны одному вызову Create. Буквальный replay имеет собственные измерения только в результате профиля: прежняя квитанция не переписывается. Время последних допусков включает вложенную сверку слоя; эти записи и внешние интервалы API не суммируются как независимые стадии. Количество, порядок и исходы проверок сохраняются, дополнительные сверки не запускаются. Сохранённые результаты формата `.1` не преобразуются и не объявляются содержащими новые метки. Отдельно измеряются полный канонический check данных реального H, пик памяти Python и RSS процесса. Холодный кэш ОС не заявляется. Профиль первого сегмента сохраняет прежний формат и границу.

`tracemalloc` измеряет только отдельную проверку H. CPU и RSS относятся к основному worker без дочерних процессов; RSS также охватывает импорты, подготовку фикстур и оба цикла.

Эти фикстуры и замеры не доказывают исполнение нативного рабочего цикла, готовность моста, R1 или состояния узла. Для собственной поставки сначала нужен отдельно принятый обычный consumer K; кандидат не выбирает его и не принимает собственный код. Интеграция и рабочий переход выполняются принимающим ROOT по отдельному действующему допуску.

Первый производственный выбор S остаётся отдельным незакрытым стыком. Лабораторные фикстуры закрепляют состав отдельным Git-коммитом без собственного stock-Журнала. Реализованного bootstrap первого S, который учитывает собственную запись обычного коммита `.7/.9`, её навигационные изменения и общий Markdown-индекс, здесь нет. Принятый родитель A не разрешает вторую открытую пару и не отменяет точную H-память. Поэтому лабораторная поставка не разрешает прямую активацию ROOT; необходим отдельный согласованный переход и его доказательства без описания будущего коммита.
