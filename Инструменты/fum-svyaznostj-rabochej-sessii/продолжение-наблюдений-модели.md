# Классификация продолжения наблюдений модели

Чистая функция `scripts/классификация_продолжения_модели.py` сравнивает две полные истории модели с предъявленными сырыми байтами текущего снимка. Она различает неизменные наблюдения, добавленные наблюдения той же пары, наблюдаемое переключение и неизвестность. Диагноз служит самостоятельным результатом чтения. Он не разрешает подготовку, готовность, создание коммита, повтор эффекта или запись состояния узла.

## Вход и обычный вызов

Python API — `классифицировать_продолжение(исходная_история, текущая_история, подтверждение)`. Обе истории сохраняют весь закрытый формат `fum.история-модели.1`: UUID задачи, SHA исходной строки `session_meta`, счётчик, события и пропуски, последнее наблюдение с точной позицией и SHA строки, завершённую границу, размер снимка и неполный хвост. Компактная квитанция импортёра не заменяет историю.

`подтверждение` имеет ровно шесть полей:

- `схема`: `fum.проверка-продолжения-наблюдений-модели.1`;
- `исходная_история_sha256` и `текущая_история_sha256`: SHA-256 канонических байтов полных историй, сериализованных прежним `сообщения_задачи._байты`;
- `сырые_байты_снимка`: неизменяемый Python `bytes` всего текущего снимка, включая возможный неполный хвост;
- `дописано_после_исходного_снимка` и `дописано_после_текущего_снимка`: целые неотрицательные счётчики именно соответствующих чтений.

Размер сырых байтов должен точно совпадать с текущим размером снимка. Функция сама вычисляет SHA текущего завершённого префикса и исходного префикса внутри тех же байтов. Затем неизменным чистым строителем `история_модели._приём` восстанавливает обе истории и сравнивает их целиком каноническими байтами. Пересчитанный хэш нарисованного счётчика, события или последнего наблюдения не заменяет соответствующих сырых данных.

Вызывающий слой заранее сохраняет результаты обоих чтений и отдельно наблюдает дописание после каждого снимка. Эти счётчики не являются разницей между нынешним размером источника и прежней границей. Функция доказывает отношения предъявленных байтов и историй; происхождение чтения, его актуальность и позднюю стабильность живого источника проверяет вызывающая сторона. История сама не хранит поле `дописано_после_снимка`, поэтому нулевое значение нельзя вывести из неё или заменить непроверенным `True`.

Вызывающая сторона сохраняет аргументы стабильными в пределах вызова; общая атомарность памяти разных потоков здесь не заявлена. После сверки хэшей диагноз вычисляется из двух самостоятельно восстановленных историй. Поздняя правка предъявленного словаря не может убрать уже проверенное промежуточное переключение.

Например, из физического корня FUM после подготовки полных историй и подтверждённых результатов чтения:

```python
import hashlib
import json
from pathlib import Path
import sys

sys.path.insert(0, 'Инструменты/fum-svyaznostj-rabochej-sessii/scripts')
import сообщения_задачи
from классификация_продолжения_модели import классифицировать_продолжение

исходная = json.loads(Path('ранняя-история.json').read_bytes())
текущая = json.loads(Path('текущая-история.json').read_bytes())
раннее_чтение = json.loads(Path('ранняя-квитанция.json').read_bytes())
текущее_чтение = json.loads(Path('текущая-квитанция.json').read_bytes())
подтверждение = {
    'схема': 'fum.проверка-продолжения-наблюдений-модели.1',
    'исходная_история_sha256': hashlib.sha256(сообщения_задачи._байты(исходная)).hexdigest(),
    'текущая_история_sha256': hashlib.sha256(сообщения_задачи._байты(текущая)).hexdigest(),
    'сырые_байты_снимка': Path('подтверждённый-снимок.jsonl').read_bytes(),
    'дописано_после_исходного_снимка': раннее_чтение['дописано_после_снимка'],
    'дописано_после_текущего_снимка': текущее_чтение['дописано_после_снимка'],
}
print(json.dumps(классифицировать_продолжение(исходная, текущая, подтверждение), ensure_ascii=False))
```

Этот пример получает данные из файлов; само сравнение после загрузки модулей не выполняет файловых операций, процессов или чтения часов и не вызывает импортёр с сохранением. Загрузка существующих зависимостей читает их исходники для прежних отпечатков. Сырые байты остаются приватными и в результат не входят. Они передаются в памяти; стоимость проверки линейна по размеру снимка и истории.

## Результаты и отказы

Результат `fum.классификация-продолжения-наблюдений-модели.1` содержит ровно `схема`, `диагноз`, `причины`, `новых_наблюдений`, `новых_событий` и два хэша входных историй. При неизвестности оба числа равны `null`; свободный текст входа не экспортируется.

| Диагноз                               | Смысл                                                         |
| ------------------------------------- | ------------------------------------------------------------- |
| `неизменный`                          | Новых модельных наблюдений нет; немодельные строки допустимы.   |
| `добавлены_наблюдения_той_же_пары`      | Счётчик вырос, добавленные наблюдения сохраняют известную пару. |
| `наблюдаемое_переключение`             | Добавленная область содержит смену модели либо усилия.         |
| `неизвестность`                       | Префикс, полнота, идентичность или модельная пара не доказаны.  |

Проверяются все модельные события, предыдущие пары и последнее наблюдение действующим `автор_коммита.проверить_токен`. Литералы `unknown`, `unavailable`, `unset`, `null` и смешанный регистр неизвестны. Служебные причина и инициатор импортёра остаются `unknown` и не считаются модельной парой.

Добавленное A → B → A даёт переключение, даже если последнее A совпало с исходным. Промежуточный неизвестный токен, пропуск, повреждённая строка или неполный хвост дают неизвестность с приоритетом над переключением. Другой UUID или `session_meta`, изменённый либо усечённый префикс, несвязанная история, лишние сырые байты и дописание после любого снимка также не подтверждают продолжение. Исторические известные переключения до исходной границы не объявляются новыми.

Лишние или отсутствующие поля, неизвестная схема, неверные вложенные типы и `bool` вместо целого числа вызывают `ValueError`. Исправьте вход и повторите отдельную диагностику. Неизвестность требует нового подтверждённого чтения либо разбора конкретной причины. Ни один исход не запускает автоматическое продолжение.

## Воспроизведение проверок и профиля

В назначенной рабочей сессии запускайте команды через штатную отчётную обёртку:

```text
python3.14 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_классификации_продолжения_модели.py
python3.14 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_классификации_продолжения_модели.py
```

Профиль выполняют в трёх свежих процессах. Подготовка синтетических снимков исключена из измерений; отдельно наблюдаются хэширование, повторное построение историй и общий вызов. Вложенные длительности не складываются с общей. Проверки и профиль не доказывают устранения прежней задержки поставки B: для этого нужны отдельная приёмка, новый версионный допуск и реальная поставка.
