# Явное принятие поручения координатора

[Приём](scripts/приём_делегации.py) сохраняет один отдельный акт принятия в `Планирование/задачи/<UUID-исполнителя>/принятие-делегации.json`. [Допуск](scripts/проверить-продолжение-задачи.py) проверяет его покрытие работой существующего собственного плана v1. Нулевой остаток человеческих сообщений не скрывает принятое поручение без работы.

До принятия вызывающий независимо выбирает JSON с полями `координатор`, `исполнитель`, `коммит`, `путь`, `sha256`. Полный OID выбирает неизменяемый коммит координатора, путь — обычный файл поручения в нём, SHA-256 — его полные исходные байты. Этот набор передаётся как `--доверенное-поручение '<JSON>'`; его нельзя извлекать из проверяемой записи принятия. Guard также поддерживает `FUM_DELEGATION_TRUST`: латинское имя нужно для переносимого назначения переменной окружения POSIX shell. Явный CLI имеет приоритет. XML, произвольный вывод инструмента и разговорное «принято» не выбирают доверенный источник.

Координаторский файл имеет схему `fum.поручение-координатора.1` и поля `координатор`, `исполнитель`, `работа`, `поручение`. Последнее содержит непустое `действие` и список строк `ограничения`. Проверка читает полный DAG выбранного коммита через прежний читатель v3 и его независимо закреплённый генезис. Корневая работа должна быть доступна в выбранном снимке. Рабочее дерево координатора не читается; выбранный коммит не обязан быть предком HEAD исполнителя. Это поддержка одного закреплённого координатора, а не произвольных корней.

Отдельный явный акт имеет схему `fum.принятие-делегации.1` и ровно следующие поля:

- `выбранное_поручение` — точная копия независимо переданного набора, проверяемая по нему;
- `корневая_работа`, `корневое_основание` — существующая работа и её проверенное человеческое основание из выбранного реестра;
- `план` — точный относительный путь собственного плана v1;
- `работа` — собственные `идентификатор`, `действие`, `основание`. Действие совпадает с поручением исполнителю. Основание сохраняет настоящий собственный UUID и дословный запрос; чужое корневое основание хранится отдельно.

Порядок запуска:

```text
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/приём_делегации.py --корень-репозитория . --codex-thread-id <UUID-исполнителя> --доверенное-поручение '<независимо выбранный JSON>' --запись <подготовленный-акт.json>
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/проверить-продолжение-задачи.py --корень-репозитория . --codex-thread-id <UUID-исполнителя> --доверенное-поручение '<тот же независимо выбранный JSON>' --план <план.json> --исходник <собственный-JSONL> --перед-завершением --профиль
```

Приём выполняет создание при ожидаемом отсутствии либо идемпотентный повтор точных байтов, используя приватный Git-замок, повторную сверку входов, атомарную замену и синхронизацию каталогов. Другое принятие поверх существующего запрещено. Операция не регистрирует человеческое сообщение и не меняет план. После неё обычным изменением собственного плана регистрируется работа с теми же тремя неизменяемыми полями, состоянием `доступна` и `свидетельство: null`.

До регистрации работы guard возвращает код 2 с указанием непокрытого принятия. При доступной работе он возвращает код 3 и её идентификатор по обычному порядку плана. Подмена определения, другой план, отсутствие независимого входа при существующем принятии, удаление либо изменение принятия на любом родительском ребре достижимого DAG дают отказ. Перед выводом повторно сверяются источник поручения, локальные входы и HEAD. Проверенный неизменяемый координаторский DAG второй раз не обходится. Это наблюдаемая стабильность, а не транзакция против произвольного внешнего писателя.

Независимо выбранное поручение требует существующей записи принятия: без неё код 2, в том числе после удаления ещё не закоммиченного файла. Вызывающий сохраняет выбранный набор во всех последующих вызовах. До первого коммита одновременно утраченные файл и внешний вход неотличимы от отсутствия делегации; это окно не закрыто одним fsync файла. Команда приёма подтверждает запись на диск, но не закрепление Git-истории или нативной конфигурации. После коммита удаление записи обнаруживается и без переданного выбранного входа.

Полнота ограничена сохранённым проверяемым принятием. Несохранённые разговорные принятия автоматически не обнаруживаются. Состояние работы остаётся только в v1: его свободное свидетельство завершения не становится закрытой приёмкой координатора. Реестр v3 и корневая приёмка не изменяются. Поддержка нескольких принятий, их миграции и снятия в этот контракт не входит. Подтверждённая человеческая остановка сохраняет приоритет.

Адресные сценарии воспроизводятся через отчётную обёртку командой `python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_приём_делегации.py`. [Измерение реального входа](../../Журнал/2026-09-16_16-25-45_MSK_связать-принятие-делегации-с-работой/отчёт.md) показало 3,318 с после оптимизации: бюджет Stop 3 с не подтверждён. Нативное подключение и Trust этим результатом не доказываются.
