# Приватный комплект перехвата завершения

[Подготовка](scripts/подготовить-комплект-завершения.py) извлекает четыре исходника из одного точного Git commit, сохраняет их иерархию и печатает проверяемого кандидата Stop. Она не устанавливает настройки, не меняет Trust, не запускает полученный project-код и не создаёт состояние реальной задачи.

## Вход и результат

Обязательны полный 40-значный lowercase commit OID, абсолютные источник, приватное хранилище, интерпретатор, дерево данных guard, фактический cwd задачи и каталог состояния; отдельно передаются UUID и конкретные относительные файлы прогресса. Необязательный план также относителен дереву данных. Сокращённые OID, refs, теги вместо commit и формат Git SHA-256 не принимаются.

Хранилище задаётся вне любого обнаруженного Git-предка: запрещены `.git` любого типа и консервативно распознаваемый bare-layout. Все компоненты приватного пути проверяются без символических ссылок; родитель должен существовать. Само хранилище создаётся 0700 либо принимается с уже точными правами и владельцем. Существующее пользовательское состояние не исправляется ради подготовки.

Команда запускается из собственного checkout. Ниже все угловые обозначения — плейсхолдеры, не готовые машинные пути:

```text
python3 -I -S -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/подготовить-комплект-завершения.py --источник <абсолютный-репозиторий-источника> --commit <полный-OID> --хранилище <приватный-каталог-вне-Git> --интерпретатор <абсолютный-Python> --корень-репозитория <дерево-данных-guard> --ожидаемый-cwd <фактический-cwd-задачи> --codex-thread-id <UUID-задачи> --каталог-состояния <приватное-состояние-вне-Git> --файл-прогресса <относительный-результат>
```

Stdout содержит JSON со схемой `fum.кандидат-комплекта-Stop.1`, путём комплекта, SHA-256 манифеста, самим манифестом, кандидатом `hooks` и справочным SHA-256 загрузчика. Вывод содержит локальные пути: его следует хранить приватно, а не без проверки публиковать в FUM. При отказе stdout пуст, код 2 и ограниченная по назначению диагностика в stderr; подготовка не выдаёт отказ за готового кандидата.

Манифест связывает commit, tree, четыре пути, исходные blob OID, режим Git 100644, приватный режим 0400, размер, SHA-256 и конфигурацию выполнения. Байты не преобразуются. Итоговый каталог именуется `stop-<SHA256-манифеста>`, каталоги внутри имеют 0500. Помимо четырёх `.py` разрешён только `манифест.json` 0400 и необходимые каталоги. Одноимённая повреждённая цель не ремонтируется и не заменяется; исправление требует отдельного решения человека.

## Проверка до исполнения

Приватные предки должны принадлежать текущему UID либо системе. Запись группы/прочих допустима только у такого доверенного предка со sticky-bit; обычный world-writable предок отклоняется. Это сохраняет допустимость стандартного общего временного каталога, не разрешая другому владельцу заменять приватную цепочку.

При извлечении проверяются SHA-1 самого commit, каждого промежуточного tree и конечных blobs. Следующий OID берётся из уже проверенных бинарных байтов родительского tree; вывод `ls-tree` не служит самостоятельным доказательством цепочки. Проверка не полагается на автоматическую сверку SHA при обычном чтении Git-объекта. Это ограничение проверено синтетической статической подменой subtree и согласуется с [путём чтения объектов Git 2.54](https://raw.githubusercontent.com/git/git/v2.54.0/object-file.c).

Граница приватного пути также отклоняет административный каталог `HEAD + commondir`, не читая содержимое `commondir` и не переходя по нему: Git поддерживает вынесенный общий каталог объектов, что закреплено в [распознавании Git-каталога](https://raw.githubusercontent.com/git/git/v2.54.0/setup.c). Проверка консервативная: похожий служебный layout тоже отклоняется.

Доверяемая command содержит весь inline-загрузчик, буквальный SHA-256 манифеста, точный путь комплекта и UUID. Она использует `exec`, очищенное окружение `env -i`, фиксированный `PATH` и абсолютный настоящий Python с `-I -S -B`. Подстановка путей выполняется через `shlex.join`, включая кавычки и знаки оболочки. Флаги изоляции дочернего guard должны быть уже включены в исходный adapter commit; внешний `-S` сам по себе не наследуется ребёнком.

Загрузчик до исполнения project-кода сверяет закрытую схему манифеста, полный инвентарь, владельца, точные режимы, обычный тип файлов, число жёстких ссылок 1, размеры, SHA-256 и Git blob SHA-1. Каждый исходник ограничен 1 МиБ, манифест — 64 КиБ. Лишние `.py`, `.pyc`, `__pycache__`, неизвестные файлы и каталоги, ссылки, спецфайлы и неверные поля означают отказ. Адаптер исполняется через `compile/exec` из уже прочитанных проверенных байтов с настоящим `__file__`. Соседние модули находятся по сохранённой иерархии:

- `scripts/перехватить-завершение.py`;
- `scripts/проверить-продолжение-задачи.py`;
- `scripts/обязательства_задачи.py` того же навыка;
- `Инструменты/fum-otchyotyi-o-zapuskakh-proverok/scripts/отчёты_о_запусках_проверок.py` относительно корня комплекта.

Успешный загрузчик не читает stdin, не добавляет служебный stdout и не перехватывает `SystemExit` адаптера. Только при собственном отказе он читает не более 65 536 байтов за одну секунду: доказанный UUID+Stop получает диагностическое `continue:false`, неизвестное или чужое событие — лишь `systemMessage`. Это не утверждение выполнения обязательств. Сигналы и отказ самого интерпретатора не превращаются в фиктивный успешный JSON.

Подготовка сериализует публикацию через приватный `flock`, собирает отдельный временный каталог, проверяет его, синхронизирует и переименовывает. Повтор принимает существующий комплект только после полной проверки, не меняя его байты, права и mtime. Остатки аварийной подготовки автоматически не разыскиваются и не удаляются. Неуспешный текущий временный каталог убирается только по известному собственному пути.

## Граница доверия и включения

Trust определения закрепляет строку с загрузчиком и хэшем манифеста, но не является глобальным доверием всем будущим байтам по пути. Интерпретатор, его stdlib, ОС и выбранный Git остаются внешней доверенной основой; их байты манифест не аттестует. Проверено на POSIX macOS, Python 3.14.7 и Git 2.54.0; загрузка stdlib требует Python 3.11 или новее. Проверка типов/режимов не заявляет защиту от злонамеренной конкурентной подмены тем же UID. Read-only режимы не являются неизменяемыми флагами ОС.

Приватный комплект не заменяет данные guard: реестр, план, карточки и Git-объекты читаются из отдельно назначенного настоящего дерева. Между проверкой и ленивым чтением соседнего кода не заявляется защита от атак владельца файлов. Состояние и native Trust также не входят в манифест; ограничение продолжений остаётся обязанностью адаптера.

Координатор отдельно проверяет вывод, выбранный commit, четыре SHA, фактический cwd, пути, лимиты и действующий слой настроек. Затем человек доверяет конкретному определению в штатной поверхности Codex. Эта автоматизация не пишет `hooks.json`, `trusted_hash`, пользовательские настройки или чужой checkout. Имя отдельного исходного примера у координатора — `Stop.hooks.шаблон.json`; для подготовки он не является исполняемым входом.

## Воспроизводимые проверки

[Адресный набор](tests/test_комплект_завершения.py) использует только временные синтетические Git-репозитории. [Сквозной сценарий и профиль](scripts/проверить-комплект-завершения.py) принимает `--источник` и точный `--commit`, извлекает фикстуры того же commit и проверяет шесть исходов реального guard через подготовленные комплекты. Для каждого исхода измерены первый процесс подготовки, идемпотентный повтор, три горячих процесса с guard и пять отдельных проверок целостности. Измеритель печатает только синтетические результаты и хэши; временные абсолютные пути в отчёт не входят.

Оба сценария запускаются через [отчётную обёртку](../fum-otchyotyi-o-zapuskakh-proverok/SKILL.md) собственного этапа. Тесты и профиль не устанавливают native hook и не доказывают наблюдение реальной следующей итерации модели в том же `run_turn`. Контрольная точка с чистым Git также не заменяет эту отдельную человеческую приёмку.

По переданному аудиту закреплённого runtime блокировка сохраняется как `response_item` с `HookPrompt role=user`, затем продолжается тот же `run_turn`, без нового `TurnStarted`. `HookStarted/Completed` не сохраняются в JSONL и игнорируются `thread_history`. Роль `user` такого служебного сообщения не доказывает человеческое происхождение или новые полномочия; точную классификацию и native наблюдение выполняет координатор. Подготовитель не использует эти сообщения как вход.
