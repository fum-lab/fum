# Выбрать одно действие между этапами

Первый срез [STEP0228](../../Планирование/карточки-шагов/🟡-FUM-STEP-0228-контролировать-доставку-в-постоянную-ветку.md) — читающая библиотека [предпросмотр()](scripts/восстановление_прерванной_задачи.py) и единственная одноимённая CLI-команда. Результат предлагает координатору одно действие, показывает каждого ожидаемого исполнителя, точные источники и неизвестности. `допуск_эффекта` и `завершение_всей_работы_доказано` всегда ложны. Даже полный переданный перечень не доказывает полноты всех обязательств FUM.

```sh
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/scripts/восстановление_прерванной_задачи.py предпросмотр --корень КОРЕНЬ --каталог-снимков КАТАЛОГ_СНИМКОВ --вход ВХОД_JSON
```

Вход — сохранённый JSON, снимки — обычные JSON-файлы внутри явно выбранного физического каталога. Относительные пути не содержат переходов вверх, скрытого `.git`, символических ссылок или несовпадения регистра. Живой JSONL не читается. Сеть, API, расписания, отправка, создание коммитов и изменение Git из предпросмотра отсутствуют. Ошибка входа возвращает код 2 без JSON-решения; рекомендация адресной сверки — корректный результат с кодом 0.

## Вход первого среза

Все схемы закрыты: лишние поля, повторные JSON-ключи на любой глубине, неизвестные версии, неверные UUID/SHA и булево число вместо целого отклоняются. Корень библиотеки и каталог снимков передаются отдельно от данных. Поле `координатор` — канонический UUID ROOT.

Схема `fum.вход-предпросмотра-продолжения.1` содержит ровно `схема`, `координатор`, `постановка`, `полнота_перечня`, `исполнители`. `постановка` — точный Git-источник `{коммит, путь, sha256}`. Полный commit OID первого среза имеет 40 знаков, SHA-256 — 64. Источник читается из обычного blob закреплённого коммита каноническим `сверить_источник()`, независимо от текущих байтов checkout.

Каждый элемент упорядоченного массива `исполнители` содержит ровно:

| Поле | Значение |
| --- | --- |
| `задача`, `хост`, `владелец` | Ожидаемый UUID чата, hostId и актуально заявленный UUID владельца |
| `поручение` | Независимый выбор обычного ACT: координатор, исполнитель, коммит, путь, sha256 |
| `решение_координатора` | Git-источник отдельного сохранённого решения ROOT |
| `снимок` | `{путь, sha256, наблюдение, курсор_запроса}` либо `null` при недоступности |
| `доставка` | `{план, владельцы}` либо `null`; допускается только план доставки v2 |
| `необязательная_инфраструктура` | Явный bool из согласованного объёма |

`наблюдение` — ISO-время с зоной, `курсор_запроса` — исходный запросный курсор либо `null` для первой страницы. Это утверждение сохраняющей стороны: ответ API сам курсор запроса не доказывает. Снимок имеет полную сохранённую MCP-оболочку `content[0].text` с JSON `read_thread` версии 1. Он приводится штатным [представить_ответ()](scripts/компактный_ответ_задачи.py); hostId отдельно сверяется с ожидаемым. Текст ответа остаётся данными, в полном файле по SHA и JSON-указателям адаптера. Он не объявляет приёмку, паузу или полномочия. Активный текущий ход имеет приоритет перед final из старого хода.

## Решение ROOT и граница доверия

Схема `fum.сохранённое-решение-root.1` содержит ровно `схема`, `координатор`, `задача`, `хост`, `этап`, `событие`, `поручение`, `владелец`, `ход`, `состояние`, `остаток`, `ожидание`, `результат`, `план_доставки`, `эффекты`.

- `этап` и `событие` — непустые стабильные идентификаторы; `ход` — ID последнего рассмотренного хода либо `null`.
- `состояние`: `открыт`, `закрыт`, `пауза`, `отменён` или `unknown`. `остаток` — отдельно согласованный bool, а не вывод из текста ответа.
- `ожидание` — непустая причина либо `null`.
- `результат` — `null` либо `{состояние: готов|принят, источник: {коммит, путь, sha256}}`. Точный файл свидетельства читается из Git; смысл готовности/приёмки заявляет ROOT.
- `план_доставки` — точный SHA идентификатора плана либо `null`. Он связывает разрешённый срез с переданным планом v2; назначение плана обязано принадлежать ROOT и включать ожидаемого исполнителя.
- `эффекты` содержит ровно `отправка` и `репозиторий`; каждое значение — `не было`, `подтверждён` или `unknown`. Они относятся к данному сохранённому событию/этапу. При неизвестном исходе повтор не предлагается; подтверждённый эффект также исключается из повторения. Новый эффект требует нового события и собственной проверки ROOT.

Git SHA/OID подтверждает целостность выбранного источника, но не авторство и смысл текста. Вход и последнее решение выбирает доверенный координатор из своей сохранённой истории; библиотека не ищет «последнюю» запись по всему репозиторию и не удостоверяет человеческое разрешение автоматически. Поздняя действительная пауза или отмена должна входить в выбранное решение. До любого эффекта ROOT снова проверяет поздние команды, текущий ход, владельца, ACT и отдельный нативный допуск. Смена этой привязки делает решение устаревшим. Preview не заменяет такой допуск.

## Выбор и доставка

Доступные предметные действия следуют согласованному порядку исполнителей. Они выбираются раньше необязательной инфраструктуры; адресные неизвестности и ожидания одного исполнителя не скрывают доступное действие другого. Среди сверок и ожиданий также сохраняется исходный порядок. Закрытый этап не возобновляется: лишь отдельный согласованный остаток позволяет предложить новый ACT. Принятый результат не реализуется и не принимается повторно.

Отдельно разрешённая доставка уже принятого среза остаётся доступной после закрытия предметного этапа и выбирается перед новым ACT на остаток. Узнаваемый краткий снимок без ID, статуса или completedAt последнего хода требует адресного чтения; неизвестные схемы, поля и неверные типы остаются ошибками входа. Недостающие значения не выдаются как наблюдённые.

Доставка использует ровно [наблюдать_назначение()](../fum-reyestr-planirovaniya/scripts/доставка_план.py). Новый алгоритм Git-истории не вводится. Устаревший план, грязное дерево или эквивалентные патчи требуют адресной сверки. Равное дерево и наличие среза в предках не доказывают получения. Поля `получатель: unknown`, `квитанция: не наблюдалась`, `ожидание_секунд: unknown` сохраняются из канонического сигнала. Его реальное `время_наблюдения` также сохраняется: повторный Git-вызов может иметь новое время при том же решении.

Устойчивый ключ действия содержит хост, задачу, последний ход, событие ROOT, `completedAt` и этап. SHA снимка находится отдельно в основаниях. При одинаковых сохранённых условиях ключ и действие совпадают; сам результат нового наблюдения доставки может отличаться временем. Снимок `completed`, `notLoaded`, пустая страница или неизменный HEAD по отдельности не доказывают прерывания. Предложение «проверить продолжение открытого ACT» означает только следующую проверку возможности, а не send или доказательство сбоя.

## Проверки и профиль

Адресные [тесты](tests/test_восстановление_прерванной_задачи.py) используют настоящие временные Git-репозитории, закреплённые ACT/решения и реальные фикстуры принятого сигнала доставки. Запускайте штатной отчётной обёрткой своей пары Журнала:

```sh
python3 -B -m unittest discover -s Инструменты/fum-svyaznostj-rabochej-sessii/tests -p test_восстановление_прерванной_задачи.py
python3 -B Инструменты/fum-svyaznostj-rabochej-sessii/tests/профиль_восстановления_прерванной_задачи.py --выход НОВЫЙ_ФАЙЛ_JSON --повторы 3
```

Профиль исключает установку фикстур, сохраняет сырые монотонные длительности, пик Python-памяти, байты явных источников и stdout Git, число обращений и отдельное вложенное время канонического сигнала. Это конечная локальная фикстура, не весь файловый ввод ОС и не ускорение FUM. Корректность и неизменность файлов проверяются на тех же фикстурах. Без измеренного основания для нового кэша сохраняются канонические читатели и повторная сверка.

Полный STEP0228 остаётся открытым. Приёмка первого этапа требует реального чтения решения ROOT между этапами и выбора следующего разрешённого действия. Отдельный apply/send-срез, пробуждение выключенного приложения и разрешение слияния здесь не реализованы.
