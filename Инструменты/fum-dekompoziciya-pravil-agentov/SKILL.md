# Декомпозиция правил агентов

Используй этот навык при изменении `AGENTS.md`, файлов `Правила/агентов/`, машинного инвентаря или самого валидатора декомпозиции. Навык не даёт полномочий на запись: право записи определяется всегда загруженным корневым ядром и действующей рабочей сессией.

## Обязательный порядок

1. До первой записи выбери триггер `правила` по корневому маршрутизатору и полностью прочитай все возвращённые тематические Markdown-файлы, `Правила/агентов/инвентарь-правил.json` и этот `SKILL.md`.
2. Сохрани стабильные идентификаторы существующих правил. Новому правилу назначь новый идентификатор, область, приоритет, триггеры, семантический ключ, единственное назначение и проверяемое основание.
3. Не меняй исторический снимок задним числом. Исходный `AGENTS.md` воспроизводится из точных `commit` и `blob`; `исходные_единицы` должны без разрывов и перекрытий покрывать каждый его байт.
4. При изменении тематического файла пересчитай его `sha256_содержания` без служебного блока `FUM-MD-RECENCY`. Не копируй одну активную норму в несколько файлов.
5. Развивай валидатор через TDD: сначала добавь отрицательную либо положительную фикстуру и наблюдай RED, затем реализуй поведение и наблюдай GREEN.
6. Каждый прямой запуск теста или валидатора в пишущей сессии проводи через локальную автоматизацию отчётов о запусках проверок с путём текущего `запрос.md`.

## Команды

Маршрут для одного или нескольких триггеров вычисляется без изменения файлов:

```sh
python3 Инструменты/fum-dekompoziciya-pravil-agentov/scripts/проверить-декомпозицию-правил.py \
  --корень-репозитория . маршрут \
  --триггер изменение \
  --триггер документация
```

Полная структурная проверка выполняется так:

```sh
python3 Инструменты/fum-dekompoziciya-pravil-agentov/scripts/проверить-декомпозицию-правил.py \
  --корень-репозитория . проверить
```

Автономные тесты:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-dekompoziciya-pravil-agentov/tests \
  -p 'test_*.py'
```

Валидатор только читает структуру. Поле инвентаря `продолжение_задачи` согласует единственный маркер `explicit-worklist-v1` в корне с существующим точным локальным сценарием проверки решения; отсутствие, дублирование, неизвестная версия и небезопасный путь закрывают допуск. Он сверяет регистрацию каждого фактического якоря в обе стороны, запрещает действующую норму в теме без полномочий и при политике изолированных worktree требует единственный совместимый маркер запрета старого автоконвейера. Он закрыто отклоняет отсутствующий путь, неверный регистр, любой symlink-компонент, выход за checkout, подмену содержания, повтор идентификатора, JSON-ключа или активной семантики, неполное исходное покрытие, некомпактный корень, несогласованный маршрут и включение исторических полномочий в обычный маршрут.

Для совместимости исходного master и результата FUM-STEP-0177 поддержаны ровно две пары тел действующих корневых правил 000062 и НОВОЕ-000017. Их точные тексты, происхождение и декларации сохранены в [открытой фикстуре профилей](tests/фикстуры/профили-продолжения.json). Пара из master требует ровно `маркер` и `сценарий`; пара JSONL дополнительно требует точный список `обязательные_параметры: ["--перед-завершением", "--исходник"]` и трёхполевой `остаток_сообщений` с командой `остаток`, `без_записи: true` и каноническим обработчиком. Оба пути проверяются как точные обычные локальные файлы. Профиль выбирается по полным телам правил проверяемого дерева и их действующему назначению P0 в `AGENTS.md`, затем сверяется декларация. Удаление новых полей не переводит правила JSONL в старый профиль.

Неизвестные и смешанные редакции, скрытие норм, иные поля и значения отклоняются. Два поддержанных корневых каркаса не содержат оград, внешних HTML-областей или многострочных HTML-комментариев; при продолжении задачи такие формы закрывают допуск. Хэш тела исключает только конечные переводы строки LF. Если правило изменено, сначала согласуйте новый профиль и его регрессии, затем повторите `проверить`; редактирование инвентаря само по себе не расширяет список профилей. Полный согласованный возврат обеих норм и декларации к старому профилю различается внешним контролем происхождения слияния, а не этим статическим валидатором.
