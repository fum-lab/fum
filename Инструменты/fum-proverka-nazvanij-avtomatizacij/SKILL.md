# Proverka nazvanij avtomatizacij

Каноническое русское имя этой локальной автоматизации FUM — `проверка названий автоматизаций`. Она сверяет русское имя на кириллице, точный результат преобразования LinguisticKit и технический slug. Кириллическое имя остаётся смысловым источником, а латинская форма не подбирается вручную.

## Контракт реестра

Реестр `Инструменты/реестр-названий-автоматизаций.json` имеет схему `fum.automation-names.v1` и хранит:

- `linguistic_kit` — путь, отдельные адреса форка и исходного upstream, закреплённую ревизию, пару `Cyrl → Latn`, таблицу `ru` и состояние материализации;
- `golden` — обязательные эталонные пары `source` и `transliteration`;
- `current` — новые и переименованные автоматизации с `source`, `transliteration` и `slug`;
- `display` — названия автоматизаций без каталога, для которых нужны только `source` и `transliteration`;
- `legacy_display` — точные прежние отображаемые host-имена без каталога, сохранённые только для распознавания мигрированной на месте автоматизации;
- `legacy` — поле совместимости исторического формата для прежних каталогов.

В каноническом реестре `legacy` пуст после завершённой миграции каталогов. `legacy_display` может содержать точное прежнее host-имя только при переименовании существующей записи на месте: оно служит входом распознавания исторической конфигурации, не считается действующим псевдонимом и не разрешает создавать или именовать новую автоматизацию по-старому. Валидатор запрещает повтор legacy-имени и его одновременное присутствие в активном `display`.

Когда один объект имеет репозиторное имя в `current` и отдельный UI-заголовок в `display`, допускается пара, различающаяся только регистром русского источника и результата LinguisticKit. Валидатор принимает её как два представления одной идентичности только при наличии `slug` ровно у одного элемента; совпадение транслитераций разных смысловых источников по-прежнему считается коллизией.

Для `current` slug получается как префикс `fum-` и точная транслитерация, приведённая к нижнему регистру и с заменой пробелов на дефисы. Эта нормализация — слой FUM, а не функция LinguisticKit.

## Что проверяется

Валидатор:

- проверяет схему, закреплённые метаданные и пять эталонных пар;
- сверяет `source` с результатом LinguisticKit через JSON-обёртку;
- отклоняет повторы, коллизии, недопустимые slug, ручные варианты транслитерации и пересечение `legacy_display` с действующими отображаемыми именами;
- находит `Инструменты/fum-*/SKILL.md`, требует совпадения slug с именем каталога и полем `name`;
- отклоняет незарегистрированную или исчезнувшую автоматизацию.

Текущая память FUM закрепляет состояние `ready`, материализованный submodule из форка `fum-lab/LinguisticKit` и живую сверку каждого сохранённого имени. После свежего клонирования зависимость нужно [инициализировать вместе с локальным `upstream`](../../Зависимости/README.md) до запуска проверки; перевод канонического реестра в `blocked` не подменяет эту операцию. Режим `blocked` сохраняется только как fail-closed совместимость формата и тестовая фикстура. Git-топологию готового submodule отдельно проверяет [fum-proverka-git-zavisimostej](../fum-proverka-git-zavisimostej/SKILL.md).

## Команды

Проверка из корня репозитория:

```bash
python3 Инструменты/fum-proverka-nazvanij-avtomatizacij/scripts/proveritj-nazvaniya-avtomatizacij.py
```

Автономные тесты без сети и без материализованной зависимости:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-proverka-nazvanij-avtomatizacij/tests \
  -p 'test_*.py'
```

Тесты подменяют JSON-преобразователь локальным процессом. Они фиксируют эталоны, ошибочную транслитерацию, невалидные slug, коллизии, незарегистрированные каталоги, имена без каталога, а также режимы `ready` и `blocked`.

## Граница автоматизации

Валидатор не определяет смысловое русское имя и не выполняет переименование каталога. Он также не устанавливает зависимость и не выбирает способ её подключения. Автоматизация даёт исполнимую структурную проверку уже записанного решения и совместимость тестов с прежним форматом реестра.
