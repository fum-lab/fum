# FUM MD Recency

Этот навык описывает локальную [автоматизацию FUM](../../Глоссарий/автоматизация-FUM.md), которая поддерживает в каждом проектном Markdown-файле [памяти FUM](../../Глоссарий/память-FUM.md) скрытую служебную метку последнего содержательного редактирования и собирает общий индекс этих `.md`-файлов от свежих к более старым.

Содержательным считается изменение текста файла без учёта самой служебной метки `FUM-MD-RECENCY`. В каноническом `Журнал/<сессия>/отчёт.md` единственная синтаксически точная пара `FUM-CHECK-RUNS` тоже считается служебной: изменение таблицы или переход из открытого marker в закрытый не сдвигает дату и индекс. Повреждённая, неполная или повторная пара отклоняется. Для нового или устаревшего отчёта автоматизация записывает стабильный хэш без этой пары, но продолжает принимать неизменённый исторический полный хэш. Если хэш не изменился, повторный запуск не обновляет дату файла.

Собственная метка занимает отдельные строки строго в конце файла, вне ограждённых цитат. Такая же метка внутри ограды из обратных кавычек или тильд остаётся исходным текстом и участвует в содержательном хэше. Прежние маркеры перед точным конечным блоком тоже остаются содержимым, включая исторический `pending`. Незакрытая ограда или повреждённый конечный блок запрещают запись этого файла; откат к предыдущей метке не допускается. Это не транзакция всего обхода: другие файлы и общий индекс могут обрабатываться независимо.

Непосредственный Markdown-файл канонического `Источники/URL/https/chatgpt.com/share/<id>/` может содержать дословный архив: единственную упорядоченную пару `FUM-CHATGPT-SHARE-VERBATIM`, перед которой стоит заголовок `## Диалог`. Эта область маскируется перед чтением оград; её байты остаются содержимым. Вне канонического пути, при неверной паре или заголовке исключение не действует.

Регрессии подтверждают сохранение дословных поручений с переводами строк LF. Чтение файлов по-прежнему нормализует CRLF/CR; сохранение произвольных исходных переводов строк этим исправлением не заявляется.

## Когда использовать

Используй эту автоматизацию в каждой [рабочей сессии](../../Глоссарий/рабочая-сессия.md), влияющей на проект, после внесения файловых правок и перед проверкой связности сессии.

Автоматизация особенно важна, когда сессия создаёт или редактирует Markdown-файлы: `Документация/`, `Глоссарий/`, `Журнал/`, `Планирование/`, `Описания/`, `Источники/`, `Инструменты/` и корневые `.md`-файлы.

## Команда запуска

```bash
python3 Инструменты/fum-svezhestj-markdown/scripts/update-md-recency.py
```

Команда обновляет:

- служебный блок `FUM-MD-RECENCY` в конце каждого Markdown-файла;
- индекс [Markdown-файлов по времени редактирования](../../Индексы/markdown-файлы-по-времени-редактирования.md) с Markdown-таблицей в основном Obsidian-стиле: колонки выровнены пробелами в исходнике.

Множество входов задаёт общая автоматизация [fum-proyektnyiye-fajlyi](../fum-proyektnyiye-fajlyi/SKILL.md): отслеживаемые и новые неигнорируемые проектные Markdown-файлы включаются, а `.build`, `.swiftpm`, каталоги кэшей, `.obsidian/plugins` и `.obsidian/themes` не читаются, не индексируются и никогда не переписываются. Структурные исключения действуют и при `--no-git`; этот флаг отключает только использование Git-истории для вычисления времени.

Для проверки без записи используется:

```bash
python3 Инструменты/fum-svezhestj-markdown/scripts/update-md-recency.py --check
```

## Правило времени

Если файл уже содержит актуальную метку и его содержательный хэш не изменился, дата сохраняется.

Если файл изменён содержательно, создан заново или ещё не содержит метки, дата выбирается так:

- для файлов, изменённых в текущем рабочем дереве Git, используется время запуска автоматизации;
- для чистых отслеживаемых файлов при первой инициализации используется дата последнего Git-коммита, который менял файл;
- если Git-история недоступна, используется время запуска автоматизации.

## Проверки

Локальные тесты автоматизации запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-svezhestj-markdown/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: автоматизация добавляет метки, сохраняет дату неизменённых файлов, строит индекс в порядке от свежих файлов к старым, оформляет таблицу индекса с выровненными колонками, замечает устаревшую метку в режиме `--check` и при первой инициализации умеет брать дату чистого отслеживаемого файла из Git-истории. Отдельные фикстуры подтверждают стабильную свежесть отчёта при замене только канонического `FUM-CHECK-RUNS`, чтение исторического полного хэша, отказ при повреждённой или повторной паре marker-строк, успешную проверку неизменного снимка на следующий календарный день и то, что `.build/checkouts/vendor/README.md`, `.swiftpm` и кэши не становятся входами и не изменяются.

## Граница автоматизации

Скрипт не определяет смысловую ценность изменения. Он только поддерживает машинно проверяемое время последнего содержательного редактирования и индекс Markdown-файлов. Агент по-прежнему отвечает за корректность содержания, публикационную чистоту, ссылки на источники требований и полноту файла исходного запроса.
