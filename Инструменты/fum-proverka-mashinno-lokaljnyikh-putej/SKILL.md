# Проверка машинно-локальных путей

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) выполняет read-only-аудит опубликованного содержимого репозитория. Она строит инвентарь через `git ls-files`, поэтому одинаково видит пути из индекса и новые неигнорируемые файлы, но не обходит Git submodule и не зависит от сети или секретов. Результат детерминированно сортируется и не повторяет найденные буквальные значения: каждая строка имеет форму `путь:строка:категория`.

## Когда использовать

Используй проверку перед фиксацией рабочей сессии, после добавления генератора Markdown, нового исходного кода или проверки путей, а также при изменении типизированной политики допустимых случаев. Общий smoke-check запускает её отдельным обязательным шагом.

## Команда запуска

Из корня репозитория:

```bash
python3 Инструменты/fum-proverka-mashinno-lokaljnyikh-putej/scripts/proveritj-mashinno-lokaljnyiye-puti.py \
  --repo-root .
```

Код `0` означает отсутствие действующих нарушений, даже если отчёт содержит типизированные `allow.*` и `report.*`. Код `1` означает нарушение содержимого, а код `2` — недостоверный Git-инвентарь или ошибку контракта политики. Сканер отклоняет произвольные POSIX-абсолюты, домашние каталоги пользователей, Windows drive, обратносолэшевые и прямослэшевые UNC, `file://`, одиночный `~`, именные формы вроде `~user/path`, POSIX-, Windows- и PowerShell-переменные домашнего каталога и Swift `#filePath`.

## Политика закреплённого кандидата

`policy-кандидата-слияния.json` предназначена для проверки данных закреплённой ведущей основы. Она отдельно связана в `происхождение-политики-слияния.json` с полными OID основы, её дерева и SHA-256 политики. Текущая основа — `14044dfd994cf16b5061fb245b18a8e5abf0ac7d`, дерево `d9af1d9e69f288c602a78e5e3edab5337b41ef58`; 447 исключений составляют прежние 419 и 28 точных добавлений относительно принятого master `9d01af6de4fc2f1c9265ee8805cda4998322e004`. Это вход существующего контура слияния, а не самостоятельное разрешение слияния. Обычная команда выше продолжает использовать `policy.json`, покрывающую только реально принятые файлы; при переносе новых файлов её изменения сверяются отдельно.

В принятой предпосылке M обычная политика сохраняла 419 исходных записей и добавляла только три точных исключения перенесённого CJS-распознавателя и его открытой regex-фикстуры, всего 422. Эти три записи уже присутствовали в точном объекте L. В подготовленном слиянии обычная policy.json сохраняется из L целиком: 447 записей, побайтно равных закреплённой в M политике кандидата. Это изменение данных кандидата; принимающая политика и её происхождение в M остаются неизменными.

## Ограниченные шаблоны веб-адресов

Полный HTTP(S)-адрес с непустым hostname и корректным портом может оканчиваться последовательностью именованных slash-переменных GitHub, например <https://api.github.com/users/example/starred{/owner}{/repo}>. Имя состоит из ASCII-букв, цифр и подчёркивания и не начинается с цифры. Распознаватель сохраняет весь такой адрес как один веб-span с точными границами; исходный REST не изменяется.

Перед расширением проверяется алфавит authority: ASCII unreserved, sub-delims и разделители authority; знак процента допускается только в escape из двух ASCII hex-цифр. Unicode сохраняет прежнее поведение. Это не полная проверка структуры authority, DNS или принадлежности сервера; прежнее выражение адреса по-прежнему задаёт доступные границы. Проверяется весь хвост. Неправильный или неподдержанный остаток не маскируется по правильному префиксу. Отдельная переменная, файловая URI, иная схема и настоящий соседний путь сохраняют прежнюю проверку. Обратная кавычка не расширяет прежнюю границу: случай с закрывающей inline-code кавычкой покрыт отрицательной регрессией. Для адреса без хвоста не вызываются дополнительное регулярное выражение и разбор сервера.

Это ограниченное распознавание, без подстановки переменных и без сетевого обращения. [Адресные регрессии](tests/test_шаблонов_адресов.py) проверяют полные границы, плохие хвосты, authority, соседние пути и обычный JSON вне типизированного архива GitHub.

## Точное обновление политики

Повторяемые пересчёты fingerprint-полей выполняет `scripts/obnovitj-policy.py`. Он не разрешает все текущие ошибки: каждая декларация явно задаёт `id`, точный репозиторный `path`, номер `line`, закрытую `category` и содержательную `reason`. Вид формы, SHA-256 всей строки и число совпадений инструмент выводит из текущего Git-инвента и содержимого файла.

Канонический манифест имеет схему `fum.machine-local-path-policy-update.v1` и массив `declarations`:

```json
{
  "schema": "fum.machine-local-path-policy-update.v1",
  "declarations": [
    {
      "id": "fixture-example",
      "path": "Инструменты/example/tests/test_fixture.py",
      "line": 12,
      "category": "allow.test-fixture",
      "reason": "Закрепляет одну явно выбранную автономную тестовую строку."
    }
  ]
}
```

```bash
python3 Инструменты/fum-proverka-mashinno-lokaljnyikh-putej/scripts/obnovitj-policy.py \
  --repo-root . \
  --manifest путь-к-манифесту.json
```

Для единичного запуска тот же JSON-объект можно передать повторяемым аргументом `--declaration`. Повторный запуск с теми же декларациями не перезаписывает файл. Существующий `id` можно пересчитать только при неизменных `path`, `category` и `reason`; это позволяет без ручного редактирования обновить временную позицию и fingerprint после механического переноса.

Если ошибочная миграция создала второй `id` для того же смыслового fence, манифест схемы `fum.machine-local-path-policy-update.v2` может добавить массив `retirements`. Каждый элемент дословно повторяет все поля удаляемой policy-записи. Изменение любого поля закрывает операцию; уже отсутствующий точный `id` считается идемпотентно завершённым retirement. Удаление и пересчёт оставшегося `id` проходят одной атомарной записью.

Обновление отклоняет неоднозначную строку, неактивную или нетипизированную строку, выход из репозитория, wildcard, symlink, неизвестную категорию, дублирующийся селектор или fingerprint, неканонический JSON, не-NFC-путь и смену политики во время записи. Новая политика сначала проходит общий контракт, а затем атомарно замещает прежний файл.

Несколько деклараций одного файла используют один полный анализ этого файла в пределах вызова. Сохраняются число строк и неизменные кандидаты; контекст и число одинаковых fingerprint по всему файлу проверяются полностью. Следующий вызов заново читает и разбирает вход, поэтому изменение файла не скрывается прежним кэшем. Отдельный итоговый scanner по-прежнему проверяет весь репозиторий.

Для сравнения стоимости используйте `tests/профиль_пакетного_анализа.py --выход <профиль.json>` через отчётную обёртку. По умолчанию он создаёт три открытые фикстуры примерно по 4 МиБ с 12 декларациями, измеряет обновление и точный повтор, сохраняет хэши входа и результата, счётчик и вложенные интервалы настоящего полного разбора. Подготовка временного Git-репозитория исключена из измеряемого обновления. До и после серии сверяются SHA-256 измеряемых исходников, профилировщика и используемых модулей фикстуры; изменившийся или исчезнувший источник не допускает запись результата. Параметры `--мегабайт`, `--деклараций` и `--повторов` задают размер сценария. Для исторической реализации переменная `FUM_CHECKED_CODE_ROOT` указывает на отдельный проверенный checkout того же монорепозитория; профилировщик запускается из текущего дерева. Историческая копия должна содержать зависимости сканера, включая модуль структуры папок запросов. Равенство результатов, состав входов и условия нагрузки сверяются отдельно; вложенные интервалы не суммируются с общим временем.

## Типизированная граница

Политика `fum.machine-local-path-policy.v3` сохраняет прежний массив `exceptions` и предел 16, добавляя массив `метаданные`. Его конечные декларации связывают точный канонический путь Журнала, SHA-256 всего исходного файла и выбранные позиции с SHA-256 строки и метки. Сами метки runtime в политику не копируются. Допуск действует только для точного диапазона `Task name` или `Sender` внутри закрытого блока наблюдения с пустым `Payload`, либо двух элементов `помощники` закрытой схемы независимой сверки переименования. Роль, заголовки, ограждение, порядок полей и индекс проверяются дополнительно к хэшам. Любые остальные кандидаты, включая другой путь в той же строке JSON, проходят обычную проверку.

Обновитель принимает `fum.machine-local-path-policy-update.v3` с полями `schema`, `declarations`, `retirements`, `метаданные`. Для каждой заявки метаданных задаются `путь`, `хэш_исходных_байтов` с префиксом `sha256:` и непустой массив `позиции`. Позиция задаёт положительную `строка` и `контекст`: `вид: заголовок-наблюдения`, `поле: Task name` либо `Sender`; для сверки — `вид: сверка-переименования`, `поле: помощники`, `индекс: 0` либо `1`. Отпечатки `хэш_строки` и `хэш_идентификатора` выводит программа после проверки контекста. В этой версии пустой `declarations` допустим только при непустом массиве заявок метаданных. Точный повтор не перезаписывает policy; другая декларация того же файла закрыто отказывает. Выбранные исходники повторно сверяются перед атомарной заменой политики. Обычное обновление прежних исключений сохраняет метаданные.

Общий сканер требует все объявленные источники. Дочерний stage0 и будущая композиция сначала разбирают полную политику, затем отбирают декларации выбранных файлов целиком и проверяют те же индексные либо будущие байты. Пропуск декларации выбранного файла или подмена его SHA недопустимы. Новый модуль включён в проверяемое замыкание исходников stage0.

## Точная байтовая фикстура v4

Схема `fum.machine-local-path-policy.v4` сохраняет массивы `exceptions` и `метаданные` и добавляет `байтовые_фикстуры`. Одна запись байтовой фикстуры связывает уникальный `идентификатор` и нормализованный NFC-`путь` с Git-`режимом` `100644`, полным `размером` и `хэшем`, `видом` `неполный-хвост-UTF-8`, точным `размером_префикса`, 1–3 байтами поля `шестнадцатеричный_хвост` в нижнем регистре, `категорией` `allow.test-fixture` и содержательной `причиной`. Идентификаторы общие с обычными исключениями; повтор пути, неизвестное поле, другой режим, NUL, символическая ссылка в любом компоненте пути или иной вид ошибки UTF-8 закрывают политику.

Совпавшая запись даёт отчёт `allow.test-fixture.неполный-хвост-UTF-8`, но не скрывает корректный префикс: он проходит обычное распознавание машинно-локальных путей. Изменение любого байта, пути, режима, размера, хэша, границы или хвоста добавляет `error.несовпадение-байтовой-фикстуры-политики` с кодом `2`; если фактические байты по-прежнему имеют неправильную UTF-8-кодировку, сохраняется и исходная ошибка декодирования. Отсутствующая декларация и дополнительный неизвестный файл неправильной UTF-8-кодировки также не получают допуск.

Манифест `fum.machine-local-path-policy-update.v4` имеет точные поля `schema`, `declarations`, `retirements`, `метаданные`, `байтовые_фикстуры`, `отмены_байтовых_фикстур`. Байтовая заявка задаёт только `идентификатор`, `путь`, `вид`, `категория` и `причина`: режим, размер, хэш, границу и хвост штатный обновитель выводит из обычного индексированного файла и повторно сверяет непосредственно перед атомарной заменой политики. Изменившийся существующий байтовый идентификатор нельзя пересчитать молча: прежняя полная запись должна находиться в `отмены_байтовых_фикстур`, а новая заявка — в `байтовые_фикстуры`. Первый точный переход считается отменой и добавлением; его точный повтор, совпадающая отмена с тем же желаемым результатом и отмена уже отсутствующей записи не перезаписывают политику.

Конечный нулевой этап передаёт сканеру режим каждого точного Git-объекта и поддерживает v4. Подготовка будущих материалов располагает байтами, но ещё не располагает доказанным Git-режимом, поэтому при выбранной байтовой декларации явно отказывает до декодирования. Действующий `policy.json` обновляется до v4 только отдельным последующим этапом уже принятым обновителем: кандидат реализации не разрешает собственный новый формат. Прежний проверяющий обязан закрыто отклонить незнакомую v4.

Адресная матрица находится в `tests/test_байтовых_фикстур.py`; согласованные потребители проверяются тестами публикационного допуска и подготовки дочернего поручения. Профиль `tests/профиль_байтовых_фикстур.py --выход <новый-файл>` отдельно измеряет вывод декларации, идемпотентный повтор и полное сканирование открытой фикстуры заданного размера; подготовка временного Git-репозитория исключена, а исходники сверяются по SHA-256 до и после серии.

Для служебной метки встроенной функции cProfile действует отдельный контекст
`встроенная-функция-cProfile`. Он допускается только в точном файле
`Журнал/<каноническая-папка>/материалы/профили/<имя>.json` с выбранным полным SHA.
Документ обязан иметь закрытую схему `fum.профиль-цепочки-подготовки.1`, режим
`чтение` и каноническое представление JSON с сортировкой ключей, отступом два
пробела, кириллицей и завершающим LF. Дубли ключей, NaN, неизвестные поля и иные
разделители строк отклоняются. Проверяются типы полей профиля, запусков и
диагностик. Прежние контексты метаданных и их сериализация сохраняются.

Позиция заявки v3 задаёт `строка` и контекст с ровно четырьмя полями:
`вид: встроенная-функция-cProfile`, `поле: файл`, `запуск` и `индекс`.
Последние два значения — неотрицательные целые, исключая bool. Структурный
обход выбирает только содержимое JSON-строки из одного символа тильды по пути
`запуски[запуск].диагностика[индекс].файл`. SHA строки и символа вычисляет
штатный обновитель; координаты сверяются повторно при сканировании. Соседние
данные, домашнее сокращение с продолжением, другой файл или изменённые байты
допуска не получают. Пропуск одной позиции оставляет один действующий отказ.

Количество точных позиций метаданных не меняет общий предел 16 совпадений
обычного fingerprint-исключения. Его превышение и дубли селектора по-прежнему
отклоняются. Новую policy с этим контекстом разрешено передавать только
независимо принятому проверяющему коду, который его понимает; прежний K обязан
отказать при разборе полной policy. Кандидатный модуль не разрешает собственную
поставку. Успех допуска конечного состава stage0 не означает успех общего
сканера и не скрывает сохранённые нарушения вне этого состава.

Адресные сценарии: `tests/test_метаданных_профилей.py`. Они включают настоящий
обновитель, полный сканер синтетического Git-репозитория и точный повтор без
перезаписи policy. Отдельный `tests/профиль_метаданных_профилей.py --выход <новый-файл>`
сравнивает прежний отказ и точный допуск на одинаковом источнике с 21 позицией
в трёх свежих процессах `-I -S -B`; хэши исходников проверяются до и после.
Это измерение стоимости нового контекста, а не ускорения всей интеграции.

Адресные сценарии находятся в `tests/test_метаданные_наблюдений.py`; обычный Python, `-O` и `-OO` должны давать одинаковые отказы. Команда `python3 -B Инструменты/fum-proverka-mashinno-lokaljnyikh-putej/tests/профиль_метаданных_наблюдений.py --повторов 25` сравнивает стоимость прежнего отказа и нового допуска на одинаковых синтетических 38 позициях, проверяя исходники до и после измерений. Она не объявляет прежний отказ функционально эквивалентным новому механизму и не доказывает ускорения полной интеграции.

Дословное содержимое только раздела `## Текст запроса` в точных файлах `Журнал/<имя-с-обязательным-временным-префиксом>/запрос.md` и файлы под `Источники/` остаются происхождением в режиме `report.*`. Обычные URL маскируются до распознавания локальных путей. Системные runtime-пути, shebang, якоря `.gitignore` и документированные обезличенные примеры получают отдельные контекстные категории; произвольный системный путь в first-party-коде не разрешается. Само нахождение строки в каталоге сканера, в файле другой проверки или в `tests` ничего не разрешает.

Gitlink выводится как граница `report.gitlink`: сканер не входит в vendored историю. Поэтому известное upstream-использование `#filePath` в `LinguisticKitBuildTool` фиксируется как ограничение зависимости, а first-party Swift-файл с `#filePath` останавливает проверку.

В каноническом `материалы/индекс-остатка.jsonl` проверенные JSON-указатели полей `указатель_обработки` и `указатель_оригинала` на номерные элементы массивов «остаток» и «сообщения» относятся к `report.json-pointer`: они не обозначают файловую систему. В массиве события из четырёх элементов поле `array[2].image_url` с типом `input_image` получает `report.data-image` только для синтаксически корректного PNG data URI с проверенным base64 и PNG-сигнатурой. Остальные поля той же строки продолжают проверяться; повреждённый JSON, иной путь файла, незнакомый тип изображения и обычный абсолютный путь льготы не получают.

Бинарное вложение с NUL-байтом в точной области `Журнал/<канонический-временной-префикс>/материалы/источники/<описательное-название>/<файл>` получает `report.external-source.binary`, как сырой источник верхнего уровня, только при существующем обычном `запрос.md` этой сессии в Git-инвентаре. Это не распространяется на текстовые и non-UTF-8 файлы без NUL, производные описания, близкие имена каталогов и бесхозные либо неканонические папки запросов. Отсутствие анализа содержимого бинарного источника не заменяет ручную публикационную проверку и его точное происхождение.

Исторические доказательные цитаты, определения распознавателя, синтаксические литералы без адреса и тестовые фикстуры вне структурных блоков происхождения допускаются только через [policy.json](policy.json). Каждая запись схемы v2 закрепляет точный относительный путь, вид формы, SHA-256 всей строки, ожидаемое число совпадений, одну базовую категорию из закрытого списка `report.historical`, `allow.path-validation-definition`, `allow.nonpath-syntax` или `allow.test-fixture` и содержательную причину. Поэтому фикстура не переименовывается в историческую цитату. Неиспользуемая запись, изменившаяся строка, неизвестное поле или категория, wildcard, выход из репозитория, дубликат или чрезмерный счётчик делают политику ошибочной; новая соседняя строка остаётся нарушением.

В каноническом журнале запусков сканер узко распознаёт метку исполнителя только в закрытых верхних схемах `fum.test-run.v1`, `fum.test-run.v2` и `fum.test-run.v3`; v3 требует дополнительное поле `профиль_проверки`. Отсутствующее или лишнее верхнее поле не даёт неканонической записи льготу для машинно-локальной метки исполнителя.

Сырые обсуждения GitHub в рабочей памяти получают категорию `report.external-source` только по точной форме `Issues/<owner>/<repo>/данные/<sha256>.json`, совпавшему SHA-256 исходного UTF-8-содержимого без NUL и корректным записям того же репозитория с обязательным `body`. Принимается массив записей страницы API либо одиночная запись адресного ответа; одиночная запись проходит те же проверки без изменения исходных байтов. Все найденные формы остаются в отчёте. Неполный или чужой JSON, подмена байтов и соседние README, наблюдения и похожие пути не получают эту категорию. Публикационная проверка источника остаётся обязательной. [Назначение рабочей памяти](../../Issues/README.md).

## Точные системные литералы нативного моста

Для четырёх канонических файлов действует конечный перечень полностью выбранных строковых литералов:

- `Инструменты/fum-svyaznostj-rabochej-sessii/scripts/вызов_нативной_подготовки.cjs`: `/bin/sh`.
- `Инструменты/fum-svyaznostj-rabochej-sessii/scripts/сформировать_нативный_вызов.py`: `/usr/bin/env`.
- `Инструменты/fum-svyaznostj-rabochej-sessii/tests/test_нативной_подготовки_базиса.py`: `/bin/sh`, `/bin/bash`.
- `Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/tests/test_сценариев_полного_ответа.py`: `/bin/sh`.

Сверяются точный регистр пути, исходный диапазон найденной формы, полное значение и совпадающие кавычки. Допускаются запятая или точка с запятой после самостоятельного литерала и явно ограниченный конец поля CJS перед закрывающей фигурной скобкой и точкой с запятой. Закрывающая круглая или квадратная скобка сама по себе окончания выражения не доказывает и получает отказ. Пустой хвост промежуточной строки тоже отказывает: продолжение может находиться после перевода строки или комментария.

Для четвёртого файла сохраняется буквальная фикстура удаления поля `shell`: границу внешней Python-строки подтверждает пассивный AST-разбор полного исходника и ровно один исходный STRING token в полном выбранном диапазоне. Склеенные AST-константы из смежных токенов отказывают. Выбираются только самостоятельные простые однострочные строковые константы в присваивании, элементе списка или кортежа либо аргументе вызова. Конкатенация, преобразование и индексирование внешней строки закрываются по её непосредственному AST-родителю. Строковый префикс, тройные кавычки и обратная косая черта не допускаются; байтовые столбцы AST переводятся в символьные до сравнения с найденной формой. Внутренний литерал поля `shell` должен непосредственно предшествовать закрывающей внешней кавычке. Исходник фикстуры не исполняется. Неизвестное окружение, строковый префикс, экранирование, суффикс, конкатенация и смежные литералы получают отказ. Иные системные литералы этих файлов и соседние файлы сохраняют прежний запрет. Пользовательский домашний путь проверяется самостоятельно, включая соседство с допустимым литералом.

Граница относится к формам, найденным `detect_path_forms`; это статическая классификация содержимого. Она не доказывает полное обнаружение всех закодированных значений или безопасность исполнения программы. Прежний перечень `SYSTEM_RUNTIME_CODE_PATHS` сохраняется. Новые определения и тестовые данные закрепляются точными fingerprint-декларациями своей категории через штатный обновитель политики.

Адресные сценарии запускаются обычной отчётной обёрткой:

```text
python3.14 -B Инструменты/fum-proverka-mashinno-lokaljnyikh-putej/tests/test_proveritj_mashinno_lokaljnyiye_puti.py СистемныеЛитералыНативногоМоста
```

Профиль того же файла:

```text
python3.14 -B Инструменты/fum-proverka-mashinno-lokaljnyikh-putej/tests/test_proveritj_mashinno_lokaljnyiye_puti.py --профиль-системных-литералов --блоков 200 --выход /путь/к/новому-профилю.json
```

Он запускает три свежих процесса с `-I -S -B`, отдельно измеряет подготовку данных, сканирование и сверку. Полный упорядоченный независимый оракул, входы, результаты, проектные модули и интерпретатор сверяются по хэшам. Выход должен быть новым файлом в существующем приватном каталоге. Внешнее время процесса включает загрузку и подготовку и не складывается с внутренними фазами; сравнение ускорения не заявляется.
