# Реестр системных приложений и инструментов
|     |
Этот реестр фиксирует системные приложения, CLI-команды, инструменты среды агента, MCP-инструменты, локальные скрипты и внешние сервисы, которые повторно используются в рабочих сессиях [памяти FUM](../Глоссарий/память-FUM.md).

Реестр не заменяет раздел `## Использованные инструменты` в файлах [исходных запросов](../Глоссарий/исходный-запрос.md). Здесь хранится устойчивый справочник и способ проверки версий, а файл запроса хранит фактический снимок инструментов, которые участвовали в конкретной [рабочей сессии](../Глоссарий/рабочая-сессия.md).

## Правила записи

- Название инструмента пишется так, чтобы его можно было узнать в командах, логах или интерфейсе агента.
- Версия фиксируется точным выводом команды, если это возможно без секретов и внешней сети.
- Если версия не раскрывается средой, указывается поставщик или контракт инструмента, дата использования и известная граница наблюдаемости.
- Для составной среды ChatGPT и Codex отдельно фиксируются версия приложения, встроенного runtime, самостоятельного CLI, активная модель и контракты инструментов. Эти значения не взаимозаменяемы.
- Значение модели из конфигурации является только сконфигурированным значением по умолчанию. Активной моделью сессии оно считается лишь при подтверждении интерфейсом или командой статуса текущей сессии.
- Корневой идентификатор текущего сеанса Codex фиксируется отдельно от версий и модели: в корневой задаче он наблюдается как `CODEX_THREAD_ID`, а субагенту передаётся явно, чтобы его собственный дочерний `CODEX_THREAD_ID` не подменил происхождение.
- Для локальных CLI-инструментов указывается путь к исполняемому файлу, если путь устойчив и публикационно чист.
- Для инструментов Codex, MCP и внешних сервисов не фиксируются токены, учётные записи, приватные URL, локальные IP, имена хостов и другие секреты.
- При изменении версии, поставщика или контракта инструмента добавляется новая строка или обновляется запись с датой снимка.

## Слои среды ChatGPT и Codex

Названия ChatGPT и Codex не задают одну общую версию. Для воспроизводимого снимка рабочей сессии различаются поверхность взаимодействия, локальный runtime, самостоятельный CLI, активная модель и контракты инструментов.

Наблюдаемый локальный снимок на 2026-07-22 09:33 MSK:

- Desktop bundle `/Applications/ChatGPT.app` - `CFBundleDisplayName` `ChatGPT`, `CFBundleIdentifier` `com.openai.codex`, версия `26.715.70719`, сборка `5650`; проверяется по локальному `Info.plist`.
- Встроенный в пакет приложения исполняемый файл Codex - `codex-cli 0.145.0-alpha.27`; проверяется командой `/Applications/ChatGPT.app/Contents/Resources/codex --version`. Наличие этой версии в пакете не доказывает версию активной агентской сессии, возможной удалённой сервисной части или модели.
- Самостоятельный Codex CLI в текущем `PATH` - `codex-cli 0.144.6`; проверяется командой `codex --version`.
- Проектный файл `.codex/config.toml` закрепляет модель по умолчанию `gpt-5.6-sol`, режим рассуждения `ultra`, сервисный уровень `fast` и возможность `fast_mode`; project hooks в нём отсутствуют. Последовательный допуск корневых задач задают `AGENTS.md` и переносимая Git-CAS-очередь, а значение конфигурации модели по-прежнему не доказывает снимок фактически активной модели.
- Корневой `CODEX_THREAD_ID` доступен как наблюдаемый неверсионированный идентификатор задачи и публикуется в файле запроса и Git trailer. Отдельные версии активной агентской сессии, возможной удалённой сервисной части и контрактов по-прежнему не раскрываются этим полем.

## Формат раздела в файле запроса

В каждом новом файле запроса используется раздел:

```markdown
## Использованные инструменты

- [Реестр системных приложений и инструментов](../Инструменты/реестр-системных-приложений-и-инструментов.md) - общий справочник инструментов и способов проверки версий.
- `название` - версия или способ проверки версии; кратко, для чего использовался в этой сессии.
```

Перед разделом инструментов или сразу после текста запроса фиксируется корневой сеанс Codex:

```markdown
## Идентификатор сеанса Codex

Codex-Thread-ID: <значение CODEX_THREAD_ID корневой задачи>
```

Если инструмент разовый и не должен становиться устойчивой частью памяти, его можно указать только в файле запроса. Если инструмент повторяется в рабочих сессиях или влияет на воспроизводимость, его нужно добавить в этот реестр.
