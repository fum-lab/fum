# Перевод объявлений кода на русский язык

Автоматизация помогает последовательно перевести собственный код FUM и затем не допускать нового латинского остатка. Она отделяет наблюдение от изменения: инвентаризация и проверка снимка ничего не меняют, `план` полностью проверяет карту и показывает будущий результат без записи, а `применить` повторяет те же проверки до первой замены.

Инструмент не придумывает русские имена и не обновляет снимок самовольно. Смысл каждого имени определяет человек или агент по контексту файла, а карта переименований служит явным проверяемым решением.

Python-ветвь использует [контракт лексических привязок и потребителей](безопасный-перевод-Python.md). Внешние атрибуты и ключевые аргументы не заменяются по совпадению имени; неоднозначные собственные употребления закрывают преобразование отказом. Инвентарь дополнительно учитывает параметры лямбд, привязки исключений и явные псевдонимы импортов. Новые внешние методы AST-посетителя исключаются только при подтверждённой базе из `ast`; свободная функция `visit` и метод постороннего класса исключения не получают.

## Область правила

Инвентарь рассматривает собственные файлы `.py`, `.swift`, `.md`, прежний точный JS-адаптер и четыре точных CJS-сценария ответа:

- для Python синтаксическое дерево даёт классы, обычные и асинхронные функции, параметры, имена в контексте записи и записываемые атрибуты;
- для Swift лексический разбор вне строк и комментариев даёт типы, функции, `let`, `var`, варианты `case`, параметры функций и явных сигнатур замыканий;
- для Markdown рассматриваются идентификаторы узлов только в собственных ограждённых блоках `mermaid`; подписи, строки, комментарии и текст вне блока не являются кодом для переименования.

Закрытая граница CJS определена в [описании сценариев ответа](сценарии-ответа.md). Она включает только `scripts/адаптер_ответа.cjs`, `tests/test_адаптер_ответа.cjs`, `tests/test_смешанный_профиль.cjs` и `tests/профиль-смешанных-ответов.cjs` внутри точного `Инструменты/fum-svyaznostj-rabochej-sessii/`. Каждый файл проходит полный ограниченный разбор связываний и полей, затем независимый `node --check --input-type=commonjs` без исполнения исходника. Наличие Node.js обязательно; отсутствие, таймаут, ошибка синтаксиса или неизвестная конструкция закрывают допуск. Остальные `.js`, `.mjs`, `.cjs` не становятся поддержанными расширениями.

Карта CJS переименовывает только связывания и их идентификаторные употребления. Строки, комментарии и ключи внешнего контракта сохраняются; сокращённое связывание разворачивается с сохранением читаемого ключа. Миграция имён собственных полей и сокращённых внешних полей закрыта: совпадение имени не доказывает принадлежность поля объекту. Для неё потребуется отдельное расширение с проверяемым учётом владельца. Во всех случаях разбираются те же исходные UTF-8-байты, чей хэш проверен картой.

Из остатка исключены внешние обязательные объявления Python: специальные имена с двумя подчёркиваниями, точные методы посетителя синтаксического дерева и обязательный префикс `test_` перед русским именем теста. Это узкие исключения внешнего интерфейса, а не разрешение вводить произвольные латинские имена.

Восемь собственных JSON-имён рабочего контекста сохраняются по [конечному перечню](аббревиатуры-контекста.json): точное имя, путь, язык и вид объявления связаны с классом исключения, причиной и исходными Git-байтами. Это имена с русской смысловой основой по правилу 000028, а не внешний API. Фильтр действует только на готовый инвентарь; объявления остаются доступны карте будущего перевода. Соседние имена, пути и виды исключение не наследуют. [Руководство](собственные-имена-контекста.md) описывает также ограниченную совместную миграцию трёх Swift-имён, ссылок и шаблона генератора.

Swift-сигнатура замыкания распознаётся непосредственно после открывающей скобки, включая `@Sendable`, список захвата, проецируемый параметр с `$`, типы и типизированный `throws`; поздний `in` в теле не делает обращения параметрами. Модификаторы захвата определяются по позиции: собственные имена `safe` и `unsafe` сохраняются. Экранированный параметр сохраняет своё имя, даже если без обратных кавычек оно может обозначать модификатор. Ключевое слово в позиции метки параметра учитывается как метка; короткое связывание `let self` не делает следующее выражение объявлением. Варианты `case` собираются только в непосредственном теле `enum`; циклы имеют отдельные связывания, включая `for try await`. Это ограниченный лексический инвентарь; компиляция и проверка реализуемых внешних протоколов остаются отдельными свидетельствами.

Обнаружение Swift-имени само по себе не доказывает безопасную миграцию. Карта меток, записанных ключевыми словами `for` и `in`, пока закрывается отказом: замена всех одноимённых ключевых слов повредила бы циклы. Если переводимое имя без экранирования совпадает с поддержанным модификатором параметра или захвата, автоматизация также отказывает до записи; точного разрешения таких ролей для миграции пока нет. Однозначные экранированные употребления сохраняют обратные кавычки при замене.

Обход полностью исключает `.git`, `.build`, `.swiftpm`, каталоги кэшей, `Зависимости`, `Источники`, символические ссылки и корневое производное пространство исторических worktree `Подузлы/`. Компонент `Подузлы` ниже другого канонического корня сам по себе не исключается: граница привязана только к первому компоненту repo-relative-пути. В Markdown не анализируются дословный `Текст запроса` в журнальном `запрос.md`, `Снимок Git` и раздел `Вопрос` в `Вопросы и ответы`. Ошибка синтаксиса, кодировки или незакрытая ограда завершает проверку отказом.

## Инвентаризация

Из корня checkout выполни:

~~~text
PYTHONDONTWRITEBYTECODE=1 python3 Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/scripts/перевести-объявления-кода.py инвентаризировать --корень-репозитория .
~~~

Команда печатает детерминированный канонический JSON схемы `1`:

~~~json
{
  "версия_схемы": 1,
  "объявления": [
    {
      "вид": "функция",
      "имя": "old_name",
      "путь": "Инструменты/пример.py",
      "столбец": 1,
      "строка": 3,
      "язык": "python"
    }
  ]
}
~~~

Порядок записей стабилен и входит в контракт снимка. Пустой массив означает отсутствие наблюдаемого латинского остатка в поддержанной области, но не заменяет содержательное ревью имён.

## Точный снимок остатка

Снимок создаётся или обновляется только явной командой после просмотра инвентаря. Он не дублирует десятки тысяч записей: хранит SHA-256 канонического полного инвентаря, общее число и сводку по языкам:

~~~text
PYTHONDONTWRITEBYTECODE=1 python3 Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/scripts/перевести-объявления-кода.py обновить-снимок --корень-репозитория . --снимок <путь-к-снимку>
~~~

~~~json
{
  "версия_схемы": 1,
  "объявлений": 43362,
  "отпечаток_инвентаря": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "по_языкам": {
    "mermaid": 469,
    "python": 16359,
    "swift": 26534
  }
}
~~~

Запись снимка проходит через временный файл в том же каталоге, синхронизацию содержимого и атомарную замену. Обычная проверка не создаёт исходный уровень и не принимает новый остаток:

~~~text
PYTHONDONTWRITEBYTECODE=1 python3 Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/scripts/перевести-объявления-кода.py проверить --корень-репозитория . --снимок <путь-к-снимку>
~~~

`проверить` заново строит полный инвентарь и требует точного совпадения его отпечатка и сводных чисел со снимком. Любое добавление, удаление, перемещение или изменение позиции наблюдаемого объявления даёт ненулевой код завершения.

## Конечный адаптер Codex

Инвентаризация дополнительно принимает только точный `Инструменты/fum-reyestr-planirovaniya/scripts/адаптер-codex.js`. Допущен конечный шаблон асинхронной функции с двумя параметрами, подготовкой допуска, условным исполнением и сохранением ответа. Четыре собственные привязки получают точные позиции в инвентаре; внешние ключевые слова JavaScript сохраняются. Пробелы и разрешённые переводы строк не меняют контракт, комментарии, строки, дополнительные инструкции, недопустимые имена и изменение связей шаблона закрывают его.

Используйте обычную команду `инвентаризировать --корень-репозитория .`; при отказе восстановите полный шаблон. Этот подтип допуска не разрешает самостоятельный перевод произвольного JS: другие пути и расширения `.js`, `.mjs`, `.cjs`, самостоятельные JS-ограды Markdown, символические ссылки и неверный регистр не соответствуют его конечному шаблону. Четыре [CJS-сценария ответа](сценарии-ответа.md) имеют отдельный конечный допуск. Дословные исходные запросы и точная производная область сохраняют прежние границы. Проектор использует ту же функцию проверки из своей принимающей версии инструмента.

## Карта переименований

Карта схемы `1` перечисляет только выбранные файлы. Для каждого файла закрепляются относительный путь, хэш точных исходных байтов и непустое соответствие старых имён новым:

~~~json
{
  "версия_схемы": 1,
  "файлы": [
    {
      "путь": "Инструменты/пример.py",
      "ожидаемый_хэш": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "переименования": {
        "old_name": "старое_имя"
      }
    }
  ]
}
~~~

Допустимое новое имя является идентификатором, содержит кириллицу и не содержит латиницу; единственное исключение — обязательный технический префикс обнаружения теста `test_` перед полностью русской смысловой частью. Инструмент отклоняет неизвестные и повторные поля JSON, повтор пути, выход из корня, символическую ссылку, неподдержанный тип файла, неверный хэш, старое имя без наблюдаемого объявления, повтор нового имени и коллизию с уже существующим идентификатором файла.

## План и применение

Сначала всегда выполни сухой прогон:

~~~text
PYTHONDONTWRITEBYTECODE=1 python3 Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/scripts/перевести-объявления-кода.py план --корень-репозитория . --карта <путь-к-карте>
~~~

Результат содержит исходный и будущий хэши, каждую пару имён и число токеновых замен. Файлы при этом не записываются. Просмотри план и только затем примени ту же карту:

~~~text
PYTHONDONTWRITEBYTECODE=1 python3 Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/scripts/перевести-объявления-кода.py применить --корень-репозитория . --карта <путь-к-карте>
~~~

До первой записи инструмент читает и проверяет всю карту, все исходные хэши, объявления и коллизии, строит полный новый текст каждого файла и создаёт временные файлы рядом с целями. Непосредственно перед заменой он снова сверяет все исходные хэши. Каждый целевой файл заменяется атомарно с сохранением его режима доступа; строки, комментарии, подписи Mermaid и обычный Markdown остаются нетронутыми. Файловая система не предоставляет общей транзакции для нескольких путей, поэтому авария операционной системы между атомарными заменами разных файлов требует сверки выданного плана и текущих хэшей перед повтором.

После применения запусти относящиеся к изменённому коду проверки, повтори инвентаризацию и обновляй снимок только как отдельное осмысленное изменение ожидаемого остатка.

## Проверка автоматизации

Автономный набор не использует сеть, секреты или содержимое рабочего репозитория:

~~~text
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/tests -p 'test_*.py'
~~~

Тесты проверяют инвентарь трёх языков, защищённые области, точный снимок, сухой план, токеновые замены без строк и комментариев, сырые подписи Mermaid, хэши, русские имена, коллизии и отсутствие латинских собственных объявлений в самом инструменте.
