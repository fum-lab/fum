# FUM MD Recency

Этот навык описывает локальную [автоматизацию FUM](../../Глоссарий/автоматизация-FUM.md), которая поддерживает в каждом проектном Markdown-файле [памяти FUM](../../Глоссарий/память-FUM.md) скрытую служебную метку последнего содержательного редактирования и собирает общий индекс этих `.md`-файлов от свежих к более старым.

Содержательным считается изменение текста файла без учёта самой служебной метки `FUM-MD-RECENCY`. Для этого автоматизация хранит рядом с датой хэш содержимого без блока метаданных: если хэш не изменился, повторный запуск не обновляет дату файла.

## Когда использовать

Используй эту автоматизацию в каждой [рабочей сессии](../../Глоссарий/рабочая-сессия.md), влияющей на проект, после внесения файловых правок и перед проверкой связности сессии.

Автоматизация особенно важна, когда сессия создаёт или редактирует Markdown-файлы: `Документация/`, `Глоссарий/`, `Запросы/`, `Журнал/`, `Планирование/`, `Описания/`, `Источники/`, `Инструменты/` и корневые `.md`-файлы.

## Команда запуска

```bash
python3 Инструменты/fum-md-recency/scripts/update-md-recency.py
```

Команда обновляет:

- служебный блок `FUM-MD-RECENCY` в конце каждого Markdown-файла;
- индекс [Markdown-файлов по времени редактирования](../../Индексы/markdown-файлы-по-времени-редактирования.md) с Markdown-таблицей в основном Obsidian-стиле: колонки выровнены пробелами в исходнике.

Множество входов задаёт общая автоматизация [fum-project-files](../fum-project-files/SKILL.md): отслеживаемые и новые неигнорируемые проектные Markdown-файлы включаются, а `.build`, `.swiftpm`, каталоги кэшей, `.obsidian/plugins` и `.obsidian/themes` не читаются, не индексируются и никогда не переписываются. Структурные исключения действуют и при `--no-git`; этот флаг отключает только использование Git-истории для вычисления времени.

Для проверки без записи используется:

```bash
python3 Инструменты/fum-md-recency/scripts/update-md-recency.py --check
```

## Правило времени

Если файл уже содержит актуальную метку и его содержательный хэш не изменился, дата сохраняется.

Если файл изменён содержательно, создан заново или ещё не содержит метки, дата выбирается так:

- для файлов, изменённых в текущем рабочем дереве Git, используется время запуска автоматизации;
- для чистых отслеживаемых файлов при первой инициализации используется дата последнего Git-коммита, который менял файл;
- если Git-история недоступна, используется время запуска автоматизации.

## Проверки

Локальные тесты автоматизации запускаются без сети и секретов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Инструменты/fum-md-recency/tests -p 'test_*.py'
```

Тесты фиксируют базовый контракт: автоматизация добавляет метки, сохраняет дату неизменённых файлов, строит индекс в порядке от свежих файлов к старым, оформляет таблицу индекса с выровненными колонками, замечает устаревшую метку в режиме `--check` и при первой инициализации умеет брать дату чистого отслеживаемого файла из Git-истории. Отдельные фикстуры подтверждают, что проверка неизменного снимка остаётся успешной на следующий календарный день, а `.build/checkouts/vendor/README.md`, `.swiftpm` и кэши не становятся входами и не изменяются.

## Граница автоматизации

Скрипт не определяет смысловую ценность изменения. Он только поддерживает машинно проверяемое время последнего содержательного редактирования и индекс Markdown-файлов. Агент по-прежнему отвечает за корректность содержания, публикационную чистоту, ссылки на источники требований и полноту файла исходного запроса.
