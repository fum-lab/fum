# FUM Prototype Launch

Эта локальная [автоматизация FUM](../../Глоссарий/автоматизация-FUM.md) проверяет единый контракт простого запуска прототипов. Каждый непосредственный подкаталог `Прототипы/` с паспортом `README.md` считается устойчивым прототипом и должен содержать исполняемый POSIX-скрипт `запустить.sh`.

## Контракт точки входа

Скрипт запуска:

- находится в корне каталога прототипа и называется `запустить.sh`;
- начинается с `#!/bin/sh` и имеет исполняемый бит;
- корректен для `/bin/sh`;
- сам определяет каталог прототипа и не зависит от текущего рабочего каталога;
- без обязательных аргументов даёт полезный и безопасный сценарий;
- передаёт явно заданные аргументы прототипу;
- не включает чувствительное действие без отдельной явной команды;
- описан в паспорте прототипа.

Автоматическая проверка подтверждает первые три структурно проверяемых свойства. Полезность, безопасность сценария по умолчанию, передачу аргументов и соответствие паспорту нужно дополнительно проверять смысловой приёмкой конкретного прототипа.

## Команда запуска

Из корня репозитория:

```bash
python3 Инструменты/fum-prototype-launch/scripts/check-prototype-launchers.py
```

Из другого каталога:

```bash
python3 /путь/к/FUM/Инструменты/fum-prototype-launch/scripts/check-prototype-launchers.py \
  --repo-root /путь/к/FUM
```

Успешная проверка сообщает число найденных точек входа. Ошибка перечисляет каждый отсутствующий или некорректный файл и возвращает ненулевой код.

## Проверки автоматизации

Автономные тесты не требуют сети, секретов, Swift-сборки или запуска прототипов:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s Инструменты/fum-prototype-launch/tests \
  -p 'test_*.py'
```

Тесты фиксируют корректный POSIX-скрипт, отсутствие каталога прототипов, отсутствие файла, отсутствие исполняемого бита, неверный shebang, синтаксическую ошибку и игнорирование служебных каталогов без `README.md`.

## Граница автоматизации

Проверка намеренно не исполняет `запустить.sh`. Прототип может открывать GUI, обращаться к заранее установленной локальной модели, читать явно выбранный файл или требовать отдельного согласия на наблюдение чувствительного ввода. Такие сценарии принимаются отдельно по паспорту, а общий smoke-check остаётся безопасным и автономным.
