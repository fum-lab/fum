# Актуализация путей

Компонент общей Swift-основы инвентаризирует выбранные области Git-worktree, вычисляет новые имена **каталогов и файлов**, показывает препятствия и позволяет повторно сверить сохранённый план. Общий читающий контракт сохраняет `применение_разрешено: false`. Отдельный конечный контракт применяет ровно девять имён архива; он описан ниже и не превращает общий план в разрешение переноса.

Поддержанная среда — macOS и Swift 6. Исходные пути, stage0, Git OID, режимы и SHA байтов входят в снимок; машинный корень передаётся только при запуске. Публичный результат использует относительные пути и логическую идентичность корня. План относится к наблюдённому физическому дереву: изменение HEAD, индекса, байтов, режима, имени или inode требует нового плана.

## Сборка первого среза

Все команды выполняются из физического корня FUM. Подготовьте закреплённую зависимость по [штатному навыку Git-зависимостей](../../Инструменты/fum-proverka-git-zavisimostej/SKILL.md). Нужна ревизия LinguisticKit `837e2ce107b97ee7b9d3344c9fe99142281fe393`.

Корневой Package.swift включает библиотечную цель `АктуализацияПутей` со статическим LinguisticKit и тестовую цель `proverki-aktualizaciya-putej`. Обе используют общие строгие настройки Swift 6. Из чистого клона после штатной инициализации зависимости все 36 проверок компонента запускаются через этот публичный вход. Проверяемая современная среда — Apple Swift 6.4 с `swiftbuild`. Пример для zsh:

```zsh
сборка=$(mktemp -d -t fum-puti)
swift test --package-path . --scratch-path "$сборка/package" --jobs 2 --build-system swiftbuild \
  --disable-automatic-resolution --filter 'proverki_aktualizaciya_putej'
```

Фильтр использует имя Swift-модуля с подчёркиваниями вместо дефисов; SwiftPM может также компилировать остальные цели общего пакета. Имя генерируемого bundle — ASCII kebab-case: прежний bundle `ПроверкиАктуализацииПутей` в наблюдённом Swift 6.4 отказал на CodeSign, в том числе при адресном `swift test list` без исполнения тестов. Исторические отказы и успешный запуск через deprecated `native` сохранены в Журнале; они не подменяют проверку современного входа и не устанавливают общую причину дефекта SDK. Отдельного пакета или приватного test runner нет. Для CLI сухого плана остаётся прямой компилятор; флаг `ФУМ_КОМАНДА_ПУТЕЙ` задаётся только здесь:

```zsh
сборка=$(mktemp -d -t fum-puti)
swift build --package-path Зависимости/LinguisticKit --product LinguisticKit \
  --scratch-path "$сборка/linguistickit" -j 2
swiftc -swift-version 6 -strict-concurrency=complete -warnings-as-errors \
  -enable-actor-data-race-checks -parse-as-library -D ФУМ_КОМАНДА_ПУТЕЙ \
  -module-cache-path "$сборка/modules" \
  -I "$сборка/linguistickit/debug" -L "$сборка/linguistickit/debug" \
  -lLinguisticKit -Xlinker -rpath -Xlinker "$сборка/linguistickit/debug" \
  iskhodniki/aktualizaciya-putej/proveritj-puti.swift \
  iskhodniki/aktualizaciya-putej/proverka-imyon.swift \
  iskhodniki/aktualizaciya-putej/chteniye-snimka.swift \
  iskhodniki/aktualizaciya-putej/modelj-plana.swift \
  iskhodniki/aktualizaciya-putej/postroyeniye-plana.swift -o "$сборка/proveritj-puti"
```

Зависимость сохраняет собственный прежний режим сборки; перечисленные строгие флаги относятся к новым исходникам. Из 19 принятых файлов запуска изменён только общий Package.swift для подключения целей; остальные 18 файлов сохранены побайтно.

## Адресный профиль дедупликации

Для адресного профиля одной занятой области и 1000/2000/4000 файлов используется тот же публичный Swift Testing вход:

```zsh
профиль=$(mktemp -d -t fum-profile)
профиль=$(cd "$профиль" && pwd -P)
env FUM_PROFILE_ROOT="$(pwd -P)" FUM_PROFILE_OUT="$профиль/замеры.json" \
  FUM_PROFILE_LABEL=indexed swift test --package-path . --scratch-path "$профиль/build" \
  --jobs 2 --build-system swiftbuild --disable-automatic-resolution \
  --filter 'измеритьСлучайЧужогоПисателя'
```

Родитель выхода должен существовать, иметь режим `0700` и находиться вне любого Git-предка. Существующий файл не перезаписывается. Пять интервалов каждого размера охватывают построитель; подготовка прямых снимков и внешняя сериализация результата исключены. Профиль сохраняет хэши исходников и планов. Без переменной `FUM_PROFILE_OUT` этот отдельный измеритель пропускается; функциональная регрессия и бюджет сравнений исполняются всегда.

Для воспроизведения пары до/после сохранён [точный обратный патч линейного baseline](../../Журнал/2026-10-26_00-20-51_MSK_устранить-квадратичную-дедупликацию-препятствий/материалы/линейный-baseline.patch.txt). Его применяют только к отдельной копии исходников, после проверки хэшей из [свидетельства](../../Журнал/2026-10-26_00-20-51_MSK_устранить-квадратичную-дедупликацию-препятствий/материалы/свидетельства-дедупликации.json). Это эквивалентный рефакторинг прежнего линейного поиска, а не неизменённый исторический commit. Малая серия не доказывает скорость всего FUM или строгую линейность при произвольных хэш-коллизиях.

## Вход и результат

Сохраните форматированный UTF-8 JSON вне Git. Поля `владелец` и `писатель` содержат наблюдённый UUID исполнителя; при штатном CLI поле `писатель` повторно берётся из `CODEX_THREAD_ID`. Совпадение строк не выдаёт полномочий: назначение и единственный писатель предварительно проверяются координатором.

```json
{
  "схема": "fum.запрос-актуализации-путей.1",
  "контекст": {
    "корень": "узел/репозиторий/направление",
    "владелец": "UUID-исполнителя",
    "писатель": "UUID-исполнителя",
    "целевая_ветка": "refs/heads/codex/example",
    "ветки": [],
    "занятые_пути": []
  },
  "области": ["iskhodniki/aktualizaciya-putej"]
}
```

`ветки` при запуске заменяются свежим читающим наблюдением Git. `занятые_пути` — конечные записи `путь`/`владелец` из отдельно выбранного существующего состояния узла; это вход операции, а не новый реестр владельцев. Неизвестное владение сохраняет препятствие.

```zsh
"$сборка/proveritj-puti" план --корень "$(pwd -P)" --вход "$сборка/input.json" > "$сборка/plan.json"
"$сборка/proveritj-puti" diff --корень "$(pwd -P)" --вход "$сборка/input.json"
"$сборка/proveritj-puti" сверить --корень "$(pwd -P)" --вход "$сборка/input.json" \
  --план "$сборка/plan.json" --sha256-плана SHA256_ВЫБРАННЫХ_СЫРЫХ_БАЙТОВ
"$сборка/proveritj-puti" профиль --корень "$(pwd -P)" --вход "$сборка/input.json"
```

`diff` показывает пары прежних и новых адресов; это не исполняемый Git patch. `сверить` заново выполняет весь читающий путь, сверяет независимо переданный SHA и точные полные байты плана. Нельзя заменять её проверкой одной подписи снимка. Код `0` означает успешное чтение/сверку, а препятствия перечисляются в JSON. Код `2` означает отказ; stdout не выдаётся за корректный план. `профиль` сохраняет три последовательных наблюдения одного процесса с раздельными монотонными границами; первый включает подготовку таблицы.

## Единый порядок имён

Исходный Unicode-компонент сначала разбивается на границах CamelCase/PascalCase, сокращений и цифр. Затем выполняется настоящий LinguisticKit `.Cyrl → .Latn`, таблица `.ru`; результат проверяется на ASCII **до** lowercase и дополнительной нормализации. Пробелы, подчёркивания и повторные дефисы становятся одной границей слова. Технические точки расширений сохраняются. Неподдержанный алфавит и непредставимый результат дают отказ.

`ModeljPlana.swift → modelj-plana.swift`, `XMLParser → xml-parser`, `JSON2Value → json2-value`, `foo2bar → foo2bar`. `XMLHTTP` не делится по предполагаемому смыслу сокращений. Кириллические Swift-идентификаторы внутри файлов не переименовываются.

Конечный перечень исключений этого среза: точное `Package.swift` для SwiftPM; точное `AGENTS.md` для инструкций агента; точное `Инструменты/<имя>/SKILL.md` для канонического обнаружения навыка. Причина и источник каждого использованного исключения входят в план. Похожий Unicode-символ, иной регистр или произвольный суффикс исключения не получают. Перечень не объявляет завершённым аудит остальных доменных форматов.

## Защитные границы

Физические имена и Git-имена сохраняются раздельно. NFC служит только поиском единственного кандидата; точный Git-путь дополнительно открывается через `openat/O_NOFOLLOW` и обязан обозначать тот же inode/тип. Casefold не даёт льготы связывания. Коллизии проверяются отдельно. Индекс с ненулевой стадией, missing tracked, symlink и выход за корень закрывают чтение. Поздний обход метаданных заново проверяет весь прочитанный состав.

Проверяются соседи посещённых каталогов без обхода чужих поддеревьев: существующее назначение, перенос неполного родителя, перенос занятого пути и его предка, циклы, только-регистр и Git ref prefix conflict сохраняются как препятствия. Внешние и производные границы сохраняют адреса; классификация использует закреплённый [существующий контракт проекции](../../Инструменты/fum-bratislavskaya-proyekciya-pamyati/контракт-v2.json), без второго перечня.

В общем читающем контракте поиск ссылок возвращает **кандидатов** Markdown, кода и конфигурации. Синтаксическая полнота и безопасная замена для произвольного переноса не доказаны. Источники, Журнал, RAW и дословные области сохраняются; глобальная строковая замена отсутствует. Отдельное проверяемое применение девяти имён с узкими адаптерами описано ниже; остальные переносы не разрешены.

В pin837 обнаружен [FUM-СБОЙ-0032](../../Сбои/FUM-СБОЙ-0032-общие-изменяемые-таблицы-LinguisticKit.md): изменяемые общие кэши таблицы. Все экземпляры нового фасада используют один общий actor; внутри нативного вызова нет `await`. Это ограничивает обращения данного компонента и не объявляет исправленной закреплённую библиотеку либо все сторонние потребители.

## Конечный пакет девяти имён архива

Точный состав и происхождение находятся в [контракте пакета](kontraktyi/kontrakt-paketa-perenosa.md). Новый план связывает актуальные HEAD/ref/tree, полный stage0, девять source mode/blob/SHA и полный канонический Markdown-инвентарь. Он содержит один Package-adapter и четыре разрешённые destination-правки с recency. Родители путей, содержимое и mode девяти переносимых файлов сохраняются. `Package.swift` и четыре Markdown-файла устанавливаются в рабочем дереве и остаются вне индекса; переименования отражаются в индексе.

Внутри компонента доступен публичный фасад `ПакетноеПрименениеПутей`: `построить(корень:поручение:)` принимает URL и JSON Data; `сверить(корень:план:sha256:)` повторно проверяет выбранный план; `применить(корень:план:sha256:)` возвращает JSON-квитанцию. Машинный корень передаётся отдельно, писатель проверяется по `CODEX_THREAD_ID`. План и применение должны использовать один и тот же исполняемый образ: его SHA закреплён в плане. Публичный фасад не позволяет выбирать другое хранилище либо вводить неисправности. Подключение batch-маршрута общего CLI остаётся отдельным решением ROOT; второго продукта или самостоятельного пакета нет.

Постоянный приватный слот связан с физическим worktree, а не UUID запуска. Долговечные план, намерение и реальное наблюдение FUMA предшествуют эффектам. Перед каждым прямым и обратным шагом, в том числе после записи намерения, повторяются ограды. Квитанция различает `завершено`, `откат-проверен`, `частичный`, `неизвестно`. Откат сохраняет историю forward-подтверждений; он не обещает прежние inode timestamps либо сырые bytes/flags/extensions индекса. Неизвестный переход не откатывается вслепую. Pending, потеря ожидаемого segment и неполный хвост закрывают повтор. Повтор терминальной квитанции читает исторический результат без нового эффекта; это не текущая проверка дерева.

Разбор ссылок поддерживает проверенное конечное подмножество Markdown. Относящаяся неподдержанная или неоднозначная форма закрывает план; несвязанные legacy-формы не должны блокировать всю партию. RAW, native, дословные блоки и защищённые области не переписываются. Это не универсальный Markdown-редактор и не атомарная транзакция Git/FS.

Новые проверки и адресный профиль находятся в собственной подпапке `proverki`. Пример с уже подготовленной зависимостью и приватным физическим scratch вне Git:

```zsh
swift test --package-path . --scratch-path "$сборка/package" --jobs 2 \
  --build-system native --disable-automatic-resolution --filter 'ПроверкиПакета'
env FUM_BATCH_PROFILE_OUT="$профиль/результат.json" \
  swift test --package-path . --scratch-path "$сборка/package" --jobs 2 \
  --build-system native --disable-automatic-resolution --filter 'ПроверкиПакета/адресныйПрофиль'
```

Родитель выхода профиля должен существовать вне Git; существующий файл не перезаписывается. Профиль отдельно включает один dry-run и независимо повторно сверенное применение всей партии. Два полных разбора Markdown не являются девятью отдельными планами. Вложенные интервалы не суммируются; малая синтетическая серия без baseline не доказывает ускорения либо скорость live RAW. Deprecated `native` в наблюдённой среде сохранён явно; исторический отказ SwiftPM не скрывается сменой названия запуска.

Обычный клиент без `@testable` сохранён в `proverki/paket-perenosa.swift`. После сборки модуля его можно отдельно проверить `swiftc -typecheck -swift-version 6 -strict-concurrency=complete -warnings-as-errors -enable-actor-data-race-checks -I <scratch>/arm64-apple-macosx/debug/Modules iskhodniki/aktualizaciya-putej/proverki/paket-perenosa.swift`. Проверка видимости не исполняет перенос; реальное применение и ошибки проверяет batch-suite.

### Восстановление инициализации после отказа parent-fsync

Существующий private-каталог может остаться после успешного mkdir и отказа синхронизации родителя. Поэтому существование не подтверждает устойчивость: повтор проверяет mode/owner и повторно синхронизирует родителя. Если остался промежуточный каталог, его родительское ребро подтверждается до создания потомка. Проверка неполной пары namespace/marker сохраняется; потерянный slot не пересоздаётся. При продолжающемся отказе программа не доходит до первого предметного шага.

Различающий интеграционный тест `устойчивостьРодителяДоЭффекта` адресует EIO единственному directory FD по dev/ino родителя, а остальные fsync выполняет штатно. Проверены листовой и вложенный случаи. Старый код при повторе выполнил14effects; исправленный повтор снова отказал до namespace/marker, сохранив HEAD/ref/index, sources и пять текстов. После снятия отказа parent-fsync действительно повторяется и план долговечно сохраняется. Это введённая неисправность, а не испытание отключением питания.

Для узкого измерения используется `FUM_BATCH_INIT_PROFILE_OUT` с фильтром `ПроверкиПакета/профильУстойчивостиРодителя`. Восемь последовательных private bases охватывают4листовых и4вложенных случая: первый отказ, повторный отказ и успешное восстановление. Подготовка fixture/плана исключена; предметные14effects не профилируются повторно.

Системные адреса Git и пустой конфигурации берутся из экспортируемых Darwin SDK `_PATH_STDPATH` и `_PATH_DEVNULL`. На проверенной SDK первый стандартный каталог дал тот же прежний исполняемый образ. Используется только первый абсолютный корректный каталог, явный `posix_spawn`, исходный C argv и прежнее очищение `GIT_*`; поиска/fallback по пользовательскому PATH нет. Проверка с поддельным PATH, посторонними конфигами, UTF8 argv и отказом прошла до/после замены. Межверсионная эквивалентность SDK не предполагается: изменение SDK требует новой сверки выбранного образа. Наблюдённый SHA образа не заменяет такую сверку.
