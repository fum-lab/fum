Рецепт формирования метаданных корректирующего коммита нормализатора

Назначение
==========

Файл шаблона является точным JSON-представлением входного значения
ПланСообщенияКоммита и содержит только поля исходныйЗапрос, заголовок и описание.
Основа будущего добавочного коммита — 12d79d197bd5b9fc2ec454649a07a908e6a68c0c.
Шаблон SHA-256: a70fdc202d3951749f22f90225c4ba0458f3ba9ae78b8e0b4238d0e44755e1f6
Исторический коммит 12d не переатрибутируется.

Ограничения
===========

- Не менять и не переписывать опубликованный коммит 12d.
- Не формировать автора из сохранённой конфигурации, заданного режима или значения по умолчанию.
- При отсутствующей, повторной, NULL, некорректной или UNKNOWN-атрибуции остановиться.
- Запрещённые токены UNKNOWN, unavailable, null и unset сравниваются без учёта регистра.
- Модель должна быть непустым допустимым токеном; усилие должно точно входить в
  none|minimal|low|medium|high|xhigh|max|ultra.
- Модель и усилие брать только из валидной свежей terminal receipt собственного потока.
  UUID ROOT получать из grant, путь и SHA которого закреплены в той же receipt.
- Ошибка любой проверки завершает рецепт до создания выходного JSON, файла сообщения
  или вызова коммита.
- Не менять существующий форматировщик, цель Swift, модуль, исполнитель или среду
  выполнения.
- Не выполнять SwiftPM, компилятор, тесты, CLI или фактическое применение.
- Не передавать несколько -m; формировать один проверенный файл сообщения и передавать
  его одному --file.

Совместимость форматтера
========================

Существующий исходник:
koordinaciya/генератор-метаданных-коммита.swift

Входной тип ПланСообщенияКоммита имеет ровно три содержательных ключа:
исходныйЗапрос, заголовок и описание. Выходной тип
ВыходГенератораGitMetadata имеет environment и message. Эталонная раскладка
сообщения в referenceOutput:

Исходный запрос:

Последняя строка заканчивается одним LF. Имя автора формируется как

строки собственного наблюдения.

Входы и fail-fast проверки
=========================

Все пути ниже задаются вызывающим процессом из уже проверенного закрытого набора.
Не искать другие файлы и не выполнять SQL, Git, Swift, компилятор, тесты, CLI или
runtime. Пример отрицательной проверки ниже использует только jq и временные файлы.

Начать отдельный shell-процесс с:

set -eu
umask 077

Обязательные переменные:

CODEX_THREAD_ID — точный UUID собственного текущего потока;
FUM_TEMPLATE — путь к трёхполёвому шаблону;
FUM_RECIPE_PATH — путь к этому рецепту;
FUM_PROVENANCE_PATH — путь к provenance JSON этого исправления;
FUM_AUTHOR_RECEIPT — путь к неизменённой свежей terminal receipt;
FUM_SOURCE_ACT — путь к correction ACT текущего этапа;
FUM_OUTPUT_JSON — новый путь выходного JSON;
FUM_MESSAGE_FILE — новый путь проверенного сообщения;
FUM_OUTPUT_RECEIPT — новый путь частной квитанции результата.

Определить валидатор receipt. Он принимает только .valid=true, точное совпадение
actor/proposal.actor/row.id с CODEX_THREAD_ID, полный ожидаемый набор ключей строки,
точную привязку grant и authorName, согласованное с model/effort. Пустая строка,
недопустимые символы и маркеры UNKNOWN/unavailable/null/unset отвергаются без учёта
регистра; effort дополнительно сверяется с закрытым перечислением:

validate_receipt() {
  jq -e --arg own "$CODEX_THREAD_ID" \
    --arg grantPath "$FUM_GRANT_PATH" \
    --arg grantSHA "$FUM_GRANT_SHA" \
    --argjson grantBytes "$FUM_GRANT_BYTES" '
    def token_ok:
      . as $v
      | if ($v | type) != "string" or ($v | length) == 0 then false
        elif (($v | test("^[A-Za-z0-9][A-Za-z0-9._-]*$")) | not) then false
        else
          ($v | ascii_downcase) as $lower
          | (($lower | startswith("unknown")) | not)
            and ((["unavailable","null","unset"] | index($lower)) == null)
        end;
    . as $r
    | if ($r | type) != "object" or ($r.row | type) != "object" then false
      else
        ($r.schema == "fum.stage0002.fresh-own-author.terminal.1")
        and
        ($r.valid == true)
        and ($r.actor == $own)
        and ($r.proposal.actor == $own)
        and ($r.row.id == $own)
        and (($r.row | keys | sort)
             == ["id","model","model_provider","reasoning_effort","updated_at","updated_at_ms"])
        and ($r.grant.path == $grantPath)
        and ($r.grant.bytes == $grantBytes)
        and ($r.grant.sha256 == $grantSHA)
        and ($r.row.model | token_ok)
        and ($r.row.reasoning_effort | token_ok)
        and ((["none","minimal","low","medium","high","xhigh","max","ultra"]
              | index($r.row.reasoning_effort)) != null)
        and ($r.authorName ==
             ("FUM Codex [" + $r.row.model + "; effort=" + $r.row.reasoning_effort + "]"))
      end
  ' "$1" >/dev/null
}

Отрицательный DATA-пример: взять ту же receipt в память, заменить только model на
UNKNOWN и согласовать authorName с этим значением. Валидатор должен вернуть
ненулевой код; обёртка генерации обязана остановиться до создания JSON, сообщения,
квитанции или маркера коммита. База данных и Git в этом примере не используются:

generate_checked() (
  receipt_path=$1
  template_path=$2
  root_uuid=$3
  output_json=$4
  message_file=$5
  if ! validate_receipt "$receipt_path"; then
    return 1
  fi
  model="$(jq -er '.row.model' "$receipt_path")" || return 1
  effort="$(jq -er '.row.reasoning_effort' "$receipt_path")" || return 1
  author_name="FUM Codex [$model; effort=$effort]"
  tmp_json="$output_json.tmp.$$"
  tmp_message="$message_file.tmp.$$"
  trap 'if [ -n "$tmp_json" ]; then rm -f "$tmp_json"; fi; if [ -n "$tmp_message" ]; then rm -f "$tmp_message"; fi' EXIT
  jq -n -cS --slurpfile plan "$template_path" \
    --arg model "$model" --arg effort "$effort" --arg rootUUID "$root_uuid" '
    ($plan[0]) as $plan
    | {
        environment: {
          GIT_AUTHOR_NAME: ("FUM Codex [" + $model + "; effort=" + $effort + "]")
        },
        message: (
          $plan["заголовок"] + "\n\n"
          + $plan["описание"] + "\n\nИсходный запрос:\n"
          + $plan["исходныйЗапрос"] + "\n\nCodex-Thread-ID: "
          + $rootUUID + "\n"
        )
      }
  ' > "$tmp_json" || return 1
  jq -j '.message' "$tmp_json" > "$tmp_message" || return 1
  jq -e --arg author "$author_name" --arg root "$root_uuid" '
    .environment.GIT_AUTHOR_NAME == $author
    and (.message | type == "string")
    and ([.message | scan("(?m)^Codex-Thread-ID:")] | length == 1)
  ' "$tmp_json" >/dev/null || return 1
  [ "$(tail -n 1 "$tmp_message")" = "Codex-Thread-ID: $root_uuid" ] || return 1
  trailer_count="$(grep -c '^Codex-Thread-ID:' "$tmp_message" || true)"
  [ "$trailer_count" = 1 ] || return 1
  [ ! -e "$output_json" ] || return 1
  [ ! -e "$message_file" ] || return 1
  mv "$tmp_json" "$output_json" || return 1
  tmp_json=
  mv "$tmp_message" "$message_file" || return 1
  tmp_message=
)

FUM_NEGATIVE_PREFIX="${TMPDIR:-/tmp}/fum-names-unknown-${CODEX_THREAD_ID}-$$"

  exit 1
fi

Единственный вызов коммита
===========================

Коммит не запускается при подготовке этих частных файлов. Только после нативного
source ACK, точной проверки diff/index, подтверждения свежего известного автора и
предварительной сверки публикации отдельно выполнить:

test "${FUM_SOURCE_ACK-}" = ACK
if ! FUM_COMMIT_AUTHOR_NAME="$(jq -er '.environment.GIT_AUTHOR_NAME' "$FUM_OUTPUT_JSON")"; then
  exit 1
fi
if ! FUM_COMMIT_MESSAGE="$(jq -er '.message' "$FUM_OUTPUT_JSON")"; then
  exit 1
fi
if ! FUM_COMMIT_MESSAGE_FILE="$(cat "$FUM_MESSAGE_FILE")"; then
  exit 1
fi
test -n "$FUM_COMMIT_AUTHOR_NAME"
test -n "$FUM_COMMIT_MESSAGE"
test "$FUM_COMMIT_AUTHOR_NAME" = "FUM Codex [$FUM_MODEL; effort=$FUM_EFFORT]"
test "$FUM_COMMIT_MESSAGE" = "$FUM_COMMIT_MESSAGE_FILE"
GIT_AUTHOR_NAME="$FUM_COMMIT_AUTHOR_NAME" \
GIT_AUTHOR_EMAIL='fum@local' \
GIT_COMMITTER_NAME='FUM' \
GIT_COMMITTER_EMAIL='fum@local' \
git commit --cleanup=verbatim --file "$FUM_MESSAGE_FILE"

После коммита выполнить точное чтение сырого объекта и дерева, проверить
author/committer, русский subject/body и последний ROOT trailer. Только затем
обычной точной отправкой передать новый OID в одноимённую ветку и независимо
сверить OID через ls-remote. Не повторять commit/push 12d.

Ограничение результата
======================

Этот рецепт задаёт формирование сообщения только для исходного checkpoint.
Он не доказывает запуск Swift-форматтера, сборку Swift, проверку нормализатора,
среду выполнения, фактическое применение или ROOT acceptance.
