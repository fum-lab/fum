# Контракт пакетного переноса имён архива

## Следующий конечный срез: пакетное применение девяти имён архива

Этот срез отдельно реализует применение в компоненте `АктуализацияПутей`. Прежний читающий план сохраняет `применение_разрешено: false`; его подпись не становится разрешением нового эффекта. Контрольная точка `ca3e59f528bfd9ab2f11e984a8bbd8f0f11c9ef0` уже содержит четырнадцать конечных эффектов и 22 прошедшие batch-функции; она не означает live-effect или ROOT-приёмку. Последующий этап включает принятый ROOT `d63cfd96b1f956ec7405e26cb23967bc8be378f8`, профиль и конечные проверки отдельно.

Основа реализации — принятый `6796c71c1e00054096c5f281e43137f593d394cb`. Предметный источник независим: `cfd73bbe1efc682fac4cec1220b9d9f4ab6caa6a`, дерево `29f5636fc080a8985ec33f30c73f7aa66e3ce6dd`. В основе реализации этих девяти исходников нет. Поэтому проверка исходного состояния и будущий эффект относятся к отдельному дереву владельца RAW, а не к дереву разработки инструмента. Это поручение не разрешает исполнителю писать в чужой checkout.

Текущий снимок девяти файлов содержит 4407 байт, SHA-256 `611e56ebf1305f5cc0133c36c242169bfba2950854aee3d6d6d89418f8d191d0`. Историческая карта на родителе `cf9caff741de309322c77fc22a396a4095564406` сохраняется без изменений: 5064 байта, SHA-256 `1e3cc36036fc03dda6f9f4fb00ded1550d5a9a81f8bccfce2ca8a750ee3d61d3`. Имена получены LinguisticKit `837e2ce107b97ee7b9d3344c9fe99142281fe393`; фактический вывод алгоритма имеет SHA-256 `8d3dabe4c3af3b1e7ec7379e348f97859f82fabac3356dceb233538c48cd719b`. Физические адреса выбранных входов остаются в приватном selector.

Обозначения таблицы: `S = iskhodniki/arkhiv-codex`, `T = proverki/arkhiv-codex`. Родительские каталоги сохраняются буквально, меняется только basename. Все девять файлов имеют mode `100644`; содержимое, mode и Git blob при переносе не меняются.

### Конечный состав изменений и ссылки

Помимо девяти переносов нужен ровно один Package-adapter: в target `АрхивКодекса` исключение `README.md` становится `rukovodstvo.md`. План закрепляет прежние и будущие полные байты, mode и SHA файла; допустима только эта проверенная правка выбранного target. Общая строковая замена и исполнение произвольного Swift из входа не используются. Полный генератор манифеста для этого adapter не требуется.

На исходном Git-снимке найдены четыре производные Markdown-ссылки, которые ROOT адресно разрешил вести за переносом:

- `iskhodniki/zapusk/README.md:35` — ссылка `../arkhiv-codex/README.md`.
- `Журнал/2026-10-26_00-11-30_MSK_сохранить-многосегментный-raw-codex/отчёт.md:132` — ссылка из раздела «Источники».
- `Журнал/2026-10-26_01-48-08_MSK_включить-принятую-основу-в-архив-codex/запрос.md:54` — ссылка из «Повлиял на файлы», вне дословного запроса.
- `Сбои/FUM-СБОЙ-0241-декомпозиция-имени-профиля.md:28` — ссылка на `ПроцессыИПрофиль.swift`.

Номера строк описывают наблюдённый источник и не служат самостоятельным selector. Перед эффектом требуются точные текущие байты и доказанное разрешение каждой прежней и новой цели. Меняются только semantic destinations и необходимые recency-метаданные. Native, RAW, дословные блоки, закреплённые исторические хэши и результаты остаются прежними. Имя каталога `Журнал/` само по себе не классифицирует все его ссылки как исторические.

Один поиск по tracked Markdown дал 27 строк в 16 документах; он выявил четыре ссылки, но не доказал полноту. Режим с нулём Markdown-правок для данного входа непригоден. Batch-план должен снять полный канонический Markdown-инвентарь, включая применимые nonignored untracked-файлы, и разрешить ссылки относительно каждой исходной и будущей базы. Неоднозначная или относящаяся неподдержанная форма закрывает план до эффекта. Отдельные девять глобальных планов не строятся.

### План, применение и квитанция

План фиксирует корневую задачу, настоящего писателя и владельца, физический namespace, актуальные HEAD/ref/tree и полный stage0, девять source mode/blob/SHA, состояния родителей и назначений, Package-adapter, Markdown-инвентарь и точные текстовые изменения. Проверки exact/NFC/casefold, только-регистр, циклов, занятых назначений, dirty/unmerged/missing source, hardlink, symlink и выхода за корень сохраняются. Историческая карта остаётся входным свидетельством; отдельно строится актуальный live-plan владельца.

Применение повторно сверяет план по независимо выбранному SHA и текущим fences. Подготовленные выходные байты и долговечное намерение сохраняются до первого эффекта. Каждый переход проверяет ожидаемый подтверждённый префикс операции; дрейф останавливает следующий эффект. Поддержка девяти переносов не объявляется общей атомарной транзакцией Git и файловой системы.

Граница staging соответствует явно проверяемому результату: девять переименований отражаются в stage0 с прежними OID/modes; Package и Markdown устанавливаются в рабочем дереве, а их последующее индексирование относится к обычному коммиту владельца. Прочие stage entries и HEAD сохраняются. Равенство stage0 означает сравнение полных `mode/blob/stage/path`, а не обещание неизменных сырых байтов `.git/index`, его flags/extensions или восстановленных inode timestamps.

Квитанция различает завершение, проверенный откат, частичный и неизвестный исход. При перехваченном отказе допустимо восстановление только доказанно принадлежащего операции состояния; неполный откат сохраняет оставшиеся backup и причину. Падение процесса не считается проверенным откатом. Существующее намерение или неизвестный исход нельзя обходить новым UUID, повторной установкой либо слепым повтором применения. Читающая сверка состояния не выполняет восстановление.

### Проверки и граница поставки

Новая реализация и результаты находятся в `iskhodniki/aktualizaciya-putej` и её собственных подкаталогах. Новые тесты размещаются в `iskhodniki/aktualizaciya-putej/proverki`, исключаются из production target и подключаются отдельным точным test target. Уже отслеживаемые старые тесты `proverki/aktualizaciya-putej` не перемещаются. Имена новых файлов вычисляются как ASCII kebab-case. Смысловые Swift-имена — русские; сохраняются Swift 6, complete concurrency, warnings-as-errors, actor checks и Swift Testing. Новый Python, ручная серия `git mv`, изменение общего допуска и массовая миграция остальных путей не входят.

Различающие проверки охватывают весь batch, точные девять blob, Package-adapter и четыре ссылки; поздний дрейф source/HEAD/ref/index/Markdown, коллизии, symlink/escape, неподдержанные ссылки, отказ внутри партии, частичный откат, неизвестный исход и повторную попытку. Отдельно подтверждаются сохранение native/RAW/дословных байтов и staging-граница. Профиль отмечает инвентаризацию, разрешение ссылок, fences и применение всей партии; число глобальных проходов и наблюдённое время называются отдельно. Старый дорогостоящий per-file цикл не повторяется ради временной базы.

Позднее прямое указание человека переносит новые записи этой области сразу в `iskhodniki/aktualizaciya-putej/zhurnal`. Первоначальная корневая пара уже успела установиться; два её начальных файла сохраняются побайтно как факт прежнего перехода, без заполнения, переноса и имитации завершённого P.1. Новое локальное начало — отдельное явное поколение с дословным поручением, техполями и русским повествованием. Target `АктуализацияПутей` точечно исключает собственный `zhurnal`; остальные настройки общего пакета сохраняются. Новый код дальнейшей адаптации относится к Swift/FUMA, а не к Python.

Первый содержательный checkpoint сохраняет эту конечную программу, фактический остаток старой установки и начало локального журнала. План не доказывает исполнения, а тестовая фикстура не разрешает live-effect. После поставки и отдельного ревью фактический RAW-владелец строит свежий live-plan в своём дереве. Генераторный ребёнок после отдельного поручения #382 доставил конечный результат и снова STOP; его ancestry и 64 исторических пути Журнала сюда не включаются. Приёмка и общий финал ROOT остаются отдельными.


## Поздние уточнения и фактическое состояние

Принятая общая постановка в `Планирование/aktualizaciya-putej.md` восстанавливается до точных байтов основы 679. Её незакоммиченный новый вариант полностью сохранён рядом в `iskhodnaya-postanovka.txt`; это источник перехода, а не новая активная версия общего плана. Все новые результаты этапа остаются в собственной области компонента.

Исторические карта и snapshot Cfd сохраняют происхождение имён. Актуальный live-source выбирается после локального журнального checkpoint владельца RAW. Package-adapter не ожидает вслепую Package из Cfd: в выбранном текущем target `АрхивКодекса` исключение `["README.md", "zhurnal"]` становится `["rukovodstvo.md", "zhurnal"]`, с сохранением остальных байтов и отдельной привязкой SHA.

Автоматизация описывается структурирующей программой FUMA, затем исполняется Swift-примитивами. Готовые `fum.определение-оператора.2`, `AutomationExecutor` и `КонтейнерНаблюдений` подлежат адресному переиспользованию для чистого решения и долговечного наблюдения. Внешние Git/FS-эффекты текущим языком операторов не реализованы; нужен узкий Swift-адаптер, а не новый параллельный язык. Полный Markdown-корпус остаётся за пределами ограниченного значения FUMA; оператор получает проверенный нормализованный снимок. Текущий локальный JSON — запись постановки, а не уже исполненная FUMA-программа.

Прикладной batch реализован. Сохранены настоящие RED решения, byte/ref, parser/FD, receipt и post-intent fences, последующие GREEN и промежуточные отказы. Шаги1–9 выполняют Git-переносы, шаги10–14 устанавливают Package и четыре Markdown-правки. Долговечный план содержит прежние/будущие байты правок; незавершённая операция не получает второй слот. Перехваченный доказанный префикс можно откатить, сохранив forward ack; неизвестный переход остаётся неизвестным и не повторяется. Полный проход и повтор квитанции проверены на собственной синтетической fixture. Public Data/URL фасад подготовлен для одного `fuma`; общий batch-маршрут CLI выбирается ROOT отдельно. Общий ремонт журнала, #380 и полный генератор манифеста в этот срез не входят.

## Адресный этап после отказа приёмки

ROOT не принял `f19779d43c1e92a6022a3f609e83654f3c88d9d7`. Новая точная основа `c6af44bf1ec061675b6205b9c6ee889d98264f28` добавляет шесть JSON сверх прежнего M, исполняемые исходники прежние. Повтор существующего private-каталога после failed parent-fsync обязан восстановить синхронизацию его родителя до namespace/marker и первого предметного эффекта; это относится и к оставшемуся промежуточному private-parent. Реальный RED на двух случаях и последующий GREEN сохраняются отдельными наблюдениями.

Прежние четыре PUB findings не объявлены успешными. Два относительных suffix выражены через API компонентов пути. Реальные системные пути нельзя объявить `allow.nonpath-syntax`; существующий manifest updater не имеет категории `allow.system-runtime`. Адресная SDK-проверка показала корректное переиспользование стандартных Darwin-констант для прежнего выбранного образа и пустого конфига, без пользовательского PATH. Глобальные policy/Python не меняются; фактический исход новой публикационной проверки фиксируется отдельно.

Два незавершённых P.1-файла891 являются новыми для receivingL, поэтому одной исторической классификации недостаточно. Их исходные891/f197/blobs и закрытые капсулы сохраняются. Следующая отдельная ограниченная поставка исключает эти два черновика из результирующего net, не меняя продукт и шесть JSONL. Точная [постановка исключения](kontrakt-isklyucheniya-chernovikov.json) опубликована в содержательном checkpoint этого этапа; до адресного выбора реализации и writer grant ребёнок не начинает запись. Приёмка ROOT остаётся отдельной.
