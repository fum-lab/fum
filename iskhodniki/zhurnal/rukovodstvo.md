# Одна локальная запись журнала

Генератор сохраняет один форматированный JSON внутри назначенной области владельца. Существующий оператор FUMA `вычислить-JSON` действительно исполняется: `ОпределениеОператора.разобрать(Data)` → `AutomationExecutor.выполнить` → типизированная проверка. Текущий граф identity: возвращает строго разобранное JSON-значение входа. Логика типизированного контракта, оболочки записи, хэшей и файлового эффекта пока находится в Swift; её перенос в операторы этим срезом не объявляется выполненным. Существующий `ПредставлениеЗапуска.байты` формирует читаемый UTF-8 с отступом в два пробела и конечным LF. Новый DSL и Python не добавлены.

Вход задаёт время с часовым поясом, ROOT, писателя, стадию и положительный номер. Обязательны происхождение, буквальные либо явно производные сообщения, решения, действительные проверки, исход, остаток и ссылки доставки. Порядок и повторы массивов сохраняются. Git — возможные данные происхождения, а не обязательная зависимость записи.

После чистого raw-разбора engine строго декодируется и проверяется результат оператора. Сериализованные JSON-значения исходных байтов побайтно сравниваются с этим типизированным результатом: сохраняются исходные типы, значения и закрытый состав полей. Число `1` и логическое `true` различаются; явный `--оператор` не разрешает исправить невалидный тип оригинала, даже если результат уже выглядит корректным. Проверка выполняется в общем планировщике, включая путь применения, до формирования записи и файлового эффекта. Повторные ключи и нецелые числовые формы engine по-прежнему отклоняет по первоначальному тексту.

Идентификатор файла — SHA256 экземпляра `ROOT/писатель/стадия/номер`. Хэши исходных байтов входа, оператора и содержимого отдельны. Изменение данных того же экземпляра сохраняет путь и вызывает конфликт. Временные ID, текущее время и UUID не выбираются автоматически.

## Запуск

Нужны Swift 6 и зарегистрированная LinguisticKit ревизии `837e2ce107b97ee7b9d3344c9fe99142281fe393`. Подготовка зависимости описана в [локальном навыке](../../Инструменты/fum-proverka-git-zavisimostej/SKILL.md). Единственный executable пакета — `fuma`; прежний `swift run` без аргументов сохранён. Журнал вызывается отдельной командой `fuma журнал`.

Владелец заранее готовит существующий физический каталог `zhurnal` внутри своей области. CLI принимает физический абсолютный корень явно. Из корня FUM:

```text
swift run fuma журнал помощь
swift run fuma журнал план --корень <физический-корень> --вход iskhodniki/zhurnal/primer.json
swift run fuma журнал применить --корень <тот-же-корень> --вход iskhodniki/zhurnal/primer.json --план <сохранённый-ответ-плана>
```

Ответ команды `план` сохраняется вне Git. Необязательный `--оператор` выбирает явный файл определения вместо встроенного ресурса. Вход, определение, ответ плана и целевые каталоги должны оставаться прежними. Сохранённый план содержит точные будущие байты в Base64 и физический снимок цели; его нельзя применять в другом checkout. После изменения цели нужен новый читающий снимок, а существующая запись по прежнему ID всё равно не перезаписывается.

Чистый план получает снимок цели явными данными. Само наблюдение цели — отдельный читающий шаг. Применение повторно вычисляет план, сравнивает полные сериализованные байты и проверяет каждый компонент пути через `openat`, `O_NOFOLLOW` и raw UTF-8/NFC/casefold. Перед эффектом удерживается неблокирующий `flock` конечного каталога. Полного обхода Git или истории нет.

## Эффект и восстановление

`O_CREAT|O_EXCL` создаёт ровно один конечный файл. Затем выполняются запись с обработкой короткого результата, `fsync` файла и каталога и чтение точных байтов. JSON виден постепенно: атомарная видимость полного документа не заявляется. Возвращённая `установлена` означает наблюдённое прохождение этих шагов.

Точный повтор читает прежний обычный файл и возвращает `наблюдена`, сохраняя inode и время изменения. Это не доказательство успешности прежнего `fsync`. Несовпадающий либо частичный файл, symlink, коллизия и дрейф дают отказ. Остаток сохраняется: приложение не удаляет, не дописывает его и не выбирает новый ID. После отказа сначала читают тот же путь и прежние свидетельства; слепое повторение запрещено. CLI возвращает код 2 и отдельную типизированную схему отказа журнала.

Срез рассчитан на сотрудничающего единственного писателя. Дескрипторы и повторные снимки не заявляются защитой от произвольного враждебного процесса с теми же правами или гарантией восстановления после потери носителя.

## Предел растущего каталога

`ГраницаЦели.проверитьИмя` перечисляет всех соседей каждого выбранного компонента. Для каталога `zhurnal` с N записями проверка имени одной новой записи требует O(N) чтений имён; последовательность отдельных коротких CLI-запусков на растущем каталоге может дать O(N²). Профили на 1 и 16 сообщениях меняют размер содержимого, создавая свежие временные цели; они не измеряют этот рост. Отсутствие квадратичности не заявляется.

До массового использования нужен отдельный адресный замер на нескольких конечных размерах каталога со счётчиками прочитанных имён и числом запусков. Минимальный кандидат предотвращения — управляемый каталог с одним писателем и длительным контекстом: один начальный полный скан, индекс raw/NFC/casefold-имён в памяти, контролируемое обновление после собственных эффектов. При перезапуске, смене владельца или неизвестном внешнем изменении индекс должен отвергаться и проверяться заново; потеря индекса не разрешает очистку остатка или новый ID. Такой контекст и индекс пока не реализованы. Это кандидат следующей оптимизации, без произвольного hard limit и без изменения строгой файловой границы текущего среза.

## Публичное представление

В текущем контракте `публичная` обязательно равна `true`. Проверяются все строковые поля; машинный путь нельзя разрешить входным `report.historical`. Для нативного поручения с приватным путём оригинал остаётся приватным. Явно производное представление сохраняет SHA256, длину и источник оригинала и не называется дословной цитатой. Преобразователь принимает ровно одно выбранное точное вхождение; ноль и два вызывают отказ. Точный шаблон `<область>/zhurnal` не скрывает соседний настоящий путь.

Первый исторический checkpoint `93e295df76da050c165f3aa8ed45e319053958dd` и его сообщение содержат прежнюю ошибочно опубликованную строку. Исправление текущих данных в `d96f3508d4639ef1017ac13f2f7c0fdeab704486` не очищает историю. [Собственная запись сбоя](zhurnal/4.json) сохраняет эту границу.

## Проверки и измерения

Сборка использует Swift 6, complete concurrency, warnings as errors и actor data race checks. Новые тесты — Swift Testing внутри [proverki](proverki/). Фильтр собственного набора — `proverki_zhurnala`; отдельные процессы используют путь к собранному `fuma` из переменной среды `FUM_КОМАНДА_ЖУРНАЛА`. Профиль вызывается фильтром `профильКонечногоВхода` и получает новый приватный выход через `FUM_ПРОФИЛЬ_ЖУРНАЛА`.

Целевые прогоны выполняются через [малый Swift-адаптер](uchyot-proverok.swift): аргументы — префикс новой локальной записи, приватный каталог свидетельств, название, executable и его argv. Он сохраняет намерение до процесса, отдельный терминальный исход, длительность, входные закрепления и хэши точных приватных argv/stdout/stderr. Это самостоятельный ограниченный учёт; он не присваивает себе схемы прежнего report/Creator. Старый resolver требует глобальную пару Журнала и к новой области неприменим.

[Профиль](profilj.json) измеряет по три повтора для 1 и 16 сообщений. Медианы формирования — 5,14 и 16,46 мс; форматирования — 0,036 и 0,070 мс; проверки цели, установки, синхронизации и readback — 68,07 и 67,94 мс. Внешний процесс, сборка и повторная валидация плана не входят в эти три внутренние стадии. Это Debug и конечные входы; интервалы не суммируются с внешним временем. По этим данным алгоритм сохранён, ускорение не заявлено.

Повторный [профиль первоначального среза](zhurnal/33.profilj.json) после авторской правки имён и уточнения публикационного примитива дал медианы 5,11/16,97 мс, 0,035/0,076 мс и 71,20/70,87 мс. Прежнее свидетельство сохранено отдельно. Это повтор проверки на тех же конечных входах, без заявления об ускорении.

RO-замечание ROOT выявило, что прежнее `NSDictionary.isEqual` при явном операторе принимало исправление `1` в `true` и обратно. [RED39](zhurnal/39.iskhod.json) воспроизвёл оба обхода и оба файловых эффекта. После замены на типосохраняющее JSON-сравнение [GREEN42](zhurnal/42.iskhod.json) подтвердил отказ до записи. Исходная отдельная защита с повторным полным декодированием и проверкой увеличивала чистую стадию до 10,44/33,88 мс — [профиль41](zhurnal/41.profilj.json). Выбранный вариант сохранил строгую границу и дал 5,31/17,85 мс; форматирование 0,036/0,076 мс, установка 74,52/73,37 мс — [профиль43](zhurnal/43.profilj.json). Это ограниченное сравнение вариантов на тех же входах, без вывода об общей производительности FUMA.

Проверка порядка теперь декодирует тело и сравнивает ровно пять сообщений `[A,B,A,C,B]`, их буквальные UTF-8-байты, происхождение и повторные решения. Известный ID закреплён независимой fixture; он не вычисляется проверяемым helper. Прежняя проверка равенства двух вызовов сама по себе такого покрытия не давала.

Исполненный [пример](primer.json) породил [один файл](zhurnal/b83d7cf2cc5c811e17d9c1b7ec19a96242e24271bcf6b14331bd908673639e60.json). [Установка](zhurnal/23.iskhod.json) и [повтор](zhurnal/24.iskhod.json) выполнены отдельными процессами. [Исходы RED и меры](zhurnal/5.json) сохранены вместе с первоначальными отказами.

Общие NAV, Markdown-индекс и проекция, старые Creator/READY/report, импорт JSONL, создание писателей и интеграция в ROOT остаются вне этого среза. `check-session-coherence` — отключена по решению №149 / не проверено. Доставка ветки не означает приёмки ROOT.
