# Многосегментный архив RAW Codex

Архив принимает ограниченные Data-порции до JSON-декодирования в существующий `КонтейнерНаблюдений`. Пределы объекта 64 МиБ, сегмента 256 МиБ, 4096 записей и 16384 фрагмента сохранены; приём по умолчанию использует 8 МиБ и ротирует сегменты. Дроби, экспоненты, неизвестные события, невалидные JSON/UTF-8 и хвост без LF сохраняются буквально. Память ограничена порцией и метаданными текущего сегмента.

Из чистого клона на macOS 14+ с Swift 6:

```sh
python3 -B Инструменты/fum-proverka-git-zavisimostej/scripts/proveritj-git-zavisimostj.py init --repo-root . --path Зависимости/LinguisticKit
swift build --jobs 2 --product fuma
swift test --jobs 2 --filter 'Архива|АрхивСЗапуском'
```

Общий пакет включает принятую актуализацию путей, поэтому чистому клону нужна штатная подготовка зарегистрированного LinguisticKit на gitlink 837e2ce107b97ee7b9d3344c9fe99142281fe393. Сам byte-archive target зависит только от КонтейнерНаблюдений.

Пакет использует Swift 6, complete concurrency, warnings-as-errors и actor checks. Test target и bundle — ASCII `arkhiv-codex-tests`. Набор создаёт обычный синтетический файл 264 МиБ, проверяет настоящий переход сегмента, три новых процесса, удаление исходника и SHA восстановленного потока. Нужно около 0,9 ГиБ свободного временного места. Сеть, Git и Python для приёма/восстановления не используются. Необязательная переменная `ФУМА_ПРОФИЛЬ_АРХИВА` задаёт новый JSON-файл с числовым профилем; родитель должен существовать, прежний файл не перезаписывается. Сборку можно вынести стандартным `--scratch-path`.

Один executable `fuma` сохраняет штатный `swift run`. Обычный запуск сам не импортирует native Codex JSONL; подкоманда архива принимает явно указанный файл. Архив — его подкоманда. Ниже `$1` — физический абсолютный путь архива вне Git с существующим принадлежащим пользователю родителем без групповой/общей записи, `$2` — заявленный UUID Codex, `$3` — выбранный UUID поколения источника, `$4` — исходный обычный файл, `$5` — отсутствующий выходной файл. Конечный корень архива требует ровно 0700; чужие права не исправляются.

```sh
swift run fuma архив-codex импорт "$1" "$2" "$3" "$4"
swift run fuma архив-codex восстановить "$1" "$2" "$3" "$5"
```

Повторный импорт точно сверяет все старые байты одним последовательным проходом, затем принимает добавку из того же fd. Размер/inode/mtime не заменяют сверку. Атомарная версия живого источника без согласования писателя не обещается. Поколение выбирается явно и сохраняется; другое поколение с тем же архивом отвергается. UUID не извлекается из имени файла. Зонд после устойчивого append подтверждает его только верхнеуровневым `session_meta.payload.id` в завершённой LF строке. Строки больше 64 КиБ зонд не декодирует: RAW остаётся полным, UUID — неподтверждённым. Противоречащий UUID даёт отказ после сохранения байтов.

Метаданные версии 1 связывают сессии, поколение, диапазон RAW, SHA256, LF-границу, обработанный курсор и SHA256 канонических метаданных предыдущей квитанции. Неподтверждённый UUID представлен отсутствием необязательного значения. Начало каждого номерного сегмента продолжает цепь. Восстановление проверяет непрерывный состав, не выбирая каталог по mtime. Общий advisory flock держит одного писателя при ротации; некооперативный процесс с теми же правами вне этой гарантии.

API `принять(_:смещение:)` адресует порцию: подтверждённый повтор тех же байтов не дописывается, подмена и разрыв отвергаются. Для целого файла нужен `импортировать`, чтобы получить один проход префикса на цикл. `сохранено` и `обработано` независимы. `проецировать` выдаёт ещё не обработанный LF-префикс порциями переданному callback; успех callback предшествует фиксации курсора. Границы порций не являются границами строк. Повторный вход запрещён. Компонент не исполняет сохранённые инструменты и LLM-запросы. Результат — нативный Swift-примитив байтового архива и системный адаптер с API, Codable и CLI. Вызов идёт от Команда.main через КомандаАрхиваКодекса.выполнить к АрхивКодекса; единственная зависимость его target — КонтейнерНаблюдений. Подключения к AutomationExecutor, ОпределениеОператора, ГрафJSON и FUMStructuringOperatorMemory здесь нет. Конкретная семантическая проекция и подключение в существующий граф/оператор FUMA остаются работой принимающего контура. Метаданные и callback не объявляются исполненной программой FUMA; полный Issue378 остаётся открытым.

Запись и fsync наблюдаются прежним адаптером; throwing `завершить()` наблюдает close обоих fd. Совместимый `закрыть() -> Void` не доказывает успешного close. Файловый отказ закрывает экземпляр для повторной записи. Новый запуск проверяет цепь и заново синхронизирует подтверждённые записи и родителя имени корня, включая EEXIST. Неизвестный append не повторяется вслепую. Неполный контейнерный хвост по умолчанию отвергается. Явный `восстановить-хвост` проверяет префикс, обрезает только незавершённый контейнерный кадр, завершает последний пустой mkdir и экспортирует подтверждённый RAW. JSONL-хвост без LF не обрезается. Частичный выходной файл после отказа сохраняется; обычный экспорт требует нового отсутствующего пути. Внешний отказ архива консервативно сообщает машинный `исходНеизвестен`.

Профиль разделяет открытие и действие с завершением. Счётчик показывает возвращённые байты источника, не весь I/O контейнера при reopen/restore. Пик памяти — getrusage отдельного процесса; нулевые блочные счётчики ОС не доказывают отсутствия I/O. Бинарник закрепляется SHA до/после каждого процесса; повтор сравнивает полный состав и SHA обоих сегментов. Измерения на 264 МиБ с неочищенным кэшем не являются импортом или ускорением приватного ROOT около 21 ГБ и восстановлением всего узла.
