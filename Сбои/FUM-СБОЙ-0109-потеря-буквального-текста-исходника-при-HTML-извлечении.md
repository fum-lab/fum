# Потеря буквального текста исходника при HTML-извлечении

## Наблюдаемый сбой

При сохранении исходников Swift и LICENSE с MIME text/plain архиватор применял HTML-очистку и извлечение. Дословные угловые конструкции исчезали; Markdown-ссылки исходного файла становились активными ссылками памяти.

## Граница повторения

Неверная маршрутизация plain text и JSON через HTML-представление. Это отличается от PDF-сигнатуры и очистки служебных данных настоящих веб-страниц. Первичное HTTP-тело уже сохранялось отдельно; ошибочным было смысловое извлечение.

## Ожидание и классификация

Наблюдённая недоработка существующего архиватора: точные исходные свидетельства не должны искажаться HTML-фильтром. Уникальный номер выделен штатным общим хранилищем под корневым UUID текущего Журнала; событие `20cb22d3f09958f7ccda934edd9593d932678db1c14bdd5f87a4c857bb91cc12`. Это не предположение о лицензии внешнего проекта.

## Механизм и системное устранение

После распаковки MIME text/plain и application/json получают буквальное представление без HTML-очистки. Длина Markdown-ограды превышает максимальную последовательность обратных кавычек исходника. Первичные bytes остаются response.body.html по прежнему контракту имени; их настоящий тип сохраняется в заголовках. HTML, PDF и публикационная проверка имеют прежние границы. Дословное представление не объявляется новым средством очистки секретов.

## Связанные шаги

Мера необходима для сохранения реальных исходников и лицензий существующего [FUM-STEP-0220](../Планирование/карточки-шагов/🟡-FUM-STEP-0220-спланировать-полную-зеркальную-сборку-Swift-toolchain.md). Отдельный STEP и native-задача не создавались.

## Критерии закрытия

- Фикстура с Markdown-ссылкой, вложенными кавычками и `<template>` сохраняет первичные bytes и буквальный текст.
- Прежние HTML регрессии проходят; JSON с угловыми конструкциями сохраняется буквально.
- Снимки текущего этапа созданы исправленным общим маршрутом и имеют проверяемые manifest hashes.
