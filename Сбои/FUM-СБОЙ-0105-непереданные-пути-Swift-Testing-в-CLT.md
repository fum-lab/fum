# Непереданные пути установленного Swift Testing в CLT

## Наблюдаемый сбой

После обновления macOS и удаления прежнего Xcode стандартный swift test с CLT 27 beta 6 не выполнил тесты: сначала не найден TestingMacros, после его явного подключения — Testing.framework, затем lib_TestingInterop.dylib. Все три файла физически присутствовали в активном комплекте.

## Граница повторения

Swift 6.4 (swiftlang-6.4.0.33.1), CLT for Xcode 27.0 beta 6, SDK 26A5419a, macOS 27.0 build 26A428; сборочный движок swiftbuild. Это доказанная граница Swift Testing текущего клиента. Наблюдение XCTest в другой задаче и причина некорректного сравнения в макросе не объединены с ней.

## Проявления

- `FUM-СБОЙ-0105/ПРОЯВЛЕНИЕ-0001`: [история запусков собственного этапа](../Журнал/2026-09-12_01-06-00_MSK_проверить-и-измерить-приёмник-клиента-Telegram/отчёт.md), записи bce85edb-967c-4a4b-9216-046bb644f166, e59187c9-8eea-44ca-b4d9-c2459ddeb56a и e5027844-8923-4ea6-901c-014ae03402fc. Это последовательная диагностика одного неполного набора переданных путей. Единственная проба native отдельно завершилась отсутствием модуля Testing и не повторялась.

## Ожидание и классификация

Ожидалось выполнение существующего Swift Testing набора на установленном комплекте. Наблюдён отказ среды до содержательных тестов. Окончательная внутренняя причина SwiftPM/CLT не установлена; наличие файлов само по себе не обеспечивает их поиск компилятором и загрузчиком.

## Механизм и системное устранение

Добавлен ограниченный [исполнитель проверки пакета](../Приложения/FUMA/Packages/КлиентTelegram/Проверки/проверить-пакет.py). Он получает developer directory через xcode-select, проверяет полный набор файлов и выход символических ссылок за комплект, вычисляет путь плагина и два runtime RPATH. В дочерней среде фиксируется выбранный DEVELOPER_DIR; глобальная настройка не меняется. Машинные абсолютные пути не зашиты в процедуру.

## Восстановление и текущая граница

Через исполнителя прошли все 42 теста клиента; четыре автономные проверки подтверждают переносимый расчёт путей и отказы при неполном/чужом комплекте. Исходный содержательный RED профиля и последующий GREEN отделены от отказов среды. Процедура ограничена объявленным расположением CLT и Swift Testing, не доказывает XCTest, стабильность SDK либо права передачи полного инструментария.

## Критерии закрытия

Проверенный состав CLT и автоматическое обнаружение путей связаны с доставленным снимком кода, повторяемой командой и принятым свидетельством полного набора. Проверка закрыто отклоняет неподдержанный комплект. Одна локальная успешная команда не закрывает весь STEP0222 и не подтверждает другие тестовые среды.
