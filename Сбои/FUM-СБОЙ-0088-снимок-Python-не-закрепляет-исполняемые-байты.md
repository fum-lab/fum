# Снимок Python не закрепляет исполняемые байты

## Наблюдаемое расхождение

Промежуточная фабрика записывала сведения о Python в паспорт, но запускала наблюдатель через заново прочитанный `sys.executable`. При изменении этого значения после создания фабрики тест получил RuntimeError вместо успешного запуска закреплённого интерпретатора. Другой случай той же RED-проверки подменял байты runtime во время имитированной подписи: поставка принималась, хотя ожидался отказ.

## Механизм и граница повторения

Общая мера связывает снимок runtime с фактическим запуском и проверкой его неизменности в одной фабрике. Версия, физический путь и SHA-256 исполняемого файла входят в паспорт повтора; изменение между сборками требует новой цели. Снимок не хэширует всю стандартную библиотеку Python: её установка остаётся объявленной доверенной зависимостью. Карточка не обещает защиту от произвольного привилегированного изменения машины между системными вызовами.

## Критерий закрытия и доказательство

Статус `устранена` относится к коммиту `d4ee3ee01920f0806dbb319df796602e7d3d12db`. При изменённом глобальном `sys.executable` после создания фабрики реальная команда выполняется прежним закреплённым Python; фактический argv наблюдателя совпадает со снимком. Подмена байтов во время имитированной сборки даёт ValueError и не устанавливает конечную поставку. Повтор при иной реализации, версии либо хэше не принимается как прежний вход. Эти сценарии входят в [GREEN 20](../Журнал/2026-09-11_19-51-31_MSK_подключить-экспорт-и-повтор-гостевых-измерений/материалы/запуски-проверок/10_0108337f-6e20-4228-995f-5e26f4b2e7f0.json); совместимость прежнего вызова адаптера подтверждена отдельно. Реальная компиляция Swift и подпись полного пакета этим доказательством не объявляются выполненными.
