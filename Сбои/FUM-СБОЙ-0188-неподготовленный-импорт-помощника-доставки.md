# Неподготовленный импорт помощника сверки доставки

## Наблюдаемый сбой

После push C273 частный вызов существующего `проверенная_поставка_сообщений` с неполной средой импортов завершился кодом 1: «ModuleNotFoundError: No module named приём_направления». Удалённый OID затем проверен отдельно без повторного push. Поставка подтверждена наблюдением remote; код первоначального процесса push после сбоя помощника остаётся неизвестным.

## Граница повторения

Standalone-вызов точного существующего helper без обязательной инициализации транзитивных импортов. Это не угадывание имени0009 и не частная загрузка dataclass без регистрации0128. Последующее чтение ещё не созданного результата учитывается отдельно как0079/0002.

## Ожидание и классификация

Поддержанный способ readback должен загружаться в холодном процессе через объявленную точку входа с нужными зависимостями. Ошибка импорта после push не означает отказа push и не разрешает повторять запись.

## Механизм и системное устранение

Чтением установлена штатная цепочка инициализации каталогов конвейера, реестра, связности, структуры запросов и отчётов. Текущая поставка проверена точным удалённым OID, без повторного push. Отдельного поддержанного читающего ROOT CLI пока нет; его подготовка относится к0245, не к новому терминализатору.
