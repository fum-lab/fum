# Экстрактор LinguisticKit требует тестовый импорт в Release

Граница устранения — сборка и запуск продукта LinguisticKitBuildTool в проверенной дочерней ветке. Обновление зависимости FUM и принятие upstream PR выполняются отдельно.

## Наблюдаемый сбой

При сборке всех продуктов в Release компилятор отвергает @testable import LinguisticKit: оптимизированная библиотека не собрана для тестирования. Исправление Sendable само по себе этот отказ не устраняет.

## Граница повторения

Стандартная оптимизированная сборка исполняемого экстрактора без флага enable-testing. Это контракт доступа между целями пакета, а не гонка таблиц.

## Механизм и ограниченное восстановление

В исполняемой цели оставлен обычный import LinguisticKit. Перечень чувствительных к регистру письменностей и типы описания контекстов доступны соседней цели через package. Публичный API библиотеки ради экстрактора не расширен, флаги проверки не ослаблены.

## Критерии закрытия

- Все продукты собираются в Release без enable-testing.
- Экстрактор запускается и сохраняет точные байты всех JSON в Extracted.
- Исполняемый путь измерен, условия сравнения с исходником названы явно.

## Подтверждение устранения

[Коммит библиотеки b868465](https://github.com/fum-lab/LinguisticKit/commit/b8684654b2a16b04852b5b4cb0ec29e23c354939) прошёл Release-сборку; [отчёт](../Журнал/2026-09-08_22-21-18_MSK_обновить-LinguisticKit-для-Swift-Concurrency/отчёт.md) и профиль экстрактора сохраняют результат выполнения и отсутствие diff Extracted. Исходному сравнению понадобились явно обозначенные режим Swift 5 и enable-testing; новый вариант обходов не требует. Переносить вычисления или добавлять кеши ради этого изменения не требуется.
