# Пропуск parent-fsync при EEXIST

## Наблюдаемый сбой

RED: первый fsync родителя после mkdir отказал, следующий init без удаления существующего корня ошибочно прошёл. Отдельно directory-fsync при ротации оставлял пустой последний каталог, не поддержанный явным восстановлением.

## Граница повторения

Текущий компонент RAW Codex по Issue №378. Новое проявление при изменении соответствующего адаптера или API возвращает внимание; свой коммит не означает приёмки ROOT или интеграции.

## Механизм и системное устранение

Родитель синхронизируется и при EEXIST. Явное восстановление проверенной цепи завершает только последний пустой mkdir после синхронизации его имени; обычный запуск сохраняет отказ.

## Критерии закрытия и результат

Регрессия: `синхронизацияРодителяПовторяетсяПослеОтказа; отказКаталогаРотацииТребуетЯвногоВосстановления` в [публичных проверках](../proverki/arkhiv-codex/). Оба RED сохранены; GREEN проверяет повторный отказ той же инъекции, успешное новое открытие и точный префикс без дубля. Реальная потеря питания не моделировалась. Статус ограничен этой проверяемой реализацией в ветке; неизвестные ошибки, 21 ГБ ROOT и общая устойчивость ОС не объявляются проверенными.
