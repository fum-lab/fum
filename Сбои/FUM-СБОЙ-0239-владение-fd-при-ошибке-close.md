# Владение fd при ошибке close

## Наблюдаемый сбой

Статическая трасса: новый fd был открыт, но переменная владения обновлялась после throwing close старого. Catch мог повторно закрыть старый номер и потерять новый fd.

## Граница повторения

Текущий компонент RAW Codex по Issue №378. Новое проявление при изменении соответствующего адаптера или API возвращает внимание; свой коммит не означает приёмки ROOT или интеграции.

## Механизм и системное устранение

Владение новым fd переносится до однократного close старого. Catch освобождает текущий новый fd; EINTR не разрешает повтор неизвестного close.

## Критерии закрытия и результат

Регрессия: `ошибочноеЗавершениеНеЗакрываетПовторноИспользованныйДескриптор` в [публичных проверках](../proverki/arkhiv-codex/). GREEN закрывает старый fd, занимает его номер новым и инъецирует EINTR; новый владелец номера остаётся открыт. Старый дефект отдельно динамически не запускался. Статус ограничен этой проверяемой реализацией в ветке; неизвестные ошибки, 21 ГБ ROOT и общая устойчивость ОС не объявляются проверенными.
