# Пропуск опорной даты графа после перехода через полночь MSK

Карточка сохраняет исторический сбой инвентаря рабочей сессии. Когда `.obsidian/graph.json` и `.obsidian/fum-recency-reference-date` ещё были Git-выходами, переход через календарную границу MSK сделал sidecar неожиданным затронутым путём. Теперь весь корневой `.obsidian/` является игнорируемым локальным состоянием и не входит в сессионный Git-инвентарь.

## Наблюдаемый сбой

До полного smoke-check опорная дата графа оставалась `2026-08-06`, а файл не входил в Git diff. Smoke-check длился около 27 минут и пересёк полночь MSK. После закрытия машинного журнала штатное замыкающее обновление графа заменило дату на `2026-08-07`; проверка связности сообщила `unexpected Git status path: .obsidian/fum-recency-reference-date`, потому что раздел `Повлиял на файлы` текущего запроса ещё называл только тепловую карту `graph.json`.

## Граница повторения

Исходная граница повторения охватывала только ту политику, в которой оба файла графа отслеживались Git и обязаны были покрываться разделом `Повлиял на файлы`. При точном корневом правиле для `.obsidian/` и пустом Git-инвентаре тот же переход даты изменяет только локальное игнорируемое состояние и не может создать неожиданный Git-путь.

Сюда не относятся произвольные изменения настроек Obsidian, ручное редактирование sidecar, неверная дата с другой доказанной причиной и сам закрытый отказ связности: проверка правильно обнаружила непокрытый путь. Общая мера должна учитывать полный объявленный набор выходов генератора до динамического изменения Git-статуса.

## Ожидание и классификация

В исходном контракте это была ошибка исполнения инвентаря, а не дефект генератора или проверки связности. Текущая классификация изменилась вместе с политикой хранения: оба пути теперь являются локальными выходами, а не частью публикуемой памяти FUM.

## Механизм и системное устранение

Подтверждён временной механизм: между предфинальным и замыкающим запусками изменилась дата MSK, поэтому ранее чистый sidecar стал выходом текущей сессии. Ручной раздел `Повлиял на файлы` не был повторно согласован с полным контрактом выходов до первой замыкающей связности.

Системное устранение снимает весь корневой `.obsidian/` с Git-учёта без удаления локальных копий. Генератор по-прежнему обновляет тепловую карту и sidecar, но ни один из них не попадает в Git-статус, список затронутых файлов, staging или коммит. Свежий checkout допускает полное отсутствие локальной пары, а при существовании хотя бы одного из двух выходов проверка остаётся строгой.

## Критерии закрытия

- Корневой `.gitignore` содержит ровно одну точную эффективно действующую корне-якорную строку для `.obsidian/`, не допускает последующего повторного включения, а `git ls-files` не возвращает путей этого корня.
- Обычный запуск генератора материализует и обновляет локальные граф и sidecar без Git-статуса.
- Проверка свежего checkout пропускает полностью отсутствующую пару без записи, но отклоняет частичное, повреждённое или устаревшее локальное состояние.
- Связность сессии не требует и не допускает локальные пути `.obsidian/**` в списке затронутых файлов; игнорируемая локальная цель не удовлетворяет активной Markdown-ссылке, а переход даты не создаёт неожиданного Git-пути.
- Автономные тесты свежести графа и связности сессии, а также общий smoke-check проходят; FUM-STEP-0135 снята как утратившая применимость.

## Подтверждение устранения

Текущая сессия точным staged-набором сняла прежний HEAD-инвентарь `.obsidian/` с Git-учёта и сохранила каждую локальную копию. Полный набор свежести графа из 15 тестов подтвердил fresh-checkout пропуск без записи, локальную материализацию обычным обновлением, строгий отказ для частичной, повреждённой или устаревшей пары и отказ при повторном включении путей через отрицательные правила `.gitignore`.

Полный набор связности из 81 теста подтвердил новый маркер снятия с учёта, запрет активной ссылки на игнорируемую локальную цель и отсутствие незаявленного Git-пути при обновлении локальной пары. [Полный smoke-check после восстановления сессии](../Журнал/2026-08-14_18-45-51_MSK_игнорировать-изменения-Obsidian-при-старте-задачи/материалы/запуски-проверок/74_a716d133-d8ca-4922-83d3-d80b9d6aeaa8.json) завершил все `77` шагов успешно, а FUM-STEP-0135 снята как утратившая применимость без ложного заявления о реализации.
