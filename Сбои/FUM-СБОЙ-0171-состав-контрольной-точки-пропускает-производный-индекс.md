# Состав контрольной точки пропускает производный индекс

## Наблюдаемый сбой

Объявленный состав был получен из текущего diff до полного формирования производных файлов. Индекс свежести Markdown не вошёл в разрешённые цели; готовность канонического создателя отказала до коммита.

## Граница повторения

Подготовка контрольной точки перечисляет только уже изменённые файлы и пропускает объявленный будущий вывод обязательного генератора. Это не ошибка разрешения существующего пути из 0009 и не устаревший проверочный отпечаток из 0061.

## Проявления

### FUM-СБОЙ-0171/ПРОЯВЛЕНИЕ-0001

Инструментальный ответ `c47f30`: готово завершилось кодом 2 — «Путь вне разрешённого состава: Индексы/markdown-файлы-по-времени-редактирования.md». Создать не запускалось. Отказ сохранён приватно и в [отчёте](../Журнал/2026-09-28_08-08-30_MSK_применить-закрытие-остановленных-задач-конвейера/отчёт.md). Восстановление — новый вход подготовки с прежней историей модели, объявленным индексом и новыми адресными проверками.

## Ожидание и классификация

Ошибка подготовки принадлежит корню; создатель правильно закрыл допуск. История Git и исходная подготовка сохранены.

## Механизм и системное устранение

Состав подготовки должен включать точные будущие результаты обязательных генераторов до проверки и staging, затем сверяться с фактическим индексом. Ручное дополнение исправляет этот экземпляр, не доказывая системного устранения.

### FUM-СБОЙ-0171/ПРОЯВЛЕНИЕ-0002

В ACT19 из C491 будущая штатная навигация начала дочернего J19 была перечислена вручную с прежним C490J. Читающий план исполнителя и независимый ROOT вызов подготовить_начало на C491 потребовали точный соседний ROOT J того же времени с другим стемом. Установка не выполнялась; дерево исполнителя сохранилось чистым на C491. [Отчёт](../Журнал/2026-10-13_17-04-48_MSK_исправить-состав-поручения-нативного-моста/отчёт.md) и [машинный расчёт](../Планирование/решения-постановки/2026-10-13/точный-состав-начала-нативного-моста.json) сохраняют конкретную границу.

Восстановление — новый независимый ACT20 с составом из штатного сухого плана; исходный ACT19 остаётся в Git и не редактируется. Это второй случай неполного объявления будущего вывода обязательного генератора; общий механизм подготовки состава и единая регрессия полного dry-plan должны предотвращать оба проявления. Локальное исправление не закрывает системный сбой.

## Критерии закрытия

Автоматическая подготовка на открытой фикстуре включает будущий индекс свежести, новую историю модели и конечные записи проверок; неизвестный результат генератора остаётся закрытым отказом. Готовность принимает ровно объявленный фактический состав. Для поручения генерация также учитывает соседний запрос из реального dry-plan начала: отдельная фикстура с одинаковым временем и разными стемами проверяет состав до ACT, без последующего ручного расширения.
