# Неверная подкоманда проверки структуры Журнала

## Наблюдаемый сбой

В J14 вызвана неподдерживаемая подкоманда check вместо validate. Парсер отклонил её до проверки структуры; составной процесс завершился кодом 1 после успешного чтения реестра.

## Граница повторения

Только выбор подкоманды автоматизации структуры запросов. Ошибки аргументов других CLI не объединяются с этим эпизодом без доказанной общей меры.

## Проявления

### FUM-СБОЙ-0153/ПРОЯВЛЕНИЕ-0001

[Отчёт J14](../Журнал/2026-09-17_23-32-48_MSK_зарегистрировать-объединённую-приёмку-CLI/отчёт.md) сохраняет исходный неверный вызов. Машинная запись 2 фиксирует отказ, запись 3 — успешный validate. Входные документы не исправлялись для обхода парсера.

## Ожидание и классификация

Вызывающий должен выбирать подкоманду из текущего CLI-help. Это ошибка вызывающего, не дефект валидатора.

## Механизм и системное устранение

Выполнено ограниченное восстановление: прочитан CLI-help, применён документированный validate с явным корнем. Глобальный генератор CLI-вызовов этим не реализован; отсутствие будущих ошибок не обещается.

## Связанные шаги

[Регистрационный этап](../Журнал/2026-09-17_23-32-48_MSK_зарегистрировать-объединённую-приёмку-CLI/запрос.md) завершил конкретное восстановление; отдельного незавершённого шага для этого ограниченного контракта нет. Общая профилактика угадывания остаётся за его пределами.

## Критерии закрытия

Сохранены оба вызова, ошибочная подкоманда не запускала валидатор, исправленная штатная команда проверила тот же Журнал успешно.

## Подтверждение устранения

Терминальные записи J14 связывают отказ и успех; проверены 651 папка запроса, 591 отчёт и 60 исторических запросов без отчёта. Коммит 762253489549980e20dd3efc3333c9dedcdc2515 сохранил результат.
