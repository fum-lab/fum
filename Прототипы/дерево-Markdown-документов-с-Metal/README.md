# Дерево Markdown-документов с отрисовкой через Metal

Этот устойчивый Swift-прототип строит из каталогов и файлов `.md` выбранного репозитория интерактивное иерархическое дерево и выводит его через Metal. Он проверяет узкий графический срез интерфейса FUM: чтение локальной структуры, подготовку геометрии, аппаратную отрисовку и навигацию по крупной карте документов. Текущий статус — «проверяется».

## Проверяемый результат

Прототип рекурсивно читает выбранный каталог, включает файлы с расширением `.md` и только их каталоги-предки и сохраняет родительско-дочернюю иерархию. Из обхода исключаются `.git`, `.build`, `.swiftpm`, кэши, корневые `Подузлы`, вложенные корни Git-репозиториев и символические ссылки. Нечитаемые пути пропускаются с видимым счётчиком, а текст с повреждённым UTF-8 декодируется с заменой недопустимых последовательностей. Полученное дерево является файловой проекцией репозитория, а не семантическим графом памяти FUM: оно не выводит смысловые связи из Markdown-ссылок, текста документов, происхождения требований или операторной структуры.

Экран позволяет:

- искать узлы по имени;
- выбирать каталог или Markdown-документ;
- перемещать карту жестом панорамирования и менять масштаб;
- сворачивать и раскрывать ветви дерева;
- открывать выбранный `.md` штатным системным приложением;
- различать каталоги, документы, выбранный узел и найденные совпадения.

Для больших карт прототип применяет уровни детализации (`LOD`) и отсечение (`culling`): за пределами видимой области геометрия не отправляется на отрисовку, а подписи и второстепенные детали появляются только при достаточном масштабе. Эти механизмы проверяют устройство пути от модели дерева к кадру, но пока не задают и не подтверждают измеримые пороги производительности.

## Графический путь

Основной экран использует `MTKView`, `MTLDevice` и `MTLCommandQueue`. Фон, рёбра, узлы и выделение собираются через `CIContext`, привязанный к Metal-устройству, и записываются в drawable одним Metal-командным буфером. Подписи остаются отдельным `CATextLayer`-оверлеем и не выдаются за часть аппаратной геометрии. Код реализует вызов `CIContext.render(...commandBuffer:)` в текстуру текущего drawable; безоконная диагностика отдельно подтверждает наличие Metal-устройства и создание командной очереди. Короткий графический smoke-прогон подтверждает, что приложение проходит начальное сканирование и остаётся в цикле событий, но не выполняет снимок или обратное чтение кадра.

Если Metal-устройство недоступно, приложение явно показывает ограниченный режим. Такой режим сохраняет возможность увидеть причину ограничения, но не выдаётся за проверку аппаратной отрисовки и не считается выполнением требования к полноценному Metal-пути.

## Запуск

Нужны macOS 14+ и Swift 6+. Из каталога прототипа безопасный запуск с корнем текущего репозитория выглядит так:

```bash
./запустить.sh
```

Другой каталог репозитория можно передать первым аргументом:

```bash
./запустить.sh /путь/к/репозиторию
```

Безоконная диагностика Metal выполняется отдельно:

```bash
./запустить.sh диагностика
```

Автономные тесты запускаются из каталога прототипа:

```bash
swift test
```

Запуск и тесты не требуют сети, учётных данных или секретов. Исполняемое приложение только читает выбранное файловое дерево и не изменяет Markdown-документы, Git-состояние или настройки Obsidian. Сборка и первый `swift run` создают Git-игнорируемый каталог `.build` внутри каталога прототипа. Явное открытие документа передаёт путь штатному приложению macOS; дальнейшее поведение этого приложения находится за границей прототипа.

## Границы проверки

Безоконная диагностика подтверждает создание Metal-устройства и командной очереди; исходный код и строгая сборка подтверждают наличие пути геометрии через `MTKView`, `CIContext` и один Metal-командный буфер. Восьмисекундный графический smoke-прогон не завершился раньше времени после начальной загрузки, но пиксельное обратное чтение, ручная проверка всех взаимодействий и измерение частоты кадров не выполнялись. Прототип не является полноэкранным интерфейсом FUM без системной оболочки, не получает модель представления из канонической памяти или структурирующих операторов и не возвращает действия человека в версионированный событийный контур. Семантические рёбра, совместное редактирование, наблюдение за изменениями файлов, полный Markdown-парсинг и измеримые пороги частоты кадров или размера дерева также не входят в этот срез.
