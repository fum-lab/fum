# Живой прогон одного одноагентного эпизода 2026-08-01

Один узкий сценарий прошёл в собственном runtime FUM от двух реальных model-only-вызовов до разрешённого локального Git-действия, изолированного кандидатного коммита, независимой приёмки и единственного терминального исхода `completed`. Harness дважды наблюдал заранее зарегистрированное подтверждённое поколение, посылал остановленному worker фактический `SIGKILL`, а продолжение выполняли новые процессы без прежнего stdin, чата и скрытых переменных. Возобновление связывало полный execution-passport с SHA в `CURRENT`; перед Git-переходом отдельный внешний артефакт подтверждения был привязан к первому checkpoint.

Результат относится только к этому синтетическому сценарию. Он не доказывает готовность универсального или распределённого FUM, продуктового runtime, произвольного набора действий, устойчивость к потере питания либо преимущество над контрольным агентом.

## Паспорт и модельные вызовы

Живой execution-passport схемы `fum.live_single_agent_episode.execution_passport` версии `1` имеет SHA-256 `sha256:68fec7d41fa64ddc937582a1fae347d656426ea3648816ad91cabe06422c67a0`. Он разрешает только синтетические данные назначения `single_agent_candidate_variant`, не более `467` входных байтов за вызов и одно действие `create_candidate_commit` через `fum-git-candidate-v1` класса `isolated-git-write`. В паспорте перечислены проверки строгого намерения, совпадения candidate plan и отдельной приёмки, два checkpoint и исходы `completed`, `needs_input`, `budget_exhausted`, `failed`.

Provider использовался через уже установленный локальный контур без скачивания весов, новых секретов, платного доступа и пользовательских данных:

| Поле       | Наблюдаемое значение                                 |
| ---------- | ---------------------------------------------------- |
| provider   | `lmstudio`                                           |
| interface  | `lmstudio.rest-api.v0.chat-completions`              |
| model      | `qwen/qwen3-0.6b`, локальный вариант `Q8_0`          |
| runtime    | `llama.cpp-mac-arm64-apple-metal-advsimd@2.27.1`     |
| transport  | `lmstudio_live`; recorded transport не использовался |
| disclosure | только заранее подготовленные синтетические строки   |
| money      | `0` микроденежных единиц                             |

Максимальный бюджет равен двум вызовам, `512` входным и `512` выходным токенам, `60 000` миллисекундам и `60 000` compute units. Reservation одного вызова равен `1 / 256 / 256 / 30 000 / 30 000 / 0` в порядке `calls / input / output / wall-clock-ms / compute / money`. Точная предварительная токенизация была закреплена для обоих входов и совпала с usage provider.

Третий proposal `variant-c` был недоступен по конечному бюджету. Runtime сохранил `budget_checkpoint_created` без нового request, transport-вызова или ответа; независимый аудит harness потребовал `model_response_count = 2` и `budget_checkpoint_no_call = true`.

## Кандидат и отдельная приёмка

Разрешённое действие создало кандидат только в отдельном clone и отдельной ветке. Исходный checkout сохранил базовый `HEAD`, индекс, рабочее дерево и refs; merge, rebase, push и автоматическая интеграция не выполнялись.

Приёмочный процесс получил только каталог эпизода и точный candidate OID, заново прочитал подтверждённый контракт, проверил parent/tree/diff/checker и сохранил отдельный receipt. Терминальное поколение содержит `27` событий и ровно одно `continuation_decided = completed`; SHA журнала событий — `sha256:40190293152bfc3ea5af8053350fa9c646fbab37055c86a51b07cd682e1c2f67`.

## Воспроизведение и отсутствие эффектов replay

Автономный recorded harness дважды прошёл из нового чистого общего предка с теми же двумя фактическими убийствами. Его каноническая семантическая проекция закреплена SHA-256 `sha256:316f1189af9cd027fafbe87edba82a3799f67b691ea1dac54e1473ddfa42a9a1`; оба независимых прогона дали точные одинаковые байты, несмотря на различные PID и абсолютные временные каталоги в сыром аудите.

Живой replay выполнили отдельные PID `58810` и `58812`. Оба вернули одинаковые байты проекции с SHA-256 `sha256:54ee25678c3608db8081d4682950884242a9fef656999422dc338c415dc5473a`. Хэш всего run-каталога до и после обоих replay совпал. Replay не создаёт model-, action-, Git- или acceptance-адаптеры и не записывает workspace; это no-call чтение, проверка подтверждённого `CURRENT` и чистое свёртывание сохранённой трассы.

После живого прогона точная модель была выгружена, локальный сервер остановлен, `lms server status --json` вернул `{"running":false,"port":1234}`, а `lms ps --json` — пустой массив. Это восстановило наблюдаемое исходное состояние provider.
