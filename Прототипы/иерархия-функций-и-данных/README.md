# Иерархия функций и данных

Этот Swift-прототип проверяет минимальную [иерархию функций и данных FUM](../../Глоссарий/иерархия-функций-и-данных-FUM.md) на конечной целочисленной фикстуре. [Чистая функция](../../Глоссарий/чистая-функция.md) получает неизменяемый снимок входных данных, параметров и тела, а цикл `применить -> оценить -> изменить -> закрепить` сравнивает четыре атомарных варианта: оставить слой неизменным, обновить данные, изменить параметры или заменить тело функции.

Ожидаемый результат и проверочная выборка находятся вне изменяемого снимка. Поэтому кандидат не может улучшить собственную оценку подменой цели. Каждый кандидат строится непосредственно от исходного снимка и меняет ровно один объявленный слой; мета-функция отбрасывает составные или неверно объявленные изменения до оценки.

## Проверяемый цикл

```mermaid
flowchart LR
    baseline["Исходный неизменяемый снимок"] --> apply["Применить чистую функцию"]
    apply --> evaluate["Оценить ошибку, стоимость и пользу"]
    evaluate --> candidates["Породить keep, data, parameters, body"]
    candidates --> selector["Выбрать максимум utility"]
    selector --> verification["Проверить на независимой фикстуре"]
    verification -->|"нет регрессии"| stabilize["Закрепить новую ревизию"]
    verification -->|"есть регрессия"| rollback["Вернуть точный исходный снимок"]
```

Тело функции — закрытый перечислимый тип: `affine` вычисляет `multiplier * x + bias`, а `quadratic` — `multiplier * x * x + bias`. Замена тела в этом прототипе означает выбор другого заранее скомпилированного варианта, а не генерацию или исполнение нового Swift-кода.

Для каждого кандидата трасса хранит выход, суммарную абсолютную ошибку, стоимость вычисления, три составляющие цены изменения, пользу относительно исходной ошибки и итоговую полезность:

```text
benefit = baseline_error - candidate_error
total_cost = change_cost + instability_penalty + complexity_penalty
utility = benefit - total_cost
```

Фиксированный профиль иллюстрирует разный темп изменения слоёв:

| Действие            | Цена изменения | Штраф нестабильности | Штраф сложности                           |
| ------------------- | --------------: | -------------------: | ----------------------------------------- |
| `keep`              |               0 |                    0 | `0`                                       |
| `update_data`       |               1 |                    0 | `0`                                       |
| `change_parameters` |               2 |                    1 | `0`                                       |
| `replace_body`      |               4 |                    2 | рост сложности относительно прежнего тела |

Конкретные числа являются параметрами фикстуры, а не универсальными коэффициентами FUM. При одинаковой `utility` детерминированно выбирается более быстрый слой в порядке `keep -> data -> parameters -> body`. Изменение закрепляется только при положительной полезности и отсутствии регрессии на независимой проверке.

## Безопасная фикстура

Без аргументов точка входа выполняет пять сценариев и печатает один канонически упорядоченный JSON-отчёт:

```bash
./Прототипы/иерархия-функций-и-данных/запустить.sh
```

Явный повтор той же фикстуры:

```bash
./Прототипы/иерархия-функций-и-данных/запустить.sh fixture
```

Получить справку:

```bash
./Прототипы/иерархия-функций-и-данных/запустить.sh --help
```

| Сценарий            | Проверяемое решение                                                                      |
| ------------------- | ---------------------------------------------------------------------------------------- |
| `keep`              | точный исходный слой остаётся без новой ревизии                                          |
| `update-data`       | изолированная ошибка входа исправляется без изменения параметров и тела                  |
| `change-parameters` | общий масштаб исправляется параметром, который проходит независимую проверку             |
| `replace-body`      | квадратичное тело окупает более высокую цену и закрепляется                              |
| `rollback`          | то же тело выигрывает на основной выборке, ухудшает проверочную и полностью откатывается |

Пробник не читает файлы, не обращается к сети, не запускает subprocess и не принимает исполняемый код. Все данные сценариев встроены в пакет.

## Проверки

```bash
swift test --package-path Прототипы/иерархия-функций-и-данных
swift build \
  --package-path Прототипы/иерархия-функций-и-данных \
  --product FUMFunctionHierarchyProbe
swift format lint \
  --configuration Инструменты/fum-kompleksnaya-proverka-repozitoriya/swift-format.json \
  --strict \
  --recursive \
  Прототипы/иерархия-функций-и-данных/Package.swift \
  Прототипы/иерархия-функций-и-данных/Sources \
  Прототипы/иерархия-функций-и-данных/Tests
```

Автономный набор проверяет чистоту и повторяемость применения, полную экономику трассы, каждое из четырёх решений, преимущество полезности над минимальной сырой ошибкой, устойчивое разрешение равенства, успешное закрепление, откат до точного исходного значения, атомарность кандидатов, несовпадение размера цели и целочисленное переполнение.

## Структура

- `Sources/FUMFunctionHierarchy/` — неизменяемые типы, чистое применение, генератор атомарных кандидатов, оценка, мета-выбор, проверка и откат;
- `Sources/FUMFunctionHierarchyProbe/` — пять безопасных встроенных сценариев и JSON-отчёт;
- `Tests/FUMFunctionHierarchyTests/` — автономные проверки без сети, секретов и внешних зависимостей;
- `Package.swift` — самостоятельный SwiftPM-пакет;
- `запустить.sh` — общая POSIX-точка входа прототипа.

## Граница применимости

Результат доказывает различение данных, параметров, тела и неизменяемой мета-функции на одной малой детерминированной модели. Он не доказывает обучение нейросети или LLM, автоматический поиск хороших мутаций, синтез и безопасное исполнение кода, корректность выбранных весов стоимости, статистическую обобщаемость, длительную работу на потоке, конкурентность, персистентность, многоуровневую рекурсию мета-функций или изменение самой политики отбора.

Кандидаты заранее заданы фикстурой, а обновление данных допустимо только как вариант с внешним происхождением; цель и проверочные примеры остаются неизменяемыми. Проверка на одной конечной выборке показывает механизм fail-closed отката, но не утверждает, что закреплённый вариант устойчиво лучше в реальной среде. Откат здесь является возвратом исходного value-снимка в памяти процесса, а не транзакцией внешнего состояния.

Статус: действующий проверочный прототип. Пакет собирается, автономные тесты и строгий форматный lint проходят, безопасная фикстура воспроизводимо показывает `keep`, обновление данных, изменение параметров, замену тела и откат.
