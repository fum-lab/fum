# Эталоны сериализации для профиля

Два патча восстанавливают точные исходники измерений [до](../../../../Журнал/2026-09-11_07-43-37_MSK_реализовать-интерпретатор-и-UTF-32/материалы/профиль-до.json) и [после](../../../../Журнал/2026-09-11_07-43-37_MSK_реализовать-интерпретатор-и-UTF-32/материалы/профиль-после.json) оптимизации из итогового пакета FUM-STEP-0208. Это исторические проверочные материалы одного исполнителя, не второй движок и не альтернативная точка входа продукта.

Патчи сохраняют шесть исходных Swift-файлов до позднего форматирования и исходную версию профильного скрипта. Отличие двух измеренных вариантов — прямое кодирование типизированных значений и единый буфер байтов скаляров. Старые строки наносекунд загрузки/разбора сохранены как часть точного эталона; окончательный продукт использует числа для всех стадий. Четыре остальных Swift-файла, Package.swift и определения берутся из итогового коммита. Все десять SHA-256 исходников и хэш скрипта совпадают с соответствующим историческим профилем.

## Воспроизведение из чистого клона

Нужны Swift 6.0+, macOS 14+, Python 3 и Git. Исходные измерения выполнены Swift 6.4 и Python 3.14.7; времена и хэш собранного бинарника зависят от среды. Хэши исходников, входов и наблюдений позволяют сравнить смысл и точные байты результата независимо от длительности.

1. Скопировать целиком `Прототипы/память-структурирующих-операторов` из итогового коммита в новый внешний каталог, не копируя существующую `.build`. Канонический checkout остаётся исходником для обеих копий.
2. В корне первой внешней копии применить `git apply --no-index Проверки/эталоны-профиля/профиль-до.patch.txt`. В другой свежей копии применить `профиль-после.patch.txt` той же командой. Патчи не последовательные: каждый применяется к итоговому пакету. До сборки сверить каждый файл с `исходники_sha256` и профильный скрипт с `сценарий_sha256` соответствующего отчёта.
3. В каждой копии собрать `swift build -c release --product FUMStructuringOperatorMemoryProbe`. Команда `swift build -c release --show-bin-path` возвращает каталог готового бинарника. Копии и их `.build` находятся вне checkout FUM.
4. В каждой копии выполнить `python3 -B Проверки/проверить-и-измерить.py --бинарник <путь-к-бинарнику> --выход <внешний-путь-отчёта.json>`. Скрипт содержит шесть открытых входов, определения и независимый кодек проверки; делает по пять повторов каждого сценария.
5. Сверить `наблюдение_sha256` по всем шести сценариям между отчётами и с исторической серией. Сравнивать медианы соответствующих стадий при одной среде и режиме сборки. Прежние численные длительности не являются побитно воспроизводимым обещанием.

Для проверки окончательного продукта используется текущий скрипт из канонического пакета без патчей; [окончательный профиль](../../../../Журнал/2026-09-11_07-43-37_MSK_реализовать-интерпретатор-и-UTF-32/материалы/профиль-окончательный.json) отдельно связывает исправленный формат длительностей с исходниками.
