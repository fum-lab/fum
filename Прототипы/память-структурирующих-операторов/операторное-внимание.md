# Два определения операторного внимания

Ограниченное расширение общего `AutomationExecutor` связывает наблюдение, значимость, внимание, предложение действия, проверку результата и состояние причины. Предметные условия принадлежат определениям [структурирующих операторов](../../Глоссарий/структурирующий-оператор-FUM.md) для актуальности README и потребности интеграции. Адаптеры извлекают факты. Сигнал не исполняет действие и не предоставляет полномочий.

Пакет прошёл 52 Swift-теста, 23 Python-теста, строгий lint и сквозной Release-сценарий. Доставка ветки и завершение документационной приёмки учитываются отдельно; RED/GREEN и профиль сохранены в [отчёте реализации](../../Журнал/2026-09-11_21-46-50_MSK_реализовать-операторное-внимание/отчёт.md).

## Конечный граф

Новая схема определения `fum.определение-графа.2` имеет поля `схема`, `идентификатор`, `версия`, `цель`, `идентичность`, `основания`, `узлы`, `обязательные`, `исходы`, `сигналы`. Версия определения — положительное целое число; схема языка задаётся отдельно. Исходные определения `fum.определение-оператора.1`, наблюдения и прежний путь исполнения сохраняются.

Узел задаёт `идентификатор`, `оператор`, `входы`. Поддержаны равенство выбранных значений, вхождение значения в конечный список, `все`, `любой`, отрицание ранее вычисленного условия, SHA-256 канонического JSON-значения и SHA-256 строки UTF-8. Последние две операции возвращают 64 шестнадцатеричных знака без префикса; хэши всего определения, параметров и наблюдения используют `sha256:`. Селектор — объект с единственным полем: `поле` содержит массив ключей входа; `константа` — буквальное значение; `узел` — имя предшествующего узла; `цель` — пустую строку для подстановки выбранной цели определения. Компонент пути `$цель` выбирает целую строку цели как ключ. Неизвестные ссылки и циклы отклоняются до вычисления.

Условие имеет три значения: `да`, `нет`, `unknown`. Отсутствующее поле не равно пустой строке или нулю. Обязательное условие должно получить `да`; любой иной исход сохраняет неизвестность независимо от численных весов. Трасса показывает имя узла, оператор, хэши выбранных входов и строковый результат. Селекторы находятся в хэшируемом определении. Обязательные основания выводятся отдельной таблицей условий; роль сигнала `обязательный-критерий` отдельно обозначает предметный критерий, нарушение которого не исчезает при нулевом весе. Общий код не знает имён README, веток и предметных исходов.

Исходы перечислены в явном порядке. Каждый содержит условие, результат, причину, предложение действия и операцию над памятью: активировать причину, сохранить прежнее состояние, подтвердить снятие или отметить неприменимость. Отсутствие доказанного исхода даёт `unknown`. Состояние причины учитывается отдельно от рассмотрения и внимания.

## Чувствительность

Обязательные параметры `fum.параметры-чувствительности.1` содержат `версия`, `веса`, `порог`, `хэш`. Поддержаны целые веса 0…100 для точного набора сигналов определения и порог 0…10 000. Версия — 1…1 000 000. Хэш — SHA-256 канонического JSON с временно пустым полем `хэш`; пробелы оформления не влияют. Отсутствие, лишнее поле, неизвестная схема, неправильный тип, выход за предел либо несовпадение хэша дают явный отказ.

Для каждого объявленного сигнала сохраняются наблюдённое условие, единица вклада 0 либо 1, вес, произведение и порог. Сумма не является вероятностью, уверенностью или доказательством истинности: она задаёт приоритет рассмотрения. Приоритет требует внимания при сумме не ниже порога. Неизвестность обязательного факта и доказанная причина не обнуляются низким весом. Хэши определения, параметров и фактических источников выводятся отдельно; изменение настроек не свидетельствует об устранении.

## README

Идентичность области связывает репозиторий и точный путь `README.md`. Текущий commit или хэш README являются версиями свидетельства. Первый обязательный маршрут — прямая видимая ссылка на `Приложения/FUMA/README.md`. Второй адрес для независимого A/B — присутствующий `Документация/README.md`.

Адаптер читает ограниченные сырые байты, извлекает ссылки и сохраняет для каждой начало и конец диапазона UTF-8, SHA-256 диапазона и всего исходника. Полный прочитанный срез позволяет проверить отсутствие ссылки. Комментарии, код и изображения не считаются видимыми ссылками. Разбор независимо сопоставляется с существующим `check-readme-index`; тот проверяет структуру и навигацию, но не смысловую актуальность. Recency вычисляется существующими функциями и хранится отдельно от SHA-256 сырых байтов.

Доказанное отсутствие обязательной ссылки даёт расхождение. Изменение значимого основания даёт повод пересмотреть его; смысловое устаревание из хэша не выводится. Посторонние файлы не входят в зависимости. Недоступность источника, нарушенная привязка или устаревший срез дают `unknown`. Прежняя активная причина сохраняется.

Просмотр не равен рассмотрению. Рассмотрение не равно устранению. Для снятия активной причины нужны одновременно наличие обязательной ссылки и новое проверенное свидетельство, связывающее текущие байты README, текущую версию основания и область. Старое подтверждение после изменения источника не подходит. Повтор тех же данных воспроизводит тот же JSON; новое время не подставляется исполнителем скрыто.

## Интеграция

Идентичность связывает репозиторий, исходную поставку и выбранную стадию маршрута `fuma` → `master`. Наблюдённый HEAD цели является версией свидетельства. Стадия `master` принимает закреплённый результат стадии `fuma`, связанный с исходной поставкой; прямой перескок с боковой ветки запрещён.

Ancestry и приёмка вычисляются и показываются раздельно. Полное замыкание родителей проверяется по сырым commit-объектам, с независимым пересчётом OID. Отсутствие объекта не заменяется отрицательным ancestry. Закрытый отчёт требует точного v3/report-v2, полного инвентаря, неизменяемых файлов, хэшей и результата существующего проверяющего. Связь отпечатка с поставкой отдельно восстанавливается из её родителя и реальной разницы деревьев. Область проверок сохраняется: документационный smoke не становится проверкой всей функциональности CLI. Неподдержанный v4 не принимается по аналогии.

| Наблюдение                                                    | Предлагаемый результат                                |
| ------------------------------------------------------------- | ---------------------------------------------------- |
| Проверенная поставка ещё не включена в цель                    | Интегрировать в выбранную область                     |
| Только checkpoint либо предметная постановка                  | Разобрать недостающий допуск                          |
| Источник уже ancestor, подходящей квитанции нет                 | Проверить подтверждение включения                    |
| Вход отсутствует, противоречив или неполон                      | Unknown с сохранением прежней активной причины        |
| Включение и совпадающая квитанция подтверждены                  | Снять потребность только выбранной области            |
| Подтверждена отмена                                            | Отметить неприменимость                               |
| Подтверждена утрата результата после включения                  | Разобрать утрату; повторное слияние ancestor не нужно   |

Квитанция ссылается на поставку, её приёмку, выбранную область и результат включения. Чужой OID или чужая квитанция дают unknown. Ancestry само по себе не доказывает сохранность результата после revert. Название коммита не считается доказательством утраты.

## Граница среза

Закрытый JSON принимает строки, целые числа, массивы и объекты. Булевы значения, null и дроби не входят в новый вход, как и в прежний парсер. Предел — 65 536 байтов на определение, параметры или вход; глубина 16, 8 192 узла. Граф конечен и не содержит общего планировщика. Пределы и повреждение параметров дают неуспешный код CLI, а недостаточные предметные свидетельства — вычисленный `unknown` с кодом 0. Код 0 подтверждает исполнение контракта; предметный исход находится в поле `результат` JSON.

Читатель Git может временно материализовать проверенные объекты вне checkout, чтобы настоящий Git воспроизвёл бинарный diff. Он не меняет refs, индекс или объектную базу проекта, не обращается к сети и удаляет временные данные после чтения. Точные источники сохраняются открытыми фикстурами; недоступность обязательного объекта честно остаётся неизвестностью.

Полный язык графов, эмоции, субъективное переживание, Metal, hooks, расписание, автономная фабрика, merge, push и запуск задач не входят в механизм. Рассмотрение сигнала не записывает обработку 0177. Прикладной срез не закрывает весь STEP0165 и REQ0044.

## Память следующего наблюдения

Поле результата `память` готово для передачи как `прежнее` следующего структурированного входа. Оно содержит состояние, активную причину, её область и основания с устойчивым критерием. Поле `прежнее` сохраняет исходный сигнал отдельно. При unknown либо чужой области память остаётся побайтово тем же каноническим значением: старая причина не переносится в новую стадию. Время, параметры и наблюдённый target HEAD не входят в идентичность интеграционного сигнала.

Рассмотрение хранится отдельно. Утрата результата после revert имеет критерий `сохранность-результата`; действующая квитанция включения без новой проверки восстановления эту причину не снимает. Новый проверенный срез README может подтвердить соответствие изменившемуся основанию без правки самого документа. Во всех случаях решение графа является предложением, а поле полномочия остаётся `не предоставлено`.

## Происхождение и область доверия

[Сборщик README](Сборщики/факты_внимания.py) читает обычные файлы с точным регистром, повторно сверяет их версии, сохраняет сырые UTF-8-байты README, диапазоны ссылок и хэш полного извлечения. Видимость Markdown сверяется с существующим `check-readme-index.py`; recency извлекается существующим `update-md-recency.py`. Проверяющий и его исходники имеют закреплённый в определении хэш. Опция `--проверить-результат` отдельно воспроизводит проверку конечного критерия и связывает её с текущим README, выбранным основанием и прежней причиной. Она не вычисляет состояние потребности.

Граф проверяет связи полученного наблюдения, а физическое извлечение остаётся ответственностью объявленного сборщика. Самосогласованный пакет, целиком подделанный вызывающей стороной вместе со всеми исходниками и утверждениями, не аутентифицируется JSON-хэшами. Этот CLI не является границей выдачи полномочий или механизмом электронной подписи. Открытые отрицательные фикстуры проверяют нарушенные связи, неподдержанные схемы и противоречия; они не заявляют защиту от компрометации проверяющего процесса.

[Читатель объектов](Сборщики/объекты_внимания.py) проверяет полные SHA-1 OID по сырым объектам. Архив ограничен 64 МиБ и 8 192 объектами; отдельный объект — 8 МиБ, замыкание истории и деревьев — по 4 096. Глубина дерева ограничена 64, развёрнутая разница — 32 768 записями путей и 16 МиБ вывода Git. Размер live-объекта проверяется до чтения содержимого; накопленный декодированный кэш ограничен 64 МиБ. Полный обход родителей обязателен и для положительного ancestry. Для diff создаётся отдельный временный Git-контекст вне checkout, без чтения локальной конфигурации и `info/attributes` принимающего репозитория. Отслеживаемые `.gitattributes` этим первым профилем отклоняются. Имена веток, refs, рабочий индекс и объектная база проекта не меняются.

Portable-профиль явно задаёт `--abbrev=8`: старое автоматическое сокращение OID зависело от размера объектной базы. Сохраняются стандартные правила Git diff, включая распознавание переименований, без external diff и textconv. Совпадение с сохранённым v3-отпечатком проверяется точно; отличающийся результат не подбирается и не принимается по аналогии.

[Три реальные поставки](Сборщики/примеры_интеграции.py) воспроизводятся из [открытого архива](Проверки/внимание/git-объекты.json) без локального дополнения объектов. Для c7 восстановлена точная связь закрытого report-v2; 8d имеет проверенный открытый checkpoint. У f49 структурно проверен report-v2 и доказано положительное ancestry, но связь сохранённого отпечатка с поставкой не восстановлена также в live Git. Это отдельная неизвестность, которая не разрешает повторное слияние предка или ложный resolved. Состояние приёмки и ancestry выводятся раздельно.

Демонстрационный сборщик формирует наблюдение стадии fuma для трёх закреплённых примеров. Конечные входы стадии master, квитанции, отмены, revert и последовательная память представлены независимыми синтетическими JSON-фикстурами и передаются общему CLI. Они явно названы открытой фикстурой и не выдаются за реальные квитанции интеграции.

## Воспроизведение из корня FUM

Пакет требует macOS 14+, Swift 6.0+ и Python 3.11+. Общий исполнитель написан на Swift. Сборщики используют Python для непосредственного повторного применения уже принятых читателей v3, индекса README и recency; отдельная реализация этих проверяющих не создаётся. SwiftPM-зависимости не добавляются; используются системные Foundation/CryptoKit и стандартная библиотека Python. Для чтения реального архива нужен Git. Собственный код остаётся под CC0 проекта; лицензии используемых Swift, SDK и Git сохраняют самостоятельное действие, сторонние библиотеки в пакет не копируются. Документационная проекция использует отдельно зарегистрированный LinguisticKit `837e2ce107b97ee7b9d3344c9fe99142281fe393`: его фактический LICENSE — CC0 1.0 Universal, отдельный NOTICE в закреплённом дереве отсутствует. Эта зависимость не добавляется в Swift-пакет внимания; её [инициализация](../../Зависимости/README.md) нужна общему документационному контуру.

В одной оболочке фиксируется выбранная через `xcode-select` среда разработчика и создаётся внешний временный каталог сборки средствами Python; следующие команды используют эти значения. Команды Release и определения пути бинарника используют один и тот же Swift через `xcrun`, режим `swiftbuild`, конфигурацию и каталог сборки:

```sh
export DEVELOPER_DIR="$(xcode-select -p)"
fum_attention_scratch="$(python3 -c 'import tempfile; print(tempfile.mkdtemp(prefix="fum-operator-attention-build-"))')"
```

Адресные проверки и последующая регрессия v1 требуют среды с XCTest. Прежний успешный запуск выполнен с Xcode 27.0 build 27A5237l; после обновления установленный CLT без XCTest не подходит для этих команд. Настройка плагина Swift Testing отсутствующий XCTest не заменяет:

```sh
swift test --package-path Прототипы/память-структурирующих-операторов --scratch-path "$fum_attention_scratch" --jobs 1 --filter ПроверкиВнимания
swift test --package-path Прототипы/память-структурирующих-операторов --scratch-path "$fum_attention_scratch" --jobs 1
python3 -B -m unittest discover -s Прототипы/память-структурирующих-операторов/Проверки -p 'test_*внимания.py'
```

Первое определение на открытом отсутствии ссылки:

```sh
swift run --package-path Прототипы/память-структурирующих-операторов --scratch-path "$fum_attention_scratch" --jobs 1 FUMStructuringOperatorMemoryProbe внимание --определение Прототипы/память-структурирующих-операторов/Sources/FUMStructuringOperatorMemory/Определения/актуальность-README.json --параметры Прототипы/память-структурирующих-операторов/Проверки/внимание/актуальность-README-обычные.json < Прототипы/память-структурирующих-операторов/Проверки/внимание/README-без-ссылки.json
```

Для второго определения передаются `потребность-интеграции.json`, `потребность-интеграции-обычные.json` и `интеграция-проверенная.json` из тех же каталогов. Файлы с суффиксами `-пониженные` и `-нулевые` задают альтернативную чувствительность без изменения фактов. Точная [таблица ожидаемых исходов](Проверки/внимание/случаи.json) включает положительные, отрицательные и последовательные случаи.

Чтение существующих неизменяемых свидетельств:

```sh
python3 -B Прототипы/память-структурирующих-операторов/Сборщики/примеры_интеграции.py
```

Сборка профилируемого исполняемого продукта выполняется отдельно:

```sh
xcrun swift build --build-system swiftbuild --package-path Прототипы/память-структурирующих-операторов --scratch-path "$fum_attention_scratch" --jobs 1 -c release --product FUMStructuringOperatorMemoryProbe
```

[Сквозной профиль](Проверки/проверить-и-измерить-внимание.py) принимает `--бинарник` с полученным исполняемым продуктом и `--выход` с внешним файлом JSON. Он проверяет всю таблицу, обе смены определения и параметров, полный цикл README и три реальные поставки, затем трижды измеряет каждое определение одним неизменным бинарником. Для README отдельно измеряется сбор фактов и проверка результата; для Git — чтение архива и восстановление свидетельств. `--профиль` самого CLI выводит раздельные монотонные стадии загрузки, разбора, графа и трассы в stderr; JSON-наблюдение остаётся в stdout. Профиль не включает сборку и не объявляет очистку кэша ОС.

Фактические запуски реализации записаны [отчётной обёрткой](../../Инструменты/fum-otchyotyi-o-zapuskakh-proverok/SKILL.md). Их результаты, RED/GREEN и согласование тяжёлых окон находятся в [журнале реализации](../../Журнал/2026-09-11_21-46-50_MSK_реализовать-операторное-внимание/отчёт.md).


### Фактический корневой README

После сборки Release следующий запуск читает текущие файлы и сохраняет вход, сигнал и память вне checkout:

```sh
fum_attention_dir="$(python3 -c 'import tempfile; print(tempfile.mkdtemp(prefix="fum-attention-demo-"))')"
fum_attention_bin="$(xcrun swift build --build-system swiftbuild --package-path Прототипы/память-структурирующих-операторов --scratch-path "$fum_attention_scratch" --jobs 1 -c release --show-bin-path)/FUMStructuringOperatorMemoryProbe"
python3 -B Прототипы/память-структурирующих-операторов/Сборщики/факты_внимания.py --корень-репозитория . --репозиторий FUM --задача демонстрация --время 2026-09-11T18:00:00Z > "$fum_attention_dir/вход.json"
"$fum_attention_bin" внимание --определение Прототипы/память-структурирующих-операторов/Sources/FUMStructuringOperatorMemory/Определения/актуальность-README.json --параметры Прототипы/память-структурирующих-операторов/Проверки/внимание/актуальность-README-обычные.json < "$fum_attention_dir/вход.json" > "$fum_attention_dir/сигнал.json"
python3 -c 'import json,sys; print(json.dumps(json.load(open(sys.argv[1]))["память"],ensure_ascii=False))' "$fum_attention_dir/сигнал.json" > "$fum_attention_dir/память.json"
```

Для следующего наблюдения сборщик получает `--прежнее "$fum_attention_dir/память.json"`. Файл обратной связи имеет точную форму `{"рассмотрение":"рассмотрено","проверка":{}}` и передаётся через `--обратная-связь`. После исправления причины дополнительный `--проверить-результат Приложения/FUMA/README.md` заново проверяет текущие байты; полученный вход снова передаётся тому же исполнителю. Механизм не переписывает README. У уже соответствующего README потребность сначала не возникает.

### Полный воспроизводимый цикл и реальные поставки

Один сценарий выполняет `расхождение → рассмотрено при расхождении → изменение с ожиданием проверки → resolved`. Он создаёт временную копию двух выбранных оснований, берёт сырые README из открытых фикстур, каждый раз вызывает настоящий сборщик и передаёт именно `память` предыдущего ответа. Изменение ссылки и новое свидетельство показаны разными шагами. Поля `цикл_README` выходного профиля сохраняют каждый результат и память.

Этот же сценарий читает три закреплённых Git-примера из архива, передаёт каждый отдельный JSON тому же бинарнику и сохраняет приёмку отдельно от ancestry в `реальные_примеры`. Сборщик `примеры_интеграции.py` сам выдаёт три строки JSONL: весь его поток не является одним входным JSON исполнителя.

```sh
python3 -B Прототипы/память-структурирующих-операторов/Проверки/проверить-и-измерить-внимание.py --бинарник "$fum_attention_bin" --выход "$fum_attention_dir/профиль.json"
```
