# Сравнение строгого декодирования UTF-8

Стенд сравнивает текущий [интерпретатор структурирующих операторов](конечное-исполнение.md) и стандартный Swift на одинаковых байтах. Он сначала доказывает совпадение результата, затем измеряет готовые вызовы в одном процессе Release. Исходная реализация интерпретатора из коммита `f49eeee3fd80a87cd63391d6606dafa19cd6d2b8` сохранена без оптимизации под сравнение.

## Воспроизведение

Нужны macOS 14 или новее, установленный Swift и Python 3. Команды выполняются из корня чистого клона FUM. В примерах используется системный временный каталог macOS из `TMPDIR`; оболочка остановится, если он не задан. Сборка находится вне checkout; открытые входы и ожидаемые скаляры заданы литералами в [исходнике стенда](Sources/СтендДекодирования/Стенд.swift). Сетевых зависимостей у этого SwiftPM-пакета нет.

```sh
python3 Прототипы/память-структурирующих-операторов/Проверки/сравнить-декодирование.py подготовить --каталог-сборки "${TMPDIR:?}fum-utf8-comparison-build"
python3 Прототипы/память-структурирующих-операторов/Проверки/сравнить-декодирование.py проверить --каталог-сборки "${TMPDIR:?}fum-utf8-comparison-build" --вывод "${TMPDIR:?}fum-utf8-correctness.json"
python3 Прототипы/память-структурирующих-операторов/Проверки/сравнить-декодирование.py измерить --каталог-сборки "${TMPDIR:?}fum-utf8-comparison-build" --вывод "${TMPDIR:?}fum-utf8-comparison.json"
```

Первая команда строит продукт `СравнениеДекодирования` с `--configuration release` и сохраняет хэши исходников и бинарника в каталоге сборки. Следующие команды отклоняют устаревшую сборку. После изменения исходников снова выполните подготовку. Выходной JSON содержит все исходные наблюдения, статистику и происхождение; файл результата появляется только после успешного завершения. Диагностика неверных аргументов и ошибок идёт в stderr с ненулевым кодом. Сам исполняемый файл принимает `проверить` или `измерить`; в сборке Debug режим измерения запрещён.

Для адресной проверки стенда:

```sh
swift test --package-path Прототипы/память-структурирующих-операторов --scratch-path "${TMPDIR:?}fum-utf8-comparison-build" --filter ПроверкиСравненияДекодирования
```

## Что сравнивается

Оба пути отдельно материализуют полный `[UInt32]`, затем в другом сравнении — полный `[UInt32]` и байты UTF-32LE. Массив скаляров сам по себе не имеет порядка байтов. Упаковка явно выдаёт четыре байта на скаляр, младший первым; BOM не добавляется, имеющийся U+FEFF сохраняется. Нормализации Unicode и подсчёта графем нет.

Стандартный путь вызывает `transcode(_:from:to:stoppingOnError:into:)` из `Unicode.UTF8` в `Unicode.UTF32`, с `stoppingOnError: true`. Возвращённое `true` означает ошибку; накопленный префикс отбрасывается, наружу возвращается `nil`. Этот контракт проверен по установленному Swift.swiftinterface и первичному исходнику Swift. Исправляющий неверный ввод `String(decoding:as:)` не используется. Стандартный массив скаляров растёт через `append`, без предварительного знания числа скаляров; упаковка резервирует ровно четыре байта на скаляр. Такой же выбор резервирования использует текущий интерпретатор.

JSON определения загружается и разбирается до серий. Для границы скаляров заранее удаляется последний общий шаг упаковки; сами правила декодирования совпадают. `AutomationExecutor.выполнить` при каждом вызове всё равно проверяет определение и пределы, считает операции, материализует трассу и вычисляет хэши, включая JSON наблюдения. Вариант скаляров также выполняет внутреннюю байтовую сериализацию ради хэшей. Поэтому отношение времён описывает стоимость доступных API при равных полезных результатах. Оно не измеряет чистую стоимость двух алгоритмов декодирования.

Основные ряды вызывают интерпретатор без callback профиля с обычным лимитом 256 событий трассы. Ещё три диагностических вызова для каждой границы записывают штатные интервалы `проверка`, `исполнение`, `трасса` и время полного вызова. Они исключены из основных рядов. Интервал `исполнение` включает общий механизм правил, счётчики и упаковку, а трасса вычитается внутренними метками; это тоже не чистый декодер. Полный интервал и вложенные метки нельзя складывать.

## Корпус и метод измерения

Четыре повторяемых образца: ASCII `Az \n`; кириллица `Ёж ёж.`; смесь `Aё€🙂`; декомпозированное `e` + U+0301 + NUL + U+FEFF + 🙂. Каждый повторяется целиком до ближайшего числа байтов, не превышающего 4096, 32768 и 262144. Многобайтовые последовательности не обрезаются. В отчёте сохранены фактическое число байтов, скаляров, выходных байтов и хэши входа и ожидаемого выхода. Предел исполнителя — 262144 байта входа и 1048576 байт результата.

До замеров проверяются 46 положительных сочетаний: 12 входов корпуса и 11 коротких граничных векторов в двух режимах. Скаляры заданы независимо от обоих декодеров; ожидаемые байты получены отдельной арифметической упаковкой. Ещё 14 сочетаний проверяют отказ на неверном UTF-8. Они сохраняют код и позицию ошибки интерпретатора отдельно от стандартного `nil`. Время ошибок не сравнивается: диагностические контракты различаются.

Для каждого пути — три прогревочных вызова, одиночная проба и калибровочный пакет. По калибровке выбирается 1–10000 повторов с целью около 20 мс суммарного времени вызовов. Затем выполняются девять пар пакетов; порядок путей чередуется и зависит также от номера корпуса и границы результата. Крупный единичный вызов может превышать цель пакета. Публикуются медиана, минимум, максимум и медианное абсолютное отклонение средних времён пакетов. Пропускная способность в десятичных МБ/с рассчитана по входным байтам.

Каждый вызов окружён монотонными таймерами `DispatchTime`. Полная контрольная сумма всех скаляров и выходных байтов проверяется после второго таймера, результат затем освобождается. `autoreleasepool` ограничивает накопление временных объектов. В основных функциях и потребителе стоит `@inline(never)`. Два чтения часов и вызов обёртки входят в наблюдаемую стоимость; отдельное полное время пакета включает контрольную сумму и освобождение. Массивы отдельных результатов между повторами не удерживаются. Калибровки и сырые пакеты сохранены, повторные процессы на каждый вызов не создаются.

Процесс не закрепляется за ядром, частота CPU не фиксируется. Прогон отражает конкретный хост и его нагрузку; он не доказывает соотношения на других процессорах или холодном кэше. Встроенный профиль не оптимизируется по результату этого сравнения.

## Зафиксированный прогон

Apple M1 Max, 10 логических процессоров, 64 ГиБ памяти, macOS 27.0 (26A5425a), Apple Swift 6.4, сборка Release. После успешной проверки готового бинарника выполнена одна серия в согласованном окне без наших конкурирующих сборок, проекции и smoke-check. Фоновая работа macOS сохранялась; [два среза нагрузки](../../Журнал/2026-09-11_12-00-09_MSK_сравнить-декодирование-UTF-8/материалы/нагрузка.json) не являются непрерывным мониторингом. Тепловое состояние во всех пакетах равно 0, энергосбережение выключено.

Процесс занял 16,504 с, интервал серий и отдельной диагностики — 16,095 с. Загрузка определения заняла 5,138 мс, разбор и подготовка — 0,809 мс; эти одноразовые наблюдения исключены из рядов. Выбрано 1–1655 повторов на пакет. MAD девяти средних времён пакетов составляет 0,091–2,507% медианы по 48 рядам. Это описательный разброс, не доверительный интервал. Все 46 положительных случаев и 14 строгих отказов подтверждены до серий, контрольная сумма каждого измеряемого вызова совпала. UTF-32BE и скорость обработки ошибочных входов не измерялись. Оптимизация интерпретатора по этим данным требует отдельного этапа. Стенд сохраняет выбранную реализацию: профиль не показал основания усложнять сбор метрик, а изменение исполняемого декодера прямо исключено из текущего сравнения.

Сырые [432 пакета, 48 калибровок и 72 диагностических вызова](../../Журнал/2026-09-11_12-00-09_MSK_сравнить-декодирование-UTF-8/материалы/сравнение-Release.json) содержат также минимум, максимум и MAD. Независимый Python-проверяющий повторно выводит статистику из суммарного времени и числа повторов, проверяет пары, чередование и хэши исходников. После измерения переименовано только собственное имя одного Swift-теста по языковому правилу; исполняемые исходники стенда и интерпретатора не менялись. Старая квитанция по-прежнему включает Tests. Точные [прежние байты теста](Проверки/эталоны-профиля/тест-сравнения-до-переименования.swift.txt) сохранены. Следующие команды восстанавливают измеренный снимок в отдельном временном каталоге, проверяют все 21 хэш без исключений и выводят таблицу. Для собственного нового прогона достаточно указать его JSON без флага корня исходников, если текущие файлы совпадают с его квитанцией. Диагностические 72 вызова проверяются здесь только по количеству; семантика внутренних меток проверялась отдельно при чтении методики.

```sh
set -- "$(mktemp -d "${TMPDIR:?}fum-utf8-source.XXXXXX")"
```

Проверяющий закрепляет независимый конечный перечень 21 пути исходного стенда версии 1. С этим перечнем отдельно сравниваются квитанция и состав Sources/Tests восстановленного каталога; затем проверяются байты. Флаг `--корень-исходников` выбирает место чтения байтов и не определяет обязательный состав. Изменение состава исходников будущего стенда потребует явного обновления этого контракта. Семь регрессий включают одновременную потерю файла и записи о нём.
