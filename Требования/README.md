# Требования FUM

Этот каталог хранит атомарные [карточки требований FUM](../Глоссарий/карточка-требования-FUM.md). Одна карточка формулирует одно требование, даёт критерии его проверки и сохраняет путь к исходному запросу и материалу, из которого оно выведено.

Каждая карточка имеет один неизменяемый идентификатор `FUM-REQ-NNNN` в машинном маркере `FUM-REQUIREMENT-ID` сразу после заголовка. Идентификатор назначается один раз, не выводится из положения в индексе, заголовка, имени файла или статуса и не меняется при последующем `git mv`. Освободившиеся номера повторно не используются.

[Семантические связи требований FUM](../Глоссарий/семантическая-связь-требований-FUM.md) оформляются обычными локальными Markdown-ссылками в разделе `Семантические связи` каждой карточки. Одна связь записывается с обеих сторон согласованной парой отношений; это позволяет читать граф в любом направлении и автоматически проверять его целостность. Общая тема или общий источник сами по себе недостаточны для связи.

Используется минимальный расширяемый словарь отношений:

| Прямое отношение  | Обратное отношение | Когда применяется                                                               |
| ----------------- | ------------------ | ------------------------------------------------------------------------------- |
| `зависит от`      | `требуется для`    | первое требование невозможно или бессмысленно выполнить без второго             |
| `является частью` | `состоит из`       | первое требование является составной частью более крупного требования           |
| `дополняет`       | `дополняется`      | требования дают совместный результат, но каждое сохраняет самостоятельный смысл |
| `усиливает`       | `усиливается`      | первое требование добавляет более строгую гарантию, не подменяя базовое         |

Новый тип добавляется только вместе с первым содержательным примером, определением области применения и обратным типом. В карточке одна строка описывает одну связь: жирная метка отношения, локальная ссылка на требование и краткое основание после тире. Inline-ссылки в формулировке и критериях могут пояснять текст, но не заменяют типизированную запись.

Первый эмодзи имени файла показывает [статус требования FUM](../Глоссарий/статус-требования-FUM.md):

- `⚪` — черновик: формулировка ещё требует решения;
- `🟡` — принято и запланировано: требование зафиксировано, но проверенная реализация не завершена;
- `🚧` — реализуется;
- `✅` — реализовано и подтверждено указанной в карточке проверкой;
- `⛔` — заблокировано;
- `🗑️` — снято с сохранением истории и основания.

Статус меняется переименованием файла через `git mv`. Эмодзи не заменяет содержательное основание: карточка со статусом `✅` обязана ссылаться на проверку, а `⛔` и `🗑️` — объяснять блокировку или снятие.
