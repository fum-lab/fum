# Максимально сырая запись событий устройств ввода

[Коробочная реализация FUM](../Глоссарий/коробочная-реализация-FUM.md) должна с максимально доступной на каждой поддерживаемой платформе точностью получать и долговременно сохранять события клавиатуры, трекпада, мыши, стилуса, графического планшета и других графических устройств ввода. Сохраняется наиболее сырой доступный представлению FUM поток до необратимого сведения к жестам или командам интерфейса: исходный порядок, монотонное время, тип и идентичность устройства, физический идентификатор элемента управления и, если применимо, его сторона, фаза, координаты, относительные смещения, нажатия, давление, наклон, повтор и все иные предоставленные API низкоуровневые поля.

Сырые события хранятся отдельно от производных жестов, команд и смысловых интерпретаций. Запись должна сохранять происхождение, версию схемы, сведения об использованном API и явно обозначенные потери, объединение событий, недоступные поля, разрывы и изменения конфигурации устройств. «Максимально сырая» означает наиболее ранний публично поддерживаемый и публикационно допустимый слой конкретной платформы, а не обход системной защиты, скрытый сбор или обещание аппаратных отчётов там, где операционная система их не предоставляет.

Для клавиатуры первичным элементом является физическая клавиша, а не символ, команда, флаг или режим. Удерживаемые квазирежимные клавиши-модификаторы Shift, Control, Option и Command, а также режимная клавиша Caps Lock должны давать такие же раздельные события `нажато` и `отпущено`, как остальные клавиши. Для парных модификаторов сохраняется различие левой и правой физических клавиш; одновременное нажатие не должно сворачивать их в общий признак.

Такой поток должен позволять последующему интерпретатору назначить каждой физической клавише любое требуемое поведение без изменения слоя наблюдения. Например, две клавиши Command можно интерпретировать как клавиши Leap в духе интерфейса Джефа Раскина, а Caps Lock — как кнопку автодополнения. Это примеры допустимой интерпретации, а не закреплённая раскладка поведения. Слой ввода FUM не наследует от этих клавиш системную модальную семантику и не должен требовать режима Caps Lock для их использования.

Флаги модификаторов, логическое состояние Caps Lock, раскладочно разрешённый символ и другие высокоуровневые представления не входят в целевой контракт. Если источник предоставляет их вместе с физическими событиями, они могут сохраняться только как необязательные диагностические поля и не заменяют идентичность и фазу клавиши. Системные раскладки находятся вне области этого требования. Если публичный API сообщает только изменение общего флага или переключение режима, адаптер фиксирует потерю, не синтезирует отсутствующие физические события и по возможности дополняется более низкоуровневым источником.

## Кандидаты реализации

| Кандидат                                                | Сильная сторона                                                                                   | Ограничение, которое нужно измерить                                                                                  |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Game Controller: `GCKeyboard`, `GCMouse`, другие `GCDevice` | Единая модель устройств во фреймворке Apple и наибольший кандидат на переносимость между платформами Apple | Это не один класс `GCController`; покрытие трекпада, стилуса, редких HID-полей, частота и объединение событий требуют проверки |
| AppKit `NSEvent`                                        | Богатые прикладные события клавиатуры, мыши, трекпада и планшета в macOS                          | Слой macOS и оконной системы уже интерпретирует ввод; глобальное наблюдение имеет ограничения и разрешения           |
| Core Graphics `CGEventTap`                              | Более низкий системный поток Quartz-событий клавиатуры и мыши в macOS с временными метками и полями | Не является переносимым API всех платформ Apple и не равен исходным HID-отчётам                                      |
| IOKit `IOHIDManager`                                    | Значения HID-элементов и входные отчёты ближе всего к устройству в macOS                          | Наиболее сложный и платформенно ограниченный путь; права, sandbox, встроенный трекпад и семантика отчётов требуют проверки |
| UIKit, SwiftUI и платформенные gesture/pointer API      | Поддерживаемый прикладной путь для касаний, указателя, пера и жестов на соответствующих платформах | Обычно даёт уже нормализованные или распознанные события и потому служит дополнением, а не эталоном сырости           |

Предпочтение нельзя отдавать одному кандидату только по широте API или по сырости. Архитектура может использовать переносимое общее ядро Game Controller и платформенные адаптеры более низкого уровня, если измерение подтвердит, что один источник не сохраняет требуемые данные.

## Критерии проверки

- одинаковые физические сценарии воспроизводятся через каждый доступный кандидат на macOS, iPadOS, iOS, tvOS и visionOS, где соответствующее устройство и публичный API поддерживаются;
- для каждого источника измеряются полнота полей, различимость устройств, временное разрешение, задержка, частота, порядок, пропуски, повтор, объединение событий и поведение под нагрузкой;
- для каждой доступной квазирежимной клавиши-модификатора и Caps Lock выполняется цикл `нажать -> удерживать -> отпустить`; отчёт показывает отдельные физические события с устойчивой идентичностью клавиши, а для левой и правой Command дополнительно проверяет раздельное и одновременное нажатие;
- источник, который сворачивает физические переходы в общий флаг модификаторов или изменение режима Caps Lock, получает явную отметку потери; способность фактически доступного и публикационно допустимого источника или сочетания источников сохранить обе фазы и сторону каждой клавиши учитывается как отдельное преимущество при выборе наряду с разрешениями, ограничениями sandbox, задержкой, устойчивостью и стоимостью;
- критерии успеха не используют флаги модификаторов, логическое состояние Caps Lock, символ системной раскладки или переключение раскладки как ожидаемый результат;
- на macOS отдельно сравниваются `GCKeyboard`/`GCMouse`, `NSEvent`, `CGEventTap` и `IOHIDManager`; для трекпада, стилуса и планшета проверяются доступные платформенные источники;
- сохранённая трасса допускает побитово устойчивое чтение по версии схемы и повторное построение производных жестов без изменения исходных записей;
- подключение, отключение, сон, пробуждение, изменение конфигурации устройств, несколько одновременных устройств и переполнение очереди оставляют явные события или диагностируемые разрывы;
- сбор включается с явным согласием владельца, минимальными правами и документированным сроком хранения; чувствительный клавиатурный ввод защищён и не покидает локальный контур без отдельного разрешения;
- выбранный стек и отклонённые варианты сопровождаются воспроизводимым сравнительным отчётом, а не только архитектурным предположением.
