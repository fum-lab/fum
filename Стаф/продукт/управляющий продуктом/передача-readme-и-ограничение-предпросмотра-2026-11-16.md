## Фактический предел отчётов

После доставки Главстрой обнаружил в навыке отчётов прямое ограничение: первая активная проверка может иметь пустой терминальный префикс, но это не разрешает пустой машинный журнал через обычный `предпросмотр`. Это же условие независимо подтверждено в навыке из исходной базы `c2c2ac2282abbeef365d091e248677509134bb88`.

При подготовке `c4449eeddb368ddd46d8aee4fb46811196a5bddb` редактор сообщил один вызов изменённого предпросмотра на пустой истории, PID 80549, exit 0; при подготовке `37e4bd54d246c166af6bbedd5008db13a14d392c` — PID 95150, exit 0. Оба фактических эффекта сохраняются; соответствие обычному контракту не подтверждено. Оптимизатору поручено остановить применение и доставку этого patch как штатного; повторять вызовы нельзя.

В отчёте первого этапа отдельно описан прямой bootstrap вне обёртки, но его текст оставляет окончательную recency невыполненной, хотя редактор позднее сообщил успешные адресные update и check. Во втором отчёте аналогично остались слова о невыполненных адресных recency и проверках, хотя редактор сообщил успешные update и check до коммита. Открытые таблицы с нулём записей не являются машинной историей этих прямых проверок. Полный индекс, общий smoke, Creator и отчётная обёртка не запускались. Два коммита остаются фактически доставленными в рабочую ветку; исправление объяснения, процессная оценка и приёмка должны сохранять историю и не создавать фиктивных записей.

Ранее при подготовке предка `1bdd247b7487c75947a4ff549daedda60d31b179` трижды применялся отдельно зафиксированный запрещённый новый Python guard; Управляющий принял ответственность. Эти случаи не смешиваются с двумя последующими вызовами обычного предпросмотра.
