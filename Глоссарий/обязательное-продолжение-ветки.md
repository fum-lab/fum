# Обязательное продолжение ветки

Обязательное продолжение ветки — протокол последовательной именованной линии FUM, который связывает каждый её обычный промежуточный коммит [рабочей сессии](рабочая-сессия.md) с одной точной уже зарегистрированной задачей Codex. Связь закрепляет идентичность линии, полный локальный Git-ref, физический worktree, его FIFO, фактический `threadId` и неизменяемую квитанцию продолжения; подтверждённый `hostId` дополнительно обязателен только для задачи, созданной через host.

До коммита worktree-линии существует ровно один первый FIFO-билет: самостоятельно открытый чат может выбрать exact активную линию из свежего ограждённого снимка, и атомарное присоединение само создаст intent и квитанцию; если такого билета нет, владелец создаёт одну задачу с эквивалентной связью. Handoff выполняется командой пула по хэшу intent, а достигшее головы продолжение перечитывает закреплённый `protocol_oid`, подтверждает точную вершину линии и последовательно использует те же слот, ref и worktree без второго checkout.

Обычная branch FIFO, включая `master`, использует другой профиль: владелец всегда создаёт продолжение до коммита, ребёнок предъявляет exact-квитанцию и выполняет обычный `join`, а `commit` получает его идентификатор. Достигнув головы, ребёнок перечитывает фактический `HEAD`, выполняет `ack-head` и выбирает [следующий шаг ветки](следующий-шаг-ветки.md); `master` остаётся в первичном checkout. После регистрации отсутствующая, использованная, stale либо несовпавшая квитанция любого профиля закрывает маршрут и не создаёт резервный независимый слот.

Это унарный переход внутри одного [ветвевого fork FUM](ветвевой-fork-FUM.md): один обычный коммит линии — одно продолжение тех же ref и worktree. `finish-clean`, `done` и `not_ready` завершают цепочку без ребёнка. Терминальные commits результата писателя, ревью и интеграционного кандидата локального пула завершают отдельные назначения собственными квитанциями и обязательным продолжением не охватываются. Read-only-задача не получает писательский слот, а независимый писатель без квитанции продолжения начинает новую линию в отдельном переиспользуемом слоте `Подузлы/`.

Когда профиль требует `create_thread`, его неоднозначный результат закрывает переход отказом: родитель не коммитит и автоматически не повторяет host-вызов, потому что задача могла фактически появиться. Git-переход самостоятельно присоединившегося worktree-продолжения вместо этого восстанавливается из прежних intent и FIFO по exact `task_id`. Документарный и эталонный прототип проверяет exact slot `repo-root` содержательных команд, но Codex Desktop пока не даёт переноса workspace на уровне host с машинным ACK. Поэтому worktree не является нативной изоляцией host и не доказывает отсутствия чтений первичного checkout. Протокол также не обещает атомарность Codex-host с Git, exactly-once создания или безусловную живучесть; исчезнувший исполнитель не обходится таймером либо диспетчером.
