# Сессия шага FUM

Сессия шага FUM — эфемерная host-задача, исполняющая один контекстно посильный рабочий пакет дочернего fork-агента FUM. В начальном профиле корневой FUM создаёт в Codex Desktop только первую сессию цепочки и связывает её с точными назначением, ролью, `CODEX_THREAD_ID`, репозиторием, живым клоном, базовым commit, полным рабочим ref и бюджетами. Каждую следующую сессию заранее создаёт коммитящий владелец как обязательное продолжение того же клона и ref.

Сессия шага не является [рабочей сессией](рабочая-сессия.md) корневого запроса, устойчивой идентичностью [дочернего fork-агента FUM](дочерний-fork-агент-FUM.md) или отдельным модельным вызовом. Одна сессия может содержать несколько модельных вызовов и инструментальных переходов, но обслуживает ровно один шаг. Один `CODEX_THREAD_ID` не переиспользуется для другого шага или поколения назначения.

Каждый шаг получает отдельную сессию и новый `CODEX_THREAD_ID`, но задачи одной линейной цепочки наследуют один физический checkout и полный ref. Одновременно исполняются только готовые совместимые шаги разных цепочек или независимых ветвей; зависимые шаги одной линейной цепочки запускаются последовательно от принятой вершины. Завершение сессии не уничтожает состояние агента: следующий шаг восстанавливается из Git, назначения, паспортов и артефактов без обязательной истории прежнего чата.

Для [ветвевого fork FUM](ветвевой-fork-FUM.md) активной считается только одна авторитетная сессия-владелец: пишущая сессия рабочего ref либо ограждённая сессия модерации, но не обе одновременно. Заранее созданная ожидающая сессия обязательного продолжения, неактивная дочерняя задача и внешняя проверяющая задача без права записи могут существовать параллельно, но не получают полномочий fork. После развилки тот же родительский логический узел может продолжить роль модератора новой сессией; прежняя host-сессия не должна удерживать родительский FIFO во время работы детей.

Один экземпляр Codex Desktop является заявленным начальным профилем развёртывания. Машинно доказуемая часть закрепляет разные host-задачи, `CODEX_THREAD_ID`, checkout и refs. Единственность физического Desktop-контроллера считается доказанной только при наличии устойчивой идентичности и авторитетного readback host; иначе она остаётся наблюдаемой конфигурацией, а не проверенным инвариантом.
