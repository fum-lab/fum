# Ветка работы

Ветка работы в FUM — отдельная именованная линия развития задачи, гипотезы или конечной цепочки изменений. Она сохраняет собственный контекст, происхождение решений, промежуточные результаты и итог, который затем может быть возвращён в общую память через осмысленное слияние.

Ветка работы нужна для параллельного развития вариантов: [FUM](FUM.md) должен уметь сравнивать линии работы, обнаруживать конфликты и сохранять историю того, почему выбран итоговый вариант.

Автоматически развиваемая именованная Git-ветка имеет ровно один [следующий шаг ветки](следующий-шаг-ветки.md), который выбирает актуальную [карточку шага](карточка-шага.md) либо явно фиксирует завершение. Идентичность ветки включает репозиторий и полный ref: одинаковый `refs/heads/master` в ядре, подузле и проекте обозначает разные линии. Самостоятельный проект хранит ветки и следующий шаг в собственном репозитории, а родитель закрепляет его проверенную ревизию через [репозиторную композицию](репозиторная-композиция-FUM.md).

Для конечной последовательности шагов канонический upstream ветки задаёт [карточка цепочки шагов](карточка-цепочки-шагов.md): она связывает устойчивый идентификатор цепочки, точный полный ref и упорядоченные карточки, тогда как следующий шаг ветки остаётся производным селектором текущего продолжения. Переход версии `1` разрешён только между корневыми задачами, из чистого и пустого FIFO-состояния, на отсутствующий целевой ref, создаваемый ровно на точном исходном `HEAD`; допущенный владелец ветку не переключает.

В дереве исполнения одна пара идентичности репозитория и полного ref является авторитетной рабочей линией одного [ветвевого fork FUM](ветвевой-fork-FUM.md) и не переиспользуется другим узлом. Линейный fork может отдельным ограждённым переходом породить ровно два дочерних fork от проверенного общего исходного состояния; каждый ребёнок получает другую пару репозитория и полного ref и живой checkout, а тот же родительский узел становится модератором. Внутри каждого ребёнка последовательность коммитов остаётся линейной, а последующая интеграция не меняет дерево происхождения.

Каждое успешное изменяющее прохождение шага завершается атомарным коммитом в ветку текущей цепочки. Зелёный внутренний smoke-check ещё не является внешним успехом: сначала закрываются проверочный отчёт и его снимок, затем их включает атомарный `commit+handoff`. Действующий автоматический selector/dispatcher пока остаётся маршрутом `master.next-step` для `refs/heads/master`; ветки карточек цепочек требуют отдельного подключения.

[Ветка шага FUM](ветка-шага-FUM.md) является одноразовой веткой одной пишущей попытки от точного `base_oid`; она не заменяет долговечную ветку подузла или проекта. Git submodule хранит точный gitlink, а не саму живую ветку.
