# Проекты

Каталог хранит паспорта самостоятельных проектов, которые развиваются в форке [памяти FUM](../Глоссарий/память-FUM.md) в отдельных именованных [ветках работы](../Глоссарий/ветка-работы.md). Он позволяет вести несколько линий параллельно, не превращая общую ветку `master` в смесь несвязанных целей.

Корневой FUM остаётся описан в [главном README](../README.md) и не дублируется отдельным паспортом. Для нового проекта создаётся подкаталог `Проекты/<краткое-имя>/` с `README.md`, а рабочая ветка обычно именуется `project/<краткое-имя>`.

## Паспорт проекта

Паспорт должен содержать:

- цель проекта и ожидаемый передаваемый результат;
- полный ref основной ветки проекта;
- границы разрешённых действий, доступа и публикации;
- опорные требования, документацию и источники;
- ссылку на единственный выбранный [следующий шаг ветки](../Глоссарий/следующий-шаг-ветки.md) в `Планирование/следующие-шаги-веток/`;
- способ проверки и условие завершения либо возврата результата в основную память.

Паспорт не заменяет исходные запросы, производную документацию, требования или журнал. Секреты, локальные учётные данные и непубликуемое машинное состояние в `Проекты/` не сохраняются.

## Ветки и форки

Новая проектная ветка наследует общую память на момент ответвления, но до автоматического запуска обязана получить собственный паспорт и собственную запись следующего шага с точным `refs/heads/...`. Запись `master` не считается шагом новой ветки только потому, что была унаследована при её создании.

Параллельная работа над разными проектными ветками в одном клоне использует отдельные worktree. Внутри каждого checkout корневые задачи допускаются последовательно общей Git-CAS-очередью. Отдельные форки и клоны координируют свои задачи независимо; локальная очередь одного checkout не доказывает простой другого.
