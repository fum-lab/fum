# Настройка виртуальной машины

Swift-автоматизация подготавливает личную Linux VM на Apple silicon: проверяет ресурсы и план, устанавливает необходимые конвертер и GnuPG, проверяет подпись Ubuntu и байты образа. Собственные исходники находятся в монорепозитории FUM. Каноническое имя — «настройка виртуальной машины», идентификатор — `fum-nastrojka-virtualjnoj-mashinyi`.

Подтверждены реальная загрузка Ubuntu, автоматизированное восстановление VSOCK и два выполнения переносимого профиля FUM после штатных остановок. Команда `готовность` проверяет 58 тестов и два индекса в госте; повтор сохранил данные и использовал прежний клон без нового fetch. Это промежуточная поставка: первый запуск нового NoCloud, полный профиль прерываний, упаковка ресурсов и финальная приёмка ещё не закончены.

## Сборка и первый проверенный этап

Нужны Apple silicon, macOS с Virtualization.framework, Xcode Command Line Tools со Swift и установленный Homebrew. Наблюдённая среда: M1 Max, macOS 27.0, Swift 6.4, SDK 27.0. Другие сочетания пока не испытаны. Сборка хранится в явно выбранном каталоге вне Git; ниже используется стандартный временный каталог оболочки.

```sh
VM_BUILD="${TMPDIR%/}/fum-vm-build"
swift build --package-path Проекты/ВиртуальнаяМашина --scratch-path "$VM_BUILD" --jobs 2 -Xswiftc -j2
VM_BIN="$(swift build --package-path Проекты/ВиртуальнаяМашина --scratch-path "$VM_BUILD" --show-bin-path)/машина"
codesign --force --sign - --entitlements Проекты/ВиртуальнаяМашина/виртуализация.entitlements "$VM_BIN"
"$VM_BIN" проверить
"$VM_BIN" план > "${TMPDIR%/}/fum-vm-plan.json"
"$VM_BIN" подготовить --план "${TMPDIR%/}/fum-vm-plan.json" --до образ
```

`план` выводит JSON и не создаёт VM. По умолчанию выбираются 4 CPU, 8 GiB RAM, диск 32 GiB и отдельный личный каталог в системной области Shared с UID пользователя. Любой Git-предок, неизвестная существующая цель, symlink, чужие права или несовпавший план дают отказ. `--каталог` позволяет задать свой абсолютный физический путь; служебные символы, `..` и ссылки не допускаются. Образы и ключи нельзя размещать в checkout, включая скрытый Git-репозиторий домашнего каталога.

`подготовить` принимает `--до зависимости`, `образ`, `диск` или `всё`. qemu применяется только для конвертации QCOW2 в RAW; виртуализацией управляет Apple VZ. Автоматизация устанавливает только отсутствующие `qemu` и `gnupg` как Homebrew bottles, без общего обновления и очистки пакетов. Отсутствующий bottle требует отдельного решения; неявной сборки из исходников нет. SHA-256 образа проверяется после получения, после возобновления и перед конвертацией. Свидетельства связывают план, источник и проверенные файлы. Рабочий диск после первой конвертации сохраняется.

## Воспроизводимая упаковка

Добавлена отдельная команда сборки поставки. Она прошла 16 автономных проверок с подставными сборочными командами. Четыре проверки фабрики используют настоящие процессы: успешный повтор, код отказа 17 и предельный срок с прекращением поздней записи. Настоящая компиляция и проверка загрузки ресурсов из поставки ещё ожидают ресурсного окна. Нужен заранее установленный CPython не ниже 3.13 с `waitid/WNOWAIT`, выбранный Xcode и два разных абсолютных физических пути вне любого Git-репозитория:

```sh
python3 -B Проекты/ВиртуальнаяМашина/собрать.py --сборка /Users/Shared/FUM-VM-501/сборки/кэш --поставка /Users/Shared/FUM-VM-501/сборки/поставка-1
```

В примере замените `501` своим UID. Команда создаёт только собственный кэш с маркером владельца и неизменяемую поставку: `машина`, пакет гостевых ресурсов и `поставка.json`. Сборка использует два задания, включает гостевые ресурсы, подписывает бинарник для виртуализации и проверяет подпись. JSON результата показывает путь бинарника и измеренные стадии. Режим `--система xcode` выбран по испытанному toolchain; `--система native` доступен как явный вариант SwiftPM, но в этой среде пока не принят.

Упаковщик проверяет CPython до создания кэша и сохраняет его физический путь, версию, SHA-256 исполняемого файла и возможности в `поставка.json`. Наблюдатель получает закреплённый путь; снимок повторно сверяется перед командой, после неё и до принятия поставки. Это отдельная зависимость поставки: массив `[qemu, gnupg]` и хэш плана VM не меняются. Хэш одного файла не удостоверяет стандартную библиотеку; доверенная установка Python остаётся объявленной внешней зависимостью.

Повтор с теми же исходниками, снимком Python, версией Swift и выбранным SDK проверяет хэши готовой поставки и подпись без повторной сборки. Изменение входов или поставки требует нового `--поставка`; кэш той же области можно сохранить для инкрементальной сборки. Занятый замок, неизвестная цель, ссылки за границу кэша и несовпавший точный набор гостевых ресурсов дают отказ. Прерванные собственные staging-каталоги сохраняются для диагностики. Полная устойчивость к смерти самого упаковщика ещё не подтверждена.

Общее устройство и граница подтверждений зафиксированы в [решении текущего этапа](../../Журнал/2026-09-11_19-51-31_MSK_подключить-экспорт-и-повтор-гостевых-измерений/материалы/решение-устройства.md).

## Работа с подготовленной VM

После подготовки `--до всё` используйте `запустить`, затем `готовность`. Команда `ssh` открывает сеанс, `ssh --команда ТЕКСТ` выполняет команду, `остановить` ожидает штатного завершения. Повторный `запустить` использует прежние диск, EFI и ключи. `служить` — внутренний процесс, который держит замок VM и принимает команды. Успешный `start()` обозначает только работающую VM. Файл состояния без ответа текущей службы не подтверждает готовность; PID из файла никогда не используется для отправки сигнала.

SSH использует заранее созданные отдельные Ed25519-ключи клиента и гостя, собственные `known_hosts` и `ssh_config`, строгую проверку ключа и постоянный HostKeyAlias. Путь связи: loopback → Virtio Socket 2222 → systemd-socket-proxyd → sshd. Для VSOCK используется системный прокси из закреплённого образа, без установки пакетов при первой загрузке. Управляющий loopback-канал подписывает запросы и ответы HMAC-SHA256 с новым nonce и UUID запуска; секрет остаётся в личном состоянии. Общие настройки SSH не меняются. Остановка ожидает подтверждённое завершение гостя; тайм-аут не заменяется принудительным выключением.

Ограниченный профиль Linux выполняет четыре набора Python (8 + 4 + 25 + 21 тестов) и две проверки индексов из точного опубликованного коммита `4dd5a7f33913b17f705e512be1826314da89a4c4`. Пропуски, пустые наборы, незавершённый cloud-init, изменения клона и несовпадение идентичности отклоняются. Профиль не подтверждает Swift/FUMA или полный документационный smoke внутри Linux. Общих каталогов хоста нет; собственный клон хранится в `.fum-linux-vm` домашнего каталога гостя на ext4.

На испытанном хосте прямой исходящий HTTPS через NAT завершался тайм-аутом. Поэтому `готовность` на время проверки создаёт обратный SOCKS через SSH, разрешённый только для `ports.ubuntu.com:443` и `github.com:443`. Туннель завершается вместе с командой; результат явно указывает этот способ сети. VPN, PF, firewall и маршруты macOS не меняются. Это ограниченная сеть готовности; обычный интерактивный SSH не включает прокси автоматически.

Для VM прежней версии, где установка socat не завершилась, доступна команда `восстановить --адрес-гостя IPv4` вместе с обычным `--каталог`. Укажите фактический частный адрес именно своей VM. Восстановление подключается по NAT с тем же закреплённым ключом, сверяет идентификатор и точные собственные units, сохраняет резервные копии и переключает VSOCK на встроенный прокси. Неизвестные надстройки и изменённые файлы дают отказ. В конце команда отдельно подтверждает SSH через VSOCK. Диск и ключи не пересоздаются; `cloud-init clean` не выполняется.

## Автономная проверка и диагностика

```sh
swift test --package-path Проекты/ВиртуальнаяМашина --scratch-path "$VM_BUILD" --jobs 2 -Xswiftc -j2
```

Тесты проверяют недостаток ресурсов, изменение плана, неизвестный и занятый каталог, symlink/hardlink/FIFO, предел метаданных, подмену таблицы и подписи, тип размера QCOW2, буквальную передачу аргументов, сроки ожидания, повтор этапа, NoCloud, переходы состояния и аутентификацию кадров. Нативная VM, сеть и конвертация не запускаются автономным набором.

Ошибки подготовки оставляют собственные файлы попыток для продолжения и диагностики. Неизвестные файлы не удаляются, диск не пересоздаётся. Исполнитель создаёт отдельную группу через posix_spawn и завершает её при тайм-ауте, включая потомков, игнорирующих мягкий сигнал. Необрабатываемое завершение самого родителя и восстановление ещё проходят испытание. Уникальные выходные файлы каждой попытки исключают их совместную запись после прерывания. Вызовы и вложенные интервалы сохраняются в личных `событие-*.json`; повторное объединение одного UUID не удваивает счётчик. Область учёта не включает произвольные сторонние команды, GUI и обращения модели.
