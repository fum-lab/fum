# Операторные модели нативного ответа

Одно [описание данных и проекции](контракты/описание-ответа.json) порождает [Swift Codable-модели](порождённые/МоделиОтвета.swift) и [Python dataclass-модели](порождённые/модели_ответа.py). Через тот же описанный граф вычисляются проверки, выбор ответа, переименование полей, счётчики и ссылки на полный снимок. Ручные общие функции находятся в [поддержке языков](общие/); предметного соответствия полей в них нет.

Это первый конечный профиль `fum.модели-и-проекция.1`, числовая область — `целые64-без-дробей`. Рабочий [прежний Python-срез](../../Инструменты/fum-svyaznostj-rabochej-sessii/компактный-ответ-задачи.md) и его схемы сохранены. Совпадение двух новых реализаций внутри профиля проверено; совместимость со всей числовой областью прежнего контракта не заявлена. Общая API/cache-обёртка пока использует прежний срез.

## Откуда берётся генерация

В [существующем исполнителе](../../Прототипы/память-структурирующих-операторов/) `AutomationExecutor.выполнить` исполняет два новых конечных шага: `разобрать-структурный-контракт` создаёт проверенное структурное значение, `породить-представление` выдаёт исходный текст выбранного языка. Определения [Swift](контракты/генерация-Swift.json) и [Python](контракты/генерация-Python.json) вызывают эти шаги с одинаковым профилем. Исполнитель считает стоимость, проверяет ресурсные пределы и выдаёт следы с SHA входных байтов. [Обёртка генерации](породить-ответ.py) связывает оба наблюдения с одним описанием и только после успеха обоих вычислений пишет выходы.

Перенесён минимальный набор из десяти файлов исходного коммита `f49eeee3fd80a87cd63391d6606dafa19cd6d2b8`; прежние три изменяемых файла предварительно совпали с его родителем. Перенос и исторические свидетельства перечислены в [манифесте происхождения](../../Журнал/2026-09-14_15-54-44_MSK_породить-модели-ответа-операторами/материалы/источник-исполнителя.json). Проверки источника не заменяют собственную приёмку: текущий пакет прошёл 45 тестов.

Собственный исходный интерфейс поддержки использует `КонтрактМоделей(кодированноеОписание:)`; поле структурного контракта называется `допускаетПустойМаркер`. [Согласованная миграция имён](../../Инструменты/fum-perevod-obyyavlenij-koda-na-russkij-yazyik/собственные-имена-контекста.md) обновила объявления, известные вызовы и шаблон генератора, после чего модели пересозданы исполнителем. Метки внешних протоколов `init(from:)` и `encode(to:)`, машинные ключи и JSON-схема сохраняются. Составные собственные JSON-имена закреплены конечным перечнем по русской смысловой основе.

## Воспроизведение

Нужны Python 3.10+ со стандартной библиотекой и Swift 6.0+ на macOS 14+. Измерено на Python 3.14.7 и Apple Swift 6.4. Внешние пакеты и сеть не нужны. Сборочные каталоги задаются вне Git. Все команды выполняются из корня клона FUM; угловые плейсхолдеры заменяются фактическими путями.

```bash
swift build --package-path Прототипы/память-структурирующих-операторов --scratch-path <сборка-операторов> --jobs 2
swift build --package-path Прототипы/память-структурирующих-операторов --scratch-path <сборка-операторов> --show-bin-path
python3 -B Проекты/рабочий-контекст/породить-ответ.py --исполнитель <путь-к-FUMStructuringOperatorMemoryProbe> --выход Проекты/рабочий-контекст/порождённые
swift build --package-path Проекты/рабочий-контекст --scratch-path <сборка-ответа> --jobs 2
swift build --package-path Проекты/рабочий-контекст --scratch-path <сборка-ответа> --show-bin-path
```

`--show-bin-path` возвращает каталог исполняемых файлов выбранной системы сборки. `FUMStructuringOperatorMemoryProbe` находится в первом каталоге, `ОтветЗадачи` — во втором. Порождённые файлы уже хранятся в Git; повторная генерация не нужна для обычной сборки.

Проверка дрейфа добавляет `--проверить` к команде генерации. Успех — код 0 и размеры/SHA двух файлов. Код 2 означает неподдержанное описание, недостоверное наблюдение либо дрейф; существующие выходы не исправляются режимом проверки. Вычислительный отказ до записи сохраняет оба старых файла. Атомарная пара записей при отказе файловой системы не заявлена.

Swift CLI получает SHA-256 точных UTF-8-байтов оболочки, UUID задачи и бюджет; полный файл заранее сохраняет вызывающий слой:

```bash
<путь-к-ОтветЗадачи> <полный-sha256> <uuid-задачи> 16000 < <полный-сохранённый-json>
```

Python вызывается через `представить_снимок(данные, ожидаемый_хэш, задача, максимум_байтов=16000)` из порождённого модуля. В путь модулей добавляются `общие/Python` и `порождённые`. Возвращаются готовые UTF-8-байты с LF; `ValueError` — отказ без изменения входных байтов. Общий предел снимка — 128 МиБ, глубина JSON — 64, бюджет — 100–1048576 байтов. Swift CLI на отказе возвращает код 2, пустой stdout и краткую диагностику. Ни одна реализация не обрезает результат до бюджета.

## Точная область профиля

Отсутствие, null и пустое значение различаются. `error: false`, `error: 0`, пустые строка, массив и объект сохраняются как значения. Все целые ограничены Int64; логический тип отдельный. Токены `1.0` и `1e0` отклоняются даже внутри произвольного `error`. Лексический контроль выполняется до Codable в `представитьСнимок`; отдельный вызов JSONDecoder без этого входа не доказывает соответствие числовых токенов профилю.

Строки и ключи сопоставляются по точным Unicode-скалярам. Полные исходные строки не нормализуются. Повторные и канонически совпадающие ключи одного JSON-объекта отклоняются в обоих языках; группировка тоже отказывает, если потребовала бы объединить такие ключи. Пробельность задаётся общей таблицей скаляров в описании, включая U+0085 и U+001C, но исключая U+200B и U+FEFF.

Выбор использует порядок массивов: первый ход с подходящим сообщением и последнее непустое сообщение этого хода. `commentary` и `final` равноправны. Последующие ходы и элементы всё равно проверяются и учитываются. Выход сохраняет точные метаданные выбранного хода, `error`, пагинацию и явные счётчики пропуска. Неизвестные поля и варианты закрытого предметного типа дают отказ. Объявленные непрозрачные типы элементов сохраняются только в полном оригинале и учитываются счётчиками.

Сначала проверяется SHA всей оболочки. Двухуровневый указатель адресует строку внутреннего JSON и нужный элемент внутри неё. Оригинал остаётся необходимым для раскрытия пропущенного. Отказ профиля не означает отсутствие ответа или успешную обработку. Пустой принятый ответ тоже не доказывает завершения задачи; признаки свежести и завершения явно ложны.

Описание ограничено 64 КиБ, 32 моделями, 64 полями модели и двумя уровнями контейнеров типов. Рекурсивные модели, повторные объявления, служебные имена, неизвестные операции и заведомо неверные типы констант отклоняются. Динамический путь дополнительно проверяется при применении. Это конечный язык одного рабочего контракта, а не универсальный компилятор.

## Проверки и измерения

```bash
swift test --package-path Прототипы/память-структурирующих-операторов --scratch-path <сборка-операторов> --jobs 2
swift test --package-path Проекты/рабочий-контекст --scratch-path <сборка-ответа> --jobs 2
python3 -B Проекты/рабочий-контекст/проверить-операции.py
python3 -B Проекты/рабочий-контекст/проверить-генерацию.py --исполнитель <путь-к-FUMStructuringOperatorMemoryProbe>
FUM_СВИФТ_ОТВЕТ=<путь-к-ОтветЗадачи> python3 -B Проекты/рабочий-контекст/проверить-порождённый-ответ.py
python3 -B Проекты/рабочий-контекст/профиль-порождённого-ответа.py --исполнитель <путь-к-FUMStructuringOperatorMemoryProbe> --swift <путь-к-ОтветЗадачи> --выход <файл-профиля>
```

Без `FUM_СВИФТ_ОТВЕТ` нативная Python-проверка не заявляет запуска Swift. Общие 32 примера операций проверяют строгие типы, глубинное равенство, Unicode, отсутствие и переполнение. Нативные семь групп дополнительно проверяют весь набор пробельных скаляров, границы Int64, SHA, точную границу бюджета и доступность исходного файла после отказа. Повторные выходы runtime сравниваются по смыслу: порядок JSON-ключей и экранирование `/` могут различаться, а значит, размеры и приёмка на одинаковой границе бюджета тоже могут различаться. Бюджет проверяется по реальным байтам каждой реализации.

[Профиль](../../Журнал/2026-09-14_15-54-44_MSK_породить-модели-ответа-операторами/материалы/профиль-генерации-и-применения-окончательный.json) содержит семь повторов. Медиана генерации — 54,69 мс без сборки. Малый вход 493 байта даёт 2133 байта Python или 2145 Swift; крупный 4021534 байта даёт 2870 или 2897 байтов. Применение Python измерено внутри загруженного процесса, Swift — вместе с новым CLI-процессом; это разные границы, не рейтинг языков. Токены, RSS, сеть и экономия на реальной смешанной последовательности здесь не измерены. Исторический живой малый вход прежнего среза тоже увеличивался: 885 → 2595 байтов.

Оптимизация этого этапа не расширяет язык и не меняет формат ради меньшего результата. [Следующий профиль сохранённой API-обёртки](../../Инструменты/fum-svyaznostj-rabochej-sessii/компактный-ответ-задачи.md) измерил смешанную последовательность больших и малых ответов с повторным использованием. Он использует прежний Python-эталон и отдельно указывает стоимость файлов, вызовов и полезной выдачи.
