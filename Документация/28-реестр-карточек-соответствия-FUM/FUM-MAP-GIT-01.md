# FUM-MAP-GIT-01: Git-инфраструктура эволюционных цепочек

Эта карточка фиксирует Git-инфраструктуру как первый конкретный инженерный носитель [эволюционной цепочки FUM](../../Глоссарий/эволюционная-цепочка-FUM.md). Она показывает, как уже используемый репозиторий может не только хранить документацию, но и выполнять роль наблюдаемого контура порождения вариантов, проверки, отбора, наследования и возврата кредита.

## Карточка

- Идентификатор: `FUM-MAP-GIT-01`.
- Объект сопоставления: Git-инфраструктура эволюционных цепочек.
- Слой: инженерный носитель отбора.
- Наблюдатель: человек, агент рабочей сессии и будущий [FUM-узел](../../Глоссарий/FUM-узел.md), читающий историю репозитория как трассу происхождения.
- Соответствие общей схеме: [ветка работы](../../Глоссарий/ветка-работы.md) выступает вариантом, commit или артефакт - [передаваемым результатом FUM](../../Глоссарий/передаваемый-результат-FUM.md), проверка - внешним отбором, Git DAG и [реестр происхождения FUM](../../Глоссарий/реестр-происхождения-FUM.md) - родословной и основанием возврата кредита.
- Сохраняемые инварианты: результат имеет происхождение, может быть проверен, может быть унаследован следующей работой и может быть связан с источником требования.
- Потери наблюдаемости: Git не хранит весь внутренний ход рассуждения, не гарантирует полноту пользовательского контекста и не заменяет журнал, исходный запрос или публикационный аудит.
- Переход к источнику: основная спецификация раскрыта в документе [Git-инфраструктура эволюционных цепочек FUM](../20-Git-инфраструктура-эволюционных-цепочек-FUM.md), а требование закреплено в исходном запросе 2026-07-02 10:51:13 MSK.
- Границы аналогии: сопоставление применимо к воспроизводимым рабочим изменениям с явным источником, проверкой и коммитом; оно ослабевает для незафиксированных локальных действий, внешних сервисов без трассы и результатов, которые нельзя проверить.
- Проверка: рабочая сессия должна иметь файл исходного запроса, журнал, обновлённые производные материалы, локальные проверки и Git-коммит.
- Статус уверенности: закреплённая карточка текущей практики.

## Слияние, специализация и отбор

Статус этого дополнения — гипотеза сопоставления; полный общий алгоритм ещё не установлен. Пользователь описывает слияние с последующим ветвлением как половое размножение, [гендер агента](../../Глоссарий/гендер-FUM-агента.md) — как его специализацию, а тесты — как хищников.

Последовательность модели: совместимые наследуемые основания → объединение → последующее ветвление и назначение роли → исполнение в [среде](../../Глоссарий/окружающая-среда-FUM.md) → отбор проверками. Merge-коммит сохраняет происхождение от нескольких родителей; fast-forward отдельного события объединения в DAG не создаёт. Число родителей коммита и множество возможных ролей агента описывают разные свойства.

«Геном» обозначает наследуемое основание в этой гипотезе. Его состав и критерий общей совместимости требуют определения; отсутствие текстового конфликта Git само по себе не доказывает совместимость исполняемого результата. Запущенный агент проходит заданные проверки в наблюдённых условиях; именно эти условия и результаты сохраняются в журнале.

«Астероид» расширяет отбор до резкой смены среды с длительными последствиями. Инженерное сопоставление — проверка поведения при продолжительной нехватке ресурсов, недоступности зависимостей и последующем восстановлении. Внешнее происхождение события не исключает отбора по устойчивости к новым условиям. Исход испытания, наблюдённые условия и установленная причина отказа хранятся раздельно; неустановленная причина остаётся неизвестной.

Состав наследуемого основания, соответствие специализации клетки назначению роли, инварианты общего алгоритма и критерии его опровержения добавлены в [открытый вопрос](../../Вопросы/2026-06-26_12-19-03_MSK_абстракция-уровней-наблюдаемой-вселенной-FUM.md). Прохождение конечного набора тестов подтверждает этот набор в данных условиях; общее соответствие биологической и инженерной моделей из него не следует.
