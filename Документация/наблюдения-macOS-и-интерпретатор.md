# Наблюдения macOS и интерпретатор операторов

FUMA получает события и выполняет обращения к macOS через слой Swift-адаптеров. Слой передаёт типизированные входы внутреннему API интерпретатора структурирующих операторов. Граф операторов превращает наблюдения в значимые сигналы, выбирает реакцию и формирует запрос следующего действия. Наблюдение системы, его интерпретация и результат действия сохраняются раздельно.

Документ задаёт принятый контракт разработки. Полный охват API macOS и подключение этого слоя к действующему интерпретатору ещё не подтверждены. Текущий локальный детектор бюджета вывода является ограниченным первым участком; его наличие не доказывает наблюдения за всеми инструментами Codex.

## Первый сквозной сценарий

Swift-адаптер наблюдает полученный вывод процесса и передаёт его размер с единицей «байты», идентичностью источника и границами измерения. Операторы сравнивают размер с явно заданным бюджетом. При превышении возникает сигнал перерасхода; реакция использует существующее компактное чтение. Полный исходный результат сохраняется, а ограниченное представление содержит указатели на оригиналы и явную неполноту выбранной страницы.

Проверка сравнивает одинаковые принятые входы, выбранное действие, сохранность оригиналов и фактический размер результата. Байты не объявляются токенами модели. Недоступный счётчик остаётся неизвестным; пропущенное наблюдение не заменяется нулём.

## Обязательная память обращений

Каждый вызов и каждое наблюдение FUMA через этот слой записываются на постоянный носитель. Для вызова сохраняются идентичность, запрошенная операция, принятые параметры, инициировавший оператор и версия графа; затем отдельно фиксируются результат, ошибка или отмена и монотонная длительность. Асинхронное событие связывается с источником, подпиской и порядком приёма. Запрос действия и подтверждённое исполнение не смешиваются.

Перед внешним действием сохраняется намерение. Если после сбоя результата нет, вызов остаётся незавершённым: отсутствие записи не доказывает ни успеха, ни того, что действие не произошло. Повтор внешнего действия требует определения безопасного способа проверки его фактического исхода.

Происхождение позволяет связать исходное наблюдение, путь операторов, сформированный сигнал и последующее действие. Повторный импорт не создаёт второе событие, а реальные повторные обращения сохраняются отдельными экземплярами. Изменение порядка конкурентных входов фиксируется как часть принятого потока, а не скрывается под заявлением детерминизма.

## Воспроизведение и хранение

Повторное исполнение графа получает сохранённые входы и результаты внешних обращений вместе с версиями операторов и объявленными зависимостями. Чтение живого времени, случайности и текущего состояния macOS не подменяет эти входы. Воспроизведение наблюдений само по себе не разрешает повторить внешние побочные эффекты.

Приватные наблюдения хранятся в локальной памяти FUMA. Открытый репозиторий получает только публикационно допустимые материалы. Для крупных бинарных данных сохраняются ссылки и контрольные суммы фактического содержимого; их размещение следует принятому способу хранения вне Git. Хэш без доступного содержимого не означает полноценного воспроизведения.

Нужно определить проверяемую границу служебных операций самого журнала, иначе запись каждого собственного системного вызова порождает бесконечную рекурсию. Эта граница, гарантии долговечности, поведение при заполнении диска и учёт потерянных входов должны быть явно описаны и проверены до заявления полного покрытия. Внутренние обращения закрытых системных frameworks нельзя объявлять наблюдёнными только потому, что записан вход в публичный API.

## Приёмка первого участка

- Один сохранённый ввод даёт одинаковый сигнал и выбор реакции при тех же операторах и бюджете.
- Превышение бюджета вызывает компактное чтение без второго поручения человека; неуместившийся результат возвращает явный отказ без скрытого усечения.
- Сбой API, отмена, повторное событие, недоступность источника и незавершённый вызов различаются в памяти.
- Профиль измеряет стоимость самого наблюдения и журналирования; подавление подробного представления не стирает первичные данные.
- Полнота покрытия подтверждается перечнем подключённых адаптеров и проверенными границами; отсутствующие источники перечисляются явно.

## Язык операторов и диагностический интерфейс

Язык описания структурирующих операторов должен выражать типы входов и выходов, композицию, явное состояние, порядок обработки и внешние эффекты. Подсистема GUI описывается тем же механизмом: события ввода изменяют состояние интерфейса, операторы рассчитывают компоновку и формируют команды отрисовки Metal. Конкретный синтаксис и исполняемый граф ещё предстоит разработать и проверить.

В первом диагностическом сценарии Swift-часть FUMA запускает Codex CLI. Параметры запуска, переданные сообщения, stdout, stderr, доступные структурированные события и завершение процесса сохраняются до сокращения представления. Операторы переводят наблюдения в состояние диагностического интерфейса, затем в команды Metal. Полный поток сохраняется отдельно от текущего окна просмотра; байтовый бюджет представления не заменяет счётчик токенов модели.

Отображаются наблюдаемые задача, действия, ошибки и доступные показатели ресурсов. Недоступные внутренние состояния CLI помечаются неизвестными. Для двух независимых потоков сохраняются источник и наблюдённый порядок чтения; это не доказательство точного общего порядка записи внутри процесса.

Приёмка первого сквозного среза сравнивает состояние интерфейса и команды отрисовки на одинаковом сохранённом потоке при закреплённых версиях операторов. Повторное воспроизведение не запускает CLI или его инструменты заново. Полное совпадение пикселей на разных устройствах Metal требует отдельного проверенного контракта; оно не следует только из равенства команд.

## Наблюдаемость и настройка автоматизаций для LLM

LLM получает представление о том, что выполняется автоматически и почему: идентичность и версия определения, правило запуска, происхождение входов, фактически пройденные операторы, текущее состояние, результаты и ошибки. Декларация автоматизации сама по себе не доказывает её запуск. Состояние строится из наблюдений; неполнота и устаревание остаются видимыми.

Настройка выражается языком описания структурирующих операторов. Предлагаемое изменение, проверенное определение и фактически применённая версия различаются. Трасса последующего запуска ссылается на применённую версию; воспроизведение использует сохранённую версию и не подменяет её текущей настройкой.

Для экономии контекста сначала выдаются компактное состояние и значимые изменения с адресами полной трассы. LLM может запросить нужный участок с происхождением; сокращённое представление не удаляет первичные наблюдения. Доступность такого контура и применение настроек пока являются требованиями, а не реализованными возможностями текущего CLI.

## API Codex CLI в системе операторов

Операторный адаптер предоставляет командам Codex CLI типизированные входы и связывает ответы, события и ошибки с идентичностью вызова и задачи. Параметры, версия протокола, версия определения оператора и наблюдённый исход сохраняются в памяти. Инвентарь реально доступных операций, их совместимость и способ подключения уточняются по используемой поставке CLI.

По последующему уточнению Swift-оболочка FUMA охватывает сами обращения, инициируемые Codex CLI: оба потока — к API модели и к инструментам и ОС. Для каждого нужны проверяемые точки подключения, запрос, исход и связь с операторным графом. Подключение протокола управления CLI или захват вывода процесса сами по себе не доказывают такого охвата. Реестр покрытия перечисляет контролируемые операции и известные неподключённые пути.

Описание оператора отделяет намерение вызова от подтверждённого результата. Неизвестный исход, потерянная связь и отмена видимы; повтор с внешними эффектами требует явного решения. Режим воспроизведения подаёт сохранённые ответы в граф без обращения к живому Codex. Диагностический интерфейс и компактный контекст используют те же наблюдения и связи происхождения. Это контракт следующего адаптера, его работоспособность ещё не подтверждена.
