## Вывод по зависимостям

На Tools base root `Package.swift` называет пакет `FUMA`; его единственный продукт — executable `fuma`, а зависимость пакета — `LinguisticKit` (строки 9–15). Target `АктуализацияПутей` уже есть и зависит только от `LinguisticKit.static` (строки 44–47). Root manifest не зависит от `КомпозицияНаблюдений`. Его target `КонтейнерНаблюдений` компилирует указанный каталог исходников напрямую (строки 50–52); это не dependency на package `КомпозицияНаблюдений`.

В текущем FUMA source `Приложения/FUMA/macOS/Package.swift` локальные package dependencies — память операторов, контейнер наблюдений и архивный снимок (строки 17–21); root package и `КомпозицияНаблюдений` в них отсутствуют. Путь `Приложения/FUMA/Packages/КомпозицияНаблюдений/**` в этом Git-дереве отсутствует.

Поэтому проверенные manifests не дают цикла `root → Composition → root`. Если Composition добавит зависимость на продукт root target, появится только ребро `Composition → root`; при отдельном подключении Composition в FUMA macOS graph будет `FUMA macOS → Composition → root`. Обратное ребро появится только при новом явном dependency из root package в Composition, которого в закреплённом root manifest нет.

Минимальная существующая граница для единственного core — target `АктуализацияПутей`, экспортированный library product без нового target/runtime. Но его текущий публичный фасад `ПубличныйФасадИмён` канонизирует логические компоненты/составляет имена ссылок; это не подтверждает применение преобразования к корням каталогов. Указанные в постановке файлы `normalizaciya-kornej-agentov.swift` и `primeneniye-normalizacii-kornej-agentov.swift` отсутствуют в Tools base. Продуктовый экспорт возможен как граница модуля; наличие и API общего root-apply ядра на разрешённых source pins остаются `UNKNOWN`.

## Caller и one-shot граница

В Tools base CLI `Команда.swift` вызывает `ЦиклЗапуска().выполнить` в ветке `.запуск` (строка 47). Сам цикл создаёт `НачальноеНамерение` с `подключённыеАдаптеры: []` и спецификацией «адаптеры ожидают подключения» (строки 22–26), записывает его в контейнер и затем читает запись после переоткрытия (строки 48–64). Это действительный вызов одноразового сохранения/проверки намерения, но не вызов общего нормализатора и не автоматический цикл агентов.

В текущем FUMA macOS source `КомандаОператора` вызывает `КомандноеИсполнениеОператора`; исполнитель запускает `AutomationExecutor` и сохраняет запись исполнения в `КонтейнерНаблюдений`. Этот путь подтверждает разовый вызов оператора, но не вызов Composer/root-normalizer. `FUMAttentionLoop` действительно повторяет `tick` и читает input/AX-наблюдения (строки 232–255), однако в его manifest-зависимостях и просмотренном caller-пути нет Composer, root apply или запуска оператора.

Заявленный в постановке caller `КомандаОператора → КомпозицияНаблюдений/cikl-nablyudenij-sostoyaniya.swift` не подтверждён текущим Git source: пакет и файл отсутствуют в pin `b8b670d8…`. Это пока описание/план, не установленная исполняемая связь.

## Добавление: уточнение source pin и CLI caller

Это уточнение не переписывает предыдущее наблюдение по `b8b670d8f511affb08fb3a64874b737e5890c689`: оно относится только к тому локальному alias/ref и верно для его дерева. ROOT передал отдельный immutable producer source C=`fa7412482776a3ef28d0fe316bddb8edefe713ce`; это подтверждает источник, но само по себе не доказывает перепривязку текущего ref. Принятый root pin — `4a2375a4dcbe1495b5afe520185795a00acaff9b`.

В root `Package.swift` на `fa741248…` уже экспортируется `.library(name: "АктуализацияПутей", targets: ["АктуализацияПутей"])` (строка 14); его package dependencies по-прежнему содержат только `LinguisticKit`, без Composition (строки 16–18). В принятом root `4a2375a…` экспорт этого library product отсутствует: в списке продуктов только executable `fuma` (строки 12–15). Поэтому product export подтверждён в producer source C, но не в принятом root pin.

`Приложения/FUMA/macOS/Package.swift` на `4a2375a…` явно зависит от локального package `КомпозицияНаблюдений` (строки 18–22); targets `КомандаОператора` и `ИсполнениеОператора` используют его product (строки 43–55). Это зависимость nested macOS package вниз к Composer. В обоих проверенных Composer manifests (`4a2375a…` и `fa741248…`) перечислены соседние packages контейнера, Git и архивного снимка; в `fa741248…` дополнительно указан снимок агентской задачи. Ни один из них не зависит от root package или его продукта `АктуализацияПутей`.

Следовательно, в этих pins есть путь `FUMA macOS → КомпозицияНаблюдений`, но нет обратного package edge `root FUMA → КомпозицияНаблюдений`. Добавление предложенной зависимости `КомпозицияНаблюдений → root product АктуализацияПутей` даст направленную цепочку `FUMA macOS → КомпозицияНаблюдений → root FUMA`, не цикл. Состояние root и Composer из двух pins не следует объединять: product export есть в producer C, но отсутствует в принятом `4a`; Composer→root dependency отсутствует в обоих manifests.

Реальный CLI caller подтверждён в `КомандаОператора.swift` обоих pins: аргумент `--исполнить-цикл-наблюдений` выбирает ветку вызова (строки 26–28), а helper создаёт `ЦиклНаблюденийСостояния` и ожидает его `выполнить` (строки 154–159); после возвращения плана CLI передаёт его в `МостСрезаНаблюдений.исполнить` (строки 160–162). Это действительный явный CLI-путь к циклу перед исполнением оператора, но он запускается выбранным вызовом команды и не подтверждает автоматический вызов на каждом turn/для каждого агента.
