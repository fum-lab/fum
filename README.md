# [FUM](Глоссарий/FUM.md)

[FUM](Глоссарий/FUM.md) - `fraktaljnyij uzel myishleniya`, по-русски - [фрактальный узел мышления](Глоссарий/фрактальный-узел-мышления.md). Название фиксируется как аббревиатура латинскими буквами.

Этот репозиторий служит [памятью проекта FUM](Глоссарий/память-FUM.md) - открытого агента следующего поколения. Сейчас он является [документационным прототипом FUM](Глоссарий/документационный-прототип-FUM.md): память уже ведётся через требования, происхождение решений, проверки, журнал, индексы и наследуемую Git-историю, хотя [коробочная реализация FUM](Глоссарий/коробочная-реализация-FUM.md) ещё проектируется.

Долгий ориентир проекта - [FUM](Глоссарий/FUM.md)-агент полного цикла разработки и исследования: от выработки требований, постановки гипотез и [экспериментов](Глоссарий/эксперимент-FUM.md) до написания кода, проверки результатов, оформления [открытий](Глоссарий/открытие-FUM.md) и постепенного перехода к агенту, способному развивать самого себя.

## Ключевые идеи

### Память и происхождение

[Память FUM](Глоссарий/память-FUM.md) строится как проверяемая, наследуемая и развиваемая среда. Каждый значимый запрос сохраняется в [Запросы/](Запросы/), производные материалы живут в [Документация/](Документация/) и [Глоссарий/](Глоссарий/), а история изменений читается не только через Git, но и через [журнал работ](Глоссарий/журнал-работ.md).

Модель памяти ориентируется на живые организмы: от генома до накопленного опыта нервной системы. На каждом уровне должен работать цикл наследования, изменчивости и отбора.

### Фрактальная архитектура

[FUM](Глоссарий/FUM.md) рассматривается как сеть [FUM-узлов](Глоссарий/FUM-узел.md), где узлом может быть простой элемент, агент, человек, команда, организация или составная сеть узлов. Образец для архитектуры - повторяемые [модули](Глоссарий/модуль-FUM.md), способные объединяться в сеть из модулей того же рода.

На человеческом и агентском уровнях естественный язык является языком [синхронизации знаний FUM](Глоссарий/естественно-языковая-синхронизация-знаний-FUM.md). Люди, LLM-поддерживаемые агенты и гибридные узлы через весь строй языка обновляют локальные модели, выявляют расхождения и координируют совместное действие. Сам [агент человеческого образца FUM](Глоссарий/агент-человеческого-образца-FUM.md) должен повторять этот принцип рекурсивно: быть участником внешней сети и одновременно сетью внутренних подузлов, а не только монолитной LLM с чат-интерфейсом.

В расширенной исследовательской рамке [многоуровневая языковая синхронизация FUM](Глоссарий/многоуровневая-языковая-синхронизация-FUM.md) связывает этот человеческий случай с клеточными сигналами, химическими реакциями, атомными взаимодействиями, уровнем элементарных частиц, другими субатомными масштабами и гравитационно-релятивистскими ограничениями. На нечеловеческих уровнях «язык» является проверяемой общей схемой взаимодействий, а не утверждением о словах, намерении или сознании.

[Сознание](Глоссарий/сознание.md) в проекте определяется как совместное знание: эмерджентное свойство сети элементов. Поэтому [FUM](Глоссарий/FUM.md) рассматривает сознание как многоуровневое сетевое свойство, а не как бинарный признак человеческого масштаба.

### Интерфейс и компьютерная среда

Важен не только сам [FUM-узел](Глоссарий/FUM-узел.md), но и [интерфейс FUM-узла](Глоссарий/интерфейс-FUM-узла.md). Внутренний интерфейс показывает узлу его состояния, память, подузлы и ограничения; внешний интерфейс связывает узел с человеком, другими узлами, сервисами и средой.

Отдельный целевой слой - связка [FUM](Глоссарий/FUM.md) и [MCP-серверов](Глоссарий/MCP-сервер.md) разных сервисов как [единая точка взаимодействия пользователя с компьютером](Глоссарий/единая-точка-взаимодействия-с-компьютером.md). Такой слой должен снижать [модальность приложений](Глоссарий/модальность-приложений.md), сокращать дублирование интерфейсного кода и уменьшать расстояние от идеи до воплощения.

### Наблюдаемость и обучение

[FUM](Глоссарий/FUM.md) должен иметь доступ ко всем своим [внутренним состояниям](Глоссарий/внутреннее-состояние.md), включая информацию, отображаемую пользователю в интерфейсе. [Навигация по памяти FUM](Глоссарий/навигация-по-памяти-FUM.md) считается [наблюдаемым входным сигналом](Глоссарий/наблюдаемый-входной-сигнал.md): открытия документов, переходы по ссылкам, поиск, прокрутка и выбор фрагментов должны быть видимы агенту как часть работы.

Для собственного обучения [FUM](Глоссарий/FUM.md) нужен [обобщённый алгоритм поиска повторяющихся последовательностей](Глоссарий/обобщённый-поиск-повторяющихся-последовательностей.md), пригодный для байтов, текста, структурированных событий, выявленных [паттернов](Глоссарий/паттерн-памяти.md) и последовательностей действий агента.

### Автоматизации и проверки

[Автоматизации FUM](Глоссарий/автоматизация-FUM.md), [устройства восприятия и действия](Глоссарий/устройство-восприятия-и-действия-FUM.md), визуализация и рабочие проверки входят в память проекта как воспроизводимые артефакты. Их исходные тексты, конфигурации, версии, тесты и ограничения должны быть локально проверяемыми; при развитии автоматизаций используется [TDD](Глоссарий/TDD.md).

[Язык автоматизаций FUM](Глоссарий/язык-автоматизаций-FUM.md) должен стать программным слоем, удобным для LLM: входы, выходы, эффекты, проверки, трассы, версии и происхождение фиксируются так, чтобы модель могла надёжно читать, генерировать, объяснять и точечно править автоматизации.

### Открытость и границы доступа

[Открытость FUM](Глоссарий/открытость-FUM.md) является частью идеи, а не только публикационным режимом. Репозиторий ведётся под [CC0 1.0 Universal](LICENSE.md), чтобы базовая память, требования и архитектурные решения могли проверяться, наследоваться и развиваться.

При этом личная память [персонального агента](Глоссарий/личный-FUM-агент.md) не публикуется автоматически. Для обмена [наработками](Глоссарий/наработка.md) между узлами нужны явные [уровни доступа](Глоссарий/уровень-доступа.md), а [децентрализация FUM](Глоссарий/децентрализация-FUM.md) и [границы власти](Глоссарий/граница-власти-FUM.md) должны сохранять координацию без тотального контроля.

### Исследования и дальние контуры

[FUM](Глоссарий/FUM.md) должен не только выполнять инженерную работу, но и вести [научные исследования](Глоссарий/научное-исследование-FUM.md), ставить [эксперименты](Глоссарий/эксперимент-FUM.md) и оформлять [открытия](Глоссарий/открытие-FUM.md) как проверяемые [наработки](Глоссарий/наработка.md) памяти.

Дальние горизонты проекта включают [физическое действие FUM](Глоссарий/физическое-действие-FUM.md), [роботизированные системы FUM](Глоссарий/роботизированная-система-FUM.md), [производственные цепочки FUM](Глоссарий/производственная-цепочка-FUM.md), [космическую автономию FUM](Глоссарий/космическая-автономия-FUM.md) и [межзвёздное расселение FUM](Глоссарий/межзвёздное-расселение-FUM.md). Эти темы ведутся как проверяемые требования и открытые вопросы, а не как немедленное обещание автономного действия.

## Форк памяти

Репозиторий готовится к публикации на GitHub как базовый upstream [памяти FUM](Глоссарий/память-FUM.md). Внешний пользователь может форкнуть его, держать `master` своего форка близко к обновляющемуся upstream `master`, а собственные проекты и личную память вести в отдельных ветках вроде `memory/<название>` или `project/<название>`.

Базовая схема работы:

```bash
git clone <url-вашего-форка-FUM>
cd FUM
git remote add upstream <url-базового-репозитория-FUM>
git fetch upstream
git switch -c memory/<название>
```

Когда upstream обновляется, сначала обновляется `master` форка, затем он сливается в собственную ветку:

```bash
git fetch upstream
git switch master
git merge --ff-only upstream/master
git push origin master
git switch memory/<название>
git merge master
```

Улучшения, полезные для общей памяти, выносятся в отдельную ветку от свежего `master` и передаются обратно через pull request без приватных материалов. Полный протокол форка, периодического слияния, обратной передачи улучшений и публикационный аудит зафиксированы в документе [Публичный upstream и форки памяти FUM](Документация/27-публичный-upstream-и-форки-памяти.md).
