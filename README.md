# FUM

FUM - `fraktaljnyij uzel myishleniya`, по-русски - фрактальный узел мышления. Название фиксируется как аббревиатура латинскими буквами.

Этот репозиторий служит памятью проекта FUM - открытого агента следующего поколения. Цель проекта - реализовать агента полного цикла разработки от выработки требований до написания кода; долгосрочный ориентир - FUM-агент, способный написать самого себя.

Модель памяти FUM также ориентируется на организацию памяти в живых организмах: от генома до накопленного опыта нервной системы. На каждом уровне памяти должен работать цикл наследования, изменчивости и отбора.

Дополнительным образцом для FUM является устройство неокортекса: повторяемые универсальные модули, способные объединяться в сеть из модулей того же рода. Это задает архитектурный ориентир для FUM как фрактальной сети узлов мышления.

Проект также опирается на обзор актуальных реализаций агентских циклов: от ReAct-подобных tool-use контуров до graph-based orchestration, multi-agent workflows и software agents для работы с кодом.

FUM должен запоминать собственные шаги, находить повторяющиеся последовательности наблюдений и действий и отбирать устойчивые паттерны для будущих циклов работы.

Для этого FUM нужен обобщенный алгоритм поиска повторяющихся последовательностей, пригодный для байтов, единиц текста, структурированных событий, выявленных паттернов и последовательностей действий агента.

FUM должен иметь доступ ко всем своим внутренним состояниям, включая информацию, отображаемую пользователю в интерфейсе, чтобы агент мог видеть и обрабатывать то, что влияет на его работу и память.

FUM должен уметь передавать устойчивые наработки другим узлам и заимствовать наработки от узлов, к которым предоставлен доступ. Такой обмен требует явных уровней доступа: от полностью публичных материалов до приватных и ограниченно передаваемых частей памяти.

FUM должен строить внутренние модели других FUM-узлов, с которыми он взаимодействует. Люди рассматриваются как особый случай FUM-узлов: модель человека должна различать прямые сообщения, наблюдения, выводы, неизвестность и границы доступа.

Проектируемый FUM должен уметь вести параллельную работу над задачами в разных ветках и затем объединять результаты через слияние, подобно командной работе людей над проектом.

Правила поведения агентов и рабочих сессий хранятся в [AGENTS.md](AGENTS.md).
